# `lib/core/git/git_repository_client.dart`: switch `add`,

`commit`, and `hasChanges` from the unchecked `_run` helper to
`_runChecked`. `hasChanges` keeps its existing
`result.stdout.toString().trim().isNotEmpty` logic, now reached
only past the non-zero-exit check. Update each method's dartdoc
to note it now throws `ProcessException` on failure instead of
failing silently (matching `createWorktree`'s existing dartdoc
style for the same behavior). No behavior change to `init`,
`createWorktree`, `removeWorktree`, `deleteBranch`, `push`,
`changedFileCount`, `defaultBranch`, `tag`, `pushTag` — already
correct or intentionally soft-failing (`defaultBranch`).
