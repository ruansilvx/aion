# Spec Delta: Decision Graph `agentJudgment` Condition

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md` `aion-arch/specs/providers.md`'s "Decision graphs" section — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification (e.g. bare `_foo` vs `TicketsCubit._foo`), line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. the `agentJudgment` condition type this delta introduces is documented there in full, matching this delta's description closely.

Relative to `aion-arch/specs/providers.md` (`core/agent/`,
`core/automation/`, `core/contracts/`,
`features/tickets/presentation/cubit/`,

## ADDED

- **`AgentProvider.supportsSessionResume`** (`core/contracts/agent_provider.dart`)
  — new required `bool` member. `ClaudeAgentSdkProvider => true`,
  `AnthropicMessagesApiProvider => false`.
- **`AgentSessionHandle`** (new file,
  `core/contracts/agent_session_handle.dart`) — `providerId`, `sessionId`,
  `modelId`. A resumable handle to an in-flight run's provider-native
  session.
- **`AgentRequest.resumeSessionId`** (`core/contracts/agent_model_client.dart`)
  — `String?`, default `null`. When set, the run resumes and forks that
  session instead of starting fresh.
- **`AgentRequest.onToolCall`'s function type gains a 4th parameter**,
  `AgentSessionHandle? session` — passed by `ClaudeAgentSdkClient`
  (constructed from the bridge's captured session id + the request's own
  model), always `null` from `AnthropicMessagesApiClient`.
- **`agent_bridge/index.mjs`**: emits a new `{"type":"session","sessionId":"..."}`
  NDJSON line as soon as the SDK's message stream reports one; accepts
  new `resume`/`forkSession` fields on the initial request line, forwarded
  into `query()`'s options.
- **`DecisionEvalContext.session`** (`AgentSessionHandle?`) and
  **`DecisionEvalContext.askAgentJudgment`**
  (`Future<bool?> Function(AgentSessionHandle, String)?`) — both
  optional/nullable, default `null`.
- **`evaluateDecisionGraph` becomes `Future<DecisionOutcome>`**
  (previously synchronous) — the walk is otherwise unchanged; only an
  `agentJudgment` node's evaluation actually awaits anything.
- **`agentJudgmentConditionId`** (`'agentJudgment'`,
  `decision_graph_evaluator.dart`) — a fourth `DecisionNode.conditionId`
  shape, alongside the fixed catalog and `ruleBuilderConditionId`.
  `conditionParams == {'prompt': String}` — a free-text yes/no question,
  no fixed vocabulary.
- **`agentJudgmentConditionSpec`, generalized `isRecognizedConditionId`/
  `decisionNodeTitle`/`decisionNodeSummary`** (`decision_field_catalog.dart`)
  — mirrors the rule-builder's own picker-integration/node-display
  pattern, gated on a fixed 3-context allowlist (`ticketCreation`,
  `ticketLinking`, `chatBranching`) rather than a field-vocabulary check.
- **`TicketsCubit._askAgentJudgment`** — the real `askAgentJudgment`
  implementation: resolves the session's provider via
  `_providerRegistry`, issues a forked/resumed `AgentModelClient.run`
  call asking the node's prompt as a scoped yes/no question, parses the
  answer. Returns `null` (not `false`) for every failure mode, letting
  `evaluateDecisionGraph`'s own `?? false` be the single place "couldn't
  ask" becomes "unmatched."
- **`DecisionNodeForm`'s condition picker** gains an "Ask the agent"
  entry (only for the 3 eligible contexts), swapping the parameter area
  to a single free-text prompt field. **`DecisionOutlineList`**/
  **`GraphCanvas`** node chrome gain an `ASK ·` eyebrow (paralleling
  `RULE ·`/`IF ·`) plus a cost/latency info affordance.
- **`decisionGraphAgentJudgmentLabel`** l10n key (`lib/l10n/app_en.arb`).

## MODIFIED

- **`TicketsCubit._evaluateDecisionGraph`** gains an optional `{AgentSessionHandle?
  session}` named parameter, `null` for every existing call site except
  the 3 rebuilt below.
- **`TicketsCubit._handleCreateTicketToolCall`/`_handleAddLinkToolCall`/
  `_handleBranchToolCall`** gain a new `AgentSessionHandle? session`
  parameter (threaded from `onToolCall`'s new 4th argument) and pass it
  to `_evaluateDecisionGraph` as `session:`.
  `_handleCloseBranchToolCall` gains the same parameter for signature
  symmetry but doesn't use it (`chatBranching`'s decision graph is only
  consulted from the branch/close-branch pair together, per the existing
  "governs both tools symmetrically" contract — `agentJudgment` nodes
  configured there are reachable from either call).
- **`TicketsCubit._onToolCallFor`/`.handleChatToolCall`** and
  **`ChatCubit.runChatTurn`**'s `onToolCall` parameter — signature
  updated for the new 4th argument; behavior otherwise unchanged.
- **`ClaudeAgentSdkClient.run`** — captures the bridge's new `"session"`
  line into a local variable and forwards `AgentRequest.resumeSessionId`
  as `resume`/`forkSession: true` in the outgoing request JSON.

## UNCHANGED (explicitly)

- `DecisionNode`/`DecisionBranch`/`DecisionGraph`/`DecisionOutcome`
  entities, `DecisionGraphRepository` interface,
  `DriftDecisionGraphRepository`, the two drift tables and their schema
  version — `conditionId`/`conditionParamsJson` already accept arbitrary
  values; no migration. `DecisionOutcome.modelJudgment` — unchanged,
  coexists with `agentJudgment` as a distinct mechanism (see proposal.md
  Non-goals).
- `DecisionGraphConfigCubit` — condition-agnostic CRUD/invariant
  enforcement, no changes.
- Every `AutomationContext` call site's confidence-resolution logic
  (`AutomationConfidence.manual`/`.gated` branches) — unchanged; this
  proposal only ever affects behavior already inside an
  `AutomationConfidence.auto` branch that already consults a graph.
- The 5 no-live-session contexts' decision-graph evaluation
  (`sddStage`, `codingExecution`, `codingExecutionRetry`,
  `codingExecutionResume`, `specAutoLink`) — `session`/`askAgentJudgment`
  stay `null` at these call sites; an `agentJudgment` node is never
  offered in their pickers and would defensively resolve unmatched if
  one somehow existed there.
- `decision_condition_catalog.dart`'s two fixed entries
  (`attemptExceedsMax`, `sessionOverageDetected`) and every seeded
  baseline graph — unmodified.
- `AnthropicMessagesApiProvider`/`AnthropicMessagesApiClient` — gains
  only the one-line `supportsSessionResume => false` and an ignored 4th
  `onToolCall` parameter; no resumable-session support built for it (see
  proposal.md Non-goals).
