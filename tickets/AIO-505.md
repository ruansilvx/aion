# Spec Delta: Chat Transcript UX Redesign

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's ChatCubit/ChatState section` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. currentToolUse, streaming state, and the transcript-pane mechanism this delta describes are confirmed current (the automated check missed ChatState.currentToolUse only because the qualifier wraps across lines).

Scope: `TicketDetailScreen`'s rendering of `TicketType.chat` tickets
only. Behaviors for every other ticket type are unaffected and not
listed below.

## ADDED

- A `chat`-type ticket's message transcript renders in its own
  independently-scrolling region, separate from the ticket's metadata
  column (header fields, SDD-stage tracker, coding execution section,
  linked tickets, backlinks) above it. The metadata column no longer
  shares a scroll view with the transcript.
- The transcript auto-scrolls to the newest message on initial load, on
  every new human message sent, on every streamed AI-reply chunk, and
  once the AI reply settles.
- Human (`CommentAuthorType.human`) messages render right-aligned in
  the transcript. AI (`CommentAuthorType.ai`) and system
  (`CommentAuthorType.system`) messages render left-aligned (unchanged
  position from today).
- Each message bubble's width is capped at a fraction of the
  transcript's available width (does not stretch full-width), for
  both left- and right-aligned messages.
- AI-authored message content renders as Markdown (headings, lists,
  fenced code blocks, inline code, emphasis, links, tables — the same
  feature set `MarkdownView` already supports for ticket page content)
  instead of plain text.
- While an AI reply is in flight, a live status line derived from
  `ChatState.currentToolUse` (e.g. "Running `<tool>`...") is shown in
  the transcript, ahead of any streamed reply text. Previously this
  state was tracked by `ChatCubit` but never rendered.
- The chat compose field auto-expands from one line up to a maximum
  height as the user types multi-line input, then scrolls internally
  beyond that height, instead of staying a fixed single-line field.
- Pressing Enter in the chat compose field (hardware keyboard) sends
  the message; pressing Shift+Enter inserts a newline instead.

## MODIFIED

- The chat compose field's shape changes from a fully-rounded pill to a
  large-radius rounded rectangle (`AionRadius.lg`), to read correctly
  once it grows past one line.
- The "COMMENTS · `<count>`" header line above a chat ticket's
  transcript is now rendered inside the new independently-scrolling
  transcript region instead of inside the shared page scroll (same
  copy, same count logic, different container).

## REMOVED

- The chat transcript's message list is no longer a `shrinkWrap`,
  `NeverScrollableScrollPhysics` list embedded inside the ticket
  detail page's single whole-page scroll view. (Non-chat ticket
  comment threads keep this exact pattern — this removal applies to
  chat tickets only.)
- Uniform left-alignment for every author type in the chat transcript
  is removed for human messages (now right-aligned per ADDED above).
  AI/system alignment is unchanged. Note: `CommentTile`, used for the
  plain (non-chat) ticket comment thread, keeps uniform left-alignment
  for all author types — this REMOVED entry applies only to the new
  chat-specific message rendering, not to `CommentTile`.
