# 7.3 Manual interactive pass on a **native desktop build**

(`flutter run -d windows`), not Chrome/web: the entire
gitignore-gate/directory-picker flow is desktop-only (`isDesktop`
gates `_DirectoryPicker`/`GitignoreConfirmationBanner` in
`NewProjectScreen`, and `offerCodebaseAnalysis` can only ever
become `true` via that same desktop-only path, since a web project
has no `rootPath`) — Flutter Web genuinely cannot reach this
feature's code at all, so Chrome was never a valid target for this
pass. No native-GUI-automation tool was available either, so this
was driven directly via Win32 API calls through PowerShell
(`SetCursorPos`/`mouse_event`/`SendKeys` + `Graphics.CopyFromScreen`
for screenshots) against the real running `aion.exe` window.
Verified against two real git-tracked scratch repos: the
gitignore banner appears pre-submit and only when the chosen
directory is already a repo; checkbox defaults checked, unchecking
reveals the warning-hint row exactly per design.md §2.3; declining
shows the decline toast with the exact expected copy and leaves no
`.gitignore` written; accepting writes a `.gitignore` containing
exactly `.aion/`/`tickets/` (confirmed via `git status --short`
showing both correctly excluded); `git init` is correctly skipped
both times (`git log` unchanged); the codebase-analysis offer
banner appears once on the resulting empty ticket list in both
cases, and dismissing it (×) removes it immediately. Did not
trigger an actual Shallow/Full scan, since that would spend real
agent-bridge/API quota on the user's account beyond what a UI
verification pass needs — that path is already covered by
task 5.4's mocked-agent-client tests. Both scratch projects and
their on-disk repos were removed afterward via the app's own
"Remove" action + filesystem cleanup, and the `flutter run`
process was terminated (confirmed no lingering `dart`/`flutter`
processes).
