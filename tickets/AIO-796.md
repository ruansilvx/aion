# Spec Delta: design-system-restructure

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (19/19 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

### Directory: `lib/design_system/`

A new top-level directory, sibling to `lib/core/` and `lib/features/`,
holding the entire design system: design tokens plus every reusable,
feature-agnostic widget. Internally organized by atomic-design tier:

- `tokens/` — design tokens (`AionColors`, `AionRadius`, `AionSpacing`,
  `AionShadows`, `AionText`, `AionThemeData`, `ThemeScope`). Content
  identical to the former `core/theme/`, only relocated.
- `atoms/` — smallest reusable widgets with no dependency on any other
  custom widget: `AppButton`, `AppCheckbox`, `AppTextField`,
  `AppSpinner`.
- `molecules/` — widgets composed from atoms and/or managing their own
  `Overlay`: `showAppConfirmDialog`/`ConfirmDialogTone`, `AppDropdown`,
  `AppHeader`, `AppToast`, `SelectionMenu`, and `InlineEditableField`
  (see MODIFIED below).

Exposed via one barrel, `lib/design_system/design_system.dart`,
exporting all three subfolders. This is the sole public entry point —
callers import the barrel, never a leaf file inside `design_system/`.

### Convention: design-system promotion bar

`flutter-conventions.md` gains a documented rule: a widget is eligible
for promotion into `design_system/` only once it is fully generic — no
constructor parameter of a feature's domain entity/enum type, and no
feature-specific copy/strings baked into its body. A widget must be
generalized *before* promotion, never generalized as part of the same
move.

## MODIFIED

### `InlineEditableField<T>`

Relocated from `features/tickets/presentation/widgets/inline_editable_field.dart`
to `design_system/molecules/inline_editable_field.dart`. No change to
its public API, constructor parameters, or behavior — it already took
no `tickets` domain type. `features/tickets/tickets.dart` no longer
exports it (callers now reach it through `design_system.dart`, the
same way they already reach `AppButton`/`AppTextField`).

### `lib/core/core.dart`

Barrel's export list shrinks to `database/`, `localization/`,
`routing/`, `utils/` — the widget and theme exports it used to carry
move to `design_system.dart` instead. No symbol is removed from the
app's public surface; every symbol previously reachable via `core.dart`
remains reachable, just through a different barrel for the
widget/theme subset.

### `lib/features/tickets/tickets.dart`

Drops the `inline_editable_field.dart` export line (see MODIFIED
`InlineEditableField<T>` above). No other export changes.

### `aion-arch/project.md`, `aion-arch/flutter-conventions.md`

Architecture section documents `design_system/` as a third top-level
`lib/` grouping alongside `core/` and `features/`. Barrel-files section
describes the new `design_system.dart`/`core.dart` split and the
extended self-import-exception rule (tokens/atoms/molecules
cross-imports are internal to `design_system/` and go direct, not
through the barrel; reaching from `design_system/` into `core/` for
localization now crosses a barrel boundary and must go through
`core.dart`).

## REMOVED

### `lib/core/theme/`, `lib/core/widgets/`, `lib/core/design_system.dart`

Fully retired — contents relocated to `design_system/tokens/`,
`design_system/atoms/`, and `design_system/molecules/` respectively
(see ADDED above). No behavior removed; this is a location change only.
