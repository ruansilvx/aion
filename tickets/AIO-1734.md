## ADDED

- **`AgentModelClient`** (`core/contracts/agent_model_client.dart`) — the
  provider-agnostic interface every model call in Aion goes through.
  `AgentRequest` (`prompt`, `model`) in, a `Stream<AgentEvent>` out,
  terminated by exactly one `AgentDoneEvent` or `AgentErrorEvent`.
  `AgentTextEvent` carries incremental generated text.
  `AgentOverageDetectedEvent` carries an informational plan-usage-window/
  rate-limit signal, if the provider reports one — does not gate or
  block anything; see Non-goals below.
- **`ClaudeAgentSdkClient`** (`core/agent/claude_agent_sdk_client.dart`)
  — the sole `AgentModelClient` implementation. Spawns a bundled Node.js
  bridge process (`agent_bridge/index.mjs`) per call via `dart:io
  Process`, sends the request as one JSON line on stdin, parses NDJSON
  events from stdout. Authenticates via the user's existing Claude
  plan (Pro/Max) — no API key entry, nothing Aion stores as a secret.
  Every call runs with tool access disabled (no file/git/bash/MCP) —
  this MVP has no coding-execution caller. Desktop-only.
- **`agent_bridge/`** — a Node.js project (its own `package.json`
  declaring `@anthropic-ai/claude-agent-sdk`) sibling to the `aion/`
  Flutter project root, invoked by `ClaudeAgentSdkClient`. Requires a
  one-time `npm install` (documented in `project.md`'s Bootstrap &
  Dependency Notes) and `node` reachable on `PATH`.
- **`AgentModel`** (`features/providers/domain/entities/agent_model.dart`)
  — a fixed enum of three selectable models: Opus 4.8, Sonnet 5,
  Haiku 4.5. Not discovered from a live endpoint.
- **`AgentSettingsRepository`** / `SharedPrefsAgentSettingsRepository` —
  persists the single selected `AgentModel` via `shared_preferences`.
  Global (app-level), not per-project.
- **`ProviderSettingsCubit`** (`features/providers/presentation/cubit/`)
  — loads the persisted model selection and immediately runs one live
  connection test against `ClaudeAgentSdkClient` (there is no static
  credential/plan-introspection check to run instead — Agent SDK
  exposes none). Exposes `testConnection()` (manual re-test) and
  `selectModel(AgentModel)` (persists + re-tests); both no-op while a
  test is already in flight, rather than racing two concurrent tests.
  States: `ProviderSettingsLoading`, `ProviderSettingsReady`
  (`selectedModel`, `status` — `unknown`/`checking`/`connected`/
  `disconnected` — `statusMessage`).
- **Settings screen** (`/workspace/settings`,
  `features/providers/presentation/screens/settings_screen.dart`) —
  shows the Claude Agent SDK connection status (via
  `ProviderConnectionBadge`, a status pill matching `SyncStatusBadge`'s
  established visual pattern), a "Test Connection" action, and a model
  dropdown (`AppDropdown<AgentModel>`).
- New app-level (not per-project) providers wired in `main.dart`:
  `AgentBridgeLocator`, `AgentModelClient`, `AgentSettingsRepository`.

## MODIFIED

- `WorkspaceNavShell`'s secondary-actions popover (`tickets.md`'s
  "Persistent navigation shell" section) gains a third entry,
  **"Settings"**, alongside the existing "Switch Project" and "Trash" —
  navigates to the new `/workspace/settings` route. Same shared
  `SelectionMenu<T>` popover mechanism, no new overlay.

## Known gaps carried forward (not resolved by this change)

- **No per-phase/tier model routing.** `AgentRequest`/`AgentModelClient`
  resolve to exactly one globally-configured model — there is no
  `ModelPhase` concept, no "Settings → Models" per-phase UI. See
  proposal.md's Non-goals and design.md §6 for why, and what's needed
  to add it later.
- **No `AutomationConfidence` type, no budget/usage-window consent
  gate.** `AgentOverageDetectedEvent` is surfaced informationally only —
  nothing in Claude Agent SDK exposes a way to check remaining
  plan-usage-window budget proactively, so a real predictive consent
  gate isn't buildable yet. See proposal.md's Non-goals.
- **No coding-execution tool access.** Every call this MVP makes runs
  with file/git/bash/MCP tools disabled. A tool-enabled mode for actual
  coding-execution tasks is unbuilt — no caller needs it yet.
- **Only Claude Agent SDK is configurable.** Anthropic Messages API,
  Ollama, OpenAI, OpenAI-compatible, and Firebase AI Logic — all still
  described in `project.md` §5 — remain unbuilt. Mobile/web have no
  working provider at all after this change (Agent SDK is desktop-only).
- **No live model-list discovery.** `AgentModel`'s three values are a
  fixed enum; unlike Ollama's planned `/api/tags` fetch, Agent SDK has
  no equivalent endpoint to query at settings-save time.
