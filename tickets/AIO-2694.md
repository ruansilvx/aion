# Post-`/verify` fixes (second pass — 2 WARNING findings)

A second `/verify` pass (after T31-T35 landed) found 2 non-blocking
WARNING findings. Fixed below.

- [x] T36. `test/features/tickets/cubit/tickets_cubit_test.dart` —
      T32's `TicketDetailLoaded.copyWith` fix (field preservation across
      `_resolveAndFireAttachment`'s `gated` branch,
      `confirmPendingSkillAttachment`, and
      `rejectPendingSkillAttachment`) was verified only by reading
      `copyWith`'s implementation, not exercised by a test that could
      actually fail if one of those three call sites regressed back to a
      bare `TicketDetailLoaded(ticket)` construction. A seeded-upfront
      field (e.g. `childDocs`) turned out not to be a usable
      differentiator: `updateTicketStatus` always transitions live
      `state` through `TicketStatusUpdating`/`TicketStatusUpdated`
      (list-view states) before `_refreshDetailIfOpenAndAffected`
      re-derives a fresh `TicketDetailLoaded` via `getTicketById` —
      which finds no `previousDetail` (state is no longer
      `TicketDetailLoaded` at that point) and so legitimately resets
      `childDocs`/`isExecuting`/etc. to their defaults *before* any T32
      call site runs, identically with or without the fix. Fixed: three
      new test cases use a stage-less epic instead, whose
      `canAdvanceSddStage` `getTicketById` freshly computes `true` (via
      `_sddStageAdvanceCheck`'s `case null` branch, no extra repository
      mocking needed) immediately before each call site runs — a
      genuinely non-default value only `copyWith` (not a bare
      reconstruction) would carry through. `advanceSddStage`'s
      gated/manual branch was investigated too, but its own copyWith
      call is immediately preceded, within the same method, by an
      unconditional pre-existing bare `TicketDetailLoaded(refreshed,
      isAdvancingStage: true)` emission (predating this feature,
      out of T32's 4-call-site scope) that already resets every other
      field first — meaning no field can reach that specific copyWith
      as non-default either way, so no test was added there; the
      dartdoc-level fix (routing through `copyWith` regardless) still
      stands, just without an observable-difference regression test.
- [x] T37. `presentation/widgets/ticket_metadata_section.dart` /
      `presentation/screens/ticket_detail_screen.dart` —
      `_RunAttachedSkillButton` was rendered as a standalone block above
      Description instead of Component Spec §7's specified placement
      ("on the meta line of the ticket detail header block, after the
      type chip + status indicator, wrapping to its own line beneath
      them on narrow width"), a self-disclosed simplification made
      during `/apply` to avoid a deep edit inside
      `TicketMetadataSection`. Fixed: moved the `_RunAttachedSkillButton`
      widget (and its own private `_KindGlyphMini` glyph, duplicated
      per this file's existing `_KindGlyphMini`-duplication convention)
      into `ticket_metadata_section.dart`, appended to the existing
      type-chip/status-indicator meta line, converting that line's
      `Row` to a `Wrap` (`spacing: 8, runSpacing: 8`) so it wraps to its
      own line on narrow width per spec, rather than overflowing.
      `_PendingSkillAttachmentBanner` was already spec-compliant
      (Component Spec §6's placement matches its existing location
      verbatim) and is unchanged.
