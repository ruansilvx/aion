# Spec delta: Release preparation and tagging

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/projects.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (31/33 identifiers confirmed verbatim; the rest are prose/filename references, not drift). Delta against `aion-arch/specs/projects.md`, `aion-arch/specs/tickets.md`,
and `aion-arch/specs/release.md`. Read alongside `proposal.md`/`design.md`
— this file only states what's ADDED/MODIFIED/REMOVED, not full

## `aion-arch/specs/projects.md`

### ADDED

- `ProjectStackDetector` gains `detectVersionFile(rootPath)` and
  `writeVersion(detected, newVersion)`, alongside the existing `detect`.
  Unlike `detect`'s output (`DetectedStack`, guidance text only —
  "never a value Aion's own code runs or enforces"), `detectVersionFile`'s
  output (`DetectedVersionFile`) *is* read and written by Aion's own code
  — the first real, programmatic consumer of stack-detection output.
  Real read/write support covers `pubspec.yaml`, `package.json`,
  `Cargo.toml`, and `pyproject.toml` (PEP 621 `[project]` layout only);
  `go.mod` and `requirements.txt` remain detected for guidance text but
  have no version-file support (no in-file semver concept for the
  former, no project-metadata field at all for the latter).

### MODIFIED

- None. `detect`/`DetectedStack`'s existing guidance-text behavior is
  unchanged.

## `aion-arch/specs/tickets.md`

### ADDED

- A `release`-type ticket's detail screen now renders a **Release
  section** after the Content block — previously `release` was one of
  the ticket types excluded from the Documentation-mode sections block
  entirely (`page`/`chat`/`idea`/`knownGap`/`openQuestion`/`release`),
  meaning it rendered no content about its own linked work. This new
  section lists every `relatesTo`-linked `epic`/`story`/`task`/`bug` (via
  the existing `LinkedTicketsSection` molecule) and hosts a new
  **Prepare Release** action. This closes the "no dedicated
  assign-to-release UI" known gap for the *viewing* side; creating the
  links themselves still goes through the existing generic
  `TicketLinkPicker` from the linked ticket's own side, or the Release
  Planning inbox chat, or the new auto-population path below — no
  release-specific link-creation UI is added by this change.
- `InboxScreen` gains a fifth launcher card, "Cut a release", alongside
  the existing four purposes. Unlike those four, it does not spawn a
  chat ticket and is **not** a new `InboxPurpose` value — it fires
  immediately (`TicketsCubit.autoCreateReleaseTicket`), auto-creating a
  `release` ticket and linking every `epic`/`story`/`task`/`bug` at the
  project's `done`-role status not yet linked to any existing `release`
  ticket, then navigates directly into that new ticket's detail screen.
- `TicketsCubit` gains `prepareReleaseDraft(releaseTicketId)`,
  `autoCreateReleaseTicket()`, and `confirmRelease(draft)` — see
  `design.md` §4 for full behavior. `prepareReleaseDraft` resolves
  `ModelPhase.capable` (an `AgentModelClient.run` call) to draft
  changelog prose and a suggested semver bump from a release ticket's
  linked work; `confirmRelease` writes `CHANGELOG.md`, bumps the
  detected version file (when one exists), commits, tags
  (`GitRepositoryClient.tag`, new method), and pushes both the commit
  and the tag (`GitRepositoryClient.pushTag`, new method) — only once
  the user explicitly confirms the drafted content via
  `ReleaseDraftScreen` (new screen, pushed from the new Release
  section's Prepare Release button, not a router-addressable route).
- `TicketsErrorReason` gains `releasePreparationFailed`, mapped to a new
  toast string, mirroring the existing `specWriteFailed` entry's shape.
  Emitted when `prepareReleaseDraft`'s model call fails; the release
  ticket's own state is never touched by that failure.
- `GitRepositoryClient` gains `tag(rootPath, tagName, message)` and
  `pushTag(rootPath, tagName)`, mirroring the existing `_runChecked`
  error-handling shape used by `push`/`createWorktree`.
- A new domain entity, `ReleaseDraft` (in-memory only, no persistence) —
  carries a release ticket id, its linked-ticket ids, AI-drafted
  changelog markdown, a suggested version, and an optional
  `DetectedVersionFile`. Exists only between drafting and confirming (or
  discarding) a release; nothing about a discarded draft is persisted.

### MODIFIED

- None to existing behaviors — the Release Planning inbox chat
  (`startReleasePlanning`/`handleReleasePlanningReply`) is unchanged;
  curated-mode population continues to work exactly as it does today,
  now simply followed by the new Prepare Release action once a release
  ticket exists.

## `aion-arch/specs/release.md`

### ADDED

- A new, Aion-native path to drafting a release exists alongside
  `/prepare-release` (the Claude Code skill, itself unmodified by this
  change): from a `release` ticket's own detail screen (curated) or the
  Inbox's "Cut a release" launcher (auto), Aion drafts a changelog entry
  and version bump using its own per-project model routing, and — on
  explicit user confirmation — writes `CHANGELOG.md`, bumps the detected
  version file, commits, and creates/pushes the version tag itself
  (`GitRepositoryClient.tag`/`.pushTag`). This still stops at the tag
  push: whatever CI (if any) reacts to that tag — as
  `aion/.github/workflows/release.yml` already does for Aion's own
  repo — remains entirely the target project's own concern, unchanged
  by this addition.

### MODIFIED

- None. The existing `/prepare-release` skill, `CHANGELOG.md` convention,
  and CI workflow description all remain accurate as written; this
  change adds an alternative preparation path, it does not alter the
  existing one.

### Known gaps — update at archive time

- "The release pipeline has never been exercised by a real tag push" —
  unaffected by this change directly (this change adds a *second* way to
  prepare a release, it doesn't itself push a tag for Aion). Still open
  until an actual `v*.*.*` tag is pushed, per
  `aion-arch/ideas/release-pipeline-dry-run-via-tag-push.md`.
