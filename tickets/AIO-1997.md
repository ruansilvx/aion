# Spec Delta: Show a last-updated timestamp on each ticket's detail screen

**Reconciled 2026-09-03:** confirmed against the current `aion-arch/specs/tickets.md` "Live-updating the detail screen's 'Updated' label" section — `detailTick`/`startDetailTicker`/`stopDetailTicker` and the mechanism described here still match current text verbatim (a few identifiers were missed by the automated check only because they wrap across lines in the source prose, e.g. `TicketsCubit`
`.detailTick`). No drift.

Relative to `aion-arch/specs/tickets.md` as it stands before this
change.

## ADDED

- **`TicketMetadataSection` "Updated" line.** Directly below the
  existing "Created {date}" line, an always-rendered "Updated
  {relative}" line (`AionText.time`/`c.textMuted`, matching the
  "Created" line's styling), where `{relative}` is
  `formatRelativeTime(ticket.updatedAt)` (`core/utils/
  relative_time_format.dart` — already shipped for
  `InboxHistoryItem`, reused unchanged here). Renders unconditionally,
  including when `ticket.updatedAt == ticket.createdAt` (an unedited
  ticket). Present for every ticket type that reaches
  `TicketMetadataSection` — the same set the existing "Created" line
  already covers, including `chat`-type tickets via
  `ChatTranscriptPane`'s collapsing header.
- **`TicketsCubit.detailTick`.** A broadcast `Stream<void>` that pulses
  once every 60 seconds while running, driven by a private
  `Timer.periodic` — same "transient stream outside `TicketsState`"
  shape as the existing `codebaseAnalysisStatus`. Started by
  `TicketsCubit.startDetailTicker()`, stopped by
  `TicketsCubit.stopDetailTicker()`; both are idempotent. Exists so the
  new "Updated" line can advance on its own while `TicketDetailScreen`
  is open, independent of any write to the ticket.
- **`TicketDetailScreen` ticker lifecycle.** `initState` calls
  `TicketsCubit.startDetailTicker()`; `dispose` calls
  `TicketsCubit.stopDetailTicker()` — the same "screen registers on
  mount, unregisters on unmount" shape this screen already uses for
  `ActiveTicketViewRegistry`.
- **`ticketDetailLastUpdated` l10n key** (`lib/l10n/app_en.arb`):
  `"Updated {relative}"`, one `relative` `String` placeholder —
  sibling to the existing `ticketDetailCreatedOn`.
- **Test coverage for `formatRelativeTime`**
  (`test/core/utils/relative_time_format_test.dart`) — previously
  untested; now covers every bucket boundary the function has,
  matching `formatTrashedAge`'s existing coverage shape in the same
  file.

## MODIFIED

- **`test/features/tickets/presentation/widgets/ticket_metadata_section_test.dart`'s
  `_wrap` helper** — `MockTicketsCubit` now also stubs `.detailTick`
  (`Stream<void>.empty()`), since `TicketMetadataSection` calls it
  unconditionally once this change lands and every existing test in
  this file renders `TicketMetadataSection` through `_wrap`.

## REMOVED

Nothing.

## Not affected (explicitly out of scope)

- `TicketListTile`, `TicketBoardCard` — no "Updated" indicator added to
  either (see proposal.md's Scope).
- `Ticket` entity, `TicketRepository`, `TicketDao` — `updatedAt`'s
  read/write behavior is entirely unchanged; this is a pure
  presentation-layer addition reading an already-correct field.
- `TicketsState`/`TicketDetailLoaded` — no new state, no new field; the
  new stream lives beside `TicketsState`, not inside it (see
  design.md §2).
