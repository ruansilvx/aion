# Design: Multi-select filters for the ticket list

## 0. Current state (for contrast)

- `TicketRepository.searchTickets({query, status, type, priority, limit,
  offset})` takes one nullable `TicketStatus?`/`TicketType?`/
  `TicketPriority?` each, ANDed with each other and with `query`.
- `TicketDao.searchTickets` builds this two ways depending on whether
  `query` is set: a plain drift `Query` (`.where((t) =>
  t.status.equals(status.name))` etc.) when there's no search text, or a
  raw `customSelect` FTS join (`tickets.status = ?` etc. appended to a
  `conditions` list) when there is.
- `TicketsCubit` remembers the last-used filters in nullable fields
  (`_lastStatus`, `_lastType`, `_lastPriority`) alongside `_lastQuery`,
  re-applying them on `loadMoreTickets()` and every mutation-triggered
  refresh (create/trash/status-change/etc. — ~6 call sites).
- `TicketsListScreen` owns the *selection* itself in three
  `StatefulWidget` fields (`_statusFilter`/`_typeFilter`/
  `_priorityFilter`), each bound to one `AppDropdown<T?>` with `null` as
  its "All ___" sentinel item. A dropdown's `onChanged` does
  `setState(...)` then calls `_runSearch()`, which reads all three
  widget fields plus the search text into one `searchTickets(...)` call.
- No persistence of any kind — filters reset to "All" every time
  `TicketsListScreen` remounts.

## 1. Data model changes

### 1.1 `TicketRepository`/`TicketDao`/`DriftTicketRepository`: single value → `Set`

`searchTickets`'s three filter parameters become possibly-empty sets,
replacing the nullable-single-value shape. An empty set means "no
constraint on this field" (replaces `null`); a non-empty set means "match
any of these values" (OR within the field), same as a single value meant
"match exactly this value." Cross-field combination stays AND, unchanged.

```dart
// domain/repositories/ticket_repository.dart
Future<TicketSearchPage> searchTickets({
  String? query,
  Set<TicketStatus> statuses = const {},
  Set<TicketType> types = const {},
  Set<TicketPriority> priorities = const {},
  required int limit,
  int offset = 0,
});
```

`DriftTicketRepository.searchTickets` passes the sets straight through to
`TicketDao.searchTickets` unchanged (it's already a thin passthrough
today — no logic to update beyond the signature).

`TicketDao.searchTickets` gets an `isIn`-based rewrite on both of its
existing paths:

- **No-query (plain drift `Query`) path** — replace each `if (status !=
  null) q.where((t) => t.status.equals(status.name))` with `if
  (statuses.isNotEmpty) q.where((t) =>
  t.status.isIn(statuses.map((s) => s.name)))`. Mirrors
  `getTicketsByParent`'s existing `t.type.isIn(typeNames)` usage
  elsewhere in the same file — not a new pattern for this codebase.
- **FTS (`customSelect`) path** — replace each single `tickets.status =
  ?` condition with a variable-length `tickets.status IN (?, ?, ...)`
  clause, one `?` per selected value, appending one `Variable` per value
  in the same order. Built with a small local helper (e.g. `String
  _inClause(String column, int count) => '$column IN (${List.filled(count,
  '?').join(', ')})'`) shared by all three fields to avoid repeating the
  placeholder-building logic three times.

Both paths keep skipping the condition entirely when the set is empty —
identical to today's `null`-skips-the-condition behav6or, just keyed off
`isEmpty` instead of `== null`.

### 1.2 New: `TicketListFilters` entity

```dart
// domain/entities/ticket_list_filters.dart
class TicketListFilters {
  const TicketListFilters({
    this.statuses = const {},
    this.types = const {},
    this.priorities = const {},
  });

  final Set<TicketStatus> statuses;
  final Set<TicketType> types;
  final Set<TicketPriority> priorities;
}
```

Plain value holder — no behavior. Exists so the persistence repository
has one thing to read/write instead of three parallel get/set method
pairs, and so `TicketsCubit` has one type to pass to/from it.

### 1.3 New: `TicketListFilterRepository` (domain interface)

```dart
// domain/repositories/ticket_list_filter_repository.dart
abstract interface class TicketListFilterRepository {
  /// The persisted filter selection for [projectId]. Returns an
  /// all-empty [TicketListFilters] if nothing has been saved yet for
  /// this project.
  Future<TicketListFilters> getFilters(String projectId);

  /// Persists [filters] for [projectId], replacing whatever was saved
  /// before.
  Future<void> setFilters(String projectId, TicketListFilters filters);
}
```

Plain reads/writes only, no validation — same shape as
`ExecutionContextCapRepository`.

### 1.4 New: `SharedPrefsTicketListFilterRepository` (data impl)

```dart
// data/repositories/shared_prefs_ticket_list_filter_repository.dart
class SharedPrefsTicketListFilterRepository
    implements TicketListFilterRepository {
  String _statusesKey(String projectId) =>
      'ticket_list_filters.$projectId.statuses';
  String _typesKey(String projectId) =>
      'ticket_list_filters.$projectId.types';
  String _prioritiesKey(String projectId) =>
      'ticket_list_filters.$projectId.priorities';

  @override
  Future<TicketListFilters> getFilters(String projectId) async {
    final prefs = await SharedPreferences.getInstance();
    return TicketListFilters(
      statuses: _decode(prefs.getStringList(_statusesKey(projectId)),
          TicketStatus.values),
      types: _decode(prefs.getStringList(_typesKey(projectId)),
          TicketType.values),
      priorities: _decode(prefs.getStringList(_prioritiesKey(projectId)),
          TicketPriority.values),
    );
  }

  @override
  Future<void> setFilters(String projectId, TicketListFilters filters) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setStringList(
        _statusesKey(projectId), filters.statuses.map((s) => s.name).toList());
    await prefs.setStringList(
        _typesKey(projectId), filters.types.map((t) => t.name).toList());
    await prefs.setStringList(_prioritiesKey(projectId),
        filters.priorities.map((p) => p.name).toList());
  }
}
```

(`_decode` is a small private generic helper mapping stored name strings
back to enum values via `.name`, dropping any that no longer match —
guards against a stale saved value if an enum member is ever removed.)

This is the first project-scoped `SharedPreferences` repository in the
codebase — every existing one (`SharedPrefsAutomationSettingsRepository`,
`SharedPrefsModelRoutingRepository`, `SharedPrefsExecutionContextCapRepository`)
uses flat, global keys. The `ticket_list_filters.<projectId>.<field>`
prefix is the convention this change introduces; nothing else adopts it
yet.

`SharedPreferences.setStringList`/`getStringList` are used directly — no
manual join/split encoding needed, since the plugin already supports
string lists natively.

## 2. `TicketsCubit` changes

### 2.1 Fields: nullable single value → `Set`, plus new dependencies

```dart
Set<TicketStatus> _lastStatuses = const {};
Set<TicketType> _lastTypes = const {};
Set<TicketPriority> _lastPriorities = const {};
```

Replaces `_lastStatus`/`_lastType`/`_lastPriority`. Every existing call
site that reused them (`loadMoreTickets`, the create/trash/status-change/
etc. mutation-refresh methods — 6 sites per the current file) is updated
to pass the plural/set-typed names through unchanged in spirit: still
"whatever `searchTickets` was last called with."

New optional constructor dependency, following the file's own established
optional-dependency convention (see `_baselineRepository`/`_projectId`/
etc.'s existing dartdoc block):

```dart
final TicketListFilterRepository? _filterRepository;
```

`null` (the default) makes filter selection behave exactly like today,
just in-memory and unpersisted — every existing test/call site keeps
working unchanged. Real usage (`app_router.dart`) always supplies one,
alongside the already-supplied `_projectId`.

### 2.2 `searchTickets` signature

```dart
Future<void> searchTickets({
  String? query,
  Set<TicketStatus> statuses = const {},
  Set<TicketType> types = const {},
  Set<TicketPriority> priorities = const {},
}) async { ... }
```

Body unchanged in structure — still remembers the args into
`_lastQuery`/`_lastStatuses`/`_lastTypes`/`_lastPriorities`, bumps
`_searchGeneration`, calls `_repository.searchTickets(...)`, emits
`TicketsLoading`/`TicketsLoaded`/`TicketsError` exactly as today. This
method's contract is otherwise unchanged: still the sole entry point
`TicketsListScreen` uses to load its list, still "all parameters
omitted" == unfiltered pagination.

### 2.3 New: selection getters

```dart
Set<TicketStatus> get selectedStatuses => _lastStatuses;
Set<TicketType> get selectedTypes => _lastTypes;
Set<TicketPriority> get selectedPriorities => _lastPriorities;
```

Read by `TicketsListScreen` to build the popover's checked state and the
chip row — plain getters, not part of `TicketsState`, since they're
metadata about the *last search's params*, not the list-loading
lifecycle `TicketsState`'s sealed hierarchy models. The screen already
sits under a `BlocProvider<TicketsCubit>`/rebuilds on every `TicketsState`
change; since every toggle (§2.4) always ends in a fresh `searchTickets`
call that emits a new state, reading these getters from inside the
existing `BlocBuilder<TicketsCubit, TicketsState>` scope stays correctly
in sync without adding filters to `TicketsState` itself.

### 2.4 New: toggle methods

```dart
Future<void> toggleStatusFilter(TicketStatus status) =>
    _toggleFilter(_lastStatuses, status, (s) => searchTickets(
        query: _lastQuery, statuses: s, types: _lastTypes,
        priorities: _lastPriorities));
```

(Illustrative — the three methods, `toggleStatusFilter`/
`toggleTypeFilter`/`togglePriorityFilter`, share one private
`_toggleFilter<T>(Set<T> current, T value, ...)` helper that computes the
new set by add-if-absent/remove-if-present, persists it via
`await _filterRepository?.setFilters(_projectId!, TicketListFilters(...))`
— guarded the same way every other optional-dependency side effect in
this file already is, no-op when `_filterRepository`/`_projectId` is
`null` — then re-runs `searchTickets` reusing `_lastQuery` and the other
two unchanged dimensions.)

Each toggle is a full mutation-refresh in the same shape as the
existing create/trash/status-change refreshes: reuse remembered filters
except the one dimension being changed, request
`limit: _pageSize` (a toggle always starts a fresh filtered view, not a
"keep however many are loaded" continuation — same as a brand new
`searchTickets` call from the screen, not a `loadMoreTickets`-style
append).

A chip's "×" calls the same toggle method with the value it displays —
removing a chip is exactly "toggle this value off," so the popover and
the chip row share one code path with no special-case removal logic.

### 2.5 New: `loadPersistedFilters()`

```dart
Future<void> loadPersistedFilters() async {
  final projectId = _projectId;
  final repo = _filterRepository;
  if (projectId == null || repo == null) return;
  final saved = await repo.getFilters(projectId);
  _lastStatuses = saved.statuses;
  _lastTypes = saved.types;
  _lastPriorities = saved.priorities;
}
```

Populates the remembered-filter fields *without* running a search or
emitting a state — `TicketsListScreen.initState` awaits this once, then
makes its own first `searchTickets()` call reading the now-populated
`selectedStatuses`/etc. getters, exactly mirroring how a normal
filter-driven re-search already works. No new state-emission path is
introduced.

## 3. Widget changes

### 3.1 New: `AppFilterChip` (design-system atom)

`lib/design_system/atoms/app_filter_chip.dart` — a small stateless
label-plus-remove-button primitive, general-purpose (not ticket-specific,
same placement rationale as `AppCheckbox`):

```dart
class AppFilterChip extends StatelessWidget {
  const AppFilterChip({
    super.key,
    required this.label,
    required this.onRemove,
    required this.removeSemanticsLabel,
  });

  final String label;
  final VoidCallback onRemove;
  final String removeSemanticsLabel;
  ...
}
```

Renders a `primarySubtle`-filled, `AionRadius`-rounded pill (reusing
`AppDropdown`'s `isActive` tint formula for visual consistency with the
rest of the filter row) containing `label` (`AionText.chip`, matching
`TypeChip`'s existing type-scale choice) and a small trailing "×"
(`PhosphorIcons.xLight` or similar) wrapped in its own
`FocusableActionDetector`/`GestureDetector`/`MouseRegion` tap target —
built with real Hover/Focused/Pressed states from the start (not a bare
`GestureDetector`), so this new primitive doesn't add a second instance
of the bug already flagged against `AppDropdown`'s overlay rows.

### 3.2 New: `TicketFilterPopover` (ticket-feature widget)

`lib/features/tickets/presentation/widgets/ticket_filter_popover.dart` —
structurally mirrors `SelectionMenu<T>`'s
`LayerLink`/`CompositedTransformFollower`/`OverlayEntry` mechanics
(§Reference below), generalized from one flat single-select list to
three independently-toggleable checkbox groups:

```dart
class TicketFilterPopover extends StatefulWidget {
  const TicketFilterPopover({
    super.key,
    required this.trigger,
    required this.selectedStatuses,
    required this.selectedTypes,
    required this.selectedPriorities,
    required this.onToggleStatus,
    required this.onToggleType,
    required this.onTogglePriority,
  });

  final Widget trigger;
  final Set<TicketStatus> selectedStatuses;
  final Set<TicketType> selectedTypes;
  final Set<TicketPriority> selectedPriorities;
  final ValueChanged<TicketStatus> onToggleStatus;
  final ValueChanged<TicketType> onToggleType;
  final ValueChanged<TicketPriority> onTogglePriority;
  ...
}
```

The open overlay panel renders three labeled groups in a `Column`
(reusing the existing `ticketsListFilterStatusLabel`/
`ticketsListFilterTypeLabel`/`ticketsListFilterPriorityLabel` l10n
strings as group headers — the same strings today's dropdowns pass as
`semanticsLabel`, now shown visibly since the popover has room for
captions the compact three-dropdown row didn't). Each row is one
`OverlayMenuItem` (not a bare `GestureDetector` — this is the same fix
`SelectionMenu`/`TicketOverflowMenu`/`MoveToStatusMenu` already have,
applied to a brand-new widget instead of retrofitted onto `AppDropdown`)
wrapping an `AppCheckbox` plus the item's label
(`ticketStatusLabel`/`ticketTypeLabel`/`ticketPriorityLabel`, the same
helpers the current dropdowns already use). Tapping anywhere in the row
(not just the checkbox glyph) toggles it — `OverlayMenuItem.onTap` calls
the relevant `onToggleX` directly, `AppCheckbox` inside is presentational
only (`enabled: false`-equivalent tap passthrough, matching how
`TicketListTile`'s own leading `AppCheckbox` already works inside a
tappable row in selection mode).

The Type group uses the same hardcoded, client-side-filtered item list
`TicketsListScreen` already hardcodes today (`epic`, `story`, `task`,
`bug`, `chat` — `page`/`resource` excluded, `signal`/`release` excluded
as a pre-existing gap) — this change doesn't touch that exclusion list,
just re-renders it as checkboxes instead of dropdown items.

Unlike `AppDropdown`/`SelectionMenu`, selecting an item never closes the
popover (multi-select needs to stay open across several taps) — only the
existing "tap outside" (`Positioned.fill` translucent `GestureDetector`,
same as both reference widgets) or a keyboard `Escape` dismisses it.

### 3.3 `TicketsListScreen` changes

- Remove `_statusFilter`/`_typeFilter`/`_priorityFilter` fields and the
  three `AppDropdown` widgets from the filter row.
- Add a "Filters" trigger button in their place — same row, same
  `Expanded`/spacing rhythm the three dropdowns used, now one button.
  Shows `context.l10n.ticketsListFilterTriggerLabel` ("Filters") plus a
  small count badge (`selectedStatuses.length + selectedTypes.length +
  selectedPriorities.length`) when non-zero, using the same
  `primarySubtle`/`primary` tint `AppDropdown.isActive` already uses, for
  visual continuity with the row it's replacing.
- Wrap the trigger in `TicketFilterPopover`, reading
  `context.watch<TicketsCubit>().selectedStatuses` (etc.) for its checked
  state and wiring `onToggleStatus: context.read<TicketsCubit>().toggleStatusFilter`
  (etc.) directly — no local `setState` involved, since selection state
  now lives entirely in the cubit (§2.3–2.4).
- Add a chip row below the trigger row, built from the same three
  `selectedX` getters, each rendered as an `AppFilterChip` whose
  `onRemove` calls the matching `toggleXFilter` with that chip's value.
  Hidden entirely (zero height, no reserved space) when all three sets
  are empty.
- `_hasActiveFilter` becomes: `_searchController.text.trim().isNotEmpty
  || cubit.selectedStatuses.isNotEmpty || cubit.selectedTypes.isNotEmpty
  || cubit.selectedPriorities.isNotEmpty` (reading the cubit instead of
  local fields).
- `_runSearch()` reads `cubit.selectedStatuses`/etc. instead of the
  removed local fields when assembling its `searchTickets(...)` call —
  it remains the method the search-text debounce calls; it is *not*
  called by the new toggle handlers (§2.4 already re-searches internally
  on every toggle).
- `initState` adds one `unawaited(_initializeAndSearch())` call (same
  fire-and-forget precedent this file already uses for
  `_loadBaselineUpgradeTargetVersion`), where `_initializeAndSearch`
  awaits `context.read<TicketsCubit>().loadPersistedFilters()` then calls
  `_runSearch()` — replacing the bare synchronous `_runSearch()` call
  `initState` makes today, so the very first search after opening the
  ticket list already reflects the persisted selection instead of
  flashing an unfiltered list first.

Board-mode's existing client-side `(t) => t.type == TicketType.story ||
t.type.isExecutable` restriction (`tickets_list_screen.dart`, applied to
whatever `TicketsLoaded.tickets` already contains) is untouched — it
composes the same way regardless of how many types were DB-filtered by
the new multi-select Type group.

# Aion — Multi-Select Ticket Filters: Component Spec

Implementation-ready spec for replacing the ticket list's three single-select `Status` / `Type` / `Priority` dropdowns (see [Aion Ticket Search & Filters Spec](./Aion%20Ticket%20Search%20and%20Filters%20Spec.md) §3) with **one combined "Filters" trigger button** that opens a multi-select checkbox popover, plus a **removable chip row** underneath showing the active selection. All within the existing `TicketsListScreen` — no new screens.

**No Material widgets or types anywhere.** Every component below is built from `flutter/widgets.dart` primitives only: `DecoratedBox`, `Container`, `GestureDetector`, `MouseRegion`, `FocusableActionDetector`, `CustomPaint`, `Row`, `Column`, `Wrap`, `Align`, `Padding`, `Overlay` / `OverlayEntry` / `CompositedTransformFollower`. Never `Card`, `ElevatedButton`, `Scaffold`, `Chip`, `Checkbox`, `PopupMenu*`, `ThemeData`, `ColorScheme`, or any `material.dart` import.

- `c` = active `AionColors`; `a` = theme `fillAlpha` (Arctic `0.11` / Obsidian `0.16`); `isDark` = Obsidian. Both themes share **one** code path; only token values differ. Where a component is identical across themes it is stated explicitly.
- Existing primitives reused unchanged: `AppCheckbox`, `OverlayMenuItem` (row-fill formula), `AppDropdown`'s `isActive` trigger language, the `SelectionMenu` elevated-panel treatment. New atoms introduced: `AppFilterChip` (§2) and the `TicketFilterButton` (§3) / `TicketFilterPopover` (§4) composition.
- Companion mockups: `Aion Multi-Select Filters Mockups.dc.html` (Arctic + Obsidian; trigger idle `1a`, active + chip row over list `2a`, popover open `3a`, control states `4a`).

## 1. Toolbar composition

### 1.1 Layout & placement

The toolbar keeps the search field on top and replaces the three-dropdown `Row` with a **trigger row** (a single left-aligned "Filters" button) followed by a **conditional chip row**:

```
Header block  (Column, crossAxisAlignment: stretch)
├─ Title row              (existing: AION · MAIN / Tickets / avatar)
├─ SizedBox(height: 16)
├─ Search field           (§2 of Search spec — unchanged)
├─ SizedBox(height: 10)
├─ Trigger row            (§3 — Filters button, left-aligned, size-to-content)
└─ Chip row               (§5 — conditional; zero height when no filters active)
List body                 (top border, ticket rows / empty state)
```

- **Header block padding:** `EdgeInsets.fromLTRB(20, 8, 20, 14)` (unchanged).
- **Search-to-trigger gap:** `10` (unchanged from the old filters-to-search gap).
- **Trigger-to-chip-row gap:** `AionSpacing.sp8` (8) — applied **only** when the chip row is visible; collapsed with it otherwise (§5.4).
- **Chip-row-to-list gap:** none — the list body's own 1px top `border` is the divider, flush under the `14px` header bottom padding, exactly as today. When the chip row is hidden the trigger row sits directly above that border.

**Rationale for one trigger, not `Expanded`:** the button is size-to-content and left-aligned (not stretched across the row like the three old dropdowns) — a lone full-width button reads as a text field, not an action, and stretching it wastes the horizontal space the count badge makes unnecessary. Left-aligned at natural width matches how a single action control reads in the rest of the app.

### 1.2 Trigger row

```dart
Align(
  alignment: Alignment.centerLeft,
  child: TicketFilterButton(activeCount: n, onTap: _openPopover),
)
```

Single child, `centerLeft`, natural width. The row's height is the button's height (§3), keeping the same vertical rhythm the old dropdown row occupied.

## 2. `AppFilterChip` — new design-system atom

A small removable pill representing **one** active filter value: a label plus a trailing "×" tap target. A chip only ever represents an *active* filter, so it has a single resting appearance (there is no "inactive chip") — it borrows `AppDropdown`'s `isActive` color language (`primarySubtle` fill, `primary` border + text) for continuity with the trigger it summarizes. The **label is not interactive**; only the "×" is a tap target, and only the "×" carries hover / focus / pressed states.

### 2.1 Dimensions & layout

- **Height:** `26` (driven by padding; fixed so a `Wrap` of chips aligns on one baseline).
- **Padding:** `EdgeInsets.fromLTRB(9, 4, 4, 4)` — tighter on the right so the "×" hit-slop reaches the chip edge.
- **Layout:** `Row(mainAxisSize: MainAxisSize.min, crossAxisAlignment: center)` → label, `SizedBox(width: 4)`, "×" target.
- **Border radius:** `AionRadius.sm` (6) — matches the `TypeChip` rounded-rect family.
- **Border:** `1px c.primary`.
- **Fill:** `c.primarySubtle`.
- **Shadow:** none.

### 2.2 Label

- **Text style:** `AionText.bodySm` sized (13.5) is too tall for a 26px pill; use a dedicated compact style — Manrope **12 / w700**, color `c.primary`, `maxLines: 1`, no ellipsis (chips are short values). If a shared token is preferred, this equals a `chipLabel` derived from `AionText.chip` (Manrope w700) at 12px **without** the 0.53 tracking and **without** forced uppercase (filter values like "In Progress" must keep natural case). See §7.
- **Color:** `c.primary` (both themes; token-driven).

### 2.3 The "×" remove target

- **Glyph:** a thin "×" (`PhosphorIcons.xLight` or a 1.5px `CustomPaint` cross), **12px**.
- **Tap target:** a `20×20` square centered on the glyph (`GestureDetector` + `MouseRegion(cursor: click)`); the 26px chip height plus the 4px right padding keeps the full target inside a comfortable reach without enlarging the pill.
- **Corner radius of the ×'s own hover wash:** `AionRadius.iconBtnSm` (8), inset inside the chip's right edge.

#### 2.3.1 "×" states

| State | Glyph color | Wash behind glyph |
|---|---|---|
| **Default** | `c.primary` | none |
| **Hover** | `c.primaryHover` | `c.primary.withOpacity(a)` (`0.11 / 0.16`) |
| **Focused** (keyboard focus on the ×) | `c.primary` | `c.primary.withOpacity(a)` **plus** a `1px` inset ring `c.primary.withOpacity(isDark ? 0.30 : 0.16)` |
| **Pressed** | `c.primaryHover` | `c.primary.withOpacity(a * 1.6)` (`0.176 / 0.256`) |
| **Disabled** | n/a — a chip is never disabled (removing it is always available) | — |

- **Focus traversal:** each chip's "×" is a focus stop in visual order; `Enter` / `Space` removes the chip (same as tap). `FocusableActionDetector` supplies the node + `ActivateIntent` binding.
- **Removal:** `onRemove` clears that one value from its field's selection set; the list re-filters immediately (§6). If it was the **last** active value the chip row collapses (§5.4).
- **Transition:** the wash animates via `AnimatedContainer(duration: 100ms, curve: Curves.easeOut)` — matching `OverlayMenuItem` §1.6.

### 2.4 Semantics

`Semantics(button: true, label: 'Remove filter: <value>')` on the "×" target. The chip label itself is not a button (`Semantics(label: <value>)` only).

**Theme note:** identical structure both themes; only token values differ (Arctic `primary #2E86D4` / `primarySubtle #DBE9F7`; Obsidian `primary #9366FF` / `primarySubtle #241F3E`).

## 3. `TicketFilterButton` — the "Filters" trigger

Replaces the three-dropdown row (§1.2). Two visual sub-states — **idle** (no filters active) and **active** (N filters active) — mapped directly onto `AppDropdown`'s inactive / `isActive` language for continuity with the row it replaces, plus a trailing count badge in the active state.

Built as `FocusableActionDetector → MouseRegion → GestureDetector → AnimatedContainer`. `Enter` / `Space` and tap both call `onTap` (open the popover).

### 3.1 Dimensions & layout (both sub-states)

- **Height:** `36` (driven by padding; matches the ≈34–36 rhythm the old `Expanded` dropdowns occupied).
- **Padding:** `EdgeInsets.symmetric(horizontal: 12, vertical: 8)`.
- **Layout:** `Row(mainAxisSize: MainAxisSize.min, gap via SizedBox)` → leading funnel icon, `SizedBox(width: 8)`, `"Filters"` label, [active only: `SizedBox(width: 8)` + count badge].
- **Border radius:** `AionRadius.lg` (12).
- **Leading icon:** funnel / sliders glyph (`PhosphorIcons.funnelLight` or `slidersHorizontalLight`), **16px**.
- **Label:** `"Filters"`, `AionText.button` (Manrope 14 / w700).
- **Shadow:** none.

### 3.2 Idle sub-state (no filters active) — states

Matches `AppDropdown` inactive (§3.1 of Search spec).

### 3.3 Active sub-state (N ≥ 1 filters active) — states

Matches `AppDropdown` `isActive` (§3.2 of Search spec), plus the count badge (§3.4). The leading `6×6` dot `AppDropdown` uses is **replaced** by the count badge — the badge is the richer active signal, so a redundant dot is omitted.

| State | Fill | Border | Icon color | Label color |
|---|---|---|---|---|
| **Default** | `c.primarySubtle` | `1.5px c.primary` | `c.primary` | `c.primary` |

A small filled pill carrying the active-filter count, trailing the label. Shown **only** in the active sub-state.

## 4. `TicketFilterPopover` — the open overlay panel

An overlay panel anchored under the trigger, hosting three independently-toggleable checkbox groups. **Stays open across taps** (multi-select — no auto-close on selection, unlike the old single-select `AppDropdown`); dismissed only by tapping outside or pressing `Escape`.

### 4.1 Container

Matches the `SelectionMenu` elevated-panel treatment (same as `AppDropdown`'s overlay, §3.5 of Search spec).

- **Fill:** `c.surface`.
- **Border:** `1px c.borderStrong`.
- **Border radius:** `AionRadius.lg` (12), `clipBehavior: Clip.antiAlias` (so first/last row washes clip to the corners).
- **Shadow:** `BoxShadow(color: Color.fromRGBO(0, 0, 0, isDark ? 0.55 : 0.30), offset: Offset(0, 20), blurRadius: 40, spreadRadius: -14)`.
- **Width:** `min(260, availableWidth - 40)` — wide enough for the longest row label ("All priorities" scale content) without stretching to the trigger's narrow width. Anchored left-aligned to the trigger.
- **Panel padding:** `EdgeInsets.symmetric(vertical: 8)` (top/bottom breathing room; horizontal padding lives on rows and headers, not the panel).
- **Position:** `top: triggerHeight + 6`, left-aligned to the trigger via `CompositedTransformFollower`. If it would overflow the bottom edge it flips to open upward (`targetAnchor: topLeft` / `followerAnchor: bottomLeft`).
- **Max height / scroll:** `maxHeight: min(availableHeight - anchorBottom - 16, 420)`; contents in a `SingleChildScrollView` when they exceed it. At the three groups' natural size (≈ 12 rows) they fit without scrolling on a phone.

### 4.2 Dismissal

- **Tap outside:** a full-screen transparent `GestureDetector` barrier behind the panel (part of the `OverlayEntry`) closes on tap.
- **Escape:** a `Shortcuts` / `Actions` pair (`DismissIntent` → close) while the panel owns focus.
- **No close button, no "Apply".** Selections apply live (§6); the panel is purely a picker.

### 4.3 Group structure

Three groups stacked vertically in order **Status · Type · Priority**, each a caption header followed by its rows, separated by a divider:

```
Column(crossAxisAlignment: stretch)
├─ _GroupHeader('Status')
├─ _CheckRow(...) × status options
├─ _GroupDivider()
├─ _GroupHeader('Type')
├─ _CheckRow(...) × type options
├─ _GroupDivider()
├─ _GroupHeader('Priority')
└─ _CheckRow(...) × priority options
```

### 4.4 `_GroupHeader`

- **Text:** the field name, `AionText.caption` (JetBrains Mono 11 / w600 / tracking 1.54), **UPPERCASE**, color `c.textMuted`.
- **Padding:** `EdgeInsets.fromLTRB(13, 8, 13, 6)` — the first header's top padding sits inside the panel's own `8` vertical padding, giving a comfortable ~16 above the first group.
- **Fill / border:** none (non-interactive, no focus stop).

### 4.5 `_CheckRow` — one option row

Full-row tap target (not just the checkbox). Reuses the **`OverlayMenuItem` neutral row-fill formula** (see [Overlay Menu Item Spec](./Aion%20Overlay%20Menu%20Item%20Spec.md) §1.3): resting transparent → hover/focus `surfaceHover` → pressed `border`, animated 100ms `easeOut`. Tapping the row toggles the checkbox (it does **not** close the panel).

- **Row layout:** `Row(crossAxisAlignment: center)` → `AppCheckbox`, `SizedBox(width: 10)`, [optional accent dot/square], label, `Spacer` (so the whole width is the target).
- **Row padding:** `EdgeInsets.symmetric(horizontal: 13, vertical: 8)` → row height ≈ 36 (the 20px checkbox + 2×8 padding).
- **Checkbox:** `AppCheckbox`, `20×20`, reused verbatim — unchecked `surface` fill / `borderStrong` border (`primary` on hover), checked `primary` fill/border + white check, focus 3px-spread `primary` glow (`0.30 / 0.16`). The row's own hover fill and the checkbox's hover border co-occur (both driven by the same row hover) — intended.
- **Label:** `AionText.bodySm` (13.5 / w400), color `c.textPrimary`. Checked rows keep the same label weight/color — the checkbox is the state signal, not the text.
- **Optional leading accent** (between checkbox and label, `gap: 8`), reusing each field's existing badge color so a row echoes how the value looks elsewhere in the app:
  - **Status:** `8×8` dot — Backlog `c.textMuted`, In Progress `c.primary`, Done `c.success`.
  - **Type:** `10×10` rounded square (`radius 2`) in the type accent — Task `c.typeTask`, Story `c.typeStory`, Epic `c.typeEpic`, Bug `c.typeBug`, etc.
  - **Priority:** `8×8` dot in the level's `fg` — `c.priority.criticalFg` / `highFg` / `mediumFg` / `lowFg`.

#### 4.5.1 `_CheckRow` states

| State | Row fill | Checkbox | Label |
|---|---|---|---|
| **Default (unchecked)** | transparent | `surface` fill / `borderStrong` border | `textPrimary` |
| **Default (checked)** | transparent | `primary` fill/border + white ✓ | `textPrimary` |
| **Hover** | `c.surfaceHover` | checkbox border → `c.primary` (unchecked) / `c.primaryHover` fill (checked) | unchanged |
| **Focused** | `c.surfaceHover` (same as hover) | + checkbox's own 3px focus glow if focus is on the box; row focus alone paints only the row wash | unchanged |
| **Pressed** | `c.border` | unchanged | unchanged |
| **Disabled** | transparent, whole row `opacity: 0.45`, no focus stop | dimmed | dimmed |

- **Focus model:** the **row** is the focus stop (`FocusableActionDetector` on the row), `Enter` / `Space` toggles. The `AppCheckbox` inside is presentational here (its own focus ring only appears if a caller ever focuses the box directly; in this composition the row owns focus). On open, the popover autofocuses the **first row of the Status group**.
- **Transition:** 100ms `Curves.easeOut` fill fade (matches `OverlayMenuItem` §1.6).

### 4.6 `_GroupDivider`

- **Line:** `1px c.border`, full panel width.
- **Vertical spacing:** `SizedBox(height: 8)` above and below the line (so groups read as visually separated: ~8 + hairline + 8 between the last row of one group and the next group's header, versus 0 extra between rows within a group). The header's own `8` top padding compounds to give a clear group break without a heavy rule.
- Non-interactive; no focus stop.

**Theme note:** identical structure both themes; only token values differ.

## 5. Chip row layout

Renders one `AppFilterChip` (§2) per currently-selected value across all three fields. **Visibility + one-tap removal only** — it is not a second way to *add* filters (adding is the popover's job).

### 5.1 Order & content

Chips flow in field order (all Status values, then Type, then Priority), each in the order they appear in the popover. Each chip's label is the value's display name ("In Progress", "Backlog", "Bug", "High"). No field-name prefix on the chip — the popover is where fields are named; the chip row is a flat "what's on" summary.

### 5.2 Wrapping & spacing

- **Container:** `Wrap(spacing: 8, runSpacing: 8)` — chips flow left-to-right and wrap to a new run when the row is full; every gap (horizontal and between runs) is `AionSpacing.sp8` (8).
- **Alignment:** `WrapAlignment.start`, left-aligned under the trigger.
- **Top gap:** `AionSpacing.sp8` (8) below the trigger row (§1.1) — applied only when visible.
- **Bottom:** nothing extra; the header block's existing `14` bottom padding is the gap to the list's top border.

### 5.3 No "clear all"

No aggregate "Clear all" control in the chip row for this iteration — each chip's "×" clears its own value, and re-opening the popover to uncheck is the bulk path. (A future "Clear all" text button could sit at the end of the `Wrap`; out of scope here — noted so a reviewer knows it was considered, not missed.)

### 5.4 Collapsed (no filters active) state

When zero values are selected the chip row occupies **zero height** — not an empty `Wrap`, not a placeholder, not the `8` top gap. Implement as a conditional child so nothing is laid out:

```dart
if (activeValues.isNotEmpty) ...[
  const SizedBox(height: AionSpacing.sp8),
  Wrap(spacing: 8, runSpacing: 8, children: activeValues.map(...).toList()),
],
```

The trigger row then sits directly on the list's top border, identical to the pre-feature layout. Appearance/disappearance of the row animates with the same 120ms list cross-fade if desired, but zero reserved height when empty is the hard requirement.

## 6. Behavior

- **Multi-select semantics:** each field holds a `Set<T>` of selected values. Empty set = "no filter on this field" (equivalent to the old "All ___"). The list matches a ticket when, **for every field with a non-empty set**, the ticket's value is in that set (AND across fields, OR within a field).
- **Live apply:** toggling a checkbox or removing a chip re-filters the list **immediately** (no debounce, no "Apply" button) — same immediacy the old dropdown selections had. Search text keeps its `250ms` debounce (unchanged).
- **Result transition:** the list body reuses the existing `120ms` opacity cross-fade (Search spec §5) on result-set change.
- **Active count** feeding the trigger badge (§3.4) = total selected values across all three fields (`status.length + type.length + priority.length`).
- **Empty state:** the existing "No tickets match your search" empty state (Search spec §4) covers a zero-match filter combination unchanged.

## 7. New tokens

Almost none. Every color, radius, and spacing value resolves to existing `AionColors`, `AionRadius`, and `AionSpacing` tokens, or to explicit multiples of 4 already used by `AppDropdown` / `AppCheckbox`. Two small text styles are the only additions, and only if a shared token is preferred over an inline `TextStyle`:

| Token | Definition | Why nothing existing fits |
|---|---|---|
| `AionText.chipLabel` | `TextStyle(fontFamily: 'Manrope', fontSize: 12, fontWeight: FontWeight.w700, height: 1.0, color: <set at use>)` | `AionText.chip` (10.5, tracking 0.53, pre-uppercased) is built for type-badge glyph labels and forces uppercase + heavy tracking, which mangles natural-case filter values like "In Progress"; `AionText.bodySm` (13.5) is too tall for the 26px chip. A 12/w700 natural-case label is the gap. |
| `AionText.badgeCount` | `TextStyle(fontFamily: 'Manrope', fontSize: 11, fontWeight: FontWeight.w700, height: 1.0, color: Color(0xFFFFFFFF))` | No existing style is an 11px white-on-primary numeral; `AionText.caption` is JetBrains Mono with heavy tracking, wrong for a single digit in a circle. |

Both may instead be written as inline `TextStyle`s at their single use sites if the team prefers not to grow `AionText`. **No new `AionColors`, `AionRadius`, or `AionSpacing` members.** The only explicit non-scale values are the `26` chip height, the `18` badge diameter, and the `6` popover top offset — each intentional and local. Translucent fills are always `token.withOpacity(x)` (the ×-wash `primary @ a`, `primary @ a×1.6`, and focus ring `primary @ 0.30/0.16`) — never hardcoded ARGB.
