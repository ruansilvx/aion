# `lib/features/tickets/presentation/cubit/tickets_cubit.dart`:

**Correction found during `/apply`** — a full-text search of
`_triggerGitProjection(` surfaced five call sites, not three:
`createTicket`, `updateTicketStatus`, `changeTicketStatus` (a
third single-ticket status-change path, from the ticket-detail
screen — also calls `_repository.updateTicketStatus` directly,
so the decorator covers it the same way), the per-id loop inside
the bulk status-update method, **and** `_trashBatchGitSideEffects`
(backs the bulk `trashTickets` cubit method). The first four all
call a repository method the new decorator now projects
(`updateTicketStatus`) — remove those four call sites. The fifth
calls `TicketRepository.trashTickets` (**plural** — a distinct
interface method from `trashTicket`, deliberately *not* added to
the decorator: it exists once, alongside a batched rollup
recompute the cubit sequences after it, and both share the
"concurrent git commands can coalesce into one mislabeled
commit" hazard `TicketRollupRecomputer`'s own batching already
works around — folding it into the decorator would either force
the cubit to block on N sequential git commits before its bulk
trash even reports done, or lose the sequencing guarantee
entirely). **Keep** `_trashBatchGitSideEffects` and its
`_triggerGitProjection` call exactly as they are. Because of
this one remaining legitimate use, **keep** the
`_triggerGitProjection` method itself and the `_gitProjector`
field (do not remove either) — only delete the four now-redundant
call sites. The `gitProjector` constructor parameter already
needed to stay regardless (threaded to the internally-constructed
`TicketRollupRecomputer`/`TicketParentTrashService`), and every
`_projectRootPath` usage unrelated to projection
(`_readTokenFilesForContext`, coding-execution worktree paths,
release version-file detection, etc.) is untouched. Updated the
dartdoc on `_triggerGitProjection` itself and on
`createTicket`/`updateTicketStatus`/`changeTicketStatus`/the bulk
status method to reflect that they no longer call it, and left
`_trashBatchGitSideEffects`'s own dartdoc as-is (still accurate).
