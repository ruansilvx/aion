# Design: Persistent Navigation Shell

## 1. Where this plugs in

`core/routing/app_router.dart` already has a `ShellRoute` wrapping every
`/workspace/*` route, builder-supplied as `WorkspaceShell`:

```dart
ShellRoute(
  builder: (context, state, child) {
    final activeState = context.watch<ActiveProjectCubit>().state;
    return switch (activeState) {
      ActiveProjectOpen(:final project) => WorkspaceShell(
        key: ValueKey(project.id),
        project: project,
        child: child,
      ),
      _ => const SizedBox.shrink(),
    };
  },
  routes: [ /* /workspace/tickets, /workspace/tickets/new, */
            /* /workspace/tickets/trash, /workspace/documentation, */
            /* /workspace/tickets/:id, /workspace/pages/new, */
            /* /workspace/pages/:id */ ],
),
```

Today `WorkspaceShell` only wires per-project repositories/cubits
(`MultiRepositoryProvider` → `BlocProvider<TicketsCubit>` →
`RepositoryProvider<PageTicketProvider>`) and renders `widget.child`
directly — no persistent UI. This change adds one thing: a new
`WorkspaceNavShell` wrapping that innermost `widget.child`.

`WorkspaceShell` currently discards the `GoRouterState state` parameter
the `ShellRoute` builder receives — it isn't threaded anywhere. This
change adds a `currentLocation` field to `WorkspaceShell` (`state.uri.path`,
passed from the `ShellRoute` builder), so `WorkspaceNavShell` can compute
which destination is active without needing its own routing dependency
beyond `go_router`'s `context.go`.

## 2. New file: `core/routing/workspace_nav_shell.dart`

### 2.1 `WorkspaceNavShell`

```dart
class WorkspaceNavShell extends StatelessWidget {
  const WorkspaceNavShell({
    super.key,
    required this.currentLocation,
    required this.child,
  });

  final String currentLocation;
  final Widget child;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        final isCompact = constraints.maxWidth <= _kBreakpoint;
        return isCompact
            ? _CompactShell(currentLocation: currentLocation, child: child)
            : _WideShell(currentLocation: currentLocation, child: child);
      },
    );
  }
}

const double _kBreakpoint = 900;
```

Follows the same `LayoutBuilder` + `constraints.maxWidth` responsive
convention already established by `MarkdownEditor` (`_breakpoint`, 640)
and `TrashScreen` (`isNarrow`, 380) — no new responsive mechanism.

### 2.2 Destinations and active-route computation

```dart
enum _NavDestination { tickets, documentation }

_NavDestination _destinationFor(String location) {
  if (location.startsWith('/workspace/documentation') ||
      location.startsWith('/workspace/pages')) {
    return _NavDestination.documentation;
  }
  return _NavDestination.tickets;
}
```

`/workspace/pages/*` (page detail/create) counts as Documentation, not
Tickets — pages are Documentation's content
(`aion-arch/specs/tickets.md`'s Documentation section), even though their
routes live outside the `/workspace/documentation` path prefix.
Everything else under `/workspace/tickets*` (list, new, trash, `:id`)
counts as Tickets.

Tapping a nav item always navigates to that destination's root
(`/workspace/tickets` or `/workspace/documentation`), even if already
inside a sub-route of that destination (e.g. tapping "Tickets" while
viewing `/workspace/tickets/:id` returns to the list) — consistent with
how a persistent app-level nav item is expected to behave, and matching
`_SwitchProjectButton`'s existing unconditional-navigate pattern today.

### 2.3 `_WideShell` (sidebar, `> 900px`)

```
Row
├─ _Sidebar (fixed width, e.g. 220px)
│  ├─ Column
│  │  ├─ _NavItem(tickets)        // icon: squaresFourLight, label: ticketsListTitle
│  │  ├─ _NavItem(documentation)  // icon: bookOpenLight, label: documentationTitle
│  │  ├─ Spacer
│  │  └─ _SecondaryActionsTrigger // avatar circle, opens SelectionMenu popover
└─ Expanded(child: child)
```

`_NavItem` mirrors `ProjectSwitcherMenu`'s existing full-width-row visual
language (icon + label + hover/focus/press states via
`FocusableActionDetector`/`GestureDetector`, `c.surfaceHover` fill,
`AionRadius.md`), tinted `c.primary`/`c.primarySubtle` when active — same
active-state treatment `_ViewModeIcon` already uses for the List/Board
toggle. Doesn't reuse `ProjectSwitcherMenu` itself (that widget hardcodes
its own label/icon/action), but matches its shape closely enough that a
future pass could factor out a shared row primitive if a third consumer
appears — not done speculatively here.

`_Sidebar`'s bottom slot places `_SecondaryActionsTrigger` (2.5 below).

### 2.4 `_CompactShell` (bottom tab bar, `<= 900px`)

```
Column
├─ Expanded(child: child)
└─ _BottomTabBar (fixed height, e.g. 64px)
   ├─ _NavItem(tickets)        // icon above label, compact
   ├─ _NavItem(documentation)
   └─ _SecondaryActionsTrigger // avatar circle, same trigger as wide layout
```

Same three logical items as the sidebar, laid out horizontally with
icon-above-label instead of icon-beside-label. `_NavItem` takes a
`compact: bool` param controlling this, rather than being two separate
widget classes.

### 2.5 Secondary actions: `_SecondaryActionsTrigger`

Reuses the existing `SelectionMenu<T>` overlay primitive
(`design_system/molecules/selection_menu.dart`) — already used for
`MoveToStatusMenu`/priority/type editors — instead of building a new
overlay mechanism:

```dart
enum _SecondaryAction { switchProject, trash }

SelectionMenu<_SecondaryAction>(
  trigger: /* the existing avatar-circle visual: DecoratedBox, circle, 'U' */,
  items: _SecondaryAction.values,
  currentValue: _sentinelNotInList, // both items always shown
  itemLabel: (a) => switch (a) {
    _SecondaryAction.switchProject => context.l10n.projectSwitcherMenuLabel, // "Switch Project"
    _SecondaryAction.trash => context.l10n.ticketTrashScreenTitle,           // "Trash"
  },
  onSelected: (a) => switch (a) {
    _SecondaryAction.switchProject => context.go('/hub'),
    _SecondaryAction.trash => context.go('/workspace/tickets/trash'),
  },
  semanticsLabel: context.l10n.navShellSecondaryMenuLabel, // new key, see §4
)
```

`SelectionMenu<T>.currentValue` is designed to exclude the current
selection from the shown list — there's no "current value" concept here,
so `currentValue` is set to a value never present in `items` (e.g. a
private sentinel outside the enum, or simplest: since this is a 2-item
enum, just always render both — `currentValue` can point at a value
guaranteed absent by construction). This is a deliberate reuse-shaped-fit,
not a semantic mismatch: `SelectionMenu` genuinely only needs
"trigger + list of labelled, tappable items", which is exactly this menu.

One trigger, one popover, identical on both `_WideShell` and
`_CompactShell` — not two different secondary-action mechanisms per
breakpoint.

### 2.6 String reuse (no new nav-label strings)

| Usage | Existing key | Value |
|---|---|---|
| Tickets nav item label | `ticketsListTitle` | "Tickets" |
| Documentation nav item label | `documentationTitle` | "Documentation" |
| "Switch Project" menu item | `projectSwitcherMenuLabel` | "Switch Project" |
| "Trash" menu item | `ticketTrashScreenTitle` | "Trash" |

Only one new string is needed: the secondary-actions trigger's semantics
label (nothing existing describes "open this menu" rather than "what it
navigates to"). See §4.

## 3. `app_router.dart` changes

- `WorkspaceShell` gains a `currentLocation` field (`String`), threaded
  from the `ShellRoute` builder's `state.uri.path`.
- `WorkspaceShell.build`'s innermost `child: widget.child` (inside the
  `RepositoryProvider<PageTicketProvider>`) becomes
  `child: WorkspaceNavShell(currentLocation: widget.currentLocation, child: widget.child)`.
- No route table changes — `/workspace/tickets` and
  `/workspace/documentation` keep their existing paths/builders exactly
  as-is.

## 6. Why not `StatefulShellRoute`

`go_router`'s `StatefulShellRoute` gives each nav branch its own
persistent `Navigator`/state stack (e.g. returning to Tickets after
visiting Documentation would restore the exact previous scroll position
and any pushed sub-routes). This change deliberately uses a plain nav
shell over the existing `ShellRoute` instead: switching sections already
behaves this way today (a fresh `context.go` navigation, no state
preservation), the proposal's scope is "give Board/Documentation/future
sections a shared, reachable switcher", and adopting
`StatefulShellRoute` would mean restructuring the entire route table's
shape, not just adding chrome. If state preservation across section
switches becomes a felt problem later, that's a separate, focused idea.

## 7. Widget tree summary

```
WorkspaceShell (existing, MODIFIED: +currentLocation)
  MultiRepositoryProvider (existing, unmodified)
    BlocProvider<TicketsCubit> (existing, unmodified)
      RepositoryProvider<PageTicketProvider> (existing, unmodified)
        WorkspaceNavShell (NEW)
          LayoutBuilder
            (wide)    _WideShell    → Row[_Sidebar[_NavItem×2, _SecondaryActionsTrigger], Expanded(child)]
            (compact) _CompactShell → Column[Expanded(child), _BottomTabBar[_NavItem×2, _SecondaryActionsTrigger]]
```

`child` here is whatever the active `/workspace/*` route builds
(`TicketsListScreen`, `DocumentationScreen`, `TicketDetailScreen`,
`TrashScreen`, `PageDetailScreen`, `PageCreateScreen`, `CreateTicketScreen`)
— none of those screens' own bodies change shape or scroll behavior, they
just render inside the nav shell's content area instead of edge-to-edge.

# Aion — Persistent Navigation Shell Specification

A persistent chrome that wraps **every** workspace screen (Tickets, Documentation, ticket/page detail, Trash, create screens) and lets the user switch sections and reach secondary actions from anywhere.

- **Wide layout (`viewport width > 900`)** — a left **sidebar**, always visible.
- **Compact layout (`viewport width <= 900`)** — a **bottom tab bar** pinned to the bottom.

Exactly one layout is visible at a time, chosen **purely by available width**, not by platform. Narrowing the same window past 900px switches sidebar → bottom bar live. Both **Arctic** (light) and **Obsidian** (dark) are covered; where a component is theme-identical, that is stated.

This document is implementation-ready. Colors are `Color(0xFFRRGGBB)` or existing `AionColors` token references; translucent values are `token.withOpacity(x)`. Type is `AionText.xxx`. Spacing is `AionSpacing.xxx` or an explicit multiple of 4. Radius is `AionRadius.xxx`. **No Material widgets** — build from Flutter primitives only (`DecoratedBox`, `GestureDetector`, `FocusableActionDetector`, `MouseRegion`, `AnimatedScale`, `Row`/`Column`/`Stack`, `Container`, `CustomPaint`, `LayoutBuilder`, `MediaQuery`).

Mockups: `Aion Navigation Shell Mockups.dc.html`.

## 0. Layout switching & shell structure

### 0.1 Breakpoint

```dart
const double kNavShellBreakpoint = 900.0; // logical px
// wide when constraints.maxWidth > 900, compact when <= 900
```

Drive the choice from the shell's own `LayoutBuilder`/`MediaQuery` width — never from `Platform.isX` or `defaultTargetPlatform`. The switch must be reactive to window resize.

### 0.2 Widget tree

```
NavShell (StatelessWidget, wraps the routed child)
└─ LayoutBuilder
   ├─ wide:    Row(  [ _Sidebar(active, onSelect, onSecondary), Expanded(child) ] )
   └─ compact: Column([ Expanded(child), _BottomTabBar(active, onSelect, onSecondary) ])
```

- `active` — an enum `NavSection { tickets, documentation }`.
- `onSelect(NavSection)` — navigate to that section's root.
- `onSecondary(GlobalKey triggerKey)` — open the `SelectionMenu` popover anchored to the trigger.
- The wrapped screen content is unchanged; the shell adds no padding to it beyond the space the sidebar / bar occupy.

### 0.3 New tokens introduced

Only two derived values are needed; both compute from existing tokens, so no new palette entries.

```dart
// active nav destination fill + foreground (reuse existing tokens)
final navActiveFill = c.primarySubtle;      // fill behind current section
final navActiveFg   = c.primary;            // icon + label of current section
final navRestFg     = c.textSecondary;      // inactive icon + label

// focus ring — identical to the rest of Aion
final focusRing = c.primary.withOpacity(isDark ? 0.30 : 0.16); // 3px solid spread
// == AionShadows.focus(colors, isDark)
```

No new `AionColors`, `AionRadius`, or `AionText` entries are required. One new text style alias is defined for the compact tab label in §4.1 (it is `AionText.chip` re-cased, or may reuse `AionText.chip` directly).

## 1. Sidebar container (wide, `> 900`)

A fixed-width, full-height vertical panel left of the screen content.

| Property | Value |
|---|---|
| Width | **244px** (fixed; `SizedBox(width: 244)`) |
| Height | Full height (`double.infinity`) |
| Fill | `AionColors.surface` |
| Border | **Right** hairline only: 1px `AionColors.border` (`Border(right: BorderSide(color: border, width: 1))`) |
| Radius | none (flush to window edge) |
| Padding | `EdgeInsets.fromLTRB(14, 18, 14, 16)` |
| Shadow | none |

**Vertical arrangement** — a `Column` with three zones:

1. **Brand header** (`EdgeInsets.fromLTRB(8, 2, 8, 20)`): `Row`, `gap: 10`, center-aligned.
   - Emblem: 26×26 hexagon, fill `AionColors.primary`, `CustomPaint`/`ClipPath` polygon `(50% 0, 93% 25%, 93% 75%, 50% 100%, 7% 75%, 7% 25%)`.
   - Wordmark: `"AION"`, `AionText.caption` (JetBrains Mono 11 / w600, tracked) color `textPrimary`.
2. **Nav items** — `Column`, `gap: AionSpacing.sp4`, two `_NavItem` rows (§2), top-aligned.
3. **Flexible spacer** — `Spacer()` / `Expanded(SizedBox())` pushing the trigger to the bottom.
4. **Secondary-actions trigger** (§5) — bottom-anchored, `EdgeInsets.symmetric(horizontal: 4)`. On desktop/web, allow the window inset; on any platform with a bottom safe-area, add `MediaQuery.viewPadding.bottom`.

`ProjectSwitcherMenu` is **not** placed in this shell (Switch Project now lives in the popover, §6).

## 2. Sidebar nav item (`_NavItem`, wide variant)

A full-width tappable row matching `ProjectSwitcherMenu`'s shape: leading icon + label, `AionRadius.md` rounded fill.

| Property | Value |
|---|---|
| Width | full (`double.infinity`) |
| Padding | `EdgeInsets.symmetric(horizontal: 12, vertical: 10)` |
| Radius | `AionRadius.md` (10) |
| Layout | `Row`, `gap: AionSpacing.sp12` (12), `crossAxisAlignment: center` |
| Icon size | 20px |
| Label | `AionText.cardTitle` (Manrope 14 / w600), `letterSpacing: -0.07` |
| Height | intrinsic (~40px) |

Icons — Phosphor **Light** family (already in use):
- **Tickets** → `squares-four` (a 2×2 grid of 7×7 rounded squares, 1.6px stroke).
- **Documentation** → `book-open` — **match the exact glyph already used elsewhere in the app for Documentation.**

Wrap in `FocusableActionDetector` (hover + focus) → `GestureDetector` (tap + press) → `AnimatedScale` → `DecoratedBox`. Icon color follows the row's foreground (`currentColor` equivalent).

### 2.1 States

| State | Fill | Icon + label color | Border/ring | Transform |
|---|---|---|---|---|
| **Default (inactive)** | transparent | `textSecondary` | none | none |
| **Hover** | `surfaceHover` | `textSecondary` | none | none |
| **Focused** | transparent (or current fill) | `textSecondary` | `AionShadows.focus` — 3px solid `primary.withOpacity(isDark?0.30:0.16)` | none |
| **Pressed** | `surfaceHover` | `textSecondary` | none | `AnimatedScale` → **0.97** |
| **Active (current section)** | `primarySubtle` | `primary` | none | none |
| **Active + hover** | `primarySubtle` (unchanged) | `primary` | none | none |

Active is the same selected-state treatment used by the existing List/Board view-mode toggle (`primarySubtle` fill + `primary` foreground). Focus ring composes over any fill.

## 5. Secondary-actions trigger (avatar-circle button)

The existing 38×38 circular "U" avatar visual, now the interactive entry point to the popover (§6). The base look is unchanged; interaction states are added on top.

| Property | Value |
|---|---|
| Size | **38×38** |
| Shape | full circle |
| Fill | `AionColors.surfaceHover` |
| Border | 1px `AionColors.border` (default) |
| Glyph | `"U"`, `AionText.key` (JetBrains Mono 11 / w600), color `textSecondary`, centered |
| Radius | circle (`BorderRadius.circular(19)`) |

Compose `FocusableActionDetector` → `GestureDetector` → `AnimatedScale(duration: 90ms)` → `DecoratedBox`. Expose a `GlobalKey` so the popover can anchor to its rect.

### 5.1 States

| State | Fill | Border | Ring | Transform |
|---|---|---|---|---|
| **Default** | `surfaceHover` | 1px `border` | none | none |
| **Hover** | `surfaceHover` | 1px `borderStrong` | none | none |
| **Focused** | `surfaceHover` | 1px `borderStrong` | `AionShadows.focus` (3px `primary.withOpacity(...)`) | none |
| **Pressed** | `surfaceHover` | 1px `borderStrong` | none | `AnimatedScale` → **0.96** (matches `_SwitchProjectButton`) |
| **Menu-open** | `surfaceHover` | 1px `borderStrong` | `AionShadows.focus` | none |

**Menu-open indicator — chosen:** while the popover is open the trigger holds the **focus ring + `borderStrong`** (same as focused). This gives a clear "this opened the menu" anchor; when the popover closes it reverts to default/hover. (Stated explicitly per brief; a "no change" option was acceptable but the persistent ring reads better for a bottom-anchored control.)

### 5.2 Placement

- **Wide sidebar:** bottom zone, left-aligned within the sidebar's `horizontal: 4` padding. Optional trailing `"You"` label (Manrope 13 / w600, `textSecondary`, `gap: 11`) — decorative; the whole row is one tap target. The **popover opens upward**, its bottom edge ~52px above the trigger, left edge aligned to the trigger.
- **Compact bottom bar:** centered in the trailing (third) `Expanded` cell. The **popover opens upward** from the trigger, bottom edge ~78px above the bar (clearing the bar height + safe area), right edge inset 16px from the window edge.

## 6. Secondary-actions popover (reused `SelectionMenu<T>`)

**Do not redesign the panel or its rows.** The trigger opens the existing, unmodified `SelectionMenu<T>` as an overlay. Recorded here only for placement + item content.

- **Panel:** fill `surface`, 1px `borderStrong`, `AionRadius.lg` (12), shadow `AionShadows.card` (`0 20px 44px -14px` black at `isDark?0.60:0.22` opacity), padding `EdgeInsets.all(5)`.
- **Rows:** `bodySm` (Manrope 13.5) at **w600**, `textPrimary`, padding `EdgeInsets.symmetric(vertical: 9, horizontal: 13)`, `AionRadius.sm`–`8` fill on hover (`surfaceHover`). Optional 15px leading icon in `textSecondary`, `gap: 11`.
- **Width:** ~210px (intrinsic to the longest row; SelectionMenu default).

### 6.1 Items

| Order | Label | Icon (Phosphor Light, `textSecondary`) | Action |
|---|---|---|---|
| 1 | **Switch Project** | hexagon emblem (same polygon as the sidebar brand mark) | opens the project switcher flow (`ProjectSwitcherMenu`) |
| 2 | **Trash** | `trash` | navigates to the Trash screen |

### 6.2 Anchoring

- Overlay via an `OverlayEntry` positioned from the trigger's `GlobalKey` rect.
- **Wide:** open upward-right; bottom of panel ~8px above the trigger's top, left edges aligned.
- **Compact:** open upward; bottom of panel ~8px above the bar's top edge, right edge aligned to the trigger, clamped 16px from the window edge.
- Dismiss on outside tap / `Escape` / route change. Trigger returns to default state on dismiss.

## 8. Implementation notes
