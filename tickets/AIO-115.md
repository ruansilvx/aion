# `core/agent/` — the second implementation

- [x] T3. `lib/core/agent/anthropic_messages_api_client.dart` — ADD:
  `AnthropicMessagesApiClient implements AgentModelClient`, constructed
  with a `Dio` and a `Future<String?> Function()` API-key getter.
  `run()`: returns an immediate `AgentErrorEvent` if `toolsEnabled` is
  `true` (unsupported) or no API key is available; otherwise POSTs to
  `https://api.anthropic.com/v1/messages` with `stream: true`, parses
  the SSE response into `AgentTextEvent`/`AgentDoneEvent` (reading
  `usage.input_tokens`/`usage.output_tokens` off `message_start`/
  `message_delta`), maps a `429` response to `AgentOverageDetectedEvent`
  instead of `AgentErrorEvent`, and maps any other non-2xx/error frame
  to `AgentErrorEvent`. Per design.md §2. Depends on T1. Full dartdoc,
  file header.
- [x] T4. `lib/core/agent/anthropic_messages_api_provider.dart` — ADD:
  `AnthropicMessagesApiProvider implements AgentProvider`, constructed
  with an `AgentModelClient`. `id → ProviderId.anthropicMessagesApi`;
  `displayName → 'Anthropic API'`; `supportedToolAccessTiers →
  {ToolAccessTier.noTools}`; `availableModels` — three
  `AgentModelDescriptor`s mirroring `ClaudeAgentSdkProvider`'s
  Opus/Sonnet/Haiku labels, using real Anthropic Messages API model-id
  strings (source these from Anthropic's current published model list
  at implementation time — do not invent/guess an id); `describeOverage`
  → `CostConsumption(rawMessage, null)`; `normalizeErrorMessage` —
  strips Anthropic-vendor-specific text (status-line/header noise,
  literal "Anthropic" mentions), maps common HTTP status codes to
  vendor-neutral phrases (e.g. 401 → "Invalid API key."), falls back to
  the raw message unchanged when nothing matches. Per design.md §3.
  Depends on T2, T3. Full dartdoc, file header.
