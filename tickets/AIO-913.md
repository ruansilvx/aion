# 7. In `updateTicketParent`: capture `stateBeforeThisWrite = state`

at the method's top. In the `ParentChangeSuccess` case, after
`emit(TicketDetailLoaded(ticket))`, add
`unawaited(_refreshDetailIfOpenAndAffected({ticket.id},
fromState: stateBeforeThisWrite))`. **Corrected during test-writing**:
a single call using the written ticket's post-write `parentId`
can only ever discover the *new* parent — the old parent is
structurally undiscoverable that way, since nothing about the
post-write ticket still points at it, so "one call covers both
directions" (as originally planned above) was wrong. Also capture
`oldParentId = ticket.parentId` (the method parameter, before the
service call) and, in the same `ParentChangeSuccess` case, added a
second targeted check: if `oldParentId` is non-null, differs from
the ticket's new `parentId`, and `stateBeforeThisWrite` is
`TicketDetailLoaded` for that old parent, look up
`_liveRefreshDependents[stateBeforeThisWrite.ticket.type]` directly
and call `getTicketById(oldParentId)` if the reparented ticket's
type is in that set. Updated the method's dartdoc accordingly.
