# Catalog generalization (`lib/core/automation/decision_field_catalog.dart`)

- [x] Add `_agentJudgmentEligibleContexts` (private `Set<AutomationContext>`:
      `ticketCreation`, `ticketLinking`, `chatBranching`) and
      `agentJudgmentConditionSpec(AutomationContext)` — `null` outside
      that set, otherwise a `DecisionConditionSpec(id:
      agentJudgmentConditionId, displayName: 'Ask the agent', contexts:
      [context], parameterSpecs: const [])`. Dartdoc per design.md §6
      (explain why this allowlist isn't derived from any existing
      enum/field — it's this change's own source of truth for "has a
      live session at evaluation time").
- [x] Add `defaultAgentJudgmentConditionParams(AutomationContext)` (or
      fold into a single seeding helper alongside
      `defaultRuleConditionParams` — implementer's choice) returning
      `{'prompt': ''}`.
- [x] `isRecognizedConditionId`: add `|| conditionId ==
      agentJudgmentConditionId`.
- [x] `decisionNodeTitle`: add a branch for `node.conditionId ==
      agentJudgmentConditionId` returning the plain-English fallback
      `'Ask the agent'` — `decision_field_catalog.dart` is a `core/`
      file with no Flutter/`AppLocalizations` dependency today (only
      `package:meta`), and the rule-builder case already establishes
      this exact convention: `decisionNodeTitle` returns a field's
      unlocalized `displayName`, with the *picker row's* localized
      override (`decisionGraphRuleBuilderLabel`, line ~933 of
      `decision_node_form.dart`) applying only to that one row, never to
      `decisionNodeTitle`'s own output. Match that pattern exactly —
      don't introduce a `BuildContext` dependency into this file.
- [x] `decisionNodeSummary`: add a branch returning
      `node.conditionParams['prompt']` (truncated to ~120 chars, mirroring
      `agent_bridge/index.mjs`'s `summarizeToolInput` truncation
      convention) when `node.conditionId == agentJudgmentConditionId` and
      the value is a non-empty `String`; `null` otherwise.
