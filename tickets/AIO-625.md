- [x] `DecisionEvalContext`: add `session` (`AgentSessionHandle?`) and
      `askAgentJudgment` (`Future<bool?> Function(AgentSessionHandle,
      String)?`) fields, both defaulting to `null`. Dartdoc per
      design.md §5's exact text.
- [x] Add `const agentJudgmentConditionId = 'agentJudgment';` and
      `_evaluateAgentJudgment(DecisionEvalContext, Map<String, dynamic>)`
      per design.md §5's exact implementation — defensive `false` for a
      missing/non-`String` `prompt`, a `null` `session`, or a `null`
      `askAgentJudgment`.
- [x] `evaluateDecisionGraph`'s signature becomes `Future<DecisionOutcome>
      evaluateDecisionGraph(...)`. The walk loop's condition-evaluation
      step branches on `node.conditionId == agentJudgmentConditionId`
      (awaits `_evaluateAgentJudgment`) vs. the existing synchronous
      `_conditionEvaluators` lookup — everything else in the loop
      (root-null/dangling-reference `proceed`, matched/unmatched branch
      following) unchanged. Update the function's dartdoc: no longer
      "pure, no I/O" — note the one exception per design.md §5, and
      cross-reference `providers.md`'s "Decision graphs" section as the
      place this "pure" claim currently lives (so whoever runs `/archive`
      knows to correct it there too).
