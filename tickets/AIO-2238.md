# Spec Delta: Ticket-graph and embedding context enrichment for spawned chats

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (20/20 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Relative to `aion-arch/specs/tickets.md`. Read alongside `proposal.md`/
`design.md` in this change folder.

## ADDED

- A new `TicketContextEnricher` orchestrator
  (`presentation/cubit/ticket_context_enricher.dart`), constructed once
  by `TicketsCubit` alongside `TicketRollupRecomputer`/
  `TicketEstimationSuggester`. Its `relatedTicketsSection(Ticket ticket)`
  assembles a `## Related tickets` Markdown section from:
  - A **structured walk**: `ticket`'s full ancestor chain (via
    `parentId`, nearest-first, cycle-guarded the same way
    `TicketRollupRecomputer`'s ancestor walk already is) plus every
    direct `TicketLink` row for `ticket` (`TicketLinkRepository
    .getLinksForTicket`, any `TicketLinkType`, any ticket type — not
    limited to the one `page`-typed design link `_linkedDesignPage`
    already resolves).
  - An **embedding-similarity walk**: a cosine-similarity scan (reusing
    `domain/utils/embedding_similarity.dart`'s existing
    `cosineSimilarity`) over every other live ticket's `embedding`
    column, querying with `ticket`'s own title+description, included
    only at or above a fixed similarity threshold (`0.75`) and capped at
    a top-K fallback (`5`), excluding `ticket` itself and anything the
    structured walk already surfaced.
  - Each surfaced ticket renders as one bullet: title, relationship
    label (ancestor's `TicketType` name, the link's `TicketLinkType`
    name as read from `ticket`'s side, or `similar`), and its
    description truncated to 400 characters (`(no description)` when
    empty/`null`).
  - Returns `''` when there is nothing to add (no ancestors, no links,
    no similarity matches, or no `TicketLinkRepository`/
    `EmbeddingProvider` configured) — callers skip the section entirely
    in that case.

## MODIFIED

- **`_assembleExecutionContext`** (coding execution's opening
  system-context comment): now includes the Task's `## Related tickets`
  section (via `TicketContextEnricher`), inserted after the title/
  description block and before the `## Project conventions` block, when
  non-empty. A Task with no ancestors, links, or similarity matches still
  produces exactly today's plain title/description/conventions output.
- **`_assembleStageContext`** (the shared context builder behind
  `_createStageChat`, `_runStageChatTurn`, and `retryDesignSync`'s
  re-assembly): now includes the parent ticket's `## Related tickets`
  section, inserted after the title/description block and before each
  stage's own extra section (children list for `verifying`/`archived`,
  design-token contents for `designBrief`/`designSync`, decomposition
  instructions for `proposed`), when non-empty. Since all three existing
  callers share this one method, the enrichment applies uniformly —
  including `retryDesignSync`'s re-run, with no separate change needed
  there. This replaces the prior "no embeddings/repo-map-lite involvement
  at any stage" behavior — SDD-stage chats (which run with
  `toolsEnabled: false`, no file/git/bash access) now receive
  ticket-graph context they previously had no way to discover
  themselves.

## REMOVED

- The known gap: "No repo-map-lite or embedding-based context enrichment
  for a spawned SDD-stage chat's initial message — plain-text parent
  fields and direct hierarchy/`relatesTo` links only, no similarity
  search, no tree-sitter symbol index." Superseded by the ADDED/MODIFIED
  behavior above for the ticket-graph half of that gap. Source-code-level
  enrichment (repo-map-lite, tree-sitter symbol indexing) remains
  unbuilt and out of scope — see `proposal.md`'s Out of scope section —
  so no claim is made that the *symbol-index* half of the old gap
  wording is resolved; the gap entry itself is removed because Aion has
  no plans to build that half at all (confirmed during brainstorming),
  making it no longer a tracked gap rather than a deferred one.
