# T20. Same file — decomposition cases: `_parseDecomposition` on a

reply with a valid `## Decomposition` block returns the expected
ordered pairs, including one with a `(blockedBy: ...)` suffix;
returns `[]` for a reply with no block; returns `[]` for a block
whose lines don't match the expected prefix.
`_materializeDecomposition` creates one child ticket per parsed
line under the parent; creates a `blockedBy` link for a resolvable
`blockedByTitle`; still creates the child ticket (but no link) for
an unresolvable `blockedByTitle`; is a no-op when
`_linkRepository` is unset or the reply has no block. A
`SddStage.proposed` turn's `_runStageChatTurn` calls
`_materializeDecomposition` exactly once per successful turn, not
for any other stage.
