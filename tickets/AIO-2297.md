# T2. Create `aion/lib/features/tickets/presentation/widgets/ticket_parent_picker.dart`.

File header comment (presentation/widgets layer). Move
`TicketParentPicker`, `_NoParentRow`, `_CandidateRow`, and their
`State` classes here from `ticket_detail_screen.dart` (currently
lines 795-end of file). Apply the constructor changes from
design.md §2: `ticketType`, `currentParentId`, `candidatesLoader`,
`onParentSelected` replace `required Ticket ticket`;
`_loadCandidates()` calls `widget.candidatesLoader()` instead of
`context.read<TicketsCubit>().getValidParentCandidates(widget.ticket)`;
`_commit()` calls `widget.onParentSelected(parentId)` instead of
`context.read<TicketsCubit>().updateTicketParent(widget.ticket, parentId)`;
`_resolveParent` and the trigger's resolved-title lookup use
`widget.currentParentId` instead of `widget.ticket.parentId`. Keep
the existing search/overlay/keyboard-escape/mounted-guard behavior
unchanged. Preserve and update every existing dartdoc comment to
match the new parameters.
per design.md "Changes §1. Extract TicketParentPicker into its own
file" and "§2. Generalize TicketParentPicker's constructor".
NOTE (design-sync finding, not yet reflected above): the
Component Spec (second half of design.md) §2 "Parent field
trigger (form-field variant)" specifies a *second*, visually
distinct trigger appearance for the create-form embedding —
full-width, `AppDropdown`-style — separate from the existing
compact inline `"+ PARENT"` trigger `TicketDetailScreen` still
uses. The constructor as scoped here has no parameter to select
between the two trigger renderings; this needs a variant flag
(e.g. `TicketParentPickerVariant variant`) added during
implementation, cross-referencing Component Spec §2.1-§2.3 for
the form-field variant's states and Ticket Parent Spec §1 for the
existing inline variant's. Flagged for `/apply`, not resolved
here per this stage's tasks.md edit-scope restriction.
RESOLVED during `/apply`: added `enum TicketParentPickerVariant {
inline, formField }` and a `variant` constructor parameter
(defaults to `inline`) to `TicketParentPicker`. `build()` switches
on `widget.variant` to call `_buildInlineTrigger` (unchanged
existing behavior) or `_buildFormFieldTrigger` (new, per Component
Spec §2.1-§2.3: empty/filled states, hover/focus/press border and
glyph-color transitions, `AnimatedScale` press feedback).
`TicketDetailScreen`'s call site omits `variant` (inline default);
`CreateTicketScreen` passes `variant: TicketParentPickerVariant.formField`.
