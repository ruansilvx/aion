# Markdown editor (unchanged from the original proposal)

- [x] T1. Add the `markdown` package (pub.dev, `dart-lang`-maintained
      CommonMark + GFM parser) to `pubspec.yaml` as a direct dependency.
      Pure Dart, no Flutter/Material transitive dependency — verify via
      `flutter pub deps` before proceeding.

- [x] T2. Modify `design_system/atoms/app_text_field.dart`: change the
      `maxLines` parameter's type to accept `null` (unbounded/expanding
      textarea) and pass it through to the underlying `TextField` as-is.
      Update the existing dartdoc on the constructor. No other behavior
      change — existing callers all pass a finite value. Per design.md
      §1.2, §1.5, §8.2 (Markdown/content textareas).

- [x] T3. Create `design_system/molecules/markdown_view.dart`:
      `MarkdownView` — stateless, read-only widget parsing `source` via
      `md.Document(extensionSet: md.ExtensionSet.gitHubWeb).parse(...)`
      (`package:markdown`) and rendering the resulting AST via `AionText`/
      `AionColors`/`AionRadius`/`AionSpacing` tokens per design.md's
      per-tag mapping (headings 1-6, paragraphs with inline emphasis/links,
      bullet/ordered/nested/task lists, fenced/indented code blocks,
      blockquotes, horizontal rules, GFM tables via `Table`, not
      `DataTable`). Images render alt text only. Any unrecognized node
      falls back to a plain-text paragraph. No Material widgets. File
      header + dartdoc on the class and constructor. Per design.md §2
      MarkdownView (§2.1–§2.10, per-tag rendering rules).

- [x] T4. Create `design_system/molecules/markdown_view_test.dart`: widget
      tests covering one case per supported tag — headings 1-6, a paragraph
      with mixed inline emphasis (bold/italic/strikethrough/inline-code)
      plus a link, bullet/ordered/nested/task lists, a fenced code block, a
      blockquote, a horizontal rule, a GFM table, and an unrecognized-node
      fallback.

- [x] T5. Create `design_system/molecules/markdown_editor.dart`:
      `MarkdownEditor` — stateful, responsive editor per design.md:
      `LayoutBuilder` with `isNarrow = constraints.maxWidth <= 640`; narrow
      layout is a view/edit toggle (view renders `MarkdownView`, edit
      renders an `AppTextField` with `maxLines: null` plus an explicit
      Save/Cancel row); wide layout is a live split view (`AppTextField`
      left, `AionColors.border` divider, `MarkdownView` right, both
      independently scrollable) with the same Save/Cancel row beneath.
      Commits only via explicit Save, calling the caller-supplied
      `onCommit` with the trimmed text — never calls a repository or Cubit
      method directly. File header + dartdoc on the class, constructor,
      and all public fields. Per design.md §1 MarkdownEditor (§1.1–§1.7:
      narrow toggle, wide split view, saving/error/empty states).

- [x] T6. Export `MarkdownView` and `MarkdownEditor` from
      `design_system/design_system.dart`.
