`BaselineRepository? baselineRepository`, `String? projectId`,
`String? baselineVersion` (and matching `late final` fields),
following the existing optional-dependency pattern.
- Rename `_maxAnalyzeRetries` → `_maxVerifyRetries`.
- Add `_effectiveAssetContent(String assetKey)` (§5.2).
- Change `_assembleExecutionContext` to `Future<String>`, adding
the `## Project conventions` section and the environment-setup
sentence (§5.3).

the null-guard to require `baselineRepository`/`projectId`/

parameter instead of `FlutterVerifyResult` (§5.7).
- Rewrite every dartdoc comment referencing `FlutterVerifier`/
`flutter analyze` by name (the class-level dartdoc, the
constructor's dartdoc, `_runCodingExecution`'s dartdoc,
`_assembleExecutionContext`'s dartdoc,
`_assembleCorrectiveContext`'s dartdoc) to describe the
implement-then-verify two-model-turn loop instead (§5.8).
