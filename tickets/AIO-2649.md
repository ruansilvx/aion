# Delta Spec: v1 Ticket Slice

**Reconciled 2026-09-03, with real drift folded in:** this is the original v1 MVP scaffold — the very first ticket slice, predating essentially every later change. Its enums, entities, and UI are historical starting points, extensively extended since: TicketType grew from 6 values to today's 10 (idea/knownGap/openQuestion/release/bug/spec added); TicketStatus as a fixed enum was replaced entirely by project-configurable WorkflowStatus strings (configurable-ticket-workflow); the Material-flavored theming this delta describes (AppThemeData, AppColors, TextTheme/labelSmall etc.) was replaced by the current AionColors/typography design-token system (design-system-restructure, and the broader Material-decoupling work documented in tickets.md's "Material coupling" section). This ticket's content is valuable as historical record of where the app started, not as a description of current behavior — nearly every surface it touches has since been rebuilt.

> Legend: ADDED = new behavior, MODIFIED = changed behavior, REMOVED = deleted behavior.
> Baseline: blank Flutter scaffold (main.dart Hello World only).

## Domain

### ADDED — TicketType enum
Values: `epic`, `story`, `task`, `resource`, `page`, `chat`.
Serialized as its `.name` string for storage.

### ADDED — TicketStatus enum
Values: `backlog`, `todo`, `inProgress`, `inReview`, `done`, `cancelled`.
Serialized as its `.name` string for storage.

### ADDED — TicketPriority enum
Values: `critical`, `high`, `medium`, `low`, `none`.
Serialized as its `.name` string. Default at creation: `none`.

### ADDED — TicketLinkType enum
Values: `blocks`, `blockedBy`, `relatesTo`, `duplicates`, `duplicatedBy`.
Serialized as its `.name` string. Used exclusively by `TicketLinksTable`.
Parent/child hierarchy is NOT a link type — it is modelled by `parent_id`
on the ticket table only.

### ADDED — CommentAuthorType enum
Values: `human`, `ai`.
Serialized as its `.name` string.

### ADDED — Ticket entity
Immutable Equatable value object.
Fields: `id` (String UUID — internal PK), `ticketId` (String — human-readable
display ID, e.g. `"AIO-42"`), `type` (TicketType), `title` (String),
`description` (String?), `status` (TicketStatus),
`priority` (TicketPriority — default `TicketPriority.none`),
`parentId` (String? UUID — structural parent/child only),
`embedding` (Uint8List?),
`estimate` (int? — minutes, nullable),
`timeSpent` (int? — minutes, nullable),
`createdAt` (DateTime), `updatedAt` (DateTime).
Equality and hashCode based on all fields via Equatable.

### ADDED — TicketComment entity
Immutable Equatable value object.
Fields: `id` (String UUID), `ticketId` (String — FK to Ticket.id),
`content` (String — plain text), `authorType` (CommentAuthorType),
`aiModel` (String? — set only when `authorType == ai`),
`createdAt` (DateTime).
No `updatedAt`. Structural immutability enforces append-only semantic.

### ADDED — TicketRepository interface
Located in `domain/repositories/`.
Methods:
- `Future<List<Ticket>> getAllTickets()` — returns all tickets ordered by
  `createdAt` descending.
- `Future<Ticket?> getTicketById(String id)` — returns null if not found.
- `Future<void> createTicket(Ticket ticket)` — inserts; throws if id
  already exists.

### ADDED — TicketLinkRepository interface
Located in `domain/repositories/`.
Methods:
- `Future<List<TicketLinkData>> getLinksForTicket(String ticketId)` — returns
  all links where `source_ticket_id` or `target_ticket_id` equals the given id.
- `Future<void> createLink({required String sourceTicketId, required String targetTicketId, required TicketLinkType linkType})`.
No link UI in this slice. Schema + domain/data layer only.

### ADDED — CommentRepository interface
Located in `domain/repositories/`.
Methods:
- `Future<List<TicketComment>> getCommentsForTicket(String ticketId)` —
  returns all comments for the ticket ordered by `createdAt` ascending.
- `Future<void> addComment(TicketComment comment)` — append-only insert.
  Never modifies an existing comment.

### ADDED — Subtask convention (documentation, no schema change)
A `task` ticket with a `parent_id` referencing another `task` or `story`
is the Aion subtask pattern. No dedicated subtask type exists. Documented
canonically in `design.md`.

### ADDED — Rollup invariant (documentation)
`estimate` and `time_spent` rollup MUST be computed from the `parent_id`
structural tree only. Links in `ticket_links` NEVER contribute to any
rollup. This invariant is documented in `design.md` and must be honoured
by all future rollup implementations.

## Data

### ADDED — TicketsTable (Drift)
Single table in `AppDatabase`. Schema as defined in design.md.
Columns include: `ticket_id` (TEXT NOT NULL UNIQUE), `priority`
(TEXT NOT NULL DEFAULT `'none'`), `estimate` (INTEGER nullable),
`time_spent` (INTEGER nullable).
No FK constraints. Schema version 1 — no migrations (fresh DB).

### ADDED — TicketIdSequenceTable (Drift)
Singleton table (`id INTEGER PRIMARY KEY`, `seq INTEGER NOT NULL DEFAULT 0`).
Initialized with one row (`id: 1, seq: 0`) in the `onCreate` migration.
Used exclusively by `TicketDao.insertTicket` to generate the next sequence
number within a transaction.

### ADDED — TicketLinksTable (Drift)
Columns: `id` (TEXT PK), `source_ticket_id` (TEXT NOT NULL),
`target_ticket_id` (TEXT NOT NULL), `link_type` (TEXT NOT NULL).
No FK constraints. Non-hierarchical relationships only.

### ADDED — TicketCommentsTable (Drift)
Columns: `id` (TEXT PK), `ticket_id` (TEXT NOT NULL), `content` (TEXT NOT NULL),
`author_type` (TEXT NOT NULL), `ai_model` (TEXT nullable),
`created_at` (INTEGER NOT NULL).
No `updated_at` column — structural append-only enforcement.
No FK constraints.

### ADDED — TicketDao
`@DriftAccessor(tables: [TicketsTable, TicketIdSequenceTable])`.
Provides: `getAllTickets()`, `getTicketById(String id)`,
`insertTicket(TicketsTableCompanion entry, String prefix)`.
`insertTicket` runs in a Drift transaction: read `seq` → increment → write
back → build `ticketId` string → insert ticket row with `priority` field.
Returns the generated `ticketId`.

### ADDED — TicketLinkDao
`@DriftAccessor(tables: [TicketLinksTable])`.
Provides: `getLinksForTicket(String ticketId)`, `insertLink(TicketLinksTableCompanion)`.

### ADDED — CommentDao
`@DriftAccessor(tables: [TicketCommentsTable])`.
Provides: `getCommentsForTicket(String ticketId)` (ordered by `created_at` ASC),
`insertComment(TicketCommentsTableCompanion)`.
No UPDATE or DELETE methods. Append-only by construction.

### ADDED — AppDatabase
`@DriftDatabase(tables: [TicketsTable, TicketIdSequenceTable, TicketLinksTable, TicketCommentsTable], daos: [TicketDao, TicketLinkDao, CommentDao])`.
Platform-conditional connection:
- Native: `drift_flutter` `driftDatabase(name: 'aion')`.
- Web: drift + sqlite3 WASM via `WasmDatabase.open`.
`onCreate` seeds `TicketIdSequenceTable` with `(id: 1, seq: 0)`.

### ADDED — DriftTicketRepository implements TicketRepository
Maps `TicketData` ↔ `Ticket`. All enum parsing done here with fallbacks:
`TicketType.task`, `TicketStatus.backlog`, `TicketPriority.none` on
unrecognised strings. Reads prefix from `SharedPreferences` key
`ticket_id_prefix` (default `"AIO"`) and passes it to `dao.insertTicket`.

### ADDED — DriftTicketLinkRepository implements TicketLinkRepository
Maps `TicketLinkData` ↔ domain representation. Generates UUID for `id`.
Enum conversion for `link_type` with safe fallback. No UI — data layer only.

### ADDED — DriftCommentRepository implements CommentRepository
Maps `TicketCommentData` ↔ `TicketComment`. Generates UUID for `id`.
Enum conversion for `author_type`. `addComment` → `dao.insertComment`.
No UPDATE/DELETE paths exist.

## Presentation

### ADDED — TicketsState (sealed class)
States: `TicketsInitial`, `TicketsLoading`, `TicketsLoaded`,
`TicketsError`, `TicketCreating`, `TicketCreated`, `TicketDetailLoaded`.
All extend `Equatable`.

### ADDED — CommentsState (sealed class)
States: `CommentsInitial`, `CommentsLoading`, `CommentsLoaded`,
`CommentsError`, `CommentAdding`, `CommentAdded`.
All extend `Equatable`.

### ADDED — TicketsCubit
- `loadTickets()`: emits Loading → Loaded (or Error).
- `createTicket({type, title, description, priority, parentId})`: generates
  UUID, emits TicketCreating → TicketCreated (or Error). `priority` defaults
  to `TicketPriority.none`.
- `getTicketById(String id)`: emits Loading → TicketDetailLoaded (or Error).

### ADDED — CommentsCubit
- `loadComments(String ticketId)`: emits CommentsLoading → CommentsLoaded
  (or CommentsError).
- `addComment({ticketId, content, authorType, aiModel})`: generates UUID,
  emits CommentAdding → CommentAdded (or CommentsError). `authorType`
  defaults to `CommentAuthorType.human`.
  Comments bypass the watcher gate — see Watcher Gate Bypass below.

### ADDED — Watcher Gate Bypass (semantic invariant)
`CommentsCubit.addComment` writes directly to `CommentRepository` without
going through any review or scheduled-change queue. Comments are
observations/narrations about ticket state, not proposed changes to it.
Any future watcher implementation MUST explicitly exclude `CommentRepository`
writes from the review queue. This invariant is documented in `design.md`
and `proposal.md`.

### ADDED — TicketsListScreen (`/tickets`)
- Calls `cubit.loadTickets()` on `initState`.
- BlocBuilder renders: `AppSpinner` (loading), error `Text` + retry
  `AppButton`, empty-state `Text`, or `ListView` of `TicketListTile` widgets.
- `AppFab` navigates to `/tickets/new`.
- Each `TicketListTile` shows: `ticketId` badge, title, type chip, status
  label, and `PriorityBadge` (color-coded, hidden when priority is `none`).
- Each tile navigates to `/tickets/:id` on tap.

### ADDED — CreateTicketScreen (`/tickets/new`)
- Form with: `AppTextField` (title, required), `AppDropdown<TicketType>`
  (defaults to `task`), `AppDropdown<TicketPriority>` (defaults to `none`),
  `AppTextField` (description, optional multiline).
- Submit calls `cubit.createTicket(type, title, description, priority)`.
- On `TicketCreated`: `context.go('/tickets')`.
- On `TicketsError`: `AppToast.show(context, message)`.
- No `SnackBar`, no `ScaffoldMessenger`.

### ADDED — TicketDetailScreen (`/tickets/:id`)
- Reads `id` from go_router path params.
- Calls `cubit.getTicketById(id)` and `commentsCubit.loadComments(id)` in
  `initState`.
- `MultiBlocProvider` scopes both cubits to this screen.
- Read-only ticket detail section: `ticketId` badge, type chip, priority
  indicator, title, status, description, `parentId` ref (if set), timestamps.
- Comments section (below a divider):
  - `BlocBuilder<CommentsCubit>` renders: `AppSpinner`, error `Text`, or
    comment list (`ListView` of `CommentTile`) + comment input bar.
  - `CommentTile`: `DecoratedBox` with `commentHumanBg` / `commentAiBg`
    token. Human comments: left-aligned, no model label. AI comments:
    right-aligned, `ai_model` label shown above content.
  - Comment input bar: `AppTextField` (multiline, hint: "Add a comment…") +
    `AppButton` ("Send"). On submit: `commentsCubit.addComment(...)`.
  - A11y: `CommentTile` gets `Semantics(label: '${authorType.name} comment: $content')`.

### ADDED — TicketDetailLoaded state
```
TicketDetailLoaded extends TicketsState { final Ticket ticket; }
```
Emitted by `TicketsCubit.getTicketById`. Needed by `TicketDetailScreen`
independently of the list state.

## Design System

### ADDED — AppColors (`core/theme/app_colors.dart`)
`abstract final class` with `static const Color` tokens for brand, surface,
on-surface, primary, on-primary, error, and border — for both light and dark
variants. No Material import. All foreground/background pairs meet WCAG AA
(4.5:1 normal text, 3:1 large text/UI components).

### ADDED — AppTypography (`core/theme/app_typography.dart`)
`abstract final class` with `static const TextStyle` tokens: `titleLarge`,
`titleMedium`, `bodyLarge`, `bodyMedium`, `labelLarge`, `labelSmall`.
No Material font package dependency. System default sans-serif in v1.

### ADDED — AppSpacing (`core/theme/app_spacing.dart`)
`abstract final class` with `static const double` spacing constants:
`xs` (4), `sm` (8), `md` (16), `lg` (24), `xl` (32), `xxl` (48).

### ADDED — AppRadii (`core/theme/app_radii.dart`)
`abstract final class` with `static const double` border-radius constants:
`xs` (4), `sm` (8), `md` (12), `lg` (16), `full` (999).

### ADDED — AppShadows (`core/theme/app_shadows.dart`)
`abstract final class` with `static const List<BoxShadow>` shadow tokens:
`none`, `sm`, `md`. No Material elevation model dependency.

### ADDED — AppThemeData (`core/theme/app_theme.dart`)
Plain Dart class. No `ThemeData`, no `ColorScheme`, no Material import.
Holds resolved `AppColorScheme` and `AppTypographyScheme` instances for
the active brightness. Static accessors: `AppThemeData.light`,
`AppThemeData.dark`.

### ADDED — ThemeScope (`core/theme/theme_scope.dart`)
`InheritedWidget` that provides `AppThemeData` to the subtree.
`ThemeScope.of(context)` is the sole way widgets read theme tokens.
`Theme.of(context)` is never called in widget code.
`updateShouldNotify` returns `true` when `AppThemeData` instance changes
(i.e. on system brightness change).

### RULE — No Material theme access or Material widget chrome in widget code
- `Theme.of(context)` is banned in all files under `lib/`.
- `ThemeData`, `ColorScheme`, `TextTheme`, `MaterialApp` are banned in
  widget files.
- `MaterialApp` replaced by `WidgetsApp.router` at the app root.
- `Scaffold`, `AppBar`, `FloatingActionButton`, `Card`, `ListTile`,
  `ElevatedButton`, `TextButton`, `InkWell`, `DropdownButton`,
  `SnackBar`/`ScaffoldMessenger`, `CircularProgressIndicator` are all
  replaced by primitive or in-house equivalents (see Material Coupling
  Audit in design.md).
- `TextField` is kept with fully explicit `InputDecoration` — no reliance
  on `Theme` defaults. All decoration values sourced from `ThemeScope`.
- No raw `Color(0x...)` literals, numeric font sizes, or numeric padding
  in widget files. All values via `ThemeScope.of(context)` or token
  constants.
- Violations detected by grep checks in T26.

## Documentation

### MODIFIED — openspec/project.md
Adds under "Foundational Decisions":

**6. Web URL Strategy**
Clean paths (go_router default in Flutter 3.x). No explicit
`usePathUrlStrategy()` call required. Firebase Hosting deployment requires:
```json
"rewrites": [{ "source": "**", "destination": "/index.html" }]
```
in `firebase.json`. Without this, direct URL access and page refresh on
web will 404.
