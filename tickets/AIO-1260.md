# Spec delta: Multi-select filters for the ticket list

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's TicketListFilters/TicketListSort entities and Screens' filter popover` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. single-select filtering is still the foundation; multi-select (a later ticket, Multi-select filters for the ticket list) extended it additively rather than replacing it.

Delta against `aion-arch/specs/tickets.md`. Read alongside
`proposal.md`/`design.md` in this same change folder — this file only
states what's ADDED, MODIFIED, or REMOVED relative to that baseline.

## ADDED

- **`TicketListFilters`** (`domain/entities/ticket_list_filters.dart`) —
  a plain value holder for a ticket-list filter selection: `Set<TicketStatus>
  statuses`, `Set<TicketType> types`, `Set<TicketPriority> priorities`, all
  defaulting to empty.
- **`TicketListFilterRepository`**
  (`domain/repositories/ticket_list_filter_repository.dart`) — domain
  interface: `getFilters(String projectId)` returns the persisted
  `TicketListFilters` for that project (all-empty if nothing saved yet);
  `setFilters(String projectId, TicketListFilters filters)` persists it.
  Plain reads/writes, no validation.
- **`SharedPrefsTicketListFilterRepository`**
  (`data/repositories/shared_prefs_ticket_list_filter_repository.dart`) —
  `SharedPreferences`-backed implementation, using
  `ticket_list_filters.<projectId>.statuses`/`.types`/`.priorities` as
  keys (`setStringList`/`getStringList` of each enum's `.name` values).
  The first project-scoped `SharedPreferences` repository in the
  codebase — every prior one used flat, global keys.
- **`AppFilterChip`** (`design_system/atoms/app_filter_chip.dart`) — a
  general-purpose removable-chip primitive: a tinted pill showing a label
  and a trailing "×" tap target, built with full Hover/Focused/Pressed
  states via `FocusableActionDetector` from the start.
- **`TicketFilterPopover`**
  (`features/tickets/presentation/widgets/ticket_filter_popover.dart`) —
  a new overlay widget offering three independently-toggleable checkbox
  groups (Status/Type/Priority) anchored to a trigger widget, structured
  on `SelectionMenu<T>`'s `LayerLink`/`OverlayEntry` mechanics but never
  auto-closing on selection (multi-select stays open across taps; closes
  only on tap-outside or `Escape`). Each row is an `OverlayMenuItem`
  wrapping an `AppCheckbox` plus the item's existing label helper
  (`ticketStatusLabel`/`ticketTypeLabel`/`ticketPriorityLabel`) — fully
  keyboard-focusable and `Enter`/`Space`-activatable from the start,
  unlike `AppDropdown`'s existing overlay rows.
- **`TicketsCubit.selectedStatuses`/`.selectedTypes`/`.selectedPriorities`**
  — plain getters exposing the filter sets `searchTickets` was last
  called with (i.e. `_lastStatuses`/`_lastTypes`/`_lastPriorities`).
- **`TicketsCubit.toggleStatusFilter(TicketStatus)`/`.toggleTypeFilter
  (TicketType)`/`.togglePriorityFilter(TicketPriority)`** — each toggles
  membership of the given value in the corresponding selected set,
  persists the new `TicketListFilters` via the cubit's optional
  `TicketListFilterRepository` dependency (no-ops if that dependency or
  `_projectId` is `null`), then re-runs `searchTickets` reusing
  `_lastQuery` and the other two dimensions unchanged. Used by both
  `TicketFilterPopover`'s checkboxes and `AppFilterChip`'s "×" (chip
  removal is "toggle this value off" — same code path).
- **`TicketsCubit.loadPersistedFilters()`** — reads the active project's
  persisted `TicketListFilters` (via the same optional dependency) into
  `_lastStatuses`/`_lastTypes`/`_lastPriorities`, without running a
  search or emitting a state. Called once by `TicketsListScreen.initState`
  before its first `searchTickets()` call, so the initial list render
  already reflects the persisted selection.
- **`TicketsCubit` constructor param `filterRepository:
  TicketListFilterRepository?`** — optional, following the file's
  existing optional-dependency convention; `null` (the default) leaves
  filter selection working exactly as before, just unpersisted.

## MODIFIED

- **`TicketRepository.searchTickets`/`TicketDao.searchTickets`/
  `DriftTicketRepository.searchTickets`** — `status`/`type`/`priority`
  parameters (each a nullable single value) become `statuses`/`types`/
  `priorities` (each a `Set<T>`, defaulting to the empty set). An empty
  set means "no constraint on this field" (replaces the old `null`
  meaning); a non-empty set matches *any* value in it (OR within the
  field) — cross-field combination stays AND, unchanged from today. Both
  of `TicketDao.searchTickets`'s existing query-building paths (the plain
  drift `Query` used with no search text, and the raw `customSelect` FTS
  join used with search text) are rewritten to build an `IN (...)` clause
  per non-empty set instead of an `=` clause per non-null value.
- **`TicketsCubit.searchTickets`** — `status`/`type`/`priority` params
  become `statuses`/`types`/`priorities` (`Set<T>`, default empty),
  matching the repository signature above. Behavior otherwise unchanged:
  still remembers the args for `loadMoreTickets()`/mutation-refresh
  reuse, still the sole entry point `TicketsListScreen` uses to load its
  list, still treats "everything omitted" as unfiltered pagination.
- **`TicketsCubit`'s internal `_lastStatus`/`_lastType`/`_lastPriority`
  fields** — become `_lastStatuses`/`_lastTypes`/`_lastPriorities`
  (`Set<T>`, default empty, replacing the nullable single-value shape).
  Every existing reuse site (`loadMoreTickets`, and every
  mutation-triggered refresh that re-applies the last-used filters)
  updated accordingly — no change in *when* they're reused, only in
  their type.
- **`TicketsListScreen`'s "Search and filtering" section** — the row of
  three `AppDropdown<T?>` filters (status/type/priority, each with a
  `null` "All ___" sentinel item) is replaced by a single "Filters"
  trigger button (an active-count badge, styled with the same
  `primarySubtle`/`primary` tint `AppDropdown.isActive` used) that opens
  a `TicketFilterPopover`, plus a chip row below it (one `AppFilterChip`
  per currently-selected value across all three fields, hidden entirely
  when nothing is selected). Filter *selection state* moves from the
  screen's own `StatefulWidget` fields
  (`_statusFilter`/`_typeFilter`/`_priorityFilter`, now removed) into
  `TicketsCubit` (`selectedStatuses`/etc., §ADDED above) — the screen
  reads the cubit's getters and calls its toggle methods directly, with
  no local `setState` for filter selection. The search-text field, its
  250ms debounce, and its own widget-local `Timer` are unchanged by this
  delta (a separate, pre-existing pattern, not in scope here). Board
  mode's existing client-side `story`-plus-`isExecutable` restriction
  layered on top of the loaded ticket list is unchanged. `_hasActiveFilter`
  now reads the cubit's three selection getters instead of the removed
  local fields.
- **`TicketsListScreen.initState`** — now awaits (fire-and-forget, via
  `unawaited`) `TicketsCubit.loadPersistedFilters()` before its first
  `searchTickets()` call, instead of calling `_runSearch()` synchronously
  with always-empty filters.
- **`app_router.dart`'s `TicketsCubit` construction** — gains a
  `filterRepository: context.read<TicketListFilterRepository>()`
  argument, backed by a new `RepositoryProvider<TicketListFilterRepository>`
  (`SharedPrefsTicketListFilterRepository()`) added alongside the
  existing repository providers in the same widget subtree.

## REMOVED

- The three-`AppDropdown` filter row on `TicketsListScreen` (superseded
  by the Filters trigger + popover + chip row above). `AppDropdown`
  itself is untouched and stays in use elsewhere (e.g.
  `TicketParentPicker`, `CreateTicketScreen`'s type/priority fields).
- `TicketsListScreen`'s `_statusFilter`/`_typeFilter`/`_priorityFilter`
  `StatefulWidget` fields (superseded by `TicketsCubit`'s
  `selectedStatuses`/`selectedTypes`/`selectedPriorities`).
- The now-single-select-only "Known gaps" entry in `tickets.md`: *"The
  ticket list's status/type/priority filters are single-select only... a
  user can filter to `backlog` or `todo`, not `backlog` OR `todo` in one
  dimension."* — resolved by this change.
- l10n keys `ticketsListFilterAllStatuses`/`ticketsListFilterAllTypes`/
  `ticketsListFilterAllPriorities` (the dropdown's "All ___" sentinel
  labels), if confirmed to have no other reference at `/apply` time — a
  multi-select empty set has no equivalent "All" item to label.
