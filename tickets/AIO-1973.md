# `WorkflowStatusSettingsScreen` — exclude `SddStage.archived` (the

one `SddStage.values` entry with no precondition) from getting
the "Configure precondition" affordance. `/verify` found the
`for (final stage in SddStage.values)` loop feeding
`_SddStageRenameRow` unconditionally, so `_PreconditionAffordance`
rendered — and its route pushed and loaded — for `archived` too,
contradicting design.md §5 ("every one of the five stages carries
a precondition") and proposal.md's Non-goals (`archived` has no
precondition, untouched). Fixed by guarding the affordance's
render site (`if (widget.stage != SddStage.archived)`) rather
than the outer loop — `_SddStageRenameRow` still renders for
`archived` (it still needs its rename field), only the
precondition affordance is withheld. Added a regression test
asserting the "Configure precondition" semantics label exists for
all 5 precondition-bearing stages and not for `archived`.
