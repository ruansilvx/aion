# Spec Delta: board-execution-indicators-and-notifications

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md` "Coding execution" and "Board view" sections — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification (e.g. bare `_foo` vs `TicketsCubit._foo`), line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. retry/queue mechanics (in-flight tracking, `_preExecutionStatus`, restart persistence) are confirmed present in the merged Coding execution section.

## ADDED

- **`TicketsCubit._inFlightStageAdvanceIds`** (`Set<String>`, in-memory,
  does not survive an app restart) — Epic/Story ids currently mid-`advanceSddStage`,
  plus, once known, the id of the chat ticket that advance spawned. Both
  ids for one in-flight advance are added/removed together. Mirrors
  `_inFlightExecutionTaskId`'s role but as a plain `Set` rather than a
  single id + FIFO queue — stage chats share no exclusive resource (no
  git worktree, unlike coding-execution), so concurrent Epic/Story
  advances are allowed.
- **`TicketDetailLoaded.isAdvancingStage`** (`bool`, default `false`) —
  `true` when the loaded ticket is an `epic`/`story` with an in-flight
  `advanceSddStage` spawn, *or* a `chat` ticket that is itself that
  spawn's target. Computed by `TicketsCubit.getTicketById` from
  `_inFlightStageAdvanceIds`, the same-shape sibling of `isExecuting` one
  ticket-type-hierarchy level up.
- **`TicketDetailLoaded.sddStageFailureReason`** (`String?`, default
  `null`) and **`TicketDetailLoaded.sddStageCanRetry`** (`bool`, default
  `false`) — why an `epic`/`story`'s most recent stage-advance attempt
  failed, and whether a retry is available. Computed by
  `TicketsCubit._computeStageAdvanceFailure`, mirroring
  `executionFailureReason`/`executionCanRetry`'s persisted-comment-thread
  derivation (survives an app restart, unlike `isAdvancingStage`).
- **`TicketsLoaded.inFlightExecutionIds`** (`Set<String>`, default `{}`),
  **`TicketsLoaded.executionQueuePositions`** (`Map<String, int>`,
  default `{}`), and **`TicketsLoaded.inFlightAdvanceIds`** (`Set<String>`,
  default `{}`) — the same underlying in-memory state `getTicketById`
  already exposes per-ticket, now also reachable from the Board's
  list-shaped state. Refreshed by a new private
  `TicketsCubit._refreshInFlightBoardState()`, called at every mutation
  site of `_inFlightExecutionTaskId`/`_executionQueue`/
  `_inFlightStageAdvanceIds` (`_triggerOrQueueCodingExecution`,
  `_dequeueNext`, `_runCodingExecution`'s completion/error paths,
  `advanceSddStage`, `_runStageChatTurn`). No-ops (does not emit) unless
  `state is TicketsLoaded` — nothing to refresh while a detail screen or
  a mutation-in-flight state is showing instead.
- **`TicketsCubit._createStageChat(Ticket parent, SddStage stage)`** —
  the chat-ticket-creation + context-comment-post half of the former
  `_spawnStageChat`, `await`ed, returning the new chat's id (or `null`
  under the same no-op guards `_spawnStageChat` had).
- **`TicketsCubit._runStageChatTurn(Ticket parent, SddStage stage, String
  chatId)`** — the `ChatCubit.runChatTurn` half of the former
  `_spawnStageChat`, called `unawaited` from `advanceSddStage`. Wrapped
  in a `catch` that posts a `"Stage advance failed: <e>"` system comment
  (mirrors `_runCodingExecution`'s `"Execution failed: ..."` shape) and
  emits `TicketsError(reason: TicketsErrorReason.sddStageAdvanceFailed)`.
  Removes `parent.id` and `chatId` from `_inFlightStageAdvanceIds` on
  both success and failure.
- **`TicketsCubit._computeStageAdvanceFailure(String epicOrStoryId)`** —
  mirrors `_computeExecutionFailure`'s shape against the ticket's most
  recent stage-type chat child instead of an execution chat: a
  `"Stage advance failed: "`-prefixed most-recent comment → that reason,
  retriable; no `chat` child, or its most recent comment is
  `ai`-authored → not failed; a `chat` child whose most recent comment
  isn't `ai`-authored and the ticket isn't in `_inFlightStageAdvanceIds`
  (orphaned, e.g. after a restart mid-turn) → a fixed "ended without a
  clear result" message, retriable.
- **`TicketsErrorReason.sddStageAdvanceFailed`** — a spawned SDD-stage
  chat's turn hard-failed. Surfaced once via `AppToast`, alongside the
  Epic/Story detail screen's new failure banner.
- **Board card execution/advance indicator.** `TicketBoardCard`/
  `_CardVisual` (`tickets_board_view.dart`) render a compact badge driven
  by a new `context.select`-based lookup against `TicketsLoaded`'s three
  new fields: "Running" (Task/Bug, `inFlightExecutionIds`), "Queued #N"
  (Task/Bug, `executionQueuePositions`), "Advancing" (Epic/Story,
  `inFlightAdvanceIds`). No badge for `executionAwaitingReview`/
  `executionFailureReason` or their stage-advance equivalents — see
  proposal.md's scope-narrowing note.
- **`_SddStageSection` advancing/failure states**
  (`ticket_metadata_section.dart`) — new `isAdvancingStage`/
  `sddStageFailureReason`/`sddStageCanRetry`/`onRetryStageAdvance`
  params drive a new "Advancing to `<stage>`" hint (mirrors
  `_ExecutionRunningHint`, no live-tool-use sub-line) and a new
  stage-advance failure banner (mirrors `_ExecutionActionBanner(tone:
  .failure)`), both taking priority over the existing gated/manual/auto
  Advance controls and the "Not ready" hint.
- **Chat-ticket "Waiting for reply…" indicator**
  (`ticket_detail_screen.dart`) — shown in place of the pending AI reply
  when the currently-viewed `chat`-type ticket's own `isAdvancingStage`
  is `true` (i.e., it's the live target of a `_runStageChatTurn` this
  screen's own `ChatCubit` didn't itself initiate). A new
  `BlocListener<TicketsCubit, TicketsState>` case calls
  `ChatCubit.loadMessages` when this ticket's `isAdvancingStage`
  transitions `true` → `false`, so the real reply replaces the indicator
  once it lands.
- **Shell-level `TicketsErrorReason` toast.** `WorkspaceNavShell`
  (`core/routing/workspace_nav_shell.dart`) wraps its `build` output in a
  `BlocListener<TicketsCubit, TicketsState>` that calls
  `AppToast.show(context, ticketsErrorMessage(context, reason))` for
  every classified `TicketsError` (all seven `TicketsErrorReason`
  values), regardless of which `/workspace/*` screen (Board, a ticket
  detail, Documentation, Settings) is currently active.

## MODIFIED

- **`TicketsCubit.advanceSddStage`.** Previously: persisted the stage,
  re-emitted `TicketDetailLoaded`, then `return await _spawnStageChat(...)`
  — the caller's `Future<String?>` didn't resolve until the spawned
  chat's first AI reply was persisted. Now: persists the stage,
  re-emits `TicketDetailLoaded(isAdvancingStage: true)`, adds the
  ticket's id to `_inFlightStageAdvanceIds`, `await`s only
  `_createStageChat` (chat-ticket creation + context comment — fast),
  adds the resulting chat id to `_inFlightStageAdvanceIds` too, then
  fires `unawaited(_runStageChatTurn(...))` and returns the chat id
  immediately. The caller's contract (`Future<String?>`, resolves to the
  chat id or `null`) is unchanged; it now resolves sooner. Also gains an
  early no-op guard: if `ticket.id` is already in
  `_inFlightStageAdvanceIds`, returns `null` without starting a second
  concurrent spawn (double-tap/rebuild-race guard).
- **`TicketsCubit._spawnStageChat`** — removed, replaced by
  `_createStageChat` + `_runStageChatTurn` (see ADDED). No behavioral
  change to the design-Page side effect, the context-comment content, or
  the model resolved per stage — only the awaited/backgrounded split.
- **`TicketsCubit._triggerOrQueueCodingExecution`/`_dequeueNext`/
  `_runCodingExecution`'s completion and error paths** — unchanged
  control flow, each gains a `_refreshInFlightBoardState()` call
  immediately after mutating `_inFlightExecutionTaskId`/
  `_executionQueue`.
- **`ticket_detail_screen.dart`'s `BlocListener<TicketsCubit,
  TicketsState>`.** Previously: handled `TicketTrashed` (navigate),
  `TicketDetailLoaded` (local state + relations load), and three of four
  `TicketsErrorReason` toast cases inline (`invalidParent`,
  `codingExecutionBlocked`, `executionBudgetOverageDetected` —
  `executionVerificationFailed` was never handled here, a pre-existing
  gap). Now: the three toast branches are removed — that responsibility
  moves to `WorkspaceNavShell`'s new listener (see ADDED). `TicketTrashed`/
  `TicketDetailLoaded` handling is unchanged.
- **`create_ticket_screen.dart`'s `BlocListener<TicketsCubit,
  TicketsState>`.** Previously: `state is TicketsError` showed a toast
  for *any* reason (classified or not) via `ticketsErrorMessage`/raw
  `message`. Now: narrowed to `state is TicketsError && state.reason ==
  null` — classified reasons are now the shell-level listener's job;
  this screen's listener still covers an unclassified (raw-message)
  `TicketsError`, which the shell-level listener intentionally skips.
- **`ticketsErrorMessage`** (`tickets_board_view.dart:53-67`) — gains a
  `TicketsErrorReason.sddStageAdvanceFailed` case in its `switch`. No
  change to existing cases.

## REMOVED

- None. Every change is additive or a behavior-preserving relocation
  (toast listening moved, not dropped; `_spawnStageChat`'s work is
  fully preserved across `_createStageChat`/`_runStageChatTurn`, just
  split by `await` boundary).
