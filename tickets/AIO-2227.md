## Domain Layer

### `Ticket.copyWith` (widened)

Current form only handles `status`/`updatedAt`. This change widens it to
cover every field this slice makes editable. `description`, `estimate`,
and `timeSpent` are nullable and need to be *clearable* — a plain
`x ?? this.x` fallback can't distinguish "caller didn't pass this field"
from "caller explicitly wants it set to null," since both look like `null`
at the call site. Standard fix: those three params take a nullary
function ("setter") instead of a bare value — presence of the function
(not its return value) signals intent to overwrite.

```dart
typedef _FieldSetter<T> = T Function();

/// Returns a copy of this ticket with the given fields replaced.
/// [description], [estimate], and [timeSpent] are nullable and therefore
/// take a zero-arg setter instead of a bare value — pass `() => null` to
/// explicitly clear one of them, or omit the parameter entirely to leave
/// it unchanged. `id`, `ticketId`, `parentId`, `embedding`, and `createdAt`
/// are never mutated by this method.
Ticket copyWith({
  String? title,
  _FieldSetter<String?>? description,
  TicketStatus? status,
  TicketPriority? priority,
  TicketType? type,
  _FieldSetter<int?>? estimate,
  _FieldSetter<int?>? timeSpent,
  DateTime? updatedAt,
}) {
  return Ticket(
    id: id,
    ticketId: ticketId,
    type: type ?? this.type,
    title: title ?? this.title,
    description: description != null ? description() : this.description,
    status: status ?? this.status,
    priority: priority ?? this.priority,
    parentId: parentId,
    embedding: embedding,
    estimate: estimate != null ? estimate() : this.estimate,
    timeSpent: timeSpent != null ? timeSpent() : this.timeSpent,
    createdAt: createdAt,
    updatedAt: updatedAt ?? this.updatedAt,
  );
}
```

`_FieldSetter<T>` is a plain top-level function-type typedef — no import
needed, so the domain layer's "no Flutter imports" rule stays intact
(this is why it's a hand-rolled typedef here rather than Flutter's
`ValueGetter<T>`).

Callers: `ticket.copyWith(title: 'New title')`,
`ticket.copyWith(description: () => null)` (clears),
`ticket.copyWith(estimate: () => 90)` (sets to 90 minutes).

## Data Layer

### `TicketDao` (modified — rename)

```dart
/// Applies [companion] to the ticket row with primary key [id]. Generic —
/// [companion] may cover any subset of columns; both status-only updates
/// ([DriftTicketRepository.updateTicketStatus]) and general field updates
/// ([DriftTicketRepository.updateTicket]) go through this one method.
Future<void> update(String id, TicketsTableCompanion companion) {
  return (update(ticketsTable)..where((t) => t.id.equals(id))).write(companion);
}
```

Renamed from `updateStatus` — the method body was already fully generic
(it just writes whatever companion it's given); the old name was
status-specific only because it had a single caller. This change adds a
second caller, so the name is corrected rather than adding a duplicate
near-identical method. `DriftTicketRepository.updateTicketStatus`'s call
site updates to `_db.ticketDao.update(...)` — mechanical rename, no
behavior change, no schema change.

### `DriftTicketRepository` (modified)

```dart
@override
Future<void> updateTicket(Ticket ticket) {
  return _db.ticketDao.update(
    ticket.id,
    TicketsTableCompanion(
      title: Value(ticket.title),
      description: Value(ticket.description),
      priority: Value(ticket.priority.name),
      type: Value(ticket.type.name),
      estimate: Value(ticket.estimate),
      timeSpent: Value(ticket.timeSpent),
```

Deliberately omits `status` from the companion — the `Ticket` passed in

## Core — Duration Formatting

### `core/utils/duration_format.dart` (new)

```dart
/// Formats [minutes] as a short label ('2h 30m', '45m', '3h'). Returns
/// [placeholder] for `null` or non-positive input.
String formatDurationMinutes(int? minutes, {String placeholder = 'Not set'}) {
  if (minutes == null || minutes <= 0) return placeholder;
  final h = minutes ~/ 60;
  final m = minutes % 60;
  if (h == 0) return '${m}m';
  if (m == 0) return '${h}h';
  return '${h}h ${m}m';
}

/// Parses a free-form duration ('2h30m', '2h 30m', '90m', '2h', or a bare
/// number of minutes like '90') into total minutes. Blank input returns
/// `null` (no estimate/time). Throws [FormatException] for anything else
/// unrecognised.
int? parseDurationMinutes(String input) {
  final trimmed = input.trim();
  if (trimmed.isEmpty) return null;

  final match = RegExp(r'^(?:(\d+)\s*h)?\s*(?:(\d+)\s*m)?$', caseSensitive: false)
      .firstMatch(trimmed);
  if (match != null && (match.group(1) != null || match.group(2) != null)) {
    final hours = int.tryParse(match.group(1) ?? '0') ?? 0;
    final mins = int.tryParse(match.group(2) ?? '0') ?? 0;
    return hours * 60 + mins;
  }

  final bare = int.tryParse(trimmed);
  if (bare != null) return bare;

  throw FormatException('Not a valid duration: "$input"');
}
```

Pure Dart, no Flutter import — lives under `core/utils/`, not
`core/widgets/`.

## Core — `SelectionMenu<T>` (new)

Generalizes the overlay-picker mechanics `MoveToStatusMenu`
(`tickets_board_view.dart`, from `kanban-board-view`) already established:
same `Overlay`/`OverlayEntry`/`LayerLink`/`CompositedTransformFollower`
pattern, same outside-tap-to-dismiss, same `mounted` guard before
`setState` in the dismiss callback (the exact class of bug `project.md`'s
`AppDropdown` crash note warns about). `MoveToStatusMenu` itself is *not*
refactored to use this in this change — it's already shipped and
verified; retrofitting it is out of scope here. `SelectionMenu<T>` is
introduced because this change is the second legitimate need for the
pattern (priority and type), which is exactly when generalizing rather
than copy-pasting a third bespoke widget is the previously-established
project bar (see `kanban-board-view`'s own reasoning for *not*
generalizing `AppDropdown` for a single use).

```dart
class SelectionMenu<T> extends StatefulWidget {
  const SelectionMenu({
    super.key,
    required this.trigger,
    required this.items,
    required this.itemLabel,
    required this.currentValue,
    required this.onSelected,
    required this.semanticsLabel,
  });

  /// The always-visible tappable widget (e.g. a `PriorityBadge`/`TypeChip`).
  final Widget trigger;
  final List<T> items;
  final String Function(T) itemLabel;
  final T currentValue;
  final ValueChanged<T> onSelected;
  final String semanticsLabel;

  @override
  State<SelectionMenu<T>> createState() => _SelectionMenuState<T>();
}
```

- Wraps `trigger` in `CompositedTransformTarget` +
  `FocusableActionDetector` (with `ActivateIntent` opening the overlay —
  built in from the start this time; `kanban-board-view`'s own
  post-verify fixes had to retrofit this onto `MoveToStatusMenu`, so it's
  a known, already-paid-for lesson) + `Semantics(button: true, label:
  semanticsLabel)`.
- Overlay content: `items.map` → one row per item (current value
  highlighted via `c.primarySubtle`/`c.primary`, mirroring
  `MoveToStatusMenu`'s existing overlay row styling), `onTap` calls
  `widget.onSelected(item)` then dismisses.
- Dismiss guards `setState` with `if (mounted)`, exactly like
  `MoveToStatusMenu`/`AppDropdown`.

## Presentation — `InlineEditableField<T>` (new)

`lib/features/tickets/presentation/widgets/inline_editable_field.dart`.
One generic tap-to-edit widget reused for title, description, estimate,
and time spent (four call sites; the codebase's own bar for extracting a
shared widget rather than repeating a `StatefulWidget` is "the second or
third real duplicate," same reasoning as `SelectionMenu<T>` above).

```dart
class InlineEditableField<T> extends StatefulWidget {
  const InlineEditableField({
    super.key,
    required this.displayText,
    required this.editText,
    required this.parser,
    required this.onCommit,
    this.placeholder,
    this.maxLines = 1,
    required this.semanticsLabel,
  });

  /// What to render in view mode.
  final String displayText;
  /// Pre-fill text when entering edit mode.
  final String editText;
  /// Parses the raw text box contents into [T]. May throw
  /// [FormatException] (or any Exception) for invalid input — caught by
  /// this widget, surfaced via [AppToast], and reverted; never reaches
  /// [onCommit].
  final T Function(String raw) parser;
  /// Called with the parsed value once validation succeeds.
  final ValueChanged<T> onCommit;
  final String? placeholder;
  final int maxLines;
  final String semanticsLabel;

  @override
  State<InlineEditableField<T>> createState() => _InlineEditableFieldState<T>();
}
```

- **View mode**: `Semantics(button: true, label: semanticsLabel)` +
  `FocusableActionDetector` (`ActivateIntent` → enter edit mode) +
  `GestureDetector` wrapping `Text(displayText.isEmpty ? (placeholder ??
  '') : displayText, ...)` — muted color when showing `placeholder`.
- **Edit mode**: `AppTextField` (reused as-is, not modified), controller
  pre-filled with `editText`, autofocus, `textInputAction: maxLines == 1
  ? TextInputAction.done : TextInputAction.newline`.
  - `Focus`/keyboard handling: `Escape` reverts the controller to
    `editText` and exits edit mode without calling `parser`/`onCommit`.
  - Single-line fields commit on `onSubmitted` (Enter) or on focus loss.
    Multiline (description) commits on focus loss only (Enter inserts a
    newline instead).
  - `_commit()`: calls `widget.parser(controller.text)` in a try/catch. On
    `FormatException`, shows `AppToast.show(context, e.message)`, reverts
    the controller text, exits edit mode — `onCommit` is never called, so
    the cubit/repository is never touched by an invalid duration string.
    On success, calls `widget.onCommit(parsed)` and exits edit mode.
  - **`mounted` guard**: the focus-node listener that triggers `_commit()`
    on blur must check `if (!mounted) return;` before any `setState` —
    same class of bug as the project's documented `AppDropdown`
    overlay-dismiss crash (`project.md` Testing section). Call out
    explicitly in `tasks.md`; this is exactly the kind of thing
    `flutter analyze`/`flutter test` won't catch.

Field-specific wiring (all inside `TicketDetailScreen`, all calling
`context.read<TicketsCubit>().updateTicket(...)`):

| Field | `T` | `parser` | `onCommit` |
|---|---|---|---|
| Title | `String` | trims; throws `FormatException('Title is required')` if empty | `cubit.updateTicket(ticket.copyWith(title: v))` |
| Description | `String?` | trims; empty → `null` (never throws) | `cubit.updateTicket(ticket.copyWith(description: () => v))` |
| Estimate | `int?` | `parseDurationMinutes` | `cubit.updateTicket(ticket.copyWith(estimate: () => v))` |
| Time spent | `int?` | `parseDurationMinutes` | `cubit.updateTicket(ticket.copyWith(timeSpent: () => v))` |

`displayText`/`editText` for estimate/time spent come from
`formatDurationMinutes(ticket.estimate)` /
`formatDurationMinutes(ticket.timeSpent)`; `placeholder: 'Add an
estimate…'` / `'Add time spent…'` when null.

## Presentation — Cubit

### `TicketsCubit.updateTicket` (new method, no new states)

```dart
/// Persists every editable field of [ticket] via
/// [TicketRepository.updateTicket], then re-fetches and emits
/// [TicketDetailLoaded] with the refreshed ticket. Emits [TicketsError] on
/// failure. Unlike [updateTicketStatus], this does not emit an optimistic
/// intermediate state — the calling [InlineEditableField]/[SelectionMenu]
/// already renders the new value locally before the repository round trip
/// completes, so no separate "Updating" state is needed here.
Future<void> updateTicket(Ticket ticket) async {
  try {
    await _repository.updateTicket(ticket);
    final refreshed = await _repository.getTicketById(ticket.id);
    if (refreshed != null) {
      emit(TicketDetailLoaded(refreshed));
    }
  } catch (e) {
    emit(TicketsError(e.toString()));
  }
}
```

A repository-level failure here still falls through to the existing
`TicketsError` branch in `TicketDetailScreen`'s `BlocBuilder`, which
replaces the whole ticket-detail body with the error message — the same
degraded-but-consistent behavior `updateTicketStatus` already has on the
board. This is a deliberate scope call (see `proposal.md`'s "Out" list):
only client-side format validation (duration parsing) gets a friendlier
inline toast-and-revert; a genuine backend failure is rare and treated
the same as every other mutation in this cubit.

## Accessibility

- Every new interactive element (`InlineEditableField` triggers,
  `SelectionMenu` triggers) carries `Semantics(button: true, label: ...)`

  built in from the start — not retrofitted after a verify pass, unlike
  `MoveToStatusMenu`'s history in `kanban-board-view`.

- `AppTextField` (reused, unmodified) already carries its own label/hint

# Aion — Ticket Detail Inline Editing: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name; no new tokens are introduced — every state below is expressible with the existing set. No Material widgets. `TextField` wrapped in a transparent `Material` is the only Material usage, matching the existing `AppTextField` pattern.

Covers six fields on the ticket detail screen becoming in-place editable: **Title**, **Description**, **Priority**, **Type**, **Estimate** (new), **Time Spent** (new). Status is unaffected — no status editor is specified here.

---

## 1. Inline editable text field

Used for **Title** (single-line) and **Description** (multiline). Two states of the same widget: **view** and **editing**. Never a separate "edit mode" for the whole screen — each field converts independently on tap.

### 1.1 View state — has value

- No container chrome (no fill, no border) — reads as plain text sitting in the layout, identical to today's read-only rendering.
- Title text: `AionText.h2`, color `textPrimary`.
- Description text: `AionText.body`, color `textSecondary`, up to full content height (no clamp on detail screen).
- Hit target: `GestureDetector` wraps the full text block; `HitTestBehavior.opaque` so tapping anywhere in blank space within the block still registers.

### 1.2 View state — empty (Description only)

- Renders the placeholder copy instead of blank space: `"Add a description…"`.
- Text style: `AionText.body`, color `textMuted`.
- The placeholder text itself is the tap target — no separate "+ Add" button.
- Title has no empty state (a ticket always has a title).

### 1.3 Hover state (desktop / web pointer only — skip on touch)

- Signals "tappable" without changing layout or type size:
  - Background: `DecoratedBox` fill `surfaceHover`, `BorderRadius(AionRadius.md)` (10), padding added to compensate so text position doesn't shift — `EdgeInsets.symmetric(horizontal: 8, vertical: 4)` inset, with an equal negative margin (`Transform.translate` by `-8, -4`) so the text itself stays pinned to the non-hover layout position.
  - Trailing edit glyph (`feather`/`quill`, 14px, color `textMuted`) fades in (`AnimatedOpacity`, 120ms) at the end of the text line — `margin-left: 6`. For multiline Description, the glyph sits at the top-right of the block, not inline with wrapped text.
- Cursor: `SystemMouseCursors.text`.

### 1.4 Focused / editing state

Matches the existing `AppTextField` visual language exactly:

- Fill: `surface`.
- Border: `1.5px solid primary`.
- Focus ring: `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), blurRadius: 0, spreadRadius: 3)`.
- Radius: `AionRadius.lg` (12).
- Text style: same as view state (`h2` for title, `body` for description) — no size change between view and edit, so the field doesn't visually "jump."
- Cursor color: `primary`. Selection highlight: `primary.withOpacity(0.24)`.

**Title (single-line):**
- Padding: `EdgeInsets.symmetric(horizontal: 14, vertical: 11)`.
- `TextInputAction.done` — Enter commits and blurs.
- `maxLines: 1`, overflow disabled while editing (field scrolls horizontally rather than wrapping).

**Description (multiline):**
- Padding: `EdgeInsets.symmetric(horizontal: 14, vertical: 13)`.
- Min height: 6 lines (`AionText.body` line-height 1.5 → ~136px min height), grows with content, no max.
- `TextInputAction.newline`; a lightweight `Row` below the field (`gap: 12`, right-aligned, padding-top `8`) holds two `Button` (§2.1 base spec) instances — **Cancel** (Ghost) and **Save** (Primary, small) — shown only while this field is focused, so multiline commit doesn't rely on losing focus by accident.

**Commit / cancel:**
- Title: commits on blur or Enter. Escape (`Esc` key on web/desktop) reverts to last saved value and blurs.
- Description: commits only via the **Save** button, Cancel button, or Escape — never on blur alone, since blur happens too easily while scrolling a long multiline field.

### 1.5 Error state

- Submitting an empty Title (Description has no validation — empty is a valid "no description" state) is rejected.
- **No inline error color or border change.** On rejection:
  1. Field reverts immediately to its previous view-state value and rendering (no lingering red border).
  2. A toast (§5) appears: `"Title can't be empty"`, icon `danger`, auto-dismisses after 3.2s or on tap.

## 2. Inline editable duration field

Used for **Estimate** and **Time Spent** — new fields, not present in the current detail screen. Always single-line. Same interaction shape as §1 (view → hover → focus), distinguished by a leading glyph and compact sizing.

### 2.1 Placeholder state (no value)

- Leading icon: `clock` (Phosphor Light or equivalent), **16px**, color `textMuted`.
- Text: `"Add an estimate…"` / `"Add time spent…"`, `AionText.bodySm`, color `textMuted`.
- Layout: `Row`, `gap: 6`, `crossAxisAlignment: center`.
- No container chrome in view state, same as §1.1.

### 2.2 Value state

- Leading icon: same `clock` glyph, 16px, color `textSecondary` (one step darker than placeholder — reads as "filled in").
- Text: compact duration label (e.g. `"2h 30m"`, `"45m"`), `AionText.bodySm`, color `textPrimary`, `fontWeight` bumped to `w600` inline via `.copyWith` (distinguishes a real value from the label style used elsewhere at `bodySm`'s default w400).

### 2.3 Hover state

- Same treatment as §1.3: `surfaceHover` fill, `AionRadius.md`, edit glyph (12px this time, to match the field's smaller scale) fades in after the text.

### 2.4 Focused / editing state

- Fill `surface`, border `1.5px solid primary`, radius `AionRadius.md` (10 — smaller field, smaller radius than the text fields' `lg`), focus ring identical formula to §1.4.
- Padding: `EdgeInsets.symmetric(horizontal: 10, vertical: 8)`.
- Leading `clock` icon persists inside the field, 16px, color `textSecondary`, `margin-right: 6`.
- Input text: `AionText.bodySm` w600, `textPrimary`.
- Free-text entry (not a stepper/picker) — accepts strings like `2h 30m`, `45m`, `1h`; parse/validate on commit. `TextInputAction.done`; Enter or blur commits.
- **Invalid format** (doesn't parse to a duration) uses the same non-inline pattern as §1.5: field reverts to previous value, toast reads `"Couldn't read that as a duration — try '2h 30m'"`.

---

## 3. Selection menu / overlay picker

Used for **Priority** and **Type**. The trigger is the existing badge/chip; tapping opens an `Overlay` entry anchored below it (`CompositedTransformFollower`, offset `(0, 6)`).

### 3.1 Trigger — default state

- Unchanged visual: Priority badge per base spec §2.3, Type chip per base spec §2.2.

### 3.2 Trigger — hover state

- Add `1px solid` ring in the badge/chip's own foreground color at low opacity, no fill change: `border: 1px solid {fg}.withOpacity(isDark ? 0.35 : 0.25)`. Keeps the "tappable" cue theme-agnostic without introducing a new fill.
- Cursor: `SystemMouseCursors.click`.

### 3.3 Overlay container

- Fill: `surface`.
- Border: `1px solid borderStrong`.
- Radius: `AionRadius.lg` (12).
- Shadow: `BoxShadow(color: rgba(0,0,0, isDark ? 0.55 : 0.16), blurRadius: 28, offset: Offset(0, 12))`.
- Width: `min(220, trigger-width * 2.2)` — wide enough for the longest label ("Critical" / "Story") plus padding; min `160`.
- Padding: `EdgeInsets.symmetric(vertical: 6)` (rows fill full width, no horizontal container padding).
- Entrance: scale-in from `0.96 → 1.0` + fade, 120ms, anchored top-left (grows from the trigger).

### 3.4 List row

- Height: `40`. Padding: `EdgeInsets.symmetric(horizontal: 13, vertical: 9)`.
- Layout: `Row`, `gap: 9` — leading swatch (priority: filled `10×10` circle in that level's `fg` color; type: filled `10×10` square, radius `2`, in that type's base color) + label (`AionText.bodySm`, `w600` inline override).
- **Default:** fill transparent, label color `textPrimary`.
- **Hover:** fill `surfaceHover`.
- **Selected** (only relevant if the current value is ever listed — see §3.5/3.6): fill `primarySubtle`, label color `primary`, trailing checkmark glyph (`check`, 14px, `primary`).
- **Pressed:** fill one step darker — `surfaceHover` at `0.7` opacity blended toward `borderStrong`, or simply reuse `primarySubtle` momentarily before commit.
- Divider: none between rows — the `9px` vertical padding plus row height provides enough separation; add a single `1px solid border` divider only before a destructive-style row (not applicable here — no "remove priority" action specified).

### 3.5 Priority menu content

- Lists the **three other** priority levels (excludes the current value — no point offering to re-select it). Order fixed: Critical → High → Medium → Low, skipping whichever is current.
- Swatch color = that level's `Fg` token (e.g. Critical row swatch = `priority.criticalFg`).

### 3.6 Type menu content

- Lists the **other two** types (Task / Story / Epic, excluding current).
- Swatch color = that type's base token (`typeTask` / `typeStory` / `typeEpic`).

### 3.7 Dismissal

- Tap a row → commits new value, closes overlay, trigger badge/chip re-renders with new colors/label immediately (no toast on success — this is a low-stakes, reversible action).
- Tap outside (scrim is invisible/hit-testable, not a dimming layer — this is an inline control, not a modal) → closes overlay, no change.
- `Esc` (desktop/web) → closes overlay, no change.

## 5. Error toast

Used by §1.5 and §2.4's error paths. Not a `SnackBar`/`ScaffoldMessenger` — a custom `Overlay` entry.

- Position: bottom-anchored, `16px` above the comment composer's top edge, horizontally centered, max-width `320`.
- Container: fill `surface`, border `1px solid border`, radius `AionRadius.lg` (12), shadow `BoxShadow(color: rgba(0,0,0, isDark ? 0.5 : 0.14), blurRadius: 24, offset: Offset(0,10))`.
- Padding: `EdgeInsets.symmetric(horizontal: 14, vertical: 12)`.
- Layout: `Row`, `gap: 10` — leading icon (`x-circle` or `warning-circle`, 18px, `danger`) + message (`AionText.bodySm`, `textPrimary`, flexible/wraps to 2 lines max).
- Entrance: slide up `12px` + fade, 160ms. Auto-dismiss after `3.2s` (fade + slide down 12px, 160ms) or immediately on tap.
- Only one toast at a time — a new error replaces the current toast rather than stacking.
