# 2. Widened signal promotion

- [x] 2.1 Modify `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart` —
      rename `promoteSignalToEpic` to `promoteSignal`, add required
      `TicketType targetType` parameter, validate
      `targetType == TicketType.epic || targetType == TicketType.bug`
      (else `emit(TicketsError(...))`, mirroring the existing
      wrong-source-type guard), and replace the hardcoded
      `TicketType.epic` ticket-creation branch with `targetType`.
      Rename the `existingEpicId` parameter to `existingTicketId`.
      Update the method's full dartdoc to describe both target types.
- [x] 2.2 Modify `aion/lib/features/tickets/presentation/widgets/ticket_overflow_menu.dart` —
      `_RootMenu`'s single "Promote to Epic" row becomes two rows
      ("Promote to Epic" / "Promote to Bug"); `_PromoteChooser` gains a
      `targetType` parameter threaded into its `candidatesLoader`
      (`all.where((t) => t.type == targetType)` instead of the
      hardcoded epic filter) and into its `onCreateNewTap`/
      `onLinkSelected` calls to `promoteSignal`. Whichever row matches
      `widget.ticket.suggestedType` (when non-null) is visually
      distinguished as the suggested default per design.md §7 Widened
      "Promote" menu (existing signal chooser, modified) — a
      "Suggested" pill (§7.3) plus a resting accent-tinted row
      background (§7.3.1), not the draft's own unrelated §7 (Screens &
      widgets). The resting-tint alpha pair (0.09/0.06) doesn't match
      any existing `AionColorsHubTokens` method (which all close over
      one fixed instance field, e.g. `primary`/`danger`) since this one
      is parameterized on whichever accent (`typeEpic`/`typeBug`) is
      suggested — add a new generic method to that extension taking an
      explicit `Color` parameter: `Color accentTint(Color accent, bool
      isDark) => accent.withValues(alpha: isDark ? 0.09 : 0.06);` in
      `aion/lib/design_system/tokens/aion_colors.dart`. Update widget
      dartdocs.
- [x] 2.3 Update `aion/lib/l10n/app_en.arb` — replace whatever single
      key covered "Promote to Epic" with `ticketOverflowPromoteToEpic`/
      `ticketOverflowPromoteToBug`, following the existing
      `ticketOverflow*` naming convention.
- [x] 2.4 Extend `test/features/tickets/presentation/cubit/tickets_cubit_test.dart`
      (`bloc_test`) — `promoteSignal(targetType: epic)` and
      `promoteSignal(targetType: bug)` both create/link correctly;
      an invalid `targetType` (anything else) emits the classified
      error without touching the repository. Extend
      `test/features/tickets/presentation/widgets/ticket_overflow_menu_test.dart`
      (widget test) — both promote rows open the chooser with the
      correctly filtered candidate list; a `suggestedType` signal
      visually highlights the matching row.
