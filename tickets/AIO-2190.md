# Tasks: Ticket Detail Status Editing

Strict, ordered checklist. Each task that creates/modifies a Dart file
includes its documentation (dartdoc + file header where applicable) in the
same task — no separate doc-cleanup task.

- [x] 1. **`lib/l10n/app_en.arb`** — add
      `"ticketDetailChangeStatus": "Change status",` next to the existing
      `ticketDetailChangePriority`/`ticketDetailChangeType` entries. No
      `@`-metadata block needed (matches those two entries).

- [x] 2. **Regenerate localization bindings** — run
      `flutter gen-l10n` so `lib/l10n/generated/app_localizations*.dart`
      (gitignored) picks up `ticketDetailChangeStatus` and exposes it via
      `context.l10n`.

- [x] 3. **`lib/features/tickets/presentation/cubit/tickets_cubit.dart`**
      — add `changeTicketStatus(Ticket ticket, TicketStatus status)`:
      calls `_repository.updateTicketStatus(ticket.id, status)`, re-fetches
      via `_repository.getTicketById(ticket.id)`, emits
      `TicketDetailLoaded(refreshed)` on success or `TicketsError(e.toString())`
      on failure — same try/re-fetch/emit shape as the existing
      `updateTicket` method (see `design.md` for the exact body). Add a
      dartdoc comment on the new method per `flutter-conventions.md`
      (one-line summary + why it exists separately from
      `updateTicketStatus`, matching the docstring drafted in `design.md`).
      No file-header change needed (file already has one).

- [x] 4. **`lib/features/tickets/presentation/screens/ticket_detail_screen.dart`**
      — replace the read-only `StatusIndicator(status: ticket.status)` in
      the type/status `Row` with a `SelectionMenu<TicketStatus>` whose
      `trigger` is that same `StatusIndicator`, `items: TicketStatus.values`,
      `itemLabel: (s) => ticketStatusLabel(context, s)`,
      `currentValue: ticket.status`, `onSelected` calling
      `context.read<TicketsCubit>().changeTicketStatus(ticket, s)`, and
      `semanticsLabel: context.l10n.ticketDetailChangeStatus` — exact
      mirror of the adjacent `SelectionMenu<TicketType>` wiring (see
      `design.md`). `SelectionMenu`, `ticketStatusLabel`, and
      `StatusIndicator` are already imported/used in this file; a direct
      import of `ticket_status.dart` was needed in addition, since this
      edit is the file's first *explicit* reference to the `TicketStatus`
      identifier itself (as a type argument and via `TicketStatus.values`)
      — Dart imports aren't transitive, so `ticket.status`'s inferred type
      didn't require it before. No new public symbols introduced by this
      edit, so no new dartdoc needed beyond what already exists on the
      surrounding widget tree.

- [x] 5. **`test/features/tickets/cubit/tickets_cubit_test.dart`** — add
      two `blocTest` cases for `changeTicketStatus`:
      - success: mocks `repository.updateTicketStatus` to complete and
        `repository.getTicketById` to return the updated ticket; expects
        `[TicketDetailLoaded(updatedTicket)]`.
      - failure: mocks `repository.updateTicketStatus` to throw; expects
        `[isA<TicketsError>()]`; `verifyNever` on `repository.getTicketById`.
      Follow the existing `updateTicket` test cases immediately above/below
      as the template for setup/mocking style.

- [x] 6. **Verify** — run `flutter analyze` (must be clean) and
      `flutter test test/features/tickets/cubit/tickets_cubit_test.dart`
      (must pass). Then do a manual interactive pass in a real Chrome
      instance (not the sandboxed preview browser — see `project.md`'s
      Testing section): open a ticket's detail screen, tap the status
      field, confirm the overlay lists the other five statuses, select
      one, confirm the detail screen updates in place (no blank/flash),
      then navigate to the board and confirm the ticket now shows under
      the new column.
