# 7. Second `/verify` follow-up fix (2026-09-08, same day)

The second `/verify` pass on this branch confirmed the four fixes
above and found one more WARNING against the trash/restore fix
specifically.

- [x] **WARNING — `_projectOrSwallow` caught too broadly.** Its bare
      `catch (_)` swallowed *any* exception from `_project`, not just
      the git/file-write failures it exists to tolerate — risking
      silently hiding an unrelated bug (a serializer defect, a corrupt
      DB read) behind an apparently-successful trash/restore, working
      against this whole change's own "stop silently swallowing
      failures" principle.
      `lib/features/tickets/data/repositories/git_projecting_ticket_repository.dart`:
      narrowed `_projectOrSwallow` to `on ProcessException` (a failed
      `git add`/`status`/`commit`) and `on FileSystemException` (the
      Markdown write itself failing) specifically — anything else now
      propagates and fails loudly. Updated its dartdoc to match.
      Updated the two existing swallow tests in
      `test/features/tickets/data/repositories/git_projecting_ticket_repository_test.dart`
      to throw a real `ProcessException` (previously a generic
      `Exception`, which no longer matches the narrowed catch), and
      added a new test confirming an unrelated exception (`StateError`)
      still propagates instead of being swallowed.
- [x] Re-ran `flutter analyze` (clean, same 2 pre-existing unrelated
      lints) and `test/features/tickets/` (1275/1275 — 1274 plus the
      one new test above).
