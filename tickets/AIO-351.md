# Spec Delta: blocked-ticket-transition-gate

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (20/23 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **A hard gate on a blocked ticket's move to `TicketStatus.inProgress`.**
  Any ticket (every type — Epic, Story, Task, Bug, Resource, Page, Chat)
  that currently has an unresolved `blocks`/`blockedBy` dependency (a
  live link naming it as blockee whose blocker either doesn't exist or
  isn't `TicketStatus.done` — the same definition the Board's
  `_BlockedBadge`/`blockedTicketIds` already use) is rejected from
  moving to `inProgress` via drag-and-drop, `MoveToStatusMenu`, or the
  detail screen's status control. The rejection surfaces as a toast
  (`TicketsErrorReason.blockedByOpenDependency` →
  `ticketsErrorMessage`/`AppToast`) and the write never happens — no
  optimistic update, no repository call, no git-projection trigger.
- **`TicketsCubit._isTicketBlocked(Ticket)`** — new private method.
  Resolves whether a single ticket has an unresolved `blocks`/
  `blockedBy` dependency via `TicketLinkRepository.getLinksForTicket`,
  mirroring `_computeBlockedTicketIds`'s existing row-resolution logic
  (blockee/blocker resolution per link direction) at single-ticket
  scope instead of board-wide scope. Returns `false` if constructed
  without a `TicketLinkRepository`.
- **`TicketsCubit._interceptBlockedDependencyTrigger(Ticket,
  TicketStatus)`** — new private interceptor, same reject-then-re-emit
  shape as the existing `_interceptTaskExecutionTrigger`: on a blocked
  ticket's `inProgress` attempt, emits `TicketsError(reason:
  blockedByOpenDependency)` then a re-emitted unchanged
  `TicketDetailLoaded`, and returns `false` so the caller skips the
  write. Returns `true` (proceed) for every other status, and for an
  unblocked ticket.
- **`TicketsErrorReason.blockedByOpenDependency`** — new enum value.
  Applies to every ticket type, unlike the existing
  `codingExecutionBlocked` (Task/Bug-only).
- **`ticketBlockedByOpenDependencyError`** — new localization key
  (`app_en.arb`), read by `ticketsErrorMessage`'s new switch case.

## MODIFIED

- **`TicketsCubit.updateTicketStatus`** — when `status ==
  TicketStatus.inProgress`, now runs `_interceptBlockedDependencyTrigger`
  against the freshly-fetched target ticket before the existing
  `_interceptTaskExecutionTrigger` call (both share the same up-front
  fetch already present for the `inProgress` case; no new repository
  round trip). A rejection from either interceptor short-circuits the
  method with no write, matching the existing single-interceptor
  behavior's shape.
- **`TicketsCubit.changeTicketStatus`** — same addition: now runs
  `_interceptBlockedDependencyTrigger` ahead of
  `_interceptTaskExecutionTrigger`, both short-circuiting on rejection.
- **`ticketsErrorMessage`** (`tickets_board_view.dart`) — switch
  expression gains the `blockedByOpenDependency` case.

## REMOVED

None.

## Resolves

`tickets.md`'s Known gaps bullet: "No hard gate preventing a blocked
Task/Story from moving to `inProgress` — the Board's `BlockedBadge` is
visual-only, with no effect on drag-and-drop or `MoveToStatusMenu`."
(Resolved for every ticket type, not just Task/Story — see
`proposal.md`'s Scope section for why the gate isn't type-restricted.)
