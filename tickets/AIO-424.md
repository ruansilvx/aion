# Spec Delta: board-task-ordering-indication

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md` "Coding execution" section's Blocked-dependency gate — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification (e.g. bare `_foo` vs `TicketsCubit._foo`), line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. current text explicitly cross-references "the Board's `BlockedBadge` (below)" as the enforcement's visual half, confirming this delta's mechanism is still live.

## ADDED

- **`TicketLinkDao.getLinksByTypes(List<TicketLinkType> types)`** —
  returns every live (neither side trashed) `ticket_links` row whose
  `linkType` is one of `types`, app-wide — not scoped to a single
  ticket. Mirrors `deleteLinksForTickets`'s whole-table-scoped shape
  rather than `getLinksForTicket`'s per-ticket shape.
- **`TicketLinkRepository.getLinksByTypes`** — straight delegation to
  the DAO method above, same one-line shape as the interface's existing
  methods.
- **`TicketsCubit._computeBlockedTicketIds(List<Ticket> allTickets)`**
  — resolves every live `blocks`/`blockedBy` row (via
  `getLinksByTypes`) to a `(blockee, blocker)` pair (`blockedBy`'s
  blockee is its `source`; `blocks`'s blockee is its `target`), and
  returns the set of blockee ids whose blocker's status (looked up in
  `allTickets`) isn't `TicketStatus.done`. Returns `{}` if constructed
  without a `TicketLinkRepository`.
- **`TicketsLoaded.blockedTicketIds`** (`Set<String>`, default `{}`) —
  work-ticket ids currently blocked by an unresolved dependency,
  computed by `_computeBlockedTicketIds`. Recomputed whenever the
  ticket list loads (`searchTickets`, `loadMoreTickets`'s continuation)
  or via the new `_refreshBlockedBoardState()` (mirrors
  `_refreshInFlightBoardState`'s shape: re-emits the current
  `TicketsLoaded` with the field freshly recomputed, no-ops unless
  `state is TicketsLoaded`), called from `updateTicketStatus` and from
  the widened `TicketLinkPicker`'s `onSelected` when the created link's
  type is `blocks`/`blockedBy`.
- **`TicketsCubit._assembleStageContext`'s `SddStage.proposed` branch**
  — previously no branch existed for this stage (context was just
  title+description); now instructs the spawned chat to end its reply
  with a fenced `## Decomposition` block, one `"- Story: <title>"`/
  `"- Task: <title>"` line per child (rank derived the same way the
  existing `verifying`/`archived` branch already derives it: `story`
  children for an `epic` parent, `task` children for a `story` parent),
  optionally suffixed `" (blockedBy: <title>)"` referencing an earlier
  line in the same block.
- **`TicketsCubit._parseDecomposition(String reply, TicketType
  childType)`** — parses the `## Decomposition` block into an ordered
  list of `(title, blockedByTitle)` pairs via a fixed-prefix regex
  (`"- Story: "`/`"- Task: "` depending on `childType`). Returns `[]`
  (not an error) if no block is found or no line matches.
- **`TicketsCubit._materializeDecomposition(Ticket parent, String
  reply)`** — parses `reply` via `_parseDecomposition`, creates one
  child ticket per parsed line under `parent` (`TicketRepository
  .createTicket`), then creates a `blockedBy` link (new child as
  `source`, resolved sibling as `target`) for every line whose
  `blockedByTitle` exact-matches (case-insensitive) another parsed
  line's title. An unresolved `blockedByTitle` skips the link only —
  the child ticket is still created. No block, or a block with no
  parseable lines, is a silent no-op (today's exact behavior — a human
  creates children by hand — is unchanged, not treated as failure).
  Called from `_runStageChatTurn` immediately after a successful
  `SddStage.proposed` turn, reading the reply back via
  `commentRepo.getCommentsForTicket`'s most-recent entry (mirrors
  `_designSyncApproved`'s existing "read back the most recent comment"
  pattern) rather than changing `ChatCubit.runChatTurn`'s shared
  return-value contract.
- **`TicketLinkPicker.linkTypeOptions`** (`List<TicketLinkType>`,
  required) and a changed `onSelected` signature (`void
  Function(Ticket, TicketLinkType)`, previously `ValueChanged<Ticket>`)
  — the overlay's header row gains a `SelectionMenu<TicketLinkType>`
  (same trigger-pattern component already driving priority/complexity/
  type/status pickers), defaulting to `TicketLinkType.relatesTo`,
  restricted to whatever `linkTypeOptions` the caller supplies.
- **Widened Linked Tickets render/load gate.** `ticket_metadata_section
  .dart`'s Linked Tickets section (and `TicketsCubit
  .loadDocumentRelations`'s matching gate) now also render/populate for
  `epic`/`story`/`task` — previously `resource`/`bug` only.
- **`_BlockedBadge`** (`tickets_board_view.dart`) — a static, non-
  interactive pill in `_CardVisual`'s meta-chip row, shown whenever the
  card's ticket id is in `TicketsLoaded.blockedTicketIds`. Rendered
  after `PriorityBadge` and before the existing execution-state
  `Spacer()`+badge block. No effect on drag-and-drop or `MoveToStatus
  Menu` — informational only.
- **Localization.** `ticketLinkTypeBlocks`/`ticketLinkTypeBlockedBy`/
  `ticketLinkTypeRelatesTo`/`ticketLinkTypeDuplicates` (the new
  `SelectionMenu<TicketLinkType>` item labels) and
  `ticketDetailBoardBadgeBlocked` ("Blocked").

## MODIFIED

- **`TicketLinkRepository.createLink`** — no signature or behavior
  change. Direction is already fully expressed by a single row
  (`source`/`target`/`linkType`); this change relies on that existing
  semantics rather than altering it.
- **`ticket_metadata_section.dart`'s Linked Tickets call site.** The
  type gate (`ticket.type != TicketType.resource && ticket.type !=
  TicketType.bug` → early return) widens to exclude only `page`/`chat`/
  `signal`/`release`. The `TicketLinkPicker` call site passes
  `linkTypeOptions: [TicketLinkType.relatesTo]` for `resource` (unchanged
  single-tap UX) and `[blocks, blockedBy, relatesTo, duplicates]` for
  `epic`/`story`/`task`/`bug`; `onSelected` forwards the chosen
  `linkType` to `createLink` instead of the previously hardcoded
  `TicketLinkType.relatesTo` literal, and calls
  `_refreshBlockedBoardState()` when the created type is `blocks`/
  `blockedBy`.
- **`TicketsCubit.loadDocumentRelations`'s type gate** — widens from
  `page`/`resource`/`bug` to also include `epic`/`story`/`task`, so the
  now-visible Linked Tickets section on those types actually populates
  instead of hitting the method's early return.
- **`_CardVisual`'s meta-chip `Row`** (`tickets_board_view.dart`) —
  gains the conditional `_BlockedBadge` insertion described above. No
  change to the existing `TypeChip`/`PriorityBadge`/execution-state
  badge rendering or their order relative to each other.

## REMOVED

- None. Every change is additive, or a gate-widening that preserves
  each type's previously-supported behavior unchanged (e.g. `resource`
  keeps its exact current one-tap `relatesTo` linking flow).
