# T16. Same file — new field `_pendingSkillAttachments`

(`Map<String, SkillAttachment>`, keyed by ticket id) and private
method `_resolveAndFireAttachment(Ticket parent, SkillAttachment
attachment)` implementing the three-way confidence branch (design.md
§3.3): `auto` fires `_fireSkillAttachment` unawaited immediately;
`gated` records the pending entry and re-emits `TicketDetailLoaded`
with `pendingSkillAttachment` set if the ticket's detail screen is
open (mirrors `_refreshDetailIfOpenAndAffected`'s existing
pattern); `manual` no-ops. New public methods
`confirmPendingSkillAttachment(String ticketId)` (fires the
pending attachment, clears the map entry),
`rejectPendingSkillAttachment(String ticketId)` (clears the map
entry, never fires), and `runAttachedSkillManually(Ticket ticket)`
(resolves the ticket's current status/stage attachment; no-ops
unless its confidence is `manual`). Full dartdoc on all four,
citing `confirmPendingToolProposal`/`rejectPendingToolProposal`
as the existing pattern this mirrors.
