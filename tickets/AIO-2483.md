# Spec Delta: token-cost-prediction

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (47/54 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **`Ticket.predictedExecutionTokensLow`/`predictedExecutionTokensHigh`**
  (`int?`, default `null`, always non-`null` together) — a token-count
  range predicting a not-yet-executed `task`/`bug` ticket's
  coding-execution spend, derived deterministically (no model call) from
  comparable past `task`/`bug` tickets' own recorded execution token
  totals. `null`/`null` means "no estimate available" (no sufficiently
  comparable ticket with execution history exists yet) — never a
  fabricated fallback. Persisted via `Ticket`/`ticket_model.dart` (Drift
  schema version 13 → 14, two new nullable `IntColumn`s). Deliberately
  excluded from `Ticket.copyWith` — written only through
  `TicketRepository.applyTokenPrediction`, mirroring
  `complexitySource`/`estimateSource`'s existing write-path isolation.
- **`TicketTokenPredictor`** (`presentation/cubit/ticket_token_predictor.dart`)
  — background predictor mirroring `TicketEstimationSuggester`'s shape
  and trigger (fires `unawaited` from `TicketsCubit.createTicket`/
  `updateTicket`, alongside the existing estimation-suggester call), but
  computing a purely deterministic result: ranks other `task`/`bug`
  tickets with a non-`null` embedding by cosine similarity (reusing
  `ai-assisted-complexity-and-estimate-suggestions`'s existing
  `embedding_similarity.dart` helper), walks the ranked list collecting
  up to 5 candidates that have recorded execution-token history (scanning
  at most 20 similarity-ranked candidates), and persists the min/max of
  those candidates' totals via `applyTokenPrediction`. No-ops (no
  computation, no write) when: no `EmbeddingProvider` is configured; the
  ticket isn't `task`/`bug`; the ticket has no embedding yet; the ticket
  already has at least one `"Coding Execution — "`-titled child chat
  (already executed — a prediction is moot); or zero comparable
  candidates with execution history are found.
- **`TicketRepository.getExecutionTokenTotals(List<String> taskIds)`** —
  batched query returning `Map<String taskId, int total>`, summing
  `inputTokens + outputTokens` across every comment in every
  `"Coding Execution — "`-titled child chat of each requested ticket
  (spanning implement/verify turns, retries, and continuation-handoff
  chats alike). One grouped SQL query regardless of `taskIds.length` — no
  per-id looping at any call site. A missing key means no recorded spend
  (equivalent to `0`).
- **`TicketRepository.applyTokenPrediction(String id, {required int low, required int high})`**
  — dedicated write path for `Ticket.predictedExecutionTokensLow`/`High`,
  never routed through `updateTicket`/`copyWith`.
- **`TicketsCubit._executionTokenTotals`** (`Map<String, int>`, in-memory,
  does not survive an app restart on its own — always reconstructable
  from persisted `ticket_comments` via `getExecutionTokenTotals`) — cache
  of each task/bug's accumulated coding-execution token spend so far.
  Seeded per-ticket via `getExecutionTokenTotals` in `loadTickets`/
  `loadMoreTickets`/`getTicketById` when a ticket isn't already cached;
  incremented in place inside `_runCodingExecution` the moment each
  implement/verify turn's `AgentDoneEvent` is known (right after that
  turn's `ai` comment is persisted with its real `inputTokens`/
  `outputTokens`).
- **`TicketsLoaded.executionTokenTotals`** (`Map<String, int>`, default
  `{}`) — `_executionTokenTotals` exposed to the Board/list, refreshed by
  the existing `_refreshInFlightBoardState()` (a plain synchronous copy —
  no new async work added to that method) alongside
  `inFlightExecutionIds`/`executionQueuePositions`.
- **`TicketDetailLoaded.executionTokenTotal`** (`int?`, default `null`)
  — a task/bug's running total from `_executionTokenTotals`, resolved by
  `getTicketById` alongside `isExecuting`/`executionFailureReason`.
  `null` means no coding-execution chat has ever existed for this ticket.
- **`TokenCountLabel`** (`presentation/widgets/token_count_label.dart`)
  — shared stateless widget + `formatTokenCount(int)` pure function
  (compact "~12.3K"/"~1.2M" abbreviation), rendering either a
  `.range(low, high)` (predicted estimate) or `.total(total)` (running
  total) label. Used by `TicketBoardCard`, `TicketMetadataSection`, and
  `_CodingExecutionSection`.
- **`TicketBoardCard`'s meta-chip row: a token label**, resolved by new
  private helper `_cardTokenLabel(TicketsState, Ticket)` (mirrors
  `_cardExecutionState`/`_cardIsBlocked`'s no-signal-outside-
  `TicketsLoaded` floor, scoped to `task`/`bug` tickets only). Shows the
  running total when `TicketsLoaded.executionTokenTotals` has an entry
  for the card's ticket; else the predicted range when the ticket's
  `predictedExecutionTokensLow`/`High` are set; else renders nothing.
  Placed after `PriorityBadge`, before `RollupBadge`/
  `_BoardCardStatusBadge` in the existing meta-chip row.
- **`TicketMetadataSection`'s predicted-range label**, beside the
  existing complexity/estimate row, shown when
  `ticket.predictedExecutionTokensLow != null &&
  executionTokenTotal == null` — a new required `executionTokenTotal`
  (`int?`) constructor parameter threaded in alongside the section's
  existing `isExecuting`/`executionFailureReason` parameters.
- **`_CodingExecutionSection`'s running-total line**, rendered inside the
  existing execution banner whenever its new `executionTokenTotal`
  (`int?`) parameter is non-`null` — does not change the banner's own
  visibility condition (unaffected: a non-`null` total only ever
  co-occurs with an already-truthy `isExecuting`/
  `executionQueuePosition`/`executionAwaitingReview`/
  `executionFailureReason`).

## MODIFIED

- **`Ticket.copyWith`** — no signature change (the two new fields are
  deliberately excluded), but its dartdoc's list of fields "never part of
  `copyWith`" grows to include `predictedExecutionTokensLow`/`High`
  alongside `complexitySource`/`estimateSource`.
- **`TicketsCubit.createTicket`/`updateTicket`** — each now also fires
  `_tokenPredictor.suggest(ticket)` `unawaited`, alongside the existing
  `_estimationSuggester.suggest(ticket)` call. Both are independent,
  swallow their own failures, and never block the caller's own save flow.
- **Drift schema** — version 13 → 14. `TicketModel` gains
  `predicted_execution_tokens_low`/`predicted_execution_tokens_high`
  (nullable `IntColumn`s). A `MigrationStrategy.onUpgrade` step adds both
  columns; no backfill.

## Non-goals carried into this spec (see proposal.md)

- No gate/confirmation behavior — purely informational.
- No dollar-amount figure — raw token counts/ranges only, consistent with
  Aion's flat-rate provider having no real per-token cost to report.
- No SDD-stage-chat or Inbox-chat coverage — coding-execution (`task`/
  `bug`) only.
- No true mid-turn live ticking — `AgentToolUseEvent` gains no usage
  payload; the running total updates once per completed turn, not
  continuously. `AgentModelClient`/`AgentDoneEvent` are otherwise
  unmodified by this change.
