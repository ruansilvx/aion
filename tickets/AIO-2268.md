# T8. `features/tickets/presentation/cubit/tickets_cubit.dart` —

several changes to this file (design.md §2, §4):
- `loadDocumentRelations` computes each link row's
`relativeType` via T3's `relativeLinkType` instead of
discarding the row, emitting `List<LinkedTicketRef>` for both
`linkedTickets` and `backlinks`.
- New `createTicketLink(String ticketId, String targetTicketId,
TicketLinkType linkType)`, `deleteTicketLink(String ticketId,
String linkId)`, `updateTicketLinkType(String ticketId, String
linkId, TicketLinkType newCanonicalType)` — all three following
the create/refresh/conditionally-`_refreshBlockedBoardState`
shape in design.md §4. No-op (return early) if constructed
without a `TicketLinkRepository`, matching every other
`linkRepo`-gated method in this file.
- New private `_linkInvolvesBlocking(String linkId)` helper (uses
T4's `getLinkById`) backing the guard in the three methods
above.
- `_computeBlockedTicketIds`/`_isTicketBlocked` refactored to call
T3's `relativeLinkType`/T1's `TicketLinkTypeRelative.inverse`
instead of each inlining its own switch statement (design.md
§2) — no behavior change, update their dartdoc to reference the
shared helper instead of describing the logic inline twice.
Dartdoc every new/changed public method.
