# Verify follow-ups (round 2, 2026-09-01)

Gaps found by a second `/verify` pass, after the round-1 follow-ups above
had already landed. Ordered severity-first, matching that `/verify`
report's own CRITICAL → WARNING → SUGGESTION order.

- [x] `WorkflowStatusSettingsScreen` — exclude `SddStage.archived` (the
      one `SddStage.values` entry with no precondition) from getting
      the "Configure precondition" affordance. `/verify` found the
      `for (final stage in SddStage.values)` loop feeding
      `_SddStageRenameRow` unconditionally, so `_PreconditionAffordance`
      rendered — and its route pushed and loaded — for `archived` too,
      contradicting design.md §5 ("every one of the five stages carries
      a precondition") and proposal.md's Non-goals (`archived` has no
      precondition, untouched). Fixed by guarding the affordance's
      render site (`if (widget.stage != SddStage.archived)`) rather
      than the outer loop — `_SddStageRenameRow` still renders for
      `archived` (it still needs its rename field), only the
      precondition affordance is withheld. Added a regression test
      asserting the "Configure precondition" semantics label exists for
      all 5 precondition-bearing stages and not for `archived`.
- [x] Outcome glyph (design.md §0.1) — implemented as a new shared
      `TransitionOutcomeGlyph` `CustomPaint` widget
      (`transition_node_form.dart`, public since the other two
      consumers import that file already) and wired into all three
      mandated consumers: the canvas terminal pill
      (`_CanvasNodeContent` in `sddstage_precondition_editor_screen.dart`,
      12×12 per §1.3), the outline badge (`_OutcomeBadge` in
      `transition_outline_list.dart`, 10×10 with §2.2's literal
      `1.8`/`1.4` stroke widths), and the form's outcome chip
      (`_OutcomeChip` in `transition_node_form.dart`, 11×11 per §3.3).
      Also added `_OutcomeBadge`'s missing §2.2 `MATCHED`/`UNMATCHED`
      branch-word prefix, abbreviated to `M`/`U` via a `LayoutBuilder`
      measuring the row's own available width against the `360`px
      threshold (not the outline pane's gross width, which isn't
      locally available at that widget — the row's own constraint is
      what's actually cramped).
- [x] Field picker menu grouping (design.md §0.3's illustrative
      pattern) — considered and deliberately not added: each stage's
      `transitionFieldsFor` catalog is 1–3 fields (the full catalog is
      only 7 entries total), so a `THIS TICKET`/`LINKED WORK` grouping
      header adds a scan step without helping orientation at that size.
      `/verify`'s SUGGESTION explicitly left this to judgment; no code
      change made.
