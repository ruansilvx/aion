# Spec Delta: Pluggable Provider Abstraction

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/providers.md` text — every distinctive symbol/behavior this delta names is still present and accurate (48/49 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/providers.md`. Read alongside
`proposal.md` and `design.md` in this change folder.

## ADDED

- **`ProviderId`** (`core/contracts/provider_id.dart`) — the extensible
  provider identifier enum. One value: `claudeAgentSdk`.
- **`ToolAccessTier`** (`core/contracts/tool_access_tier.dart`) —
  `noTools | readOnly | full`, a provider capability-declaration axis,
  independent of `ModelPhase`.
- **`AgentModelDescriptor`** (`core/contracts/agent_model_descriptor.dart`)
  — a provider-scoped model value object (`providerId`, `modelId`,
  `label`, `contextWindowTokens`).
- **`ConsumptionSignal`** (`core/contracts/consumption_signal.dart`) — a
  sealed type (`UsageWindowConsumption`, `CostConsumption`) that's the
  one generic dimension every provider maps its own budget/usage
  semantics onto.
- **`AgentProvider`** (`core/contracts/agent_provider.dart`) — the
  provider abstraction: `id`, `displayName`,
  `supportedToolAccessTiers`, `availableModels`, `client`
  (`AgentModelClient`), `describeOverage(String) → ConsumptionSignal`,
  `normalizeErrorMessage(String) → String`.
- **`ProviderRegistry`** (`core/contracts/provider_registry.dart`
  interface) / **`StaticProviderRegistry`** (`core/agent/`
  implementation) — the `ProviderId`-to-`AgentProvider` lookup every
  consumer now goes through, constructed once in `main.dart`.
- **`ClaudeAgentSdkProvider`** (`core/agent/claude_agent_sdk_provider.dart`)
  — the first `AgentProvider` implementation, wrapping the existing
  `ClaudeAgentSdkClient` unchanged. Declares `{noTools, full}` tool-access
  support (no `readOnly` — the bridge has no allowlist tier).
- **`ModelPhase.requiredToolAccessTier`** (extension getter,
  `domain/enums/model_phase.dart`) — `frontier`/`capable` require
  `noTools`, `execution` requires `full`. Used to filter which
  registered providers' models a phase's Settings dropdown may offer.

## MODIFIED

- **`AgentModel`** (`features/providers/domain/enums/agent_model.dart`)
  — **removed**, replaced by `AgentModelDescriptor` (above). A model is
  no longer an implicit "the one provider's model" — it now carries its
  own `providerId`.
- **`ModelRoutingRepository`** — `getModelForPhase`/`setModelForPhase`
  now operate on `AgentModelDescriptor`, not `AgentModel`.
  `SharedPrefsModelRoutingRepository` persists two `shared_preferences`
  keys per phase (`..._provider_id`, `..._model_id`, was one) and takes
  a `ProviderRegistry` dependency to resolve persisted ids back into a
  full descriptor. A phase with no `..._provider_id` key yet (existing
  installs) defaults to `ProviderId.claudeAgentSdk`, preserving an
  already-chosen model — same fallback precedent as the pre-existing
  legacy single-model key.
- **`ModelRoutingCubit`** — `ModelRoutingReady` gains `availableModels`
  (`List<AgentModelDescriptor>`, filtered per phase by
  `ModelPhase.requiredToolAccessTier` against each registered
  provider's `supportedToolAccessTiers`). `selectModel` now takes an
  `AgentModelDescriptor`.
- **`ExecutionContextCapCubit`** — reads `.contextWindowTokens` off an
  `AgentModelDescriptor` instead of `AgentModel`; no other behavior
  change.
- **`ProviderSettingsCubit`** — resolves the Frontier tier's
  `AgentModelDescriptor` and its `AgentProvider` (via `ProviderRegistry`)
  instead of pinging a directly-injected `AgentModelClient`.
  `statusMessage` on a `disconnected` result is now
  `provider.normalizeErrorMessage(...)`-cleaned, not the raw event
  message.
- **Settings screen** (`_ModelPhaseSection`) — its `AppDropdown` item
  type changes from `AgentModel` to `AgentModelDescriptor`, sourced from
  `ModelRoutingCubit`'s new `availableModels` instead of
  `AgentModel.values`. No visible change today (one registered provider,
  same three models, same labels).
- **`ChatCubit.runChatTurn`** (the shared static helper every
  text/tool-enabled turn goes through) — gains a required `provider:
  AgentProvider` parameter; its `model` parameter is now
  `AgentModelDescriptor`; its `onOverageDetected: VoidCallback?`
  parameter is replaced by `onConsumptionSignal: void
  Function(ConsumptionSignal)?`; `AgentErrorEvent` failure messages are
  now passed through `provider.normalizeErrorMessage` before being
  surfaced (e.g. into `TicketComment` content).
- **`TicketsCubit`, `ChatCubit`, `InboxCubit`** — each replaces its
  directly-injected `AgentModelClient` field with a `ProviderRegistry`
  field, and resolves `(AgentModelDescriptor, AgentProvider)` together
  per call (via a new `_resolveModelAndProvider(ModelPhase)` helper) —
  the mechanism that makes per-tier provider assignment real, since a
  different tier's resolved descriptor can now carry a different
  `providerId`.
- **`main.dart`** — the standalone `RepositoryProvider<AgentModelClient>`
  is replaced by `RepositoryProvider<ProviderRegistry>` (constructed as
  `StaticProviderRegistry([ClaudeAgentSdkProvider(...)])`).
  `SharedPrefsModelRoutingRepository`'s construction now takes
  `context.read<ProviderRegistry>()`.
- **`app_router.dart`** — every `context.read<AgentModelClient>()` call
  site (`TicketsCubit`, `ChatCubit`, `InboxCubit`,
  `ProviderSettingsCubit` construction) becomes
  `context.read<ProviderRegistry>()`.

## Known gaps carried forward (not resolved by this change)

- **Only Claude Agent SDK is configurable.** `ProviderRegistry` is
  populated with exactly one `AgentProvider` — the interface is defined
  and real, but validated against a single implementation only. A
  second provider (Anthropic Messages API or otherwise) remains
  unbuilt.
- **No per-provider credential storage or enabled/disabled state.** The
  registry's construction-time list is today's de facto "which
  providers exist" — no `ProviderConfigRepository` or per-provider
  Settings UI exists yet. See proposal.md's Non-goals and design.md §5
  for the deferred shape.
- **No cross-provider per-ticket/per-chat manual override.** Every
  chat/ticket still resolves strictly through its `ModelPhase`'s
  currently configured `AgentModelDescriptor` — no override field, no
  UI affordance.
- **No predictive budget/usage-window consent gate.** `ConsumptionSignal`
  is wired to the existing reactive `AgentOverageDetectedEvent` signal
  only; there is still no proactive/predictive data source to gate on
  before a limit is hit.
- **No real `readOnly` tool-access tier.** `ToolAccessTier` is
  three-valued, but `ClaudeAgentSdkProvider` (and the bridge underneath
  it) only ever actually supports `noTools`/`full` — `readOnly` has no
  working implementation anywhere yet.
- **No live model-list discovery.** `AgentProvider.availableModels` is
  still a fixed, hardcoded list per provider (unchanged from
  `AgentModel`'s previous fixed-enum behavior) — no live endpoint query.
