# Spec Delta: Baseline Skill Staleness Detector

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/projects.md` text — every distinctive symbol/behavior this delta names is still present and accurate (0/0 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

None as new app-facing behavior — `aion-arch/specs/*.md` documents the
Aion *app's* current-state behavior, and this change adds OpenSpec
tooling (a script plus a skill-prompt tweak), not app behavior. Per
existing precedent, `detect-cycle.sh` and `detect-gaps.sh` themselves
have no entry anywhere in `aion-arch/specs/*.md` either — their
documentation lives in their own header comments and in
`workflow/shared/cycle-stages.md`. This change's new script follows the
same pattern (see `design.md`'s header-comment content); only its
resolution of an existing, already-documented known gap is reflected in
`specs/`, below.

## MODIFIED

- **`aion-arch/specs/projects.md`'s "Known gaps" section** — the "No
  automated or enforced sync between `aion-arch/.claude/skills/` and the
  bundled `assets/baseline/<version>/manifest.json` skill assets" bullet
  is reworded on `/archive` from:

  > No automated or enforced sync between `aion-arch/.claude/skills/`
  > and the bundled `assets/baseline/<version>/manifest.json` skill
  > assets — relevant only to `0.1.0`/`0.2.0`, which literally pointed
  > into `aion-arch`. `0.3.0`'s skill content is deliberately generic
  > and stack-agnostic (see [Baseline package and override
  > resolution](#baseline-package-and-override-resolution)), not a
  > mirror of `aion-arch`'s own skills, so it has no such sync gap to
  > begin with — but any future update to `aion-arch`'s own skills still
  > has no automated path to influence `0.3.0`'s (or a future
  > version's) content.

  to:

  > **Partially resolved.**
  > `aion-arch/workflow/scripts/detect-baseline-staleness.sh` (folded
  > into `detect-gaps.sh`'s priority-0 output, surfaced by
  > `/what-next`) now flags whenever an
  > `aion-arch/.claude/skills/<name>/SKILL.md` file has been committed
  > more recently than its bundled `assets/baseline/<latest
  > version>/skills/<name>.md` counterpart was last reviewed — so drift
  > no longer goes unnoticed. This is a *staleness detector*, not a
  > content sync: porting an `aion-arch` skill's operative,
  > project-specific instructions into the bundled baseline's
  > deliberately generic, stack-agnostic wording still requires a human
  > judgment call every time; there is still no automated or enforced
  > mechanism that writes or merges that content for you. Relevant only
  > to skills present in both places — `aion-arch`-only tooling skills
  > (e.g. `prepare-release`) have no bundled counterpart and are
  > silently skipped, not flagged. Checked only against the latest
  > bundled version; `0.1.0`/`0.2.0` stay frozen per this same section
  > and are intentionally not checked.

- **`aion-arch/workflow/scripts/detect-gaps.sh`** — its priority-0
  results now include entries folded in from the new
  `detect-baseline-staleness.sh` script (`"source": "baseline-
  staleness"`), in addition to its existing `"specs"` and
  `"specs-open-questions"` sources. Its own output shape (a JSON array
  of `{priority, source, file, title, next_action}` objects) is
  unchanged; only the set of possible `source` values grows.

- **`aion-arch/.claude/skills/what-next/SKILL.md`** — its "Note on the
  gaps above" paragraph gains one sentence describing the new
  `"baseline-staleness"` source value, per `design.md`'s exact wording.
  Its "Instructions" priority-order logic is unchanged — the new
  entries arrive pre-merged into the same `detect-gaps` output step 3
  already reads.

## REMOVED

None.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **`aion-arch/workflow/scripts/detect-cycle.sh`.** Untouched — this
  change only touches `detect-gaps.sh` and adds a new sibling script.
- **Bundled baseline content itself
  (`aion/assets/baseline/*/skills/*.md`).** No file under `aion/` is
  created, edited, or deleted by this change — see `proposal.md`'s Out
  of scope. The detector only *reads* those files (via `git log`) to
  compute a date; it never writes to them.
- **`0.1.0`/`0.2.0` baseline versions.** Deliberately excluded from the
  staleness check — both are frozen, per the existing "Baseline package
  and override resolution" section of `projects.md`, which this change
  does not modify.
- **Any CI, pre-commit hook, or blocking gate.** This surfaces as an
  advisory `/what-next` gap only — nothing about it blocks a commit,
  push, or any other workflow stage.
