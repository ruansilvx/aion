# Spec Delta: sdd-ticket-execution

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (36/41 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md` and `aion-arch/project.md`.
Read alongside [proposal.md](../proposal.md) and [design.md](../design.md)
— this file only lists what changes, not full current-state context.

## ADDED

- **`TicketComplexity`** (`domain/enums/ticket_complexity.dart`) —
  `small | medium | large`, nullable, universal to every `TicketType`.
  User-set only, no automated estimation. New nullable `complexity`
  column on `TicketsTable` (schema v5).
- **`SddStage`** (`domain/enums/sdd_stage.dart`) — `exploring | proposed
  | verifying | archived`, nullable, meaningful only for `epic`/`story`
  tickets. New nullable `sdd_stage` column on `TicketsTable` (schema v5),
  written only via `TicketRepository.updateTicketSddStage`.
- **`AutomationConfidence`** (`lib/core/automation/automation_confidence.dart`)
  — `auto | gated | manual`, the shared three-state type from
  `project.md` §5, first real consumer is SDD-stage-triggering.
- **`AutomationSettingsRepository`/`SharedPrefsAutomationSettingsRepository`**
  (`lib/core/automation/`) — persists the single global
  `AutomationConfidence` value for SDD-stage-triggering.
- **`CommentAuthorType.system`** (`domain/enums/comment_author_type.dart`)
  — third author-type value for Aion-assembled context messages,
  alongside existing `human`/`ai`.
- **`TicketsCubit.advanceSddStage(Ticket ticket)`** — validates the
  current→next `SddStage` transition's precondition, persists the new
  stage, and spawns that stage's `chat`-type child ticket (posts a
  `system`-authored context comment, calls `AgentModelClient.run()`,
  streams and persists the reply).
- **`TicketsCubit.promoteSignalToEpic(Ticket signal, {String?
  existingEpicId})`** — links a `signal` ticket to an existing or newly
  created `epic` via `TicketLinkType.relatesTo`.
- **`TicketDetailLoaded.canAdvanceSddStage`** (new field) — computed by
  `TicketsCubit.getTicketById` for `epic`/`story` tickets by checking
  direct children against the current stage's precondition.
- **`TicketRepository.updateTicketSddStage(String id, SddStage stage)`**
  — dedicated single-field update, mirroring `updateTicketStatus`.
- **`ChatCubit`/`ChatState`** (`presentation/cubit/chat_cubit.dart`) —
  used instead of `CommentsCubit` on `chat`-type ticket detail routes;
  `sendMessage` posts a human comment, calls `AgentModelClient.run()`,
  streams the reply into `ChatLoaded.streamingText`, persists the final
  text as one `ai` comment.
- **"SDD Stage Automation" setting** (`SettingsScreen`, backed by new
  `AutomationSettingsCubit`) — picks the global `AutomationConfidence`
  value.
- **"Promote to Epic" action** (`TicketOverflowMenu`, `signal` tickets
  only) — links to an existing epic (via `TicketLinkPicker`) or creates
  a new one.
- **Complexity picker** (`CreateTicketScreen`, `TicketDetailScreen`) —
  `SelectionMenu<TicketComplexity>`, mirroring the existing Priority
  picker.
- **SDD-stage section** (`TicketDetailScreen`, `epic`/`story` only) —
  current-stage display plus an auto/gated/manual-dependent advance
  control (see design.md's semantics section).

## MODIFIED

- **`Ticket`** (`domain/entities/ticket.dart`) — gains `complexity`
  (`TicketComplexity?`, via `copyWith`'s `TicketFieldSetter` pattern) and
  `sddStage` (`SddStage?`, **not** exposed through `copyWith` — written
  only via `advanceSddStage`/`updateTicketSddStage`).
  `TicketRepository.updateTicket` now also persists `complexity`.
- **`TicketsCubit.getTicketById`** — for `epic`/`story` tickets, also
  fetches direct children and computes `canAdvanceSddStage`.
- **`CommentTile`** (`presentation/screens/ticket_detail_screen.dart`) —
  gains an `isSystem` branch rendering `CommentAuthorType.system`
  comments distinctly (no avatar initial, no "via `<model>`" line).
- **`LinkedTicketsSection._typeColor`**
  (`design_system/molecules/linked_tickets_section.dart`) — gains
  explicit `TicketType.signal`/`.release`/`.chat` arms; previously all
  three fell into the `_ => c.typeTask` catch-all.
- **`AppDatabase`** (`core/database/app_database.dart`) — schema version
  4 → 5, adding `tickets.complexity`/`tickets.sdd_stage` columns.
- **`project.md`** §5 — "Watcher system" subsection removed; "Shared
  automation-confidence pattern" updated to the three-state model; new
  status note naming SDD-stage-triggering as the first real
  `AutomationConfidence` consumer.

## REMOVED

- **`project.md` §5's "Watcher system" subsection** — every
  responsibility it described (decompose Epic/Story, create tickets,
  merge chats, update documentation, assure quality, handle failure
  escalation) already has a concrete owner among the stage-specific
  chats, Branch/Merge Semantics, and mid-task branching this idea's
  source brainstorm resolved — see `aion-arch/ideas/
  sdd-workflow-in-ticket-system.md`'s Follow-up decisions.

## Known gaps this change does not resolve

- **Mid-task/issue chat branching** — `chat` tickets remain leaves;
  nothing spawns a chat-under-chat. The Branch/Merge Semantics UX
  (`project.md` §2) applied at this granularity stays undesigned, per
  the source idea's own flag. A stage-triggered chat runs start-to-finish
  with no interruption/branch path.
- **No repo-map-lite or embedding-based context enrichment** for a
  spawned chat's initial message — plain-text parent fields and direct
  links only.
- **No automated estimation** consuming `complexity` — plain user-set
  field, same treatment `estimate`/`timeSpent` already get.
- **`project.md`/`CLAUDE.md`-as-Page-ticket** — still an open,
  undecided question (see the source idea's Open questions); untouched
  by this change.
- **Only one `AutomationConfidence` consumer exists** (SDD-stage-
  triggering) — the budget gate and batch-flush gate described in
  `project.md` §5 remain unbuilt concepts, not wired to this type yet.
- **No polling/live-refresh of `canAdvanceSddStage`** — it's computed
  once when the detail screen loads; a sibling Task completing while
  the Story's detail screen is already open does not retroactively flip
  the banner/button without a reload.
