# Spec delta: barrel-files

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (6/6 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

This change has **no user-observable behavior delta** — no screen,
Cubit, repository, or database behavior changes. It's scoped entirely
to internal code organization (which file re-exports which symbols),
so there is nothing to add to `aion-arch/specs/tickets.md` under
ADDED/MODIFIED/REMOVED app behaviors.

What *is* being added is a project-wide **code convention**, which is
the closest thing to a "behavior" this change modifies:

## ADDED

- **Barrel-file convention**: every major `core/` subdirectory grouping
  and every `features/<feature>/` directory gets exactly one barrel
  file at its root, re-exporting its public surface.
  - `core/design_system.dart` — theme tokens (`AionColors`, `AionText`,
    `AionRadius`, `AionShadows`, `AionThemeData`, `ThemeScope`). Kept
    separate from `core.dart` by explicit design.
  - `core/core.dart` — the rest of `core/` (database, routing,
    localization, utils, widgets).
  - `features/<feature>/<feature>.dart` — domain + presentation only.
    Data-layer implementations (DAOs, table models, `Drift*Repository`)
    are never exported through a feature barrel; the composition root
    (`main.dart`) and any core file that owns wiring the concrete
    implementation (e.g. `core/database/app_database.dart`) keep direct
    leaf imports into `data/`.
  - Self-import exception: files inside a directory never import that
    directory's own barrel; only outside consumers (sibling
    subdirectories, other features, `main.dart`, `test/`) do.
  - Documented in `flutter-conventions.md`, enforced by code review
    (no new lint tooling), matching the existing precedent for the
    localization convention.
