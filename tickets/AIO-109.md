# Spec Delta: AI-assisted complexity and estimate suggestions

**Reconciled 2026-09-03:** confirmed against the current `aion-arch/specs/tickets.md` "AI-suggested complexity/estimate" section — `TicketEstimationSuggester`, the `complexitySource`/`estimateSource` lock model, `applyEstimationSuggestion`, and the display rules (`AiSuggestionBadge`) all still match. Flagged-missing items are either DB column names/schema version not restated in this particular prose subsection (covered in the Drift tables section instead) or l10n key names the current prose describes functionally rather than by literal key. No material drift.

Relative to `aion-arch/specs/tickets.md`. See that file's `Ticket`
entity table, `TicketsCubit`, `TicketRepository`, and DB schema sections
for full current-state context this delta modifies.

## ADDED

- **`TicketEstimationSource`** (`domain/enums/ticket_estimation_source.dart`)
  — `aiSuggested | aiSuggestedLowConfidence | manual`. Tracks where a
  ticket's current `complexity`/`estimate` value came from, independently
  per field.
- **`Ticket.complexitySource`** / **`Ticket.estimateSource`**
  (`TicketEstimationSource?`) — `null` iff the companion field
  (`complexity`/`estimate`) is itself `null`. No settable `copyWith`
  parameter (both pass through unchanged on every call); written only by
  `TicketRepository.updateTicket` (stamps `manual`, gated by its
  `complexityEdited`/`estimateEdited` parameters — see MODIFIED below)
  and `TicketRepository.applyEstimationSuggestion` (stamps `aiSuggested`/
  `aiSuggestedLowConfidence`).
- **`TicketRepository.applyEstimationSuggestion(id, {complexity,
  estimate})`** — writes an AI-generated suggestion for one or both
  fields without touching `updatedAt`, mirroring `updateEmbedding`/
  `updateRollup`'s existing "background side effect, not a user edit"
  treatment.
- **`TicketEstimationSuggester`**
  (`presentation/cubit/ticket_estimation_suggester.dart`) — background
  orchestrator, constructed once per `TicketsCubit` alongside
  `TicketRollupRecomputer`. Gathers up to 5 comparable live tickets
  (already-sized, ranked by embedding cosine similarity to the ticket
  being estimated), calls the `ModelPhase.capable` model with a
  fixed-format prompt, parses `COMPLEXITY`/`ESTIMATE_MINUTES` lines from
  the response, and writes back via `applyEstimationSuggestion` — only
  for whichever field(s) aren't currently `manual`-locked. Zero
  comparable tickets found → the suggestion is still produced (content-
  only) but flagged `aiSuggestedLowConfidence`. Every failure mode
  (missing provider/embedding dependency, model error, unparseable
  response) is swallowed silently — this never surfaces `TicketsError` or
  interrupts the caller's save flow.
- **Automatic estimation trigger** — `TicketsCubit.createTicket` (always)
  and `TicketsCubit.updateTicket` (only when `title`/`description`
  changed) each fire `unawaited(_estimationSuggester.suggest(ticket))`
  immediately after their existing `_triggerEmbeddingRegen` call — same
  gating condition, same fire-and-forget shape.
- **`TicketsCubit.regenerateComplexitySuggestion(ticket)`** /
  **`regenerateEstimateSuggestion(ticket)`** — user-invoked, awaited.
  Bypasses a `manual` lock for exactly the named field only (the other
  field, and its lock state, is left untouched even if the same model
  call would have produced a value for it). No-ops if the named field is
  currently unset. Re-fetches and emits `TicketDetailLoaded` with the
  refreshed ticket once the suggestion attempt completes — including
  when the attempt silently fails and the value is unchanged.
- **`cosineSimilarity`** (`domain/utils/embedding_similarity.dart`) —
  cosine-similarity function extracted from
  `TicketDocumentSearchService`'s previously-private
  `_cosineSimilarity`, now shared by both that service and
  `TicketEstimationSuggester`.
- **`AiSuggestionBadge`** (`design_system/molecules/ai_suggestion_badge.dart`)
  — small monochrome badge rendered next to a field's trigger whenever
  its source is `aiSuggested`/`aiSuggestedLowConfidence`, with a distinct
  low-confidence visual variant.
- **`TicketMetadataSection`'s Regenerate action** — a small icon button
  shown next to the Complexity/Estimate rows only when that field's
  source is `manual`, calling `regenerateComplexitySuggestion`/
  `regenerateEstimateSuggestion`.
- **DB schema v10** — `tickets.complexity_source`/`tickets.estimate_source`
  (`TEXT`, nullable, `TicketEstimationSource.name`). On upgrade from a
  pre-v10 schema, both are backfilled to `'manual'` for every existing
  row whose `complexity`/`estimate` is already set (every ticket sized
  before this change was necessarily sized by hand).
- Two new `l10n` keys: `aiSuggestedBadge`, `aiSuggestedLowConfidenceBadge`,
  `ticketDetailRegenerateComplexity`, `ticketDetailRegenerateEstimate`.

## MODIFIED

- **`TicketRepository.updateTicket`** — gains two optional parameters,
  `complexityEdited`/`estimateEdited` (default `false`), alongside its
  existing field writes. `updateTicket` is the single generic write path
  for *every* field edit in `TicketMetadataSection` (title, priority,
  type, severity, description, ...), not just the Complexity/Estimate
  rows — so source-stamping can't key off non-null-ness of
  `Ticket.complexity`/`estimate` alone without silently relocking an
  `aiSuggested` value on an edit to some unrelated field. The actual
  rule: whenever the passed-in `Ticket.complexity`/`estimate` is `null`,
  its companion source is unconditionally cleared to `null` regardless
  of the `*Edited` flag (a source can't outlive its value); when it's
  non-null, the companion source is stamped `TicketEstimationSource.manual`
  only if the matching `*Edited` flag is `true` — otherwise the source
  column is left completely untouched, preserving whatever it already
  was. Only the detail screen's Complexity `SelectionMenu`/Estimate
  `InlineEditableField` (a genuine direct edit of that specific field)
  pass `complexityEdited: true`/`estimateEdited: true`; every other field
  edit passes neither, so `TicketsCubit.updateTicket` forwards to the
  repository with the plain (no-named-args) call shape it always had.
- **`TicketRepository.createTicket`** — unconditionally stamps
  `complexitySource`/`estimateSource` to `TicketEstimationSource.manual`
  for a ticket created with a non-null `complexity`/`estimate` already
  set via the create form (locked `manual` from creation, no `*Edited`
  parameter needed here since a fresh insert has no prior source to
  preserve); a ticket created with either field `null` gets a `null`
  source, freshly eligible for automatic suggestion.
- **`Ticket` entity** — gains `complexitySource`/`estimateSource` fields
  (see ADDED above). `copyWith` gains no settable parameter for either —
  both pass through unchanged on every call, the same treatment
  `estimateRollup`/`timeSpentRollup` already get.
- **`TicketsTable`** (Drift schema) — gains `complexity_source`/
  `estimate_source` columns; `schemaVersion` 9 → 10.
- **`TicketDocumentSearchService`** — its private `_cosineSimilarity`
  method is removed in favor of calling the new shared
  `cosineSimilarity` top-level function; no behavior change.

## Non-goals for this slice (see proposal.md's Scope section)

- No AI-suggested badge on list rows or board cards — detail screen only.
- No trigger from hand-edited `resource`/`page` markdown file changes.
- No live push/refresh of an already-open `TicketDetailScreen` when the
  *passive* background suggestion lands (the explicit Regenerate action
  is the one path that does re-emit immediately).
- No model-self-reported confidence score.
- No Settings-level configuration of comparable-ticket count or model
  tier for this feature.
