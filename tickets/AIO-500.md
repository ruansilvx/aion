# Post-apply correction (flat AI / divider system messages)

Corrects a drift from this cycle's own originating brainstorm
(`aion-arch/ideas/chat-transcript-ux-redesign.md`: "bubble for human,
no bubble for agent... system-context comments render as a quiet
subtle divider") that the Claude Design export/`/design-sync`
round-trip lost — caught after T1–T12 shipped. See `design.md` §9 and
`proposal.md`'s second post-approval amendment.

- [x] T13. `features/tickets/presentation/widgets/chat_message_bubble.dart`
      — split `_AiOrSystemMessage` (currently one class branching
      internally on `isAi`) into two private widgets dispatched
      alongside the existing `_HumanMessage` branch: `_AiMessage`
      (design.md §9.1 — drop the `DecoratedBox` fill/border/tail-radius
      around the Markdown content; keep the avatar, label row, "AI"
      badge, timestamp, `via <model>` caption, and 88% width cap
      exactly as before) and `_SystemMessage` (design.md §9.2 — replace
      the left-aligned bubble+avatar+label-row structure entirely with
      a centered `Row`: `diamond` glyph (`10px`, `c.textMuted`) +
      label text (`AionText.caption` resized 12/w500, `c.textMuted`,
      ellipsized) + optional trailing `· <time>`; no avatar, no fill,
      no border, no badge; vertical padding `AionSpacing.sp8`). No
      shared bubble wrapper exists in this file (each private widget
      already owns its own layout), so this is a natural split, not a
      refactor of shared code. Update file header + class/method
      dartdocs.

- [x] T14. `features/tickets/presentation/widgets/chat_transcript_pane.dart`
      — in `_StreamingBubble`/`_StreamingBubbleState`, apply design.md
      §9.3: remove `_glowController` and the animated border-glow
      `BoxDecoration` overlay entirely (no bubble edge left to glow
      around); render the in-flight AI content flat, matching T13's
      `_AiMessage` treatment (avatar, label row, 88%-capped Markdown,
      no fill/border). Keep the pulsing dot (pre-text tool-use status)
      and blinking caret (streaming text) unchanged — both are
      independent of the bubble shape. Update file header + dartdocs
      for the removed controller/decoration.

- [x] T15. Verification: `flutter analyze` — clean, 0 issues. Full test
      suite (`chat_cubit_test.dart` is the only chat-specific file; no
      `chat_state_test.dart` exists in this repo) — all 431 tests pass
      unmodified, confirming no `ChatCubit`/`ChatState` behavior
      changed.

      Chrome stayed unavailable after repeated retries (same as T12),
      so fell back to T12's native `flutter run -d windows` +
      hand-rolled Win32 automation. **Correction mid-pass:** the first
      `Get-Process aion` match was a same-named, unrelated game process
      running on the machine, not the Flutter build — its window was
      briefly foregrounded/screenshotted by mistake before being
      caught (`SetForegroundWindow` had actually failed, so no real
      focus was stolen and nothing was disrupted, but the screenshot
      mistake was still real). Re-did the window lookup filtered by
      `Path` (`...\build\windows\x64\runner\Debug\aion.exe`) to
      positively confirm PID 6268 before any further interaction, and
      used `AttachThreadInput` to reliably foreground it.

      **Confirmed working** against the same live chat ticket T12 used
      (AIO-4, real AI turns, `claude-haiku-4-5`): an existing
      system-authored comment (the auto-assembled task-context message)
      renders as the design.md §9.2 centered divider — `◇` glyph +
      muted single-line label + timestamp, no avatar/bubble; the AI
      replies immediately below and elsewhere in the transcript render
      fully flat per §9.1 — avatar, "Aion AI" badge, timestamp, then
      Markdown (numbered/bulleted lists, bold, emoji) directly on
      `background` with no fill/border/tail, width still capped; human
      messages are pixel-for-pixel unchanged (right-aligned, `surface`
      fill, `borderStrong` border, "You" label). Sent a new message
      live to trigger an in-flight reply: mid-stream the AI content
      showed only the blinking caret at the end of the accumulating
      Markdown — no animated border glow, no bubble edge of any kind —
      confirming §9.3; the reply settled cleanly afterward with the
      `via claude-haiku-4-5` caption still flat. The pre-text
      tool-use pulsing-dot line wasn't exercised (this test turn had no
      tool calls), same untested-this-pass caveat T12 already noted for
      that indicator.

      Closed the app window and stopped the `flutter run -d windows`
      process (and its child `dart`/`dartvm`/`dartaotruntime`
      processes) as the last step — confirmed no `aion`/`dart`
      processes remained running afterward.

      **Post-`/verify` fix:** `/verify` caught a spacing bug in
      `_SystemMessage` (design.md §9.2) — its own internal
      `Padding(vertical: sp8)` was stacking on top of
      `ChatMessageBubble`'s unchanged outer `sp16` wrapper, netting a
      `24px` gap around a system divider, heavier than the ordinary
      `16px` inter-message gap and the exact opposite of §9.2's
      "tighter... light separator" intent. Fixed by removing
      `_SystemMessage`'s internal padding (matching
      `_HumanMessage`/`_AiMessage`, which also carry none) and reducing
      the outer wrapper's bottom padding to `sp8` for the system case
      only — the divider now gets a `8px` trailing gap, half the
      normal `16px`. `design.md` §9.2 updated to match.
      `flutter analyze` re-run clean after the fix.
