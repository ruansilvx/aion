# Spec delta: List/board view persistence & board column visibility

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (27/28 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`. Section references below
are to that file's current headings (`### Screens`, `### Board view`).

## MODIFIED — `### Screens` → `TicketsListScreen`

**Current text being replaced:**

> Renders `AppSpinner` while loading or while a trash call is in
> flight..., or the ticket list body — either a `ListView.separated` of
> `TicketListTile`, or `TicketBoardView`..., depending on a private,
> non-persisted `_TicketViewMode { list, board }` toggle. Two icon
> buttons in the header (list / board glyphs) switch between them; the
> screen always opens in Board mode — a fixed, non-user-configurable
> starting point (the toggle itself is still unpersisted; only which
> mode is selected before the user's first interaction changed).

**New behavior:**

The list/board toggle is now `TicketListViewMode` (promoted from a
private widget enum to `domain/entities/ticket_list_view_mode.dart` —
see design.md §2.1), and its selection **persists per project** via
`TicketListViewModeRepository`
(`SharedPreferences`, project-id-prefixed key — see design.md §3.1),
restored the next time that project's ticket list is opened, including
after an app restart — the same restoration timing and mechanism
`TicketListFilterRepository`/`TicketListSortRepository` already use:
`TicketsListScreen.initState` awaits
`TicketsCubit.loadPersistedViewMode()` (alongside the existing
`loadPersistedFilters()`/`loadPersistedSort()` calls, all before the
first `searchTickets()`/build) so the very first render already
reflects the restored mode instead of flashing `board` first.

`TicketListViewMode.board` remains the fixed fallback — used only when
the active project has never had an explicit choice persisted (a
brand-new project's first-ever ticket-list visit), not as a value the
screen resets to on every open. Two icon buttons in the header (list /
board glyphs) still switch between them; selecting one now also
persists the choice via `TicketsCubit.setViewMode`.

Selection state itself now lives on `TicketsCubit`
(`currentViewMode`/`setViewMode` — see design.md §4), not a
screen-local `StatefulWidget` field, mirroring the Filters/Sort
selections' own cubit-owned pattern — with one difference from those
two: `setViewMode`/`toggleBoardColumnVisibility` (below) never call
`searchTickets`, since neither a view-mode nor a hidden-column change
affects which tickets match the current query — see design.md §4/§5.2
for the resulting forced-rebuild handling this requires.

## ADDED — `### Board view`

**Current text being replaced:**

> All 6 columns always render, including empty ones. Column order is
> fixed — there's no configurable/persisted column order or
> visibility.

**New behavior:**

Column **order** stays fixed and unconfigurable, exactly as before.
Column **visibility** is now configurable: a new "Columns" header
trigger — placed beside the existing Filters/Sort triggers in
`_TicketFilterAndSortSection`, shown only while Board mode is active
(no equivalent in List mode) — opens `TicketColumnsPopover`
(design.md §7.1), a single checkbox group listing all 6
`TicketStatus` values in their fixed declared order (mirroring
`BulkStatusMenu`'s existing status ordering), each row checked when
that status's column is currently visible. Unchecking a row hides that
status's `BoardColumn` entirely (it is skipped when
`TicketBoardView` builds its columns, not merely emptied/collapsed);
re-checking it restores the column, still in its original fixed
position relative to the other visible columns. Like the Filters
popover, toggling a row never closes the popover and re-applies
immediately — no separate "Apply" step.

The hidden-column selection persists per project via
`TicketBoardColumnVisibilityRepository`
(`SharedPreferences`, project-id-prefixed key — see design.md §3.2)
and is restored the next time that project's ticket list is opened,
the same way the filter/sort/view-mode selections are —
`TicketsCubit.loadPersistedBoardColumnVisibility()`, awaited from
`TicketsListScreen.initState` alongside the other three persisted
restores.

Hiding a column is a **display preference only**, not a workflow
restriction:

- `MoveToStatusMenu` (the keyboard/screen-reader-accessible equivalent
  of dragging a card to a new status) is unaffected — it still lists
  all 5 other statuses regardless of which columns are currently
  hidden. A ticket can be moved into a hidden status's column; it will
  simply not be visible on the board again until that column is shown.
- Dragging a card onto a hidden column is not reachable (a hidden
  column renders no `DragTarget` at all), but this doesn't make any
  status change drag-only — `MoveToStatusMenu` already covers every
  status regardless, the same reasoning the existing spec already
  gives for why board status changes are never drag-only in general.

**New empty state.** If every one of the 6 statuses is currently
hidden, `TicketBoardView` renders a centered hint ("No columns are
visible" / "Reopen Columns above to show one.") in place of the
(now-empty) horizontal column scroller — distinct from the existing
"No tickets match your search"/"No tickets yet" empty states, which
are about ticket *content*, not column *visibility*. This state is
reachable only through deliberate user action (unchecking every row in
the Columns popover) and remains reachable back out of via that same
popover, which stays available regardless of how many columns are
currently visible.

Everything else in this section — `BoardColumn`, `TicketBoardCard`
(status/blocked/rollup/token badges, hybrid clustering),
`MoveToStatusMenu`'s status-change behavior itself, and the Board
"Load more" button — is unchanged. A rendered column doesn't know or
care whether a sibling column is hidden.
