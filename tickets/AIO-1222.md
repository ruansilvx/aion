# Design: multi-project-hub

## 1. New feature: `features/projects/`

Follows the standard feature-first layering from `project.md`.

```
lib/features/projects/
  domain/
    entities/
      project.dart
      baseline_manifest.dart
      baseline_asset.dart
      project_override.dart
      resolved_config_item.dart
    repositories/
      project_repository.dart
      baseline_repository.dart
  data/
    models/
      project_model.dart              // json_serializable, drift row mapping
    repositories/
      drift_project_repository.dart
      bundled_baseline_repository.dart
  presentation/
    cubit/
      project_hub_cubit.dart
      project_hub_state.dart
      create_project_cubit.dart
      create_project_state.dart
      active_project_cubit.dart        // implements core/contracts/active_project_provider.dart
      active_project_state.dart
    screens/
      hub_screen.dart
      new_project_screen.dart
    widgets/
      project_card.dart
      project_switcher_menu.dart
```

## 2. Domain entities

- `Project` — `id` (uuid), `name`, `storageKey` (platform-agnostic string
  used to derive the per-project DB name/path — see §6), `rootPath`
  (nullable, desktop-only real directory; null on mobile/web), `baselineVersion`
  (pinned semver string), `createdAt`, `lastOpenedAt`.
- `BaselineManifest` — `version` (semver), `assets` (`List<BaselineAsset>`).
- `BaselineAsset` — `key` (unique name, e.g. `skills/propose`), `kind`
  (enum `BaselineAssetKind { skill, modelConfig, architectureConvention }`),
  `bundledPath` (asset path inside the app bundle).
- `ProjectOverride` — `projectId`, `assetKey`, `overridePath` (real file
  path under `<rootPath>/.aion/overrides/` — desktop-only; on mobile/web,
  overrides are not supported in this change since there is no local
  filesystem override surface yet).
- `ResolvedConfigItem` — `key`, `source` (enum `ConfigSource { baseline,
  override }`), `contentPath`. Output of merging a manifest with a
  project's overrides; consumed wherever Aion needs "the effective config
  for the active project" (e.g. which skills are available, desktop only
  for now).

## 3. Repository interfaces (domain — dumb persistence, no validation)

```dart
abstract interface class ProjectRepository {
  Future<List<Project>> getAllProjects();
  Future<Project?> getProject(String id);
  Future<void> createProject(Project project);
  Future<void> updateLastOpened(String id, DateTime timestamp);
  Future<void> removeProject(String id); // removes registry entry only —
                                          // does not delete the project's
                                          // on-disk data (desktop) or
                                          // storage namespace (mobile/web)
}

abstract interface class BaselineRepository {
  Future<List<String>> getAvailableBaselineVersions();
  Future<BaselineManifest> getManifest(String version);
  Future<List<ProjectOverride>> readOverrides(String projectId);
}
```

`DriftProjectRepository` reads/writes a lightweight **registry DB** — a
single global drift database (`core/database/registry_database.dart`,
separate from any per-project `AppDatabase`) holding only the `projects`
table. This is the one piece of drift state that is *not* per-project,
since it's what the Hub needs before any project is active.

`BundledBaselineRepository` reads baseline manifests from
`assets/baseline/<version>/manifest.json` (bundled app assets) and, for
overrides, lists files under `<rootPath>/.aion/overrides/` matching known
asset keys. Pure reads — no validation, no "is this override valid"
logic; that belongs in a Cubit if/when override authoring UI exists
(out of scope here per proposal.md).

## 4. Cross-feature wiring — `core/contracts/`

Per `project.md`'s Pattern 1 (dependency inversion via `core`), other
features must depend only on an abstraction to know "what project is
active" — they must not import `features/projects/` directly.

```dart
// core/contracts/active_project_provider.dart
abstract interface class ActiveProjectProvider {
  Project? get activeProject;
  Stream<Project?> get activeProjectStream;
}
```

`ActiveProjectCubit` (in `features/projects/presentation/cubit/`)
implements `ActiveProjectProvider`. It is provided once at the app root in
`main.dart`, above the workspace subtree, so any feature that needs to
know the active project (e.g. to label a screen, or to decide whether to
render a "no active project" empty state) depends on the `core` interface
only.

Note: unlike the general Pattern 1 example, feature repositories do
**not** consume `ActiveProjectProvider` directly to pick a DB connection.
See §6 — the DB swap is handled structurally by rebuilding the workspace
subtree, not by repositories reading "current project" at call time. This
avoids a stale-connection class of bugs a runtime-lookup proxy would risk.

## 5. Cubit states

`ProjectHubCubit` / `ProjectHubState`:
- `ProjectHubInitial`
- `ProjectHubLoading`
- `ProjectHubLoaded(projects: List<Project>)` — hub has projects to show
- `ProjectHubEmpty` — no projects exist yet (first run) — distinct from
  `Loaded([])` so the Hub can render an onboarding empty-state instead of
  an empty list
- `ProjectHubError(message: String)`

`CreateProjectCubit` / `CreateProjectState` — holds real domain/invariant
logic per `project.md`'s Cubit convention (validation lives here, not in
`DriftProjectRepository`):
- `CreateProjectInitial`
- `CreateProjectValidating` — checking name non-empty + unique among
  existing projects, and (desktop) that the chosen directory is not
  already an Aion project (no existing `.aion/manifest.json` marker)
- `CreateProjectReady(name, rootPath, baselineVersion)` — validated,
  awaiting submit
- `CreateProjectSubmitting`
- `CreateProjectSuccess(project: Project)`
- `CreateProjectFailure(message: String)` — surfaces both validation
  failures (duplicate name, path already an Aion project) and repository
  failures (disk write error) with distinct messages

`ActiveProjectCubit` / `ActiveProjectState`:
- `ActiveProjectNone` — at the Hub, no project open
- `ActiveProjectSwitching(from: Project?, to: Project)` — transient state
  while the old DB/subtree is torn down and the new one is built, used to
  show a loading transition rather than a flash of empty content
- `ActiveProjectOpen(project: Project)`

## 6. Runtime active-project switching (resolves the "hot-swap vs.
   restart" open question from storage-model-per-project-scoping.md)

Decision: **live hot-swap, no app restart**, implemented as a **subtree
rebuild**, not a runtime connection-swap proxy.

`main.dart`'s router defines two branches:
- `/hub`, `/hub/new` → `HubScreen` / `NewProjectScreen`, wrapped only in
  the app-root providers (`ActiveProjectCubit`, `ProjectRepository`,
  `BaselineRepository` — none of which need a project to be active).
- `/workspace/...` (existing `/tickets`, `/boards`, etc., now nested under
  a `/workspace` prefix) → wrapped in a widget keyed on
  `ValueKey(activeProject.id)` that owns the entire existing
  `MultiRepositoryProvider` tree for `AppDatabase`-backed feature
  repositories (tickets, boards, chat, posts).

When `ActiveProjectCubit` emits a new `ActiveProjectOpen(project)` with a
different `project.id` than before, the `ValueKey` changes, Flutter
disposes the old keyed subtree (closing its `AppDatabase` connection in
`dispose()`) and builds a fresh one that opens `AppDatabase` at the new
project's storage location. `go_router` redirects to `/workspace/tickets`
(or wherever) once the new subtree reports ready.

This keeps every existing feature repository's constructor signature
unchanged (`AppDatabase` still injected once per subtree instance) —
no feature needs a "current project" runtime lookup, and no
`AppDatabase`-holding singleton risks staleness after a switch.

## 7. `AppDatabase` per-project addressing

`core/database/app_database.dart`'s existing `_openConnection()` split
(native `drift_flutter` vs. `WasmDatabase.open`) is extended to take a
`Project` rather than opening one fixed global path:

- **Desktop/mobile (native)**: DB file at
  `<rootPath>/.aion/data/app.db` (desktop, real path) or
  `<app documents dir>/<storageKey>/app.db` (mobile — no user-chosen
  directory; `storageKey` is a generated id).
- **Web**: `WasmDatabase.open` database name becomes
  `aion_<storageKey>` instead of one fixed name, so each project gets an
  isolated OPFS/IndexedDB namespace within the same browser origin.

The separate **registry database** (§3) always opens at one fixed
location per platform (it must be readable before any project is picked)
and is never subtree-keyed — it lives in the app-root provider tree
alongside `ActiveProjectCubit`.

## 8. Baseline bundling

`assets/baseline/<version>/manifest.json` + referenced asset files,
declared under `pubspec.yaml`'s `flutter.assets`. First version ships as
`0.1.0`, seeded from the skill set already in `aion-arch/.claude/skills/`
plus a default model/provider config stub and a pointer to
`flutter-conventions.md` as the architecture-convention asset. `Project`
rows default `baselineVersion` to the latest bundled version at creation
time; existing projects never move to a newer version automatically
(upgrade UI is out of scope for this change — the pin is set once at
creation and is otherwise immutable through this change's UI surface).

## 9. go_router changes

```
/hub                      → HubScreen
/hub/new                  → NewProjectScreen
/workspace/tickets/...    → existing ticket routes (now nested)
/workspace/boards/...     → existing board routes (now nested)
```

Redirect logic: if `ActiveProjectCubit.state` is `ActiveProjectNone` and
the requested location starts with `/workspace`, redirect to `/hub`. If
state is `ActiveProjectOpen` and location is `/hub`, this is allowed
(user explicitly navigated back to switch projects) — it does not
force-redirect into `/workspace`.

## 10. Widget tree

```
HubScreen
  AionScaffoldEquivalent (non-Material root container, existing pattern)
    HubHeader
      AppText "Your Projects"
      AppButton "New Project" → context.go('/hub/new')
    BlocBuilder<ProjectHubCubit, ProjectHubState>
      ProjectHubLoading   → AppSpinner
      ProjectHubEmpty     → EmptyHubState (illustration + "New Project" CTA)
      ProjectHubLoaded    → ListView/GridView of ProjectCard
        ProjectCard(project)
          - name, rootPath/storageKey, lastOpenedAt (relative time),
            baseline version badge
          - "Open" → ActiveProjectCubit.switchTo(project) → context.go('/workspace/tickets')
          - overflow menu (AppDropdown) → "Remove" (confirmation, calls
            ProjectRepository.removeProject — registry entry only, see §3)
      ProjectHubError     → error text + AppButton "Retry"

NewProjectScreen
  AppTextField (name)               — bound to CreateProjectCubit
  Path picker row (desktop only)    — file_selector package, new dependency
  AppDropdown (baseline version)    — defaults to latest
  AppButton "Create"                — disabled while Validating/Submitting
  inline error text                 — from CreateProjectFailure

ProjectSwitcherMenu (in the workspace shell's nav, existing sidebar)
  AppDropdown-style menu → "Switch Project" → context.go('/hub')
```

`ProjectCard`, `ProjectSwitcherMenu`, and `EmptyHubState` are
feature-owned widgets (they embed `Project`, a feature entity) — not
promoted to `design_system/`, consistent with the promotion rule in
`flutter-conventions.md`.

## 11. Open questions carried forward (not resolved by this design)

- Exact override-authoring UX (editing/removing a project's overrides
  through the app) — deferred, no UI ships for it in this change.
- Mobile/web project git story — deliberately deferred (see proposal.md
  platform note); `storageKey`-only isolation ships now, git-backed
  version history stays desktop-only.
- Baseline version *upgrade* flow for existing projects (pin is
  immutable through this change's UI) — future change.
- Whether `removeProject` should eventually offer "also delete on-disk
  data" — out of scope; this change only removes the registry entry.

# Aion — Multi-Project Hub Specification

Implementation-ready spec for Aion's **Multi-Project Hub**: explicit, isolated projects (each with its own data store) and a **Hub** — a project list/switcher that becomes the app's entry point, replacing the current single-workspace assumption. From the Hub a user creates a project, opens one into the ticket/board workspace, and switches between projects without restarting the app.

- **No Material widgets or types anywhere.** Every component is built from plain Flutter primitives — `DecoratedBox`, `Container`, `GestureDetector`, `MouseRegion`, `CustomPaint`, `Row`, `Column`, `Stack`, `Positioned`, `Align`, `Padding`, `Wrap`, `GridView`/`Column` (scroll via `SingleChildScrollView` + `Column`, or a raw `ScrollView`), `CompositedTransformTarget`/`CompositedTransformFollower`, `Overlay`/`OverlayEntry`, `Focus`/`FocusNode`, `AnimatedContainer`, `AnimatedScale`. Do **not** reference `Card`, `ElevatedButton`, `TextButton`, `Scaffold`, `AppBar`, `ListTile`, `Dialog`, `AlertDialog`, `SnackBar`, `DropdownButton`, `PopupMenuButton`, `CircularProgressIndicator`, `ThemeData`, `ColorScheme`, `InkWell`, or any other `material.dart` symbol.
- `c` = active `AionColors`; `a` = theme `fillAlpha` (Arctic `0.11` / Obsidian `0.16`); `isDark` = Obsidian.
- Both themes share one code path; only token values differ. Where a component is identical across themes it is stated explicitly.
- Translucent fills are `token.withOpacity(x)` — never hardcoded ARGB.
- All existing `AionColors` / `AionText` / `AionRadius` / `AionSpacing` tokens are referenced by name. New tokens are defined only in §0.
- Companion mockups: `Aion Multi-Project Hub Mockups.dc.html` — Hub populated `1a`, Hub empty `1b`, New Project `1c`, New Project errors `1d`, mobile/web adaptations `1e`, component states `1f` (Arctic + Obsidian throughout).

**Platform terms.** `isDesktop` = macOS/Windows/Linux desktop build (has a filesystem + native directory picker). `isCompact` = mobile or web build (no filesystem path; data lives in an app/browser store). These gate the directory picker and the ProjectCard location rendering.

## 1. ProjectCard

One project's card in the Hub grid. Built as `MouseRegion` → `GestureDetector` → `Focus` → `AnimatedContainer` (150ms fill/border) wrapping a `Column`. **Never** a `material.Card` / `ListTile` / `InkWell`.

Tapping the card body (anywhere except the overflow trigger and the Open button) opens the project — identical to pressing **Open**. The overflow trigger and Open button are separate `GestureDetector`s that sit above the card's tap region and call `stopPropagation` equivalent (handle in the child, don't bubble to the card).

### 1.0 Dimensions & structure

| Property | Value |
|---|---|
| Width | grid track — `1fr` in a 2-column grid on desktop (min track ~340), full-width single column on compact |
| Height | intrinsic (content-driven), ~118 at default content |
| Padding | `EdgeInsets.fromLTRB(16, 16, 16, 14)` |
| Radius | `AionRadius.lg` (12) |
| Fill | `c.surface` |
| Border | `1px c.border` |
| Shadow | none at rest (Arctic may add `BoxShadow(color: Color(0xFF142230).withOpacity(0.07), blurRadius: 2, offset: Offset(0,1))`) |
| Inner layout | `Column`, `crossAxisAlignment: stretch`, `gap: AionSpacing.sp12` (12) |

Row structure (top → bottom):

1. **Title row** — `Row`, `gap: AionSpacing.sp8` (10 used), `crossAxisAlignment: center`:
   - **Name** — `Expanded`, `AionText.cardTitle` bumped to 15/700 (`AionText.cardTitle.copyWith(fontSize: 15, fontWeight: FontWeight.w700, letterSpacing: -0.15)`), color `c.textPrimary`, `maxLines: 1`, ellipsis.
   - **Overflow trigger** — `dots-three-vertical`/`dots-three` glyph, **20px**, color `c.textSecondary`, in a `28×28` `GestureDetector` hit area (radius `AionRadius.iconBtnSm` = 8). See §1.5.
2. **Location row** — `Row`, `gap: AionSpacing.sp8` (8), `crossAxisAlignment: center`, `min-width: 0`:
   - **Location glyph** — `16×13` (path: `folder` outline) or `14×14` (store: `database`/rounded-square) `CustomPaint`, `1.4px` stroke, color `c.textMuted`.
   - **Location text** — `AionText.key`-family mono (`AionText.key.copyWith(fontSize: 11.5, letterSpacing: 0)`), color `c.textMuted`, `Expanded`, `maxLines: 1`, ellipsis.
     - `isDesktop` + filesystem project → real path (`C:\Users\devon\Projects\aion`, `~/sites/marketing-site`).
     - `isCompact` **or** a browser/web-backed project → short storage identifier (`App storage · aion`, `Browser storage · field-notes`) — **no path**.
3. **Meta + action row** — `Row`, `gap: 9`, `crossAxisAlignment: center`, `margin-top: 2`:
   - **Version badge** — see §1.6.
   - **Last-opened time** — `AionText.time` (mono 11/400), color `c.textMuted`. Relative string computed app-side (`Just now`, `2 hours ago`, `Yesterday`, `3 days ago`, `1 week ago`).
   - `Spacer`.
   - **Open button** — §1.7.

## 2. HubScreen

Full-screen layout; the app's entry point. Two states: **populated** (§2.1) and **empty** (delegates to §3). On desktop it fills the app window; on compact it fills the device viewport. **No `Scaffold`/`AppBar`** — compose with `Column` + a background `DecoratedBox`.

### 2.0 Frame

| Property | Value |
|---|---|
| Background | `c.background` |
| Content padding (desktop) | `EdgeInsets.fromLTRB(32, 28, 32, 32)` |
| Content padding (compact) | header `EdgeInsets.fromLTRB(20, 8, 20, 14)`; list `EdgeInsets.symmetric(horizontal: 16)`; footer `EdgeInsets.fromLTRB(20, 14, 20, 20)` |

### 2.1 Header (populated)

`Row`, `crossAxisAlignment: start`, `mainAxisAlignment: spaceBetween`, `gap: AionSpacing.sp16`:

- **Left — title block** — `Column`, `gap: AionSpacing.sp4` (6 used):
  - Eyebrow: `AionText.caption` (mono uppercase) at `letterSpacing: 0.14em`-equiv, color `c.textMuted`, text `WORKSPACE`.
  - Heading: `AionText.h1` (Manrope 25/800), color `c.textPrimary`, text `Projects`.
- **Right — New Project button** — primary (§4.5 shared spec): fill `c.primary`, text `#FFFFFF` `AionText.button`, leading `plus` glyph 17px, `gap: AionSpacing.sp8`, padding `EdgeInsets.symmetric(horizontal: 17, vertical: 10)`, radius `AionRadius.md` (10), shadow `BoxShadow(color: c.primary.withOpacity(isDark ? 0.60 : 0.45), blurRadius: 22, spreadRadius: -10, offset: Offset(0, 12))`.
  - On **compact**, the header omits the button; a pinned bottom **New Project** bar is used instead (§2.3).

### 2.2 Project grid (populated)

- **Desktop:** 2-column grid — `Wrap` with two `Expanded`-equivalent tracks, or a manual `Column` of `Row`s. Column gap `AionSpacing.sp16` (16), row gap `AionSpacing.sp16` (16). `alignment: start`. Scrolls vertically if it overflows (`SingleChildScrollView`).
- **Compact:** single-column `Column` of full-width `ProjectCard`s, `gap: AionSpacing.sp12` (12), inside a vertical scroll view.
- Each child is a `ProjectCard` (§1), fed the project's registry entry.
- Ordering: most-recently-opened first.

### 2.3 Compact bottom bar (New Project)

Pinned below the scrolling list on compact:

| Property | Value |
|---|---|
| Container | top `1px c.border`, fill `c.background`, padding `EdgeInsets.fromLTRB(20, 14, 20, 20)` |
| Button | full-width primary: fill `c.primary`, text `#FFFFFF` `AionText.button` at 15px, leading `plus` 18px, centered, padding `EdgeInsets.symmetric(vertical: 15)`, radius `AionRadius.lg` (13 used), shadow FAB glow (`blurRadius: 26, spreadRadius: -10, offset: Offset(0,14)`) |

### 2.4 Empty state

When the project registry is empty, the grid area is replaced by `EmptyHubState` (§3), centered in the available space. The header (§2.1) is **hidden** on first run — the empty state owns the whole canvas including its own CTA.

### 2.5 Theme note

Identical structure both themes; token values differ.

## 8. Behavior & data notes

- **Registry vs data store.** The Hub reads a **project registry** (name, location descriptor, storage kind, baseline version, last-opened timestamp). Each project's ticket data lives in its own isolated store. **Remove** (§6.3/§7) deletes only the registry entry — never the on-disk/app-store data.
- **Location descriptor.** Desktop filesystem projects store an absolute path and render it (§1.0). Web/mobile-backed projects store a short storage identifier and render that with no path. The same ProjectCard code path chooses the glyph + text from the entry's storage kind and the current platform (`isCompact` always shows the storage identifier).
- **Directory picker gating.** §4.3 is present only when `isDesktop`; on `isCompact` the tree contains §4.4.1 instead. Do not merely `Visibility(visible:false)` — omit the subtree so it never participates in layout/focus order.
- **Open** (card body tap, Open button, or `Enter` on a focused card) loads the project into the existing ticket/board workspace and updates its last-opened timestamp.
- **Switch Project** (§5) returns to the Hub from within the workspace; it does not close/reopen the app.
- **Overlays.** Overflow menu (§6) and confirm dialog (§7) are `OverlayEntry`s; only one is open at a time; both dismiss on outside-tap and `Esc`.
- **No Material anywhere** — every surface, button, field, menu, and dialog above is a plain-primitive composition.
