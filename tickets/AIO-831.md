# Design: Documentation Section

## Architecture overview

No new domain entity is introduced. `page`/`resource` tickets are already
`Ticket` rows with `TicketType.page`/`TicketType.resource` — this change
adds new query/service capability around the existing entity plus new
presentation-layer screens/cubits, all inside `lib/features/tickets/`
(not a new top-level feature — everything here operates on `Ticket`/
`TicketLink`, which already live in `features/tickets/`; a separate
`features/documentation/` would need to import those internals,
violating the no-cross-feature-import rule).

## Domain layer changes

### `TicketTypeHierarchy.canParent` (MODIFIED)

`lib/features/tickets/domain/enums/ticket_type.dart`

```dart
bool canParent(TicketType child) {
  if (this == TicketType.page) {
    return child == TicketType.page || child == TicketType.resource;
  }
  final parentRank = _rank[this];
  if (parentRank == null) return false; // resource/chat: pure leaves
  if (child == TicketType.chat) return true; // work items still parent chat
  final childRank = _rank[child];
  if (childRank == null) return false; // resource/page no longer parentable by work items
  return parentRank < childRank;
}
```

Existing cycle-prevention (`TicketsCubit._descendantIds`) and the
epic-never-has-a-parent rule in `updateTicketParent` are unaffected —
both operate generically on `parentId` regardless of type.

## Data layer changes

### `TicketRepository` / `TicketDao` — new query method (ADDED)

`getTicketsByParent(String? parentId, {required List<TicketType> types})`
added to `TicketRepository` (domain interface) and implemented in
`DriftTicketRepository` / `TicketDao`. A dumb, parameterized query — no
business logic, consistent with "repositories stay dumb persistence
layers." Used by `DocumentationCubit` to load:
- root-level docs: `getTicketsByParent(null, types: [page, resource])`
- a page's children: `getTicketsByParent(pageId, types: [page, resource])`

Excludes soft-deleted tickets (`deletedAt IS NULL`), matching every other
ticket query in the app.

### `TicketDocumentSearchService` (ADDED)

`lib/features/tickets/data/services/ticket_document_search_service.dart`

```dart
class TicketDocumentSearchService {
  TicketDocumentSearchService(this._embeddingProvider, this._repository);

  final EmbeddingProvider _embeddingProvider;
  final TicketRepository _repository;

  /// Returns page/resource tickets ranked by cosine similarity to [query],
  /// highest similarity first. Brute-force over all non-trashed
  /// page/resource tickets with a populated embedding — matches the
  /// brute-force approach already used for embeddings elsewhere (see
  /// project.md Foundational Decision #1).
  Future<List<Ticket>> search(String query, {int limit = 20}) async {
    final queryVector = await _embeddingProvider.embed(query);
    final candidates = await _repository.getTicketsByParent(
      null, // ignored when scanning all docs; see note below
      types: const [TicketType.page, TicketType.resource],
    );
    // scored via a private cosine-similarity helper, sorted desc, top `limit`
  }
}
```

Note: the doc-search scan needs *all* pages/resources regardless of
nesting depth, not just root-level ones — `getTicketsByParent` as scoped
above only fetches one level. This service instead uses a second new
repository method, `getAllTicketsByType(List<TicketType> types)` (a
simple type-filtered, non-recursive variant), rather than overloading
`getTicketsByParent`'s `parentId` semantics. `getAllTicketsByType` is
listed as its own task below.

Cosine similarity is computed as a small private helper
(`double _cosineSimilarity(Uint8List a, Uint8List b)`) inside this
service — not promoted to a shared utility, since it has exactly one
caller today.

### `DocumentParentMigrationService` (ADDED)

`lib/features/tickets/data/services/document_parent_migration_service.dart`

One-time, idempotent migration, gated by a `shared_preferences` bool flag
(`hasMigratedDocumentParentsToLinks`). Run from `WorkspaceShell.initState`
alongside the existing `_purgeOldTrashOnOpen` call
(`lib/core/routing/app_router.dart`):

```dart
class DocumentParentMigrationService {
  DocumentParentMigrationService(this._ticketRepository, this._linkRepository, this._prefs);

  /// For every non-trashed resource/page ticket whose parentId points at
  /// an epic/story/task, creates a `relatesTo` TicketLink to that former
  /// parent and clears parentId to null. No-ops if already run once.
  Future<void> migrateIfNeeded() async { ... }
}
```

Runs once per install (flag persists in `shared_preferences`), fire-and-
forget like the existing trash-purge call, logged but non-blocking on
failure (matches the "focus-only... non-blocking" pattern established in
the storage-model idea).

## Presentation layer changes

### `DocumentationCubit` / `DocumentationState` (ADDED)

`lib/features/tickets/presentation/cubit/documentation_cubit.dart`,
`documentation_state.dart`

Per-route cubit (provided fresh on route entry, like `TrashCubit` — not
root-scoped like `TicketsCubit`, since the tree doesn't need to survive
navigating away).

States:
- `DocumentationInitial`
- `DocumentationLoading`
- `DocumentationLoaded` — carries the root-level doc tree (`List<Ticket>`
  root nodes; children loaded lazily per-node on expand, cached in a
  `Map<String, List<Ticket>>` keyed by parent id), plus current search
  results (`List<Ticket>?`, null when not searching).
- `DocumentationError`

Methods:
- `load()` — fetches root docs via `getTicketsByParent(null, types: [page, resource])`.
- `loadChildren(String pageId)` — lazy-loads and caches one page's
  children; only called for `page` nodes (resources never have children).
- `search(String query)` — debounced, delegates to
  `TicketDocumentSearchService.search`.
- `clearSearch()`.

### `DocumentationScreen` (ADDED)

`lib/features/tickets/presentation/screens/documentation_screen.dart`

Root screen for the new section. Layout:
- Header: title "Documentation", search field (AppTextField), "+ New
  page" / "+ New resource" actions.
- Body: when not searching, a collapsible tree (`DocumentationTreeItem`
  rows, indent-per-depth, expand/collapse chevron on `page` rows only).
  When searching, a flat ranked list of `DocumentationTreeItem` rows (no
  tree chrome, just relevance order).
- Empty state: faction-motif icon + "No documentation yet" copy, per
  existing empty-state convention.
- Tapping a row navigates to the existing `/workspace/tickets/:id` route
  (reuses `TicketDetailScreen` — see below; no new detail route).
- "+ New page"/"+ New resource" navigate to the existing
  `CreateTicketScreen` with `initialType` and `initialParentId` params
  (new optional constructor params — `CreateTicketScreen` already has a
  generic type/parent picker driven by `getValidParentCandidatesForType`,
  which now naturally excludes work items and includes pages once
  `canParent` is updated, so no picker-logic changes are needed there,
  only wiring the initial values through).

### `DocumentationTreeItem` (ADDED)

`lib/features/tickets/presentation/widgets/documentation_tree_item.dart`

Single row: type icon (page vs resource, Phosphor), title, expand
chevron (page only, hidden if no children loaded yet — lazy, so shown
whenever the row is a `page`; empty-children case just shows a caret that
expands to nothing), depth-based indent. No feature-specific business
logic — pure presentation, given a `Ticket` and callbacks.

### `TicketDetailScreen` (MODIFIED)

`lib/features/tickets/presentation/screens/ticket_detail_screen.dart`

Adds two new conditionally-rendered sections, both only when
`ticket.type == TicketType.page || ticket.type == TicketType.resource`:
- `DocumentationLinkedTicketsSection` — links (via `TicketLinkRepository
  .getLinksForTicket`) where the *other* side's type is in
  `{epic, story, task, chat}`.
- `DocumentationBacklinksSection` — links where the other side's type is
  in `{page, resource}` (see proposal's scoping decision #2).

Both sections reuse the same `getLinksForTicket` call already made for
the existing generic "related tickets" UI — the two new sections and the
pre-existing generic list are populated by grouping one query result by
the other side's type, not three separate queries.

Also adds, for `page` type only, a "Sub-pages" section listing direct
children (via the same `getTicketsByParent`/cubit-cached data used by
`DocumentationCubit`, fetched directly here rather than requiring
`DocumentationCubit` on this route — this screen already has its own
`TicketDetailCubit`, extended with a `loadChildDocs()` method).

### `DocumentationLinkedTicketsSection` / `DocumentationBacklinksSection` (ADDED)

`lib/features/tickets/presentation/widgets/documentation_linked_tickets_section.dart`,
`documentation_backlinks_section.dart`

Presentational list widgets — given a `List<Ticket>` and an
on-tap-navigate callback, no business logic of their own (grouping logic
lives in `TicketDetailCubit`).

### `TicketsListScreen` (MODIFIED)

`lib/features/tickets/presentation/screens/tickets_list_screen.dart`

- Header gains a "Documentation" icon button next to the existing Trash
  button, navigating to `/workspace/documentation` — same pattern as the
  existing Trash entry point (no centralized nav widget in this app; see
  `project-state.md`/existing Trash convention).
- The flat ticket list's type filter dropdown (`items: const [null,
  ...TicketType.values]`) excludes `TicketType.page` and
  `TicketType.resource`.
- `_visibleTickets`/board-ticket computation (already `task`/`story`
  only) is unaffected — resource/page were never included there.
- The underlying list query itself (`TicketsCubit.searchTickets`) is
  unaffected at the repository level; the exclusion is applied the same
  way the existing task/story board filter is applied today (client-side
  type filtering in the screen), keeping `TicketRepository.searchTickets`
  generic.

### `app_router.dart` (MODIFIED)

`lib/core/routing/app_router.dart`

- New `GoRoute('/workspace/documentation', ...)` inside the existing
  `ShellRoute`, alongside `tickets`/`tickets/trash`. Declared before any
  `:id`-wildcard route per the existing route-ordering convention.
  Provides a fresh `DocumentationCubit` per-route (mirrors `TrashCubit`'s
  provisioning at the trash route).
- `WorkspaceShell.initState` gains a fire-and-forget call to
  `DocumentParentMigrationService.migrateIfNeeded()`, alongside the
  existing `_purgeOldTrashOnOpen()` call.

## Data flow summary

```
DocumentationScreen
  └─ BlocProvider<DocumentationCubit>
       ├─ load() ─────────────► TicketRepository.getTicketsByParent(null, [page, resource])
       ├─ loadChildren(id) ──► TicketRepository.getTicketsByParent(id, [page, resource])
       └─ search(q) ─────────► TicketDocumentSearchService.search(q)
                                   ├─ EmbeddingProvider.embed(q)
                                   └─ TicketRepository.getAllTicketsByType([page, resource])
                                        (cosine-ranked in-memory)

TicketDetailScreen (type == page|resource)
  └─ TicketDetailCubit (extended)
       ├─ loadChildDocs() ───► TicketRepository.getTicketsByParent(ticket.id, [page, resource])
       └─ existing getLinksForTicket(ticket.id) result grouped into:
             - "linked tickets" (other side: epic/story/task/chat)
             - "backlinks" (other side: page/resource)

WorkspaceShell.initState
  └─ DocumentParentMigrationService.migrateIfNeeded()
       for each non-trashed resource/page with parentId → epic/story/task:
         create TicketLink(relatesTo) + clear parentId
```

# Aion — Documentation Section: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name; defines new tokens only where the base table has no fit (§1). **No Material widgets anywhere** — every surface below is `DecoratedBox` / `Container` / `GestureDetector` / `CustomPaint` / `Row` / `Column` / `Stack` / `AnimatedFoo`, never `Card`, `Scaffold`, `AppBar`, `ListTile`, `ElevatedButton`, `TextButton`, `InkWell`, `Chip`, `ColorScheme`, or `ThemeData`.

The Documentation section is the primary home for `resource` and `page` tickets, replacing their presence in the main ticket list. Pages nest sub-pages Notion-style; resources are leaf nodes. This spec covers:

1. New color tokens `typeResource` / `typePage` and their fills (§1).
2. `DocumentationScreen` — root screen (§3).
3. `DocumentationTreeItem` — tree/list row (§4).
4. Documentation entry-point icon button on the ticket-list header (§5).
5. `DocumentationSearchField` (an `AppTextField` leading-icon variant) (§6).
6. `DocumentationEmptyState` (§7).
7. Ticket-detail documentation-mode sections — Sub-pages, Linked Tickets, Backlinks (§8).

Mockups: [Aion Documentation Section Mockups](./Aion%20Documentation%20Section%20Mockups.dc.html).

Every color resolves from the active `AionColors`, so a single widget serves both **Arctic** (light) and **Obsidian** (dark). Where a value is theme-dependent it is expressed as `token.withOpacity(x)` and the alpha is stated per theme — never a hard-coded ARGB.

---

## 1. Foundations added

### 1.1 New type-accent tokens — `typeResource`, `typePage`

The base `AionColors` defines `typeTask` / `typeStory` / `typeEpic` only. `resource` and `page` are ticket types with no chip accent yet. Add two tokens to `AionColors`, following the same one-base-color-per-type rule and choosing hues clearly separated from the existing three (blue / green / indigo) and from the reserved priority (rose/amber/teal/slate), `warning` (gold), and `danger` (rose) hues:

```dart
// added to AionColors
final Color typeResource; // reference / leaf docs — terracotta
final Color typePage;     // container / nesting docs — orchid
```

| Token | Arctic | Obsidian | Hue |
|---|---|---|---|
| `typePage` | `Color(0xFFB0499E)` | `Color(0xFFD98CE6)` | Orchid / magenta |
| `typeResource` | `Color(0xFFC2622E)` | `Color(0xFFE68A4E)` | Terracotta / orange |

```dart
// arctic
typePage:     Color(0xFFB0499E),
typeResource: Color(0xFFC2622E),
// obsidian
typePage:     Color(0xFFD98CE6),
typeResource: Color(0xFFE68A4E),
```

Rationale: `typePage` (orchid) and `typeResource` (terracotta) are mutually distinct and separated from `typeTask` (blue), `typeStory` (green), `typeEpic` (indigo). Terracotta sits between `warning` gold and `danger` rose without colliding with either.

### 1.2 New-type tinted fills

Exactly as `typeTask` etc. are tinted elsewhere — base token at the theme's `fillAlpha` (`fillAlphaArctic = 0.11`, `fillAlphaObsidian = 0.16`). **Never hard-code; always `.withOpacity`.**

```dart
// c = active AionColors, a = fillAlpha for the theme (0.11 Arctic / 0.16 Obsidian)
final typePageFill     = c.typePage.withOpacity(a);
final typeResourceFill = c.typeResource.withOpacity(a);

// leading type-icon chip in tree rows / backlink rows uses a slightly stronger fill:
final typePageIconFill     = c.typePage.withOpacity(a);     // same alpha; glyph at full strength
final typeResourceIconFill = c.typeResource.withOpacity(a);
```

### 1.3 Selection tint

Selected/active tree rows reuse the base `primarySubtle` token (selection tint) — no new token. The active-row left rail uses `primary` at full strength.

### 1.4 New iconography

Two new thin-line glyphs (1.5px stroke, same family as the base set), plus reuse of existing glyphs:

| Function | Glyph | Notes |
|---|---|---|
| page (doc container) | file-text (page with a folded corner + text lines) | color `typePage` in tree/backlink; `textSecondary` when neutral |
| resource (leaf ref) | bookmark-simple (tag/bookmark with a bottom notch) | color `typeResource` in tree/backlink |
| expand/collapse | chevron-right (rotates 90° down when expanded) | 14px, color `textMuted`; hidden entirely on childless pages and all resources |
| documentation (entry point) | book-open (reuses base `story` glyph family, distinct weight) | 20px, color `textSecondary` |

No new radius, spacing, or type tokens are required — every component below reuses `AionRadius`, `AionSpacing`, and `AionText`.

### 1.5 Indentation unit

Tree depth indent = **`20` px per depth level** (= `AionSpacing.sp20`), applied as extra left padding on the row. Depth 0 has no extra indent. The chevron/spacer column (`18` px wide) is a fixed leading column so titles at the same depth align whether or not the row has a chevron.

## 2. Shared primitives

`c` = active `AionColors`; `a` = theme `fillAlpha` (Arctic 0.11 / Obsidian 0.16); `isDark` = `theme.brightness == Brightness.dark`.

### 2.1 Type chip — page / resource

Identical structure to base §2.2 type chip, using the new tokens.

- Layout: `Row`, `gap: 5`, `crossAxisAlignment: center`.
- Padding: `EdgeInsets.fromLTRB(5, 2, 7, 2)` (row) / `(6, 3, 8, 3)` (detail).
- Radius: `5`.
- Fill: `typePage.withOpacity(a)` / `typeResource.withOpacity(a)`.
- Leading solid square: `9×9` (row) / `11×11` (detail), radius `2.5`, color `typePage` / `typeResource`.
- Text: `AionText.chip`, UPPERCASE (`"PAGE"` / `"RESOURCE"`), color `typePage` / `typeResource`.

### 2.2 Type icon — page / resource (leading, tree + backlinks)

A `20×20` glyph, optionally inside a `26×26` rounded tint chip (used in backlink rows and the sub-pages section header; the tree uses the bare glyph).

- Bare glyph: `20×20`, page → file-text `typePage`, resource → bookmark `typeResource`.
- Tint chip variant: `26×26`, radius `AionRadius.iconBtnSm` (8), fill `typePage.withOpacity(a)` / `typeResource.withOpacity(a)`, centered glyph `15px` at full-strength token color.

## 3. `DocumentationScreen`

Full-screen root. Phone canvas `380×812`, status bar `46px` (base §3). Column: header block → search field → body (tree · search-results · empty) → primary "+ New page" affordance is reachable from the header actions and the empty state.

### 3.1 Header block

- Container: `Column`, `crossAxisAlignment: stretch`, padding `EdgeInsets.fromLTRB(20, 8, 20, 12)`.
- **Eyebrow row:** `AionText.caption` (mono, UPPERCASE, +1.54 tracking) `"AION · DOCS"`, color `textMuted`.
- **Title row:** `Row`, `crossAxisAlignment: center`, `gap: 12`:
  - `AionText.h1` `"Documentation"`, color `textPrimary`, `Expanded`.
  - Trailing `38×38` outlined user avatar (base §2.6 outlined), unchanged.
- **Actions row:** `Row`, `gap: AionSpacing.sp8` (8), `margin-top: 14`:
  - **"+ New page"** — primary button (base §2.1 Primary): fill `primary`, text `#FFFFFF`, `AionText.button`, leading `+` 16px, padding `EdgeInsets.symmetric(horizontal: 15, vertical: 10)`, radius `AionRadius.md` (10), FAB-glow shadow (`BoxShadow(color: fabGlow, blurRadius: 18, spreadRadius: -9, offset: Offset(0,10))`).
  - **"+ New resource"** — secondary button (base §2.1 Secondary): fill `surfaceHover`, text `textPrimary`, 1px `borderStrong`, `AionText.button`, leading `+` 16px `textSecondary`, padding `EdgeInsets.symmetric(horizontal: 15, vertical: 10)`, radius `AionRadius.md` (10).

### 3.2 Search field

`DocumentationSearchField` — see §6. Sits below the header block, padding `EdgeInsets.fromLTRB(20, 2, 20, 12)`.

### 3.3 Body — tree mode (default, not searching)

- Container: `surface` fill, top `1px border`, fills remaining height, scrolls.
- Content: a `Column` of `DocumentationTreeItem` (§4), one per visible node (children of collapsed pages are not built). Rows are separated by **no** divider — the tree reads as a continuous indented list; row hover/selection provides the only surface change. (A 1px `border` divider is optional between depth-0 roots only; default is none.)
- Vertical rhythm: each row is self-contained with its own vertical padding (§4); no inter-row gap.

### 3.4 Body — search mode (query non-empty)

- Same `surface` container.
- A `caption`-style result count header: `AionText.caption` `"N RESULTS"`, color `textMuted`, padding `EdgeInsets.fromLTRB(20, 14, 20, 6)`.
- Rows: `DocumentationTreeItem` in **flat variant** (§4.5) — no depth indent, no chevron column; each row instead shows a `breadcrumb` subtitle (`AionText.breadcrumb`, `textMuted`) with the ancestor path (e.g. `"Product Specs"`). Ranked by match; the matched substring in the title is emphasized with `textPrimary` w700 (rest of title stays `cardTitle` weight).
- No-results: centered `Column`, `gap: 12`, padding `40`: `20px` search glyph `textMuted`, `AionText.body` `"No docs match \u201c{query}\u201d"` `textSecondary`, and a ghost "Clear search" action (`AionText.button`, `primary`).

### 3.5 Body — empty state

`DocumentationEmptyState` — see §7. Fills the body region.

### 3.6 State summary — screen body

| Condition | Body |
|---|---|
| Has docs, not searching | Tree mode §3.3 |
| Has docs, searching (matches) | Flat ranked list §3.4 |
| Has docs, searching (no match) | No-results §3.4 |
| Zero docs | Empty state §7 |

## 4. `DocumentationTreeItem`

A single row in the tree (or, in flat variant, the search list). `resource` and `page` only.

### 4.0 Shared geometry

- Container: `GestureDetector` → `AnimatedContainer` (120ms fill), full width.
- Padding: `EdgeInsets.fromLTRB(leftPad, 9, 14, 9)` where `leftPad = 12 + depth * 20` (tree) or `14` (flat).
- Radius: `AionRadius.md` (10) on the row's fill box, with `EdgeInsets.symmetric(horizontal: 8)` outer margin so the selected/hover fill is an inset rounded pill, not full-bleed. (Set outer margin `0` and radius `0` if you prefer full-bleed rows; default is the inset pill.)
- Structure: `Row`, `crossAxisAlignment: center`, `gap: 9`:
  1. **Chevron column** (tree only) — fixed `18` px wide. Page with children → chevron-right `14px` `textMuted`, rotated `90°` (down) when expanded (`AnimatedRotation`, 140ms). Page with no children or any resource → empty `18px` spacer (glyph omitted, space preserved for alignment).
  2. **Type icon** — `20×20`, page → file-text `typePage`, resource → bookmark `typeResource` (§2.2 bare glyph).
  3. **Title** — `AionText.cardTitle`, color `textPrimary`, `Expanded`, `maxLines: 1`, `TextOverflow.ellipsis`.
  4. **Trailing meta** (optional) — a child-count pill on collapsed pages: `AionText.key` (mono 11px), color `textMuted`, fill `surfaceHover`, padding `2×6`, radius `5`, e.g. `"4"`. Omit for resources and for pages with zero children.

### 4.1 Default

- Fill: transparent.
- Border: none.
- Title: `textPrimary`. Chevron/spacer + child-count as above.

### 4.2 Hover

- Fill: `surfaceHover`.
- Everything else unchanged. Chevron brightens to `textSecondary`.

### 4.3 Pressed

- Fill: `surfaceHover`, `AnimatedScale` `0.99` (80ms).

### 4.4 Selected / focused

- Fill: `primarySubtle`.
- **Leading rail:** a `3px` wide, full-row-height rounded bar in `primary` on the row's left edge (inside the inset margin), radius `2`.
- Title: `textPrimary` (unchanged weight). Type glyph and chevron shift to `primary` **only if** the row is the keyboard-focused row; a merely-selected (last-opened) row keeps its type color. Focus ring is the rail + tint, not a `BoxShadow` ring, to stay quiet in a dense list.

### 4.5 Flat (search-result) variant

- No chevron column, no depth indent (`leftPad = 14`).
- Adds a second line under the title: `AionText.breadcrumb` (11px, `textMuted`), the ancestor path joined with `\u203a` (e.g. `"Product Specs \u203a Ticket Sync Design"`), `maxLines: 1`, ellipsis. Structure becomes `Row(icon, Expanded(Column(title, breadcrumb, gap: 2)))`, row padding `EdgeInsets.fromLTRB(14, 10, 14, 10)`.
- Matched substring in the title rendered `textPrimary` w700 via `TextSpan`; remainder `AionText.cardTitle`.

### 4.6 State summary — tree item

| State | Fill | Rail | Title | Chevron | Notes |
|---|---|---|---|---|---|
| Default | transparent | none | `textPrimary` | `textMuted` (if page w/ children) | — |
| Hover | `surfaceHover` | none | `textPrimary` | `textSecondary` | — |
| Pressed | `surfaceHover` | none | `textPrimary`, scale 0.99 | — | 80ms |
| Selected | `primarySubtle` | 3px `primary` | `textPrimary` | as default | last-opened doc |
| Focused | `primarySubtle` | 3px `primary` | `textPrimary` | `primary` | keyboard focus; glyph→`primary` |
| Disabled | n/a | — | — | — | rows are never disabled |

Theme parity: structure identical; all colors resolve from the active `AionColors`.

## 5. Documentation entry-point icon button (ticket-list header)

A header icon button added to the existing ticket-list screen header (base §3.1), opening the Documentation section. Same visual family as the header icon-button pattern (the outlined `37×37` header buttons); specified standalone here so it is unambiguous.

### 5.1 Geometry (all states)

- Size: `37×37`.
- Radius: `AionRadius.iconBtn` (11).
- Glyph: book-open (documentation), `20px`, centered.
- Wrapped in a `GestureDetector` → `AnimatedContainer` (120ms).

### 5.2 States

| State | Fill | Border | Glyph color | Extra |
|---|---|---|---|---|
| Default | `surfaceHover` | `1px border` | `textSecondary` | — |
| Hover | `surfaceHover` | `1px borderStrong` | `textPrimary` | — |
| Focused | `surfaceHover` | `1px borderStrong` | `textPrimary` | focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), spreadRadius: 3, blurRadius: 0)` |
| Pressed | `border` | `1px borderStrong` | `textPrimary` | `AnimatedScale` 0.96 (80ms) |

## 8. Ticket-detail documentation-mode sections

Added to the existing generic `TicketDetailScreen` (base §3.3) **only** for `ticket.type ∈ {page, resource}`. Three stacked sections inserted into the scroll body after the existing Content block, each separated by a top `1px border` and using the base mono-eyebrow section-header pattern. For any other ticket type none are built (`SizedBox.shrink()`).

### 8.1 Section frame (shared)

- Container: `Column`, `crossAxisAlignment: stretch`, padding `EdgeInsets.fromLTRB(20, 16, 20, 16)`, top `1px border`.
- Header row: `Row`, `crossAxisAlignment: center`, `gap: 8`, `margin-bottom: 12`:
  - `AionText.caption` (mono, UPPERCASE, +1.54 tracking) section label, color `textMuted`.
  - Trailing count pill (optional): `AionText.key` mono 11px `textSecondary`, fill `surfaceHover`, padding `2×6`, radius `5`.
  - Trailing "+ Add" ghost affordance (Sub-pages / Linked only): `AionText.button` 13px `primary`, leading `+` 15px, right-aligned (`Expanded` spacer before it).
- Body: a `Column` of rows, `gap: 0` (rows self-pad) or `gap: 8` for card-style rows — stated per section.

### 8.2 Sub-pages section (`page` type only)

Titled `"SUB-PAGES"`. A flat list of the page's **direct children** (pages and resources), using `DocumentationTreeItem` (§4) in **non-expandable** form: no chevron column, no depth indent, but the leading type icon and title are as §4.0. Tapping a row opens that child's detail.

- Header count pill: number of direct children.
- Rows: `DocumentationTreeItem` with `depth: 0`, `showChevron: false`, `leftPad: 0`. Row padding `EdgeInsets.symmetric(horizontal: 0, vertical: 9)`; separated by no divider.
- Empty (page has no sub-pages): a single muted line `AionText.bodySm` `textMuted` `"No sub-pages yet"` + the "+ Add" affordance in the header.
- Resource-type ticket details **omit** this section entirely (resources are leaves).

### 8.3 Linked Tickets section (`DocumentationLinkedTicketsSection`)

Titled `"LINKED TICKETS"`. Rows of linked board tickets (epic / story / task / chat) this doc references.

- Header count pill: number of linked tickets. Trailing "+ Add" affordance.
- Body: `Column` of link rows, `gap: 8`.

**Link row** — a tappable card:

- Container: `GestureDetector` → `AnimatedContainer` (120ms), fill `surface`, 1px `border`, radius `AionRadius.md` (10), padding `EdgeInsets.symmetric(horizontal: 12, vertical: 11)`.
- Structure: `Row`, `crossAxisAlignment: center`, `gap: 10`:
  1. **Type chip** — base §2.2, using `typeTask` / `typeStory` / `typeEpic` per the ticket's type (chat rows use the AI mark treatment: `9×9` `primary` square + `"CHAT"` label `primary` on `primary.withOpacity(a)`).
  2. **Key** — `AionText.key` (mono, e.g. `"AIO-12"`), color `textSecondary`, fill `surfaceHover`, padding `2×6`, radius `5`.
  3. **Title** — `AionText.cardTitle`, color `textPrimary`, `Expanded`, `maxLines: 1`, ellipsis.
  4. **Priority badge** — base §2.3 row size (`AionText.prioritySm`, `priority.{level}Bg` / `Fg`), right-aligned; **omitted when priority is null**.

**Link-row states:**

| State | Fill | Border |
|---|---|---|
| Default | `surface` | `1px border` |
| Hover | `surfaceHover` | `1px borderStrong` |
| Pressed | `surfaceHover`, scale 0.99 (80ms) | `1px borderStrong` |
| Focused | `surface` | `1.5px primary` + focus ring `BoxShadow(primary.withOpacity(isDark ? 0.30 : 0.16), spread 3, blur 0)` |

Empty: `AionText.bodySm` `textMuted` `"No linked tickets"` + "+ Add" in header.

### 8.4 Backlinks section (`DocumentationBacklinksSection`)

Titled `"BACKLINKS"`. Rows of **other page/resource docs** that link **to** this doc. Same card shape as §8.3 but the leading indicator is a **type icon** (not a chip), using the new `typePage` / `typeResource` tokens, since backlinked items are always page/resource. Read-only (no "+ Add" — backlinks are derived, not authored).

**Backlink row:**

- Container: identical to §8.3 link row (fill `surface`, 1px `border`, radius `10`, padding `12×11`); same tap states.
- Structure: `Row`, `crossAxisAlignment: center`, `gap: 10`:
  1. **Type icon chip** — §2.2 tint-chip variant: `26×26`, radius `AionRadius.iconBtnSm` (8), fill `typePage.withOpacity(a)` / `typeResource.withOpacity(a)`, centered glyph `15px` `typePage` / `typeResource`.
  2. **Title** — `AionText.cardTitle`, `textPrimary`, `Expanded`, ellipsis.
  3. **Type label** — `AionText.chip`, UPPERCASE (`"PAGE"` / `"RESOURCE"`), color `typePage` / `typeResource`, right-aligned.
- Optional second line (breadcrumb): `AionText.breadcrumb` `textMuted` ancestor path, `maxLines: 1`, ellipsis — same treatment as §4.5; wrap the title+breadcrumb in a `Column(gap: 2)`.

Empty: section omitted entirely when there are no backlinks (derived — an empty backlinks section carries no affordance, so it is not shown).

### 8.5 Insertion order (page-type detail)

```
[header row]                         ← base §3.3, gains the sync badge (Sync spec) for file docs
──────────────────────────────
[priority badge]                     ← base body
[title (AionText.h2)]
[type chip (PAGE) · status]
[Content block]                      ← base, top border
──────────────────────────────
[SUB-PAGES]        §8.2  (page only)
──────────────────────────────
[LINKED TICKETS]   §8.3
──────────────────────────────
[BACKLINKS]        §8.4  (omitted if none)
```

For a `resource`-type detail, the Sub-pages section (§8.2) is dropped; Linked Tickets and Backlinks remain in that order.

### 8.6 Theme parity

All three sections are structurally identical across Arctic and Obsidian; every color resolves from the active `AionColors` plus the §1 tints. No per-theme layout differences.
