# 3. `BaselineRepository` override read/write

- [x] Update `lib/features/projects/domain/repositories/
      baseline_repository.dart` — add `readBundledContent`,
      `readOverrideContent`, `writeOverride` per design.md §4, with
      dartdoc. Remove the class-level dartdoc's now-stale "out of scope
      for this change" note about override-authoring UI.
- [x] Update `lib/features/projects/data/repositories/
      bundled_baseline_repository.dart` — implement the three new
      methods per design.md §4. Also fixed a pre-existing bug in
      `readOverrides` found while implementing this: it derived
      `ProjectOverride.assetKey` from a bare file-name segment (e.g.
      `"propose"`) that never matches `BaselineAsset.key`'s
      slash-qualified form (`"skills/propose"`), silently breaking
      override lookup for both this change's `TicketsCubit` resolver and
      the Overrides UI. Now cross-references the pinned manifest to
      reconstruct the full key.
- [x] Update `test/features/projects/data/repositories/
      bundled_baseline_repository_test.dart` — cover
      `readBundledContent` (loads from the fake bundle),
      `readOverrideContent` (reads a written file), `writeOverride`
      (creates the overrides dir if missing, writes the correctly-named
      file, no-ops when the project has no `rootPath`). Also updated
      `readOverrides`'s existing test for the assetKey fix above, and
      added a case for the "no manifest match" fallback.
