# Spec Delta: Idea, Known Gap, and Open Question ticket types

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's Gaps & Open Questions section and PageTicketProvider's createGapOrQuestion` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. the idea/knownGap/openQuestion split this delta introduces is confirmed current and actively used elsewhere in the spec. The old signal-type identifiers the automated check flagged are this delta's own REMOVED-section content (superseding the prior combined signal type from sdd-ticket-foundation — see that ticket's own reconciliation note) — expected, not drift.

Delta against `aion-arch/specs/tickets.md`. Read alongside
[proposal.md](../proposal.md) and [design.md](../design.md) — this file

## ADDED

- **`TicketType.idea`** — freestanding, always a subtree root
  (`isAlwaysRoot`), may parent a `chat` only, promotable into `epic`/
  `bug` via `TicketsCubit.promoteIdea`. Behaviorally identical to the
  removed `TicketType.signal`.
- **`TicketType.knownGap`**, **`TicketType.openQuestion`** — always a
  subtree root, may parent a `chat` only, never promotable. Each must
  be created already linked (`TicketLinkType.relatesTo`) to an existing
  ticket — a hard rule enforced in `TicketsCubit.createGapOrQuestion`,
  not a UI-layer convention. Creatable only from the target ticket's
  own detail screen (the new Gaps & Open Questions section's "+ Add"
  affordance), never from the generic global New Ticket flow.
- **`GapOrQuestionRef`** (`domain/entities/gap_or_question_ref.dart`) —
  new record typedef: `({Ticket ticket, Ticket raisedOn, String linkId})`.
- **`TicketDetailLoaded.gapsAndOpenQuestions`** — new state field
  (`List<GapOrQuestionRef>`), populated by
  `TicketsCubit.loadDocumentRelations`. Recursively aggregates every
  `knownGap`/`openQuestion` ticket `relatesTo`-linked to the viewed
  ticket **or to any descendant of it**, walked via
  `TicketsCubit._descendantIds`. Populated for the same gated ticket
  types `linkedTickets`/`backlinks` already are: `epic`/`story`/`task`/
  `bug`/`resource`/`page`.
- **`TicketsCubit.createGapOrQuestion(TicketType type, {required
  String title, String? description, required String
  targetTicketId})`** — creates a `knownGap`/`openQuestion` ticket and
  its mandatory `relatesTo` link to `targetTicketId` atomically. Emits
  `TicketsError` and creates nothing if `type` isn't `knownGap`/
  `openQuestion`, or if `targetTicketId` doesn't resolve to an existing
  ticket.
- **`TicketsCubit.reclassifyIdea(Ticket idea, {required TicketType
  targetType, required String targetTicketId})`** — converts an
  existing `idea` ticket into a `knownGap`/`openQuestion` in place
  (mutates `type` via `TicketRepository.updateTicket`, preserving id/
  ticketId/createdAt/comments/children) and creates the mandatory
  `relatesTo` link. Same validation as `createGapOrQuestion`, plus
  refusing any ticket whose current type isn't `idea`. This is the only
  way a pre-existing `signal`-turned-`idea` ticket (see Migration notes
  below), or any other misclassified `idea`, becomes a `knownGap`/
  `openQuestion` — no automatic reclassification exists.
- **`GapsAndOpenQuestionsSection`** (new `design_system/molecules`
  widget) — renders `TicketDetailLoaded.gapsAndOpenQuestions`: type-
  colored rows (ticket key + title, tap-to-navigate), each annotated
  "on `<raisedOn.title>`" when the entry was rolled up from a
  descendant rather than raised directly on the viewed ticket; empty
  state when the list is empty; header "+ Add" trigger opening the new
  creation popover. Wired into `ticket_metadata_section.dart`'s
  Documentation-mode block and `page_detail_screen.dart`, immediately
  after the existing Linked Tickets/Backlinks pair.
- **Gap/open-question creation popover** (new, unnamed pending Design
  Gate) — `Overlay`-anchored, opened by `GapsAndOpenQuestionsSection`'s
  "+ Add" trigger: a type-choice menu ("Raise a known gap" / "Raise an
  open question") followed by a compact title + optional-description
  form. Calls `TicketsCubit.createGapOrQuestion` with the viewed
  ticket's own id as `targetTicketId`.
- **`TicketOverflowMenu` reclassify rows** — "Change to Known Gap" /
  "Change to Open Question", shown only for `TicketType.idea` tickets,
  alongside the existing "Promote to Epic"/"Promote to Bug" rows.
  Selecting one opens a searchable existing-ticket picker (no "create
  new" option, unlike promotion) and calls
  `TicketsCubit.reclassifyIdea`.
- **A "Raised on" indicator** on a `knownGap`/`openQuestion` ticket's
  own detail screen — a small, read-only, tap-to-navigate element
  naming the ticket it's linked to. Not a full Linked Tickets section
  (see MODIFIED below) — the relationship is fixed at creation.
- **`AionColors.typeKnownGap`, `AionColors.typeOpenQuestion`** — new
  required color tokens (both themes).
- **Drift migration, schema version 10 → 11** — data-only: every
  pre-existing `tickets` row with `type = 'signal'` is rewritten to
  `type = 'idea'`. No new/changed columns.
- **`app_en.arb` entries** for the two new type labels, the new
  section's label/empty-state/creation-form copy, and the two
  reclassify-action labels.

## MODIFIED

- **`TicketType.signal` → `TicketType.idea`** (rename) — identical
  `_rank` (`null`), `canParent` (`chat` only), `isAlwaysRoot` (`true`)
  behavior; every existing `signal` producer (Inbox brain-dump,
  codebase-analysis scan findings/run-record) now creates `idea`
  tickets.
- **`TicketsCubit.promoteSignal` → `TicketsCubit.promoteIdea`**
  (rename) — identical signature and behavior, now validated against
  `TicketType.idea` instead of `TicketType.signal`.
- **`TicketsCubit.loadDocumentRelations`** — extended (not replaced) to
  additionally populate `gapsAndOpenQuestions` (see ADDED above). Its
  existing `linkedTickets`/`backlinks` behavior and gated-type list are
  unchanged.
- **`ticket_metadata_section.dart`'s Documentation-mode exclusion
  gate** — the excluded-type set changes from `chat`/`signal`/
  `release` to `chat`/`idea`/`knownGap`/`openQuestion`/`release`. `idea`
  keeps `signal`'s prior exclusion; `knownGap`/`openQuestion` are newly
  excluded from the *generic* Linked Tickets/Backlinks block (they get
  the narrower "Raised on" indicator instead — see ADDED above), not
  from the new Gaps & Open Questions section itself, which they never
  render on their own screen regardless (it only ever appears on the
  ticket they're raised *on*).
- **`CreateTicketScreen`'s type dropdown** — excludes `knownGap`/
  `openQuestion` in addition to the existing `page` exclusion. `idea`
  remains offered (unchanged from `signal`'s prior inclusion).
- **`TicketFilterPopover`'s Type-group exclusion list** — `signal`/
  `release`'s existing "pre-existing gap" exclusion carries forward
  onto `idea`/`knownGap`/`openQuestion`/`release`; no new gap
  introduced, none closed.
- **`TypeChip`, `linked_tickets_section.dart`'s `_typeColor`,
  `TicketFilterPopover`'s type-label switch** — each exhaustive
  `TicketType` switch gains `idea`/`knownGap`/`openQuestion` arms in
  place of the removed `signal` arm.
- **`InboxCubit.startBrainDump`** — internal `SIGNAL:` reply-parsing
  marker renamed to `IDEA:`; creates `TicketType.idea` tickets instead
  of `TicketType.signal`.
- **`InboxCubit.startWhatNextGuidance`'s context assembly** — priority
  tier 2 ("known gaps documented in the project's own docs") now
  queries `TicketType.knownGap`/`TicketType.openQuestion` tickets
  directly instead of scanning Documentation `page` descriptions for a
  "## Known gaps" markdown heading; priority tier 3 ("open, not-yet-
  promoted raw ideas") queries `TicketType.idea` the same way it
  previously queried `TicketType.signal`. Still advisory prose only,
  never parsed or acted on programmatically.
- **`AionColors.typeSignal` and its `signalFill`/`signalBorderTint`/
  `signalIconTint`/`signalChipTint` tint family** → `typeIdea`/
  `ideaFill`/`ideaBorderTint`/`ideaIconTint`/`ideaChipTint` (rename,
  same formulas). `CodebaseAnalysisBanner` updates every call site to
  match.
- **`AppDatabase`** — `schemaVersion` 10 → 11; class dartdoc's version-
  history list gains a Version 11 entry describing the `signal` → `idea`
  data migration.

## REMOVED

- **`TicketType.signal`** — replaced by `idea`/`knownGap`/
  `openQuestion` (see ADDED/MODIFIED above). No code references the bare
  `signal` value after this change; every pre-existing stored row is
  migrated at schema version 11.
- **`InboxCubit._extractKnownGapsSection`** and the markdown "## Known
  gaps" heading-scanning convention it implemented — superseded by
  first-class `knownGap` tickets. `aion-arch/ideas/
  sdd-workflow-in-ticket-system.md`'s Follow-up decisions had already
  flagged this file convention as "considered and rejected" in favor of
  the ticket-native design this change finally builds.

## Known gaps this does not resolve

- No lifecycle/resolution mechanism for a `knownGap`/`openQuestion`
  beyond plain `TicketStatus` transitions every ticket already has —
  what "resolved" means for one, and whether resolving it should do
  anything to its target ticket, is left for a future change.
- Bulk/automatic reclassification tooling for pre-existing `signal`
  (now `idea`) tickets does not exist — only the one-at-a-time manual
  `reclassifyIdea` action does. A project with many old `signal`
  tickets has no faster path than reclassifying each by hand.
- No generic, editable "Type" field exists for any other ticket-type
  pair — `reclassifyIdea` is narrowly scoped to `idea →
  knownGap|openQuestion` only.
