# Delta Spec: Reconciler applies hand-edited parentId/deletedAt changes

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's Git projection section` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. hand-edited deletedAt round-tripping through the serialized frontmatter, and the reconciler mechanism this delta introduces, are confirmed current.

Relative to `aion-arch/specs/tickets.md`'s current-state description of
`TicketMarkdownReconciler`/`TicketRepairService`.

## ADDED

- **`TicketParentTrashService`** (`data/services/
  ticket_parent_trash_service.dart`) — a new plain (non-`Cubit`) shared
  service holding parentId-reparent and trash/restore domain logic:
  `changeParent(Ticket, String? newParentId)` (cycle-prevention/type-
  compatibility validation, returning a `ParentChangeResult` —
  `ParentChangeSuccess`/`ParentChangeRejected`), `trash(String id)`,
  `restore(String id)` (both delegating to `TicketRepository`'s existing
  cascade-carrying methods, then firing the same git-projection +
  rollup-recompute side effects `TicketsCubit`/`TrashCubit` already
  fire), and `applyFromParsedFields(Ticket, Map<String, Object?>
  fields)` (the shared entry point `TicketMarkdownReconciler` and
  `TicketRepairService.reformat` both use). `TicketsCubit` and
  `TrashCubit` each construct their own instance, mirroring
  `TicketRollupRecomputer`'s existing per-cubit-construction pattern.
- **`TicketMarkdownReconciler` applies a hand-edited `parentId`.** When
  a reconciled file's frontmatter `parentId` differs from the ticket's
  current `parentId`, the reconciler now validates and applies it via
  `TicketParentTrashService.changeParent` — the identical cycle-
  prevention, always-root-type, Inbox-spawned-chat, and structural
  type-compatibility checks `TicketsCubit.updateTicketParent` already
  enforces for an in-app reparent. A valid change is persisted (and
  triggers the same rollup-recompute fire-and-forget `TicketsCubit`'s
  own reparent path already triggers); an invalid one is rejected and
  the field's old value is left in place, same as any other rejected
  frontmatter field.
- **`TicketMarkdownReconciler` applies a hand-edited `deletedAt`.** A
  reconciled file's frontmatter `deletedAt` transitioning from `null` to
  a timestamp trashes the ticket via `TicketParentTrashService.trash`
  (which delegates to `TicketRepository.trashTicket`'s existing
  descendant-cascade logic); transitioning from a timestamp to `null`
  restores it via `TicketParentTrashService.restore` (delegating to
  `TicketRepository.restoreTicket`'s existing ancestor/descendant-revival
  cascade). A changed-but-still-non-null timestamp (re-trashing an
  already-trashed ticket with a different stamp) has no corresponding
  domain operation and remains a no-op, matching every other
  unsupported frontmatter transition's existing treatment.
- **`needsRepair` on a rejected hand-edited `parentId`/`deletedAt`.**
  When either applied-field check above is rejected, the reconciled
  ticket's `syncStatus` becomes `TicketSyncStatus.needsRepair` instead
  of `synced` — surfaced through the existing sync-status badge and
  repair banner/actions (`sync_status_badge.dart`,
  `ticket_needs_repair_banner.dart`), the same UI already used for an
  `Unparseable` file. No new UI is added; this is a second trigger for
  an existing state.
- **`TicketRepairService.reformat` re-validates `parentId`/`deletedAt`
  before declaring success.** After lint-trimming and re-parsing,
  `reformat` now also calls `TicketParentTrashService
  .applyFromParsedFields` against the re-parsed fields; if that
  rejects a changed `parentId`/`deletedAt`, `reformat` returns `false`
  (leaving the ticket `needsRepair`) instead of unconditionally marking
  the ticket `synced` once the content merely re-parses. This closes a
  gap this change would otherwise introduce: prior to this change,
  `needsRepair` only ever meant `Unparseable` content, for which
  `reformat`'s old "does it re-parse" check was already sufficient;
  once a syntactically-valid-but-semantically-rejected `parentId`/
  `deletedAt` becomes a second `needsRepair` cause, that old check alone
  would incorrectly mark such a ticket `synced` without the file's value
  ever actually matching the database.

## MODIFIED

- **`TicketMarkdownReconciler`'s class-level "Known limitation"
  documentation** for `parentId` and `deletedAt` (previously: "does not
  apply a `parentId`/`deletedAt` change from a hand-edited file... left
  out rather than risk a corrupted parent graph / trash state") is
  replaced with documentation of the new applied behavior and its
  `needsRepair` rejection path, described above. The third "Known
  limitation" (estimateRollup/timeSpentRollup, structurally inert for
  `resource`/`page`) is unchanged.
- **`TicketsCubit.updateTicketParent`** keeps its exact existing
  external contract (same emitted states — `TicketDetailLoaded` on
  success, `TicketsError(reason: invalidParent)` followed by a re-
  emitted `TicketDetailLoaded` on rejection) but now delegates its
  validation-and-write step to `TicketParentTrashService.changeParent`
  instead of performing the checks and the
  `TicketRepository.updateTicketParent` call inline.
- **`TicketsCubit.trashTicket`** keeps its exact existing external
  contract (same `previousState`-based state selection between
  `TicketTrashed()` and a refreshed `TicketsLoaded(...)`) but now
  delegates the trash-and-side-effects step to
  `TicketParentTrashService.trash` instead of calling
  `TicketRepository.trashTicket` and `_trashGitSideEffects` directly.
- **`TrashCubit.restore`** keeps its exact existing external contract
  (reloads the trash list via `load()` on success, emits `TrashError` on
  an unexpected failure) but now delegates to
  `TicketParentTrashService.restore` instead of calling
  `TicketRepository.restoreTicket` and `_restoreGitSideEffects`
  directly.
