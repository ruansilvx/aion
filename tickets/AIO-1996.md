# Design: Show a last-updated timestamp on each ticket's detail screen

## 1. Overview

Two pieces:

1. A new, always-on "Updated {relative}" `Text` line in
   `TicketMetadataSection`, directly below the existing "Created
   {date}" line, formatted via the already-shipped
   `formatRelativeTime` (`lib/core/utils/relative_time_format.dart`).
2. A `Timer`-backed broadcast stream on `TicketsCubit`
   (`detailTick`) that `TicketDetailScreen` starts in `initState` and
   stops in `dispose`, so the label above rebuilds once a minute
   without needing a Cubit-state emission or a repository re-fetch.

No new files, no new widget classes, no new Cubit states, no schema
change — `Ticket.updatedAt` already exists and is already correctly
maintained by every write path (see `specs/spec.md`).

## 2. Why a side-channel stream, not a `TicketDetailLoaded` re-emit

The obvious-looking alternative — have the ticker call
`emit(TicketDetailLoaded(ticket))` every 60s so `BlocBuilder` picks up
the "fresh" state — was rejected:

- `TicketDetailLoaded` extends `Equatable`. Re-emitting the *same*
  `Ticket` (nothing about it changed — only wall-clock time passed)
  compares equal to the current state, and `Cubit.emit` is a no-op for
  an equal state — the rebuild the ticker exists to cause simply
  wouldn't happen.
- Even if `TicketDetailLoaded` carried a synthetic "last ticked at"
  field purely to defeat that equality check, every subscriber of
  `TicketsCubit`'s state stream would rebuild every 60s — including
  the entire `TicketMetadataSection` tree (every `SelectionMenu`,
  `InlineEditableField`, the SDD-stage/coding-execution sections) for
  a change that only one small `Text` node actually needs to reflect.
  That's a real cost on a screen already doing nontrivial work per
  build, for a purely cosmetic clock tick.

Precedent already exists in this exact file for the right shape: a
transient, non-`TicketsState` broadcast stream a single widget
subscribes to directly, bypassing `BlocBuilder` entirely —
`_codebaseAnalysisController` / `Stream<CodebaseAnalysisStatus> get
codebaseAnalysisStatus`, consumed by `CodebaseAnalysisBanner`. This
change adds a second instance of the same pattern rather than
inventing a new one.

## 3. `TicketsCubit` changes
(`aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart`)

New private state, alongside the existing
`_codebaseAnalysisController`/`_workflowStatusChangesSubscription`
fields:

```dart
/// Fires [detailTick] every 60 seconds while a [TicketDetailScreen] is
/// mounted — see [startDetailTicker]/[stopDetailTicker]. `null`
/// whenever no detail screen currently has it running. Cancelled in
/// [close].
Timer? _detailTickTimer;

/// Broadcasts an empty pulse once a minute while [_detailTickTimer] is
/// running, purely so [TicketDetailScreen]'s "Updated {relative}"
/// label can rebuild off elapsed wall-clock time without a
/// [TicketsState] emission — see design.md §2 for why a state
/// re-emit isn't used. Not tied to [state] the same way
/// `codebaseAnalysisStatus` isn't.
final _detailTickController = StreamController<void>.broadcast();

/// See [_detailTickController]'s dartdoc.
Stream<void> get detailTick => _detailTickController.stream;
```

Two new public methods, placed near the other small lifecycle-style
methods:

```dart
/// Starts (or restarts) the 60-second [detailTick] pulse. Called by
/// [TicketDetailScreen.initState] — idempotent, so re-navigating
/// between two tickets (a fresh screen instance each time) safely
/// cancels any previous timer before starting its own.
void startDetailTicker() {
  _detailTickTimer?.cancel();
  _detailTickTimer = Timer.periodic(const Duration(seconds: 60), (_) {
    if (!isClosed) _detailTickController.add(null);
  });
}

/// Stops the [detailTick] pulse started by [startDetailTicker]. Called
/// by [TicketDetailScreen.dispose] so the timer doesn't keep firing
/// into an empty stream once no detail screen is mounted to consume
/// it — [TicketsCubit] is a single app-wide instance (see
/// `aion-arch/ideas/live-refresh-open-ticket-detail-screen.md`), so
/// nothing else would stop it otherwise.
void stopDetailTicker() {
  _detailTickTimer?.cancel();
  _detailTickTimer = null;
}
```

`close()` gains the timer cancel + controller close alongside the
existing cleanup:

```dart
@override
Future<void> close() {
  _codebaseAnalysisController.close();
  _detailTickTimer?.cancel();
  unawaited(_detailTickController.close());
  unawaited(_workflowStatusChangesSubscription?.cancel());
  unawaited(_skillAttachmentChangesSubscription?.cancel());
  return super.close();
}
```

60 seconds is chosen to match `formatRelativeTime`'s own granularity —
its `<60 minutes` branch changes value once per whole minute
(`elapsed.inMinutes`), so ticking faster than that buys nothing.

No unit test is added for `startDetailTicker`/`stopDetailTicker`
themselves — per `project.md`'s "trivial pass-throughs may be skipped"
allowance, these two methods are Timer plumbing with no branching
logic; `bloc_test` also has no good way to assert on a live
`Timer.periodic` without `fake_async`, which this codebase doesn't
currently depend on. `TicketDetailScreen`'s widget test (§5 below)
exercises the real call sites.

## 4. `TicketMetadataSection` changes
(`aion/lib/features/tickets/presentation/widgets/ticket_metadata_section.dart`)

Immediately below the existing "Created" `Text` (the last child before
the section's closing `Container(color: c.border, height: 1)` divider
row), add:

```dart
const SizedBox(height: AionSpacing.sp4),
StreamBuilder<void>(
  stream: context.read<TicketsCubit>().detailTick,
  builder: (context, _) => Text(
    context.l10n.ticketDetailLastUpdated(
      formatRelativeTime(ticket.updatedAt),
    ),
    style: AionText.time.copyWith(color: c.textMuted),
  ),
),
```

This is an inline widget expression (`StreamBuilder<void>(...)`), not
a widget-returning helper function — it doesn't trip the
`Widget _xyz(` grep check, and matches how the adjacent "Created" line
is already written directly inline rather than extracted into its own
class (this is the smallest form the composition convention allows for
a single-call-site, non-reused piece).

`StreamBuilder`'s `builder` re-runs on every `detailTick` pulse *and*
on `TicketMetadataSection`'s own normal rebuilds (e.g. any other field
edit) — both cases correctly recompute `formatRelativeTime(
ticket.updatedAt)` from whatever `ticket` is current in that build, so
a write-triggered refresh (already covered by
`_refreshDetailIfOpenAndAffected`, see
`aion-arch/ideas/live-refresh-open-ticket-detail-screen.md`) and the
new clock-only refresh both keep the label correct without the two
mechanisms needing to know about each other.

No gating on `ticket.updatedAt == ticket.createdAt` — the line always
renders, mirroring "Created"'s own unconditional treatment (see
proposal.md's Design decisions §3).

`context.read<TicketsCubit>()` inside `build` (not `context.watch`) is
correct here and matches this file's existing style — the surrounding
`BlocBuilder<TicketsCubit, TicketsState>` already rebuilds this whole
subtree on relevant state changes; only the `Stream` subscription
itself needs to be read once per build to hand to `StreamBuilder`, not
listened to via `InheritedWidget` rebuild propagation.

## 5. `TicketDetailScreen` changes
(`aion/lib/features/tickets/presentation/screens/ticket_detail_screen.dart`)

`initState` gains one line, alongside the existing
`getTicketById`/`loadComments`/`loadMessages` calls:

```dart
@override
void initState() {
  super.initState();
  context.read<TicketsCubit>().getTicketById(widget.ticketId);
  context.read<CommentsCubit>().loadComments(widget.ticketId);
  context.read<ChatCubit>().loadMessages(widget.ticketId);
  context.read<TicketsCubit>().startDetailTicker();
  unawaited(
    context
        .read<AutomationSettingsRepository>()
        .getConfidence(AutomationContext.sddStage)
        .then((confidence) {
          if (mounted) setState(() => _automationConfidence = confidence);
        }),
  );
}
```

`dispose` gains one line, before `super.dispose()` — same pattern as
the existing `ActiveTicketViewRegistry` unregister above it:

```dart
@override
void dispose() {
  final registeredId = _registeredTicketId;
  if (registeredId != null) {
    final registry = _tryReadRegistry(context);
    if (registry?.activeTicketId.value == registeredId) {
      registry!.activeTicketId.value = null;
    }
  }
  context.read<TicketsCubit>().stopDetailTicker();
  _commentController.dispose();
  super.dispose();
}
```

## 7. Test coverage

- **`test/core/utils/relative_time_format_test.dart`** — add a new
  `group('formatRelativeTime', ...)` alongside the existing
  `formatTrashedAge` group, covering: `< 60s` → `'just now'`,
  `< 60min` → `'{n}m ago'`, `< 24h` → `'{n}h ago'`, `< 7d` →
  `'{n}d ago'`, `< 30d` → `'{n}w ago'`, `30d+` → `'{n}mo ago'`, and the
  `now` defaulting-to-`DateTime.now()` case — same shape as the
  existing `formatTrashedAge` group, just for the sibling function.
  (Pre-existing gap: `formatRelativeTime` shipped with
  `InboxHistoryItem` without its own tests; this change makes it a
  second, more prominent call site, so it's brought up to the same bar
  as `formatTrashedAge` rather than left as the one untested function
  in that file.)
- **`test/features/tickets/presentation/cubit/tickets_cubit_test.dart`**
  — add a `group('detailTick', ...)` with `bloc_test`/plain
  `async`-based cases: `startDetailTicker` followed by
  `stopDetailTicker` does not throw and leaves no pending timer (assert
  via `Timer` absence is impractical without `fake_async` — instead
  assert the simple contract: calling `stopDetailTicker` with no prior
  `startDetailTicker` is a safe no-op, and calling `startDetailTicker`
  twice in a row doesn't throw or leak — i.e. cancel-before-replace
  works). Full elapsed-time tick verification is left to the widget
  test below rather than mocked here, since asserting a real 60-second
  `Timer.periodic` in a unit test would either be slow or require
  `fake_async`, which this codebase doesn't currently pull in for one
  timer.
- **`test/features/tickets/presentation/screens/ticket_detail_screen_test.dart`**
  (or wherever this screen's existing widget tests live — extend, not
  create, if a file already exists) — add a case asserting the
  "Updated {relative}" text renders once a `TicketDetailLoaded` state
  is showing, using `formatRelativeTime`'s own `now` parameter
  indirectly via a fixed `ticket.updatedAt` and checking the rendered
  string matches `formatRelativeTime(ticket.updatedAt)` computed the
  same way the widget does (real `DateTime.now()`, tolerant match —
  same non-deterministic-clock caveat every other "now"-based render
  test in this codebase already accepts).
