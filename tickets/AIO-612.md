# Spec Delta: Consistent max-width, centered content layout

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's Design System section` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. AionContentWidth's form(520)/reading(840) scale is confirmed present verbatim.

## ADDED

- **`ContentMaxWidth` widget** (`design_system/atoms/`): a shared
  layout wrapper that constrains its child to a maximum width
  (`AionContentWidth.form` = 520px or `AionContentWidth.reading` =
  840px, selected via a `ContentWidthVariant` enum) and centers it
  horizontally when the available width exceeds that maximum. Below
  the maximum width, it has no visual effect — the child renders at
  its natural constrained width, identical to today.
- **`AionContentWidth` token** (`design_system/tokens/`): the two
  max-width values (`form`, `reading`) as named constants, the single
  source of truth for both `ContentMaxWidth` and any future caller
  needing the same values.
- **Max-width, centered content on wide viewports** for: ticket
  detail body and pinned comment composer; page detail content
  (Notion-style page reading/editing surface); the documentation
  tree/search list; the ticket list's list-mode body; and the
  `NewProjectScreen`, `CreateTicketScreen`, `PageCreateScreen` forms
  (scroll body + pinned submit button). On viewports narrower than
  the applicable max width, behavior and appearance are unchanged
  from today.

## MODIFIED

- **`NewProjectScreen`**: its existing ad hoc
  `ConstrainedBox(maxWidth: 520)` is replaced with
  `ContentMaxWidth(variant: ContentWidthVariant.form)`. Behaviorally
  identical — this is a de-duplication onto the new shared widget,
  not a visual change.
- **`design_system/design_system.dart` barrel**: exports the two new
  files (`tokens/aion_content_width.dart`,
  `atoms/content_max_width.dart`).

## REMOVED

None.

## Explicitly unchanged (exemptions, stated for completeness)

- **Kanban board** (`tickets_board_view.dart` / board-mode branch of
  `tickets_list_screen.dart`): continues to render at full available
  width. Not in scope — its multiple columns need the space to stay
  usable on wide screens.
- **Floating/viewport-anchored overlays** on the ticket list screen
  (FAB, multi-select action bar, board "load more" button): continue
  to anchor against the full viewport via `Positioned` on the root
  `Stack`, not against the new constrained content column. See
  design.md's "Overlay anchoring" section.
- **Screen headers** (`AppHeader`, `_PageDetailHeader`,
  `documentation_screen.dart`'s `_Header`) and filter/search rows:
  continue to render full-width on every in-scope screen. Only body/
  form content gets the max-width treatment.
