# Ticket Deletion

# Proposal: Ticket Deletion

## What

Add a complete, confirmation-gated path to delete a single ticket:
`TicketRepository.deleteTicket(String id)` down through the Drift DAOs,
`TicketsCubit.deleteTicket`, and a UI entry point on `TicketDetailScreen`
via its header's `⋮` overflow trigger (currently rendered but inert).

Deleting a ticket cascades to its comments and any `ticket_links` rows
referencing it (both are dependent data with no independent value once
the ticket is gone). Deletion is **blocked** — with a clear, actionable
error — if the ticket has structural children (other tickets whose
`parentId` points at it). The user must reparent or delete those children
first. This is the only remaining item in `aion-arch/specs/tickets.md`'s
Known Gaps list for the ticket entity itself (see that file's "No
deletion path exists for tickets" bullet).

## Why

Ticket create/read/update already shipped in the v1 slice — delete is the
one missing piece of core CRUD on the app's central entity. Without it,
a wrong or test ticket created via `CreateTicketScreen` has no way to be
removed short of manually editing the SQLite file.

## Scope

**In scope:**
- `TicketRepository.deleteTicket(String id)` — cascades comments +
  ticket_links, blocks (throws) if structural children exist.
- Confirmation dialog before deleting (irreversible, destructive action).
- Delete entry point on `TicketDetailScreen` only, via the existing `⋮`
  overflow trigger.
- Clear, count-aware error messaging when deletion is blocked by children.

**Out of scope (explicitly deferred):**
- Bulk delete / delete from the list or board views.
- Undo, trash, or soft-delete — deletion is immediate and permanent once
  confirmed.
- Cascading delete of structural children — blocking is the chosen
  behavior; cascade-to-children can be revisited later as its own change
  if it turns out to be wanted.
- Any change to `ticket_links` UI (still not built at all — separate
  known gap).

## Known gaps this closes

From `aion-arch/specs/tickets.md`:
> No deletion path exists for tickets: no `TicketRepository` method, DAO
> query, cubit method, or UI affordance.

`parentId` immutability and board-only `status` editing (the other two
clauses in that same bullet) are unaffected and remain as documented.
