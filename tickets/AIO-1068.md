# Delta Spec: Kanban Board View

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (36/38 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

> Legend: ADDED = new behavior, MODIFIED = changed behavior, REMOVED = deleted behavior.
> Baseline: current state as documented in `openspec/specs/tickets.md`.

---

## Domain

### MODIFIED — `Ticket` entity

Adds `copyWith({TicketStatus? status, DateTime? updatedAt})`. Returns a new
`Ticket` with only those two fields optionally replaced; all other fields
copied unchanged. No other fields are parameterized — this is not a
general-purpose `copyWith`.

### MODIFIED — `TicketRepository` interface

Adds `Future<void> updateTicketStatus(String id, TicketStatus status)` —
updates only the `status` (and `updatedAt`) of the ticket with id `id`.
Does not touch `title`, `description`, `priority`, `type`, or `parentId`.
Throws if `id` does not exist.

---

## Data

### MODIFIED — `TicketDao`

Adds `Future<void> updateStatus(String id, TicketsTableCompanion companion)`
— issues an `UPDATE tickets SET ... WHERE id = ?` using the given
companion (built by the repository, containing only `status` and
`updated_at`). No new table, no schema-version bump — `status` and
`updated_at` columns already exist on `TicketsTable`.

### MODIFIED — `DriftTicketRepository`

Implements `updateTicketStatus`: builds a `TicketsTableCompanion` with
`status: Value(status.name)` and `updatedAt: Value(<now, Unix ms>)`, calls
`TicketDao.updateStatus`. No enum-fallback parsing needed (write-side, not
read-side).

## Presentation

### ADDED — `TicketStatusUpdating` state

```
TicketStatusUpdating extends TicketsState { final List<Ticket> tickets; }
```
Carries the ticket list with the in-flight ticket's `status` already
replaced locally (optimistic) — the moved card renders in its new column
immediately, before the repository round trip completes.

### ADDED — `TicketStatusUpdated` state

```
TicketStatusUpdated extends TicketsState { final List<Ticket> tickets; }
```
Carries the list re-fetched from `TicketRepository.getAllTickets()` after
a successful `updateTicketStatus` call — the source-of-truth list
supersedes the optimistic copy.

### ADDED — `TicketsCubit.updateTicketStatus(String id, TicketStatus status)`

Emits `TicketStatusUpdating` (optimistic list) immediately, then calls
`TicketRepository.updateTicketStatus`. On success, re-fetches all tickets
and emits `TicketStatusUpdated`. On failure, emits `TicketsError` (no
per-card rollback UI — same error-handling shape as every other mutation
in this cubit).

### MODIFIED — `TicketsListScreen`

- Adds a private `_TicketViewMode { list, board }` enum and local state,
  defaulting to `list`, not persisted across app restarts.
- Header gains a two-icon view-mode toggle (list / board, `PhosphorIcons`
  glyphs) positioned left of the existing user avatar. Each icon carries
  `Semantics(button: true, label: 'Switch to list view' | 'Switch to
  board view')`.
- The existing `BlocBuilder<TicketsCubit, TicketsState>` switch is
  extended to also match `TicketStatusUpdating`/`TicketStatusUpdated`
  (rendering the same `ListView.separated` as `TicketsLoaded` when in
  List mode).
- When `_viewMode == board`: the resolved ticket list is filtered to
  `{TicketType.task, TicketType.story}` and rendered via
  `TicketBoardView` instead of `ListView.separated`. Same underlying cubit
  state, same `loadTickets()` call in `initState` — no duplicate data
  fetch.
- `StatusIndicator`'s private status-label switch is extracted to a
  top-level `ticketStatusLabel(TicketStatus)` function in the same file,
  reused by `BoardColumn`'s header.

### ADDED — `TicketBoardView` (`presentation/screens/tickets_board_view.dart`)

Takes an already type-filtered `List<Ticket>`. Groups tickets by `status`.
Renders a horizontally-scrolling row of one `BoardColumn` per
`TicketStatus.values` entry, in declared enum order — all 6 columns always
render, including when their group is empty. No configurable column order,
no persisted board-layout config.

### ADDED — `BoardColumn`

Renders a status label + ticket count header, and a `DragTarget<Ticket>`
wrapping a vertical list of `TicketBoardCard`s for that status. Accepting
a drop calls `TicketsCubit.updateTicketStatus(droppedTicket.id, column
status)` — a no-op (via an early-return status-equality check) when
dropped back onto its origin column. Tints its background while a
compatible drag hovers over it.

### ADDED — `TicketBoardCard`

Renders a floating card (ticket-id badge, title, `PriorityBadge`,
`TypeChip` — reusing the existing badge/chip widgets from
`tickets_list_screen.dart`). Tapping navigates to `/tickets/:id`, same as
`TicketListTile`. Wrapped in `Draggable<Ticket>` on desktop/web or
`LongPressDraggable<Ticket>` on mobile (branched via
`core/utils/platform_utils.dart`'s `isMobile`), carrying the `Ticket` as
drag data. Carries a trailing `MoveToStatusMenu` icon button as the
non-drag path to the same mutation.

### ADDED — `MoveToStatusMenu`

An icon-button-triggered overlay (same `Overlay`/`OverlayEntry`/
`CompositedTransformFollower` mechanics as `AppDropdown`) listing the 5
statuses other than the card's current one. Selecting an item calls the
same `TicketsCubit.updateTicketStatus` the drag path calls — the
keyboard/screen-reader-accessible equivalent of the drag interaction,
required so board status changes are not drag-only.

## Accessibility

### ADDED — Board status-change accessibility requirement

Every board status change reachable via drag MUST also be reachable via
`MoveToStatusMenu` (keyboard + screen reader). Both paths call the
identical `TicketsCubit.updateTicketStatus` method — enforced by
construction, not by parallel/duplicated logic.

### ADDED — Board card focus order

`TicketBoardCard` and its `MoveToStatusMenu` icon button are separate,
sequential Tab stops. Enter/Space on the card navigates to ticket detail
(same as `TicketListTile`); Enter/Space on the menu button opens the
status picker. The two actions are never overloaded onto the same
focusable element.

## Known gaps (carried forward, updated)

- `openspec/specs/tickets.md`'s "No ticket editing or deletion" gap is now
  partially closed: status is editable via the board (and, by extension,
  via `TicketRepository.updateTicketStatus` for any future caller). Title,
  description, priority, type, and parent remain non-editable.
- No configurable board column order/visibility.
- No board support for ticket types other than task/story.
- No persistence of the last-used List/Board view choice.
