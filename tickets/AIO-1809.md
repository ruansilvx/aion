- [x] **T14** — On a real desktop build (per `project.md`'s Testing
  section — automated tests won't catch overlay/async-callback issues,
  and this flow is entirely desktop/git-dependent): exercise curated
  mode end-to-end against a disposable local git remote (a scratch repo,
  not this project's own `aion`/`aion-arch` remotes) — build a release
  ticket via the existing Release Planning chat, run Prepare Release,
  edit the draft, confirm, and verify the tag/commit/`CHANGELOG.md`
  landed correctly, including the T15–T18 scope strip, tag pill, header
  badge, and tag/branch confirmation dialog rendering with real data.
  Then exercise auto mode the same way against a second disposable
  scratch project with no pre-existing `release` ticket. Close out any
  scratch repos/remotes created for this verification afterward.

  **Completed across two sessions** — see
  `aion-arch/changes/release-preparation-and-tagging/T14-manual-pass-notes.md`
  for the full account (kept for history rather than deleted, since it
  documents two real bugs found this way). Session 1 reached
  `ReleaseSummarySection` (via List view — the Kanban board excludes
  `release` tickets by design, not a bug) and verified it
  pixel-for-pixel against design.md §1, then hit two real bugs: T20
  (fixed) and a second, pre-existing, out-of-scope routing defect
  (`TicketDetailScreen` never remounting between two ticket ids —
  flagged separately via `spawn_task`, not fixed here), plus a hard
  blocker on this environment's Claude Agent SDK OAuth session having
  expired. Session 2 resumed after the user re-authenticated it:
  curated mode was exercised fully — `prepareReleaseDraft`'s real model
  call, `ReleaseDraftScreen`'s Scope strip/tag pill/header badge
  (T16/T17), the Confirm & Tag dialog's literal TAG/BRANCH block (T18),
  `confirmRelease`'s full git mechanics (commit, tag, push, version
  bump, `CHANGELOG.md`) against the disposable remote — verified via
  `git log`/`git tag`/`git ls-remote --tags` — and the success toast.
  That surfaced T21 (fixed). Auto mode was then exercised the same way
  against the second scratch project: Inbox's "Cut a release" card
  correctly auto-created and auto-linked the release ticket, and the
  rest of the flow (draft, confirm, tag, push, status flip) matched
  curated mode exactly. Both scratch projects were removed from Aion's
  Hub (non-destructive — files stayed on disk) and both scratch git
  repos/remotes were then deleted from disk, per this task's own
  instruction.

- [x] **T22** — `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart`:
  fix the quality observation noted at the end of T14's manual pass —
  `prepareReleaseDraft`'s prompt never told the model the project's
  *current* version, so every drafted suggestion came back as a literal
  `x.y.z` placeholder rather than a real next version, even though
  `ProjectStackDetector.detectVersionFile` was already being called
  (just after the model ran, to populate `ReleaseDraft
  .detectedVersionFile` — never before, to inform the prompt). Fixed by
  detecting once, up front, and folding `detected.currentVersion` (when
  non-null) into the prompt's version-suggestion instruction; the same
  detection result now also populates `detectedVersionFile` directly
  (no second detection call), so the draft's suggestion and the
  version-file it would bump from can never disagree with each other.
  Dartdoc updated. `flutter analyze` clean,
  `test/features/tickets/cubit` passes 491/491.

  **Verified live**, against a third disposable scratch project
  (`pubspec.yaml` pinned to `3.4.5`): the model's response correctly
  read "the current version is `3.4.5`" back from the prompt and
  suggested a real, correct patch bump (`3.4.6`) instead of the old
  literal `x.y.z` placeholder — confirms the fix. That same live pass
  also surfaced an unrelated, out-of-scope discovery: `AgentRequest`'s
  `toolsEnabled: false` (the default `prepareReleaseDraft` uses, and
  every other text-only call site in the app) doesn't appear to
  actually suppress the `claudeAgentSdk` provider's file/git tool
  access — the model's own narration showed it exploring the real
  filesystem (reproduced twice, from two different working
  directories, including once reading real private symbols out of
  the actual `aion` source checkout mid-draft). Flagged separately via
  `spawn_task` for its own investigation — a provider/SDK-client
  concern well outside this change's scope, not fixed here.
