# 4. `InboxCubit` / `InboxState`

- [x] 4.1 Create `aion/lib/features/tickets/presentation/cubit/inbox_state.dart` —
      `InboxInitial`, `InboxLoading`, `InboxLoaded(List<Ticket>
      history)`, `InboxLaunching(InboxPurpose purpose)`,
      `InboxError(String message)`. Full class + field dartdocs per
      design.md §5.
- [x] 4.2 Create `aion/lib/features/tickets/presentation/cubit/inbox_cubit.dart` —
      constructed with `TicketRepository`, `CommentRepository`,
      `TicketLinkRepository`, `AgentModelClient`,
      `ModelRoutingRepository`. Implements:
      - `load()` — `getTicketsByParent(null, types: [TicketType.chat])`,
        filtered to `inboxPurpose != null`, sorted `createdAt`
        descending, emits `InboxLoaded`.
      - `startBrainDump(String rawText)` — per design.md §5.1: creates
        the parentless `chat` ticket (`inboxPurpose: brainDump`), posts
        the system prompt comment, runs the opening turn via
        `ChatCubit.runChatTurn` (`toolsEnabled: false`, model from
        `ModelRoutingRepository.getModelForPhase(ModelPhase.frontier)`),
        parses the reply into one or more `signal` tickets with
        `suggestedType` set. Returns the created chat ticket's id.
      - `startWhatNextGuidance()` — per design.md §5.2: assembles the
        three-tier context (in-flight SDD-stage tickets, Documentation
        Pages' "Known gaps" sections, open `signal` tickets), runs the
        opening turn (`toolsEnabled: false`, `frontier`), no reply
        parsing.
      - `startReleasePlanning()` — per design.md §5.3: assembles
        read-only Epic/Story/Task/Bug context, runs the opening turn
        (`toolsEnabled: false`, `frontier`). Also exposes
        `handleReleasePlanningReply(String chatTicketId, String
        aiCommentText)` — called after every AI comment persists in a
        release-planning chat (opening and human-follow-up alike) to
        check for the terminal `RELEASE PLAN: DONE` marker and, if
        present, materialize the `release` ticket + `relatesTo` links.
      - `startQa(String initialQuestion)` — per design.md §3/§5: creates
        the chat (`inboxPurpose: qa`), runs the one-shot
        worktree-isolated opening turn (mirrors
        `TicketsCubit._runFullSummarization`'s exact worktree-create/
        run/remove-in-`finally` shape, `toolsEnabled: true`, model from
        `ModelRoutingRepository.getModelForPhase(ModelPhase.capable)`).
        Every later reply in this chat goes through the ordinary
        `ChatCubit.sendMessage`, not this method.
      Full class + method dartdocs per project.md's density
      conventions (matching `TicketsCubit`'s own documentation depth).
- [x] 4.3 Create `test/features/tickets/presentation/cubit/inbox_cubit_test.dart`
      (`bloc_test` + mocktail) — `load()` returns only
      `inboxPurpose != null` chats, sorted correctly; each `start*`
      method creates the expected ticket with the correct
      `inboxPurpose`/model phase/`toolsEnabled`; brain-dump parsing
      produces the expected `signal` tickets with correct
      `suggestedType` from a sample multi-block reply; release-planning
      parsing creates the `release` ticket + links only on seeing
      `RELEASE PLAN: DONE`, and is a no-op on an ordinary
      mid-conversation reply that hasn't reached it yet; Q&A's opening
      turn creates and always removes its worktree (including on a
      thrown error, mirroring the existing `_runFullSummarization`
      failure-path test coverage).
