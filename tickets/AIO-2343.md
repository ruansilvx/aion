# Spec Delta: Ticket Search & Filters

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's TicketListFilters entity and Screens' filter/search UI` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. TicketsCubit.searchTickets and the filter popover mechanism this delta introduces are confirmed current; later tickets (multi-select filters, sort control) extended this foundation additively.

## ADDED

- **`AppDatabase` schema version 2.** New SQL objects, created on fresh
  install and backfilled/added on upgrade from version 1: indexes on
  `tickets.status`, `tickets.type`, `tickets.priority`; an external-content
  FTS5 virtual table `tickets_fts` (indexing `title`/`description` without
  duplicating their storage) kept in sync via `AFTER INSERT`/`UPDATE`/
  `DELETE` triggers on `tickets`.

- **`TicketRepository.searchTickets`** (and its `DriftTicketRepository`
  implementation, backed by a new `TicketDao.searchTickets`) — returns
  tickets matching every non-null filter among `query` (full-text match
  against title/description, relevance-ranked via `bm25`), `status`,
  `type`, `priority` (exact match, ANDed together). All parameters
  omitted/null returns every ticket ordered by `created_at desc`
  (identical to today's `getAllTickets`).

- **`TicketsCubit.searchTickets`** — the Cubit-layer entry point calling
  the above. Emits `TicketsLoading` only when no ticket list is currently
  visible; otherwise keeps the current list on screen until the new
  results replace it. Emits `TicketsLoaded`/`TicketsError` exactly like
  the method it replaces (see MODIFIED).

- **A working search box and filter row on `TicketsListScreen`.** The
  search field (already visually present, previously non-functional) now
  filters as the user types (debounced 250ms — the exact value specified
  by the Claude Design export approved via `/design-sync`, superseding
  this change's own `~300ms` architecture-draft placeholder). Three new
  dropdown controls (status/type/priority, built from the existing
  `AppDropdown` primitive) filter the list; each includes an "All ___"
  option that clears that filter, and a non-default selection renders a
  tinted-fill/leading-dot "active" treatment. All active filters combine
  (ANDed). Result-set changes cross-fade via a 120ms `AnimatedSwitcher`
  rather than swapping instantly.

- **A distinct "no results" empty state.** When a search/filter is active
  and matches zero tickets, the list shows a centered motif icon plus a
  primary line (`ticketsListNoResultsState`, "No tickets match your
  search") and a secondary hint line (`ticketsListNoResultsHint`, "Try a
  different term, or reset a filter to its \"All\" option.") instead of
  the existing plain "No tickets yet" text — which now means specifically
  "there are zero tickets in the workspace," not "zero tickets match the
  current filter."

- **Two small, backward-compatible additions to shared primitives**,
  needed to build the approved design without duplicating their chrome:
  `AppTextField` gains an optional `prefixIcon` (passed straight to
  `InputDecoration.prefixIcon`); `AppDropdown` gains an optional
  `isActive` flag (tinted fill/border/text/leading dot when `true`, used
  by the filter row) and an optional `semanticsLabel` (announced by
  `Semantics` without rendering a visible caption — the filter row omits
  visible captions by design, so this is what keeps each dropdown
  announcing "Status"/"Type"/"Priority" to assistive technology). Both
  default to their previous behavior, so every existing call site
  (`CreateTicketScreen`'s type/priority pickers, etc.) is unaffected.

- New localization keys: `ticketsListFilterStatusLabel`,
  `ticketsListFilterTypeLabel`, `ticketsListFilterPriorityLabel` (used
  only as the three filter dropdowns' `semanticsLabel`, not rendered
  visibly), `ticketsListFilterAllStatuses`, `ticketsListFilterAllTypes`,
  `ticketsListFilterAllPriorities`, `ticketsListNoResultsState`,
  `ticketsListNoResultsHint`.

## MODIFIED

- **`TicketsListScreen`'s search box** — previously static UI chrome
  (icon + hint text, no `TextField`, no state). Now a functioning
  `AppTextField` wired to `TicketsCubit.searchTickets`.

- **`aion-arch/specs/tickets.md`'s "Known gaps" bullet** — "No search,
  filtering, or sorting on the ticket list (the board's type-filter to
  task/story is fixed, not a user-facing filter control)" is narrowed by
  this change. On `/archive`, replace it with two bullets reflecting what
  remains open:
  - "No user-facing sort control on the ticket list — results are
    ordered by relevance (`bm25`) when a search query is active, or by
    creation date descending otherwise; there is no way to sort by, e.g.,
    priority."
  - "`TicketsCubit.getValidParentCandidates` and `TicketParentPicker`
    (the reparent picker on `TicketDetailScreen`) still load every
    ticket into memory and filter/search client-side — self/descendant
    exclusion via an in-memory graph walk, text matching via Dart
    `.contains()` — unlike the main ticket list's DB-level search added
    by `ticket-search-filters`. Doesn't scale the same way; would need a
    `WITH RECURSIVE` descendant-exclusion query plus an async/debounced
    rework of the picker's overlay."
  - "The ticket list's status/type/priority filters are single-select
    only (each is one `AppDropdown<T>`, which has no multi-select
    variant in this codebase) — a user can filter to `backlog` or `todo`,
    not `backlog` OR `todo` in one dimension. Flagged during
    `/design-brief ticket-search-filters` (2026-07-15); not fixed here
    since it would mean designing and building a new multi-select
    primitive, out of proportion with the rest of this change."
  - "`TicketRepository.searchTickets`/`TicketDao.searchTickets` return
    every matching row with no `LIMIT`/pagination — an unfiltered or
    loosely-filtered search on a large ticket table fetches and holds
    the entire result set in memory (and, on web, marshals it across the
    drift WASM worker boundary) even though `TicketsListScreen`'s
    `ListView.separated` only ever builds the visible rows. Flagged
    during `/design-brief ticket-search-filters` (2026-07-15) as an
    oversight in a change whose whole premise was 'expect huge ticket
    volume' — not fixed here since the design brief had already been
    sent to Claude Design by the time it was caught; fixing it means a
    result cap on both `TicketDao.searchTickets` query paths plus a
    'showing the first N results' UI affordance, which needs its own
    design pass."

## REMOVED

- **`TicketsCubit.loadTickets()`.** Its only two call sites
  (`TicketsListScreen.initState`, the error-state Retry button) both move
  to `TicketsCubit.searchTickets()` called with no arguments, which
  produces an identical result (every ticket, `created_at desc`) when no
  filter is active. `TicketRepository.getAllTickets()` itself is **not**
  removed — see Explicitly unchanged below.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **`TicketRepository.getAllTickets()` / `TicketDao.getAllTickets()`.**
  Still present, still used by `TicketsCubit.getValidParentCandidates`.
  Not touched by this change.
- **`TicketsCubit.getValidParentCandidates` and `TicketParentPicker`.**
  Unchanged — still in-memory, still fetch-once-filter-locally. See
  MODIFIED above for the known-gap bullet documenting this explicitly.
- **`TicketBoardView`.** Still receives a pre-filtered (task/story-only)
  list from `_buildTicketsBody`; the new type filter is applied upstream
  of that restriction, not inside `TicketBoardView` itself. No file in
  `tickets_board_view.dart` changes.
- **`Ticket.embedding` / semantic similarity search.** Untouched —
  separate, still-unbuilt feature (`project.md`'s Storage Model
  foundational decision).
- **No new `TicketsState` subclass, no new fields on `TicketsLoaded`.**
  Active filter values are widget-local state on `TicketsListScreen`, not
  Cubit state.
