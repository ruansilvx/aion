# **T13** — Modify `lib/features/tickets/presentation/cubit/

tickets_cubit.dart`:
- Add two optional constructor dependencies: `PageWikilinkRepository?
pageWikilinkRepository` and `ActiveTicketViewRegistry?
activeTicketViewRegistry` (the latter is the *existing* registry
instance `WorkspaceShell` already constructs for
`TicketMarkdownWatcherService`/`TicketRepairCubit` — not a new one),
both stored as private final fields, same optionality pattern as
`_embeddingProvider`/`_gitProjector`.
- Add a private `String? _resolveWikilinkTarget(String target,
List<Ticket> candidates)`: an exact `Ticket.ticketId` match when
`WikilinkExtractor.looksLikeTicketId(target)`, otherwise a
case-insensitive title match (first `createdAt`-ascending match on
a duplicate title); `null` if nothing matches.
- In `updateTicket`, after the existing embedding-regen/estimate-
suggester trigger block, add the fire-and-forget
`_reindexAndCascadeWikilinks` call (gated on
`pageWikilinkRepository != null && ticket.type ==
TicketType.page`), reusing whatever value `updateTicket` already
computes for "did title/description change" rather than performing
a second lookup.
- Add private `Future<void> _reindexAndCascadeWikilinks({required
Ticket oldTicket, required Ticket newTicket})` per design.md's
pseudocode: fetch candidates via
`_repository.getAllTicketsByType([TicketType.page,
TicketType.resource])` (widened), parse
`WikilinkExtractor.extractReferences(newTicket.description ?? '')`,
resolve each match's `target` via `_resolveWikilinkTarget`, persist
the resolved id set via `pageWikilinkRepository!
.replaceOutgoingLinks`; when `oldTicket.title != newTicket.title`,
fetch `pageWikilinkRepository!.getIncomingLinks(newTicket.id)` and
call the new `_rewriteReferrerOrDefer` (below) for each referrer.
Wrapped in try/catch that swallows failures (matching embedding
regen's existing non-blocking tolerance, logged rather than
silently opaque) — dartdoc must state this explicitly.
- Add private `Future<void> _rewriteReferrerOrDefer({required String
referrerId, required String oldTitle, required String newTitle})`
per design.md's pseudocode: fetch the referrer, compute
`WikilinkExtractor.rewriteTitle(referrer.description ?? '',
oldTitle, newTitle)`, no-op if unchanged (no title-anchored
occurrence found); if `activeTicketViewRegistry?.activeTicketId ==
referrerId`, register a one-shot listener that retries this same
method once `activeTicketId` changes away from `referrerId` (mirrors
`TicketMarkdownReconciler`'s existing "re-attempt once the active id
changes" pattern) instead of rewriting immediately; otherwise call
`updateTicket(referrer.copyWith(description: rewritten))` unawaited
(recurses through `updateTicket` itself — inherits file
write-through, embedding regen, and its own outgoing-link reindex;
cannot recurse further since this call never changes a title).
- Update `loadDocumentRelations`'s backlinks computation to merge
`TicketLinkRepository`-derived rows (mapped to
`BacklinkRef(origin: explicitLink)`) with, when
`pageWikilinkRepository != null` **and the gated ticket is a `page`
or `resource`** (widened), `pageWikilinkRepository!
.getIncomingLinks`-derived rows (each `sourcePageId` resolved via
`_repository.getTicketById`, mapped to `BacklinkRef(origin:
wikilink)`) into one `List<BacklinkRef>`.
- Update every dartdoc touched to describe the new behavior (what's
emitted/fired and when — per flutter-conventions.md's Cubit dartdoc
rule).
