# Spec Delta: Bulk status and priority edit for ticket selection

**Reconciled 2026-09-03:** confirmed against the current `aion-arch/specs/tickets.md` "Bulk status/priority edit" section — `updateStatusForTickets`/`updatePriorityForTickets`, `BulkStatusMenu`/`BulkPriorityMenu`, and the gating rules still match current text closely. A few widget/state names the automated check flagged (`_SelectionBarTriggerChip`, `_hasMore`, `_currentTickets`) are shared selection-mode infrastructure documented once under the neighboring "Trash & bulk delete" section rather than repeated here — not drift, just not re-mentioned in this subsection.

Delta against `aion-arch/specs/tickets.md`. On `/archive`, these changes
merge into that file's prose (not appended as a changelog).

## ADDED

### `TicketsCubit` — bulk status/priority writes

- `updateStatusForTickets(List<String> ids, TicketStatus status)` — sets
  `status` on every ticket in `ids`, after excluding any id that would be
  rejected by the same two per-ticket gates a single-ticket status write
  already enforces when the target is `TicketStatus.inProgress`: the
  Blocked-dependency gate (`_isTicketBlocked`) and, for Task/Bug
  tickets, the coding-execution gate (`_codingExecutionGateCheck`).
  Every other target status skips gating entirely and writes the full
  selection, mirroring `updateTicketStatus`'s own short-circuit. Emits
  `TicketsBatchStatusUpdating` then `TicketsBatchStatusUpdated`
  (refreshed page, updated count, skipped count, `hasMore`), or
  `TicketsError` on an unexpected failure. For every successfully-written
  ticket: triggers git projection (`'status-changed'`) and, for a
  Task/Bug moving to `inProgress`, starts/queues its coding-execution run
  — identical post-write side effects to `updateTicketStatus`. Also
  refreshes the Board's blocked-badge state on completion.
- `updatePriorityForTickets(List<String> ids, TicketPriority priority)`
  — sets `priority` on every ticket in `ids`, unconditionally (no
  gating — priority has no structural constraint). Emits
  `TicketsBatchPriorityUpdating` then `TicketsBatchPriorityUpdated`
  (refreshed page, updated count, `hasMore`), or `TicketsError` on an
  unexpected failure. Does not trigger git projection (a plain field
  edit isn't one of `project.md`'s event-triggered projection events)
  and does not trigger embedding regeneration (only a title/description
  change does).

### `TicketsState` — four new states

- `TicketsBatchStatusUpdating` — a bulk status write is in flight.
- `TicketsBatchStatusUpdated(tickets, updatedCount, skippedCount, {hasMore})`
  — a bulk status write completed. `skippedCount` is always 0 unless the
  target status was `TicketStatus.inProgress`.
- `TicketsBatchPriorityUpdating` — a bulk priority write is in flight.
- `TicketsBatchPriorityUpdated(tickets, updatedCount, {hasMore})` — a
  bulk priority write completed. `updatedCount` always equals the
  original selection size (no rejection path exists for priority).

### `TicketRepository`/`DriftTicketRepository`/`TicketDao` — bulk write methods

- `TicketRepository.updateStatusForIds(List<String> ids, TicketStatus status)`
  and `updatePriorityForIds(List<String> ids, TicketPriority priority)` —
  unconditional bulk writes, no validation (matching
  `updateTicketStatus`'s existing no-validation contract; gating is a
  `TicketsCubit`-layer concern).
- `TicketDao.updateStatusByIds(List<String> ids, TicketStatus status, int updatedAtMs)`
  and `updatePriorityByIds(List<String> ids, TicketPriority priority, int updatedAtMs)`
  — single bulk `UPDATE ... WHERE id IN (...)` per call, same shape as
  the existing `softDeleteByIds`/`restoreByIds`.

### `TicketSelectionBar` — Status and Priority actions

- Two new required callbacks, `onChangeStatus: ValueChanged<TicketStatus>`
  and `onChangePriority: ValueChanged<TicketPriority>`.
- Two new inline trigger controls rendered in the bar's action row,
  between the Select-all/Deselect-all toggle and the destructive Delete
  button, reachable only when `selectedCount > 0`. Each is a
  `SelectionMenu<T>` wrapping a small passive `_SelectionBarTriggerChip`
  (icon + short label, no gesture handling of its own — `SelectionMenu`
  supplies that), listing every `TicketStatus`/`TicketPriority` value
  with nothing excluded (a bulk selection has no single "current" value
  to exclude). Selecting a value calls `onChangeStatus`/`onChangePriority`
  and dismisses the overlay.
- Wired from `TicketsListScreen` to `TicketsCubit.updateStatusForTickets`/
  `updatePriorityForTickets`. No confirmation dialog — unlike Delete, a
  status/priority write has no cascade, matching the single-ticket
  editors' existing no-confirmation behavior.
- `TicketsListScreen`'s `BlocListener<TicketsCubit, TicketsState>` gains
  two more branches (alongside the existing `TicketsBatchTrashed` one):
  a summary toast on `TicketsBatchStatusUpdated`
  (`updatedCount`/`skippedCount`-aware wording) and on
  `TicketsBatchPriorityUpdated`, each clearing the selection via
  `TicketSelectionCubit.clear()` afterward.

### New localized strings

`ticketSelectionStatusAction`, `ticketSelectionPriorityAction`,
`ticketBulkStatusSummaryToast`, `ticketBulkStatusSummaryWithSkippedToast`,
`ticketBulkPrioritySummaryToast`.

## MODIFIED

### `SelectionMenu<T>` — nullable `currentValue`

- `currentValue` widens from `required T currentValue` to
  `required T? currentValue`. When `null`, no item is excluded from the
  rendered overlay list — every value in `items` is selectable. Every
  existing caller (the detail screen's priority/status/type pickers,
  the board's — unrelated, bespoke — `MoveToStatusMenu`) is unaffected:
  each already passes a concrete non-null value, which still satisfies
  the widened type, and their exclusion behavior is unchanged.

### `TicketsListScreen` state-rendering switches

- The loading-spinner arm (previously `TicketsLoading() ||
  TicketTrashing() || TicketsBatchTrashing()`) gains
  `TicketsBatchStatusUpdating()` and `TicketsBatchPriorityUpdating()`.
- The body-render arm (previously `TicketsLoaded() || TicketCreating()
  || TicketCreated() || TicketStatusUpdating() || TicketStatusUpdated()
  || TicketsBatchTrashed() || TicketsLoadingMore() ||
  TicketsLoadMoreFailed()`) gains `TicketsBatchStatusUpdated()` and
  `TicketsBatchPriorityUpdated()`.
- `_currentTickets`/`_hasMore` (and any other exhaustive `switch` over
  `TicketsState` extracting `tickets`/`hasMore`) gain matching `case`
  arms for all four new states.

### Known gaps

- The "No bulk operations other than delete (status change, reparent,
  type/priority edit)" gap in `aion-arch/specs/tickets.md`'s Known Gaps
  section narrows: bulk status change and bulk priority edit are now
  built. Bulk reparent and bulk type/edit remain unbuilt, but are now
  recorded as a deliberate exclusion (see this change's proposal.md
  Non-goals) rather than an open gap — at archive time, replace the
  existing bullet with one reflecting only the reparent/type-edit
  remainder, framed as "won't build" rather than "not yet built."

## UNCHANGED (confirmed, not modified)

- `TicketSelectionCubit`/`TicketSelectionState` — untouched. They remain
  a plain id-set toggler with no opinion on what a caller does with the
  selection.
- The single-ticket status/priority editors (`TicketDetailScreen`'s
  `SelectionMenu<TicketStatus>`/`SelectionMenu<TicketPriority>`, the
  board's `MoveToStatusMenu`) — unchanged behavior, including their
  existing current-value exclusion.
- `trashTickets`/`TicketsBatchTrashing`/`TicketsBatchTrashed` and the
  existing Delete action — unchanged.
- Bulk reparent and bulk type/priority-combined edit — remain unbuilt
  (see Non-goals in proposal.md).
