# Delta Spec: Ticket Editing

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (42/42 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

> Legend: ADDED = new behavior, MODIFIED = changed behavior, REMOVED = deleted behavior.
> Baseline: current state as documented in `aion-arch/specs/tickets.md`.

---

## Domain

### MODIFIED — `Ticket.copyWith`

Widened from `{status, updatedAt}`-only to also cover `title`,
`description`, `priority`, `type`, `estimate`, `timeSpent`. The three
nullable fields (`description`, `estimate`, `timeSpent`) take a zero-arg
setter function rather than a bare value, so a caller can explicitly
clear one back to `null` (`() => null`) — distinct from omitting the
parameter to leave it unchanged. `id`, `ticketId`, `parentId`,
`embedding`, and `createdAt` are still never mutated by this method.

### MODIFIED — `TicketRepository` interface

Adds `Future<void> updateTicket(Ticket ticket)` — persists `title`,
`description`, `priority`, `type`, `estimate`, `timeSpent`, and a fresh
`updatedAt` for the ticket with id `ticket.id`. Does not touch `status`
(use the existing `updateTicketStatus`), `parentId`, `embedding`, `id`, or
`ticketId`. Throws if `ticket.id` does not exist.

## Data

### MODIFIED — `TicketDao`

`updateStatus(String id, TicketsTableCompanion companion)` is renamed to
`update(String id, TicketsTableCompanion companion)` — the method body
was already fully generic (writes whatever companion it's given); the
rename reflects that it now has two distinct callers (status-only and
general field updates), not a schema or behavior change.

### MODIFIED — `DriftTicketRepository`

Adds `updateTicket(Ticket ticket)`: builds a `TicketsTableCompanion`
covering `title`, `description`, `priority`, `type`, `estimate`,
`timeSpent`, and `updatedAt` (Unix ms, now), calls `TicketDao.update`.
Deliberately omits `status` from the companion. `updateTicketStatus`'s
existing call site is updated to call `TicketDao.update` (renamed from
`updateStatus`) — no behavior change.

## Core

### ADDED — `duration_format.dart` (`core/utils/`)

`formatDurationMinutes(int? minutes, {String placeholder})` — formats a
minute count as `'2h 30m'`/`'45m'`/`'3h'`, or `placeholder` for
null/non-positive input.

`parseDurationMinutes(String input)` — parses a free-form duration
(`'2h30m'`, `'2h 30m'`, `'90m'`, `'2h'`, or a bare number of minutes)
into total minutes. Blank input returns `null`. Throws `FormatException`
for anything else unrecognised.

### ADDED — `SelectionMenu<T>` (`core/widgets/`)

A generic overlay-picker widget: an always-visible `trigger` widget that,
on tap or `ActivateIntent`, opens an `Overlay` listing `items` (each
rendered via `itemLabel`, current value highlighted); selecting one calls
`onSelected` and dismisses. Same `Overlay`/`LayerLink`/
`CompositedTransformFollower`/mounted-guard mechanics as the existing
`MoveToStatusMenu`, generalized for reuse beyond ticket status.
`MoveToStatusMenu` itself is unchanged and does not use this widget.

## Presentation

### ADDED — `InlineEditableField<T>` (`features/tickets/presentation/widgets/`)

A tap-to-edit widget: view mode renders `displayText` (or a muted
`placeholder` when empty); activating it (tap, or `Enter`/`Space` via
keyboard focus) swaps in a text field pre-filled with `editText`.
Committing (Enter for single-line fields, or losing focus) runs the
supplied `parser` against the raw text; on success calls `onCommit` with
the parsed value and returns to view mode; on a thrown `FormatException`,
shows an `AppToast` with the error message, reverts to the previous text,
and returns to view mode without calling `onCommit`. `Escape` cancels an
in-progress edit (reverts, exits) without ever calling `parser`.

### ADDED — `TicketsCubit.updateTicket(Ticket ticket)`

Calls `TicketRepository.updateTicket(ticket)`, re-fetches the ticket via
`getTicketById`, and emits the existing `TicketDetailLoaded` state with
the refreshed ticket. Emits `TicketsError` if the repository call throws.
No new state classes — reuses `TicketDetailLoaded`, since the calling
inline-edit widgets already provide their own instant local feedback
before the repository round trip completes.

### MODIFIED — `TicketDetailScreen`

- Title becomes an `InlineEditableField<String>` (required — an empty
  submission is rejected client-side with a toast, no cubit call made).
- Description becomes an `InlineEditableField<String?>` (multiline,
  always rendered — including as an "Add a description…" placeholder
  when currently `null` — rather than only rendered when non-null).
- Priority (`PriorityBadge`) and type (`TypeChip`) each become the
  trigger of a `SelectionMenu<TicketPriority>` /
  `SelectionMenu<TicketType>`, selecting a new value calls
  `TicketsCubit.updateTicket` with the corresponding field replaced via
  `Ticket.copyWith`.
- Two new fields are surfaced for the first time: Estimate and Time
  Spent, each an `InlineEditableField<int?>` displaying/parsing via
  `formatDurationMinutes`/`parseDurationMinutes`.
- `StatusIndicator` (status) is unchanged — status editing remains
  board-only.

## Accessibility

### ADDED — Ticket-detail field accessibility requirement

Every new editable trigger (`InlineEditableField`, `SelectionMenu`) is a
`Semantics(button: true, label: ...)`-labeled, `FocusableActionDetector`
+ `ActivateIntent` focusable stop, built in from the start (not
retrofitted after verification, unlike the board's `MoveToStatusMenu`
history in `kanban-board-view`).

---

## Known gaps (carried forward, updated)

- `aion-arch/specs/tickets.md`'s "Ticket editing is limited to status
  only" gap is now further closed: title, description, priority, type,
  estimate, and time spent are all editable in place on the ticket detail
  screen. `parentId` remains non-editable (structural, deferred);
  `status` remains board-only by design; there is still no deletion path.
- `embedding` remains unpopulated/unexposed — still system-only, no UI
  planned.
- No automatic time tracking (timer UI) — manual entry only; automatic
  tracking is captured as a separate idea
  (`aion-arch/ideas/automatic-time-tracking-for-tickets.md`), not
  addressed here.
- `MoveToStatusMenu` remains a separate, unrefactored bespoke widget
  alongside the new `SelectionMenu<T>` — an acknowledged minor
  duplication, not consolidated in this change.
