# T37 — Fix the WARNING finding that `TicketsCubit.previewTrashCount`

could undercount relative to what `TicketRepository.trashTickets`
actually moves, in a mixed live/already-trashed subtree (e.g. a child
trashed individually, then its still-live parent trashed later) — the
cubit's `_descendantIds` walk sourced from `getAllTickets()` (live
only) never saw the already-trashed descendants that
`TicketDao.getDescendantIds` (unfiltered) would still cascade to.
Moved `previewTrashCount` from `TicketsCubit` to
`TicketRepository`/`DriftTicketRepository`
(`lib/features/tickets/domain/repositories/ticket_repository.dart`,
`lib/features/tickets/data/repositories/drift_ticket_repository.dart`),
sharing a new private `_resolveTrashCascade` helper with
`trashTickets` so the preview is mechanically guaranteed to match the
actual cascade. `TicketsCubit.previewTrashCount`
(`lib/features/tickets/presentation/cubit/tickets_cubit.dart`) now
just delegates to the repository. Dartdoc updated on all three.
Updated/added tests:
`test/features/tickets/cubit/tickets_cubit_test.dart` (delegation, not
cascade math), `test/features/tickets/data/repositories/drift_ticket_repository_test.dart`
(new `previewTrashCount` group, including a regression test for the
mixed live/trashed-descendant case that previously diverged).
