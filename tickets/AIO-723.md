# Dependency caching

- [x] T1. `lib/core/build/dependency_cache_service.dart` — new file: `DependencyCacheService` (`seed`, `writeBack`, `cacheDirFor`), fully dartdoc'd, plus file header. Resolve design.md's open question (constructor-injected vs. inline `const` instantiation) before T3 — check whether `_runCodingExecution`'s existing test coverage mocks `_gitClient`/`_gitHubClient`-style optional dependencies; mirror that pattern if so, otherwise instantiate inline. See design.md §1.1.
  - Resolved: constructor-injected. `tickets_cubit_test.dart` already mocks `_gitClient`/`_gitHubClient` via constructor injection at every `_runCodingExecution` test site, so `DependencyCacheService` follows the same convention for T12's mocking needs.
  - Also resolved: `cacheDirFor`'s key param is `projectId` (`Project.id`), not `project.storageKey` as design.md's draft assumed — `TicketsCubit` has no `Project` instance in scope inside `_runCodingExecution`, only `_projectId` (already `Project.id`, a unique-per-project UUID, captured locally as `projectId`). Serves the same per-project-cache-key purpose.
  - Deviation from design.md's exact sketch: added a fourth method, `installDependencies(String worktreePath)`, wrapping the `npm install` `Process.run` call design.md had inline in `_runCodingExecution`. `Process.run` is a static `dart:io` call with no mock seam, and a real `npm install` (even with zero dependencies) took ~14s locally in this environment — network/registry-dependent and far too slow/flaky for a unit test. Moving it onto the already-constructor-injected `DependencyCacheService` lets T12 mock it like every other dependency-caching step, mirroring why `GitRepositoryClient`/`GitHubCliClient` wrap their own `Process.run` calls in an injectable class rather than calling it bare from `TicketsCubit`.

Skip this task if T1 resolves to inline instantiation instead.
- [x] T3. `tickets_cubit.dart` — in `_runCodingExecution`, after `createWorktree` succeeds and before `_assembleExecutionContext` is called: detect the project's stack via `ProjectStackDetector().detect(rootPath)`; when `language == 'Node.js'`, seed the worktree's `node_modules` from the project's cache dir, mechanically run `npm install` via `Process.run`, and write the result back to the cache on success. Update `_runCodingExecution`'s existing dartdoc to describe this new step. See design.md §1.2.
