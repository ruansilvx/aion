# `TicketsCubit` wiring (`lib/features/tickets/presentation/cubit/tickets_cubit.dart`)

- [x] Add optional constructor parameter
      `TransitionPreconditionRepository? transitionPreconditionRepository`;
      cached `Map<SddStage, TransitionGraph>`/`Map<String,
      TransitionNode>` state, loaded once at construction and
      refreshed on `TransitionPreconditionRepository.onChanged` —
      mirrors `_workflowStatuses`'s own cache-and-refresh pattern.
- [x] Extract `hasChildren`, `allChildrenComplete`,
      `linkedDesignPageHasContent` as small private helpers from
      `_sddStageAdvanceCheck`'s current inline `proposed`/`designBrief`
      logic (`_storyNeedsDesignReview`/`_designSyncApproved` already
      exist as helpers — reused as-is).
- [x] Rewrite `_sddStageAdvanceCheck`'s `exploring`/`verifying`,
      `proposed`, `designBrief`, `designSync` branches: build a
      `TransitionEvalContext` from the helpers above, call
      `evaluateTransitionGraph` against that stage's cached graph,
      return `(canAdvance: outcome == allowed, blockReason: outcome ==
      blocked ? 'Waiting on: $blockingFieldDisplayName' : null)`. The
      `null`/`archived` branches are untouched.
      Return type changes to `Future<({bool canAdvance, String?
      blockReason})>`.
- [x] Update every existing construction site that supplies
      `WorkflowStatusRepository` (tests included) to also decide
      whether it needs `transitionPreconditionRepository` — any test
      exercising real `_sddStageAdvanceCheck` behavior must supply one
      seeded with the baseline graphs (`design.md` §3), or be rewritten
      against the new `(bool, String?)` shape.
