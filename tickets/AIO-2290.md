# Spec delta: Ticket link management UI

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's TicketsCubit/Screens sections (Linked Tickets)` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. LinkedTicketsSection, TicketLinkPicker, and the link-management mutations this delta introduces are confirmed still current and actively cross-referenced elsewhere in the spec.

Delta against `aion-arch/specs/tickets.md`. Relative to the ticket
detail screen's Documentation-derived sections and `TicketLinkRepository`.

## ADDED

- `TicketLinkRepository.getLinkById(String linkId)` — returns the single
  `TicketLinkData` row with that id, or `null` if it no longer exists.
- `TicketLinkRepository.deleteLink(String linkId)` — deletes a single
  `ticket_links` row by id.
- `TicketLinkRepository.updateLinkType(String linkId, TicketLinkType
  newType)` — updates a single row's stored `linkType` in place; no
  source/target change, no companion-row bookkeeping (each
  `blocks`/`blockedBy`/`duplicates`/`duplicatedBy` relationship is one
  row, read directionally — see design.md §1).
- `TicketLinkTypeRelative.inverse` extension on `TicketLinkType` — the
  perspective-flipped reading of a type (`blocks`↔`blockedBy`,
  `duplicates`↔`duplicatedBy`, `relatesTo`↔`relatesTo`).
- A `relativeLinkType(TicketLinkData row, String viewingTicketId)`
  helper computing how a row reads from a specific ticket's point of
  view.
- `TicketsCubit.deleteTicketLink(String ticketId, String linkId)` — new
  Cubit method: deletes the link, refreshes `loadDocumentRelations` for
  `ticketId`, and refreshes the Board's blocked-badge state when the
  removed link was a `blocks`/`blockedBy` relationship.
- `TicketsCubit.updateTicketLinkType(String ticketId, String linkId,
  TicketLinkType newCanonicalType)` — new Cubit method: same
  refresh shape as `deleteTicketLink`, for an in-place type change.
- `TicketsCubit.createTicketLink(String ticketId, String targetTicketId,
  TicketLinkType linkType)` — new Cubit method wrapping link creation,
  replacing the previous direct-repository-call pattern in
  `ticket_metadata_section.dart` (see MODIFIED below).
- Per-row relationship-type indicator on `LinkedTicketsSection`'s rows
  (glyph + label, e.g. "Blocked by"), computed relative to the ticket
  whose detail screen is showing it.
- Per-row remove action on `LinkedTicketsSection`, backed by
  `TicketsCubit.deleteTicketLink`, with a confirmation step before the
  link is actually deleted.
- Per-row in-place link-type editing on `LinkedTicketsSection`, backed
  by `TicketsCubit.updateTicketLinkType`, restricted to the same
  `linkTypeOptions` set already used for that ticket type's link
  creation (e.g. `resource` tickets: `relatesTo` only) — with one
  carve-out: a row currently read (relatively) as "Duplicated by" has no
  edit control, matching the existing creation-time restriction that
  `duplicatedBy` is never a directly user-chosen value.
- New localization keys: `ticketLinkTypeDuplicatedBy`,
  `linkedTicketsRemoveAction`, `linkedTicketsChangeTypeAction`,
  `linkedTicketsRemoveConfirmTitle`, `linkedTicketsRemoveConfirmBody`,
  `linkedTicketsRemoveConfirmAction`.

## MODIFIED

- `LinkedTicketsSection` (`design_system/molecules/`): constructor
  changes from `List<Ticket> tickets` to `List<LinkedTicketRef> links`
  (a new `({Ticket ticket, TicketLinkType relativeType, String linkId})`
  record type), and gains two new required callbacks: `onRemove
  (ValueChanged<String> linkId)` and `onChangeType (void
  Function(String linkId, TicketLinkType newRelativeType))`.
- `TicketDetailLoaded.linkedTickets` and `.backlinks`
  (`tickets_state.dart`): type changes from `List<Ticket>` to
  `List<LinkedTicketRef>`. `TicketsCubit.loadDocumentRelations` now
  computes each row's `relativeType` instead of discarding the
  underlying `TicketLinkData`.
- `PageRelations.linkedTickets`/`.backlinks` (pages feature): same type
  change, for the same reason, feeding `PageDetailScreen`.
- `BacklinksSection` callers (`ticket_metadata_section.dart`,
  `page_detail_screen.dart`): unwrap `LinkedTicketRef.ticket` before
  passing to `BacklinksSection`, which keeps its existing `List<Ticket>`
  contract unchanged (no new backlink behavior — see proposal.md's
  Non-goals).
- `ticket_metadata_section.dart`'s `TicketLinkPicker.onSelected`
  callback: no longer calls `context.read<TicketLinkRepository>()
  .createLink(...)` directly — calls the new
  `TicketsCubit.createTicketLink` instead, for consistency with the two
  new mutation methods (all three link mutations now go through the
  Cubit, none bypass it).
- `TicketsCubit._computeBlockedTicketIds`/`_isTicketBlocked`: internal
  refactor to call the new `relativeLinkType`/`TicketLinkTypeRelative
  .inverse` helpers instead of each inlining its own equivalent switch
  statement. No behavior change.
- `_linkTypeGlyph`/`_linkTypeLabel` (previously private top-level
  functions in `ticket_link_picker.dart`): promoted to extension methods
  on `TicketLinkType` itself (`domain/enums/ticket_link_type.dart`), so
  both `ticket_link_picker.dart` and the new `_LinkRow` code in
  `linked_tickets_section.dart` share one definition.
