# 5.3 Modify `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart` —

add the `codebaseAnalysisStatus` stream/state (kept separate from
the main `TicketsState`, per design.md) and
`Future<void> runCodebaseSummarization({required SummarizationDepth depth})`:
- shallow: one `AgentModelClient` call (`toolsEnabled: false`),
prompt built from `ProjectStackDetector.detect(_projectRootPath)`
plus a depth-limited `Directory.list()` (filenames only).
- full: mirrors `_runCodingExecution`'s shape — fresh worktree via
`GitRepositoryClient.createWorktree`, spawns a root `signal`
ticket ("Codebase Analysis — `<project name>`") and its `chat`
child, runs `ChatCubit.runChatTurn(toolsEnabled: true,
workingDirectory: worktreePath)` streaming into that chat's
comments, always removes the worktree in a `finally` block.
- both: parse the final reply for a `SUMMARY: DONE` marker
(mirroring the existing `IMPLEMENTATION: DONE` convention) into
`(title, description)` finding pairs; for each, `TicketRepository
.createTicket(type: signal, ...)` then (full depth only, or both —
decide during implementation whether shallow findings link back to
a run-record ticket too) `TicketLinkRepository.createLink(...,
linkType: relatesTo)`. Shallow findings' descriptions are prefixed
with the `"[Shallow scan — structural only, may be incomplete]"`
line.
Every new/modified public method gets a full dartdoc per
project.md, matching `_runCodingExecution`'s existing documentation
density.
