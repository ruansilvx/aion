# Design: Ticket Trash & Bulk Delete

## 1. Overview

```
TicketOverflowMenu (single)          TicketSelectionBar (bulk)
        │                                     │
        ▼                                     ▼
TicketsCubit.previewTrashCount(ids)  ← shared preview, both paths
        │
        ▼ (shown in confirm dialog, then confirmed)
TicketsCubit.trashTicket(id) / trashTickets(ids)
        │
        ▼
TicketRepository.trashTicket / trashTickets   ← domain interface
        │
        ▼
DriftTicketRepository — computes full structural subtree per id,
        bulk-sets deletedAt on the union. Never blocks.
        │
        ▼
TicketDao.getDescendantIds / softDeleteByIds  (new)


TrashScreen (new, /tickets/trash)
        │
        ▼
TrashCubit.load / restore / permanentlyDelete / emptyTrash
        │
        ▼
TicketRepository.getTrashedTickets / restoreTicket /
        permanentlyDeleteTicket / emptyTrash
        │
        ▼
TicketDao.getAncestorIds / getDescendantIds / restoreByIds /
        deleteTicketRows  +  CommentDao/TicketLinkDao batch cascades
```

No FK constraints exist on `TicketsTable`/`TicketLinksTable` (documented
in both tables' class docs), so every cascade here — trash, restore,
permanent delete — is orchestrated in Dart at the repository layer, same
as the app's existing deletion cascade always has been.

## 2. Data model

### `TicketsTable` — new column

```dart
/// When this ticket was moved to trash (soft-deleted). `null` means the
/// ticket is live. Set by [TicketDao.softDeleteByIds], cleared by
/// [TicketDao.restoreByIds]. Unix milliseconds.
IntColumn get deletedAt => integer().named('deleted_at').nullable()();
```

### `AppDatabase` — schema version 3

```dart
@override
int get schemaVersion => 3;

@override
MigrationStrategy get migration => MigrationStrategy(
  onCreate: (Migrator m) async {
    await m.createAll();
    await into(ticketIdSequenceTable).insert(...); // unchanged
    await _createSearchInfrastructure(m);
  },
  onUpgrade: (Migrator m, int from, int to) async {
    if (from < 2) {
      await _createSearchInfrastructure(m);
    }
    if (from < 3) {
      await m.addColumn(ticketsTable, ticketsTable.deletedAt);
    }
  },
);
```

`addColumn` is Drift's standard additive-migration primitive — existing
rows get `deleted_at = NULL`, i.e. every pre-existing ticket is live
after upgrading, which is exactly right (nothing was ever in trash
before this change existed).

### `Ticket` (domain entity)

Add a nullable `deletedAt` field (`DateTime?`), mapped the same way
`createdAt`/`updatedAt` already are (`DateTime.fromMillisecondsSinceEpoch`
when present). Included in `props` for `Equatable`. `copyWith` does not
need a `deletedAt` parameter — every repository method that changes it
(`trashTicket(s)`, `restoreTicket`) writes directly via the DAO, the same
way `parentId`/`status` changes bypass `copyWith` today.

## 3. Domain layer

### `TicketRepository` — replaces `deleteTicket`

Remove `deleteTicket` and `TicketHasChildrenException` entirely (see
§9 for the exception file's removal). Add:

```dart
/// Moves [id] and every ticket in its structural subtree into trash
/// (sets `deletedAt`, deletes nothing). Never blocked by children —
/// they're cascaded into trash alongside [id] instead. Throws
/// [StateError] if [id] does not exist.
Future<void> trashTicket(String id);

/// Moves every ticket in [ids] — and each one's full structural
/// subtree — into trash in one call. Returns the total number of
/// tickets actually moved (== [ids] plus every cascaded descendant,
/// deduplicated), so the caller can report an accurate count even when
/// it's larger than `ids.length`. Ids that don't exist are silently
/// skipped.
Future<int> trashTickets(List<String> ids);

/// Restores [id] out of trash, along with any currently-trashed
/// ancestors (so it's never left with a hidden parent) and any
/// currently-trashed descendants (its own subtree, trashed alongside
/// it originally — see §4's invariant). Throws [StateError] if [id]
/// does not exist.
Future<void> restoreTicket(String id);

/// Permanently deletes [id] and its full structural subtree —
/// cascading to comments and `ticket_links` exactly as the old
/// `deleteTicket` did. Irreversible. Throws [StateError] if [id] does
/// not exist.
Future<void> permanentlyDeleteTicket(String id);

/// Permanently deletes every currently trashed ticket (and their
/// comments/`ticket_links`). Irreversible. Used by the trash screen's
/// "Empty trash" action. No-ops if trash is empty.
Future<void> emptyTrash();

/// Returns every currently trashed ticket, most recently trashed
/// first.
Future<List<Ticket>> getTrashedTickets();
```

### `TicketRepository` — modified contracts

- `getAllTickets()` / `searchTickets(...)` — now exclude trashed
  tickets (`deletedAt IS NULL`). Dartdoc updated to say so explicitly.
- `getTicketById(id)` — unchanged/unfiltered. Still resolves a trashed
  ticket, since restore/permanent-delete need to look one up by id.

`TicketsErrorReason.hasChildren` and `TicketsError.childCount` are
removed — nothing blocks anymore, so there's no classified error left
to carry. `ticketsErrorMessage`'s switch drops that case; the
`hasChildren`-specific ARB keys are removed (see §8).

## 4. Data layer

### Cascade invariant

**A live (non-trashed) ticket never has a trashed ancestor.** Maintained
by: trashing always cascades to the full descendant subtree (so a
ticket and its children move to trash together, never one without the
other); restoring always cascades to trashed ancestors too (so a
restored ticket is never left under a hidden parent); and
`getValidParentCandidates` (§6) excludes trashed tickets, so a live
ticket can never be reparented under one. Given the invariant, neither
trash nor restore ever needs to ask the user anything or report a
partial result — every call fully succeeds or throws on a genuine
unexpected failure.

### `TicketDao` additions

```dart
/// Returns the ids of every ticket in [rootId]'s structural subtree
/// (children, grandchildren, ...), not including [rootId] itself.
/// Breadth-first, with a visited-set guard against a cycle (shouldn't
/// be possible — [TicketsCubit.updateTicketParent] rejects cycles at
/// write time — but cheap insurance against an infinite loop if one
/// ever existed).
Future<List<String>> getDescendantIds(String rootId);

/// Returns the ids of every ticket above [id] in its structural parent
/// chain (its parent, its parent's parent, ...), not including [id]
/// itself. Stops at the first ticket with no parent, or defensively at
/// a repeated id (cycle guard, same rationale as [getDescendantIds]).
Future<List<String>> getAncestorIds(String id);

/// Sets `deleted_at = deletedAtMs` for every id in [ids]. Bulk
/// `UPDATE ... WHERE id IN (...)` — used by trash operations.
Future<void> softDeleteByIds(List<String> ids, int deletedAtMs);

/// Sets `deleted_at = NULL` for every id in [ids]. Bulk
/// `UPDATE ... WHERE id IN (...)` — used by restore. A no-op per row
/// already live (idempotent), so callers don't need to filter down to
/// "currently trashed" ids first.
Future<void> restoreByIds(List<String> ids);

/// Returns every trashed ticket row (`deleted_at IS NOT NULL`), most
/// recently trashed first.
Future<List<TicketData>> getTrashedTickets();
```

### `TicketDao` — modified / removed

- `getAllTickets()` — add `..where((t) => t.deletedAt.isNull())`.
- `searchTickets(...)` — add the same `deleted_at IS NULL` condition to
  both the filtered-select branch and the FTS `customSelect` branch
  (`'tickets.deleted_at IS NULL'` added to `conditions`).
- `countChildTickets` — **removed**. Its only caller (the old
  `deleteTicket`'s block-on-children check) no longer exists.
- `deleteTicketRow(String id)` — **replaced** by a batch
  `deleteTicketRows(List<String> ids)` (`DELETE FROM tickets WHERE id IN
  (...)`), used by `permanentlyDeleteTicket`/`emptyTrash` to remove a
  whole subtree (or the whole trash) in one statement instead of a
  per-id loop.

### `CommentDao` / `TicketLinkDao` — modified

`deleteCommentsForTicket(String ticketId)` /
`deleteLinksForTicket(String ticketId)` become
`deleteCommentsForTickets(List<String> ticketIds)` /
`deleteLinksForTickets(List<String> ticketIds)` (batch `isIn`/`|`
conditions, same query shape, generalized from one id to a list) — used
by permanent delete, which always operates over a whole subtree's worth
of ids at once, not one ticket at a time.

### `DriftTicketRepository`

```dart
@override
Future<void> trashTicket(String id) async {
  final existing = await _db.ticketDao.getTicketById(id);
  if (existing == null) throw StateError('Ticket $id does not exist');
  await trashTickets([id]);
}

@override
Future<int> trashTickets(List<String> ids) async {
  final affected = <String>{...ids};
  for (final id in ids) {
    affected.addAll(await _db.ticketDao.getDescendantIds(id));
  }
  if (affected.isEmpty) return 0;
  await _db.ticketDao.softDeleteByIds(
    affected.toList(),
    DateTime.now().millisecondsSinceEpoch,
  );
  return affected.length;
}

@override
Future<void> restoreTicket(String id) async {
  final existing = await _db.ticketDao.getTicketById(id);
  if (existing == null) throw StateError('Ticket $id does not exist');

  final toRestore = <String>{id};
  toRestore.addAll(await _db.ticketDao.getAncestorIds(id));
  toRestore.addAll(await _db.ticketDao.getDescendantIds(id));
  await _db.ticketDao.restoreByIds(toRestore.toList());
}

@override
Future<void> permanentlyDeleteTicket(String id) async {
  final existing = await _db.ticketDao.getTicketById(id);
  if (existing == null) throw StateError('Ticket $id does not exist');

  final ids = <String>{id, ...await _db.ticketDao.getDescendantIds(id)}
      .toList();
  await _db.transaction(() async {
    await _db.commentDao.deleteCommentsForTickets(ids);
    await _db.ticketLinkDao.deleteLinksForTickets(ids);
    await _db.ticketDao.deleteTicketRows(ids);
  });
}

@override
Future<void> emptyTrash() async {
  final trashed = await _db.ticketDao.getTrashedTickets();
  if (trashed.isEmpty) return;
  final ids = trashed.map((t) => t.id).toList();
  await _db.transaction(() async {
    await _db.commentDao.deleteCommentsForTickets(ids);
    await _db.ticketLinkDao.deleteLinksForTickets(ids);
    await _db.ticketDao.deleteTicketRows(ids);
  });
}

@override
Future<List<Ticket>> getTrashedTickets() async {
  final rows = await _db.ticketDao.getTrashedTickets();
  return rows.map(_toEntity).toList();
}
```

`emptyTrash` deletes every row where `deleted_at IS NOT NULL` directly
— it doesn't need to separately compute descendants, because the §4
invariant guarantees the trashed set is already closed under the
parent/child relationship (nothing live has a trashed ancestor, so
every ticket connected to a trashed one is also trashed).

`_toEntity` gains one line mapping `row.deletedAt` to the entity's new
nullable `deletedAt` field (same `DateTime.fromMillisecondsSinceEpoch`
pattern already used for `createdAt`/`updatedAt`, conditional on
non-null).

## 5. Presentation layer — `TicketsState` / `TicketsCubit`

### `TicketsState` — removed

`TicketDeleting`, `TicketDeleted`, `TicketsErrorReason.hasChildren`,
`TicketsError.childCount`.

### `TicketsState` — added

```dart
/// A [TicketsCubit.trashTicket] call is in flight (single ticket,
/// triggered from `TicketOverflowMenu`).
class TicketTrashing extends TicketsState {
  const TicketTrashing();
}

/// A single ticket was moved to trash successfully. Carries no data —
/// `TicketDetailScreen` responds by navigating back to `/tickets`,
/// where [TicketsCubit.loadTickets]/`searchTickets` re-fetches the now-
/// shorter (trash-excluded) list.
class TicketTrashed extends TicketsState {
  const TicketTrashed();
}

/// A [TicketsCubit.trashTickets] batch call is in flight (bulk,
/// triggered from `TicketSelectionBar`).
class TicketsBatchTrashing extends TicketsState {
  const TicketsBatchTrashing();
}

/// A batch trash call completed. Carries the refreshed list and the
/// total number of tickets actually moved (>= the original selection
/// size, once cascaded descendants are included) so the widget layer
/// can show an accurate summary toast.
class TicketsBatchTrashed extends TicketsState {
  const TicketsBatchTrashed(this.tickets, this.trashedCount);
  final List<Ticket> tickets;
  final int trashedCount;
  @override
  List<Object?> get props => [tickets, trashedCount];
}
```

### `TicketsCubit` methods

```dart
/// Returns the total number of tickets that would move to trash if
/// every id in [ids] were trashed right now — [ids] plus every
/// structural descendant, deduplicated. Query only, no state emitted.
/// Used to preview the cascade in the confirm dialog before the user
/// commits, for both the single-ticket (`TicketOverflowMenu`) and bulk
/// (`TicketSelectionBar`) delete flows. Reuses the same [_descendantIds]
/// helper [getValidParentCandidates]/[updateTicketParent] already use.
Future<int> previewTrashCount(List<String> ids) async {
  final all = await _repository.getAllTickets();
  final affected = <String>{...ids};
  for (final id in ids) {
    affected.addAll(_descendantIds(id, all));
  }
  return affected.length;
}

/// Moves ticket [id] to trash via [TicketRepository.trashTicket].
/// Context-aware on the state active before the call, same rationale
/// as the old `deleteTicket`: [TicketDetailLoaded] previous state (the
/// caller is `TicketDetailScreen`) emits [TicketTrashed] on success;
/// any other (list/board-shaped) previous state re-fetches and emits
/// [TicketsLoaded] instead, so `TicketsListScreen`/`TicketBoardView`
/// never fall into a blank state. No blocking branch remains — trash
/// never fails except on a genuine unexpected repository error, which
/// emits [TicketsError].
Future<void> trashTicket(String id) async {
  final previousState = state;
  emit(const TicketTrashing());
  try {
    await _repository.trashTicket(id);
    if (previousState is TicketDetailLoaded) {
      emit(const TicketTrashed());
    } else {
      emit(TicketsLoaded(await _repository.getAllTickets()));
    }
  } catch (e) {
    emit(TicketsError(e.toString()));
  }
}

/// Moves every ticket in [ids] to trash via
/// [TicketRepository.trashTickets]. Always triggered from
/// `TicketsListScreen`'s selection mode (list or board rendering) — no
/// detail-screen caller to special-case, unlike [trashTicket]. Emits
/// [TicketsBatchTrashing] then [TicketsBatchTrashed] (refreshed list +
/// actual trashed count) on success, or [TicketsError] on an
/// unexpected failure.
Future<void> trashTickets(List<String> ids) async {
  emit(const TicketsBatchTrashing());
  try {
    final trashedCount = await _repository.trashTickets(ids);
    final tickets = await _repository.getAllTickets();
    emit(TicketsBatchTrashed(tickets, trashedCount));
  } catch (e) {
    emit(TicketsError(e.toString()));
  }
}
```

`getValidParentCandidates` needs no code change — it already builds its
candidate list from `getAllTickets()`, which now excludes trashed
tickets automatically.

## 6. Presentation layer — `TicketSelectionCubit`

Unchanged in shape from the original bulk-delete-only design (still a
separate, screen-scoped cubit — see the rationale in this document's
prior revision, preserved here): `TicketSelectionState { isActive,
selectedIds }`, `enter()`, `toggle(id)`, `selectAll(ids)`, `clear()`.
**No invariant-checking logic is added to `toggle`/`selectAll`** — that
whole direction (blocking a selection whose children aren't also
selected) is exactly what trash's unconditional cascade makes
unnecessary. Selection stays a plain id-set toggler with zero knowledge
of ticket relationships.

One change from the prior revision: `TicketSelectionCubit` is now
provided via `BlocProvider` at the **router** level (wrapping
`TicketsListScreen` in `/core/routing/app_router.dart`'s `/tickets`
route), matching the existing precedent of `/tickets/:id` wrapping
`TicketDetailScreen` with `BlocProvider<CommentsCubit>` right there in
the route builder — rather than inside `TicketsListScreen.build()` as
originally sketched. Screen-scoped either way (a fresh instance per
route match), just consistent with how the codebase already does
screen-scoped cubit provisioning.

## 8. New screen — Trash

### Routing

`core/routing/app_router.dart`: add
```dart
GoRoute(
  path: '/tickets/trash',
  builder: (context, state) => BlocProvider<TrashCubit>(
    create: (context) => TrashCubit(context.read<TicketRepository>())..load(),
    child: const TrashScreen(),
  ),
),
```
registered **before** the existing `GoRoute(path: '/tickets/:id', ...)`
in the `routes` list — go_router matches path segments in declaration
order, and `:id` would otherwise greedily match the literal segment
`trash`, exactly the same ordering constraint `/tickets/new` already
satisfies today.

### `TrashState` / `TrashCubit`

```dart
sealed class TrashState extends Equatable { ... }
class TrashLoading extends TrashState { ... }
class TrashLoaded extends TrashState { final List<Ticket> tickets; ... }
class TrashError extends TrashState { final String message; ... }
```

```dart
class TrashCubit extends Cubit<TrashState> {
  TrashCubit(this._repository) : super(const TrashLoading());
  final TicketRepository _repository;

  Future<void> load() async {
    emit(const TrashLoading());
    try {
      emit(TrashLoaded(await _repository.getTrashedTickets()));
    } catch (e) {
      emit(TrashError(e.toString()));
    }
  }

  Future<void> restore(String id) async {
    try {
      await _repository.restoreTicket(id);
      await load();
    } catch (e) {
      emit(TrashError(e.toString()));
    }
  }

  Future<void> permanentlyDelete(String id) async {
    try {
      await _repository.permanentlyDeleteTicket(id);
      await load();
    } catch (e) {
      emit(TrashError(e.toString()));
    }
  }

  Future<void> emptyTrash() async {
    try {
      await _repository.emptyTrash();
      await load();
    } catch (e) {
      emit(TrashError(e.toString()));
    }
  }
}
```

No per-row in-flight state — every action re-fetches and emits the
full list afterward (same "re-fetch and emit" convention used
elsewhere in `TicketsCubit` outside the optimistic `updateTicketStatus`
path), which is fine given these are local SQLite writes.

### `TrashScreen` / `TrashedTicketTile`

`TrashScreen`: header ("Trash" title, back navigation to `/tickets`, an
"Empty trash" destructive action — hidden/disabled when the list is
empty, confirmed via `showAppConfirmDialog` with an ICU-plural,
count-aware title) over a `BlocBuilder<TrashCubit, TrashState>` body:
loading spinner, error + retry, empty state ("Trash is empty"), or a
`ListView` of `TrashedTicketTile`.

`TrashedTicketTile` (new, `presentation/widgets/`): id badge + title +
type chip (same visual vocabulary as `TicketListTile`, minus status/
priority — trashed tickets don't need workflow context), non-navigating
(no detail screen for trashed tickets in this scope), two trailing icon
actions:
- **Restore** — no confirmation (non-destructive, expected-to-be-used
  action) — calls `TrashCubit.restore(id)` directly.
- **Permanently delete** — `showAppConfirmDialog` (destructive,
  irreversible copy) → `TrashCubit.permanentlyDelete(id)`.

## 11. Testing

- `TicketDao`/`DriftTicketRepository` tests (in-memory Drift, matching
  the existing style): `trashTicket`/`trashTickets` move the full
  subtree (multi-level: grandparent → parent → child, trashing the
  grandparent trashes all three); `restoreTicket` on a deep child
  restores its trashed ancestors too, leaving unrelated trashed tickets
  untouched; `getAllTickets`/`searchTickets` never return trashed rows;
  `permanentlyDeleteTicket` cascades to comments/links/subtree and
  removes the rows entirely; `emptyTrash` removes every trashed ticket
  and only trashed tickets; a non-existent id in `trashTickets` is
  silently skipped while the rest of the batch still processes.
- `TicketsCubit` tests: `previewTrashCount` returns selection size when
  no descendants exist, and a larger total when they do;
  `trashTicket`/`trashTickets` state-transition cases (context-aware
  branching for the single-ticket case, same shape as the old
  `deleteTicket` tests it replaces); generic-failure cases for both.
- `TrashCubit` tests: `load` success/failure; `restore`/
  `permanentlyDelete`/`emptyTrash` each re-load on success, emit
  `TrashError` on failure.

# Aion — Ticket Trash & Bulk Delete Specification

Implementation-ready spec for Aion's soft-delete/trash model and multi-select bulk delete. Replaces the old hard-delete-with-block flow: deleting a ticket (single or bulk) moves it **and its full structural subtree** into a recoverable **Trash**; nothing is destroyed until the user explicitly permanently-deletes or empties the Trash. Adds a **Select mode** to the ticket list/board and a new **Trash screen** (`/tickets/trash`).

- **No Material widgets or types anywhere.** Every component is built from plain Flutter primitives — `DecoratedBox`, `Container`, `GestureDetector`, `CustomPaint`, `Row`, `Column`, `Stack`, `Positioned`, `Align`, `Padding`, `CompositedTransformTarget`/`Follower`. Do **not** reference `Card`, `ElevatedButton`, `Checkbox`, `Scaffold`, `AppBar`, `Dialog`, `SnackBar`, `ThemeData`, `ColorScheme`, or any other `material.dart` symbol.
- `c` = active `AionColors`; `a` = theme `fillAlpha` (Arctic `0.11` / Obsidian `0.16`); `isDark` = Obsidian.
- Both themes share one code path; only token values differ. Where a component is identical across themes it is stated explicitly.
- Translucent fills are `token.withValues(alpha: x)` — never hardcoded ARGB.
- Companion mockups: `Aion Ticket Trash and Bulk Delete Mockups.dc.html` — Select mode `1a`, Trash screen `2a`, reversible dialog `3a`, permanent dialog `4a`, component states `5a` (Arctic + Obsidian throughout).

## 0. New tokens

**Design-sync note (resolved during `/design-sync`):** every color and radius value below resolves to an *existing* `AionColors`/`AionRadius` token — **zero new tokens are added to `aion_colors.dart`/`aion_radius.dart` by this change.** The six computed color helpers (`selectionTint`, `selectionAccent`, `reversibleTint`, `destructiveTint`, `noticeFill`, `noticeBorder`) originally proposed here as new `AionColors` getters are **not** to be added as class members — every other tinted-fill site in this codebase (`PriorityBadge`, `TypeChip`, `TicketOverflowMenu`) inlines `token.withValues(alpha: x)` directly at the call site rather than adding a named wrapper method, and `/apply` should follow that same existing convention here instead of introducing a new pattern. Treat the list below as **shorthand notation for this spec's own readability**, not literal Dart to add:

```dart
// Shorthand used only within this design.md — inline at each call site during /apply:
primarySubtle                                          // selected row/card fill
primary                                                 // 3px leading rail on selected rows
primary.withValues(alpha: a)                            // "Move to Trash" dialog icon chip
danger.withValues(alpha: a)                              // permanent-delete icon disc + trash-action fill
primary.withValues(alpha: isDark ? 0.10 : 0.06)          // Trash info banner fill
primary.withValues(alpha: isDark ? 0.30 : 0.20)          // Trash info banner border
```

**Radius — no new tokens.** The two radius names originally proposed here (`chip` = 6, `actionBtn` = 10) were exact duplicates of the existing `AionRadius.sm` (6) and `AionRadius.md` (10) — adding same-value aliases would have fragmented the scale with two names for one radius. Every occurrence below has already been rewritten to the existing **`AionRadius.sm`**/**`AionRadius.md`** names directly; do not reintroduce `chip`/`actionBtn`.

No new font styles are required. The selected-count label (§4.2) uses `AionText.button.copyWith(fontSize: 13.5)` — a one-off size override at the call site (matching the existing `PriorityBadge`/`TypeChip` `copyWith`-on-a-base-style pattern), not a new named `AionText` constant.

## 9. Cascade & data behavior (for implementers)

- **Delete (soft):** moving a ticket to Trash moves its **entire structural subtree** (subtasks, sub-subtasks, …) with it. The affected count shown in the reversible dialog (§6.1) is `1 + descendants`. Trash tiles list only the **roots** that were explicitly deleted; a restored root brings its subtree back with it (descendants are not listed as separate Trash tiles).
- **Bulk delete:** the `TicketSelectionBar` Delete acts on all checked roots; each carries its subtree. The reversible dialog's `{n} tickets` counts checked roots, and the recoverable chip's `{total}` counts roots + all cascaded descendants.
- **Restore:** re-parents the subtree to its original parent (or to the list root if the original parent is itself still trashed — in that case restore is disabled/greyed with a hint, or restores to root; pick one and keep it consistent). Out of scope for this visual spec; noted for the data layer.
- **Permanent delete / Empty trash:** irreversibly destroys the ticket(s) and their subtrees. Only reachable from the Trash screen.

## 11. Implementation notes

- Reuse the existing confirm-dialog shell widget; parameterize it with a `tone` enum (`reversible` | `destructive`) that swaps only the icon-disc shape+fill, the icon+color, the confirm-button color, and the copy (§6). Do not fork two dialog widgets.
- The `TicketSelectionBar` and the FAB occupy the same `Positioned` slot; cross-fade between them (120ms opacity) when Select mode toggles, matching the design-system's list result-transition timing.
- Never hard-code the tinted fills — always `token.withValues(alpha: ...)` with the theme's `fillAlpha`, so one widget serves both themes.
- Keep `warning` out of these components; the permanent-delete alert glyph uses `danger`, not `warning`.
- All icons are the thin-line 1.5px-stroke set at 14–20px; the empty-state and dialog motifs may use a filled `primary`/`danger` treatment per the iconography rule.
- All uppercase label text (type chips) is uppercased in Dart strings, not via a text transform.
