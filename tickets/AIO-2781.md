# `test/features/tickets/data/services/ticket_db_reconstruction_service_test.dart`:

the two existing `deletedAt`-focused tests (`'reconstructs a new
ticket with its deletedAt from the file'`,
`'updating an existing row from a file with deletedAt overwrites
the row's previous value'`) only assert against the mocked
repository's captured argument — leave them, but add two new
integration-style tests using a **real** `DriftTicketRepository`
over an in-memory `NativeDatabase` (mirroring
`drift_ticket_repository_test.dart`'s setup) instead of
`MockTicketRepository`: (a) reconstruct against a project where
a ticket is genuinely trashed in the DB and its `.md` file still
exists — asserts no exception is thrown and the row's `deletedAt`
is unchanged; (b) a live DB row whose `.md` file says trashed —
asserts `reconstruct()` leaves the row's `deletedAt` non-null
afterward (proving `_reconcileTrashState`'s `trashTicket` call
actually persisted, not just that `updateTicket` was called with
the right object). Also needed one small fix to an *existing* test
(`'updating an existing row from a file with deletedAt overwrites
the row's previous value'`): its scenario is exactly a
null→non-null `deletedAt` transition, so `reconstruct()` now also
calls `repository.trashTicket` on it — added that stub (plus a
`verify(...).called(1)`) rather than leaving it uncovered.
