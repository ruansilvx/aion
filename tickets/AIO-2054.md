# Presentation layer — tickets feature

- [x] T25. Modify `lib/features/tickets/presentation/cubit/tickets_cubit.dart`
      — embedding regen wired into `createTicket` (always, no prior to
      compare) and `updateTicket` (only when title/description actually
      changed), fire-and-forget. Git projection wired into `createTicket`
      ('created'), `updateTicketStatus`/`changeTicketStatus`
      ('status-changed'), and `trashTicket`/`trashTickets` ('trashed').
      **Corrected from the original task**: git projection is NOT
      triggered from `updateTicket` — design.md's own trigger-event list
      (create/status-change/trash/restore) doesn't include plain content
      edits, and doing so would create a commit per keystroke-adjacent
      edit. Added optional named constructor params
      (`embeddingProvider`/`gitProjector`/`projectRootPath`, all
      nullable, defaulting to no-op) instead of required params, so the
      ~40 existing construction call sites (mostly tests) don't all need
      updating for a feature most don't exercise. **Known gap**: the
      "restored" trigger lives in `TrashCubit`, which has no
      projector/root-path access and wasn't in this task's stated scope
      — flagged, not silently wired in.

      `TicketRepairCompleted`, `TicketRepairFailed`) exactly as specified
      in `design.md`, wrapping `TicketRepairService`.

- [x] T29. Modify `lib/features/tickets/presentation/screens/ticket_detail_screen.dart`
      per design.md §4 — register/unregister the viewed ticket with
      `ActiveTicketViewRegistry` (guarded reads via `_tryReadRegistry`,
      since the registry isn't provided on mobile/web); insert
      `TicketSyncStatusBadge` into the header's trailing `Row` (§4.1);
      insert `TicketNeedsRepairBanner` (wrapped in a per-ticket
      `TicketRepairCubit`) as the first child of the detail body's
      inner `Column` when `needsRepair` (§4.2) — both gated on

      design.md**: the banner's own horizontal margin (§3.1's
      `AionSpacing.sp20`) is dropped to 0 — the screen already wraps
      its body in `Padding(EdgeInsets.fromLTRB(20, 16, 20, 16))`, so
      keeping design.md's margin would double the inset.
