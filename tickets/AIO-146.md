# Design: Anthropic Messages API Provider

## §1. `ProviderId` addition

```dart
// core/contracts/provider_id.dart
enum ProviderId {
  claudeAgentSdk,
  anthropicMessagesApi, // NEW
}
```

Every existing consumer (`AgentModelDescriptor.providerId`,
`ProviderRegistry.providerById`, `SharedPrefsModelRoutingRepository`'s
persisted-id fallback) already switches/iterates generically over
`ProviderId` — no consumer needs a matching code change just to tolerate
a new value, per this enum's own dartdoc ("add a value here... nothing
else in this file changes").

## §2. `AnthropicMessagesApiClient` (`core/agent/anthropic_messages_api_client.dart`)

```dart
class AnthropicMessagesApiClient implements AgentModelClient {
  AnthropicMessagesApiClient(this._dio, this._getApiKey);

  final Dio _dio;
  final Future<String?> Function() _getApiKey;

  @override
  Future<Stream<AgentEvent>> run(AgentRequest request) async {
    if (request.toolsEnabled) {
      // Defensive, not reachable via normal routing today —
      // ModelPhase's tool-access filter never offers this provider's
      // models to the Execution tier. Fails loud rather than silently
      // dropping tool intent.
      return Stream.value(
        const AgentErrorEvent(
          'This provider does not support tool-enabled runs.',
        ),
      );
    }
    final apiKey = await _getApiKey();
    if (apiKey == null || apiKey.isEmpty) {
      return Stream.value(
        const AgentErrorEvent(
          'No API key configured — add one in Settings → Providers.',
        ),
      );
    }
    // POST /v1/messages, stream: true, headers: x-api-key / anthropic-version
    // / content-type, body: {model, max_tokens, stream: true,
    // messages: [{role: 'user', content: request.prompt}]}. Response is
    // consumed via Dio's ResponseType.stream and split into SSE frames
    // ("data: {...}\n\n") the same way ClaudeAgentSdkClient splits
    // stdout into NDJSON lines — a StreamController<AgentEvent> fed by
    // a manual buffer/split loop, not a third-party SSE package (none
    // is already a dependency, and the framing is trivial).
    ...
  }
}
```

SSE event mapping (Anthropic's own streaming event types):
- `message_start` — carries `message.usage.input_tokens`; stashed, not
  emitted directly (no `AgentEvent` maps to "run started").
- `content_block_delta` with a `text_delta` — one `AgentTextEvent` per
  delta.
- `message_delta` — carries cumulative `usage.output_tokens`; stashed.
- `message_stop` — emits the terminal `AgentDoneEvent(inputTokens:
  <stashed>, outputTokens: <stashed>)`.
- A non-2xx response or a mid-stream `error` SSE event — emits
  `AgentErrorEvent`, *except* HTTP 429, which emits
  `AgentOverageDetectedEvent` instead (§4).
- `max_tokens` request field: a fixed, conservative default for this
  round (implementation detail for `/apply` to pick — not a locked
  design decision), since nothing in `AgentRequest` carries an
  output-length hint today.

`toolsEnabled`/`workingDirectory` are otherwise unused by this client —
same shape as `AgentRequest`, no new fields added to it.

## §3. `AnthropicMessagesApiProvider` (`core/agent/anthropic_messages_api_provider.dart`)

```dart
class AnthropicMessagesApiProvider implements AgentProvider {
  AnthropicMessagesApiProvider(this.client);

  @override
  final AgentModelClient client;

  @override
  ProviderId get id => ProviderId.anthropicMessagesApi;

  @override
  String get displayName => 'Anthropic API';

  @override
  Set<ToolAccessTier> get supportedToolAccessTiers =>
      const {ToolAccessTier.noTools};

  @override
  List<AgentModelDescriptor> get availableModels => const [
    AgentModelDescriptor(
      providerId: ProviderId.anthropicMessagesApi,
      modelId: '<real Messages API model id — sourced at /apply time from
                 Anthropic's current model list, not guessed here>',
      label: 'Opus 4.8', // mirrors ClaudeAgentSdkProvider's three labels
      contextWindowTokens: 200000, // parity default; adjust per model if
                                    // /apply-time research says otherwise
    ),
    // ...Sonnet 5, Haiku 4.5 equivalents
  ];

  @override
  ConsumptionSignal describeOverage(String rawMessage) =>
      CostConsumption(rawMessage, null); // first real CostConsumption
                                          // producer — amountUsd stays
                                          // null, the API's 429 body
                                          // doesn't carry a dollar figure

  @override
  String normalizeErrorMessage(String rawMessage) {
    // Same spirit as ClaudeAgentSdkProvider.normalizeErrorMessage:
    // strip vendor-identity mentions ("Anthropic", raw status-line
    // noise), map common status codes (401 → "Invalid API key.", etc.)
    // to a vendor-neutral phrase, fall back to rawMessage unchanged if
    // nothing matches — never hides a real error.
    ...
  }
}
```

Deliberately *not* wrapping `ClaudeAgentSdkClient`'s bridge/subprocess
machinery — this provider has none of that; `client` is a plain
HTTP-backed `AnthropicMessagesApiClient`, constructed directly.

## §4. `describeOverage`'s new real trigger — HTTP 429 handling

`AnthropicMessagesApiClient.run()` distinguishes a 429 response from
every other failure status and emits `AgentOverageDetectedEvent` for it
instead of `AgentErrorEvent` — the existing event already means "a plan
usage-window/rate-limit signal," which a 429 *is*, just from a
token-billed provider instead of a flat-plan one. This is the first
real call site exercising `AgentProvider.describeOverage`'s
`CostConsumption` branch; every existing `onOverageDetected`/
`onConsumptionSignal` reaction (`TicketsCubit`'s "force `gated`",
`ProviderSettingsCubit`'s inline handling) is unchanged — they already
treat the signal as opaque (`signal.message`), so a second variant
reaching them needs no new branching.

## §5. Credential storage

```dart
// features/providers/domain/repositories/anthropic_api_key_repository.dart
abstract interface class AnthropicApiKeyRepository {
  Future<String?> getApiKey();
  Future<void> setApiKey(String? apiKey); // null/empty clears
}
```

Plain reads/writes only, no validation — matches every other repository
in this feature (`ExecutionContextCapRepository`,
`ModelRoutingRepository`). Trimming/empty-string handling is the
consuming Cubit's job (`AnthropicProviderConfigCubit.saveApiKey`), per
`project.md`'s Cubit-domain-logic split.

```dart
// features/providers/data/repositories/secure_storage_anthropic_api_key_repository.dart
class SecureStorageAnthropicApiKeyRepository
    implements AnthropicApiKeyRepository {
  SecureStorageAnthropicApiKeyRepository(this._storage);
  final FlutterSecureStorage _storage;
  static const _key = 'provider_config.anthropic_api_key';

  @override
  Future<String?> getApiKey() => _storage.read(key: _key);

  @override
  Future<void> setApiKey(String? apiKey) => (apiKey == null || apiKey.isEmpty)
      ? _storage.delete(key: _key)
      : _storage.write(key: _key, value: apiKey);
}
```

First real consumer of the `flutter_secure_storage` dependency —
everything else in the app today is `shared_preferences` (nothing else
has been a real secret).

This closes half of the known gap *"No per-provider credential storage
or enabled/disabled state"* — the credential-storage half. The
enabled/disabled half is deliberately not built (see proposal.md's
Non-goals) — reusing `ProviderConnectionStatus`'s existing states
answers the same practical question ("is this provider usable right
now?") without a second, overlapping on/off concept.

## §6. `AnthropicProviderConfigCubit` (`presentation/cubit/`)

Business logic for the new PROVIDERS section — separate from
`ProviderSettingsCubit` (which always tracks *whichever provider
Frontier currently resolves to*, not a specific provider), one cubit
per concern, same split as `AutomationSettingsCubit`/`ModelRoutingCubit`/
`ExecutionContextCapCubit`.

States: `AnthropicProviderConfigLoading` (initial),
`AnthropicProviderConfigReady` (`hasApiKey: bool`, `status:
ProviderConnectionStatus`, `statusMessage: String?` — same shape/meaning
as `ProviderSettingsReady`'s fields, reused rather than inventing new
status vocabulary).

Methods:
- `load()` — reads whether a key is stored (`getApiKey() != null &&
  .isNotEmpty`); emits `status: unknown` regardless — **never**
  auto-pings (see proposal.md's Non-goals — a real API call here would
  be a surprise-billed request on every Settings screen open).
- `saveApiKey(String rawKey)` — trims; empty clears the stored key via
  `setApiKey(null)`; re-emits with `hasApiKey` updated and `status`
  reset to `unknown` (a changed key invalidates any prior test result).
- `testConnection()` — no-ops if `!hasApiKey` or already `checking`.
  Otherwise resolves `AnthropicMessagesApiProvider` via a
  `ProviderRegistry` (constructor dependency, alongside
  `AnthropicApiKeyRepository`) and pings its *cheapest* available model
  (`availableModels.last`, i.e. Haiku — minimizing the cost of a
  connectivity check) with the same `AgentRequest(prompt: 'ping')`
  pattern `ProviderSettingsCubit._runConnectionTest` already uses,
  mapping the result the same way (error → `disconnected` +
  `normalizeErrorMessage`; overage-on-success → `connected` +
  `describeOverage(...).message`).

## §7. Settings screen additions (`presentation/screens/settings_screen.dart`)

New "PROVIDERS" eyebrow section, placed between `_ProviderStatusCard`
and the existing "MODELS" eyebrow — configuring credentials logically
precedes picking which phase uses which provider's model.

`_AnthropicApiKeySection` (new private `StatefulWidget`, same shape as
the existing `_ExecutionContextCapSection`: owns a `TextEditingController`
+ `FocusNode`, `BlocBuilder<AnthropicProviderConfigCubit, ...>`):
- Label + one-line description ("Used for spec-phase, watcher, and
  comment calls billed per token to your own Anthropic account.").
- `AppTextField` with the new `obscureText: true` + a trailing reveal-
  toggle `suffixIcon` (an eye/eye-slash `PhosphorIcon` in a small
  `GestureDetector`, local `bool _revealed` state) — masks the key by
  default, since it's a secret being typed into a plaintext-rendered
  field otherwise.
- A Save `AppButton` (secondary variant, matching `_ProviderStatusCard`'s
  Test Connection button) calling `saveApiKey`.
- A `ProviderConnectionBadge` + Test Connection `AppButton` pair, same
  visual family as `_ProviderStatusCard`'s, disabled when `!hasApiKey`.

`_ProviderStatusCard` changes: `settingsProviderCardTitle`/
`settingsProviderSubline` (currently hardcoded l10n strings) become
derived from the resolved `AgentProvider` instead of literal text.
`ProviderSettingsReady` gains a `providerDisplayName` field (computed by
`ProviderSettingsCubit` at emit time via
`_registry.providerById(model.providerId).displayName`) for the title;
the subline becomes a small `switch` on `ProviderId` (mirroring
`_confidenceLabel`'s existing per-enum switch pattern elsewhere in this
same file) — `claudeAgentSdk` keeps today's "Authenticated via your
Claude plan", `anthropicMessagesApi` reads "Configured via API key".

`_ModelPhaseSection` changes: computes
`final providers = availableModels.map((m) => m.providerId).toSet();`
and passes `itemRowLabel: providers.length > 1 ? (m) =>
'${_providerPrefix(m.providerId)} · ${m.label}' : null` to
`AppDropdown` (§8) — `null` falls back to the plain `itemLabel`,
preserving today's pixel-identical single-provider render for the
Execution tier (Claude-only) and for Frontier/Capable before any
Anthropic model is ever actually selectable... though since this
provider is unconditionally registered, Frontier/Capable will show the
prefix immediately once this ships, not just after the user configures
a key — the dropdown lists *possible* models regardless of
configuration state, same as it always has.

## §8. `AppDropdown<T>` — new optional `itemRowLabel` (design_system/molecules/)

```dart
// additive, default null
final String Function(T)? itemRowLabel;
```

Used only inside the open item panel's `Text` (closed-trigger label
stays `itemLabel(widget.value)`, unchanged — matching the archived
`pluggable-provider-abstraction/design.md` §6.2's explicit constraint
that the closed trigger never shows a provider prefix). Falls back to
`itemLabel` when `null`, so every existing `AppDropdown` call site
(automation triggers, filters, etc.) is unaffected. Precise visual
treatment (muted-prefix color/weight split per that same archived
design.md §6.1) is a `/design-brief`/`/design-sync` question, not fixed
here — this section only fixes the API shape and gating logic.

## §9. `AppTextField` — new optional `obscureText`/`suffixIcon`

```dart
// additive, default false / null
final bool obscureText;
final Widget? suffixIcon;
```

Passed straight through to the wrapped `TextField`/`InputDecoration`,
same additive pattern `keyboardType`/`inputFormatters` already
established for this widget (`dont-spawn-new-chat-ticket-per-execution-trigger`).
`suffixIcon` is the caller's responsibility for styling/interactivity
(mirrors `prefixIcon`'s existing dartdoc) — `_AnthropicApiKeySection`
supplies the reveal-toggle icon+`GestureDetector` itself, this widget
just renders whatever's passed.

## §10. Wiring (`main.dart`, `app_router.dart`)

```dart
// main.dart
RepositoryProvider<Dio>(create: (_) => Dio()),
RepositoryProvider<AnthropicApiKeyRepository>(
  create: (_) => SecureStorageAnthropicApiKeyRepository(
    const FlutterSecureStorage(),
  ),
),
RepositoryProvider<ProviderRegistry>(
  create: (context) => StaticProviderRegistry([
    ClaudeAgentSdkProvider(context.read<AgentBridgeLocator>()),
    AnthropicMessagesApiProvider(
      AnthropicMessagesApiClient(
        context.read<Dio>(),
        () => context.read<AnthropicApiKeyRepository>().getApiKey(),
      ),
    ),
  ]),
),
```

`app_router.dart`'s `/workspace/settings` route gains
`BlocProvider<AnthropicProviderConfigCubit>` alongside its existing four
provider-feature `BlocProvider`s, constructed with
`context.read<AnthropicApiKeyRepository>()` and
`context.read<ProviderRegistry>()`.

## §11. What does not change

- `AgentModelClient`, `AgentRequest`, `AgentEvent` and its five variants
  — untouched.
- `ClaudeAgentSdkClient`, `ClaudeAgentSdkProvider`, `AgentBridgeLocator`,
  `agent_bridge/index.mjs` — untouched.
- `ModelRoutingRepository`, `ModelRoutingCubit`'s filter logic — no code
  change; §7's dropdown behavior is the filter's first *visibly*
  non-no-op moment, not a logic change.
- `AutomationConfidence`/`AutomationContext`/`ExecutionContextCapRepository`
  — untouched.
- `ProviderConnectionStatus` — untouched (reused as-is by
  `AnthropicProviderConfigCubit`, not extended).

# Aion — Anthropic Messages API Provider: Settings Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md), the [Provider Configuration Spec](./Aion%20Provider%20Configuration%20Spec.md) (whose `SettingsScreen`, `ProviderStatusCard`, `ProviderConnectionBadge`, `TestConnectionButton`, and derived-tint tokens this feature reuses verbatim), and the [Per-Phase-Tier Model Routing Spec](./Aion%20Per-Phase%20Model%20Routing%20Spec.md) (whose tier `AppDropdown` item rows this feature adds a prefix to). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name.

**No Material widgets or types anywhere.** Every surface below is `DecoratedBox` / `Container` / `Row` / `Column` / `Padding` / `GestureDetector` / `MouseRegion` / `AnimatedScale` / `CustomPaint`, never `Card`, `ElevatedButton`, `Scaffold`, `ThemeData`, `ColorScheme`, `DropdownButton`, `AppBar`, `ListTile`, `CircularProgressIndicator`, `TextField`'s Material decoration defaults, or `InkWell`.

**Themes:** Arctic (light, celestial cold) and Obsidian (dark, abyssal cold). All layout, dimensions, spacing, radius, and typography are **identical** between themes; only color tokens differ, resolved from the active `AionColors`. `isDark = theme.brightness == Brightness.dark` (Obsidian).

This change lands entirely on the existing `/workspace/settings` screen. No new route, no new screen. Four component-level additions:

1. **`ProvidersSection`** (new) — a bordered credential-entry panel between the `ProviderStatusCard` and the "MODELS" eyebrow (§2).
2. **`ObscuredTextField`** (new atom variant) — masked API-key input with a reveal toggle (§3).
3. **`SaveKeyButton`** (primary-variant instance) — the section's submit action (§4).
4. **Connection-status + Test Connection pairing** with a **no-key-saved** presentation, reusing `ProviderConnectionBadge` + `TestConnectionButton` (§5).
5. **Dynamic `ProviderStatusCard`** — the existing card's title/subline become variable text (§6).
6. **Provider-prefixed dropdown item row** — an open-panel-only addition to the tier `AppDropdown` (§7).

Mockups: [Aion Anthropic API Provider Mockups](./Aion%20Anthropic%20API%20Provider%20Mockups.dc.html).

## 1. Foundations added

### 1.1 Provider identity model

Two providers are now registered. Each carries a display name and a subline; both feed the dynamic status card (§6) and the dropdown-row prefix (§7).

```dart
enum ModelProvider { claudeAgentSdk, anthropicApi }

extension ModelProviderDisplay on ModelProvider {
  String get displayName {
    switch (this) {
      case ModelProvider.claudeAgentSdk: return 'Claude Agent SDK';
      case ModelProvider.anthropicApi:   return 'Anthropic API';
    }
  }
  String get subline {
    switch (this) {
      case ModelProvider.claudeAgentSdk: return 'Authenticated via your Claude plan';
      case ModelProvider.anthropicApi:   return 'Billed per token to your own Anthropic account';
    }
  }
}
```

### 1.2 Credential-save state

Drives the §5 no-key-saved presentation. Orthogonal to `ProviderConnectionState` (Provider Configuration §1.1): a key must be saved before a connection test can run.

```dart
enum ApiKeyState { none, saved }
```

`none` = no key has ever been saved for this provider (fresh install / cleared). `saved` = a key string is persisted (masked at rest).

### 1.3 No new color, type, radius, or spacing tokens

Every value below resolves from an existing `AionColors` / `AionText` / `AionRadius` / `AionSpacing` member or the `AionColorsHubTokens` derived tints already defined in Provider Configuration §1.2. The masking glyph (§3.1) is the literal bullet character `\u2022`, not a color token. The only structural additions are the two enums above.

## 2. `ProvidersSection`

A bordered credential-entry panel that sits **between the `ProviderStatusCard` and the "MODELS" eyebrow**, inside the existing `SettingsScreen` content column (max-width 560, centered — Provider Configuration §2.1). It takes its own `surface` panel — matching the `ProviderStatusCard` chrome exactly — rather than sitting as bare rows like the MODELS section, because it groups an input, a submit, and a test cluster that read as one credential unit.

### 2.1 Vertical rhythm within the settings column

The settings column's inter-zone gap is `AionSpacing.sp24` (24). This section is one more zone in that rhythm:

```
ProviderStatusCard
  ↓ 24
ProvidersSection          ← new
  ↓ 24
MODELS eyebrow + tiers
```

### 2.2 Container

Byte-identical chrome to `ProviderStatusCard` (Provider Configuration §3.1):

| Property | Value |
|---|---|
| Fill | `AionColors.surface` |
| Border | `1px solid AionColors.border` |
| Radius | `AionRadius.lg` (12) |
| Padding | `EdgeInsets.all(18)` |
| Shadow | none (Arctic may use the base spec's optional `0 1px 2px rgba(20,34,48,0.07)`) |

Internal structure: `Column`, `crossAxisAlignment: stretch`, `gap: AionSpacing.sp16` (16) between (a) the identity block, (b) the field, and (c) the action row.

### 2.3 Identity block

`Column`, `crossAxisAlignment: start`, `gap: AionSpacing.sp4` (4):

- **Eyebrow** — `"PROVIDERS"`, `AionText.caption` (JetBrains Mono 11 / w600 / +1.54, UPPERCASE string), color `AionColors.textMuted`.
- **Title** — `"Anthropic API"`, `AionText.cardTitle` at 15px w700 override, color `AionColors.textPrimary`.
- **Description** — `"Used for spec-phase, watcher, and comment calls billed per token to your own Anthropic account."`, `AionText.bodySm` (13.5 / w400), color `AionColors.textSecondary`, `height: 1.5`, wraps freely.

### 2.4 Field block

- **Field label** — `"API Key"`, `AionText.label` (12 / w700), color `AionColors.textSecondary`, sits above the field with `gap: AionSpacing.sp8` (8).
- **Field** — the `ObscuredTextField` (§3), full-bleed to the panel's inner width.

### 2.5 Action row

`Row`, `crossAxisAlignment: center`, `mainAxisAlignment: spaceBetween`, `gap: AionSpacing.sp12` (12):

- **Leading** — the `SaveKeyButton` (§4), `mainAxisSize: min`.
- **Trailing** — the connection cluster (§5): `Row`, `mainAxisSize: min`, `crossAxisAlignment: center`, `gap: AionSpacing.sp12` (12) → `[ ProviderConnectionBadge ][ TestConnectionButton ]`.

On a narrow window the row may wrap (`Wrap`, `runSpacing: 12`, `spacing: 12`) with Save leading the first run; geometry of each child is unchanged when wrapped.

## 3. `ObscuredTextField`

A masked-input variant of the base text-field atom (base spec §2.5). Outer chrome is **byte-identical** to the atom — only the character masking and the trailing reveal toggle are new.

### 3.1 Masking

- Rendered value while hidden: each character replaced by the bullet glyph `\u2022` (`•`), same size/weight/color as normal input text (`AionText.bodySm` at 14px, `AionColors.textPrimary`). In Flutter: `TextField(obscureText: !revealed, obscuringCharacter: '\u2022')` inside the app's existing non-Material field wrapper — never Material's default decoration.
- Placeholder (empty field): `"sk-ant-…"`, `AionText.bodySm` at 14px, color `AionColors.textMuted`. Placeholder is never masked.
- Revealed value shows the plaintext string (e.g. `sk-ant-api03-Xy8f…9Q2a`).

### 3.2 Outer chrome (unchanged from base §2.5)

| Property | Value |
|---|---|
| Fill | `AionColors.surface` |
| Radius | `AionRadius.lg` (12) |
| Padding | `EdgeInsets.fromLTRB(14, 12, 8, 12)` — right inset reduced to seat the toggle |
| Layout | `Row`, center → `[ Expanded(input) ][ reveal toggle ]`, `gap: AionSpacing.sp8` (8) |

The right padding drops from the atom's 14 to **8** only to host the toggle's own hit-target padding; the input text's optical left edge (14) is unchanged.

### 3.3 Field states

| State | Border | Extra |
|---|---|---|
| Default | `1px AionColors.border` | — |
| Hover | `1px AionColors.borderStrong` | pointer cursor over the input |
| Focused | `1.5px AionColors.primary` | focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), spreadRadius: 3, blurRadius: 0)` |
| Error | `1.5px AionColors.danger` | ring `BoxShadow(color: danger.withOpacity(isDark ? 0.30 : 0.16), spreadRadius: 3, blurRadius: 0)`; error text below (§3.5) |
| Disabled | `1px AionColors.border`, panel `opacity: 0.45` | `IgnorePointer`; toggle also dimmed |

The `1.5px` focused/error border insets `0.5px` vs. the `1px` default (`BorderSide` drawn inside) so the field does not resize between states.

### 3.4 Reveal toggle

A trailing `GestureDetector` + `MouseRegion` over a Phosphor glyph, inset from the right edge. Consistent with the app's Phosphor icon usage.

| Property | Value |
|---|---|
| Hit target | `32×32`, centered glyph |
| Padding inside field | trailing edge 6px from the panel's inner right (the field's 8px right padding − the 2px the 32px box overhangs the 20px glyph) |
| Icon (hidden) | Phosphor `eye` |
| Icon (revealed) | Phosphor `eye-slash` |
| Icon size | 20px |
| Radius (hover fill) | `AionRadius.iconBtnSm` (8) |

**Toggle states** (independent of, and layered over, the field state):

| Toggle state | Icon color | Fill |
|---|---|---|
| Default (field default/hover) | `AionColors.textMuted` | transparent |
| Hover (pointer over toggle) | `AionColors.textSecondary` | `AionColors.surfaceHover` |
| Active / revealed (toggled on) | `AionColors.primary` | transparent (icon is `eye-slash`) |
| Field focused (toggle not hovered) | `AionColors.textSecondary` | transparent |
| Pressed | `AionColors.textSecondary` | `AionColors.surfaceHover`, `AnimatedScale(0.94, 80ms)` |
| Disabled | `AionColors.textMuted`, panel opacity 0.45 carries it | transparent |

Behavior: tap toggles `revealed`; while revealed the glyph is `eye-slash` and colored `primary` to signal the value is exposed. (A press-and-hold "reveal only while held" variant is acceptable but not required; the tap-toggle is the specified default.)

### 3.5 Error text

When the field is in error, a single line sits below it with `gap: AionSpacing.sp4` (4): `AionText.bodySm` at 12.5px, color `AionColors.danger`. Example copy: `"That doesn't look like an Anthropic key — it should start with sk-ant-."` Present only in the error state; absent (no reserved space) otherwise.

## 4. `SaveKeyButton`

The section's submit action — the **Primary** button variant (base spec §2.1), distinct from the neutral secondary `TestConnectionButton`, because saving the credential is the affirmative action of this panel. `GestureDetector` over a `DecoratedBox`; `AnimatedScale` for press.

### 4.1 Geometry

| Property | Value |
|---|---|
| Radius | `AionRadius.md` (10) |
| Padding | `EdgeInsets.symmetric(horizontal: 17, vertical: 10)` |
| Label | `"Save"`, `AionText.button` (14 / w700) |
| Layout | `Row`, `mainAxisSize: min`, `gap: AionSpacing.sp8` (8) (icon + label while saving) |

### 4.2 States

| State | Fill | Text | Shadow | Extra |
|---|---|---|---|---|

## 5. Connection cluster — `ProviderConnectionBadge` + `TestConnectionButton`

Both widgets are reused verbatim from Provider Configuration (§4 badge, §5 button) — same geometry, same four badge states, same five button states, same tints. **No new badge state is introduced.** This section specifies only the **no-key-saved pairing** (`ApiKeyState.none`), which is a *presentation of the existing pieces*, not a new state.

### 5.1 Key saved (`ApiKeyState.saved`) — unchanged

The badge shows the live `ProviderConnectionState` (`unknown` → `checking` → `connected` / `disconnected`) exactly as Provider Configuration §4 specifies; the `TestConnectionButton` is fully interactive (disabled only transiently while `checking`, §5.2 of that spec). This is the same pairing already shipping on the status card.

### 5.2 No key saved (`ApiKeyState.none`) — new presentation

Before any key is saved, a connection test is meaningless. Both pieces render in a **disabled-looking** presentation without inventing a badge state:

- **Badge** — render the existing `unknown` state (no fill, no border, hollow-circle `\u25CB` glyph 13px `textMuted`) but with **label `"NO KEY"`** in place of `"NOT TESTED"`, same `AionText.chip`, same `textMuted`. It reads as "nothing to report yet," matching `unknown`'s quiet register; no new fill, border, or color.
- **Test Connection button** — the existing `TestConnectionButton` **Disabled** state verbatim (fill `surfaceHover`, `opacity: 0.45`, `1px borderStrong`, label `"Test Connection"` `textPrimary`, gestures ignored). Identical to the checking-lockout disabled look; here it persists until a key is saved rather than being transient.

Transition: the moment Save succeeds (`ApiKeyState.none → saved`), the badge label reverts to `"NOT TESTED"` (`unknown`) and the Test Connection button becomes interactive.

| Pairing state | Badge | Test Connection button |
|---|---|---|
| `none` (no key saved) | `unknown` chrome, label `"NO KEY"`, `textMuted` | Disabled (opacity 0.45), ignored gestures |
| `saved` + `unknown` | `unknown`, label `"NOT TESTED"` | Default (interactive) |
| `saved` + `checking` | `checking` (spinner + `CHECKING`) | Disabled (transient, opacity 0.45) |
| `saved` + `connected` | `connected` (✓ + `CONNECTED`) | Default (interactive) |
| `saved` + `disconnected` | `disconnected` (△ + `NOT CONNECTED`) | Default (interactive) |

## 7. Provider-prefixed dropdown item row

An **open-panel-only** addition to the tier `AppDropdown` (Per-Phase-Tier Model Routing §2.4). When a tier's model list spans more than one provider, each open-panel row shows a small muted provider-name prefix ahead of the model name, on the same single line, so the user can disambiguate before selecting.

### 7.1 Hard constraints (restated)

- The **closed trigger** never shows a prefix — always the bare model name, unchanged from today (Per-Phase §2.3).
- The prefix is **inline on the same single line** as the model name — no second line, no row-height growth.
- Selected / hover / default row fill and the model-name color/weight follow the existing item-row states **unchanged** (Per-Phase §2.4.2). The prefix carries **no state of its own** — it stays one muted color across default, hover, and selected rows.

### 7.2 Row geometry (byte-identical to today)

Unchanged from Per-Phase §2.4.2 — restated here to certify no drift:

| Property | Value |
|---|---|
| Layout | `Row`, `mainAxisAlignment: spaceBetween`, `crossAxisAlignment: center` |
| Padding | `EdgeInsets.symmetric(horizontal: 13, vertical: 9)` |
| Radius | `AionRadius.sm`/`iconBtnSm` (8) |
| Height | intrinsic — **identical** to a plain no-prefix row (prefix + model name share one `AionText.bodySm` 14px line box; the prefix adds no vertical metric) |

### 7.3 Leading label group (the only new markup)

The leading side becomes a single-line `Row`, `mainAxisSize: min`, `crossAxisAlignment: baseline` (`textBaseline: alphabetic`), containing three inline runs — prefix, separator, model name — that together replace the former single model-name `Text`:

| Run | Text | Style | Color |
|---|---|---|---|
| Prefix | provider `displayName` (e.g. `"Claude Agent SDK"`) | `AionText.bodySm` at 14px, **w500** | `AionColors.textMuted` (all row states) |
| Separator | `" · "` (middle dot `\u00B7`, one space each side) | `AionText.bodySm` at 14px, w500 | `AionColors.textMuted` |
| Model name | model `displayName` (e.g. `"Opus 4.8"`) | existing per-state style: default/hover `bodySm` 14px w600 `textPrimary`; selected w700 `primary` | per existing row state |

Prefer a single `Text.rich` / `RichText` with three `TextSpan`s over three sibling `Text` widgets, so the whole label ellipsizes as one line (`maxLines: 1`, `overflow: ellipsis`) and the baseline is guaranteed shared. The trailing check glyph on the selected row (14px `primary`, Per-Phase §2.4.2) is unchanged and sits opposite the label group via `spaceBetween`.

### 7.4 When to show the prefix

The prefix appears **only** when the tier's option list contains models from more than one provider. If every option in an open panel belongs to a single provider, render the plain no-prefix rows exactly as today (no prefix, no separator). This is a per-panel decision, not per-row: either all rows in a panel carry a prefix or none do, so the model-name column stays optically aligned.

### 7.5 Example (Frontier tier, two providers registered)

Open panel, `spaceBetween` rows, prefix in `textMuted`, model name in per-state color:

```
Claude Agent SDK · Opus 4.8            ✓   ← selected (name = primary w700, ✓ primary)
Anthropic API · Opus 4.5                   ← default (name = textPrimary w600)
Claude Agent SDK · Sonnet 5                ← hover (surfaceHover fill)
Anthropic API · Sonnet 4.5
```
