# Post-verification fixes

Two findings from the initial `/verify` pass, fixed and re-verified clean.

- [x] T36 — `lib/core/widgets/app_confirm_dialog.dart`: replace
  `showAppConfirmDialog`'s `bool isDestructive` parameter with a required
  `ConfirmDialogTone` enum (`reversible` | `destructive`), with dartdoc.
  `_leadingIcon` now renders a rounded-square `primary`-tinted disc +
  trash glyph for `reversible` vs. a circular `danger`-tinted disc +
  warning glyph for `destructive`; `_confirmButton` renders
  `AppButtonVariant.primary` vs. `.destructive` to match. Fixes the
  CRITICAL finding that every dialog rendered with the destructive
  treatment regardless of tone, undermining design.md §6's explicit
  "Move to Trash" de-escalation (rounded-square primary icon, primary
  button) versus "Delete forever" (circular danger icon, destructive
  button). Updated call sites:
  `lib/features/tickets/presentation/widgets/ticket_overflow_menu.dart`
  and `lib/features/tickets/presentation/screens/tickets_list_screen.dart`
  now pass `tone: ConfirmDialogTone.reversible`;
  `lib/features/tickets/presentation/screens/trash_screen.dart` passes
  `tone: ConfirmDialogTone.destructive` for both per-tile permanent
  delete and empty-trash. Per design.md §6, §11.
- [x] T37 — Fix the WARNING finding that `TicketsCubit.previewTrashCount`
  could undercount relative to what `TicketRepository.trashTickets`
  actually moves, in a mixed live/already-trashed subtree (e.g. a child
  trashed individually, then its still-live parent trashed later) — the
  cubit's `_descendantIds` walk sourced from `getAllTickets()` (live
  only) never saw the already-trashed descendants that
  `TicketDao.getDescendantIds` (unfiltered) would still cascade to.
  Moved `previewTrashCount` from `TicketsCubit` to
  `TicketRepository`/`DriftTicketRepository`
  (`lib/features/tickets/domain/repositories/ticket_repository.dart`,
  `lib/features/tickets/data/repositories/drift_ticket_repository.dart`),
  sharing a new private `_resolveTrashCascade` helper with
  `trashTickets` so the preview is mechanically guaranteed to match the
  actual cascade. `TicketsCubit.previewTrashCount`
  (`lib/features/tickets/presentation/cubit/tickets_cubit.dart`) now
  just delegates to the repository. Dartdoc updated on all three.
  Updated/added tests:
  `test/features/tickets/cubit/tickets_cubit_test.dart` (delegation, not
  cascade math), `test/features/tickets/data/repositories/drift_ticket_repository_test.dart`
  (new `previewTrashCount` group, including a regression test for the
  mixed live/trashed-descendant case that previously diverged).
