# `TicketsCubit` (`lib/features/tickets/presentation/cubit/tickets_cubit.dart`)

- [x] `_evaluateDecisionGraph`: add an optional `{AgentSessionHandle?
      session}` named parameter; when non-null, merge it (plus
      `_askAgentJudgment`) into the `DecisionEvalContext` passed to
      `evaluateDecisionGraph` — every existing call site that doesn't
      pass `session` keeps today's `null`/`null` behavior unchanged.
      Update the method's existing dartdoc (currently describes the
      "no-repository-fallback still enforces the safety cap" contract)
      to also cover the new parameter.
- [x] Add `_askAgentJudgment(AgentSessionHandle, String)` per design.md
      §7's exact implementation — resolves the provider via
      `_providerRegistry`, guards `supportsSessionResume`, issues the
      forked/resumed `run()` call, parses yes/no, returns `null` on any
      failure mode. Full dartdoc.
- [x] `_onToolCallFor(Ticket chat)`'s returned closure: add the 4th
      `AgentSessionHandle? session` parameter, threaded to
      `_handleCreateTicketToolCall`/`_handleAddLinkToolCall`/
      `_handleBranchToolCall`/`_handleCloseBranchToolCall` (all four,
      for signature symmetry — see next task for which of them actually
      use it).
- [x] `_handleCreateTicketToolCall`/`_handleAddLinkToolCall`/
      `_handleBranchToolCall`: add the `AgentSessionHandle? session`
      parameter; pass `session: session` into each one's existing
      `_evaluateDecisionGraph(AutomationContext.ticketCreation |
      .ticketLinking | .chatBranching, ...)` call in their
      `AutomationConfidence.auto` branch. `_handleCloseBranchToolCall`
      gains the parameter but doesn't use it (see design.md §4's note on
      why `chatBranching`'s pair stays symmetric in signature even though
      only one call site's condition realistically triggers per turn).
- [x] `handleChatToolCall` (public passthrough): add the 4th parameter,
      forwarded into `_onToolCallFor(chat)(...)` unchanged.
