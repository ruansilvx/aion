# 6. `TicketDbReconstructionService` — trash-aware existence check + reconciliation

- [x] `lib/features/tickets/data/services/ticket_db_reconstruction_service.dart`:
      - `reconstruct`: build `existing` from
        `[...await _repository.getAllTickets(), ...await
        _repository.getTrashedTickets()]` instead of `getAllTickets()`
        alone.
      - In the existing-row branch (after `await
        _repository.updateTicket(ticket)`), call a new
        `_reconcileTrashState(existingRow, ticket)` (see below) — needs
        the pre-update `existingRow` (the `Ticket` from
        `existingByTicketId` before this iteration overwrites it), not
        the newly-built `ticket`.
      - Add `_reconcileTrashState(Ticket existing, Ticket parsed)`: if
        `parsed.deletedAt != null && existing.deletedAt == null`, call
        `await _repository.trashTicket(existing.id)`; else if
        `parsed.deletedAt == null && existing.deletedAt != null`, call
        `await _repository.restoreTicket(existing.id)`; else no-op.
        Dartdoc per design.md's proposed text (cross-reference
        `TicketParentTrashService.applyFromParsedFields`'s identical
        detection logic).
      - No change to `_buildTicket` — it already parses `deletedAt`
        correctly.
      - Update the class-level dartdoc's `deletedAt`-round-trip claim to
        describe the corrected (now actually true) behavior, replacing
        the current inaccurate claim that `updateTicket` alone handles
        it.
