# Tasks: Ticket-graph and embedding context enrichment for spawned chats

Ordered checklist. Each task that creates/modifies a Dart file includes
its documentation (dartdoc comments + file header) as part of that same
task — see `aion-arch/CLAUDE.md`'s Documentation rule.

- [x] 1. Create `lib/features/tickets/presentation/cubit/ticket_context_enricher.dart`:
      new `TicketContextEnricher` class per `design.md` §1 — constructor
      taking `TicketRepository` plus optional `TicketLinkRepository`/
      `EmbeddingProvider`, `relatedTicketsSection(Ticket ticket)`
      implementing the structured walk (ancestor chain + direct
      `TicketLink` rows) and the embedding-similarity walk (threshold
      `0.75`, top-K cap `5`, description snippet cap `400` chars), per
      §1.1's five-step algorithm. Full file header comment, class-level
      dartdoc, and a dartdoc on `relatedTicketsSection` covering its
      empty-string contract.

- [x] 2. Wire `TicketContextEnricher` into `lib/features/tickets/presentation/cubit/tickets_cubit.dart`:
      add `late final TicketContextEnricher _contextEnricher;` field
      (with a dartdoc mirroring `_estimationSuggester`'s own, per
      `design.md` §2) and construct it in the constructor body next to
      `_estimationSuggester`, wired to the same `_repository`/
      `linkRepository`/`embeddingProvider` already threaded through.

- [x] 3. Update `_assembleExecutionContext` in `tickets_cubit.dart`: call
      `_contextEnricher.relatedTicketsSection(task)` and append the
      result (when non-empty) after the title/description block, before
      `## Project conventions`, per `design.md` §2.1. Update its existing
      dartdoc to describe the new `## Related tickets` section instead of
      implying title/description/conventions is the whole context.

- [x] 4. Update `_assembleStageContext` in `tickets_cubit.dart`: call
      `_contextEnricher.relatedTicketsSection(parent)` and append the
      result (when non-empty) after the title/description block, before
      the stage-specific `switch` branch, per `design.md` §2.2. Update
      its existing dartdoc — including removing the now-inaccurate "No
      embeddings, no repo-map-lite involvement" line — to describe the
      new section and note it's shared by `_createStageChat`,
      `_runStageChatTurn`, and `retryDesignSync`.

- [x] 5. Add `test/features/tickets/presentation/cubit/ticket_context_enricher_test.dart`:
      unit tests per `design.md` §4's full list (empty-graph → `''`,
      multi-level ancestor chain ordering, cyclic-`parentId` termination,
      each `TicketLinkType` rendering correctly from both source and
      target side via `.inverse`, threshold inclusion/exclusion,
      structured/embedding dedup, top-K capping, description truncation
      and the `(no description)` fallback).

- [x] 6. Update `test/features/tickets/cubit/tickets_cubit_test.dart`:
      add one case each for `_assembleExecutionContext` and
      `_assembleStageContext` (via their existing public entry points)

      `TicketContextEnricher` has content to contribute, and one case
      per method asserting today's exact plain output is preserved when
      it returns `''`.
