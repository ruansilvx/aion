# Multi Select Ticket List Filters

# Proposal: Multi-select filters for the ticket list

## What

Replace the ticket list's three single-select `AppDropdown` filters
(Status/Type/Priority) with one combined "Filters" popover offering
multi-select checkbox groups per field, plus a removable chip row showing
the active selection. Selections persist per project across app restarts.

Concretely:

- A single "Filters" trigger button (showing an active-count badge)
  replaces the three separate dropdown buttons on `TicketsListScreen`.
- Tapping it opens `TicketFilterPopover` — a new overlay widget with
  three checkbox groups (Status, Type, Priority). Checking/unchecking a
  box re-runs the search immediately, same as today's dropdown
  `onChanged` behavior — no separate "Apply" step.
- Selections within one field combine as OR (`todo` or `backlog`);
  selections across fields combine as AND (matching the existing
  cross-field behavior) — Jira's standard filter semantics, scaled down
  for a solo-dev tool.
- Active selections also render as a row of removable `AppFilterChip`s
  below the trigger — visibility and one-tap removal, not a second way
  to add filters.
- The selected sets persist per project (`SharedPreferences`, project-
  id-prefixed keys) and are restored the next time that project's
  ticket list is opened, including after an app restart.

## Why

`tickets.md`'s own "Known gaps" section flags this directly: *"The
ticket list's status/type/priority filters are single-select only... a
user can filter to `backlog` or `todo`, not `backlog` OR `todo` in one
dimension."* Confirmed directly with the user (see
`aion-arch/ideas/multi-select-ticket-list-filters.md`): all three fields
are affected, not just one, and the current single-select constraint is
a real day-to-day friction point.

## Scope

In scope:
- Multi-select for Status, Type, and Priority on the main ticket list
  (`TicketsListScreen`), in both list and board view (board view's
  existing client-side `story`-plus-`isExecutable` restriction stays
  layered on top, unchanged).
- New combined popover + chip-row UI, a new dedicated widget (not an
  `AppDropdown` extension).
- Per-project persistence of the selected filter sets.

Out of scope (deliberately deferred, per the idea file's "Open
questions"):
- The separate known gap "no user-facing sort control on the ticket
  list" — not touched here.
- `AppDropdown`'s own bare-`GestureDetector` overlay-row keyboard-focus
  bug — stays unfixed; this change avoids it entirely by not extending
  `AppDropdown`.
- The reparent picker (`TicketParentPicker`) and any other
  `AppDropdown<T>` consumer — untouched; this is additive to the main
  ticket list only.
- A "Clear all filters" control — not requested; removal stays per-chip
  or per-checkbox, consistent with how the existing search/filter row
  already has no such control.

## Known gap resolved

Resolves the "single-select only" known gap in
`aion-arch/specs/tickets.md`'s "Known gaps" section.
