# Spec Delta: Reject Epic Reparenting

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (14/15 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

None. No new public API surface — this change reuses the existing
`TicketsErrorReason.invalidParent` enum value and the existing
`ticketInvalidParentError` l10n string.

## MODIFIED

- **`TicketsCubit.updateTicketParent`** — now also rejects any non-null
  `newParentId` when `ticket.type == TicketType.epic`, using the same
  `TicketsError(reason: TicketsErrorReason.invalidParent)` →
  re-emitted `TicketDetailLoaded` pattern already used for self-parent
  and cycle rejection. Clearing an epic's parent to `null` is unaffected
  (the guard only fires when `newParentId != null`).

- **`TicketDetailScreen`** — the `TicketParentPicker` row (and its
  preceding `sp8` spacer) is now conditionally omitted entirely when
  `ticket.type == TicketType.epic`. Epic tickets show no parent-picker
  affordance at all — no "+ PARENT" placeholder, no way to open the
  overlay. Non-epic tickets are unaffected.

- **`aion-arch/specs/tickets.md`'s "Known gaps" bullet** — "Reparenting
  enforces only structural validity (no self-parent, no cycles) — there
  is no type-compatibility rule (e.g. nothing prevents an `epic` from
  becoming the child of a `task`)" is narrowed by this change: the
  epic-specific case (which directly contradicted `project.md`'s "epics
  have no parent" invariant) is closed. On `/archive`, this bullet is
  reworded to state only the remaining, still-open scope — no general
  type-compatibility matrix exists for non-epic combinations
  (story/task/resource/page/chat). See
  `aion-arch/ideas/define-type-compatibility-matrix.md` for that broader
  follow-up.

## REMOVED

None.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **`TicketRepository.updateTicketParent`** — still performs no
  validation of its own. The epic invariant lives in `TicketsCubit`
  only, per `project.md`'s Cubit-level domain-logic convention. No
  repository or `TicketDao` change.
- **`TicketsCubit.getValidParentCandidates`** — unchanged. Still returns
  every non-self, non-descendant ticket regardless of type — a `story`
  or `task` choosing an epic as its parent remains valid and unaffected.
- **`TicketsErrorReason`** — no new enum value. Reuses `invalidParent`.
- **Localization** — no new l10n keys. Reuses `ticketInvalidParentError`.
- **`CreateTicketScreen`** — untouched; still doesn't expose `parentId`
  in the create form (separate, already-flagged known gap).
- **No schema migration.** No column or nullability change.
