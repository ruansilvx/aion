# Spec Delta: Tickets — Detail Status Editing

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (23/27 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`. Section references below match
that file's headings.

## ADDED

### `TicketsCubit` (under "`TicketsCubit` / `TicketsState`")

- **`changeTicketStatus(Ticket ticket, TicketStatus status)`** — the
  detail-screen write path for status changes. Calls
  `TicketRepository.updateTicketStatus(ticket.id, status)` (the same
  repository method the board's drag/`MoveToStatusMenu` path calls), then
  re-fetches via `getTicketById` and emits `TicketDetailLoaded` with the
  refreshed ticket, or `TicketsError` on failure. Distinct from
  `updateTicketStatus(String id, TicketStatus status)` (the board's
  method): that method emits list-shaped `TicketStatusUpdating`/
  `TicketStatusUpdated` states for the board's optimistic drag feedback,
  which `TicketDetailScreen`'s state switch does not render. No new
  `TicketsState` subclass — reuses `TicketDetailLoaded`, the same pattern
  `updateTicket` and `updateTicketParent` already follow for their own
  fields.

### Localization (under "Localization")

- **`ticketDetailChangeStatus`** — `"Change status"`. Accessibility label
  for the new status `SelectionMenu<TicketStatus>` trigger, parallel to
  `ticketDetailChangePriority`/`ticketDetailChangeType`.

## MODIFIED

### `TicketDetailScreen` (under "Screens")

- `status` (`StatusIndicator`) is no longer read-only. It is now the
  trigger of a `SelectionMenu<TicketStatus>` overlay picker, positioned
  identically (same cell in the type/status `Row`), styled identically
  (unchanged `StatusIndicator` widget as the trigger), and following the
  exact same interaction/accessibility pattern as the adjacent `priority`
  (`SelectionMenu<TicketPriority>`) and `type` (`SelectionMenu<TicketType>`)
  pickers on the same screen: tap or `ActivateIntent` opens an overlay
  listing `TicketStatus.values` (excluding the current status), selecting
  one calls `TicketsCubit.changeTicketStatus(ticket, status)`.
- Previous text: *"`status` (`StatusIndicator`) remains read-only here —
  status editing stays board-only, via `MoveToStatusMenu`/drag."* This
  sentence is removed; status is now editable from both the detail screen
  and the board.

## UNCHANGED (explicitly, to prevent misreading this as broader than it is)

- **`TicketRepository.updateTicketStatus`**, **`TicketDao.updateFields`**,
  **`DriftTicketRepository.updateTicketStatus`** — no changes. The new
  Cubit method calls this existing repository method as-is.
- **`TicketRepository.updateTicket`** — still deliberately excludes
  `status` from the fields it persists, exactly as documented today.
- **Board view** (`TicketBoardView`, `BoardColumn`, `TicketBoardCard`,
  `MoveToStatusMenu`) and the existing
  `TicketsCubit.updateTicketStatus(String id, TicketStatus status)`
  method it calls — no changes. Both the drag path and
  `MoveToStatusMenu` continue to work exactly as before.
- **Accessibility** — the new picker inherits `SelectionMenu<T>`'s existing
  `Semantics(button: true, ...)` + `FocusableActionDetector` +
  `ActivateIntent` treatment, the same as `priority`/`type`. No new
  accessibility gap is introduced; the existing "Known gaps" entry about
  overlay-list items lacking Hover/Focused/Pressed visual states
  (`SelectionMenu`/`MoveToStatusMenu`/`TicketOverflowMenu`) applies here
  too, unchanged — this change doesn't add or remove from that gap.
