# Design: PR metadata parsing and persistent notification center

All file paths are relative to the `aion` repo. Line numbers are as of this proposal's `/explore` verification pass and will drift once `/apply` starts editing — treat them as locators, not guarantees.

## 1. PR metadata parsing

### 1.1 `GitHubCliClient.openPullRequest` (`lib/core/git/github_cli_client.dart`)

Returns a record instead of a bare `String`, so the PR number is available without a second parse of the URL at every call site:

```dart
/// Runs `gh pr create ...` in [rootPath]. Returns the created PR's URL
/// (parsed from `gh pr create`'s stdout, its last non-empty line, as
/// before) plus its number, parsed from that same URL's last path
/// segment — `gh pr create` never prints the number on its own (`gh pr
/// create --help` documents it as printing only the URL; unlike `gh pr
/// view`/`gh pr list`, `pr create` has no `--json` flag). Throws a
/// [ProcessException] on failure, unchanged.
Future<({String url, int number})> openPullRequest({
  required String rootPath,
  required String branch,
  required String title,
  required String body,
}) async {
  final result = await Process.run('gh', [
    'pr', 'create', '--title', title, '--body', body, '--head', branch,
  ], workingDirectory: rootPath);
  if (result.exitCode != 0) {
    throw ProcessException('gh', ['pr', 'create'], result.stderr.toString());
  }
  final url = result.stdout.toString().trim().split('\n').last;
  final number = int.parse(url.split('/').last);
  return (url: url, number: number);
}
```

`int.parse` is intentionally unguarded — if `gh`'s URL format ever changes shape, this should fail loudly (caught by `_runCodingExecution`'s existing surrounding `catch`, surfaced as a normal execution failure) rather than silently produce a wrong number.

### 1.2 `GitRepositoryClient.changedFileCount` (`lib/core/git/git_repository_client.dart`) — new method

```dart
/// Runs `git diff --name-only <baseBranch>...<branch>` in [worktreePath]
/// and returns the count of changed files. Computed locally rather than
/// via `gh pr view --json files` (a second network call, with a risk of
/// eventual-consistency lag immediately after `gh pr create` returns) —
/// the worktree already has everything needed on disk. Called just
/// before `push` in `TicketsCubit._runCodingExecution`, from inside the
/// worktree `push` itself already runs from. Added for
/// `aion-arch/changes/pr-metadata-and-notification-center`.
Future<int> changedFileCount(
  String worktreePath,
  String baseBranch,
  String branch,
) async {
  final result = await _runChecked(
    ['diff', '--name-only', '$baseBranch...$branch'],
    worktreePath,
  );
  final output = result.stdout.toString().trim();
  return output.isEmpty ? 0 : output.split('\n').length;
}
```

`baseBranch` — `_runCodingExecution` doesn't currently know the repo's default branch by name (`gh pr create` resolves it itself, same as a human running the command). Resolve it the same way `createWorktree`'s branch already starts from current `HEAD`: pass `'HEAD'` is wrong here (the worktree's `HEAD` *is* the feature branch, post-checkout) — instead resolve the base once via a second new tiny helper:

```dart
/// Runs `git rev-parse --abbrev-ref origin/HEAD` in [rootPath] (the
/// *original* checkout, not the worktree — `origin/HEAD` is a
/// repository-wide ref, identical either place, but `rootPath` is
/// already resolved and doesn't require the worktree to exist yet) and
/// strips the `origin/` prefix, returning e.g. `'main'`. Falls back to
/// `'main'` if the command fails (a shallow clone or a repo with no
/// `origin/HEAD` set) — matching `gh pr create`'s own base-branch
/// resolution fallback (repository's configured default branch).
Future<String> defaultBranch(String rootPath) async {
  final result = await _run(
    ['rev-parse', '--abbrev-ref', 'origin/HEAD'],
    rootPath,
  );
  if (result.exitCode != 0) return 'main';
  final ref = result.stdout.toString().trim();
  return ref.startsWith('origin/') ? ref.substring('origin/'.length) : ref;
}
```

## 2. Notification domain layer

### 2.1 `lib/features/tickets/domain/entities/notification.dart` — new file

```dart
import 'package:equatable/equatable.dart';

/// What kind of outcome a [Notification] records. Mirrors the terminal
/// states `TicketsCubit._runCodingExecution`/`_runStageChatTurn` already
/// post system comments for — a notification is written alongside each
/// comment, not derived from it later.
enum NotificationKind {
  /// A coding-execution run finished with a confirmed, opened PR.
  executionPrOpened,

  /// A coding-execution run's verify gate failed — no PR opened.
  executionVerificationFailed,

  /// A coding-execution run failed for an infra/setup reason (worktree,
  /// push, PR-open failure) before verification was even reached.
  executionFailed,

  /// An Epic/Story SDD-stage-chat turn completed successfully.
  stageAdvanceCompleted,

  /// An Epic/Story SDD-stage-chat turn failed.
  stageAdvanceFailed,
}

/// A persisted record of a coding-execution or SDD-stage-chat terminal
/// outcome, surfaced via the notification-center dropdown
/// (`WorkspaceNavShell`'s `_NotificationBellTrigger`) so a human who
/// wasn't looking at the right ticket at the right moment can still
/// catch up. See `aion-arch/changes/pr-metadata-and-notification-center/design.md`
/// §2-§3.
class Notification extends Equatable {
  /// Creates a [Notification].
  const Notification({
    required this.id,
    required this.ticketId,
    required this.ticketTitle,
    required this.kind,
    required this.message,
    required this.createdAt,
    this.readAt,
  });

  /// UUID v4 primary key.
  final String id;

  /// The Task/Bug/Epic/Story ticket this notification concerns — not
  /// the spawned chat ticket, so tapping a row always navigates to the
  /// ticket a human would actually want to act on.
  final String ticketId;

  /// [ticketId]'s title, snapshotted at write time. Deliberately
  /// denormalized: the dropdown can open from any `/workspace/*` route,
  /// not only the Board (where the full ticket list is already loaded),
  /// so resolving titles via N individual `getTicketById` lookups every
  /// time the dropdown opens would mean an extra DB round-trip per row.
  /// Can go stale if the ticket is later renamed — treated as an
  /// acceptable, deliberate tradeoff (a notification is a historical
  /// record of "what happened," same as a git commit or PR title
  /// freezing at creation time).
  final String ticketTitle;

  /// What kind of outcome this row records.
  final NotificationKind kind;

  /// Precomputed, already-formatted display text (e.g. "PR #42 opened
  /// · 5 files changed", "Advanced to Design"). Formatted once at
  /// write time, not re-derived at render time.
  final String message;

  /// Unix milliseconds.
  final DateTime createdAt;

  /// `null` while unread; set to the moment a human read/tapped this
  /// row. Nullable-timestamp read/unread, mirroring `Ticket.deletedAt`'s
  /// existing nullable-timestamp convention for a two-state flag rather
  /// than introducing a separate bool column.
  final DateTime? readAt;

  /// Whether this notification has not yet been read.
  bool get isUnread => readAt == null;

  @override
  List<Object?> get props =>
      [id, ticketId, ticketTitle, kind, message, createdAt, readAt];
}
```

### 2.2 `lib/features/tickets/domain/repositories/notification_repository.dart` — new file

```dart
import 'package:aion/features/tickets/domain/entities/notification.dart';

/// Persists coding-execution/SDD-stage-chat outcome notifications. See
/// `aion-arch/changes/pr-metadata-and-notification-center/design.md` §2.
abstract interface class NotificationRepository {
  /// Inserts a new, unread [Notification]. [id] is generated by the
  /// caller (matches every other repository's `id: ''`-then-DAO-
  /// generates convention — see `CommentRepository.addComment`).
  Future<void> addNotification(Notification notification);

  /// Returns the [limit] most recent notifications (any read state),
  /// newest first.
  Future<List<Notification>> getRecent({int limit = 20});

  /// Returns the count of notifications with `readAt == null`.
  Future<int> getUnreadCount();

  /// Sets [id]'s `readAt` to now. No-ops if [id] doesn't exist or is
  /// already read.
  Future<void> markRead(String id);

  /// Sets every currently-unread notification's `readAt` to now.
  Future<void> markAllRead();

  /// Returns [ticketId]'s most recent notification of [kind], or `null`
  /// if none exists. Feeds `TicketDetailLoaded.executionPrSubLine`
  /// (§4.6) — avoids re-deriving PR metadata from the comment thread a
  /// second time when a notification row already holds the formatted
  /// text.
  Future<Notification?> getMostRecentForTicket(
    String ticketId,
    NotificationKind kind,
  );
}
```

### 2.3 `lib/features/tickets/data/models/notification_table.dart` — new file

```dart
import 'package:drift/drift.dart';

/// Drift table backing [Notification]. Row type generated as
/// `NotificationData`. No FK constraints — matches every other table in
/// this schema (integrity enforced at the repository layer). Added for
/// `aion-arch/changes/pr-metadata-and-notification-center`.
@DataClassName('NotificationData')
class NotificationsTable extends Table {
  @override
  String get tableName => 'notifications';

  /// UUID v4 primary key.
  TextColumn get id => text()();

  TextColumn get ticketId => text().named('ticket_id')();

  TextColumn get ticketTitle => text().named('ticket_title')();

  /// `NotificationKind.name` string.
  TextColumn get kind => text()();

  TextColumn get message => text()();

  /// Unix milliseconds.
  IntColumn get createdAt => integer().named('created_at')();

  /// Unix milliseconds. `null` while unread — see
  /// `Notification.readAt`'s dartdoc for why this is a nullable
  /// timestamp rather than a bool.
  IntColumn get readAt => integer().named('read_at').nullable()();

  @override
  Set<Column> get primaryKey => {id};
}
```

### 2.4 `lib/features/tickets/data/daos/notification_dao.dart` — new file

```dart
import 'package:drift/drift.dart';
import 'package:uuid/uuid.dart';

import 'package:aion/core/core.dart';
import 'package:aion/features/tickets/data/models/notification_table.dart';

part 'notification_dao.g.dart';

/// Drift accessor for [NotificationsTable]. See
/// `aion-arch/changes/pr-metadata-and-notification-center/design.md` §2.
@DriftAccessor(tables: [NotificationsTable])
class NotificationDao extends DatabaseAccessor<AppDatabase>
    with _$NotificationDaoMixin {
  /// Creates a [NotificationDao] bound to [db].
  NotificationDao(super.db);

  static const _uuid = Uuid();

  Future<void> insert({
    required String ticketId,
    required String ticketTitle,
    required String kind,
    required String message,
    required int createdAt,
  }) {
    return into(notificationsTable).insert(
      NotificationsTableCompanion.insert(
        id: _uuid.v4(),
        ticketId: ticketId,
        ticketTitle: ticketTitle,
        kind: kind,
        message: message,
        createdAt: createdAt,
      ),
    );
  }

  Future<List<NotificationData>> getRecent(int limit) {
    return (select(notificationsTable)
          ..orderBy([
            (t) => OrderingTerm(
              expression: t.createdAt,
              mode: OrderingMode.desc,
            ),
          ])
          ..limit(limit))
        .get();
  }

  Future<int> getUnreadCount() {
    final query = selectOnly(notificationsTable)
      ..addColumns([notificationsTable.id.count()])
      ..where(notificationsTable.readAt.isNull());
    return query
        .map((row) => row.read(notificationsTable.id.count()) ?? 0)
        .getSingle();
  }

  Future<void> markRead(String id) {
    return (update(notificationsTable)..where((t) => t.id.equals(id)))
        .write(
          NotificationsTableCompanion(
            readAt: Value(DateTime.now().millisecondsSinceEpoch),
          ),
        );
  }

  Future<void> markAllRead() {
    return (update(notificationsTable)
          ..where((t) => t.readAt.isNull()))
        .write(
          NotificationsTableCompanion(
            readAt: Value(DateTime.now().millisecondsSinceEpoch),
          ),
        );
  }

  Future<NotificationData?> getMostRecentForTicket(
    String ticketId,
    String kind,
  ) {
    return (select(notificationsTable)
          ..where((t) => t.ticketId.equals(ticketId) & t.kind.equals(kind))
          ..orderBy([
            (t) => OrderingTerm(
              expression: t.createdAt,
              mode: OrderingMode.desc,
            ),
          ])
          ..limit(1))
        .getSingleOrNull();
  }
}
```

### 4.2 `unreadNotificationCount` — a `ValueNotifier`, not `TicketsState`

```dart
/// Live unread-notification count, exposed outside the Bloc `state`
/// machinery so `WorkspaceNavShell`'s bell badge can render from every
/// `/workspace/*` route regardless of which `TicketsState` variant is
/// currently active — retrofitting this onto every existing state
/// subclass (`TicketsLoaded`, `TicketDetailLoaded`, `TicketsError`, …)
/// would touch far more surface than the badge's own scope justifies.
/// Loaded via [loadUnreadNotificationCount] (chained onto construction
/// in `app_router.dart`, mirroring `..restoreExecutionQueue()`'s
/// existing precedent) and refreshed at every [_recordNotification]
/// call and every [markNotificationRead]/[markAllNotificationsRead]
/// call. `0` if constructed without a [NotificationRepository].
final ValueNotifier<int> unreadNotificationCount = ValueNotifier(0);

/// Loads the current unread count from [_notificationRepository] into
/// [unreadNotificationCount]. No-ops if constructed without one. Call
/// once after construction (see `app_router.dart`).
Future<void> loadUnreadNotificationCount() async {
  final repo = _notificationRepository;
  if (repo == null) return;
  unreadNotificationCount.value = await repo.getUnreadCount();
}
```

`TicketsCubit` must call `super.close()`-adjacent cleanup for this `ValueNotifier` — override `close()` to `unreadNotificationCount.dispose()` before `super.close()`, if `TicketsCubit` doesn't already override `close()` (confirm during `/apply`; if it does, add the dispose call to the existing override rather than adding a second one).

### 4.3 `_recordNotification` — the one shared write path

```dart
/// Writes one [Notification] for [ticketId] and refreshes
/// [unreadNotificationCount]. The single call site every terminal
/// branch of `_runCodingExecution`/`_runStageChatTurn` goes through,
/// rather than each duplicating insert-plus-refresh logic — mirrors
/// `board-execution-indicators-and-notifications`'s own precedent of
/// "one background-execution pattern serves both" consumers, applied
/// here to notification-writing. No-ops if constructed without a
/// [NotificationRepository] (mirrors [_commentRepository]'s guard
/// shape) — a coding-execution/stage-advance run's own outcome is
/// still fully surfaced via its existing system comment either way,
/// so a missing repository degrades gracefully rather than breaking
/// the run itself.
Future<void> _recordNotification({
  required String ticketId,
  required NotificationKind kind,
  required String message,
}) async {
  final repo = _notificationRepository;
  if (repo == null) return;
  final ticket = await _repository.getTicketById(ticketId);
  await repo.addNotification(
    Notification(
      id: '',
      ticketId: ticketId,
      ticketTitle: ticket?.title ?? '',
      kind: kind,
      message: message,
      createdAt: DateTime.now(),
    ),
  );
  unreadNotificationCount.value = await repo.getUnreadCount();
}
```

### 6.2 Notification dropdown (new widget)

Built directly on `Overlay`/`LayerLink`/`CompositedTransformFollower` with a `mounted` guard — the same mechanics `TicketOverflowMenu` already uses as "a third instance of that pattern, not built on `SelectionMenu<T>` since it's an action list rather than a value picker" (per `aion-arch/specs/tickets.md`'s existing description of that widget). A notification dropdown is the same shape: a scrollable list of rows, each independently actionable (tap to navigate + mark read), not a single-value picker — so this becomes that pattern's fourth instance, not a fifth divergent mechanism.

- Header: "Notifications" title + "Mark all read" text button (disabled/hidden when unread count is `0`), calling `TicketsCubit.markAllNotificationsRead()`.
- Rows: `TicketsCubit.getRecentNotifications()`'s results, each showing an icon keyed by `NotificationKind` (mirrors `_ExecutionActionBanner`'s `.success`/`.failure` icon choice — `gitPullRequestLight` for `executionPrOpened`, `warningLight` for the two failure kinds, a stage-appropriate glyph for `stageAdvanceCompleted`), `ticketTitle`, `message`, a relative timestamp (reusing whatever formatter `ticketDetailLastUpdated`'s `{relative}` placeholder already uses), and a small unread dot when `isUnread`.
- Tap on a row: `context.go('/workspace/tickets/${notification.ticketId}')` then `TicketsCubit.markNotificationRead(notification.id)` (navigate first — matches this codebase's general pattern of not blocking navigation on a write).
- Empty state: a centered "No notifications yet" message when the list is empty (mirrors `inbox_empty_state.dart`'s existing empty-state pattern for a similar list-shaped screen).

```json
  "placeholders": { "count": { "type": "int" } }
},
"ticketDetailCodingExecutionPrSubLine": "PR #{number} · {fileCount, plural, one{1 file} other{{fileCount} files}} changed",
"@ticketDetailCodingExecutionPrSubLine": {
  "placeholders": {
    "number": { "type": "int" },
    "fileCount": { "type": "int" }
  }
}
```

`notificationExecutionPrOpened` and `ticketDetailCodingExecutionPrSubLine` render identical text — kept as two separate keys rather than one shared key because they're consumed from two different layers (`TicketsCubit`, building the notification's stored `message` outside any `BuildContext`, vs. the widget-layer banner computing its `subLine` via `context.l10n`), and collapsing them into one shared formatter would require resolving §1.3's open question (whether `TicketsCubit` has a non-widget localization path at all) before either can be written — left as a genuine open question for `/apply`, not pre-decided here.

## Open questions for `/apply`

- Whether `TicketsCubit` already has a mechanism to resolve `AppLocalizations` outside a `BuildContext` (needed for `_recordNotification`'s message construction, and for `executionPrSubLine`'s stored notification message). If not, `/apply` should either add one (following whatever pattern `ticketsErrorMessage` uses, if any) or store an unlocalized-but-well-formatted `String` at write time — a real design decision this proposal deliberately doesn't force ahead of seeing the actual current code shape at `/apply` time.
- Exact bottom-tab-bar cell treatment for `_NotificationBellTrigger` (own cell vs. sharing `_SecondaryActionsTrigger`'s existing 56px slot) — a `/design-brief`/`/design-sync` question.
- Whether `TicketsCubit` already overrides `Bloc.close()` — determines whether `unreadNotificationCount.dispose()` needs its own override or an addition to an existing one.

# Aion — PR Metadata Sub-line & Notification Center: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md), the [Coding-Execution Reliability Spec](./Aion%20Coding%20Execution%20Reliability%20Spec.md) (which shipped the two-tone `_ExecutionActionBanner` and first declared its optional `subline` slot), and the [Navigation Shell Spec](./Aion%20Navigation%20Shell%20Spec.md) (whose `WorkspaceNavShell`, `_NavItem`, secondary-actions trigger, and `SelectionMenu` overlay mechanics this feature sits beside and reuses). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing`, `AionColorsHubTokens`, `AionShadows`, `TicketDetailScreen`, `WorkspaceNavShell`, `_ExecutionActionBanner`, `BannerTone`, `TicketType`, and the thin-line Phosphor Light icon set by name. Mockups: [Aion PR Metadata and Notification Center Mockups](./Aion%20PR%20Metadata%20and%20Notification%20Center%20Mockups.dc.html).

**What's being built.** Two additive UI surfaces layered onto Aion's existing ticket/execution system — **no new screens**:

1. **PR metadata sub-line** — `GitHubCliClient.openPullRequest` now returns a PR number alongside its URL, and a new `changedFileCount` git helper computes how many files a run touched. Both feed the **already-declared** `subline` slot on `_ExecutionActionBanner` (Coding-Execution Reliability §1.3), rendering a short single line — e.g. `"PR #42 · 5 files changed"` — under the banner title in the **success tone only**. This spec pins its exact formatting, color, and spacing (§1).
2. **Persistent notification center** — a new **`_NotificationBellTrigger`** (bell glyph + unread-count badge) placed in `WorkspaceNavShell` beside the existing secondary-actions trigger, in both the wide sidebar and the compact bottom tab bar. Tapping it opens the **notification dropdown panel** (§4): a header (§5), a scrollable list of the 20 most recent coding-execution / SDD-stage-advance outcome rows (§6), and an empty state (§7).

**Hard constraint — no Material widgets or types anywhere.** Plain Flutter primitives only: `DecoratedBox`, non-Material `Container`, `Padding`, `Row`, `Column`, `Stack`, `Positioned`, `GestureDetector`, `MouseRegion`, `FocusableActionDetector`, `AnimatedScale`, `AnimatedContainer`, `CustomPaint`, `SingleChildScrollView`, `Overlay`/`OverlayEntry`, `CompositedTransformTarget`/`CompositedTransformFollower`/`LayerLink`. **No** `Card`, `ElevatedButton`, `TextButton`, `Scaffold`, `AppBar`, `Chip`, `ListTile`, `Material`, `InkWell`, `Divider`, `Badge`, `ThemeData`, `ColorScheme`, `SnackBar`.

Themes: **Arctic** (light, celestial-cold) and **Obsidian** (dark, abyssal-cold). **All layout, dimensions, spacing, radius, and typography are identical between themes** — only color tokens differ, and every color below is a named `AionColors` token that already resolves per theme. Concrete hex is given as `Arctic / Obsidian` for reference only; implement against the token, never the literal. Translucent fills are always `token.withOpacity(x)` — never a hardcoded ARGB.

## 0. Decisions up front

### 0.1 New tokens — minimal

No new `AionColors`, `AionRadius`, or `AionSpacing` members. Two additions only:

- **One new `AionText` style** — `AionText.countBadge`, the tiny numeric label on the bell badge (§2.4). The existing `chip` (10.5 / w700, tracked) and `badgeLabel` (11 / w600) are both too tracked / too large for a 16px count disc.

  ```dart
  // digits inside the unread-count badge — snug, untracked, high-weight
  static const countBadge = TextStyle(
    fontFamily: 'Manrope', fontSize: 10, fontWeight: FontWeight.w700,
    letterSpacing: 0, height: 1.0,
  );
  ```

- **One new derived tint helper** on `AionColorsHubTokens`, following the existing `withValues(alpha: isDark ? X : Y)` pattern — the recessed fill behind an outcome-icon tile (§6.3):

  ```dart
  // outcome-icon tile fill: the accent at the standard chip alpha
  Color outcomeTileFill(Color accent, bool isDark) =>
      accent.withOpacity(isDark ? fillAlphaObsidian : fillAlphaArctic); // 0.16 / 0.11
  ```

### 0.2 Bell glyph — thin-line, matches the app's icon language

First use of a bell in the codebase. Use a **clean single-line bell** in the spirit of Phosphor **Light** (the app's existing 1.6px-stroke set — the DS iconography table already reserves `bell` for "alerts"): a rounded dome, a flat rim line, and a small clapper arc below. Stroke `1.7px`, `round` joins/caps, rendered at the sizes in §2 / §3, colored per state exactly like a `_NavItem` icon. **No filled variant** — even the active/open state keeps the line glyph (the badge, not a fill swap, carries the "has unread" signal).

### 0.3 Badge color — `primary`, deliberately **not** `danger`

The unread-count badge is **`primary`** (`#2E86D4 / #9366FF`), solid fill, `#FFFFFF` digits.

- **Not `danger`:** the notifications are a *mixed* stream — PR-opened successes sit beside failures. A red badge would misread the whole center as "errors," turning good news into alarm. `danger` is reserved for genuinely destructive / error states (DS §1.1).
- **Not `neutralTint`:** that quiet grey (its precedent is calm rollup chrome) is too low-contrast for a count that must catch the eye across the shell.
- **`primary` is the app's canonical attention accent** (active icons, focus rings, selected state). A count keyed to it reads as "N things want you," not "N things broke" — the correct meaning for a mixed outcome feed.

### 0.4 Outcome-icon mapping — 5 kinds, each its own glyph + tint

Every row leads with a `28×28` rounded-square tile (§6.3). Tint tokens:

| # | Outcome kind | Meaning | Glyph (Phosphor Light) | Accent token | Arctic / Obsidian |
|---|---|---|---|---|---|
| 1 | `prOpened` | coding run finished, PR opened | `git-pull-request` | `success` | `#1E9E76 / #33D19B` |
| 2 | `verificationFailed` | `flutter analyze` gate failed | `warning-triangle` | `danger` | `#CE3D54 / #F1546C` |
| 3 | `executionFailed` | run hard-errored, no PR | `x-circle` (slash-circle) | `danger` | `#CE3D54 / #F1546C` |
| 4 | `stageAdvanced` | SDD stage advanced | `arrow-right` (in a subtle ring) | `primary` | `#2E86D4 / #9366FF` |
| 5 | `stageAdvanceFailed` | stage-advance attempt failed | `warning-circle` | `warning` | `#B8912B / #D7B24E` |

Rationale for the split within "failure": the **two coding failures** (`verificationFailed`, `executionFailed`) share the `danger` family — a code run did not produce a PR — distinguished only by glyph. The **SDD stage-advance failure** is keyed to `warning` (amber) instead: it is a softer, recoverable gate rejection in the spec workflow, not a hard code error, and the amber keeps it visually separate from the two red coding failures in a scanning list. `stageAdvanced` reuses `primary` — the app's established "advance the SDD stage" hue (Chat Branching §0) — so success-family greens (`prOpened`) and stage progress (`stageAdvanced`) never collide.

## 1. `_ExecutionActionBanner` — PR metadata sub-line

The `subline` slot already exists on the banner (Coding-Execution Reliability §1.3) as `final String? subline;`. This section pins its treatment for the **PR-metadata** case. **Success tone only** — the failure tone's short `subline` (`"flutter analyze · 3 issues · run #44"`) is unchanged, and the failure tone additionally has its scrollable `errorDetail` well (CER §1.4), which the success tone never renders.

### 1.1 Placement within the banner

Inside the header `Row`'s text column (`Expanded`, `Column`, `crossAxisAlignment: start`, `gap: 2`) — CER §1.3, unchanged geometry:

1. **Title** — `AionText.cardTitle` (14 / w600), `textPrimary`. Success copy: `"Coding run finished — PR opened"`.
2. **Sub-line** — the new line, directly under the title (the `gap: 2` between them is the column's own gap; no extra spacing member). Rendered **only when `subline != null`**; when null the column is title-only and collapses to one line.

The sub-line lives **inside** the title column, so the success-tone leading glyph stays `center`-aligned against a two-line title+subline block (CER §1.2 keeps `center` for success; only the failure tone pins the glyph to `start`). No change to the banner's outer padding (`EdgeInsets.fromLTRB(14, 13, 14, 14)`), its `gap: 12` between header row and action button, its fill/border, or the action button (all CER §1.1–§1.6, inherited unchanged).

### 1.2 Sub-line text style

| Property | Value |
|---|---|
| Style | `AionText.time` (JetBrains Mono, 11 / w400) |
| Color | `textSecondary` (`#46586A / #A2AEC6`) |
| Max lines | 1 (`maxLines: 1`, `overflow: TextOverflow.ellipsis`, `softWrap: false`) |
| Spacing above | `2px` (the text column's `gap`) |
| Spacing below | `0` (the column's bottom is flush; the banner's `gap: 12` handles the space to the button) |

Mono, not Manrope, because the content is machine-formatted metadata (a PR number, a count) — it matches the app's `key` / `time` mono affordance for identifiers and reads as "data about the run," consistent with the failure tone's own mono sub-line.

### 1.3 Content format

The string is composed by the caller and passed in whole; the banner does not parse it. Canonical form — **middot-joined segments**, most-specific first:

```
PR #<number> · <n> file[s] changed
```

- **PR number** — from `GitHubCliClient.openPullRequest`'s new return value. Always present in the success case (a success tone means a PR opened). Example: `PR #42`.
- **Changed-file count** — from the new `changedFileCount` git helper. `"1 file changed"` (singular) / `"N files changed"` (plural). Omit the whole segment if the count is unavailable (`null`), leaving just `PR #42`.
- Segments joined by `" · "` (space · space), U+00B7 middot. No trailing punctuation.

Examples: `PR #42 · 5 files changed` · `PR #57 · 12 files changed` · `PR #131 · 1 file changed` · `PR #88` (count unavailable).

### 1.4 States

The sub-line is **non-interactive static text** — no hover / focus / pressed / disabled / error of its own. It appears/disappears purely on `subline` nullability. When the run is still finishing and the PR number has not yet returned, the banner is not in the success tone at all (it is `running`, CER §2), so there is no "loading sub-line" state to design.

## 4. Notification dropdown panel

The popover the trigger opens. Built on `Overlay` + `LayerLink` + `CompositedTransformFollower` — the same overlay mechanics as the shell's existing `SelectionMenu` (Nav Shell §6) — but a **purpose-built panel**, not the `SelectionMenu` shell (it needs a header and multi-line rows the menu never has).

### 4.1 Container

| Property | Value |
|---|---|
| Width | **360px** (fixed) |
| Max height | **440px** — header (§5) is fixed; the row list (§6) scrolls inside the remaining space |
| Fill | `surface` (`#FBFCFE / #131A29`) |
| Border | 1px `borderStrong` (`#BAC8D6 / #35415C`) |
| Radius | `AionRadius.lg` (12) |
| Shadow | `AionShadows.card` — `BoxShadow(color: Colors.black.withOpacity(isDark ? 0.60 : 0.22), blurRadius: 44, spreadRadius: -14, offset: Offset(0, 20))` (same as `SelectionMenu`, Nav Shell §6) |
| Padding | `0` on the container; header and rows own their internal padding. The whole panel is `ClipRRect(AionRadius.lg)` so the scrolling list and header borders clip to the corners |
| Structure | `Column` — (1) header (§5, fixed), (2) `Expanded` → `SingleChildScrollView(primary: false, physics: ClampingScrollPhysics)` → `Column` of rows (§6) **or** the empty state (§7) |

### 4.2 Anchor & offset

`LayerLink` shared between the trigger's `CompositedTransformTarget` and the panel's `CompositedTransformFollower`.

- **Wide sidebar:** opens **upward-right**. The panel's bottom-left sits ~`8px` above the bell trigger's top edge, left edge aligned to the trigger's left. `followerAnchor: Alignment.bottomLeft`, `targetAnchor: Alignment.topLeft`, `offset: Offset(0, -8)`. If the 360px width would exceed the window right edge, clamp so the panel stays ≥ 16px from the edge.
- **Compact bottom bar:** opens **upward**, clearing the bar + safe area. Panel bottom sits ~`8px` above the bar's top edge, **right edge aligned to the trigger**, clamped 16px from the window's right edge. `followerAnchor: Alignment.bottomRight`, `targetAnchor: Alignment.topRight`, `offset: Offset(0, -8)` (with the bar-height + `MediaQuery.viewPadding.bottom` already accounted for by anchoring to the trigger, which is inside the bar).
- **Dismiss:** outside tap (a full-screen transparent `GestureDetector` barrier in the `OverlayEntry` behind the panel), `Escape`, or route change. On dismiss the trigger reverts from menu-open to default/hover.

### 4.3 Enter / exit motion

Fade + 4px rise: `AnimatedOpacity` 0→1 and a `Transform.translate` from `Offset(0, 4)` to `Offset.zero`, 120ms `Curves.easeOut` on open; reverse (100ms) on close. Reduced-motion → opacity only. Matches the app's overlay convention (no scale-from-corner).

## 6. Dropdown row

One notification. A tappable row: leading outcome tile, a two-line text block, and a trailing timestamp + unread dot.

### 6.1 Container

| Property | Value |
|---|---|
| Width | full (360px minus panel edges) |
| Padding | `EdgeInsets.fromLTRB(14, 11, 12, 11)` |

### 6.2 Row states & read/unread distinction

| State | Fill | Notes |
|---|---|---|
| **Unread — default** | `surface` | title `textPrimary` w600; trailing `primary` unread dot present; outcome tile full-strength |
| **Read — default** | `surface` | title `textSecondary` (dimmed); **no** unread dot; outcome tile at `opacity 0.7` |

1. **Title line** — the ticket title, `AionText.cardTitle` (14 / w600), `maxLines: 1`, `ellipsis`.

2. **Message line** — the formatted outcome message with a leading mono ticket key.

   - Message copy per kind (caller-composed): `prOpened` → `"Opened PR #42 · 5 files changed"`; `verificationFailed` → `"flutter analyze · 3 issues"`; `executionFailed` → `"Run errored — no PR opened"`; `stageAdvanced` → `"Advanced Design → Build"`; `stageAdvanceFailed` → `"Spec gate rejected the advance"`.

## 9. Implementation notes

- Read colors via `ThemeScope.of(context).colors`; never hard-code hex in widgets — the hex columns above are for reference/verification only.
- Badge color is `primary` (§0.3) — do **not** wire it to `danger`. The outcome-icon tints (§0.4) are the only place `danger` / `warning` appear in this feature, and only inside a row's leading tile.
- The dropdown is `Overlay` + `LayerLink` + `CompositedTransformFollower` — reuse the exact mechanics `SelectionMenu` already uses (Nav Shell §6.2); only the panel body differs. Do not add a Material `PopupMenu` / `MenuAnchor`.
- Focus order in the shell adds the bell **before** the secondary-actions trigger: (wide) Tickets → Documentation → **Bell** → avatar; (compact) Tickets → Documentation → *(third destination)* → **Bell** → avatar. `Enter`/`Space` opens the panel; inside the panel, arrow keys move row focus, `Enter` opens the ticket, `Escape` closes.
- The 20-most-recent cap and read/unread persistence are model concerns; the panel renders whatever list it is handed (newest first) and shows §7 when it is empty.
- Sub-line: pass the whole formatted string in `subline`; the banner never parses PR numbers or counts. Singular/plural of "file(s)" is the caller's responsibility (§1.3).
- Both themes are identical in every dimension, radius, spacing, and type value in this spec; only the named color tokens resolve differently. No component here has a theme-specific layout.
- No Material classes anywhere — the entire feature is `DecoratedBox` / `Row` / `Column` / `Stack` / `Positioned` / `GestureDetector` / `MouseRegion` / `FocusableActionDetector` / `AnimatedScale` / `AnimatedContainer` / `SingleChildScrollView` / `Overlay` / `CompositedTransformFollower` / `CustomPaint` (bell glyph).
