# T10. Run the app in real Chrome (per project.md's Testing section

— `TicketParentPicker` manages an `Overlay` + search-controller
listener, the class of code that needs interactive verification,
not just `flutter analyze`/`flutter test`). Verify: creating a
ticket with a parent selected persists the parent correctly;
switching the create form's type to Epic hides the parent field
and clears any prior selection; the existing reparent flow on
`TicketDetailScreen` still works and now hides for epic tickets;
breadcrumbs render correctly (and are omitted for root-level
candidates) in both the create-flow and reparent-flow pickers;
both Arctic and Obsidian themes render the breadcrumb legibly.
Close the Chrome tab and stop the `web-server` process when done.
Obsidian: all behaviors above verified interactively in real
Chrome (create-flow parent selection persisted correctly, Epic
type hid/cleared the field, reparent flow gated for epics,
breadcrumbs rendered correctly including a 1-level chain and
omission for root candidates).
Arctic: Aion has no in-app theme toggle — `lib/main.dart` derives
the active theme solely from `platformDispatcher.platformBrightness`
(the OS/browser's system color scheme), and forcing that in this
environment would require changing the machine's actual display
settings, which is out of scope for an agent-run verification
pass. Confirmed instead at the code level, with the user's
agreement: (1) every color this change references
(`ticket_parent_picker.dart`, `create_ticket_screen.dart`) is an
`AionColors` token (`c.xxx`) — the only raw `Color(...)` literal
in either file is `Color(0x00000000)` (fully transparent,
theme-neutral, and an unchanged pattern from the pre-existing
code); (2) `AionColors` declares every field `required`, and
`arctic`/`obsidian` (`aion_colors.dart:163` /`:186`) are both
fully-specified `const AionColors(...)` instances — the type
system itself guarantees every token referenced here has a
defined Arctic value, no partial-theme gap is possible; (3)
design-sync's Step 2 token cross-reference already confirmed
every one of those tokens' Arctic/Obsidian hex pairs against
`aion_colors.dart` line-for-line. No new `AionText`/`AionColors`
values were introduced beyond `AionText.breadcrumb`, which is
colorless (color applied via `.copyWith` at the use site, same as
every other `AionText` style) and therefore theme-agnostic by
construction.
