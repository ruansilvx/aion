# Core — embeddings

- [x] T9. Create `lib/core/contracts/embedding_provider.dart` —
      `EmbeddingProvider` abstract interface class (`Future<Uint8List> embed(String text)`),
      following the existing `ActiveProjectProvider` contract's
      doc-comment pattern (cites `project.md` Pattern 1).
- [x] T10. Added bundled model + tokenizer assets under
      `aion/assets/models/`: `minilm-l6-v2-int8.onnx` (int8-quantized
      `avx512_vnni` export of `sentence-transformers/all-MiniLM-L6-v2`)
      and `minilm-l6-v2-vocab.txt` (the same model's WordPiece vocab),
      both fetched from the canonical
      `huggingface.co/sentence-transformers/all-MiniLM-L6-v2` repo
      (Apache 2.0) — source/license recorded in
      `aion/assets/models/NOTICE.md`, which replaces the old
      `README.md` blocker doc. Registered `assets/models/` in
      `pubspec.yaml`.
      **Found and fixed two real bugs in T11's `BundledEmbeddingProvider`
      while verifying this end-to-end** (both previously masked because
      the missing assets always short-circuited to `UnimplementedError`
      before this code path ran):
      1. Padding used `List<int>.filled(...).add(...)` on a
         fixed-length list — threw `Unsupported operation` on every
         call. Rewritten with `List<int>.generate` (no in-place growth).
      2. The exported graph requires `token_type_ids` as a third input
         (not just `input_ids`/`attention_mask`) and expects int64
         tensors — `OrtValue.fromList` silently downcasts a plain
         `List<int>` to int32, which the model rejects. Fixed by adding
         the `token_type_ids` input and passing explicit `Int64List`s.
      Also corrected a design assumption: this graph's only output is
      `last_hidden_state` (per-token), not a pooled `sentence_embedding`
      — `embed()` now does the standard mean-pool-over-`attention_mask`
      + L2-normalize itself.
      **Verified for real**: rebuilt `aion.exe` (`flutter build windows`),
      created a ticket through the running app, and confirmed via direct
      DB inspection that `tickets.embedding` now holds a real 384-dim,
      L2-normalized (`norm == 1.0000`) float32 vector — not null, not a
      stub.
- [x] T11. Create `lib/core/embeddings/bundled_embedding_provider.dart`
      — `BundledEmbeddingProvider implements EmbeddingProvider`. Uses
      `flutter_onnxruntime`'s single cross-platform API
      (`OnnxRuntime.createSessionFromAsset`) rather than a manual
      native/web conditional split — the plugin already abstracts that
      internally, unlike `AppDatabase`'s `_openConnection()` split
      (which exists because drift/sqlite3 genuinely need different
      backends per platform). Includes a from-scratch WordPiece
      tokenizer (`wordpiece_tokenizer.dart` — no maintained pure-Dart
      package exists; not yet cross-checked against a reference
      tokenizer). **Update (post-T10)**: now that the model/vocab
      assets exist and actually load, two real bugs surfaced and were
      fixed in `embed()` — see T10's entry for details (fixed-length
      list padding, missing `token_type_ids` input, int32-vs-int64
      tensor mismatch, and adding the mean-pooling + L2-normalization
      the exported graph doesn't do itself).
- [x] T12. Modify `lib/main.dart` and `lib/core/routing/app_router.dart`'s
      `WorkspaceShell` — **corrected from the original task**:
      `TicketRepository`/`TicketsCubit` are actually wired in
      `WorkspaceShell` (per-project, since they need a project's
      `AppDatabase`), not `main.dart`'s `AionApp` — `/propose` didn't
      catch this. `EmbeddingProvider` is project-agnostic, so it's
      constructed once in `AionApp` and provided via the existing
      `RepositoryProvider` tree; the git-projection/reconcile services
      (T19–T23) need `project.rootPath` and are wired in `WorkspaceShell`
      instead — see T30.
