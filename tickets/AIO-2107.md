## ADDED

- **`AgentRequest.toolsEnabled`/`.workingDirectory`** (`core/contracts/agent_model_client.dart`)
  — two new optional fields, defaulting to `false`/`null` (today's
  behavior for every existing caller). `toolsEnabled: true` requests a
  real, tool-capable run (file edits, git, bash); `workingDirectory` sets
  the cwd such a run operates in.
- **`ClaudeAgentSdkClient.run` cwd support** — passes
  `workingDirectory: request.workingDirectory` to `Process.start`, and
  forwards `toolsEnabled` in the NDJSON request line to `agent_bridge/index.mjs`.
- **`agent_bridge/index.mjs` tool-enabled mode** — when the request's
  `toolsEnabled` is `true`, the hardcoded `allowedTools: []` cap is
  omitted, so `query()` runs with the Claude Agent SDK's default tool set
  instead of none.
- **`ChatCubit.runChatTurn` new optional params**: `toolsEnabled`,
  `workingDirectory` (both threaded into the `AgentRequest` it builds),
  and `onOverageDetected` (called on `AgentOverageDetectedEvent`, in
  addition to the existing no-op handling).
- **`ChatCubit.runChatTurn` persists failure results** — a run that ends
  in `!succeeded` now posts one `CommentAuthorType.ai` comment
  (`'Execution failed: <message>'`) instead of persisting nothing, for
  every caller (existing SDD-stage spawns included), so a failed run is
  visible in the chat transcript rather than silently dropped.
- **`AutomationContext`** (new enum, `core/automation/automation_context.dart`)
  — `sddStage | codingExecution`. Identifies which automated decision
  point an `AutomationConfidence` value applies to.
- **`AutomationSettingsRepository.getConfidence(AutomationContext)`/
  `.setConfidence(AutomationContext, AutomationConfidence)`** — replace
  the previous single-purpose `getSddStageAutomation()`/
  `setSddStageAutomation()` pair. `SharedPrefsAutomationSettingsRepository`
  keys `AutomationContext.sddStage` to the *same* existing
  `shared_preferences` key (`automation_settings.sdd_stage_automation`) so
  no user's saved preference is reset by this rename, and adds a new key
  (`automation_settings.coding_execution_automation`) for
  `AutomationContext.codingExecution`, defaulting to
  `AutomationConfidence.gated` like every first-time automated decision
  point.
- **`AutomationSettingsState.AutomationSettingsReady.confidenceByContext`**
  (`Map<AutomationContext, AutomationConfidence>`) — replaces the single
  `confidence` field. `AutomationSettingsCubit.selectConfidence` now takes
  an `AutomationContext` alongside the chosen `AutomationConfidence`.
- **A second `_AutomationSection` instance in Settings** — "Coding
  Execution Automation," identical shape to the existing "SDD Stage
  Automation" section, both now instances of one context-parameterized
  widget.
- **`TicketsCubit._codingExecutionGateCheck(Ticket task)`** — the hard,
  non-`AutomationConfidence`-gated precondition: blocks coding execution
  only when the Task's governing Story's sibling Tasks indicate UI work
  (`_storyNeedsDesignReview`) and that work isn't design-approved yet
  (`_designSyncApproved`) — built directly on those two already-shipped
  functions, not on `SddStage` position (see the `_sddStageAdvanceCheck`
  fix below for why). A Task with no Story ancestor (parentless, or a
  direct Epic child), or whose Story's Tasks don't indicate UI work, is
  never blocked.
- **`TicketsCubit._governingStory(Ticket task)`** — walks `parentId` to
  find the nearest `story` ancestor, or `null` if none exists before
  reaching an `epic` or the root.
- **`CodingExecutionBlockReason`** (new enum, `tickets_state.dart`, one
  value: `storyDesignGatePending`) — surfaced only as a rejection toast
  (see `TicketsErrorReason.codingExecutionBlocked` below), not a
  persistent hint, since the block prevents the status transition itself.
- **`TicketsErrorReason.codingExecutionBlocked`** — the coding-execution
  gate rejected a Task's move to `inProgress`.
- **`TicketsErrorReason.executionBudgetOverageDetected`** — surfaced once,
  the first time `AgentOverageDetectedEvent` fires during any
  coding-execution run this session.
- **`TicketsCubit._triggerOrQueueCodingExecution(Ticket task)`** — starts
  a coding-execution run immediately if no run is in flight (single
  execution slot); otherwise appends `task.id` to an in-memory FIFO queue.
- **`TicketsCubit._runCodingExecution(Ticket task)`** — spawns a
  `chat`-type child ticket (`"Coding Execution — <Task title>"`) under
  `task`, posts an assembled system-context comment (task title/
  description plus PR-opening instructions), and calls
  `ChatCubit.runChatTurn` with `toolsEnabled: true`,
  `workingDirectory: _projectRootPath`, and an `onOverageDetected`
  callback that sets a session-scoped "overage seen" flag and emits
  `executionBudgetOverageDetected` once. On completion, checks for a
  confirmed PR (`_executionSucceededWithPr`) and, if found, flips the
  Task's status to `inReview` when the effective `AutomationConfidence`
  for `AutomationContext.codingExecution` is `auto` (forced to `gated`
  for the rest of the session once an overage has been seen, regardless
  of the configured value). Always dequeues the next Task afterward.
- **`TicketsCubit._executionSucceededWithPr(String chatId)`** — mirrors
  `_designSyncApproved`: checks the given chat's most recent AI comment
  for the literal line `EXECUTION: PR_OPENED`.
- **`TicketsCubit._assembleExecutionContext(Ticket task)`** — Task title/
  description plus an instruction to open a PR as the run's last step and
  end the reply with exactly one line, `EXECUTION: PR_OPENED <url>` or
  `EXECUTION: NO_PR` — mirrors `_assembleStageContext`'s
  `designSync`/`"DESIGN GATE: APPROVED"` parseable-signal convention.
- **`TicketDetailLoaded.isExecuting`/`.executionQueuePosition`/
  `.executionAwaitingReview`** (new fields, Task-only, all default
  `false`/`null`) — computed by `TicketsCubit.getTicketById` from the
  in-memory execution-queue state and `_executionSucceededWithPr`.
- **`_ExecutionRunningHint`/`_ExecutionQueueHint`/
  `_ExecutionReadyForReviewBanner`** (new widgets,
  `ticket_detail_screen.dart`) — Task-only, mutually exclusive, rendered
  where `_SddStageSection` sits for epic/story tickets. The first two
  mirror `_NotReadyHint`'s informational-row shape; the banner mirrors
  `_GatedBanner`'s confirm-action shape, calling the existing
  `changeTicketStatus(ticket, TicketStatus.inReview)`.
- **`TicketsCubit` constructor gains `AutomationSettingsRepository?
  automationSettingsRepository`** — optional, same "`null` no-ops the
  feature" pattern as `agentClient`/`commentRepository`. Wired at the real
  construction site (`core/routing/app_router.dart`).
- New l10n keys for the queue hint, running hint, ready-for-review banner,
  the two new toast messages, and the "Coding Execution Automation"
  section's label/description/sub-labels.

## MODIFIED

- **`TicketsCubit._sddStageAdvanceCheck`'s `proposed`/`designSync` cases
  (`story` tickets only) — bugfix.** Grounded while writing this change's
  own gate: today, advancing a `story` out of `proposed` (to `designBrief`
  or `verifying`) requires every child Task to already be
  `TicketStatus.done`, for every Story regardless of branch — but
  `designBrief`/`designSync` are meant to run *before* code is written
  (per `sdd-design-gate`'s own grounding note), so a UI-touching Story
  could never actually reach `designBrief` under the shipped precondition.
  Nothing could have hit this before now, since Tasks had no automated
  way to reach `done` until this change adds one.
  - `proposed`'s story branch now requires only "Tasks *exist*" to
    advance to `designBrief`; the skip-design branch (straight to
    `verifying`) is unchanged, still requiring Tasks *done* — it never
    had a pre-code stage to protect in the first place. The epic branch
    (child Stories archived) is entirely unchanged.
  - `designSync`'s case now requires **both** `_designSyncApproved` and
    all child Tasks done to advance to `verifying` — restoring the
    "Tasks done" check to the transition it always should have gated,
    one stage later than where it was misplaced.
  - No new `SddStageBlockReason` value — `awaitingDesignApproval`'s
    existing hint copy stays generic enough to cover both "not approved"
    and "approved but Tasks still in flight."
- **`TicketsCubit.changeTicketStatus`/`.updateTicketStatus`** — both now
  call a shared intercept before persisting a status write: if the
  ticket's `type` is `task` and the target `status` is `inProgress`, run
  `_codingExecutionGateCheck` first. A blocked check emits
  `TicketsErrorReason.codingExecutionBlocked` (re-emitting the ticket's
  unchanged `TicketDetailLoaded`, mirroring `_emitInvalidParent`) and
  skips the write entirely; an allowed check proceeds exactly as before,
  then calls `_triggerOrQueueCodingExecution` on the refreshed Task.
  Every non-Task, non-`inProgress` status change is entirely unaffected.
- **`AutomationSettingsRepository`** — its two SDD-stage-specific methods
  are replaced by the generalized `getConfidence`/`setConfidence` pair
  above (see ADDED); `TicketsCubit.advanceSddStage`'s existing gating
  reads `getConfidence(AutomationContext.sddStage)` instead of
  `getSddStageAutomation()` — behaviorally identical, same persisted key.

## Out of scope (see proposal.md)

- No per-phase/tier model routing for the coding-execution call — uses
  the existing hardcoded `AgentModel.sonnet` default, same as every other
  stage chat today.
- No true concurrent (multi-line) coding execution — one slot, FIFO
  queue only.
- No predictive, cost-estimate "Budget gate" — only the reactive
  `AgentOverageDetectedEvent`-triggered override.
- No cancellation of a queued or in-flight execution.
- No persistence of the execution queue across an app restart.
- No verification that a reported PR genuinely exists beyond string-
  matching the agent's own final reply.
