# /verify fix-ups (round 1)

Five gaps between the shipped UI and `design.md`'s Claude Design export,
found by `/verify` after the first `/apply` pass. T8–T13 stay checked —
that pass's functional/domain work was correct — but these visual-spec
pieces were missed and are being completed now rather than reopening
those tasks.

- [x] **T15** — `aion/lib/features/tickets/domain/entities/release_draft.dart`:
  add `releaseKey` (the release ticket's display id, e.g. `"AIO-51"`) and
  `targetBranch` (the branch `confirmRelease` will commit/push/tag
  against) fields to `ReleaseDraft`, both required, both dartdoc'd (per
  design.md §0.2's `ReleaseDraft` contract — `releaseKey`/`targetBranch`
  are the two fields the architecture-section §3 shape omitted but the
  UI export's own contract requires; resolve the discrepancy in favor of
  the export since the scope strip and confirm dialog below both need
  real values, not placeholders). Update `equatable`'s `props`. In
  `tickets_cubit.dart`, `prepareReleaseDraft` populates `releaseKey` from
  the release ticket's own `ticketId`, and `targetBranch` via
  `GitRepositoryClient.defaultBranch(_projectRootPath!)` — the same
  method `confirmRelease` already calls, so the branch shown during
  review is guaranteed to match the branch actually pushed to. Dartdoc
  update on `prepareReleaseDraft` noting the new fields.

- [x] **T16** — `aion/lib/features/tickets/presentation/screens/release_draft_screen.dart`:
  add the Scope summary strip per design.md §3.3 — release type chip,
  `"<N> items"` scope count (from `draft.linkedTicketIds.length`),
  separator dot, target-branch readout (`draft.targetBranch`), and a
  trailing `"View scope"` link that pops the screen back to the release
  ticket's detail screen (`Navigator.pop`, matching §3.3's "pops the
  draft back to the release ticket" — no new navigation route). Add the
  `releaseKey`/scope-count/view-scope/branch-glyph l10n strings to
  `app_en.arb` and run the localization codegen step. Dartdoc the new
  widget and its constructor parameters; one-line file header already
  exists on this file (touch-update if needed).

- [x] **T17** — Same file: add the header's trailing release-key badge
  (design.md §3.2 item 3, mono `AionText.key`, e.g. `"AIO-51"`) next to
  the title, and the derived tag-preview pill (§3.6) beside the version
  field, recomputed live from the version controller
  (`'v' + value.trim()`), dimmed to `opacity: 0.45` while the version
  field is in its error state. Both use `AionText.versionInput` (the
  token `/design-sync` approved for exactly these plus §4.2 — T18 is the
  third use). Dartdoc both new small widgets.

- [x] **T18** — Same file: replace the generic `showAppConfirmDialog`
  call in `_handleConfirmTagPressed` with a purpose-built dialog per
  design.md §4.2 — reuse the existing confirm-dialog shell (scrim, card,
  entrance/dismissal per §4.1, same as `AppConfirmDialog` already
  provides) but with custom content: the `typeRelease`-accent icon disc,
  title, body, and the two-row TAG/BRANCH block showing the *literal*
  `draft.targetBranch` value (not a generic "default branch" phrase —
  this is the finding: the branch name was never actually shown). Uses
  `AionText.versionInput` for the TAG/BRANCH values (§4.2's third use of
  that token). Add the new TAG/BRANCH-block l10n strings. Dartdoc the
  new dialog-content widget, and update `_handleConfirmTagPressed`'s
  existing dartdoc reference from the generic dialog to this one.

- [x] **T19** — `aion/lib/features/tickets/presentation/widgets/release_summary_section.dart`:
  add the disabled Prepare Release button's hover tooltip per design.md
  §1.3.6 (`"Link the work this release ships first"`, 450ms hover dwell,
  120ms fade-in) — mirror `AgentCostHint`'s existing bare
  `OverlayEntry` + `CompositedTransformFollower` + dwell-`Timer` pattern
  (`aion/lib/features/providers/presentation/widgets/agent_cost_hint.dart`)
  rather than inventing a new one. Add the tooltip copy string to
  `app_en.arb`. Dartdoc the new tooltip widget.

- [x] **T20** — `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart`:
  fix a bug found live during T14's manual pass (see below) —
  `prepareReleaseDraft`'s `catch` block emitted `TicketsError` with no
  follow-up emission, leaving `TicketDetailScreen` permanently blank
  (its body only renders for `TicketDetailLoaded`) after any drafting
  failure — directly contradicting the failure toast's own "you can try
  again from the release ticket" copy, since that screen was exactly the
  one stuck blank. Fixed by calling `_restoreDocumentTicketDetail`
  (not the simpler `_emitTicketDetailIfFound` — `ReleaseSummarySection`
  needs `linkedTickets`, which only the former reloads) in the catch
  block. Verified live: reproduced the blank-screen bug pre-fix,
  confirmed the fix resolves it post-fix (screen recovers with Release
  Scope's linked tickets intact after the same failure).

- [x] **T21** — Same file: fix a second bug found live during T14's
  resumed manual pass — `confirmRelease` never flipped the release
  ticket's own status to Done on success, contradicting design.md
  §3.7's explicit "the screen pops to the `release` ticket, whose
  status flips to Done" success behavior (confirmed by re-reading that
  line; the release ticket sat at `Backlog` after a real, successful
  tag+push). Fixed by calling `_repository.updateTicketStatus(draft
  .releaseTicketId, _doneStatus)` once every git step has succeeded
  (never reached if an earlier step throws, so a release that didn't
  actually land never reads Done), then `_restoreDocumentTicketDetail`
  so the still-mounted `TicketDetailScreen` underneath
  `ReleaseDraftScreen` shows the new status immediately on pop, with no
  manual navigate-away-and-back needed. Verified live against a real
  tag/push (curated and auto mode both): status visibly flips to Done
  in the same frame the success toast appears.
