# Tests

- [x] T3. Added cases to the existing
      `aion/test/features/tickets/cubit/trash_cubit_test.dart` (mocking
      `TicketRepository`/`TicketGitProjector` via `mocktail`, following
      `tickets_cubit_test.dart`'s existing pattern for the same
      dependency): `restore` calls `TicketGitProjector.project` with
      the restored ticket and event label `'restored'` when both
      `gitProjector` and `projectRootPath` are supplied; `restore` does
      not call it when either is omitted. Also updated the pre-existing
      "restore calls the repository then reloads" test to stub
      `getTicketById`, which `restore` now calls unconditionally
      (mirrors the identical fix `storage-embedding-git-sync`'s T40
      needed for `TicketsCubit`'s own tests after the same kind of
      change).
      **Corrected from this task's original wording**: dropped the
      planned "`restore` still reaches `TrashLoaded` even if the
      projection call itself throws" case — verified by writing it
      that it does not hold. `_triggerGitProjection` is invoked via
      `unawaited(...)`, so a thrown error surfaces as an unhandled
      Future rejection in the bloc_test zone (confirmed by running the
      test: it failed with the stubbed `Exception('git boom')`
      surfacing async, after `TrashLoaded` had already emitted
      correctly). This isn't a regression — `TicketsCubit`'s own
      `_triggerGitProjection`/`unawaited` call sites have the exact
      same shape and the same latent behavior, untested there too; it's
      a pre-existing property of the "fire-and-forget, never block the
      user-visible action" pattern this task was told to mirror, not
      something safe to silently change (e.g. by adding a `try`/`catch`
      inside `_triggerGitProjection`) as a side effect of a test-only
      task. Flagged rather than asserting behavior that isn't actually
      true. Full suite run afterward (`flutter test`): 14/14 in this
      file passing, no regressions.
