# Post-`/verify` fixes (WARNING findings from the first `/verify` pass)

- [x] T18. Fix `CreateTicketScreen`'s type dropdown ordering (finding:
      `TicketType.spec` rendered last, after `bug`, instead of
      design.md §4.1's "after Page, before Idea," since `create_ticket_screen.dart`
      built its `items` list from a bare `TicketType.values.where(...)`
      — raw enum-declaration order, and `spec` was appended last in the
      enum by T1). Added a new `_dropdownTypes()` helper that keeps
      every other type's natural enum position (so a future addition
      still appears with no list to maintain) but special-cases `spec`,
      inserting it immediately after `TicketType.resource` — the slot
      `page` itself occupied before it was excluded from this dropdown.
      Verified the resulting order directly against the filtered enum
      sequence.

- [x] T19. Implement design.md §2.4.1's full hover/focused/pressed
      interactive-link state table for `_SpecOriginBadge`'s Epic link
      (finding: the first `/apply` pass used a plain static-underline
      `TextSpan` + `TapGestureRecognizer`, citing `MarkdownView`'s
      resolved-wikilink span as precedent for skipping the interaction
      states — except that span had the identical gap, so it wasn't a
      real precedent). Built a new shared design-system molecule,
      `InteractiveLinkSpan` (`lib/design_system/molecules/interactive_link_span.dart`),
      mirroring `OverlayMenuItem`'s `MouseRegion` → `FocusableActionDetector`
      → `GestureDetector` nesting and its `onShowFocusHighlight`-based
      real keyboard-vs-pointer focus split, adapted for a `WidgetSpan`-
      embeddable inline link: hover swaps in `hoverColor` with a custom-
      offset underline (`CustomPaint`, since a `TextStyle` underline has
      no offset parameter) and the click cursor over a 100ms tween;
      keyboard focus draws a `1.5px` ring outside the link's own layout
      bounds (negative-inset `Positioned` inside a `Clip.none` `Stack`,
      so it never shifts surrounding text); pressed dims to 80% opacity.
      One deliberate, documented deviation from the literal table: the
      underline stays visible in every state (including `Default`/
      `Focused`, where the table says "none"), matching this codebase's
      pre-existing always-underlined link convention — see the widget's
      own dartdoc. Wired into `_SpecOriginBadge`'s Epic link
      (`page_detail_screen.dart`) and retrofitted onto `MarkdownView`'s
      resolved-wikilink span (`markdown_view.dart`, `typePage`-colored;
      no dedicated hover-tint token exists for it, so `hoverColor` there
      equals `color` — documented in a code comment rather than inventing
      a new token) — establishing this as the real, working precedent
      both callers can now cite. Added `interactive_link_span_test.dart`
      covering all four states (default/hover/keyboard-focus/pressed) by
      driving real `MouseRegion`/`FocusableActionDetector`/`GestureDetector`
      interaction through `WidgetTester`, not just checking static
      style/config. Full dartdoc + file header on the new file; updated
      `_SpecOriginBadge`'s own dartdoc to describe the fix (its prior
      text falsely claimed no precedent existed). `flutter analyze`
      clean; full `flutter test` suite passes (1504 tests, including the
      4 new `InteractiveLinkSpan` cases).
