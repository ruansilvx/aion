# Manual verification

- [x] 21. Manual interactive pass — per the project's Desktop-only
      verification convention, driven against a native Windows debug
      build (`flutter run -d windows`) via PowerShell/UIA system calls,
      not the web build. Confirmed: selecting tickets spanning different
      statuses/priorities enables both triggers; `BulkStatusMenu` lists
      all 6 statuses in fixed order with correct status-dot colors;
      `BulkPriorityMenu` lists all 5 priorities in fixed order with
      correct square indicators, including the hollow square for "None";
      outside-tap dismisses both overlays without applying; a bulk
      priority apply writes correctly and shows the
      "Updated priority on N tickets." toast, clearing selection
      afterward; a bulk status apply to a non-`inProgress` target writes
      correctly with zero skips and shows the
      "Updated status on N tickets." toast; resizing to a narrow width
      collapses both triggers to icon-only 34×34 squares, compacts the
      count label to a bare number, keeps Select-all/Delete labelled, and
      the compact overlay still opens fully on-screen. Two items
      short of full coverage: (1) keyboard-only operation (Tab to
      trigger, autofocus, arrow navigation, `Escape` dismiss) could not
      be conclusively verified — synthetic keyboard input reached the
      app fine for general Tab traversal and text entry, but produced no
      visible effect inside either the new overlays or the pre-existing
      `SelectionMenu<T>`-based single-ticket picker tested for
      comparison, so this reads as a pre-existing characteristic of the
      app's whole `Overlay`-menu family (or a limitation of the
      synthetic-input harness itself) rather than a regression
      introduced here — not fixed as part of this change. (2) The
      Blocked-dependency skip path (bulk move to `inProgress` with one
      selected ticket blocked) wasn't exercised live — setting up a real
      `blockedBy` link was out of proportion for this pass — but it's
      covered thoroughly by task 19's unit tests (mixed-selection gate
      test asserting the correct `updatedCount`/`skippedCount` split).
      (design.md §11; per design.md "Bulk Status & Priority Edit" export
      §5, §6)
