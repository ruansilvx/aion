# `TicketsCubit` — Board blocked-set

- [x] T4. `features/tickets/presentation/cubit/tickets_state.dart` —
      `TicketsLoaded` gains `blockedTicketIds` (`Set<String>`, default
      `const {}`) — constructor param, field, `props` entry (design.md
      §2.3). Dartdoc it, cross-referencing
      `TicketsCubit._computeBlockedTicketIds`.
- [x] T5. `features/tickets/presentation/cubit/tickets_cubit.dart` — new
      private `_computeBlockedTicketIds(List<Ticket> allTickets)`
      (design.md §2.1): queries `getLinksByTypes([blocks, blockedBy])`,
      resolves each row's `(blockee, blocker)` pair, returns blockee ids
      whose blocker's status (looked up in `allTickets`) isn't `done`.
      Returns `{}` if constructed without a `TicketLinkRepository`.
      Dartdoc it in full, including the direction-resolution rule.
- [x] T6. Same file — `searchTickets` and `loadMoreTickets`'s
      `TicketsLoaded` emission (design.md §2.2, the two call sites at
      the method bodies covering the Board's actual load path) both
      call `_computeBlockedTicketIds` on the freshly loaded page and
      pass the result as `blockedTicketIds`. Update both methods'
      dartdoc to note the new field.
- [x] T7. Same file — new private `_refreshBlockedBoardState()`
      (design.md §2.2): re-emits the current `TicketsLoaded` (no-op if
      `state is! TicketsLoaded`) with `blockedTicketIds` recomputed via
      `_computeBlockedTicketIds` against the state's own `tickets` list.
      Dartdoc it, mirroring `_refreshInFlightBoardState`'s dartdoc shape
      but noting this one recomputes from persisted data, not in-memory
      sets.
- [x] T8. Same file — add a `_refreshBlockedBoardState()` call at the
      end of `updateTicketStatus` (a blocker's status may have just
      changed) (design.md §2.2). No other behavioral change to that
      method.
