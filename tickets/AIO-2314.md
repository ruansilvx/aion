# Spec Delta: Ticket Parent Selection UX

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md's Screens section (TicketParentPicker)` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. the searchable/scrollable overlay, candidate breadcrumb, and getValidParentCandidates filtering this delta introduces are confirmed current.

## ADDED

- **`TicketsCubit.getAllTickets()`** — thin passthrough to
  `TicketRepository.getAllTickets()`. Query-only, emits no state. Feeds
  the create-time parent picker, which has no existing ticket to
  exclude self/descendants for.

- **A parent field on `CreateTicketScreen`** — reuses `TicketParentPicker`
  (see MODIFIED below). Hidden whenever the selected ticket type is
  `TicketType.epic`. Selecting a parent updates local form state only
  (`_selectedParentId`); the parent is persisted on submit via
  `TicketsCubit.createTicket`'s existing `parentId` parameter.
  Switching the type dropdown to `TicketType.epic` clears any already-
  selected parent.

- **`createTicketParentLabel` string** (`lib/l10n/app_en.arb`) — "Parent"
  label for the new create-form field.

- **`ancestorBreadcrumb(Ticket, Map<String, Ticket>, {int maxDepth})`**
  (`presentation/widgets/ticket_parent_picker.dart`) — pure function.
  Walks a ticket's `parentId` chain upward through a caller-supplied
  id-index, returning a `"Grandparent / Parent"`-style string (root-most
  first) or `null` if the ticket has no parent. Stops after `maxDepth`
  hops (default 8) or at the first id missing from the index, whichever
  comes first — a defensive bound, not a signal that cycles are expected
  (`TicketsCubit.updateTicketParent` still rejects those).

- **Ancestor breadcrumb subtitle on parent-picker candidate rows** — each
  row in the picker overlay's candidate list shows the existing
  `ticketId` + `title` line, plus a second muted-caption line below with
  the ancestor breadcrumb, omitted when the candidate has no parent.
  Computed from the same ticket list the picker already fetched for its
  candidate set — no additional query.

## MODIFIED

- **`TicketParentPicker`** (moved from `ticket_detail_screen.dart` to new
  file `presentation/widgets/ticket_parent_picker.dart`, along with its
  `_NoParentRow`/`_CandidateRow` row widgets) — constructor changes from
  `required Ticket ticket` to:
  - `required TicketType ticketType` — used only to gate whether the
    *caller* builds the picker at all (epics never take a parent); the
    widget itself no longer knows or cares whether the ticket it's
    editing already exists.
  - `required String? currentParentId` — drives the trigger's resolved-
    title display and the overlay's current-selection check mark.
  - `required Future<List<Ticket>> Function() candidatesLoader` —
    replaces the widget's internal
    `context.read<TicketsCubit>().getValidParentCandidates(widget.ticket)`
    call; each call site supplies its own loader (existing-ticket
    reparent flow passes `getValidParentCandidates(ticket)`, new create
    flow passes `getAllTickets()`).
  - `required ValueChanged<String?> onParentSelected` — replaces the
    widget's internal `context.read<TicketsCubit>().updateTicketParent(...)`
    call on commit; the existing-ticket call site still triggers
    `updateTicketParent` from this callback, the create-flow call site
    just updates local form state instead.

- **`TicketDetailScreen`'s `TicketParentPicker` usage site** — updated
  only for the constructor's new parameter names
  (`ticketType`/`currentParentId`/`candidatesLoader`/`onParentSelected`
  replacing `ticket:`). The `ticket.type == TicketType.epic ?
  SizedBox.shrink() : TicketParentPicker(...)` gate itself is
  pre-existing, not introduced by this change — it already matched
  `updateTicketParent`'s epic-rejection before this change, and
  `aion-arch/specs/tickets.md`'s current-state description of the
  parent editor (§Ticket Detail Screen) already documents that an epic
  ticket shows "no parent affordance at all". This bullet is listed
  under MODIFIED because the call site's code changed, not because its
  behavior did.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **`TicketsCubit.getValidParentCandidates` / `.updateTicketParent`** —
  cycle-detection algorithm (full descendant DFS via `_descendantIds`)
  is untouched. This change only changes how the picker widget is
  parameterized and rendered, not the validation logic behind it.
- **Bulk reparent.** Not added — out of scope per proposal.md.
- **Full indented tree view.** Not added — rejected in favor of the
  flat-list-plus-breadcrumb pattern; see proposal.md's "Why".
- **The duplicate `getAllTickets()` fetch** between picker-open and
  `updateTicketParent`'s commit-time re-validation. Pre-existing,
  unrelated to this change's UX scope.
- **`/tickets/new` route / entry points.** Still only reachable from the
  `TicketsListScreen` FAB, no query-param "create subticket under X"
  shortcut added.
