# 5. In `trashTicket`: **deviates from the original plan below** —

implementing it literally as written produced dead code, confirmed
with the user before proceeding (see commit body for the finding).
`trashTicket`'s existing `if (previousState is TicketDetailLoaded)`
branch doesn't check `previousState.ticket.id == id`, so being in
the `else` branch already guarantees no detail screen was open,
making a refresh call placed there unreachable. Fixed instead:
changed the guard to `previousState is TicketDetailLoaded &&
previousState.ticket.id == id` (only *that* case navigates away via
`TicketTrashed`); in the new `else` (list/board-shaped, **or** a
*different* ticket's detail screen open), only re-fetch/emit
`TicketsLoaded` when `previousState is! TicketDetailLoaded` (so a
different open detail screen's own state isn't clobbered by a
list-shaped emission), and fire
`unawaited(_refreshDetailIfOpenAndAffected({id}, fromState:
previousState))` unconditionally within that `else`. Updated the
method's dartdoc to document both the id-equality fix and the new
side effect.
