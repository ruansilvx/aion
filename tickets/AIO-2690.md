branch and `confirmPendingSkillAttachment`/
`rejectPendingSkillAttachment` each constructed a bare
`TicketDetailLoaded(ticket, ...)`, silently resetting every other
already-loaded field (`childDocs`, `canAdvanceSddStage`,
`isExecuting`, `pendingToolProposal`, etc.) to its default instead
of preserving them — contradicting design.md §3.3/T16's "mirrors
`_refreshDetailIfOpenAndAffected`'s existing pattern" instruction.
Same bug in `advanceSddStage`'s gated/manual branch (`emit
(TicketDetailLoaded(refreshed))`). Fixed: added
`TicketDetailLoaded.copyWith` (`tickets_state.dart` — `tasks.md`
T19 had called for one but it was never added) and routed all
four call sites through it, preserving `current`'s existing
fields and only touching the field each call site actually
changes (`pendingSkillAttachment` via a `TicketFieldSetter` for
explicit-clear, `isAdvancingStage`).
