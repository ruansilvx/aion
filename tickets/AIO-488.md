# T4. `features/tickets/presentation/widgets/chat_transcript_pane.dart`

— new file, `ChatTranscriptPane extends StatefulWidget` (design.md
§2 `ChatTranscriptPane` + §8 `Collapsing header`). Constructor:
`{ticketId, ticket}` — needs the full `Ticket`, not just its id,
to render `TicketMetadataSection`/`ChatMetaHeader` in its
collapsing header (§8.2). Owns a `ScrollController` (disposed in
`dispose()`) — pure view-layer state, not business logic.
`BlocConsumer<ChatCubit, ChatState>` (or `BlocListener`+
`BlocBuilder`) exhaustively switching `ChatInitial`/`ChatError`/
`ChatLoaded`. `ChatLoaded` renders a `CustomScrollView(controller:
_scrollController)` with:
1. `SliverPersistentHeader(pinned: true, delegate:
_CollapsingChatHeaderDelegate(ticket: ticket, onBack: ...))`
— a new private class in this file implementing
`SliverPersistentHeaderDelegate` per design.md §8.3:
`maxExtent`/`minExtent` measured from
`TicketMetadataSection`'s/`ChatMetaHeader`'s intrinsic
heights; `build` computes `progress = (shrinkOffset /
(maxExtent - minExtent)).clamp(0.0, 1.0)` and renders a
`Stack` cross-fading `Opacity(opacity: 1 - progress, child:
TicketMetadataSection(ticket: ticket))` over `Opacity(opacity:
progress, child: ChatMetaHeader(ticket: ticket, onBack:
...))`, each `IgnorePointer`-guarded at opacity `0`.
2. `SliverPadding(padding: EdgeInsets.fromLTRB(18, 14, 18, 8),
sliver: SliverList.builder(...))` rendering `"MESSAGES ·
{n}"` as the first item (§2.1 — **not** `"COMMENTS ·
<count>"`; needs a new l10n key, see T8) then one
`ChatMessageBubble` per comment, plus a trailing synthetic
item (only while `streamingText != null || currentToolUse !=
null`) rendering the moved-and-adapted `_StreamingBubble`
private class (moved from `ticket_detail_screen.dart`, now
also rendering `currentToolUse` as a status line — using a
**new `AionText.streamStatus` style**, add to `aion_text
.dart`: mono 12.5/w400/height 1.35 — ahead of `streamingText`
when present per §2.3, and rendering its accumulated text via
`MarkdownView` instead of the current `RichText`/plain-span
approach, keeping the existing blinking-caret indicator).
Empty state (§2.4 — sparkle glyph + caption, centered, no
messages yet), loading state (§2.5 — centered `AppSpinner`, no
new spec), error state (§2.6 — `danger`-tinted row, tap-to-retry)
render inside the list-sliver body. Auto-scroll: on every
`ChatLoaded` emission, `WidgetsBinding.instance
.addPostFrameCallback` calls `_scrollController.animateTo
(_scrollController.position.maxScrollExtent, ...)` (§2.2/§8.7) —
this naturally also collapses the header sliver to match the new
scroll position, no separate logic needed. File header + full
class/method dartdocs.
**Deviations:** (1) `maxExtent`/`minExtent` are fixed estimates
(560/140px), not dynamically measured — design.md §8.3 explicitly
allowed either choice; documented at the delegate. Content taller
than the estimate clips via `ClipRect`+`OverflowBox` rather than
overflowing. (2) The constructor also grew
`automationConfidence`/`onAdvanceSddStage`/`onMaybeAutoAdvance`
(forwarded to the collapsing header's `TicketMetadataSection`),
matching T1's deviation. (3) `_buildListItem`/`_buildEmptyState`
were written first as `Widget`-returning methods, then converted
to proper private widget classes (`_TranscriptListItem`,
`_ChatEmptyState`) per flutter-conventions.md's ban on that
pattern — caught by T10's grep check.
