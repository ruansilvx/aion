# Post-`/verify` fixes (CRITICAL findings from the first `/verify` pass)

- [x] T29. Add the `/workspace/tickets/:id` → `/workspace/pages/:id`
      redirect proposal.md commits to ("so there's exactly one
      creation/detail path per type, not two"), which the first
      `/apply` pass missed. Implemented as a content-level redirect in
      `ticket_detail_screen.dart`'s `TicketDetailLoaded` listener
      (simpler and more robust than a router-level `redirect:` callback,
      which can't reach `TicketRepository` — that's provided inside
      `WorkspaceShell`'s subtree, below where go_router's redirect
      callbacks run): when the loaded ticket is `TicketType.page`, call
      `context.go(ticketDetailRoute(ticket))` and return before any
      page-specific rendering runs. As a consequence, removed the now-
      unreachable `TicketType.page` branches from
      `ticket_detail_screen.dart` (`_isSyncable`, `_buildRepairBanner`'s
      `isPage` flag, and the `PageSubPagesSection` block, whose "+ Add"
      action pointed at `/workspace/tickets/new?initialType=page` — a
      dead target since T23 removed `page` from that dropdown). Updated
      the class doc comment accordingly. Verified via a real-Chrome
      manual pass (T28): created a page, then navigated directly to its
      `/workspace/tickets/:id` URL and confirmed it bounces to
      `/workspace/pages/:id`; confirmed a `Task` ticket's
      `/workspace/tickets/:id` is unaffected.

- [x] T30. Fix two wording bugs in `PageCreateScreen` found during
      `/verify`: the submit button read "Create ticket" (reusing
      `commonCreateTicket`) instead of "Create page", and the content
      field's `labelText` duplicated the placeholder sentence instead of
      a short label. Added `pageCreateSubmitAction` ("Create page") and
      `pageDetailContentLabel` ("Content") to `lib/l10n/app_en.arb`,
      regenerated via `flutter gen-l10n`, and wired both into
      `page_create_screen.dart`. Verified via the same real-Chrome pass
      as T29.
