# **Additional fix found via `flutter analyze`, not originally

listed**: `drift_ticket_repository_test.dart`'s pre-existing
`'onUpgrade backfills existing rows into the FTS5 search index'`
migration test manually drops `tickets.deleted_at` from a
simulated v1 schema *before* calling `createTicket` — safe before
this change (the insert companion never referenced that column),
broken after (task 2's `_buildInsertCompanion` fix now always
includes it). Reordered the test to drop `deleted_at` immediately
after the `createTicket` call instead, alongside the other
columns that were already dropped post-insert for the identical
reason, and updated its comment to explain why.
