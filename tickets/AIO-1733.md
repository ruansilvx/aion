# Design: Provider Configuration

## 1. Contracts — `core/contracts/agent_model_client.dart`

```dart
/// Provider-agnostic entry point for every model call in Aion. Concrete
/// providers (currently only [ClaudeAgentSdkClient]) implement this;
/// consuming Cubits depend on this interface only, never a provider
/// directly — see project.md's Pattern 1.
abstract interface class AgentModelClient {
  /// Starts a model run for [request], returning a stream of incremental
  /// [AgentEvent]s. The returned stream is finished by exactly one
  /// terminal event ([AgentDoneEvent] or [AgentErrorEvent]).
  Future<Stream<AgentEvent>> run(AgentRequest request);
}

/// A single request to an [AgentModelClient].
class AgentRequest extends Equatable {
  const AgentRequest({required this.prompt, required this.model});

  /// The user- or system-authored prompt text.
  final String prompt;

  /// The model identifier to run against — one of [AgentModel]'s `id`
  /// values. Not validated here; an unrecognized id is a provider-level
  /// error surfaced as [AgentErrorEvent].
  final String model;

  @override
  List<Object?> get props => [prompt, model];
}

/// One incremental event from an [AgentModelClient.run] stream.
sealed class AgentEvent extends Equatable {
  const AgentEvent();
}

/// A chunk of model-generated text.
class AgentTextEvent extends AgentEvent {
  const AgentTextEvent(this.text);
  final String text;
  @override
  List<Object?> get props => [text];
}

/// The run finished successfully. Always the last event on a successful
/// stream.
class AgentDoneEvent extends AgentEvent {
  const AgentDoneEvent();
  @override
  List<Object?> get props => [];
}

/// The run failed. Always the last event on a failed stream — no
/// [AgentDoneEvent] follows.
class AgentErrorEvent extends AgentEvent {
  const AgentErrorEvent(this.message);
  final String message;
  @override
  List<Object?> get props => [message];
}

/// The bridge process reported a plan usage-window / rate-limit signal
/// (e.g. Claude Code's opt-in overage prompt). Informational only — see
/// proposal.md's Non-goals for why this doesn't gate anything yet. May
/// be followed by further [AgentTextEvent]s if the underlying call still
/// completed, or by [AgentErrorEvent] if it didn't.
class AgentOverageDetectedEvent extends AgentEvent {
  const AgentOverageDetectedEvent(this.message);
  final String message;
  @override
  List<Object?> get props => [message];
}
```

No `ModelRouter` type ships in this change. `ProviderSettingsCubit`
(§4) reads the single configured `AgentModelClient` directly from
`RepositoryProvider` — there is exactly one provider and no phase
concept yet to route between. See §6 Deviations for what changes here
once a second real phase exists.

## 2. `core/agent/claude_agent_sdk_client.dart`

```dart
/// Sole [AgentModelClient] implementation for this MVP: spawns a bundled
/// Node.js bridge process per [run] call and parses its NDJSON stdout
/// into [AgentEvent]s. Desktop-only, same [isDesktop] gate as
/// `GitRepositoryClient`'s callers — construction is still safe on any
/// platform, but [run] throws if called where `dart:io Process` isn't
/// available.
class ClaudeAgentSdkClient implements AgentModelClient {
  ClaudeAgentSdkClient(this._bridgeLocator);

  final AgentBridgeLocator _bridgeLocator;

  @override
  Future<Stream<AgentEvent>> run(AgentRequest request) async {
    final scriptPath = _bridgeLocator.resolve();
    final process = await Process.start('node', [
      scriptPath,
    ], mode: ProcessStartMode.normal);

    process.stdin.writeln(jsonEncode({
      'prompt': request.prompt,
      'model': request.model,
    }));
    unawaited(process.stdin.close());

    return process.stdout
        .transform(utf8.decoder)
        .transform(const LineSplitter())
        .map(_parseLine)
        .where((event) => event != null)
        .cast<AgentEvent>();
  }

  AgentEvent? _parseLine(String line) { /* NDJSON -> AgentEvent mapping,
    matching agent_bridge/index.mjs's emitted shapes: {"type":"text",...},
    {"type":"done"}, {"type":"error",...}, {"type":"overage",...} */ }
}
```

Errors from `Process.start` itself (e.g. `node` not on `PATH`) surface
as a stream that emits a single `AgentErrorEvent` with a human-readable
message ("Node.js not found — install Node.js and ensure `node` is on
your PATH.") rather than throwing past `run`'s `Future`, so
`ProviderSettingsCubit`'s connection test has one code path for every
failure mode.

## 3. The Node.js bridge — `agent_bridge/`

Not part of the Flutter build; a sibling directory at the `aion/` repo
root, its own small Node project:

```
agent_bridge/
  package.json     — declares @anthropic-ai/claude-agent-sdk
  index.mjs        — reads one JSON request line from stdin, calls
                      query() from the SDK with { model, permissionMode }
                      (permissionMode restricted — no file/git/bash tool
                      access; this MVP has no coding-execution consumer),
                      writes one NDJSON line per SDK event to stdout:
                        {"type":"text","text":"..."}
                        {"type":"done"}
                        {"type":"error","message":"..."}
                        {"type":"overage","message":"..."}
```

`permissionMode` is fixed to a no-tool-access mode for every call this
MVP makes — Settings' "Test Connection" and any future ticket-estimation/
spec-phase caller are all plain text-in/text-out. A tool-enabled
coding-execution mode is a real, separate future need (per `/explore`'s
finding that Agent SDK's default tool loop shouldn't be the default for
non-coding calls) but has no caller in this change, so `AgentRequest`
doesn't yet grow a tool-access parameter for it — see §6 Deviations.

One-time setup (`cd agent_bridge && npm install`) is documented in
`project.md`'s Bootstrap & Dependency Notes, not automated — see
proposal.md's Non-goals.

## 4. `features/providers/`

### 4.1 Domain

```dart
/// The fixed set of models this MVP lets the user pick between. Not
/// discovered from a live endpoint (unlike Ollama's /api/tags) — Agent
/// SDK has no such endpoint. Extend this enum, not a settings screen
/// rewrite, if the confirmed-working model set changes at /apply time.
enum AgentModel {
  /// Claude Opus 4.8 — `claude-opus-4-8`. Highest capability, highest cost.
  opus('claude-opus-4-8', 'Opus 4.8'),

  /// Claude Sonnet 5 — `claude-sonnet-5`. Default balanced choice.
  sonnet('claude-sonnet-5', 'Sonnet 5'),

  /// Claude Haiku 4.5 — `claude-haiku-4-5`. Fastest, cheapest.
  haiku('claude-haiku-4-5', 'Haiku 4.5');

  const AgentModel(this.id, this.label);

  /// The identifier passed as [AgentRequest.model].
  final String id;

  /// Human-readable label for the Settings dropdown.
  final String label;
}

/// Connection-check outcome for the configured provider, tracked by
/// [ProviderSettingsCubit].
enum ProviderConnectionStatus {
  /// Not yet checked this session.
  unknown,

  /// A connection test is currently running.
  checking,

  /// The last test succeeded.
  connected,

  /// The last test failed — see the Cubit state's accompanying message.
  disconnected,
}

/// Persists the user's selected [AgentModel]. Plain reads/writes only —
/// no validation (validation belongs in [ProviderSettingsCubit], per
/// project.md's Cubit-vs-repository split).
abstract interface class AgentSettingsRepository {
  Future<AgentModel> getSelectedModel();
  Future<void> setSelectedModel(AgentModel model);
}
```

`SharedPrefsAgentSettingsRepository` (`data/repositories/`) implements
the above with `shared_preferences`, storing `AgentModel.id` under a
single string key. No `flutter_secure_storage` — nothing secret is
stored (Agent SDK auth lives entirely in the user's existing Claude
plan credentials, outside Aion's control).

### 4.2 `ProviderSettingsCubit`

```dart
sealed class ProviderSettingsState extends Equatable {
  const ProviderSettingsState();
}

/// Initial state, before [ProviderSettingsCubit.load] resolves.
class ProviderSettingsLoading extends ProviderSettingsState {
  const ProviderSettingsLoading();
  @override
  List<Object?> get props => [];
}

/// Loaded — carries the persisted model selection plus the current
/// connection-check outcome. [statusMessage] is null except when
/// [status] is `disconnected` (holds the human-readable reason) or
/// `connected` (holds an overage/rate-limit notice, if the last test
/// surfaced one — see [AgentOverageDetectedEvent]).
class ProviderSettingsReady extends ProviderSettingsState {
  const ProviderSettingsReady({
    required this.selectedModel,
    required this.status,
    this.statusMessage,
  });
  final AgentModel selectedModel;
  final ProviderConnectionStatus status;
  final String? statusMessage;
  @override
  List<Object?> get props => [selectedModel, status, statusMessage];
}

/// Business logic for the Settings screen: loads the persisted model,
/// runs/re-runs the connection test, and persists model changes. Holds
/// real logic (not a thin pass-through) per project.md's Cubit-domain-logic
/// convention: [selectModel] rejects a change while a test is already
/// `checking` rather than racing two in-flight tests.
class ProviderSettingsCubit extends Cubit<ProviderSettingsState> {
  ProviderSettingsCubit(this._client, this._repository)
      : super(const ProviderSettingsLoading());

  final AgentModelClient _client;
  final AgentSettingsRepository _repository;

  /// Loads the persisted model, then immediately runs one connection
  /// test — the "auto-detected" behavior project.md's original design
  /// described, adapted to Agent SDK's lack of a plan-introspection API:
  /// this is a live test call, not a static credential check.
  Future<void> load() async { /* ... */ }

  /// Re-runs the connection test against the currently selected model.
  /// No-ops if a test is already in flight.
  Future<void> testConnection() async { /* ... */ }

  /// Persists [model] as the selection, then re-runs the connection
  /// test against it. No-ops (see above) while a test is in flight.
  Future<void> selectModel(AgentModel model) async { /* ... */ }
}
```

## 5. Wiring

- `main.dart` (`AionApp`'s `MultiRepositoryProvider`) gains
  `RepositoryProvider<AgentBridgeLocator>`,
  `RepositoryProvider<AgentModelClient>` (constructs
  `ClaudeAgentSdkClient`), and `RepositoryProvider<AgentSettingsRepository>`
  (constructs `SharedPrefsAgentSettingsRepository`) — app-level, not
  per-project, alongside the existing `ProjectRepository`/
  `BaselineRepository`/`EmbeddingProvider` providers. Provider identity
  isn't a per-project concept.
- `core/routing/app_router.dart` gains one `GoRoute` inside the existing
  `ShellRoute`: `/workspace/settings`, wrapping `SettingsScreen` in
  `BlocProvider<ProviderSettingsCubit>` (constructed from the app-level
  `AgentModelClient`/`AgentSettingsRepository`, same `context.read`
  pattern every other route in this file already uses) — chosen over a
  top-level route (like `/hub`) because it's only reachable from
  `WorkspaceNavShell`'s secondary-actions popover, which only renders
  once a project is active.
- `core/routing/workspace_nav_shell.dart`'s `_SecondaryAction` enum
  gains a `settings` value; its `itemLabel`/`onSelected` `switch`
  expressions gain matching cases (`context.l10n.settingsScreenTitle`,
  `context.go('/workspace/settings')`) — mechanical extension of the
  existing `switchProject`/`trash` pattern, no restructuring.

## 6. Deviations from `project.md` §3/§5's originally-documented design

`project.md` currently describes a six-provider `ModelRouter` resolving
`phase → provider+model`, a "Settings → Models" screen with per-phase/
tier rows, and a proactive budget-gate. This change ships a smaller
slice — one provider, one global model setting, no phase routing, no
`AutomationConfidence`/budget gate — for the reasons in proposal.md's
Non-goals. `tasks.md` includes updating `project.md` §3/§5 to describe
what actually ships here, rather than leaving it describing an
unbuilt design that no longer matches the codebase. It also flags,
inline, that `ModelRouter`'s `resolve()` and `AgentRequest` are each
one field away (a `ModelPhase` param, a tool-access param) from
supporting per-phase routing and coding-execution tool access — additive
changes for whichever future change first has a real second phase or a
real coding-execution caller, not a redesign.

# Aion — Provider Configuration: Settings Screen Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md) and reuses the status-pill family established in [Sync Status & Repair](./Aion%20Sync%20Status%20and%20Repair%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name. **No Material widgets or types anywhere** — every surface below is `DecoratedBox` / `Container` / `Row` / `Column` / `GestureDetector` / `MouseRegion` / `CustomPaint` / `Padding` / `AnimatedFoo`, never `Card`, `ElevatedButton`, `Scaffold`, `ThemeData`, `ColorScheme`, `ListTile`, `AppBar`, `SnackBar`, `CircularProgressIndicator`, `DropdownButton`, or `InkWell`.

One new screen and one one-row addition to an existing popover:

1. `SettingsScreen` (`/workspace/settings`) — header, provider status card, model dropdown (§2).
2. `ProviderStatusCard` — provider name, connection-status badge, optional status-message line, "Test Connection" button (§3).
3. `ProviderConnectionBadge` — the four-state connection pill (§4).
4. `TestConnectionButton` — five-state utility button (§5).
5. `ModelDropdown` — labeled select + open item-list popover (§6).
6. Status-message line — conditional row beneath the badge (§7).
7. Secondary-actions popover "Settings" row — one new item in the existing `SelectionMenu` (§8).

Mockups: [Aion Provider Configuration Mockups](./Aion%20Provider%20Configuration%20Mockups.dc.html).

## 1. Foundations added

### 1.1 Connection-state enum

```dart
enum ProviderConnectionState { unknown, checking, connected, disconnected }
```

`unknown` is the initial state before any test has run. `checking` is the transient state while a test is in flight — during it the Cubit refuses to start a second test, which drives the button's disabled state (§5).

### 1.2 New derived-tint tokens

Follow the established `AionColorsHubTokens` derived-tint pattern (compute from a base token + theme-dependent alpha; higher alpha in Obsidian than Arctic; never a standalone hex). Add to that helper class:

```dart
// success family — connected
Color connectedTint(bool isDark)       => success.withOpacity(isDark ? 0.20 : 0.14); // badge fill
Color connectedBorderTint(bool isDark) => success.withOpacity(isDark ? 0.42 : 0.34); // badge border

// warning family — disconnected ("not yet working", NOT destructive → warning, not danger)
Color disconnectedTint(bool isDark)       => warning.withOpacity(isDark ? 0.20 : 0.14); // badge fill
Color disconnectedBorderTint(bool isDark) => warning.withOpacity(isDark ? 0.42 : 0.34); // badge border
```

`unknown` carries **no fill and no border** (mirrors the sync badge's `synced` state), so it needs no tint token.

**As-built note:** the `checking` state does *not* get its own `checkingTint`/`checkingSpinnerTrack` helpers. As flagged in proposal.md's Design gate non-blocking notes, those would have been numerically identical to the existing `pendingTint`/`pendingSpinnerTrack` on `AionColorsHubTokens` (same `primary` base, same alpha values) — `/apply` reused those two existing helpers directly at `ProviderConnectionBadge`'s `checking`-state call sites instead of adding duplicates. Four new helpers were added, not six: `connectedTint`, `connectedBorderTint`, `disconnectedTint`, `disconnectedBorderTint`.

**No new hex values, no new color tokens.** All families reuse existing `AionColors.success` / `warning` / `primary`. The `disconnected` choice of **`warning`** over `danger` is deliberate and matches the Sync spec's reasoning: a provider that hasn't connected yet is an expected, recoverable condition, not a destructive action or crash — `danger` stays reserved for delete/error.

### 1.3 Type token

`isDark` throughout = `theme.brightness == Brightness.dark` (Obsidian). No new radius, spacing, or type tokens are required. The badge reuses `AionText.chip`; the card reuses `AionText.caption` / `cardTitle` / `bodySm`; the button reuses `AionText.button`; the dropdown reuses `AionText.label` / `bodySm`.

## 2. `SettingsScreen`

A simple, single-column page. Renders inside the existing persistent navigation shell (sidebar on wide, bottom bar on compact) — the shell is unchanged; this screen only supplies the scrolling content.

### 2.1 Outer layout

- Background: `AionColors.background` (the screen canvas; the card below is the `surface`-toned panel that sits on it).
- **Content column:** single column, horizontally centered, `maxWidth: 560`. On a wide desktop window the column is capped at 560 and centered in the available width (never stretched edge-to-edge); on narrow windows / phone it fills the width inside the gutter.
- **Horizontal gutter:** `AionSpacing.sp20` (20) left/right (matches the app's other screens).
- **Vertical rhythm** between the three zones:
  - header → card: `AionSpacing.sp24` (24)
  - card → model group: `AionSpacing.sp24` (24)
- Top padding above the header: `AionSpacing.sp8` (8); comfortable bottom padding: `AionSpacing.sp32` (32).

### 2.2 Header zone

`Row`, `crossAxisAlignment: center`, `gap: AionSpacing.sp12` (12):

- **Back control** — the app's standard header icon-button (identical to the Create/Detail screens' back button): `37×37`, fill `surfaceHover`, `1px border`, radius `AionRadius.iconBtn` (11), centered chevron-left glyph 20px `textPrimary`. `GestureDetector` → `AnimatedScale(0.96 on press, 90ms)`; hover → border `borderStrong`; focused → focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), spreadRadius: 3, blurRadius: 0)`. Pops the route back to where the popover was invoked.
- **Title** — `"Settings"`, `AionText.h2` (Manrope 22 / w800 / -0.22), color `textPrimary`.

No trailing cluster, no eyebrow — the title alone anchors the page.

## 4. `ProviderConnectionBadge`

The connection-status pill. Follows the `SyncStatusBadge` visual family exactly — same pill shape, same leading-icon + uppercase-chip-label arrangement, same "quiet default / calm active / tinted problem" treatment — with its own four states. Non-interactive (a status readout, not a control): no hover/press/focus fill change, no disabled state.

### 4.0 Shared geometry (all states)

- Layout: `Row`, `mainAxisSize: min`, `crossAxisAlignment: center`, `gap: 6` (7 in `checking`).
- Radius: `AionRadius.pill` (22).
- Label: `AionText.chip` (10.5 / w700 / +0.53), **UPPERCASE string**, color per state.
- Leading glyph box: intrinsic, size per state.
- Height: intrinsic (~24px). No shadow in any state.

### 4.1 State table

| State | Padding (LTRB) | Fill | Border | Icon (px) | Icon color | Label | Label color |
|---|---|---|---|---|---|---|---|
| `unknown` | `8, 5, 10, 5` | none | none | hollow circle `○` 13 | `textMuted` | `"NOT TESTED"` | `textMuted` |
| `checking` | `9, 5, 11, 5` | `checkingTint` | none | spinner 12 (§4.2) | `primary` | `"CHECKING"` | `primary` |
| `connected` | `9, 5, 11, 5` | `connectedTint` | `1px connectedBorderTint` | seal-check ✓ 12 | `success` | `"CONNECTED"` | `success` |
| `disconnected` | `9, 5, 11, 5` | `disconnectedTint` | `1px disconnectedBorderTint` | warning triangle 12 | `warning` | `"NOT CONNECTED"` | `warning` |

- `unknown` recedes exactly like sync `synced`: no fill, no border, muted grey in both themes.
- `connected` uses the `success` family; unlike sync's borderless states, connected/disconnected carry a **1px tinted border** so the "resolved" pills read as deliberate results rather than transient chrome.

### 4.2 Spinner (`checking`)

Identical to the sync badge's in-progress spinner — **no Material `CircularProgressIndicator`**. A `CustomPaint` (or `AnimatedBuilder` + `Transform.rotate`) driven by a repeating `AnimationController` (period **750ms**, `linear`, `..repeat()`):

- `12×12` ring, `strokeWidth: 2`, `StrokeCap.round`.
- Track arc: full circle, color `checkingSpinnerTrack(isDark)`.
- Head arc: ~90° sweep, color `primary`, rotating.
- Dispose the controller when the badge leaves `checking`.

### 4.3 Theme parity

Structure identical across Arctic and Obsidian; every color resolves from the active `AionColors` + the §1.2 tints, so one widget serves both.

## 7. Status-message line

The small text row beneath the badge (inside the card, §3.3), shown **only** when there is something to say. Two occasions, distinguished by leading glyph but sharing one text treatment:

- Layout: `Row`, `crossAxisAlignment: start`, `gap: 8`.
- **Leading glyph:** 13px, color `warning`, `margin-top: 1` for optical alignment with the first text line.
- **Text:** `AionText.bodySm`, color `textSecondary`, `height: 1.45`, wraps freely (`Expanded`).

Both variants use `warning` for the glyph — neither is a destructive/`danger` condition — and the same `textSecondary` body. They differ only by glyph, which is enough to signal register:

| Occasion | When | Leading glyph | Example copy |
|---|---|---|---|
| **Error reason** | with `disconnected` | warning triangle | `"Couldn't reach the Claude Agent SDK. Check that you're signed in to your Claude plan and try again."` |
| **Informational overage** | with `connected` | info circle `ⓘ` | `"Connected, but you're over your plan's usage limit right now — responses may be rate-limited until it resets."` |

When the state is `unknown` or `checking`, or when a `connected` state has no overage, the line is **not in the tree** (no reserved space).
