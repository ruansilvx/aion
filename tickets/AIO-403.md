      same way the existing `verifying`/`archived` branch does

      and optional `(blockedBy: <title>)` suffix. Update the method's
      dartdoc to list this new branch alongside the existing ones.
- [x] T10. Same file — new private `_parseDecomposition(String reply,
      TicketType childType)` (design.md §3.2): regex-parses the
      `## Decomposition` block into an ordered `List<(String title,

      lines — not an error. Dartdoc it with the exact regex/prefix rule.
- [x] T11. Same file — new private `_materializeDecomposition(Ticket
      parent, String reply)` (design.md §3.3): parses via
      `_parseDecomposition`, creates one child ticket per line
      (`TicketRepository.createTicket`, `parentId: parent.id`), builds a
      `title.toLowerCase() → id` map as each is created, then creates a
      `blockedBy` link (new child as `source`, resolved sibling as
      `target`, via `TicketLinkRepository.createLink`) for every
      resolvable `blockedByTitle`. Requires `_linkRepository`
      (optional-dependency guard, same style as `loadDocumentRelations`).
      An unresolved title skips the link only, not the ticket. Dartdoc
      it in full, including the fail-open contract.
