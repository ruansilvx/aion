# T12. `design_system/molecules/linked_tickets_section.dart` —

contract change from `List<Ticket> tickets` to `List<LinkedTicketRef>
links`, adding required `onRemove (ValueChanged<String>)` and
`onChangeType (void Function(String linkId, TicketLinkType
newRelativeType))` callbacks (design.md §3, §6). `_LinkRow` gains:
the relative-type glyph/label (T1's promoted extension methods),
a hover-revealed remove action wired to a confirmation step before
calling `onRemove`, and a hover-revealed edit action opening a new
private `_LinkTypeEditor` (`SelectionMenu`-based, mirroring
`ticket_link_picker.dart`'s `_LinkTypeSelectorRow` mechanics)
restricted to the caller-supplied `linkTypeOptions` — omitted
entirely for a row whose `relativeType` is `duplicatedBy`
(design.md §7's carve-out). Per design.md §0 (piece placement) §1
(`RelationshipIndicator`), §2 (row hover/action-revealed state),
§3 (row action buttons), §4 (`_LinkTypeEditor`), §5 (remove
confirmation popover), and §6 (full-row variants) — implement the
exact geometry/state tables there, not a from-scratch design.
Note design.md's `LinkTypeSelector` references are this
codebase's existing private `_LinkTypeSelectorRow`
(`ticket_link_picker.dart`), not a differently-named class to
hunt for. Use `c.destructiveTint(isDark)`/`c.pressedAccentTint
(c.danger, isDark)` directly for §3.3/§7.2's remove-button fills
rather than the doc's own recomputed `danger.withOpacity(...)`
figures (see /design-sync's Step 2 note — the doc's cited
`0.11/0.16` for `destructiveTint` doesn't match that token's real
`0.14/0.20`). Dartdoc the changed class and every new private
widget/method.
