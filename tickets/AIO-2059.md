# T29. Modify `lib/features/tickets/presentation/screens/ticket_detail_screen.dart`

per design.md §4 — register/unregister the viewed ticket with
`ActiveTicketViewRegistry` (guarded reads via `_tryReadRegistry`,
since the registry isn't provided on mobile/web); insert
`TicketSyncStatusBadge` into the header's trailing `Row` (§4.1);
insert `TicketNeedsRepairBanner` (wrapped in a per-ticket
`TicketRepairCubit`) as the first child of the detail body's
inner `Column` when `needsRepair` (§4.2) — both gated on
`ticket.type ∈ {resource, page}` **and** sync tracking actually
being active (registry presence), not type alone — otherwise a
resource/page ticket on mobile/web would show a "SYNCED" badge
implying a mechanism that doesn't exist there. **Corrected from
design.md**: the banner's own horizontal margin (§3.1's
`AionSpacing.sp20`) is dropped to 0 — the screen already wraps
its body in `Padding(EdgeInsets.fromLTRB(20, 16, 20, 16))`, so
keeping design.md's margin would double the inset.
