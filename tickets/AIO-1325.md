# 6. Screens & widgets (design-gated — do not implement final visuals until `/design-sync` sets the gate to APPROVED)

- [x] 6.1 Create `aion/lib/features/tickets/presentation/widgets/inbox_history_item.dart` —
      `InboxHistoryItem` presentational row per design.md §5
      `InboxHistoryItem` (dot-plus-label pill badge §5.2, 56px row,
      states §5.4): purpose badge/icon (keyed off `Ticket.inboxPurpose`),
      title, relative timestamp (`relative_time_format.dart`). Tapping
      navigates via a caller-supplied callback (no direct `context.go`
      inside this widget, matching `DocumentationTreeItem`'s
      precedent). No business logic. Also add the `inboxAccentFor`
      purpose→accent lookup this row and the launcher (task 6.3) share
      (design.md §0.3) — as a private helper in this feature's
      presentation layer, not a `design_system/` extension, since it
      takes the feature-local `InboxPurpose` enum and `design_system/`
      must stay feature-agnostic per project.md's cross-feature rule
      (the export's own snippet shows it living alongside `AionColors`,
      which would violate that rule). Full dartdocs.

      dartdocs.
- [x] 6.3 Create `aion/lib/features/tickets/presentation/screens/inbox_screen.dart` —
      `InboxScreen` per design.md §2 `InboxScreen` (layout/header/
      history-label), §3 Launcher section (`_LauncherGrid`: 2×2 wide /
      stack narrow, 560px inner breakpoint), and §4 Purpose-launcher
      entries (§4.1 shared card geometry, §4.2/§4.5 the two
      inline-input purposes' expand-in-place behavior, §4.3/§4.4 the
      two one-tap purposes' in-flight state, §4.6 single-expanded-card
      invariant): header, four-purpose launcher (brain-dump/Q&A open an
      inline text input before submitting; what-next/release-planning
      trigger immediately on tap), history section (`InboxHistoryItem`
      list or `InboxEmptyState`), body wrapped in
      `ContentMaxWidth(variant: reading)` matching `DocumentationScreen`'s
      layout. Requires the new `AionText.inboxCardLabel` style (design.md
      §0.3 — add to `aion/lib/design_system/tokens/aion_text.dart`) and
      an `AionShadows.focus` signature widening to accept an optional
      `Color? color` (defaulting to `c.primary`, every existing caller
      unaffected) so the launcher cards' per-entry accent-colored focus
      ring (§4.1.1) doesn't need a second, duplicate shadow helper.
      Calls `InboxCubit.load()` in `initState`; on any `start*` call's
      returned ticket id, navigates to `ticketDetailRoute(ticket)`.
      `BlocListener` surfaces `InboxError` via `AppToast.show` (reusing
      the shell-level toast convention, per
      `board-execution-indicators-and-notifications`'s precedent,
      rather than a screen-local error view). Full class + state
      dartdocs.
