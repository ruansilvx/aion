# Spec delta: Page-nesting depth limit

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (7/8 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`.

## MODIFIED

- **`DocumentationTreeItem`** (`presentation/widgets/
  documentation_tree_item.dart`) — its tree-mode indent calculation
  (`leftPad = 12 + depth * 20` when `showChevron` is `true`) now clamps
  the effective depth it indents for at `6` (`_maxIndentDepth`): rows
  nested at depth 7 or deeper render at the same fixed indent as a
  depth-6 row, rather than continuing to grow indent per level. Depths
  `0`–`6` are unaffected. Flat mode (`showChevron: false` — search
  results) is unaffected; it already used a fixed, depth-independent
  `leftPad` of `14`. Per-row expand/collapse chevrons remain fully
  functional at any depth — only the visual indent signal flattens
  past the clamp, not navigation.

## REMOVED

- The Known Gaps bullet "No page-nesting depth limit is enforced" (and
  its identical duplicate in "Known gaps carried forward") — resolved
  by the `DocumentationTreeItem` change above. Replace both occurrences
  with a short note that `page`-nesting depth itself remains
  intentionally unbounded (a deliberate decision, not a gap — see
  `aion-arch/ideas/page-nesting-depth-limit.md`), with only the tree
  row's visual indent capped for narrow-viewport correctness.

## Unchanged (explicitly, to prevent scope drift at /apply)

- `TicketTypeHierarchy.canParent`'s `page`-under-`page` structural
  rule.
- Every `TicketsCubit` create/reparent invariant — no depth check is
  added anywhere in the data or domain layers.
- `PageSubPagesSection` / `_SubPageRow` — already a flat, single-level
  list with fixed indent; not a tree, never affected by nesting depth.
- `DocumentationTreeItem`'s flat/search-result variant
  (`showChevron: false`) — already fixed, depth-independent `leftPad`.
