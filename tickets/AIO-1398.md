# Design: Page-nesting depth limit

## Scope

Single-file, presentation-layer change:
`lib/features/tickets/presentation/widgets/documentation_tree_item.dart`.
No Cubit, repository, entity, or drift-schema change — there is no new
BLoC state to define. `DocumentationScreen`'s existing recursive
depth-passing (`_DocTreeNode`-equivalent private widget building
`depth: depth + 1` per level) is untouched: it keeps incrementing the
*true* depth forever, exactly as today. Only what
`DocumentationTreeItem` does with that number when computing its own
`leftPad` changes.

## Current behavior (baseline)

```dart
final leftPad = widget.showChevron ? 12 + widget.depth * 20 : 14;
```

- Tree mode (`showChevron: true`, `DocumentationScreen`'s collapsible
  body): `leftPad` grows 20px per level with no ceiling.
- Flat mode (`showChevron: false` — search results, and
  `PageSubPagesSection`'s separate `_SubPageRow`, which doesn't use
  this widget at all): fixed `14`, already depth-independent, already
  safe. Not touched by this change.

## The clamp

Add one constant and clamp `depth` before it feeds the formula:

```dart
/// Deepest nesting level [DocumentationTreeItem] still visually
/// indents past. Rows nested beyond this render flush with rows at
/// this depth — see `aion-arch/changes/page-nesting-depth-limit/`.
static const int _maxIndentDepth = 6;

// ...

final effectiveDepth = widget.depth > _maxIndentDepth
    ? _maxIndentDepth
    : widget.depth;
final leftPad = widget.showChevron ? 12 + effectiveDepth * 20 : 14;
```

### Why 6

Worked from the narrowest viewport this project targets (a 320px-wide
phone — see `project.md`'s Platform Support), and the row's own fixed
(non-indent, non-title) content width in tree mode:

| Element | Width |
|---|---|
| Chevron column + spacing | 18 + 9 = 27 |
| Type icon + spacing | 20 + 9 = 29 |
| Right padding | 14 |
| Row `margin` (8px each side) | 16 |
| **Fixed subtotal** | **86px** |

Reserving a minimum ~100px for the title column (enough for a short
ellipsized title plus its own text padding — below this, the row
already reads as cramped regardless of indent) leaves a budget of
`320 - 86 - 100 = 134px` for `leftPad` before content starts fighting
for space. Solving `12 + depth * 20 <= 134` gives `depth <= 6.1`, so
**`_maxIndentDepth = 6`** (`leftPad` maxes out at `12 + 6*20 = 132px`)
is the deepest level that still leaves that reserved title width
intact on the narrowest supported viewport. On wider viewports the
same cap simply leaves more breathing room — it never needs to be
larger there since the row layout is otherwise unaffected by width.

This also fully resolves the underlying correctness bug this change
exists to fix, not just the visual one: without a ceiling, a deep
enough tree on a narrow viewport pushes the fixed-subtotal + `leftPad`
past the available row width, and the title column's `Expanded` is
asked for negative space — a `RenderFlex overflowed by Npx` exception
in debug, silently clipped/misrendered content in release. The clamp
makes that arithmetically impossible at any depth, on any supported
viewport width, since `leftPad` now has a fixed ceiling independent of
how deep the real tree goes.

## Widget tree (unchanged shape, one internal calculation changed)

```
DocumentationScreen
 └─ (tree mode) recursive depth-first builder
     └─ DocumentationTreeItem(depth: N, showChevron: true, ...)  ← same tree shape
         └─ Padding(left: clamp(N, 0, 6) * 20 + 12)              ← only this line changes
             └─ Row[ chevron?, icon, title/breadcrumb, childCount? ]
```

No new widgets are introduced. `PageSubPagesSection` / `_SubPageRow`
and the flat search-result variant are structurally untouched (already
depth-independent).

## Behavior at the clamp boundary

- Depths `0`–`6`: indent increases 20px per level, exactly as today.
- Depths `7`+: all render at the same `leftPad` as depth `6` — visually
  flush with their nearest ancestor that's still at (or past) the
  clamp. A row at depth 6 and its depth-9 descendant render with
  identical indent.
- Expand/collapse chevrons remain per-row regardless of depth — a
  clamped row with children still shows its own chevron and toggles
  normally. Navigation/expansion behavior is completely unaffected;
  only the indent visual signal flattens past the clamp.
- No "you've hit the visual limit" affordance, tooltip, or badge is
  added — the flush indent *is* the signal, matching how this pattern
  reads in comparable flattened-depth tree UIs elsewhere. Revisit only
  if real usage shows this reads as confusing, not preemptively.

# Aion — Page-Nesting Depth Limit: Component Spec

A targeted revision to one existing widget — **`DocumentationTreeItem`** — that caps the *visual* indent of the Documentation tree at depth 6. Extends the [Aion Documentation Section Spec](./Aion%20Documentation%20Section%20Spec.md) (§4 `DocumentationTreeItem`, §1.5 indentation unit); references `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name. **No Material widgets anywhere** — the row is `GestureDetector` → `AnimatedContainer` over `Row` / `Column` / `Padding` / `CustomPaint` / `AnimatedRotation`, never `Card`, `ListTile`, `Scaffold`, `AppBar`, `InkWell`, `ThemeData`, or `ColorScheme`.

- **No new screen, no new component.** `DocumentationScreen` (`/workspace/documentation`) and its already-shipped tree of `DocumentationTreeItem` rows are the only surface affected.
- **Only the indent number changes past depth 6.** Fill, border, radius, chevron, type icon, title, child-count pill, and all interaction states are reused from Documentation Section §4 *unchanged*.
- `c` = active `AionColors` (`arctic` / `obsidian`); `isDark` = Obsidian. One code path, both themes; only token values differ.
- Companion mockups: [Aion Page-Nesting Depth Limit Mockups](./Aion%20Page-Nesting%20Depth%20Limit%20Mockups.dc.html) — depth ladder `1a`, desktop-at-clamp `1b`, desktop-past-clamp `1c`, mobile `1d`.

---

## 1. The problem & the change

### 1.1 Problem

`DocumentationTreeItem`'s tree-mode row indents `20` px deeper per nesting level with **no ceiling** (Documentation §1.5, §4.0: `leftPad = 12 + depth * 20`). Page tickets nest arbitrarily deep, so on a narrow viewport a sufficiently deep branch drives the row's title column toward — and past — zero available width, producing a layout overflow (`RenderFlex overflowed`) in the title `Expanded`.

### 1.2 Change

Clamp the *visual* indent at **depth 6**. Rows deeper than 6 render at the depth-6 indent (132 px) instead of continuing to step outward.

```dart
// existing (Documentation §4.0):
final double leftPad = 12 + depth * 20.0;            // unbounded

// new:
const int kDocTreeMaxIndentDepth = 6;                // visual clamp only
final double leftPad = 12 + math.min(depth, kDocTreeMaxIndentDepth) * 20.0;
```

- **Actual nesting depth is unchanged and unbounded** — the data tree, `depth` value, expand/collapse, and child building are untouched. Only the *rendered indent* saturates.
- **Nothing else in the row changes.** This clamp replaces one expression; every other property of the row is exactly Documentation §4.

### 1.3 What carries "still nested" past the clamp

Once two adjacent depths share the same 132 px indent, indent alone can no longer distinguish a clamped-depth child from a same-level sibling. The **expand/collapse chevron** carries that signal: a `page` row with children always shows its chevron (Documentation §4.0 item 1), at every real depth, clamped or not. A parent at depth 6 shows a chevron; its child at depth 7 sits at the same indent but is disclosed *underneath* an expanded chevron — the reveal relationship, not the indent step, reads the nesting. Resources and childless pages keep their `18` px chevron spacer, so titles stay column-aligned exactly as before.

## 2. Indent formula & the depth ladder

### 2.1 Formula

`leftPad` = left padding applied to the row's content box (Documentation §4.0):

```
leftPad = 12 + min(depth, 6) * 20    // px
```

- `12` — base gutter = `AionSpacing.sp12`.
- `20` — per-level step = `AionSpacing.sp20`.
- `6` — clamp depth = `kDocTreeMaxIndentDepth` (see §5).
- Saturates at `12 + 6 * 20 = 132` px.

### 2.2 Ladder (depth 0 → 8)

| Depth | `min(depth, 6)` | `leftPad` | Steps from previous |
|---|---|---|---|
| 0 | 0 | **12 px** | — |
| 1 | 1 | **32 px** | +20 |
| 2 | 2 | **52 px** | +20 |
| 3 | 3 | **72 px** | +20 |
| 4 | 4 | **92 px** | +20 |
| 5 | 5 | **112 px** | +20 |
| 6 | 6 | **132 px** | +20 |
| 7 | 6 | **132 px** | **+0 (clamped)** |
| 8 | 6 | **132 px** | **+0 (clamped)** |

Depths 6, 7, and 8 render at **visually identical** indent (132 px). This is correct and intended — the tree continues to descend (chevrons prove it); only the indent's outward growth stops.

## 3. `DocumentationTreeItem` — row spec (reused, unchanged)

Reproduced here for review so implementation can cite an exact section. Every value is exactly Documentation §4; the **only** delta is the `leftPad` expression in §3.1.

### 3.1 Geometry

- **Container:** `GestureDetector` → `AnimatedContainer` (120 ms fill), full width.
- **Padding:** `EdgeInsets.fromLTRB(leftPad, 9, 14, 9)`, `leftPad = 12 + math.min(depth, 6) * 20.0` **(§1.2 — the sole change)**.
- **Outer margin:** `EdgeInsets.symmetric(horizontal: 8)` so the hover/selected fill is an inset rounded pill.
- **Radius:** `AionRadius.md` (10) on the fill box.
- **Structure:** `Row`, `crossAxisAlignment: center`, `gap: 9`:
  1. **Chevron column** — fixed `18` px wide. `page` with children → chevron-right `14 px` `c.textMuted`, `AnimatedRotation` to `90°` (down) when expanded (140 ms). Childless page or any resource → empty `18` px spacer (glyph omitted, space preserved). *Present at every real depth, including clamped depths 6+.*
  2. **Type icon** — `20×20`. Page → file-text `c.typePage`; resource → bookmark `c.typeResource` (Documentation §2.2 bare glyph).
  3. **Title** — `AionText.cardTitle` (Manrope 14 / w600), `c.textPrimary`, `Expanded`, `maxLines: 1`, `TextOverflow.ellipsis`.
  4. **Trailing meta** (optional) — child-count pill on collapsed pages: `AionText.key` (JetBrains Mono 11), `c.textMuted`, fill `c.surfaceHover`, `EdgeInsets.fromLTRB(6, 2, 6, 2)`, radius `5`. Omitted for resources and zero-child pages.

- **Border:** none. **Shadow:** none. **Icon size:** `14 px` chevron, `20×20` type glyph. **Icon color:** chevron `c.textMuted`; type glyph `c.typePage` / `c.typeResource`.

### 3.2 States

Identical to Documentation §4.6 — the clamp changes no state treatment.

| State | Fill | Rail (left, 3 px, radius 2) | Title | Chevron | Transform |
|---|---|---|---|---|---|
| **Default** | transparent | none | `c.textPrimary` | `c.textMuted` (page w/ children) | — |
| **Hover** | `c.surfaceHover` | none | `c.textPrimary` | `c.textSecondary` | — |
| **Pressed** | `c.surfaceHover` | none | `c.textPrimary` | `c.textSecondary` | `AnimatedScale` 0.99 (80 ms) |
| **Selected** | `c.primarySubtle` | `c.primary` | `c.textPrimary` | `c.textMuted` | — |
| **Focused** | `c.primarySubtle` | `c.primary` | `c.textPrimary` | `c.primary` (glyph→`primary`) | — |
| **Disabled** | n/a — rows are never disabled | — | — | — | — |

- **Error:** n/a — a tree row has no invalid input state.
- **Focus ring:** the left rail + `primarySubtle` tint (Documentation §4.4) — no `BoxShadow` ring, to stay quiet in a dense list.

### 3.3 Theme parity

Structure identical across Arctic and Obsidian; every color resolves from the active `AionColors`. `typePage` = `#B0499E` (Arctic) / `#D98CE6` (Obsidian); `typeResource` = `#C2622E` / `#E68A4E`. The clamp introduces no theme-dependent value.

## 4. Viewport behavior

The clamp exists specifically to keep the row's icon + title layout intact on narrow viewports. Both viewports use the identical row and identical `leftPad` formula; only the surrounding column width differs.

### 4.1 Desktop / wide (`≥840` px)

- Tree wrapped in `ContentMaxWidth(variant: reading)` → **840 px**, centered on `c.background`; rows on `c.surface`, top `1px c.border` (Documentation §3.3).
- At 840 px, even the deepest visible title has ample room; the clamp is invisible here except that depths 6–8 share one indent. Renders correctly at and past the clamp boundary (mockups `1b`, `1c`).

### 4.2 Narrow / mobile (`320`–`375` px)

- Same `DocumentationScreen` body at phone width (canvas `375×…`, Documentation §3).
- **Without the clamp:** at 375 px, a depth-9 title box computes to roughly `375 − 16(gutters) − (12 + 9*20)(indent) − 18(chevron) − 9(gap) − 20(icon) − …` → negative → overflow.
- **With the clamp:** indent saturates at 132 px, so the title `Expanded` retains a stable minimum width (≈ `375 − 16 − 132 − 18 − 9 − 20 − 14 ≈ 166` px) at any real depth. Icon + title stay legible and never clip (mockup `1d`).
- No horizontal scroll, no `RenderFlex overflow`, at any nesting depth.

---

## 5. Tokens

**No new `AionColors`, `AionRadius`, or `AionSpacing` member is required.** Every value resolves to an existing token.

- **Colors** — `c.surface`, `c.surfaceHover`, `c.border`, `c.primary`, `c.primarySubtle`, `c.textPrimary`, `c.textSecondary`, `c.textMuted`, `c.typePage`, `c.typeResource`. No new color.
- **Radius** — `AionRadius.md` (10) row fill; `5` child-count pill; `2` left rail. No new radius.
- **Type** — `AionText.cardTitle` (title), `AionText.key` (count pill). No new style.
- **Spacing** — base gutter `AionSpacing.sp12` (12), per-level step `AionSpacing.sp20` (20), row `gap: 9`, vertical padding `9`, right padding `14`, outer margin `8`, chevron column `18`, clamped max `132`.

### 5.1 Suggestion (not required): name the clamp constant

The clamp depth `6` is the one genuinely new literal. The `20`/`12` step constants already have exact `AionSpacing` names (`sp20` / `sp12`) and need no change. Recommend introducing a single named constant rather than a bare literal so the ceiling is greppable and testable:

```dart
/// Visual indent stops growing past this nesting depth (data depth stays unbounded).
const int kDocTreeMaxIndentDepth = 6;
```

Scope it to the Documentation feature (e.g. `DocumentationTreeItem` or a `doc_tree_constants.dart`), not `AionSpacing` — it is a depth count, not a spacing length, so it does not belong in the spacing scale.

## 6. States coverage summary

| Aspect | default | hover | focused | pressed | disabled | error |
|---|---|---|---|---|---|---|
| `DocumentationTreeItem` row (§3.2) | ✓ | ✓ | ✓ | ✓ | n/a (never disabled) | n/a (no input) |
| Indent clamp (§2) | applies uniformly across all row states — it is a layout constant, orthogonal to interaction state | | | | | |

The clamp is a pure layout change: it alters one padding value and no state treatment, color, radius, or type. Depths 0–6 step by 20 px; depths ≥ 6 hold at 132 px; the chevron carries the "tree continues" signal past the clamp.
