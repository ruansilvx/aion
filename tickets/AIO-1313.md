# 3. Model-phase resolution and reparent guard

- [x] 3.1 Modify `aion/lib/features/tickets/presentation/cubit/chat_cubit.dart` —
      `_phaseForChat` gains a first-checked branch: if the resolved
      chat ticket's `inboxPurpose != null`, return the phase from a new
      private purpose→`ModelPhase` mapping (brainDump/whatNextGuidance/
      releasePlanning → `frontier`, qa → `capable`) without consulting
      `parentId`. Update the method's dartdoc: this is now a second,
      parent-independent resolution path, not purely a defensive
      fallback.
- [x] 3.2 Modify `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart` —
      `updateTicketParent` gains an additional rejection condition
      alongside the existing `ticket.type.isAlwaysRoot` check: also
      reject (via the same `_emitInvalidParent` path) when
      `ticket.type == TicketType.chat && ticket.inboxPurpose != null`
      and `newParentId != null`. Update the method's dartdoc to
      describe this second, instance-level rejection case alongside
      the existing type-level one.
- [x] 3.3 Extend `test/features/tickets/presentation/cubit/chat_cubit_test.dart`
      — a chat with `inboxPurpose: qa` resolves `ModelPhase.capable`
      regardless of `parentId`; each of the other three purposes
      resolves `frontier`; a non-Inbox chat's existing parent-walk
      behavior is unchanged. Extend
      `test/features/tickets/presentation/cubit/tickets_cubit_test.dart`
      — `updateTicketParent` on an Inbox-purpose chat with a non-null
      target parent emits the invalid-parent error; the same call on an
      ordinary (non-Inbox) chat with a parent already set behaves
      exactly as before this change.
