## ADDED

- **`SddStage.designBrief`/`SddStage.designSync`** (`domain/enums/sdd_stage.dart`)
  — two new values inserted between `proposed` and `verifying`. Only
  reachable by `TicketType.story` tickets whose child Tasks indicate UI
  work (see `TicketsCubit._storyNeedsDesignReview`); every Epic, and
  every Story whose Tasks don't, skips both and goes `proposed →
  verifying` as before. No schema change — `SddStage` is stored as plain
  `.name` text with no DB-level constraint.
- **`TicketsCubit._nextSddStage`** — changes signature from
  `SddStage? _nextSddStage(SddStage? current)` to `Future<SddStage?>
  _nextSddStage(Ticket ticket)`; the `proposed → ?` branch now inspects
  the ticket's child Tasks to decide between `designBrief` and
  `verifying`.
- **`TicketsCubit._storyNeedsDesignReview(List<Ticket> tasks)`** — private
  helper, keyword heuristic (`widget`/`screen`/`component`/`ui`,
  case-insensitive) against each Task's title+description, mirroring
  `/propose`'s own design-gate trigger condition. Computed fresh on
  every check, not persisted.
- **A design Page ticket, auto-created and linked** —
  `TicketsCubit._spawnStageChat`'s new `SddStage.designBrief` branch
  creates a `TicketType.page` ticket titled `"Design — <Story title>"`
  and links it to the Story via `TicketLinkRepository.createLink`
  (`TicketLinkType.relatesTo`) — the same doc-to-ticket link mechanism
  Documentation pages already use. This is where the human pastes their
  Claude Design export (mirrors `design.md` as its own artifact); no new
  content data model, reuses the existing page-content editing surface.
- **`TicketsCubit._linkedDesignPage(String storyId)`** — finds a Story's
  linked design Page by walking `TicketLinkRepository.getLinksForTicket`
  and matching the `"Design — "` title prefix.
- **`TicketsCubit._designSyncApproved(String storyId)`** — checks whether
  the Story's `"Design Sync — "`-prefixed chat's most recent comment is
  an `ai` reply containing the literal line `DESIGN GATE: APPROVED`
  (mirrors `/design-sync`'s own final-summary line format). Unlike the
  existing `_mostRecentChatHasTerminalReply` (any reply unlocks
  advancement), this checks reply *content* — a `DESIGN GATE: PENDING`
  reply does not unlock `verifying`.
- **`TicketsCubit.retryDesignSync(Ticket designSyncChat)`** — new public
  method. Re-assembles fresh `designSync` context (picking up any edit
  made to the linked Page since the last check) and posts another turn
  to the existing `designSync` chat, via the same `ChatCubit.runChatTurn`
  helper every stage-chat spawn already uses. No-ops outside a
  `designSync`-stage chat.
- **`TicketsCubit._readTokenFilesForContext()`** — reads
  `aion_colors.dart`/`aion_text.dart`/`aion_radius.dart` off disk (via
  `_projectRootPath`, the same desktop-only gate `_gitProjector` already
  uses) for inclusion as plain-text context in `designBrief`/`designSync`
  spawned chats — mirrors `/design-brief`/`/design-sync`'s own
  `cat`-injected token context. Not a new tool-access capability; the
  cubit reads these files itself when assembling context, the spawned
  chat still runs with zero tool access like every other stage.
- **`SddStageBlockReason.awaitingDesignPaste`/`.awaitingDesignApproval`**
  (`presentation/cubit/tickets_state.dart`) — two new hint-reason values
  for `TicketDetailLoaded.sddStageBlockReason`.
- **`TicketDetailLoaded.needsDesignReview`** (new field, `bool?`) —
  computed by `TicketsCubit.getTicketById` for `story` tickets via
  `_storyNeedsDesignReview` against current child Tasks; `null` until
  Tasks exist to evaluate.
- **Variable-length SDD-stage tracker** (`_SddStageSection`'s `_stages`)
  — 6 nodes (Explore/Propose/Design Brief/Design Sync/Verify/Archive)
  while `needsDesignReview` is `true` or `null` (not yet known); collapses
  to the original 4 nodes only once confirmed `false`.
- **"Retry validation" action** (new `_RetryValidationButton` widget) —
  shown on a `"Design Sync — "`-prefixed chat ticket's detail screen when
  its parent Story is at `SddStage.designSync` and its most recent AI
  reply says `DESIGN GATE: PENDING`. Calls `TicketsCubit.retryDesignSync`.
- New l10n keys: `ticketDetailSddStageDesignBrief`,
  `ticketDetailSddStageDesignSync`, `ticketDetailSddStageDesignBriefing`,
  `ticketDetailSddStageDesignSyncing`,
  `ticketDetailSddStageHintAwaitingDesignPaste`,
  `ticketDetailSddStageHintAwaitingDesignApproval`, `chatRetryValidation`.

## MODIFIED

- **`TicketsCubit._sddStageAdvanceCheck`** — gains `SddStage.designBrief`/
  `SddStage.designSync` cases (see ADDED above for the checks each
  performs). Every existing case (`null`, `exploring`, `proposed`,
  `verifying`, `archived`) is unchanged.
- **`TicketsCubit._spawnStageChat`** — gains `SddStage.designBrief`/
  `SddStage.designSync` branches (design-Page creation for the former;
  both reuse the existing create-chat/post-context/`runChatTurn`
  sequence unchanged).
- **`TicketsCubit._assembleStageContext`** — gains `SddStage.designBrief`/
  `SddStage.designSync` branches, both appending token-file context via
  `_readTokenFilesForContext`; existing `verifying`/`archived` branches
  unchanged.
- **`TicketsCubit._stagePresentName`** — gains `SddStage.designBrief =>
  'Design Brief'` / `SddStage.designSync => 'Design Sync'` arms.
- **`_SddStageSection`'s `_stageLabel`/`_stageStatusLabel`** — gain
  `SddStage.designBrief`/`SddStage.designSync` arms, backed by the new
  l10n keys above.

## Out of scope (see proposal.md)

- No read-only (or any new) tool-access tier — dropped after re-grounding
  in `/design-sync`'s actual mechanics (see proposal.md's "Grounding
  correction"). `designBrief`/`designSync` run with the same zero-tool
  access every existing stage chat already has.
- No per-phase/tier model routing — both new stages use the existing
  hardcoded `AgentModel.sonnet` default.
- No changes to Task tickets, coding execution, or
  `task-to-coding-execution-trigger`'s own scope.
