# Tasks: Page-nesting depth limit

Strict order. See `design.md` for the exact arithmetic/rationale behind
`_maxIndentDepth = 6` and `proposal.md`/`specs/spec.md` for scope
boundaries (no data-model or Cubit change).

- [x] **T1 — Clamp `DocumentationTreeItem`'s tree-mode indent.** per
  design.md §1.2 Change, §3.1 Geometry
  `aion/lib/features/tickets/presentation/widgets/documentation_tree_item.dart`:
  - Add `static const int _maxIndentDepth = 6;` on
    `_DocumentationTreeItemState`, with a dartdoc comment stating what
    it caps and pointing at this change directory (see `design.md`'s
    code sketch for the exact comment).
  - Replace the direct `widget.depth * 20` use in the `leftPad`
    calculation with a depth first clamped to `_maxIndentDepth`
    (`depth > _maxIndentDepth ? _maxIndentDepth : depth`, or
    `.clamp(0, _maxIndentDepth)` — either is fine, pick whichever reads
    more idiomatically next to the existing code).
  - Update the `depth` field's existing dartdoc (currently: "Nesting
    depth in the tree (`0` for root docs). Ignored (`leftPad` is
    fixed) when `showChevron` is `false`...") to also note that values
    past `_maxIndentDepth` render at the same indent as
    `_maxIndentDepth` itself, rather than continuing to grow.
  - File header comment already exists and needs no change (no new
    top-level symbol added — `_maxIndentDepth` is an existing class's
    member).
  - No change to `DocumentationScreen`'s recursive `depth: depth + 1`
    building — it keeps passing the true, unbounded depth; only this
    widget's own use of that number changes.

- [x] **T2 — Add a widget test covering the clamp.**
  New file `aion/test/features/tickets/presentation/widgets/documentation_tree_item_test.dart`,
  following this directory's existing pattern (see
  `inbox_history_item_test.dart` for the `_wrap`/`ThemeScope`/
  `WidgetsApp` harness shape — reuse the same wrapping approach here).
  Add a one-line file header comment per this project's documentation
  standard. Cover:
  - Indent increases normally below the clamp (e.g. assert the
    rendered `Padding`'s left inset at `depth: 3` equals `12 + 3*20 =
    72`, via `tester.widget<Padding>(find.byType(Padding).first).padding`
    or an equivalent `find`-based assertion matching this codebase's
    existing widget-test idioms).
  - Indent is identical at `depth: 6` and at a depth past it (e.g.
    `depth: 10`) — both equal `12 + 6*20 = 132` — proving the clamp
    actually caps rather than merely slowing growth.
  - `showChevron: false` (flat/search-result mode) still renders the
    fixed `14` regardless of `depth`, unaffected by this change (a
    regression guard, not new behavior).
