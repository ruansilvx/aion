# Proposal: Model-Agnostic Naming in `project.md`

## What

Reword `aion-arch/project.md`'s Agentic Engine section (Foundational
Decisions §3) and its cross-references in §5 so every agentic tier is
named by its **role** (coding execution, conversational reasoning,
lightweight on-device tasks) with the vendor/provider that currently
fills that role demoted to a parenthetical example — the same pattern
`project.md` already uses for the conversational-reasoning tier
("Messages API (or any configured provider)"). Remove the resulting
now-resolved known gap from `aion-arch/specs/README.md`.

This is a documentation-only change. No `lib/` code exists for the
agentic engine yet (confirmed via `/explore`: zero matches for
`Claude|Anthropic|GPT|OpenAI|Gemini|AgentModelClient|ModelRouter`
anywhere in `aion/lib/`), so there is nothing to retrofit — only prose
to fix before the first implementation copies today's vendor-locked
wording verbatim.

## Why

`project.md`'s own "What Is Aion" section states: "Aion is
agent/model-agnostic by design — no user-facing text, docs, or naming
should hardcode a specific vendor or model provider... This is not yet
fully true of this document." `aion-arch/specs/README.md`'s Known gaps
section names the specific drift: the desktop coding-execution tier
(§3) is described only as "Claude Agent SDK" with no provider-agnostic
framing, and that same vendor name leaks into §5's Capability tiers,
Orchestration pattern, and Watcher implementation note whenever they
reference Tier 3 execution.

Fixing this now — while the agentic engine is still pure spec, before
any code exists — is cheap (prose only) and prevents the drift from
becoming baked into class names, file names, or user-facing strings
once the model-routing feature is actually implemented.

## Scope

In scope:
- `aion-arch/project.md` — reword §3 (Agentic Engine) subsection
  headers and body text, and the §5 mentions of Tier 3 execution
  (Capability tiers, Orchestration pattern, Watcher implementation
  note), to lead with the tier's role and demote the vendor to an
  example.
- `aion-arch/project.md` — remove the "This is not yet fully true of
  this document" caveat sentence in "What Is Aion" once the drift it
  points at is fixed.
- `aion-arch/specs/README.md` — remove the resolved Known gaps bullet.

Out of scope:
- §5's Provider configuration list (Settings → Providers) is
  intentionally vendor-specific — it's the user-facing list of
  concrete provider options, not Aion's own architecture naming. No
  change needed there.
- Any `lib/` code — none exists for this area yet.
- Inventing new Dart interfaces/types. `AgentModelClient`'s existing
  shape (`Future<Stream<AgentEvent>> run(AgentRequest request)`)
  already covers every tier generically; this change only fixes prose,
  it does not propose new architecture.
