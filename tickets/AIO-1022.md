# Error-message localization pattern

- [x] **T10** — In the tickets Cubit state file: add a
      `TicketsErrorReason` enum (starting with `notFound`) and change
      `TicketsError` to carry it instead of a raw hardcoded message
      string. Update `tickets_cubit.dart`'s
      `emit(const TicketsError('Ticket not found'))` site accordingly.
      Add a `ticketsErrorMessage(BuildContext, TicketsErrorReason)`
      mapping function (co-located with the T8/T9 label functions) and
      update every widget that renders `TicketsError.message` to resolve
      through it instead. Dartdoc on the new enum, field, and function.
- [x] **T11** — `aion/lib/core/utils/duration_format.dart`: replace the
      thrown `FormatException('Not a valid duration: "$input"')` with a
      new `InvalidDurationFormatException` carrying the raw `input`
      value as structured data (no baked-in message). Update the
      formatter's `placeholder` parameter so callers must supply a
      localized string rather than relying on the `'Not set'` default.
      Update the catch site (`inline_editable_field.dart` or wherever
      the parse error is currently caught and shown via `AppToast`) to
      resolve the message via `context.l10n.durationInvalidFormat(input)`
      / `context.l10n.durationNotSet`. Dartdoc on the new exception type.
- [x] **T12** — `ticket_detail_screen.dart`: rework the title-empty
      validation so it no longer throws
      `FormatException("Title can't be empty")` with a baked-in message
      — check the condition directly where `BuildContext` is already
      available and use `context.l10n.ticketDetailTitleEmptyError` at
      the point of use (e.g. the `AppToast` call).
