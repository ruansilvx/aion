# Spec Delta: Ticket Deletion

**Reconciled 2026-09-03, with real drift folded in:** this delta's block-on-children hard-delete model (`TicketRepository.deleteTicket` throwing `TicketHasChildrenException` when the target has children) was fully superseded by the trash mechanism (see the Ticket Trash & Bulk Delete spec ticket). Current `aion-arch/specs/tickets.md`'s "Trash & bulk delete" section is explicit: "There is no block-on-children behavior anywhere in this surface: cascading into Trash is always safe, because it's always reversible." `deleteTicket`/`TicketHasChildrenException` no longer exist; trashing/restoring/permanently-deleting replaced them entirely. This ticket's content is historical only — the mechanism it describes was replaced, not merely extended.

Delta against `aion-arch/specs/tickets.md`. On `/archive`, these changes
merge into that file's prose (not appended as a changelog).

## ADDED

### Domain

- `TicketHasChildrenException` (`domain/exceptions/`) — thrown by
  `TicketRepository.deleteTicket` when the target has structural
  children. Carries `childCount`.
- `TicketRepository.deleteTicket(String id)` — cascades to comments and
  `ticket_links` rows referencing the ticket (either direction); throws
  `StateError` if `id` doesn't exist; throws `TicketHasChildrenException`
  (deleting nothing) if any ticket has `parentId == id`.

### Data

- `TicketDao.countChildTickets(String parentId)` — count of tickets with
  `parent_id == parentId`.
- `TicketDao.deleteTicketRow(String id)` — deletes the ticket row only;
  callers cascade dependent rows first.
- `TicketLinkDao.deleteLinksForTicket(String ticketId)` — deletes every
  link row where `ticketId` is source or target.
- `CommentDao.deleteCommentsForTicket(String ticketId)` — deletes every
  comment for `ticketId`. The sole exception to `CommentDao`'s
  append-only-by-construction design.
- `DriftTicketRepository.deleteTicket` — checks existence, checks
  children, then runs comment-delete + link-delete + ticket-row-delete
  in one Drift transaction.

### Presentation

- `TicketsState`: `TicketDeleting`, `TicketDeleted`.
- `TicketsErrorReason.hasChildren`; `TicketsError` gains an optional
  `childCount` field, set only when `reason == hasChildren`.
- `TicketsCubit.deleteTicket(String id)` — `TicketDeleting` →
  `TicketDeleted` on success, or `TicketsError` (classified
  `hasChildren` with `childCount`, or generic) on failure.
- `TicketOverflowMenu` (feature-local, `ticket_detail_screen.dart`) — the
  `TicketDetailScreen` header's `⋮` trigger, now interactive. Lists
  "Delete ticket" (destructive-styled). Same
  `Overlay`/`LayerLink`/`CompositedTransformFollower` mechanics as
  `SelectionMenu`/`MoveToStatusMenu`.
- `showAppConfirmDialog` + `AppConfirmDialog`
  (`core/widgets/app_confirm_dialog.dart`) — reusable, non-Material,
  `Overlay`-based confirmation dialog. Returns `Future<bool>`.
- `TicketDetailScreen` reacts to `TicketDeleted` (navigate to
  `/tickets`) and `TicketsError(reason: hasChildren)` (count-aware
  `AppToast`).

### Localization

- New `app_en.arb` keys: `ticketDetailOverflowMenuLabel`,
  `ticketDeleteMenuItem`, `ticketDeleteConfirmTitle`,
  `ticketDeleteConfirmMessage`, `ticketDeleteConfirmAction`,
  `ticketDeleteBlockedByChildren` (ICU plural).

## MODIFIED

- `CommentDao`'s class-level dartdoc — no longer "No UPDATE or DELETE
  methods are exposed"; now notes the single cascade-delete exception
  used by ticket deletion.
- `TicketDetailScreen` header — `⋮` trigger changes from a static,
  non-interactive `PhosphorIcon` to the `TicketOverflowMenu` trigger.

## REMOVED

None.

## Known gaps introduced (carry into `tickets.md`'s Known Gaps list on `/archive`)

- `TicketOverflowMenu`'s "Delete ticket" row and its `⋮` trigger have no
  Hover/Focused/Pressed visual states and no keyboard focus path for the
  row itself — mouse-only. Matches the same pre-existing gap in
  `SelectionMenu`/`MoveToStatusMenu`'s overlay list items; deferred to a
  shared follow-up pass across all three rather than fixed per-widget.
  See design.md §6.2.
- The overflow menu's container shadow reuses `AionShadows.card`, which
  returns an empty shadow list in Obsidian — the menu renders with no
  shadow at all in dark theme. Same root cause as above (shared,
  deferred fix). See design.md §6.2.

## Unaffected (explicitly, to prevent scope creep during `/apply`)

- `parentId` remains non-editable — still deferred to its own future
  change.
- `status` remains board-only, via `TicketRepository.updateTicketStatus`
  — unchanged.
- No delete affordance added to `TicketsListScreen` or `TicketBoardView`.
- No bulk delete, undo, trash, or soft-delete.
- `ticket_links` still has no consuming UI beyond this change's deletion
  cascade — that gap is untouched.
