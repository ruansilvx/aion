# Design: Reconciler applies hand-edited parentId/deletedAt changes

## Overview

No new widgets/screens/BLoC states — this is a data/presentation-cubit
layer change. The new logic lives in one new plain service class,
consumed by three existing classes (two of which already delegate
similar shared logic to a sibling plain service today —
`PageWikilinkIndexer`).

```
                     ┌─────────────────────────┐
                     │  TicketParentTrashService │   NEW — data/services/
                     │  (plain class, no Cubit)  │
                     └────────────┬─────────────┘
                 ┌─────────────────┼──────────────────┐
                 │                 │                  │
        ┌────────▼───────┐ ┌───────▼────────┐ ┌───────▼─────────────┐
        │  TicketsCubit   │ │  TrashCubit    │ │ TicketMarkdownReconciler │
        │ (UI-facing)     │ │ (UI-facing)    │ │ (background, no UI)     │
        └─────────────────┘ └────────────────┘ └──────────────────────┘
                 │                                        │
                 │                              ┌─────────▼─────────┐
                 │                              │ TicketRepairService │
                 │                              │  .reformat()        │
                 │                              └────────────────────┘
```

`TicketsCubit`/`TrashCubit` each construct their own instance (mirroring
the existing `TicketRollupRecomputer` pattern — see `tickets_cubit.dart`
and `trash_cubit.dart`, both of which already independently construct
their own `TicketRollupRecomputer(_repository, gitProjector:,
projectRootPath:)`). `TicketMarkdownReconciler` and `TicketRepairService`
receive an instance via constructor injection from `app_router.dart`,
same DI scope `TicketGitProjector` already sits at.

## New file: `data/services/ticket_parent_change_result.dart`

Sealed result type for `TicketParentTrashService.changeParent`, mirroring
`TicketMarkdownParseResult`'s existing sealed-type pattern (its own file,
`core/markdown/ticket_markdown_parse_result.dart`):

```dart
/// Outcome of [TicketParentTrashService.changeParent].
sealed class ParentChangeResult {
  const ParentChangeResult();
}

/// The reparent was valid and applied. [ticket] is the refreshed row.
class ParentChangeSuccess extends ParentChangeResult {
  const ParentChangeSuccess(this.ticket);
  final Ticket ticket;
}

/// The reparent was rejected (self-parent, cycle, always-root type,
/// Inbox-spawned chat, or a candidate parent whose type cannot
/// structurally parent this ticket's type). Nothing was written.
class ParentChangeRejected extends ParentChangeResult {
  const ParentChangeRejected();
}
```

No sub-reason payload — every existing caller (`TicketsCubit`'s
`TicketsErrorReason.invalidParent`) already treats every rejection cause
identically, so there's nothing for a richer type to buy today.

## New file: `data/services/ticket_parent_trash_service.dart`

```dart
/// Shared parentId/trash/restore domain logic — cycle-prevention and
/// type-compatibility validation for reparenting, and the git-projection
/// + rollup-recompute side effects that accompany a trash/restore —
/// used by both `TicketsCubit`/`TrashCubit` (in-app edits, which wrap
/// this in their own UI-state emission) and `TicketMarkdownReconciler`/
/// `TicketRepairService` (external file edits and repair, which have no
/// UI state to emit). Follows the same shared-plain-service pattern as
/// `PageWikilinkIndexer` for the identical dual-caller shape, rather
/// than pushing this logic down into `TicketRepository` — see
/// `aion-arch/ideas/reconciler-applies-hand-edited-parentid-deletedat.md`.
class TicketParentTrashService {
  /// Creates a [TicketParentTrashService] backed by [_repository].
  /// [gitProjector]/[projectRootPath] are optional, matching
  /// `TicketRollupRecomputer`'s identical optional-dependency pattern —
  /// `null` for either simply no-ops the git-projection side effect.
  TicketParentTrashService(
    this._repository, {
    TicketGitProjector? gitProjector,
    String? projectRootPath,
  }) {
    _gitProjector = gitProjector;
    _projectRootPath = projectRootPath;
    _rollupRecomputer = TicketRollupRecomputer(
      _repository,
      gitProjector: gitProjector,
      projectRootPath: projectRootPath,
    );
  }

  final TicketRepository _repository;
  late final TicketGitProjector? _gitProjector;
  late final String? _projectRootPath;
  late final TicketRollupRecomputer _rollupRecomputer;

  /// Reassigns [ticket]'s parent to [newParentId] (`null` clears it).
  /// Validation is byte-for-byte the same as `TicketsCubit
  /// .updateTicketParent`'s existing checks (moved here verbatim): self-
  /// parenting, always-root types, an Inbox-spawned chat, a cycle
  /// (walking descendants), and structural type-compatibility
  /// (`TicketTypeHierarchy.canParent`). On success, persists via
  /// [TicketRepository.updateTicketParent], fires the same
  /// [TicketRollupRecomputer.recompute] fire-and-forget rollup update
  /// seeded from `{ticket.id, ?oldParentId}` `TicketsCubit
  /// .updateTicketParent` already fires, and returns
  /// [ParentChangeSuccess] with the refreshed ticket. On any rejection,
  /// returns [ParentChangeRejected] without writing anything.
  Future<ParentChangeResult> changeParent(
    Ticket ticket,
    String? newParentId,
  ) async {
    final oldParentId = ticket.parentId;
    if (newParentId != null) {
      if (newParentId == ticket.id) return const ParentChangeRejected();
      if (ticket.type.isAlwaysRoot) return const ParentChangeRejected();
      if (ticket.type == TicketType.chat && ticket.inboxPurpose != null) {
        return const ParentChangeRejected();
      }
      final all = await _repository.getAllTickets();
      if (_descendantIds(ticket.id, all).contains(newParentId)) {
        return const ParentChangeRejected();
      }
      final candidateParent = await _repository.getTicketById(newParentId);
      if (candidateParent == null ||
          !candidateParent.type.canParent(ticket.type)) {
        return const ParentChangeRejected();
      }
    }

    await _repository.updateTicketParent(ticket.id, newParentId);
    final refreshed = await _repository.getTicketById(ticket.id);
    if (refreshed == null) return const ParentChangeRejected();
    unawaited(
      _rollupRecomputer.recompute(
        {ticket.id, ?oldParentId},
        'rollup updated',
      ),
    );
    return ParentChangeSuccess(refreshed);
  }

  /// Trashes the ticket with internal id [id] via
  /// [TicketRepository.trashTicket] — which already carries the full
  /// descendant-cascade logic, so no validation happens here beyond what
  /// the repository itself already guards (the ticket existing). Mirrors
  /// `TicketsCubit._trashGitSideEffects`: projects the trashed ticket to
  /// git (`'trashed'`) and fires a rollup recompute seeded from the
  /// ticket's pre-trash `parentId`. Returns the trashed [Ticket], or
  /// `null` if the repository call failed (id not found).
  Future<Ticket?> trash(String id) async {
    final preTrash = await _repository.getTicketById(id);
    if (preTrash == null) return null;
    await _repository.trashTicket(id);
    final trashed = await _repository.getTicketById(id);
    if (trashed != null) await _triggerGitProjection(trashed, 'trashed');
    unawaited(
      _rollupRecomputer.recompute({?preTrash.parentId}, 'rollup updated'),
    );
    return trashed;
  }

  /// Restores the ticket with internal id [id] via
  /// [TicketRepository.restoreTicket] — which already revives trashed
  /// ancestors/descendants. Mirrors `TrashCubit`'s existing
  /// `_restoreGitSideEffects`: projects the restored ticket to git
  /// (`'restored'`) and fires a rollup recompute seeded from its
  /// (now-restored) `parentId`. Returns the restored [Ticket], or `null`
  /// if the repository call failed (id not found).
  Future<Ticket?> restore(String id) async {
    final existing = await _repository.getTicketById(id);
    if (existing == null) return null;
    await _repository.restoreTicket(id);
    final restored = await _repository.getTicketById(id);
    if (restored != null) await _triggerGitProjection(restored, 'restored');
    unawaited(
      _rollupRecomputer.recompute({?existing.parentId}, 'rollup updated'),
    );
    return restored;
  }

  /// Applies any `parentId`/`deletedAt` transition present in [fields]
  /// (a `TicketMarkdownParseResult.ParsedOk.fields`/`ParsedPartial
  /// .validFields` map) against [ticket] — the single entry point shared
  /// by `TicketMarkdownReconciler` (the live watcher path) and
  /// `TicketRepairService.reformat` (the explicit repair action), so
  /// both apply identical parentId/deletedAt semantics instead of each
  /// re-deriving the field-presence/transition-direction logic
  /// separately. A key absent from [fields], or present but equal to
  /// [ticket]'s current value, is a no-op for that field. Returns
  /// `false` if a present, *changed* `parentId` or `deletedAt` was
  /// rejected — `true` otherwise (including when neither field has a
  /// relevant transition at all).
  Future<bool> applyFromParsedFields(
    Ticket ticket,
    Map<String, Object?> fields,
  ) async {
    var ok = true;
    if (fields.containsKey(TicketMarkdownTemplate.parentId)) {
      final newParentId = fields[TicketMarkdownTemplate.parentId] as String?;
      if (newParentId != ticket.parentId) {
        final result = await changeParent(ticket, newParentId);
        if (result is ParentChangeRejected) ok = false;
      }
    }
    if (fields.containsKey(TicketMarkdownTemplate.deletedAt)) {
      final newDeletedAt = fields[TicketMarkdownTemplate.deletedAt] as DateTime?;
      if (newDeletedAt != null && ticket.deletedAt == null) {
        if (await trash(ticket.id) == null) ok = false;
      } else if (newDeletedAt == null && ticket.deletedAt != null) {
        if (await restore(ticket.id) == null) ok = false;
      }
      // A changed-but-still-non-null deletedAt timestamp (re-trashing an
      // already-trashed ticket with a different stamp) has no
      // corresponding domain operation — left as a no-op, matching
      // today's behavior for any other unsupported transition.
    }
    return ok;
  }

  Future<void> _triggerGitProjection(Ticket ticket, String eventLabel) async {
    final projector = _gitProjector;
    final rootPath = _projectRootPath;
    if (projector == null || rootPath == null) return;
    await projector.project(ticket, rootPath, eventLabel);
  }

  /// Same descendant-walk as `TicketsCubit._descendantIds` — duplicated
  /// rather than shared, since `TicketsCubit`'s copy also backs
  /// `getValidParentCandidates` (a picker-list query untouched by this
  /// change) and extracting a shared helper for one ~15-line pure
  /// function isn't worth the indirection.
  Set<String> _descendantIds(String rootId, List<Ticket> all) {
    final childrenByParent = <String, List<Ticket>>{};
    for (final t in all) {
      final p = t.parentId;
      if (p != null) childrenByParent.putIfAbsent(p, () => []).add(t);
    }
    final result = <String>{};
    void walk(String id) {
      for (final child in childrenByParent[id] ?? const []) {
        if (result.add(child.id)) walk(child.id);
      }
    }

    walk(rootId);
    return result;
  }
}
```

## `TicketsCubit` changes

Constructor gains `_parentTrashService = TicketParentTrashService(_repository, gitProjector: gitProjector, projectRootPath: projectRootPath);`, constructed alongside the existing `_rollupRecomputer` line — same wiring, same optional dependencies already held.

`updateTicketParent` keeps its exact external contract (same emitted states, same `TicketsErrorReason.invalidParent` toast behavior) but delegates the validation-and-write step:

```dart
Future<void> updateTicketParent(Ticket ticket, String? newParentId) async {
  final result = await _parentTrashService.changeParent(ticket, newParentId);
  switch (result) {
    case ParentChangeRejected():
      await _emitInvalidParent(ticket.id);
    case ParentChangeSuccess(:final ticket):
      emit(TicketDetailLoaded(ticket));
  }
}
```

The inline self-parent/always-root/inbox-chat/descendant/canParent checks
and the direct `_repository.updateTicketParent` + `_recomputeRollupChain`
calls are removed from this method (now inside
`TicketParentTrashService.changeParent`). `_emitInvalidParent` and
`_descendantIds` (still used by `getValidParentCandidates`) are
unchanged.

`trashTicket` keeps its existing `previousState`-based state-selection
logic untouched, but its trash-and-side-effects step becomes:

```dart
final trashed = await _parentTrashService.trash(id);
```

replacing the current `await _repository.trashTicket(id)` +
`unawaited(_trashGitSideEffects(trashed, parentId))` pair — `trash`
already does both. `preTrash`'s `parentId` read (needed today to seed
`_trashGitSideEffects`) is no longer needed at this call site since
`TicketParentTrashService.trash` re-derives it internally.

## `TrashCubit` changes

Same constructor addition as `TicketsCubit` (own
`TicketParentTrashService` instance, same `gitProjector`/
`projectRootPath` it already holds). `restore` delegates:

```dart
Future<void> restore(String id) async {
  try {
    await _parentTrashService.restore(id);
    await load();
  } catch (e) {
    emit(TrashError(e.toString()));
  }
}
```

replacing the current direct `_repository.restoreTicket(id)` +
`_restoreGitSideEffects` pair.

## `TicketMarkdownReconciler` changes

New optional constructor parameter, appended after the existing
`_wikilinkIndexer` optional positional parameter (same "`null` in every
construction site except `app_router.dart` and this class's own tests
that don't need it" pattern):

```dart
TicketMarkdownReconciler(
  this._repository,
  this._serializer,
  this._activeTicketViewRegistry,
  this._embeddingProvider, [
  this._wikilinkIndexer,
  this._parentTrashService,
]);

final TicketParentTrashService? _parentTrashService;
```

`_apply`'s return type changes from `Future<Ticket?>` to a record
capturing both the updated ticket (still needed by `reconcile` for its
wikilink-reindex diffing) and whether a parentId/deletedAt transition
was rejected:

```dart
Future<({Ticket? ticket, bool rejected})> _apply(
  Ticket ticket,
  TicketMarkdownParseResult result,
) async {
  // ... existing title/description/priority/type/estimate/timeSpent/
  // status handling, unchanged ...

  var rejected = false;
  final service = _parentTrashService;
  if (service != null) {
    final ok = await service.applyFromParsedFields(ticket, fields);
    if (!ok) rejected = true;
  }

  return (ticket: updated, rejected: rejected);
}
```

`reconcile` uses the record to decide the final `syncStatus` instead of
unconditionally setting `synced`:

```dart
final applyResult = await _apply(ticket, result);
await _repository.updateSyncStatus(
  ticket.id,
  applyResult.rejected
      ? TicketSyncStatus.needsRepair
      : TicketSyncStatus.synced,
);
```

The wikilink-reindex block below it keeps reading `applyResult.ticket`
in place of the old `updated` variable — no behavior change there.

Note: `applyFromParsedFields` is called with the *pre-title/description-
update* `ticket` (not the `copyWith`-derived `updated`) — `parentId`/
`deletedAt` are independent of title/description, and
`TicketParentTrashService.changeParent`/`trash`/`restore` all re-fetch
the ticket from the repository before acting, so which snapshot is
passed in only matters for the fields `changeParent` reads directly
(`id`, `type`, `inboxPurpose`, `parentId`) — none of which `_apply`'s
title/description/priority/estimate/timeSpent/status handling touches.

Class-level dartdoc: the two "Known limitation" paragraphs about
`parentId`/`deletedAt` are rewritten to describe the new applied
behavior (and the `needsRepair` rejection path) instead of the old
"deliberately left out" framing. The third "Known limitation" paragraph
(`estimateRollup`/`timeSpentRollup`, structurally inert for
`resource`/`page`) is untouched — unrelated to this change.

## `TicketRepairService` changes

New required constructor dependency (this service is only ever
constructed at the one `app_router.dart` site, so no optional-null
fallback is needed the way `TicketMarkdownReconciler`'s is):

```dart
TicketRepairService(
  this._repository,
  this._serializer,
  this._parentTrashService,
);

final TicketParentTrashService _parentTrashService;
```

`reformat` re-validates the parentId/deletedAt transition (if any)
before declaring success, instead of treating "the trimmed content still
parses" as sufficient:

```dart
Future<bool> reformat(String ticketId, String rootPath) async {
  final file = File('$rootPath/tickets/$ticketId.md');
  if (!await file.exists()) return false;

  final reformatted = lintTicketMarkdown(
    await file.readAsString(),
    _serializer,
  );
  if (reformatted == null) return false;

  final ticket = await _findByTicketId(ticketId);
  if (ticket == null) return false;

  final result = _serializer.parse(reformatted);
  final fields = switch (result) {
    ParsedOk(fields: final f) => f,
    ParsedPartial(validFields: final f) => f,
    Unparseable() => null,
  };
  if (fields != null &&
      !await _parentTrashService.applyFromParsedFields(ticket, fields)) {
    return false;
  }

  await file.writeAsString(reformatted);
  await _repository.updateSyncStatus(ticket.id, TicketSyncStatus.synced);
  return true;
}
```

(`fields == null` only when `reformatted`'s re-parse regresses to
`Unparseable` between the two `parse` calls, which can't actually
happen since `lintTicketMarkdown` only trims trailing whitespace — kept
as a defensive `null`-check rather than an unsound cast.) On rejection,
`reformat` returns `false` and the ticket stays `needsRepair`, exactly
as when `lintTicketMarkdown` itself returns `null` — the existing UI
already falls back to offering `restoreFromLastKnownGood` in that case.
`restoreFromLastKnownGood` itself is unchanged — it already
unconditionally re-serializes the ticket's true database state
(including `parentId`/`deletedAt`) to the file, which is already the
correct fix for a rejected value.

## `app_router.dart` changes

One new `RepositoryProvider`, added to the existing `if (rootPath !=
null) ...` block, after `TicketGitProjector` and before
`TicketMarkdownReconciler` (which now depends on it):

```dart
RepositoryProvider<TicketParentTrashService>(
  create: (context) => TicketParentTrashService(
    context.read<TicketRepository>(),
    gitProjector: context.read<TicketGitProjector>(),
    projectRootPath: rootPath,
  ),
),
```

`TicketMarkdownReconciler`'s and `TicketRepairService`'s `create`
callbacks each gain
`context.read<TicketParentTrashService>()` as their new last
constructor argument. No other provider/build-order change —
`TicketsCubit`/`TrashCubit` construct their own instances internally
(see above), so this doesn't touch `BlocProvider<TicketsCubit>`'s
construction or `TrashCubit`'s route-scoped construction in
`app_router.dart` at all.
