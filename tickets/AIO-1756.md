# Tasks: Preserve `ticketId` in `TicketDbReconstructionService` imports

- [x] 1. `lib/features/tickets/data/daos/ticket_dao.dart` — add
  `Future<void> insertTicketPreservingId(TicketsTableCompanion entry)`:
  in a single `transaction`, inserts `entry` unchanged (no
  sequence-generated `ticketId`), then parses the substring after the
  last `-` in `entry.ticketId.value` as an `int`; if it parses and is
  greater than the current `TicketIdSequenceTable.seq`, writes it back
  via `insertOnConflictUpdate` (same pattern `insertTicket` already
  uses). Full dartdoc explaining the id-preservation contract and the
  sequence-bump rationale (see `design.md`'s "Sequence-bump logic").

- [x] 2. `lib/features/tickets/domain/repositories/ticket_repository.dart`
  — add abstract method `Future<void> importTicket(Ticket ticket)` with
  a dartdoc contrasting it against `createTicket`: preserves
  `ticket.ticketId` verbatim instead of generating a fresh one; intended
  for `TicketDbReconstructionService`'s true-import path only; throws if
  `ticket.ticketId` collides with an existing row.

- [x] 3. `lib/features/tickets/data/repositories/drift_ticket_repository.dart`
  — factor the existing `TicketsTableCompanion.insert(...)` construction
  out of `createTicket` into a private helper (e.g.
  `_buildInsertCompanion(Ticket ticket, {required String ticketId})`)
  parameterized on the `ticketId` to use. `createTicket` calls it with
  `ticketId: ''` exactly as before (unchanged external behavior). Add
  `Future<void> importTicket(Ticket ticket)`: calls the same helper with
  `ticketId: ticket.ticketId`, then `_db.ticketDao.insertTicketPreservingId(companion)`.
  Dartdoc on both the new method and the private helper.

- [x] 4. `lib/features/tickets/data/services/ticket_db_reconstruction_service.dart`
  — change the true-import branch (`else` of the
  `existingByTicketId.containsKey(ticket.ticketId)` check) from
  `await _repository.createTicket(ticket);` to
  `await _repository.importTicket(ticket);`. Update the class dartdoc:
  remove the "**Known limitation**" paragraph and replace it with a short
  note that true imports now preserve the file's `ticketId` via
  `TicketRepository.importTicket`.

- [x] 5. `test/features/tickets/data/services/ticket_db_reconstruction_service_test.dart`
  — in `setUp`, add
  `when(() => repository.importTicket(any())).thenAnswer((_) async {});`.
  In the `'imports valid files as new tickets when no matching row
  exists'` test, change
  `verify(() => repository.createTicket(any())).called(2);` to
  `verify(() => repository.importTicket(any())).called(2);` and add
  `verifyNever(() => repository.createTicket(any()));` alongside the
  existing `verifyNever(() => repository.updateTicket(any()));`.

- [x] 6. `test/features/tickets/data/daos/ticket_dao_test.dart` — add a
  new `group('insertTicketPreservingId', ...)` with tests covering: (a)
  the inserted row's `ticket_id` equals exactly what was passed, not a
  sequence-generated one; (b) after inserting `'AIO-5'`, a subsequent
  `dao.insertTicket(..., 'AIO')` call generates `'AIO-6'` or higher
  (never re-issues `1`-`5`); (c) inserting a `ticketId` with a
  non-numeric suffix (e.g. `'AIO-abc'`) succeeds and leaves
  `TicketIdSequenceTable.seq` unchanged. Follows this file's existing
  real-in-memory-drift convention (not mocked), since sequence/uniqueness
  behavior is exactly what that convention exists to cover.

- [x] 7. `test/features/tickets/data/repositories/drift_ticket_repository_test.dart`

  `Ticket(ticketId: 'AIO-99', ...)` (not `buildTicket(...).copyWith(...)`
  as originally sketched — `Ticket.copyWith` deliberately excludes
  `ticketId` from its mutable fields, so that path doesn't compile),

  exactly `'AIO-99'`.
