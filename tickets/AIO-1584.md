# Design: Pluggable Provider Abstraction

## §1. New `core/contracts/` types and why each is real, not speculative

Every type below is consumed by at least one real call site in this
change — none is added purely for a hypothetical future provider.

```dart
// core/contracts/provider_id.dart
/// Extensible provider identifier. Add a value here (and a matching
/// AgentProvider implementation) to register a new provider — nothing
/// else in this file changes.
enum ProviderId {
  claudeAgentSdk,
}
```
Consumer: `AgentModelDescriptor.providerId`, `ProviderRegistry.providerById`,
every persisted `ModelRoutingRepository` key.

```dart
// core/contracts/tool_access_tier.dart
/// The tool-access axis a provider declares support for, independent of
/// ModelPhase's reasoning-weight axis.
enum ToolAccessTier { noTools, readOnly, full }
```
Consumer: `AgentProvider.supportedToolAccessTiers`,
`ModelPhase.requiredToolAccessTier` (§3), the Settings model dropdown's
filtering logic (§3).

```dart
// core/contracts/agent_model_descriptor.dart
/// A provider-scoped model. Replaces AgentModel — a model is no longer
/// implicitly "the one provider's model."
class AgentModelDescriptor extends Equatable {
  const AgentModelDescriptor({
    required this.providerId,
    required this.modelId,        // was AgentModel.id
    required this.label,
    required this.contextWindowTokens,
  });

  final ProviderId providerId;
  final String modelId;
  final String label;
  final int contextWindowTokens;

  @override
  List<Object?> get props => [providerId, modelId, label, contextWindowTokens];
}
```
Consumer: `ModelRoutingRepository`, `ModelRoutingCubit`, the Settings
dropdown, `ExecutionContextCapCubit`, `ChatCubit.runChatTurn`'s `model`
param, every `_resolveModel` call site.

```dart
// core/contracts/consumption_signal.dart
/// The one generic "consumption" dimension a provider's budget/usage
/// signal maps onto — see §4.
sealed class ConsumptionSignal extends Equatable {
  const ConsumptionSignal(this.message);
  final String message;
}

/// A flat-rate plan's usage-window signal (e.g. Claude Pro/Max).
/// No numeric fraction — the provider that emits this can't report one.
class UsageWindowConsumption extends ConsumptionSignal {
  const UsageWindowConsumption(super.message);
  @override
  List<Object?> get props => [message];
}

/// A token-billed provider's cost signal. amountUsd is null when the
/// provider can report the signal occurred but not an exact amount.
class CostConsumption extends ConsumptionSignal {
  const CostConsumption(super.message, this.amountUsd);
  final double? amountUsd;
  @override
  List<Object?> get props => [message, amountUsd];
}
```
Consumer: `AgentProvider.describeOverage`, `ChatCubit.runChatTurn`'s new
`onConsumptionSignal` callback (§4) — replaces today's bare
`onOverageDetected` `VoidCallback`.

```dart
// core/contracts/agent_provider.dart
/// A configured, usable model provider. AgentModelClient stays the
/// low-level "run a request" contract (unchanged); AgentProvider is one
/// level up — identity, capability declaration, model list, and the two
/// pure text-mapping functions that keep vendor-specific detail out of
/// AgentModelClient's already-shipped, unchanged event shapes.
abstract interface class AgentProvider {
  ProviderId get id;
  String get displayName;
  Set<ToolAccessTier> get supportedToolAccessTiers;
  List<AgentModelDescriptor> get availableModels;
  AgentModelClient get client;

  /// Maps a raw AgentOverageDetectedEvent.message into this provider's
  /// ConsumptionSignal variant. Pure — no I/O.
  ConsumptionSignal describeOverage(String rawMessage);

  /// Maps a raw AgentErrorEvent.message (which may contain vendor/CLI-
  /// specific text) into a vendor-neutral, user-facing message. Pure —
  /// no I/O. Resolves provider-error-messages-leak-vendor-text.md.
  String normalizeErrorMessage(String rawMessage);
}
```

```dart
// core/contracts/provider_registry.dart
abstract interface class ProviderRegistry {
  List<AgentProvider> get availableProviders;

  /// Throws StateError if [id] has no registered AgentProvider — every
  /// ProviderId reachable from persisted ModelRoutingRepository state
  /// must be registered, so this is a real invariant violation, not a
  /// recoverable condition.
  AgentProvider providerById(ProviderId id);
}
```
Implementation: `core/agent/static_provider_registry.dart`'s
`StaticProviderRegistry` — a plain `List<AgentProvider>` wrapper,
constructed once in `main.dart` with `[ClaudeAgentSdkProvider(...)]`.
"Pluggable" for a compiled Flutter app means: adding provider #2 is one
new class + one enum value + one entry in this list — nothing else in
`main.dart` or any consuming cubit changes.

## §2. `ClaudeAgentSdkProvider`

```dart
// core/agent/claude_agent_sdk_provider.dart
class ClaudeAgentSdkProvider implements AgentProvider {
  ClaudeAgentSdkProvider(AgentBridgeLocator bridgeLocator)
      : client = ClaudeAgentSdkClient(bridgeLocator);

  @override
  final AgentModelClient client;

  @override
  ProviderId get id => ProviderId.claudeAgentSdk;

  @override
  String get displayName => 'Claude Agent SDK';

  // No readOnly — agent_bridge/index.mjs has no allowlist tier today,
  // only allowedTools: [] or the SDK's full default set. Honest about
  // current capability, not aspirational.
  @override
  Set<ToolAccessTier> get supportedToolAccessTiers =>
      const {ToolAccessTier.noTools, ToolAccessTier.full};

  @override
  List<AgentModelDescriptor> get availableModels => const [
        AgentModelDescriptor(
          providerId: ProviderId.claudeAgentSdk,
          modelId: 'claude-opus-4-8',
          label: 'Opus 4.8',
          contextWindowTokens: 200000,
        ),
        AgentModelDescriptor(
          providerId: ProviderId.claudeAgentSdk,
          modelId: 'claude-sonnet-5',
          label: 'Sonnet 5',
          contextWindowTokens: 200000,
        ),
        AgentModelDescriptor(
          providerId: ProviderId.claudeAgentSdk,
          modelId: 'claude-haiku-4-5',
          label: 'Haiku 4.5',
          contextWindowTokens: 200000,
        ),
      ];

  @override
  ConsumptionSignal describeOverage(String rawMessage) =>
      UsageWindowConsumption(rawMessage);

  @override
  String normalizeErrorMessage(String rawMessage) {
    // Strips CLI-flavored instruction text (e.g. "Please run `/login`")
    // that leaks Claude Code's own tooling identity into a model-
    // agnostic UI — the exact complaint in
    // provider-error-messages-leak-vendor-text.md. Exact pattern list
    // is an /apply-time detail (tasks.md T-normalize-errors); at minimum
    // strips any `/<slash-command>` CLI-instruction fragment and
    // "Claude Code"/"claude-agent-sdk" literal mentions, falling back to
    // the raw message unchanged if no known pattern matches (never
    // hides a real error, only cleans vendor identity out of it).
    ...
  }
}
```

Verbatim-unchanged: `ClaudeAgentSdkClient`, `agent_bridge/index.mjs`,
`AgentBridgeLocator`. `AgentRequest`/`AgentEvent` shapes are untouched —
`AgentErrorEvent.message` still carries the *raw* technical message
(useful for logs); normalization happens at the presentation boundary
(§4), not by rewriting the event.

## §3. `ModelPhase.requiredToolAccessTier` and the dropdown filter

```dart
// domain/enums/model_phase.dart — addition
extension ModelPhaseToolAccess on ModelPhase {
  ToolAccessTier get requiredToolAccessTier => switch (this) {
        ModelPhase.frontier || ModelPhase.capable => ToolAccessTier.noTools,
        ModelPhase.execution => ToolAccessTier.full,
      };
}
```

This mirrors what every call site already passes as a literal
`toolsEnabled: true`/`false` today (§providers.md's `AgentRequest`
docs) — making it declared data instead of scattered literals. It is
**deliberately not** used to derive `AgentRequest.toolsEnabled` at
request-construction time; the two stay independently authored for now.
Coupling them would mean `ToolAccessTier.readOnly` needs a real
`AgentRequest`-level representation before it's useful, which it
doesn't have (see proposal.md's Non-goals) — premature coupling for a
tier that can't be exercised yet.

Real consumer: `ModelRoutingCubit.load()` now also computes, per
`ModelPhase`, which of `registry.availableProviders` support that
phase's `requiredToolAccessTier`, and `ModelRoutingReady.availableModels`
is the union of `availableModels` across just those providers. The
Settings dropdown reads this list instead of a hardcoded
`AgentModel.values`. Today, since `ClaudeAgentSdkProvider` supports both
`noTools` and `full`, every phase's dropdown still shows the same three
models it does today — the filter is real and functioning, just
currently a no-op in its visible effect.

## §4. `ConsumptionSignal` wiring — `ChatCubit.runChatTurn`

```dart
// presentation/cubit/chat_cubit.dart — updated signature
static Future<bool> runChatTurn({
  required AgentModelClient client,
  required AgentProvider provider,        // NEW
  required CommentRepository commentRepo,
  required String chatTicketId,
  required String prompt,
  required AgentModelDescriptor model,    // was AgentModel
  void Function(String textSoFar)? onChunk,
  bool toolsEnabled = false,
  String? workingDirectory,
  void Function(ConsumptionSignal signal)? onConsumptionSignal, // was onOverageDetected VoidCallback
  void Function(String toolName, String? summary)? onToolUse,
}) async {
  ...
  final events = await client.run(AgentRequest(
    prompt: prompt,
    model: model.modelId,               // was model.id
    toolsEnabled: toolsEnabled,
    workingDirectory: workingDirectory,
  ));
  await for (final event in events) {
    switch (event) {
      ...
      case AgentOverageDetectedEvent(:final message):
        onConsumptionSignal?.call(provider.describeOverage(message));
      case AgentErrorEvent(:final message):
        succeeded = false;
        failureMessage = provider.normalizeErrorMessage(message);
      ...
    }
  }
  ...
}
```

Every existing `onOverageDetected: () => ...` call site (`TicketsCubit`'s
coding-execution "force `gated` for the rest of the session" reaction,
`ProviderSettingsCubit`'s inline handling) becomes
`onConsumptionSignal: (signal) => ...` — the reaction itself is
unchanged (still just "an overage/rate-limit signal occurred"), now
carrying a typed payload instead of nothing, so a future predictive
gate or richer UI can consume `signal.message`/`signal is CostConsumption`
without another signature change. `failureMessage` (surfaced in
`TicketComment` content, and in `ProviderSettingsCubit.statusMessage`)
is now vendor-normalized everywhere a chat turn can fail, not just in
Settings — a stricter fix for `provider-error-messages-leak-vendor-text.md`
than only patching the Settings screen would have been.

## §5. Deferred: per-provider config storage (design only, not built)

For when a second provider exists: a `ProviderConfigRepository`
interface with one method per genuinely shared concern
(`isEnabled(ProviderId)`/`setEnabled`), plus a provider-specific typed
config value object *per provider* (e.g. a hypothetical
`AnthropicMessagesApiConfig { apiKey, defaultModel }`) rather than one
forced-generic blob shape — different providers need genuinely
different fields (an API key vs. a base URL vs. nothing at all for
Claude Agent SDK), so a single `Map<String, String>` would just be an
untyped, unvalidated version of the same problem. `ProviderRegistry`'s
construction-time list remains the "which providers exist" answer;
`ProviderConfigRepository` would answer "is this one turned on and how
is it configured" once there's a second entry for which that question
has a real answer. Not implemented this round — see proposal.md's
Non-goals.

## §6. `ModelRoutingRepository` persistence migration

```dart
// data/repositories/shared_prefs_model_routing_repository.dart
class SharedPrefsModelRoutingRepository implements ModelRoutingRepository {
  SharedPrefsModelRoutingRepository(this._registry);
  final ProviderRegistry _registry;

  // Two keys per phase now: e.g. model_routing.frontier_provider_id,
  // model_routing.frontier_model_id. A phase with no
  // ..._provider_id key yet (pre-migration data) defaults to
  // ProviderId.claudeAgentSdk — today's only provider — so an
  // already-chosen model survives, mirroring the existing
  // _legacySelectedModelKey fallback this repository already has for
  // the pre-per-phase-routing single-model key.

  @override
  Future<AgentModelDescriptor> getModelForPhase(ModelPhase phase) async {
    final prefs = await SharedPreferences.getInstance();
    final providerName = prefs.getString(_providerKeyFor(phase));
    final providerId = ProviderId.values.firstWhere(
      (p) => p.name == providerName,
      orElse: () => ProviderId.claudeAgentSdk,
    );
    final modelId =
        prefs.getString(_modelKeyFor(phase)) ?? prefs.getString(_legacySelectedModelKey);
    final provider = _registry.providerById(providerId);
    return provider.availableModels.firstWhere(
      (m) => m.modelId == modelId,
      orElse: () => provider.availableModels.first, // was AgentModel.sonnet default; first registered model is the equivalent "safe default" now
    );
  }

  @override
  Future<void> setModelForPhase(ModelPhase phase, AgentModelDescriptor model) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_providerKeyFor(phase), model.providerId.name);
    await prefs.setString(_modelKeyFor(phase), model.modelId);
  }
}
```

`SharedPrefsModelRoutingRepository` gains a real `ProviderRegistry`
dependency — a repository resolving persisted ids back into full
`AgentModelDescriptor` objects needs somewhere to look models up, since
they're no longer a global fixed enum `Repository` can iterate
directly. This is still "plain reads/writes, no validation" in spirit —
the registry lookup is a resolution step, not a business rule.

## §7. Cubit/wiring migration — `TicketsCubit`, `ChatCubit`, `InboxCubit`, `ProviderSettingsCubit`

Each of these four currently holds an `AgentModelClient` field injected
directly (`_agentClient`/`_client`). All four move to holding a
`ProviderRegistry` instead, and add one private helper:

```dart
Future<(AgentModelDescriptor, AgentProvider)> _resolveModelAndProvider(
  ModelPhase phase,
) async {
  final model = await _resolveModel(phase); // existing helper, now returns AgentModelDescriptor
  final provider = _providerRegistry.providerById(model.providerId);
  return (model, provider);
}
```

Every one of the ~14 `_resolveModel(ModelPhase.xxx)` call sites (6 in
`TicketsCubit`, 4 in `InboxCubit`, 1 in `ChatCubit.sendMessage`, plus
`ProviderSettingsCubit`'s Frontier-tier ping) switches to
`_resolveModelAndProvider`, then passes both `client: provider.client`
and `provider: provider` into `ChatCubit.runChatTurn` (or, for
`ProviderSettingsCubit`'s direct `client.run(...)` ping call, uses
`provider.client` and `provider.normalizeErrorMessage` inline — it
doesn't go through `runChatTurn`).

`ProviderSettingsCubit._ProviderStatusCard`'s "Claude Agent SDK" title
text (`context.l10n.settingsProviderCardTitle`, currently a hardcoded
localized string) is unaffected by this change — still shows the same
text, since the Frontier tier still resolves to `ClaudeAgentSdkProvider`
today. Sourcing it from `provider.displayName` instead is a natural
follow-up once a second provider makes "which provider is Frontier
using" worth surfacing dynamically, not required for this change to be
correct.

## §8. `main.dart`/`app_router.dart` wiring changes

```dart
// main.dart — replaces the standalone AgentModelClient registration
RepositoryProvider<ProviderRegistry>(
  create: (context) => StaticProviderRegistry([
    ClaudeAgentSdkProvider(context.read<AgentBridgeLocator>()),
  ]),
),
RepositoryProvider<ModelRoutingRepository>(
  create: (context) =>
      SharedPrefsModelRoutingRepository(context.read<ProviderRegistry>()),
),
```

The standalone `RepositoryProvider<AgentModelClient>` is removed — every
former consumer (`TicketsCubit`, `ChatCubit`, `InboxCubit`,
`ProviderSettingsCubit`, all four constructed in `app_router.dart`) now
takes `context.read<ProviderRegistry>()` instead of
`context.read<AgentModelClient>()`.

## §9. Barrel file

`features/providers/providers.dart` drops
`export 'domain/enums/agent_model.dart';` (file deleted — replaced by
`core/contracts/agent_model_descriptor.dart`, already reachable via
`core/core.dart`). No new export needed in this barrel — the new
`core/contracts/` types are reachable the same way
`agent_model_client.dart` already is.

## §10. What does not change

- `AgentModelClient`, `AgentRequest`, `AgentEvent` and all five of its
  variants — untouched, same shapes, same file.
- `ClaudeAgentSdkClient`, `AgentBridgeLocator`, `agent_bridge/index.mjs` —
  untouched.
- `AutomationConfidence`/`AutomationContext`/`AutomationSettingsRepository` —
  untouched; no new `AutomationContext` value is added this round (the
  budget/usage-window gate stays deferred, per proposal.md's Non-goals).
- `ExecutionContextCapRepository` — untouched (still `int?`
  read/write); only its Cubit's read of `.contextWindowTokens` changes
  type from `AgentModel` to `AgentModelDescriptor`, a mechanical
  follow-through of §6/§7, not a repository-shape change.

# Aion — Pluggable Provider Abstraction: Settings Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md), the [Provider Configuration Spec](./Aion%20Provider%20Configuration%20Spec.md) (which owns `SettingsScreen`, `ProviderStatusCard`, `ProviderConnectionBadge`, and the `AppDropdown<T>` molecule), and the [Per-Phase Model Routing Spec](./Aion%20Per-Phase%20Model%20Routing%20Spec.md) (which owns the "MODELS" section and its three `_ModelPhaseSection` rows). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name.

**Pluggable Provider Abstraction is a data-layer generalization, not a visual change.** It generalizes Aion's model→provider binding so a model is no longer implicitly tied to one hardcoded provider: it introduces `AgentProvider`, a `ProviderRegistry`, and a provider-scoped `AgentModelDescriptor`, so that different tiers can *eventually* be routed to different providers. The **only screen touched is the existing `/workspace/settings` screen**, and only the *item source* behind its three MODELS-tier `AppDropdown`s changes — from a fixed `AgentModel` enum to a filtered, provider-aware descriptor list. There is **no new screen, no new visual affordance, no new layout, and no new interaction.**

**Today, with exactly one provider registered (`Claude Agent SDK`), every MODELS dropdown must render pixel-identical to the Per-Phase Model Routing Spec** — same three options (`Opus 4.8`, `Sonnet 5`, `Haiku 4.5`), same labels, same closed-field appearance, same states, same behavior. This spec therefore does two things and only two things:

1. **§1–§4 — Confirm the existing `AppDropdown` spec in full**, as used in a MODELS-tier row, across every state in both themes, so the implementer has a complete current reference to verify pixel-identity against.
2. **§6 — One forward-looking, *not-for-implementation* variant**: how an `AppDropdown` item row would carry a provider-name prefix once a *second* provider is registered, without changing the row's height or the closed trigger's appearance.

Mockups: [Aion Pluggable Provider Abstraction Mockups](./Aion%20Pluggable%20Provider%20Abstraction%20Mockups.dc.html).

**No Material widgets or types anywhere.** Every surface is `DecoratedBox` / `Container` / `Column` / `Row` / `Padding` / `GestureDetector` / `MouseRegion` / `AnimatedScale` / `CustomPaint` — never `Card`, `ElevatedButton`, `Scaffold`, `ThemeData`, `ColorScheme`, `DropdownButton`, `AppBar`, `ListTile`, `CircularProgressIndicator`, or `InkWell`.

Themes: **Arctic** (light, celestial cold) and **Obsidian** (dark, abyssal cold). All layout, dimensions, spacing, radius, and typography are **identical** between themes; only color tokens differ, and every color below is a named `AionColors` token that already resolves per theme. Concrete hex is quoted `Arctic / Obsidian` for reference only — implement against the token, never the literal. Translucent fills are always `token.withOpacity(x)` — never hardcoded ARGB.

**No new color, typography, radius, or spacing tokens are required for this change.** The forward-looking §6 variant also introduces none — it reuses `textMuted` and existing spacing. The only structural additions are the data-layer types in §5, which carry **no visual footprint** in this release.

## 1. Confirmation — the change is data-only; no gap exists

Reviewed against the Per-Phase Model Routing Spec §2 (`AppDropdown<AgentModel>`) and §2.5 (its state table). **The existing `AppDropdown` component fully covers this context. No new visual treatment is invented or required for the current change.**

| Question | Finding |
|---|---|
| Does the MODELS row layout change? | **No.** Label → description → dropdown, geometry byte-identical to `_ModelPhaseSection` (Routing Spec §2.2). |
| Does the closed field change? | **No.** Same `surface` fill, `1px border`, radius `11`, pad `13×11`, value + caret-down (§3.1). |
| Do the item rows change? | **No** (today). Same three options, same selected/hover treatment (§3.6). Provider prefix is §6, future-only. |
| Do the states change? | **No.** Default / hover / focused / pressed-open / disabled unchanged (§3, §4). |
| Any new token needed today? | **No.** Every color, text style, radius, spacing already exists. |

What changes is **internal**: the dropdown's `List<T>` is now built by `ProviderRegistry.modelsForTier(tier)` returning `AgentModelDescriptor`s, instead of the fixed `AgentModel` enum (§5). With one provider registered the returned list is identical in count, order, and display name to the old enum, so the render is pixel-identical.

## 3. `AppDropdown` — full current spec (the review reference)

The molecule reused verbatim for every MODELS tier. Two parts: a **closed field** (trigger) and, on open, a downward **`SelectionMenu` item panel**.

### 3.1 Closed field — dimensions & fill

| Property | Value |
|---|---|
| Height | intrinsic — `22px` content line + vertical padding = **44px** total at rest |
| Width | full width of the row (stretch) |
| Fill | `AionColors.surface` (`#FBFCFE / #131A29`) |
| Border | `1px` `AionColors.border` (`#D6E0EA / #232C40`) |
| Radius | `11` (screen input radius, base spec §2.5 — between `AionRadius.md` 10 and `AionRadius.lg` 12) |
| Padding | `EdgeInsets.symmetric(horizontal: 13, vertical: 11)` |
| Layout | `Row`, `mainAxisAlignment: spaceBetween`, `crossAxisAlignment: center` |
| Shadow | none at rest |

### 3.2 Closed field — value text

| Property | Value |
|---|---|
| Text | selected model display name (`"Opus 4.8"` / `"Sonnet 5"` / `"Haiku 4.5"`) |
| Style | `AionText.bodySm` rendered at `14` (Manrope, w400) |
| Color | `AionColors.textPrimary` (`#142230 / #E7EDF7`) |
| Overflow | `maxLines: 1`, `TextOverflow.ellipsis` |

### 3.3 Closed field — trailing caret

| Property | Value |
|---|---|
| Glyph | `caret-down` (`▾`), flips to `caret-up` (`▴`) when open |
| Size | `11–12px` |
| Color | `AionColors.textMuted` (`#8496A6 / #6B7690`) at rest; see §4 per state |

### 3.4 Open item panel — container

`SelectionMenu` panel anchored to the field, opening downward, matched to field width.

| Property | Value |
|---|---|
| Offset | top of panel `6` below the field's bottom edge |
| Fill | `AionColors.surface` (`#FBFCFE / #131A29`) |
| Border | `1px` `AionColors.borderStrong` (`#BAC8D6 / #35415C`) |
| Radius | `AionRadius.lg` (12) |
| Padding | `EdgeInsets.all(5)` |
| Item gap | `2` between item rows |
| Shadow | `BoxShadow(offset: (0, 20), blurRadius: 44, spreadRadius: -14, color: Colors.black.withOpacity(isDark ? 0.60 : 0.22))` |

### 3.5 Open item panel — item row dimensions

| Property | Value |
|---|---|
| Layout | `Row`, `mainAxisAlignment: spaceBetween`, `crossAxisAlignment: center` |
| Padding | `EdgeInsets.symmetric(horizontal: 13, vertical: 9)` |
| Radius | `8` |
| Label | `AionText.bodySm` rendered at `14`, weight per state (§3.6) |
| Trailing (selected only) | `check` glyph (`✓`) `14px`, `AionColors.primary` |

### 3.6 Open item panel — item states

| Item state | Fill | Label color / weight | Trailing |
|---|---|---|---|
| **Default** | transparent | `textPrimary` (`#142230 / #E7EDF7`), w600 | none |
| **Hover** | `surfaceHover` (`#E4EDF6 / #1C2436`) | `textPrimary`, w600 | none |
| **Selected** | `primarySubtle` (`#DBE9F7 / #241F3E`) | `primary` (`#2E86D4 / #9366FF`), w700 | `check` `14px`, `primary` |

Dismiss on outside tap / `Escape` / selection. On select, the field closes and shows the chosen model; the field border returns to default (§4).

## 4. `AppDropdown` field states — both themes

Identical for all three tiers; matches the automation-trigger / base-field states. Concrete hex quoted `Arctic / Obsidian`; implement against the token.

| State | Field border | Field fill | Caret | Extra |
|---|---|---|---|---|
| **Default (closed)** | `1px` `border` (`#D6E0EA / #232C40`) | `surface` | `caret-down`, `textMuted` | none |
| **Hover** | `1px` `borderStrong` (`#BAC8D6 / #35415C`) | `surface` | `caret-down`, `textSecondary` (`#46586A / #A2AEC6`) | pointer cursor (`MouseRegion`) |
| **Focused** | `1.5px` `primary` (`#2E86D4 / #9366FF`) | `surface` | `caret-down`, `textMuted` | 3px focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), blurRadius: 0, spreadRadius: 3)` |
| **Pressed / Open** | `1.5px` `primary` | `surface` | `caret-up`, `primary` | ring present; item panel (§3.4) open; `AnimatedScale(0.99, 80ms)` on field |
| **Disabled** | `1px` `border` | `surface`, `opacity 0.45` | `caret-down`, `textMuted` | wrapped in `IgnorePointer`. **Not reachable in MODELS** (every tier always holds a value) — listed for molecule parity only |
| **Error** | n/a | n/a | n/a | **n/a** — a tier always holds a valid selection; no error state exists in this context |

The `1.5px` focused/open border insets `0.5px` versus the `1px` default (`BorderSide` drawn inside), so vertical padding compensates (`9.5px` when focused/open vs `11px` at rest) and the field does **not** resize between states.

## 5. Data-layer types (no visual footprint)

The generalization behind the change. None of these render anything new today.

```dart
/// A registered agent backend. Today exactly one instance exists.
class AgentProvider {
  final String id;            // e.g. 'claude_agent_sdk'
  final String displayName;   // e.g. 'Claude Agent SDK'
  const AgentProvider({ required this.id, required this.displayName });
}

/// A model as offered *by a specific provider*. Replaces the bare
/// `AgentModel` enum as the dropdown's item type.
class AgentModelDescriptor {
  final String id;              // stable model id, e.g. 'opus-4.8'
  final String displayName;     // 'Opus 4.8'  — shown in field + item row
  final AgentProvider provider; // which backend offers it
  final Set<ModelTier> tiers;   // which tiers may select it
  const AgentModelDescriptor({
    required this.id, required this.displayName,
    required this.provider, required this.tiers,
  });
}

/// The single source of truth for what a tier dropdown may list.
class ProviderRegistry {
  final List<AgentProvider> providers;
  final List<AgentModelDescriptor> models;
  const ProviderRegistry({ required this.providers, required this.models });

  /// Filtered, provider-aware list backing each MODELS AppDropdown.
  List<AgentModelDescriptor> modelsForTier(ModelTier tier) =>
      models.where((m) => m.tiers.contains(tier)).toList();

  /// True once more than one provider is registered — the only signal
  /// the §6 provider-prefix variant keys off. False today.
  bool get isMultiProvider => providers.length > 1;
}
```

Today's single-provider seed — produces the **exact** three-item list the enum did, in the same order:

```dart
const _claudeSdk = AgentProvider(id: 'claude_agent_sdk', displayName: 'Claude Agent SDK');

final kRegistry = ProviderRegistry(
  providers: const [_claudeSdk],
  models: const [
    AgentModelDescriptor(id: 'opus-4.8',  displayName: 'Opus 4.8',
        provider: _claudeSdk, tiers: {ModelTier.frontier, ModelTier.capable, ModelTier.execution}),
    AgentModelDescriptor(id: 'sonnet-5',  displayName: 'Sonnet 5',
        provider: _claudeSdk, tiers: {ModelTier.frontier, ModelTier.capable, ModelTier.execution}),
    AgentModelDescriptor(id: 'haiku-4.5', displayName: 'Haiku 4.5',
        provider: _claudeSdk, tiers: {ModelTier.frontier, ModelTier.capable, ModelTier.execution}),
  ],
);
```

`ModelTier` and `AgentModel`-era display names are unchanged from Per-Phase Model Routing Spec §6; the routing map now stores an `AgentModelDescriptor.id` per tier instead of an `AgentModel` value.

**With `isMultiProvider == false`, the item builder renders §3.6 exactly** — display name only, no provider prefix. Nothing in §6 executes.

## 6. Forward-looking variant — provider-prefixed item row (FUTURE ONLY, do not implement)

**Not part of this change. Do not build now.** Reference only for when a *second* provider is registered (`ProviderRegistry.isMultiProvider == true`) and two providers offer models that could collide in one tier's list. At that point an item row may disambiguate which provider a model belongs to. The constraint the design must honor:

> The provider name is added to the **item row only**, as a small muted prefix on the **same single line**, so the row's height is **unchanged** from §3.5, and the **closed trigger's appearance is unchanged** from §3.1–§3.3 (it still shows the bare model display name — no provider prefix).

### 6.1 Provider-prefixed item row

Same box as §3.5 (padding `13×9`, radius `8`, height unchanged — the prefix is inline text on the existing single line, not a second line):

| Element | Style | Color |
|---|---|---|
| **Provider prefix** | `AionText.bodySm` at `14`, w600, followed by a hair-space `"·"` separator (or an `8px` gap) | `AionColors.textMuted` (`#8496A6 / #6B7690`) |
| **Model name** | `AionText.bodySm` at `14`, weight per item state (§3.6) | per item state (§3.6) |

Rendered as one `Row` of inline spans: `[ Claude Agent SDK · ] [ Sonnet 5 ]`, then the state trailing (`check` if selected) at the far end. Because both spans share the `14px` line and the row keeps `vertical: 9` padding, **row height equals §3.5 exactly** — no growth, no second line.

Selected / hover / default fills and the model-name color/weight are **unchanged from §3.6**; only the muted provider prefix is added ahead of the name.

### 6.2 What must NOT change in the variant

| Surface | Rule |
|---|---|
| **Closed field** (§3.1–§3.3) | **Unchanged.** Shows the bare model display name (`"Sonnet 5"`), no provider prefix, same fill/border/radius/padding/caret. |
| **Item row height** (§3.5) | **Unchanged.** Prefix is inline on the same line; no second line, no extra padding. |
| **Panel container** (§3.4) | **Unchanged.** |
| **States** (§4, §3.6) | **Unchanged.** Provider prefix carries no state of its own; it is always `textMuted`. |

### 6.3 Gating

The prefix is shown **only** when `ProviderRegistry.isMultiProvider` is `true` **and** the tier's list contains models from more than one provider. In the single-provider present, the item builder takes the §3.6 path and the prefix never appears. No token, layout, or trigger change ships in this release.
