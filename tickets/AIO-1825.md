# T6. Create `aion-arch/.claude/skills/prepare-release/SKILL.md` —

new skill, following the existing skill-file shape (frontmatter
`name`/`description`, then Goal/Action sections — see
`aion-arch/.claude/skills/ticket-lint/SKILL.md` for the pattern).
Instructions implement design.md's `/prepare-release` algorithm
exactly: find archived changes under `aion-arch/changes/
archive/<name>/proposal.md` missing a `Shipped in:` line; find
`fix:`/`chore:`/`refactor:` commits since the last release tag not
already covered by one of those changes (excluding their own merge
commits); draft changelog bullets from each change's "What's
building" plus a "Fixes & chores" section from the ad hoc commits;
suggest a semver bump per design.md's REMOVED/ADDED heuristic;
wait for developer confirmation or override; on confirmation, bump
`pubspec.yaml`, update `CHANGELOG.md`'s `## [Unreleased]` section
(renaming it to the confirmed version + inserting a fresh empty
`## [Unreleased]` above), stamp `Shipped in: vX.Y.Z` onto each
shipped change's `proposal.md`, and commit both repos separately
via the ad hoc `chore/release-vX.Y.Z` branch+PR convention from
`branch-and-commit.md`. Explicitly does not tag or push — stops
and tells the developer to do that themselves to trigger T5's
workflow.
