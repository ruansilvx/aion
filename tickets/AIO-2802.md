# v0.1.0 installers never bundle agent_bridge/ — every fresh install fails to connect the Claude Agent SDK provider

Installed the v0.1.0 `.exe` and hit `NOT CONNECTED` on the Claude Agent SDK provider in Settings immediately, with `Error: Cannot find module 'C:\Program Files\Aion\agent_bridge\index.mjs'` / `MODULE_NOT_FOUND`.

Root cause: `AgentBridgeLocator` (aion/lib/core/agent/agent_bridge_locator.dart) correctly resolves `agent_bridge/index.mjs` as a sibling of the running executable, but neither packaging pipeline ever puts it there. `windows/installer/aion.iss`'s `[Files]` section only packaged `build\windows\x64\runner\Release\*`; `linux/packaging/build_appimage.sh` only staged the Flutter bundle. `agent_bridge/`'s own `node_modules` is gitignored and was never `npm install`-ed anywhere in CI (`release.yml`) either — it only worked from a source checkout where a developer had manually run `npm install` in `agent_bridge/`. Same gap on both platforms; not machine-specific.

**Severity:** critical — every fresh v0.1.0 install of both `Aion-Setup-0.1.0.exe` and `Aion-0.1.0-x86_64.AppImage` has this, and it fully disables the app's core agent-powered features out of the box.

**Fix** (aion PR — branch `fix/bundle-agent-bridge-in-installers`):
- `release.yml`: added `actions/setup-node@v4` (Node 22) + `npm ci --omit=dev` in `agent_bridge/` before packaging, in both the `build-windows` and `build-linux` jobs.
- `windows/installer/aion.iss`: added `[Files]` entries copying `agent_bridge/index.mjs`, `package.json`, and `node_modules/*` into `{app}\agent_bridge`.
- `linux/packaging/build_appimage.sh`: copies the same three into `$APPDIR/usr/bin/agent_bridge` (sibling of the staged `aion` executable, matching the locator's Linux resolution path).

**Verified locally** (not just eyeballed): installed Inno Setup via `winget`, ran `npm ci --omit=dev` in `agent_bridge/`, compiled `aion.iss` with the fix — compiler log shows all 757 `agent_bridge` files (including the full `@anthropic-ai/claude-agent-sdk` and `zod` trees) compressed into the installer. Then staged the exact resulting file layout in a scratch directory and launched `aion.exe` from it: Settings went from immediate `MODULE_NOT_FOUND` to `CHECKING` to `CONNECTED`.

**Not yet done:** an actual `v0.1.1` re-release/re-tag to ship this to existing installs — that's a separate manual step (`/prepare-release` territory), not part of this fix.
