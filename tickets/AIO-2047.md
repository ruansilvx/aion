# Data layer — tickets feature services

- [x] T19. Create `lib/features/tickets/data/services/ticket_git_projector.dart`
      — `TicketGitProjector.project(Ticket, rootPath, eventLabel)`:
      serializes via T15, writes `<rootPath>/tickets/<ticketId>.md`,
      commits via `GitRepositoryClient` (skips the commit if
      `hasChanges` is false). Only invoked for `epic`/`story`/`task`/
      `chat` tickets (enforced by the caller in T25, not internally).
- [x] T20. Create `lib/features/tickets/data/services/active_ticket_view_registry.dart`
      — `ActiveTicketViewRegistry` holding a single `ValueNotifier<String?> activeTicketId`.
- [x] T21. Create `lib/features/tickets/data/services/ticket_markdown_watcher_service.dart`
      — wraps `watcher`'s `DirectoryWatcher` scoped to `<rootPath>/tickets/`,
      debounces (default ~1.5s, constructor-configurable). **Corrected
      from design.md**: `resource`/`page` type filtering happens inside
      `TicketMarkdownReconciler.reconcile` itself (which needs the DB
      lookup anyway) rather than duplicated here via a separate
      ticketId->type lookup. **Fixed post-`/verify`**: `start()` was
      only wiring the `DirectoryWatcher` for future events and never
      performed design.md's specified immediate reconcile pass over
      existing ticket files on resume, so edits made while backgrounded
      were silently missed until the next live filesystem event. `start()`
      now also sweeps every existing `tickets/*.md` file and calls
      `reconcile` on each immediately.
- [x] T22. Create `lib/features/tickets/data/services/ticket_markdown_reconciler.dart`
      — `TicketMarkdownReconciler.reconcile(ticketId, rootPath)`
      implementing the 7-step flow from `design.md` (parse, branch on
      `ParsedOk`/`ParsedPartial`/`Unparseable`, check
      `ActiveTicketViewRegistry` before applying, set `pendingReconcile`/
      `needsRepair`/`synced` accordingly, feed applied content changes
      into the embedding trigger). Known limitation documented inline:
      does not apply a hand-edited `parentId` change — reparenting's
      cycle-prevention logic lives in `TicketsCubit`, and bypassing it
      from this background service would risk a corrupted parent graph.
      Also fixed a real bug caught while implementing: `ParsedPartial`'s
      `fields[key]` can't distinguish "field absent/invalid" from "field
      present but null" — only pass `copyWith` setters for keys actually
      present in the map, so an invalid field correctly falls back to
      the DB's existing value instead of being wrongly cleared.
- [x] T23. Create `lib/features/tickets/data/services/ticket_repair_service.dart`
      — `TicketRepairService.reformat(ticketId, rootPath)` (delegates
      to T16's linter, applies result if non-null) and
      `restoreFromLastKnownGood(ticketId, rootPath)` (re-serializes the
      current DB row over the file, always resolves to `synced`).
- [x] T24. Create `lib/features/tickets/data/services/ticket_db_reconstruction_service.dart`
      — `TicketDbReconstructionService.reconstruct(rootPath)`: walks
      `tickets/*.md`, parses each via T15, upserts via
      `TicketRepository`, skips/reports unparseable files, then bulk-
      triggers `EmbeddingProvider` for every imported ticket lacking an
      embedding. Returns a `TicketReconstructionReport`. **Known
      limitation documented inline**: `TicketRepository.createTicket`
      always assigns a fresh sequential `ticketId`, ignoring the one on
      the passed `Ticket` — so importing a file with no matching
      existing row doesn't actually preserve the `ticketId` the file is
      named after. Fixing needs a repository-level change out of scope
      here; flagged rather than silently shipped as if it round-trips.
