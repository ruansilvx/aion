# **T22** — `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart`:

fix the quality observation noted at the end of T14's manual pass —
`prepareReleaseDraft`'s prompt never told the model the project's
*current* version, so every drafted suggestion came back as a literal
`x.y.z` placeholder rather than a real next version, even though
`ProjectStackDetector.detectVersionFile` was already being called
(just after the model ran, to populate `ReleaseDraft
.detectedVersionFile` — never before, to inform the prompt). Fixed by
detecting once, up front, and folding `detected.currentVersion` (when
non-null) into the prompt's version-suggestion instruction; the same
detection result now also populates `detectedVersionFile` directly
(no second detection call), so the draft's suggestion and the
version-file it would bump from can never disagree with each other.
Dartdoc updated. `flutter analyze` clean,
`test/features/tickets/cubit` passes 491/491.
**Verified live**, against a third disposable scratch project
(`pubspec.yaml` pinned to `3.4.5`): the model's response correctly
read "the current version is `3.4.5`" back from the prompt and
suggested a real, correct patch bump (`3.4.6`) instead of the old
literal `x.y.z` placeholder — confirms the fix. That same live pass
also surfaced an unrelated, out-of-scope discovery: `AgentRequest`'s
`toolsEnabled: false` (the default `prepareReleaseDraft` uses, and
every other text-only call site in the app) doesn't appear to
actually suppress the `claudeAgentSdk` provider's file/git tool
access — the model's own narration showed it exploring the real
filesystem (reproduced twice, from two different working
directories, including once reading real private symbols out of
the actual `aion` source checkout mid-draft). Flagged separately via
`spawn_task` for its own investigation — a provider/SDK-client
concern well outside this change's scope, not fixed here.
