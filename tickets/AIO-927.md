# T5. Added round-trip cases to the existing

`aion/test/core/markdown/ticket_markdown_serializer_test.dart`:
a ticket with `deletedAt: null` serializes to `deletedAt: null`
and parses back to `null`; a ticket with a real `deletedAt`
serializes to its ISO-8601 string and parses back to the
identical `DateTime`; a frontmatter block with no `deletedAt` key
at all still parses as `ParsedOk` with a `null` value for that
field (backward compatibility with already-committed ticket
files). 7/7 in this file passing.
**Found a real, separate, pre-existing bug while writing this —
not fixed here, out of scope**: `Ticket.copyWith` has no
`deletedAt` parameter at all, and its returned `Ticket(...)`
never passes `deletedAt:` either — so `deletedAt` silently resets
to `null` on *every* `copyWith` call, regardless of the
original's value. Confirmed harmless in current practice only
because `DriftTicketRepository.updateTicket` (the only write path
that persists a whole `copyWith`'d `Ticket`) explicitly excludes
`deletedAt` from what it writes to the DB — so the incorrect
in-memory value it produces is never actually persisted today.
Still a real correctness gap in `Ticket.copyWith` itself
(`lib/features/tickets/domain/entities/ticket.dart`) that a
future caller could trip over; unrelated to this change's own
scope (a domain-entity fix, not a markdown-serialization one), so
flagged rather than fixed here. The test above builds a `Ticket`
directly instead of via `copyWith` to work around it.
