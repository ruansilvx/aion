# UI

- [x] `lib/design_system/molecules/graph_canvas.dart` — `GraphCanvas`
      primitive: `InteractiveViewer` (pan/zoom) wrapping a `Stack` of
      positioned node widgets, a `CustomPainter` edge layer beneath,
      hand-built drag/select gestures (`GestureDetector`/`Listener`, no
      Material). Generic over a node/edge model and a per-node content
      builder — not `DecisionNode`-specific. Per design.md §0 Shared
      vocabulary, §1 `GraphCanvas` (§1.1–§1.7: plane, decision node +
      states, terminal outcome node, edge/connector, root marker,
      zoom/pan affordances, empty-graph state).
- [x] `lib/features/providers/presentation/widgets/decision_node_form.dart`
      — `DecisionNodeForm`: condition picker (`SelectionMenu` over
      `decisionConditionsFor(context)`), typed parameter fields per
      `DecisionConditionSpec.parameterSpecs`, matched/unmatched branch
      picker (terminal outcome `SelectionMenu` or "continue to another
      condition"). Shared by both panes. Per design.md §3
      `DecisionNodeForm` (§3.1–§3.5: condition picker, parameter field,
      matched-branch picker, unmatched-branch picker, actions) —
      implement both the inline mount and the popover mount described
      there. Fixed in the `/verify` follow-up pass: added the
      `DecisionBranchMode`-driven two-segment "End here / Continue to
      condition" control per branch (`_BranchSection`/
      `_BranchModeToggle`); picking "Continue to condition" for a
      not-yet-chained branch creates the child node via the new
      `onCreateChainedChild` callback (bound by each mount to
      `DecisionGraphConfigCubit.createNode`) and attaches it as that
      branch's `DecisionBranch.toNode` target — an already-chained branch
      shows its child's condition name read-only (editing that child
      happens on its own row/canvas node instead).
- [x] `lib/features/providers/presentation/widgets/decision_outline_list.dart`
      — `DecisionOutlineList`: one row per `DecisionNode`, children
      indented beneath their parent branch (nested outline, no depth
      cap), outcome badge on terminal branches, inline `DecisionNodeForm`
      expand-in-place per row (matching
      `WorkflowStatusSettingsScreen._AddStatusControl`'s interaction
      shape). Per design.md §2 `DecisionOutlineList` (§2.1–§2.3: list
      row + states, terminal outcome badge, "+ Add condition"
      affordance). Fixed in the `/verify` follow-up pass: `_NodeRow` now
      recurses into each branch that's a `ToNodeBranch` via the new
      `_BranchChild` wrapper (`MATCHED`/`UNMATCHED` label + a nested
      `_NodeRow` for the child), no depth cap.
- [x] `lib/features/providers/presentation/screens/decision_graph_editor_screen.dart`
      — `DecisionGraphEditorScreen`: `Row` of two `Expanded` panes with
      a 1px divider (layout scaffold from `MarkdownEditor._Wide`),
      `GraphCanvas` (default/left) + `DecisionOutlineList` (right), both
      bound to the same `DecisionGraphConfigLoaded` state. Per design.md
      §4 `DecisionGraphEditorScreen` (§4.1–§4.4: header, panes, divider,
      narrow behavior). Fixed in the `/verify` follow-up pass:
      `_CanvasPane` (now stateful, owning a per-node `LayerLink` map) tap
      opens `DecisionNodeForm.showAsPopover`, its callbacks bound to
      `DecisionGraphConfigCubit` at tap time (the popover's `OverlayEntry`
      itself can't safely `context.read` — see that method's own
      dartdoc); the new `_TreeLayout` helper walks the whole reachable
      tree recursively (in-order slot → x, depth → y, per design.md
      §1.1) instead of hardcoding the root plus two direct branches.
- [x] `lib/features/providers/presentation/screens/settings_screen.dart`
      — extend `_AutomationSection`'s per-context row with a "Configure
      decision graph" affordance that pushes
      `DecisionGraphEditorScreen(context: ...)`. Per design.md §5
      Settings automation row extension (§5.1–§5.2: affordance,
      states).
