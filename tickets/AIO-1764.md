# Post-`/verify` fixes (WARNING finding from the first `/verify` pass)

- [x] 8. `lib/features/tickets/data/services/ticket_db_reconstruction_service.dart`
  — `reconstruct`'s `existingByTicketId` map is captured once from
  `_repository.getAllTickets()` before the directory loop and never
  updated as tickets are imported/updated within the same run. If two
  different `.md` files parse to the same `ticketId`, both hit the
  true-import branch and both call `_repository.importTicket`; the
  second throws on `TicketsTable.ticketId`'s `unique()` constraint,
  uncaught, aborting the whole `reconstruct()` call instead of just that
  file. Fix: after the `updateTicket`/`importTicket` call succeeds for a
  given `ticket`, add `existingByTicketId[ticket.ticketId] = ticket;`
  before moving to the next file, so a same-run duplicate `ticketId` is
  correctly detected and routed to `updateTicket` on its second
  occurrence instead of a second `importTicket`. Update the `reconstruct`
  method dartdoc to note this within-run dedup behavior.

- [x] 9. `test/features/tickets/data/services/ticket_db_reconstruction_service_test.dart`
  — add a test: two files parsing to the same `ticketId` (no matching
  existing row for either) results in exactly one `importTicket` call and
  one `updateTicket` call (not two `importTicket` calls), and
  `reconstruct` completes without throwing.
