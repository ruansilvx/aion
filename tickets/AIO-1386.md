# Post-`/verify` fixes (WARNING findings from the first `/verify` pass)

- [x] T31. Fix `PageDetailScreen`'s header to match design.md §3.1
      (finding #3): promoted the existing `TypeChip`/`ticketTypeLabel`
      (previously private to `tickets_list_screen.dart`/
      `tickets_board_view.dart`) to `design_system/molecules/type_chip.dart`
      per Pattern 2 — it was already generic (`TicketType` + `isRow` bool,
      no `Ticket`-specific logic), just not yet promoted, so `features/pages/`
      can render it without a direct `features/tickets` presentation-layer
      import. Replaced `PageDetailScreen`'s `AppHeader` usage (which can't
      express an inline-editable title slot) with a custom
      `_PageDetailHeader`: back button, `TypeChip(type: .page, isRow: false)`,
      the mono `ticketId` as an eyebrow above an `InlineEditableField` title,
      sync-status badge, and delete action — the title editor moved out of
      the scrollable body into the header. Updated `tickets_list_screen.dart`
      / `tickets_board_view.dart` and their two other consumers
      (`ticket_link_picker.dart`, `trashed_ticket_tile.dart`) to the promoted
      import; no behavior change for `TicketDetailScreen` itself.

- [x] T32. Implement `MarkdownEditor`'s saving/error states (design.md
      §1.3–§1.4), finding #5: changed `onCommit`'s type from
      `ValueChanged<String>` to `Future<void> Function(String)` so the
      widget can await the result — the design's own fire-and-forget
      signature couldn't support this. Save now shows an `AppSpinner` and
      disables both buttons while in flight; a thrown error shows an inline
      danger row (new `pageDetailMarkdownSaveError` l10n string) that clears
      on the next keystroke. Note: `AppButton` has no built-in
      loading-label slot (no screen in this codebase swaps a button's
      label for a spinner — confirmed via `CreateTicketScreen`'s
      `_isSubmitting`), so this places the spinner beside the buttons
      rather than widening that shared atom's API for one caller.

- [x] T33. Add the 120ms debounce to `MarkdownEditor`'s wide-mode live
      preview (design.md §1.5), finding #6: previously `MarkdownView`
      re-parsed `_controller.text` synchronously on every keystroke via
      `ListenableBuilder`. Now a `Timer`-based `_previewText` mirrors the
      controller with a 120ms debounce, matching design.md's stated
      rationale (avoid re-parsing Markdown on every keystroke).
