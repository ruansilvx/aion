# `features/tickets/presentation/cubit/` — provider-registry threading

- [x] T19. `lib/features/tickets/presentation/cubit/chat_cubit.dart` —
  MODIFY: `ChatCubit`'s constructor takes a `ProviderRegistry` instead
  of an `AgentModelClient`; add a private `_resolveModelAndProvider(ModelPhase)
  → Future<(AgentModelDescriptor, AgentProvider)>` helper (per
  design.md §7); `sendMessage` uses it instead of `_resolveModel` alone.
  `runChatTurn`'s static signature changes per design.md §4: adds
  required `provider: AgentProvider`; `model` becomes
  `AgentModelDescriptor` (`model.id` references become `model.modelId`);
  `onOverageDetected: VoidCallback?` is replaced by `onConsumptionSignal:
  void Function(ConsumptionSignal)?`, calling
  `provider.describeOverage(message)`; the `AgentErrorEvent` branch
  passes its message through `provider.normalizeErrorMessage` before
  assigning `failureMessage`. Depends on T3, T4, T5, T6, T11. Update
  dartdoc to match every changed signature.
- [x] T20. `lib/features/tickets/presentation/cubit/tickets_cubit.dart`
  — MODIFY: constructor's `AgentModelClient? agentClient` param/field
  becomes `ProviderRegistry? providerRegistry`; every one of the six
  `_resolveModel(ModelPhase.xxx)` call sites (coding-execution retry,
  SDD-stage chat spawn/turn, verify-gate, full-summarization worktree
  run, and the remaining coding-execution call site) switches to
  `_resolveModelAndProvider`, threading `client: provider.client,
  provider: provider` into each `ChatCubit.runChatTurn` call. Depends on
  T19. Update dartdoc to match.
- [x] T21. `lib/features/tickets/presentation/cubit/inbox_cubit.dart` —
  MODIFY: same swap as T20 — constructor's `AgentModelClient` field
  becomes `ProviderRegistry`; all four `_modelRoutingRepository.getModelForPhase`
  + `ChatCubit.runChatTurn` call sites (brain dump, what-next guidance,
  release planning, Q&A worktree turn) resolve
  `(AgentModelDescriptor, AgentProvider)` together and thread `provider`
  through. Depends on T19. Update dartdoc to match.
