# 5. Presentation — `InlineEditableField<T>`

- [x] **T09** — Create `lib/features/tickets/presentation/widgets/inline_editable_field.dart` per design.md §1 Inline editable text field, §2 Inline editable duration field, and §5 Error toast.
  **Deviations**: (1) multiline (description) does not commit on blur —
  per design.md §1.4's explicit reasoning ("blur happens too easily while
  scrolling"), it commits only via an explicit Save/Cancel row (reusing
  `AppButton` ghost/primary variants — no "small" size variant exists on
  `AppButton`, so standard size is used) shown while editing; this
  overrides this task's original single-line-shaped wording. (2) Escape
  is intercepted via `Shortcuts`/`Actions` (`_CancelEditIntent`), not a
  second `Focus`/`FocusNode` wrapper — attaching a second `Focus` widget
  to the same `FocusNode` `AppTextField`'s inner `TextField` already
  uses would double-attach it, which Flutter disallows.
  File header comment. Implement `InlineEditableField<T>` per
  `design.md`:
  - View mode: `Semantics(button: true, label: semanticsLabel)` +
    `FocusableActionDetector` (`ActivateIntent` → enter edit mode) +
    `GestureDetector` showing `displayText` (muted `placeholder` style
    when `displayText` is empty and `placeholder` is set).
  - Edit mode: `AppTextField` (reused, not modified), controller
    pre-filled with `editText`, autofocus, `maxLines` passthrough.
    `textInputAction: maxLines == 1 ? TextInputAction.done :
    TextInputAction.newline`.
  - `Escape` key handling reverts the controller to `editText` and exits
    edit mode without calling `parser`.
  - Single-line fields commit on `onSubmitted` or focus loss; multiline
    commits on focus loss only.
  - `_commit()`: run `widget.parser(controller.text)` in try/catch. On
    `FormatException`, `AppToast.show(context, e.message)`, revert
    controller text to `editText`, exit edit mode — `onCommit` not
    called. On success, call `widget.onCommit(parsed)`, exit edit mode.
  - **`mounted` guard**: the focus-listener callback that triggers
    `_commit()` on blur must check `if (!mounted) return;` before any
    `setState` — same class of bug as the project's documented
    `AppDropdown` overlay-dismiss crash (`project.md` Testing section).
    Do not skip this.
  - Dartdoc the class and its generic type contract (what `parser`/
    `onCommit` are expected to do).
