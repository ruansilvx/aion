# 4. In `advanceSddStage`: capture `stateBeforeThisWrite = state` at

the method's top. After the successful stage-advance write's own
`TicketDetailLoaded` re-emission, add
`unawaited(_refreshDetailIfOpenAndAffected({ticket.id},
fromState: stateBeforeThisWrite))`. Update the method's dartdoc to
document this new side effect (closes the Epic/Story `sddStage`
live-refresh gap — reference
`aion-arch/changes/generalized-live-refresh-for-all-ticket-writes`
the way sibling methods reference their own originating change).
**Deviates from the placement above, noted during `/verify`**:
implemented as a single call fired once right after
`_repository.updateTicketSddStage`'s write is confirmed (before
either of the method's two branch-specific `TicketDetailLoaded`
re-emissions — the archived-stage branch and the
isAdvancingStage-true branch), not literally "after" one specific
re-emission as worded above — placing it once ahead of the branch
avoids duplicating the same call in both branches. Confirmed
harmless: `_refreshDetailIfOpenAndAffected` uses the explicitly
passed `fromState`, not a live `state` read, so its own behavior
doesn't depend on emission order; and unlike the
`updateStatusForTickets` bug found in the same `/verify` pass (see
the commit fixing it), the actual attachment-fire call in this
method is gated behind `await _createStageChat(...)` — a real
async gap — so it can never land before this refresh call's own
final re-emission. No test or behavior change needed.
