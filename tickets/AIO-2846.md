# Repoint ticket git-projection plumbing at the new location

`TicketGitProjector`, `TicketDbReconstructionService`,
`TicketMarkdownReconciler`, `TicketRepairService`,
`TicketMarkdownWatcherService`, and every `GitRepositoryClient` call
`TicketGitProjector` makes should read the tickets-repo path when the
owning project has one set, falling back to `rootPath` otherwise. Should
build on the gitignored-path handling already landed via
`GitRepositoryClient.isIgnored` (the `fix/ticket-projection-gitignored-
tickets-dir` fix) rather than duplicate it.

## Technical shape (revised after investigation)

The story's original wording named five services
(`TicketGitProjector`, `TicketDbReconstructionService`,
`TicketMarkdownReconciler`, `TicketRepairService`,
`TicketMarkdownWatcherService`) as needing to change. Investigation
found none of their own code needs to change -- each already takes
whatever `rootPath` string its caller passes as a plain parameter, with
no internal assumption about where that string comes from. The actual
fix is entirely at the composition root that decides *which* path
string to pass in:

- New `Project.ticketsGitRootPath` getter (`ticketsRootPath ??
  rootPath`) in
  lib/features/projects/domain/entities/project.dart -- the one
  resolved value any ticket-git-projection wiring should read, instead
  of raw `rootPath`.
- `lib/core/routing/app_router.dart`'s `WorkspaceShell` state has a
  single private `_rootPath` getter (currently `isDesktop ?
  widget.project.rootPath : null`) that almost everything else in that
  file reads from one local (`final rootPath = _rootPath;`):
  `GitProjectingTicketRepository`, `TicketParentTrashService`,
  `TicketMarkdownWatcherService`, and `TicketsCubit`'s
  `projectRootPath` (which is itself what `TicketRepairCubit` and
  `TicketMarkdownReconciler` ultimately see). Repointing this one
  getter to `widget.project.ticketsGitRootPath` fixes all of those in
  one place.
- Two call sites sit *outside* that State class and read
  `_activeProject(context).rootPath` directly instead: the
  `/workspace/tickets/trash` route's `TrashCubit` and the
  `/workspace/inbox` route's `InboxCubit`. Both need the same
  `ticketsGitRootPath` treatment individually.
- `TicketDbReconstructionService` has no live UI call site today --
  only the one-off `bin/migrate_aion_arch.dart` CLI and its own tests
  construct it. Nothing to repoint there; out of scope until it's
  actually wired to something in the app.

## Known external dependency (not a task here)

This story's original text assumed `GitRepositoryClient.isIgnored`
"already landed" (from a separate background fix,
`fix/ticket-projection-gitignored-tickets-dir`). As of this proposal
that fix is still uncommitted/local-only, not yet in `dev`. Nothing in
this story's own tasks touches `isIgnored` directly, so it isn't a hard
blocker for implementation -- but check whether that fix has merged
before this story's own PR does, in case of overlapping edits to
`ticket_git_projector.dart`/`git_repository_client_test.dart`/
`ticket_git_projector_test.dart`.
