This is the first real-world use of `project.md`'s Pattern 1
(dependency-inversion-via-`core`) for one feature depending on another
feature's *ticket data* specifically — the two existing `core/contracts/`
interfaces (`ActiveProjectProvider`, `EmbeddingProvider`) cover a different
kind of cross-cutting state. `ActiveProjectProvider`/`ActiveProjectCubit`
(interface in `core/contracts/`, implemented directly by a Cubit, provided
once at the app root) is the closer structural template, and is followed
here: `PageTicketProvider` is implemented in `features/tickets/data/`,
never in `features/pages/`.

## Why the `markdown` pub.dev package, but a hand-written renderer

Unchanged from the original proposal. Full CommonMark (plus the GFM
extensions: tables, strikethrough, task-list checkboxes, autolinks) is a
large, edge-case-heavy spec with an official conformance test suite —
hand-writing a compliant parser from scratch is exactly the kind of
undertaking this project has already been burned by once:
`TicketMarkdownWatcherService`'s from-scratch WordPiece tokenizer is
flagged as a standing concern in `aion-arch/specs/tickets.md`'s known gaps.
Don't repeat that mistake here. Instead:

- **Parsing** is delegated to [`package:markdown`](https://pub.dev/packages/markdown)
  (the `dart-lang`-maintained CommonMark implementation) with
  `ExtensionSet.gitHubWeb` enabled for GFM tables/strikethrough/task-lists/
  autolinks. Pure Dart, zero Flutter dependency — parses a `String` into a
  `List<md.Node>` AST and nothing more, so depending on it carries no risk
  against `project.md`'s Non-Material constraint.
- **Rendering** (AST → widgets) is hand-written, in
  `design_system/molecules/markdown_view.dart`, using `AionText`/
  `AionColors`/`AionRadius`/`AionSpacing` tokens. This is the part that
  would carry Material-coupling risk if outsourced (e.g. to
  `flutter_markdown`, which is not guaranteed Material-free), so it stays
  in-house.

## `design_system/molecules/markdown_view.dart`

```dart
/// Read-only rendering of a Markdown string, parsed via `package:markdown`
/// (CommonMark + GFM extensions — tables, strikethrough, task lists,
/// autolinks) and styled with [AionText]/[AionColors] tokens. Non-Material
/// — no [flutter_markdown] or similar rendering dependency; only the
/// upstream package's pure-Dart parser is used, never its (Flutter)
/// rendering pieces.
class MarkdownView extends StatelessWidget {
  const MarkdownView({super.key, required this.source});
  final String source;
}
```

Parsing: `md.Document(extensionSet: md.ExtensionSet.gitHubWeb).parse(source)`
(`md` aliasing `package:markdown/markdown.dart`) produces the block-level
`List<md.Node>`. `MarkdownView` walks that tree with a private
`_buildNode(md.Node node)` converter — a `switch` on `md.Element.tag` (for
`md.Element` nodes) or a leaf `md.Text` — producing widgets per tag using
existing tokens (all colors/text via `ThemeScope.of(context)`, matching
every other widget in the codebase):
- `h1`-`h6` → `AionText.h1`/`h2` for levels 1-2, `AionText.body` bold-
  weighted for levels 3-6 (no dedicated `h3`-`h6` tokens exist — reuse
  `body` with a heavier `FontWeight` via `.copyWith`).
- `p` → `Text.rich(TextSpan(children: [...]))` built by recursing into the
  paragraph's inline children (`strong` → `FontWeight.w700`, `em` →
  `FontStyle.italic`, `del` → `TextDecoration.lineThrough`, `code` →
  `AionText.key` mono token with a subtle background chip via
  `AionColors.surfaceHover` + `AionRadius.sm`, `a` → `AionColors.primary`
  colored + underlined, tapping opens the link — exact tap-handling
  mechanism, e.g. `url_launcher` vs. an in-app viewer, is an `/apply`-time
  detail since no such dependency exists yet in this project).
- `ul`/`ol` → `Column` of rows, each a bullet (`•`) or number marker +
  `Expanded(Text.rich(...))` for the item's inline content, indented with
  `AionSpacing.sp8`; nested `ul`/`ol` inside an `li` recurse with additional
  indent. GFM task-list items (`li` containing a checkbox `input` node per
  `package:markdown`'s task-list extension) render a small checked/unchecked
  box glyph instead of a bullet — **read-only** (this view never mutates
  source text; toggling a checkbox is out of scope for this change).
- `pre`/`code` (fenced/indented code blocks) → `Container` with
  `AionColors.surfaceHover` fill, `AionRadius.md`, `AionColors.border` 1px
  border, `AionText.key` mono style, horizontally scrollable
  (`SingleChildScrollView(scrollDirection: horizontal)`) for long lines.
- `blockquote` → `Container` with a left-side `AionColors.border` accent
  bar (`Border(left: BorderSide(...))`) and `AionSpacing.sp12` left
  padding, recursing into its child blocks with `AionColors.textSecondary`.
- `hr` → a 1px `AionColors.border` full-width divider.
- `img` → out of scope for this change (renders as its alt text via a
  plain `Text` fallback) — full image display for Markdown content is
  better scoped alongside the separate
  `upload-and-visualize-files-for-resource-tickets` idea, which already
  owns file visualization.
- GFM tables (`table`/`thead`/`tbody`/`tr`/`th`/`td`) → a `Table` widget
  (Flutter's layout primitive, not `DataTable` — `DataTable` is Material)
  with `AionColors.border` cell dividers and `AionText.bodySm` cell text.

Any `md.Element` tag not covered above (or any node the upstream package
can't parse cleanly) falls back to rendering its concatenated text content
as a plain paragraph — never throws, so the editor never hard-fails on
user input mid-typing.

Blocks are joined in a `Column` with `AionSpacing.sp12` vertical gaps.

**Tests** (`design_system/molecules/markdown_view_test.dart`): one case per
supported tag (headings 1-6, paragraph with mixed inline emphasis + a link,
bullet/ordered/nested/task lists, fenced code block, blockquote, horizontal
rule, GFM table) plus one unrecognized-node fallback case.

## `design_system/molecules/markdown_editor.dart`

```dart
/// Responsive Markdown content editor: a view/edit toggle on narrow
/// layouts, a live raw/preview split view on wide layouts. Commits only on
/// explicit Save (never on blur), matching [InlineEditableField]'s
/// multiline commit discipline.
class MarkdownEditor extends StatefulWidget {
  const MarkdownEditor({
    super.key,
    required this.initialValue,
    required this.onCommit,
    required this.semanticsLabel,
    this.placeholder,
  });
  final String initialValue;
  final ValueChanged<String> onCommit;
  final String semanticsLabel;
  final String? placeholder;
}
```

Unchanged from the original proposal — this widget is fully generic (a
plain `String` in, an `onCommit` callback out, no `Ticket`/`TicketType`
awareness), so it stays a `design_system/molecules/` widget regardless of
which feature wires it up. Its behavior:

**State:** `_controller` (`TextEditingController`, seeded from
`initialValue`), `_isEditing` (narrow-layout only — starts `false`, i.e.
rendered view first), `_previewText` (mirrors `_controller.text`, rebuilt
`onChanged` for live preview — cheap re-parse via `package:markdown` on
each keystroke, acceptable since content is personal-scale, not a large
document; `MarkdownView` never throws regardless of input).

**Layout** — `LayoutBuilder`, threshold `constraints.maxWidth <= 640`
(following the codebase's existing per-widget-threshold convention seen in
`trash_screen.dart`'s `isNarrow = constraints.maxWidth <= 380`):

- **Narrow (`isNarrow`):** a small header row with a view/edit toggle
  (`PhosphorIcons.pencilSimple`/`PhosphorIcons.eye`, `AionColors.textSecondary`),
  then either:
  - View mode: `MarkdownView(source: _controller.text)` (or the
    `placeholder` text in muted style, if empty), tap the header's edit
    icon to switch to edit mode.
  - Edit mode: `AppTextField` (multiline, unbounded) + an explicit
    Save/Cancel button row underneath. Save calls `widget.onCommit` with
    the trimmed text and returns to view mode; Cancel discards
    `_controller`'s edits (reset to `initialValue`) and returns to view
    mode.
- **Wide (`!isNarrow`):** a `Row` — `Expanded(AppTextField(...))` on the
  left, a 1px `AionColors.border` vertical divider, `Expanded(MarkdownView(
  source: _previewText))` on the right, both scrollable independently, an
  explicit Save/Cancel row beneath.

`MarkdownEditor` never calls a repository or Cubit method itself — it only
ever calls the caller-supplied `onCommit`, which is how `PageDetailScreen`
wires it to `PagesCubit` below.

## `design_system/atoms/app_text_field.dart` modification

Unchanged from the original proposal: accept `maxLines: int?` explicitly
allowing `null` (Flutter's `TextField` already supports `maxLines: null`
for unbounded auto-grow), passed through as-is. No other behavior change;
existing callers (all of which pass a finite `maxLines`) are unaffected.

## `core/contracts/page_ticket_provider.dart`

```dart
/// Cross-feature contract exposing the `page`-ticket data and mutations
/// `features/pages/` needs. Implemented by `PageTicketProviderImpl`
/// (`features/tickets/data/page_ticket_provider_impl.dart`) and provided
/// once per workspace, alongside `TicketsCubit`.
///
/// Per `project.md`'s Pattern 1 (dependency inversion via `core`),
/// `features/pages/` depends only on this interface — never on
/// `features/tickets/` directly. See
/// `aion-arch/changes/page-content-markdown-editor/design.md`.
abstract interface class PageTicketProvider {
  /// Fetches a single `page` ticket by id, or `null` if not found/not a page.
  Future<Ticket?> getPage(String id);

  /// Loads a page's sub-pages, linked tickets, and backlinks in one call —
  /// the same three collections `TicketsCubit.loadDocumentRelations`
  /// already computes for the shared `TicketDetailScreen`.
  Future<PageRelations> loadPageRelations(String pageId);

  /// Creates a new `page` ticket. Delegates to `TicketsCubit.createTicket`
  /// for the same validation/invariant logic every other creation path
  /// uses — no duplicated business logic in `features/pages/`.
  Future<Ticket> createPage({
    required String title,
    String? description,
    String? parentId,
  });

  /// Persists an edited `page` ticket (title/content/parent changes).
  /// Delegates to `TicketsCubit.updateTicket`.
  Future<Ticket> updatePage(Ticket page);

  /// Moves a `page` ticket to trash. Delegates to `TicketsCubit.trashTicket`.
  Future<void> trashPage(String id);

  /// Candidate parents for a page (self/descendants/type-incompatible
  /// candidates already excluded), for `PageCreateScreen`'s/
  /// `PageDetailScreen`'s parent picker.
  Future<List<Ticket>> getValidParentCandidatesForPage({String? excludeId});
}

/// A page's sub-pages, linked tickets, and backlinks — the same three
/// collections `TicketDetailScreen` already renders for `page` tickets,
/// carried across the `core/contracts/` boundary as plain domain entities.
class PageRelations extends Equatable {
  const PageRelations({
    required this.childDocs,
    required this.linkedTickets,
    required this.backlinks,
  });
  final List<Ticket> childDocs;
  final List<Ticket> linkedTickets;
  final List<Ticket> backlinks;

  @override
  List<Object?> get props => [childDocs, linkedTickets, backlinks];
}
```

`Ticket` (the domain entity from `features/tickets/domain/entities/`)
flows through this interface directly, matching the existing precedent:
`ActiveProjectProvider` (`core/contracts/active_project_provider.dart`)
already imports and exposes `Project` from `features/projects/domain/
entities/project.dart` the same way. Domain entities crossing a
`core/contracts/` boundary is the established, accepted pattern here —
only Cubits, repository implementations, and presentation-layer widgets
count as "internals" a consuming feature must never import directly.

## `features/tickets/data/page_ticket_provider_impl.dart`

```dart
/// Drift/[TicketsCubit]-backed implementation of [PageTicketProvider].
/// Reads go straight to [TicketRepository]/[TicketLinkRepository] (no
/// business logic there per project.md's Cubit-vs-repository split);
/// writes delegate to [TicketsCubit] so page creation/edit/trash reuse
/// exactly the same validation/invariant logic every other ticket type's
/// screens already trigger — no duplicated write path.
class PageTicketProviderImpl implements PageTicketProvider {
  const PageTicketProviderImpl(
    this._ticketsCubit,
    this._ticketRepository,
    this._ticketLinkRepository,
  );
  final TicketsCubit _ticketsCubit;
  final TicketRepository _ticketRepository;
  final TicketLinkRepository _ticketLinkRepository;
}
```

- `getPage`/`loadPageRelations`/`getValidParentCandidatesForPage` read
  directly via `_ticketRepository`/`_ticketLinkRepository` (mirroring what
  `TicketsCubit.loadDocumentRelations`/`getValidParentCandidatesForType`
  already do internally at the repository level — see design.md's original
  research notes: `getTicketsByParent(id, types: [page, resource])` +
  `TicketLinkRepository.getLinksForTicket`), since reads carry no
  validation/invariant logic to preserve.
- `createPage`/`updatePage`/`trashPage` call `_ticketsCubit.createTicket`/
  `.updateTicket`/`.trashTicket` — the **same three `TicketsCubit` methods**
  `TicketDetailScreen`/`CreateTicketScreen` already call for every other
  type. This requires `createTicket`/`updateTicket` to *return* the
  resulting `Ticket` (see the `TicketsCubit` modification below) so this
  adapter can hand it back through `PageTicketProvider`'s `Future<Ticket>`
  return types without racing `TicketsCubit`'s emitted Bloc state (which
  stays feature-internal to `tickets` and is never exposed here).

## `TicketsCubit` modification

`createTicket`/`updateTicket` currently return `Future<void>` while
internally persisting and emitting a `TicketDetailLoaded`/similar state.
Change both to return `Future<Ticket>` (the persisted/refreshed ticket),
in addition to still emitting the same state as before — backward
compatible, since existing callers in `TicketDetailScreen`/
`CreateTicketScreen` don't need to change (they can keep ignoring the
return value). `trashTicket` stays `Future<void>` — `PageTicketProvider
.trashPage` doesn't need a return value.

## `features/pages/presentation/cubit/pages_cubit.dart` + `pages_state.dart`

```dart
/// UI-orchestration Cubit for the `pages` feature. Mirrors the shape of
/// [TicketsCubit]'s detail/create flows, but scoped to `page` tickets only
/// and built entirely on [PageTicketProvider] — never on [TicketsCubit] or
/// [TicketRepository] directly.
class PagesCubit extends Cubit<PagesState> {
  PagesCubit(this._provider) : super(const PagesInitial());
  final PageTicketProvider _provider;

  Future<void> loadPage(String id);   // getPage + loadPageRelations -> PageDetailLoaded
  Future<void> createPage({required String title, String? description, String? parentId});  // -> PageCreated(page)
  Future<void> updatePage(Ticket page);  // -> PageDetailLoaded(refreshed)
  Future<void> trashPage(String id);     // -> PageTrashed()
}

sealed class PagesState extends Equatable { const PagesState(); }
class PagesInitial extends PagesState { const PagesInitial(); ... }
class PagesLoading extends PagesState { const PagesLoading(); ... }
/// A loaded page's detail view: the ticket plus its sub-pages/linked/backlinks.
class PageDetailLoaded extends PagesState {
  const PageDetailLoaded(this.page, this.relations);
  final Ticket page;
  final PageRelations relations;
  ...
}
class PageCreated extends PagesState { const PageCreated(this.page); final Ticket page; ... }
class PageTrashed extends PagesState { const PageTrashed(); ... }
class PagesError extends PagesState { const PagesError(this.message); final String message; ... }
```

`MarkdownEditor`'s edit/view toggle and split-view layout state stay local
`StatefulWidget` state inside `MarkdownEditor` itself (per `project.md`'s
"Cubit preferred, not required for pure UI state" allowance) — `PagesCubit`
only owns data loading/mutation, not that widget's internal presentation
state.

## `features/pages/presentation/screens/page_create_screen.dart`

A trimmed creation form: title (required), an optional parent picker
(`PageTicketProvider.getValidParentCandidatesForPage`), and an optional
initial content field (or leave content empty and let the user fill it in

content yet and the user's next action is almost always to start writing.

## Shared widget promotion (Pattern 2)

`PageDetailScreen` needs four pieces of UI currently owned by `tickets`.
Per Pattern 2, each must be confirmed generic (or generalized first) before
promotion to `design_system/molecules/` — exact current file locations
weren't fully confirmed during this proposal's research pass and must be
grepped for at `/apply` time:

- **Sub-pages section** — per `aion-arch/specs/tickets.md`, currently an
  inline private widget (`_SubPagesSection`) inside
  `ticket_detail_screen.dart` itself, not a standalone file. Must first be
  *extracted* into its own widget class, then generalized (no `Ticket`
  business logic beyond taking a `List<Ticket>` + callbacks), then promoted
  as `design_system/molecules/page_sub_pages_section.dart`.
- **Linked tickets section** (`DocumentationLinkedTicketsSection`) and
  **backlinks section** (`DocumentationBacklinksSection`) — per the spec,
  these already appear to be standalone, callback-based widgets (used
  identically for both `page` and `resource` tickets today), which suggests
  they're already close to generic. Confirm via `grep -r "class
  DocumentationLinkedTicketsSection"` at `/apply` time; promote as-is if
  genuinely type-agnostic, generalize first if not.
- **Sync-status badge/repair banner** — per the spec, currently rendered
  inline inside `TicketDetailScreen`'s build method (no separate widget
  class yet). Must be extracted into a standalone `SyncStatusBadge` widget
  (taking a `TicketSyncStatus` + repair callback, not a whole `Ticket`),
  then promoted.
- **Minimal delete action** — `TicketOverflowMenu`'s "Delete ticket" row.
  If `TicketOverflowMenu` turns out to hold more than just delete (e.g.
  other tickets-specific actions), don't promote the whole menu — extract
  a minimal, generic `AppOverflowMenu`/`DeleteActionButton` molecule
  instead and leave `TicketOverflowMenu` itself untouched in `tickets`.

This list is a commitment to the promotion **strategy**, not to exact
file-level diffs sight-unseen — `/apply`'s tasks.md tasks below phrase each
as "locate, confirm generic (or generalize), then promote" rather than
asserting unverified line numbers.

## Routing (`core/routing/app_router.dart`)

Add, following the existing file's declaration-order convention (literal
routes before `:id` wildcards, same as the existing `/workspace/tickets/*`
block):

```dart
GoRoute(path: '/workspace/pages/new', builder: (context, state) {
  final extra = state.extra;
  return PageCreateScreen(
    initialParentId: extra is PageCreateRouteExtra ? extra.initialParentId : null,
  );
}),
GoRoute(path: '/workspace/pages/:id', builder: (context, state) {
  final id = state.pathParameters['id']!;
  return PageDetailScreen(pageId: id);
}),
```

Both sit under the existing `/workspace/*` prefix, so they inherit
`_redirect`'s active-project gate for free — no change needed there.

**Redirecting stale `/workspace/tickets/:id` links for pages:** anywhere in
the app that navigates to a ticket generically by id (Documentation tree
taps, linked-tickets/backlinks taps elsewhere, search results) needs to
route `page`-type tickets to `/workspace/pages/:id` instead of
`/workspace/tickets/:id`, now that the latter no longer handles pages. Add
a small resolver, `core/routing/ticket_navigation.dart`:

```dart
/// Resolves the correct detail route for any ticket, accounting for
/// `page` tickets living in their own module since page-content-markdown-editor.
String ticketDetailRoute(Ticket ticket) => ticket.type == TicketType.page
    ? '/workspace/pages/${ticket.id}'
    : '/workspace/tickets/${ticket.id}';
```

used by every existing call site that currently does
`context.go('/workspace/tickets/${ticket.id}')` unconditionally (the exact
set of call sites — Documentation tree item taps, `LinkedTicketsSection`/
`BacklinksSection` taps, any search-result navigation — needs enumerating
at `/apply` time via `grep -r "/workspace/tickets/\$"`).

# Aion — Page Content Editor & Dedicated Page Screens: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing`, `AppTextField`, `AppSpinner`, `AppToast` by name. **No Material widgets anywhere.** Build from Flutter primitives only — `DecoratedBox`, `Container`, `GestureDetector`, `CustomPaint`, `Row`/`Column`/`Stack`, `Positioned`, `LayoutBuilder`, `SingleChildScrollView`. The one sanctioned exception is a bare `TextField` wrapped in a transparent `Material`, already encapsulated by `AppTextField`; every text input here builds on `AppTextField` and never touches `TextField` directly.

This feature gives `page`-type tickets their own dedicated screens (`PageDetailScreen`, `PageCreateScreen`), separate from the Jira-style work-item screens used by epics/stories/tasks, plus a real Markdown content editor (`MarkdownEditor` + `MarkdownView`) that replaces the plain-text description box pages currently use. Pages carry **no** priority/estimate/time-spent/status fields and **no** comment thread.

Both themes are specified for every component: **Arctic** (light, celestial-cold) and **Obsidian** (dark, abyssal-cold). Where the two are identical apart from token resolution, that is stated explicitly.

---

## 0. New tokens

Only the values below are added; everything else reuses existing tokens.

### 0.1 Type accent — `typePage`

Add to `AionColors` alongside the existing `typeTask` / `typeStory` / `typeEpic`. This is the **accent color for the entire pages module** — page-type chip, page-icon glyphs, sub-page row icons, and the editor's active affordances.

```dart
// in AionColors
final Color typePage;
// Arctic
typePage: Color(0xFFB0499E), // magenta-orchid
// Obsidian
typePage: Color(0xFFD98CE6), // soft orchid
```

Chip fill follows the base convention: `typePage.withOpacity(a)` where `a = fillAlpha` (Arctic `0.11`, Obsidian `0.16`).

### 0.2 Sync-status derived tints (`AionColorsHubTokens` extension)

Reuse the existing derived helpers; no new named constants required. For the three sync states:

```dart
// c = active AionColors, isDark = Obsidian
// needsRepair (warning-based)
final needsRepairTint       = c.warning.withOpacity(isDark ? 0.16 : 0.12);
final needsRepairBorderTint = c.warning.withOpacity(isDark ? 0.42 : 0.30);
final needsRepairIconTint   = c.warning; // full strength
// pendingReconcile (primary-based)
final pendingTint           = c.primary.withOpacity(isDark ? 0.16 : 0.11);
final pendingSpinnerTrack   = c.primary.withOpacity(isDark ? 0.24 : 0.18);
// repaired (success-based, brief confirmation)
final repairedTint          = c.success.withOpacity(isDark ? 0.16 : 0.12);
final repairedBorderTint    = c.success.withOpacity(isDark ? 0.42 : 0.30);
final repairedIconTint      = c.success;
```

No new radius, spacing, or type tokens are required. The Markdown renderer introduces one derived mono style for code (§2.10) built from `AionText.time`'s family, and one derived surface for code blocks (`surfaceHover`), both from existing tokens.

## 1. MarkdownEditor

The responsive content editor. Wrapped in a `LayoutBuilder`; the `maxWidth` breakpoint at **640** selects the layout mode.

- **Narrow** (`maxWidth <= 640`): a **view / edit toggle**. View mode renders `MarkdownView` (§2) with a small edit affordance; edit mode swaps to a raw-text editor with explicit Save / Cancel.
- **Wide** (`maxWidth > 640`): a **live split view** — raw editor on the left, rendered preview on the right, divided by a 1px vertical `border`, Save / Cancel beneath.

Outer container (both modes): fill `surface`, 1px `border`, radius `AionRadius.lg` (12), no shadow. Section eyebrow above the editor: `"CONTENT"`, `AionText.caption`, color `textMuted`, `AionSpacing.sp12` below.

### 1.1 Narrow — view mode (default, populated)

- Container padding: `EdgeInsets.all(AionSpacing.sp16)`.
- Body: `MarkdownView` (§2) at full width.
- **Edit affordance:** a ghost icon-button pinned to the section header's trailing edge (in the eyebrow row, not floating over content). `28×28`, radius `AionRadius.iconBtnSm` (8), transparent fill, `feather`/`quill` glyph **16px**, color `textSecondary`.
  - Hover: fill `surfaceHover`, glyph `textPrimary`.
  - Pressed: fill `border`, scale `0.98`.
- Tap → enters edit mode (§1.2), seeding the textarea with the raw Markdown source.

### 1.2 Narrow — edit mode (editing / focused)

- Raw textarea built on `AppTextField`, `maxLines: null`, `minLines: 8`, `alignment: topLeft`.
  - Fill `surface`, 1px `border` default → 1.5px `primary` + 3px focus ring (`primary.withOpacity(isDark ? 0.30 : 0.16)`) when focused.
  - Radius `AionRadius.md` (10). Padding `EdgeInsets.symmetric(horizontal: 14, vertical: 12)`.
  - Text: monospace so Markdown syntax is legible — derived style `codeEditor = AionText.body.copyWith(fontFamily: 'JetBrainsMono', fontSize: 13.5, height: 1.55)`, color `textPrimary`. Placeholder (empty, §1.6): color `textMuted`.
- **Action row** beneath the textarea, `AionSpacing.sp12` gap above, `Row` `mainAxisAlignment: end`, `gap: AionSpacing.sp8`:
  - **Cancel** — secondary button (fill `surfaceHover`, 1px `borderStrong`, text `textPrimary`, `AionText.button`, padding `9×16`, radius `AionRadius.md`). Discards edits, returns to view mode.
  - **Save** — primary button (fill `primary`, text `#FFFFFF`, `AionText.button`, padding `10×17`, radius `AionRadius.md`, FAB glow blur 18 spread −9).

### 1.3 Narrow — saving state

- Save button: label swaps to a centered `AppSpinner` (16px, track `#FFFFFF` @ 0.35, head `#FFFFFF`); button keeps its width (no reflow), fill `primary`, `IgnorePointer` on.
- Cancel button: disabled — opacity `0.45`, no pointer.
- Textarea: `readOnly: true`, opacity unchanged (content stays legible).

### 1.4 Narrow — error state

- Save fails: textarea returns to editable; an inline error row appears **between** the textarea and the action row, `AionSpacing.sp8` gap above/below.
  - Layout: `Row`, `gap: 8`, center. Leading `warning-circle` glyph **16px** color `danger`; message `AionText.bodySm` color `danger`: `"Couldn't save changes. Try again."`.
  - Textarea border steps to 1.5px `danger` with error ring `danger.withOpacity(isDark ? 0.30 : 0.16)` until the next keystroke, then reverts to the focused-primary treatment.
- A transient failure may also raise `AppToast` (danger, `warning-circle`), unchanged from the base pattern; the inline row is the persistent affordance.

### 1.5 Wide — split view (`maxWidth > 640`)

- Row of two panes inside the outer container; a **1px `border`** vertical divider between them (a `SizedBox(width: 1)` in a `DecoratedBox` fill `border`, full height).
- **Left pane (editor):** `Expanded`, the same `AppTextField` textarea as §1.2 (mono, `maxLines: null`), padding `EdgeInsets.all(AionSpacing.sp16)`, no inner border (the pane divider and outer container supply the chrome); focus ring is drawn as an **inset** 1.5px `primary` top border on the pane header strip only — the textarea itself shows a blinking caret, no per-field box while in split mode.
- **Right pane (preview):** `Expanded`, `MarkdownView` (§2), padding `EdgeInsets.all(AionSpacing.sp16)`, fill `surface`. Live: re-renders on each debounced (120ms) keystroke.
- Optional pane labels: a thin header strip per pane, `AionText.caption` `textMuted` — left `"EDITOR"`, right `"PREVIEW"` — padding `EdgeInsets.fromLTRB(16, 12, 16, 0)`. Omit on very short heights.
- **Action row** spans the full width beneath both panes, top 1px `border`, padding `EdgeInsets.symmetric(horizontal: 16, vertical: 12)`, `Row` `mainAxisAlignment: end`, `gap: AionSpacing.sp8` — Cancel + Save exactly as §1.2. Saving/error states as §1.3–1.4.
- Minimum pane height: `240`. Below that the editor falls back to narrow toggle mode even above 640px width (guards short landscape phones).

### 1.6 Empty / placeholder state

- No content yet (right after creation): view mode shows a placeholder block in place of `MarkdownView`.
  - Text: `"No content yet."` line 1 — `AionText.body`, color `textMuted`. Sub-line `"Tap to add page content in Markdown."` — `AionText.bodySm`, color `textMuted`.
  - Whole block is tappable (enters edit mode). Padding `EdgeInsets.symmetric(vertical: 24)`, left-aligned.
- In edit mode with empty buffer: textarea placeholder `"Write in Markdown…  # Heading, **bold**, - list, \`code\`"`, `codeEditor` style, color `textMuted`.

### 1.7 State summary — MarkdownEditor

| State | Trigger | Key visual |
|---|---|---|
| View (populated) | default, has content | `MarkdownView` + edit affordance |
| View (empty) | no content | placeholder block, tap-to-edit |
| Editing | tap edit / focus | textarea focused (ring), Save/Cancel |
| Saving | Save tapped | spinner in Save, Cancel disabled |
| Error | save failed | inline danger row + danger textarea ring |
| Split (wide) | `maxWidth > 640` | editor ∣ preview, live, Save/Cancel below |

## 2. MarkdownView

Read-only rendered Markdown. A `Column`, `crossAxisAlignment: start`, vertical rhythm via inter-block gaps below (do not use per-block top+bottom margins — one gap per adjacent pair). Base text color `textPrimary`; the whole view uses `AionText` styles `.copyWith(color:)`.

Default inter-block gap: `AionSpacing.sp12`. Exceptions noted per block.

### 2.1 Headings `h1`–`h6`

Mapped to existing type tokens, colored `textPrimary`:

| MD | Style | Extra |
|---|---|---|
| `#` h1 | `AionText.h1` (25/w800) | `AionSpacing.sp16` gap above (except first child) |
| `##` h2 | `AionText.h2` (22/w800) | `AionSpacing.sp16` gap above |
| `###` h3 | `AionText.dialogTitle` (18/w800) | `AionSpacing.sp12` gap above |
| `####` h4 | `AionText.body.copyWith(fontWeight: w800, fontSize: 16)` | |
| `#####` h5 | `AionText.cardTitle` (14/w600) | |
| `######` h6 | `AionText.caption` (mono, `textSecondary`, uppercase) | |

### 2.2 Paragraph with mixed inline emphasis

- Style `AionText.body`, color `textPrimary`, `height 1.5`, `textWidthBasis: parent`.
- Built as a single `RichText`/`Text.rich` of `TextSpan` runs:
  - **bold** → `fontWeight: w800`.
  - *italic* → `fontStyle: italic`.
  - ~~strikethrough~~ → `decoration: TextDecoration.lineThrough`, `decorationColor: textMuted`.
  - `inline code` → `codeInline` style (§2.10), background chip.
  - [link](…) → color `primary`, `decoration: underline`, `decorationColor: primary.withOpacity(0.4)`; `GestureDetector`/`TapGestureRecognizer` opens the target. Hover (pointer): color `primaryHover`.

### 2.3 Bullet list

- Each item: `Row`, `crossAxisAlignment: start`, `gap: 10`.
  - Marker: an `8×8`… actually a `5×5` filled dot (radius circular) offset with `Padding(top: 8)` to align to the first text line, color `textSecondary`.
  - Content: `Expanded`, paragraph rules (§2.2).
- Inter-item gap: `AionSpacing.sp8`. Left inset of the whole list: `EdgeInsets.only(left: 2)`.

### 2.4 Ordered list

- Marker: `"1."`, `"2."`… `AionText.body.copyWith(color: textSecondary, fontFeatures:[tabularFigures])`, right-aligned in a fixed `24`-wide leading box so multi-digit numbers stay aligned. `gap: 8` to content.
- Content + inter-item gap: as §2.3.

### 2.5 Nested list

- Rendered by recursion: a nested list is the `Expanded` content of its parent item, indented by an additional `EdgeInsets.only(left: 18)`.
- Bullet markers alternate by depth for legibility: depth 0 filled dot (`textSecondary`), depth 1 hollow ring (`1.5px textMuted`, `5×5`), depth ≥2 small dash (`6×1.5` `textMuted`). Ordered nesting keeps numeric markers at every level.

### 2.6 GFM task-list item (read-only)

- `Row`, `crossAxisAlignment: start`, `gap: 10`.
- Checkbox: `16×16`, radius `AionRadius.sm` (6)… use `4` here for a tighter box; `Padding(top: 3)` to align.
  - **Unchecked:** fill `surface`, 1.5px `borderStrong`, empty.
  - **Checked:** fill `primary`, no border, white `check` glyph **11px** centered.
- Label: paragraph rules; when checked, color steps to `textMuted` and gains `lineThrough` (`decorationColor: textMuted`).
- Non-interactive here (read-only view) — no hover/pressed. Cursor default.

### 2.7 Fenced code block (horizontally scrollable)

- Container: fill `surfaceHover`, 1px `border`, radius `AionRadius.md` (10), padding `EdgeInsets.all(14)`.
- Content: `SingleChildScrollView(scrollDirection: Axis.horizontal)` wrapping a `Text` of `codeBlock` style (§2.10), color `textPrimary`, no wrap (`softWrap: false`).
- Optional language tag: top-right, `AionText.caption` `textMuted`, if a fence info-string is present.
- Gap above/below: `AionSpacing.sp12`.

### 2.8 Blockquote

- `Row`, `crossAxisAlignment: stretch`.
  - Rule: `3`-wide bar, radius `2`, fill `primary.withOpacity(isDark ? 0.55 : 0.40)`, full height.
  - Content: `Padding(left: 14)`, paragraph rules but color `textSecondary`, `fontStyle: italic` on the base run (inline emphasis still applies over it).
- Optional whole-quote fill `primarySubtle.withOpacity(0.5)`, radius `AionRadius.md`, padding `EdgeInsets.symmetric(horizontal: 14, vertical: 10)` — use the filled variant inside the wide-preview pane; the bar-only variant in dense list contexts.

### 2.9 Horizontal rule & table

**Horizontal rule (`---`):** a `1px` `DecoratedBox` fill `border`, full width, `AionSpacing.sp16` gap above and below (overrides default gap).

**GFM table:**
- Outer: 1px `border`, radius `AionRadius.md` (10), `clipBehavior: antiAlias`, `IntrinsicColumnWidth` or a `Table` built from `Row`s in a horizontal `SingleChildScrollView` when wide.
- Header row: fill `surfaceHover`, cells `AionText.cardTitle` (14/w600) color `textPrimary`, padding `EdgeInsets.symmetric(horizontal: 12, vertical: 9)`, bottom 1px `border`.
- Body rows: fill `surface`, cells `AionText.bodySm` color `textSecondary`, same padding; 1px `border` between rows (last row none).
- Cell alignment honors the GFM `:---`, `:--:`, `---:` column markers.
- Gap above/below: `AionSpacing.sp12`.

### 2.10 Code styles (derived)

```dart
// inline code — chip behind the text
final codeInline = TextStyle(
  fontFamily: 'JetBrainsMono', fontSize: 13, fontWeight: FontWeight.w500,
  color: c.textPrimary, height: 1.5,
);
// chip decoration: background c.surfaceHover, radius 4, padding H4 V1 (via WidgetSpan or background paint)
// fenced code block
final codeBlock = TextStyle(
  fontFamily: 'JetBrainsMono', fontSize: 13, fontWeight: FontWeight.w400,
  color: c.textPrimary, height: 1.55,
);
```

Both themes identical in structure; only token resolution differs.

## 10. Responsive & theme notes

- **Breakpoint:** `MarkdownEditor` switches at `maxWidth > 640` to split view; the detail/create screens keep their column layout but widen padding (§3.2) on desktop/tablet.
- **Both themes** share every structural rule; only token resolution differs. Statements that call out `isDark` (alpha steps in §0.2, §6, §7) are the only branch points. No component here is theme-exclusive.
- **No Material:** every surface is a `DecoratedBox`/`Container`; every tap is a `GestureDetector`; every input is `AppTextField`. Spinners are `AppSpinner`, toasts `AppToast`, dialogs the existing deletion/confirmation overlay — none introduced here.
- **Accent discipline:** `typePage` is the pages-module accent (chips, page icons, sub-page glyphs, `+ Add`). `primary` remains the app's interactive accent for the Markdown editor's Save button, links, focus rings, and linked-ticket `+ Add`. `warning` is reserved for the needs-repair state only.
- **Translucent fills** always via `token.withOpacity(x)` with the theme's `fillAlpha` — never hardcoded ARGB.
