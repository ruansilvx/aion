# Spec Delta: Bug ticket type

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (44/51 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`. Read alongside
[proposal.md](../proposal.md) and [design.md](../design.md) — this file
only lists what changes, not full current-state context.

## ADDED

- **`TicketType.bug`** (`domain/enums/ticket_type.dart`) — ranked
  identically to `task` in `TicketTypeHierarchy._rank` (both return `2`).
  Parentable by `story` or directly by `epic`, may parent `chat`
  unconditionally, cannot parent or be parented by `task` (same-rank
  pair), participates in coding-execution with full parity to `task`.
- **`TicketTypeHierarchy.executableTypes`** — a new static const
  `[TicketType.task, TicketType.bug]`, and **`TicketTypeHierarchy.isExecutable`**
  — a new instance getter, `true` iff `this` is in `executableTypes`.
  Single source of truth for "this type's move to `inProgress` triggers
  coding-execution," replacing scattered `== TicketType.task` comparisons.
- **`TicketSeverity`** (`domain/enums/ticket_severity.dart`) — new enum:
  `critical | high | medium | low`. Meaningful only for `TicketType.bug`;
  distinct from `TicketPriority` (impact vs. scheduling urgency). No
  `none` member — absence is modeled by `Ticket.severity` being `null`.
- **`Ticket.severity`** (`TicketSeverity?`), **`Ticket.stepsToReproduce`**
  (`String?`), **`Ticket.expectedBehavior`** (`String?`),
  **`Ticket.actualBehavior`** (`String?`) — four new nullable fields,
  meaningful only for `TicketType.bug`, `null` until set. Added to
  `Ticket.copyWith` as `TicketFieldSetter`-typed params, same treatment
  as `complexity`.
- **`TicketsTable` columns** `severity`, `steps_to_reproduce`,
  `expected_behavior`, `actual_behavior` (all nullable `TEXT`) — Drift
  schema version 5 → 6, added via `addColumn` migration.
- **`TicketsCubit.createTicket`** gains four new optional params:
  `severity`, `stepsToReproduce`, `expectedBehavior`, `actualBehavior`,
  threaded into the constructed `Ticket`.
- **`CreateTicketScreen`** — new conditional field block (severity
  dropdown, steps-to-reproduce / expected-behavior / actual-behavior text
  fields), shown only when the type dropdown is set to `bug`. Exact
  layout is a Claude Design deliverable (see `design.md`).
- **Ticket detail screen "Bug details" section** — new, `bug`-only,
  showing/editing severity and the three text fields via the existing
  inline-edit pattern. Exact layout is a Claude Design deliverable.
- **`AionColors.typeBug`** — new required color token (both themes), for
  `TypeChip`/`LinkedTicketsSection`'s per-type accent color.
- **`app_en.arb` entries** for the type label, severity value labels, and
  the new create-form field labels.

## MODIFIED

- **`TicketType.task`'s dartdoc** — now also notes that `bug` occupies
  the same rank and is likewise unparentable by a `task`.
- **`TicketsCubit`** — every coding-execution call site that compared
  directly against `TicketType.task` now uses `.isExecutable`
  (`updateTicketStatus`, `changeTicketStatus`,
  `_interceptTaskExecutionTrigger`, `getTicketById`'s execution-state
  block); every call site fetching a Story's rank-2 children for
  design-review-gate or SDD-readiness purposes now queries
  `TicketTypeHierarchy.executableTypes` instead of a `task`-only literal
  (`_nextSddStage`, `_sddStageAdvanceCheck` — both the `proposed` and
  `designSync` branches — `_codingExecutionGateCheck`, `getTicketById`'s
  `needsDesignReview` computation, `advanceSddStage`'s stage-chat context
  generation). Net effect: a `bug` ticket triggers, queues, and gates
  coding-execution runs exactly as a `task` does, and counts as a
  Story's "unit of execution" for every readiness/gate check a Task
  already counted for.
- **`_storyNeedsDesignReview`'s dartdoc** — now describes its input as
  "each Task/Bug's title + description" instead of "each Task's."
- **Ticket detail screen's Linked Tickets/Backlinks visibility gate**
  (`ticket_metadata_section.dart`) — widened from `resource`-only to
  `resource` or `bug`, so a Bug can create a `relatesTo` link to a
  `release` ticket (or any other non-`page`/non-`resource` type) through
  the same generic picker `resource` already exposes. No change to the
  picker's own candidate filter.
- **`TypeChip`'s `ticketTypeLabel` and color switch**,
  **`linked_tickets_section.dart`'s color switch** — each gains an
  explicit `TicketType.bug` case.
- **`DriftTicketRepository._toEntity`, `createTicket`, `updateTicket`** —
  map the four new fields both directions.
- **`AppDatabase`** — `schemaVersion` 5 → 6; class dartdoc's version-
  history list gains a Version 6 entry.

## REMOVED

None.

## Known gaps this does not resolve

- No UI exists (before or after this change) for creating a `relatesTo`
  link from an `epic`/`story`/`task` ticket to a `release` — only `bug`
  gets a picker, by reusing `resource`'s existing gate. Generalizing
  relatesTo-linking to every type is explicitly out of scope (see
  `proposal.md`).
- `promoteSignalToEpic` is not generalized to also offer promotion into
  `bug`, despite `aion-arch/ideas/bug-ticket-type.md`'s superseding note
  that it should eventually. Left for whichever change implements
  Inbox's brain-dump purpose (`new-project-onboarding`).
