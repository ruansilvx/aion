# Tests

- [x] T6. In `aion/test/features/tickets/cubit/tickets_cubit_test.dart`,
      add the six cases from `design.md`'s "Test plan" section:
      direct-match refresh (via `updateTicket` firing `suggest`),
      story/child refresh (via `updateTicketStatus` on a child task),
      no-op when nothing is open, no-op when the open ticket is
      unrelated, no-op (query skipped entirely, `verifyNever` on
      `getTicketsByParent`) when the open ticket isn't a `story`, and the
      standalone `getTicketById` Loading-skip/no-skip pair. Reuse
      existing fixture/stub patterns already in this file (the
      `EmbeddingProvider`/model stub `ai-assisted-complexity-and-
      estimate-suggestions`'s own suggester tests already established) —
      no new test-only fixture infrastructure needed.

      Implemented as seven cases, one more than originally planned: the
      direct-match case is covered twice — once end-to-end through the
      real `_estimationSuggester` wiring (`createTicket`/`updateTicket`'s
      T3/T4 call sites, inside the existing "estimation-suggestion
      triggers" group, asserting no intervening `TicketsLoading` — the
      fully invisible case), and once through the raw
      `_refreshDetailIfOpenAndAffected` branching via
      `updateTicketStatus` directly (the `TicketsLoading`-flash case, per
      T5's note above) — since the two call sites have materially
      different Loading-skip behavior, each needed its own assertion
      rather than relying on one to imply the other. The two
      unrelated-open-ticket no-op cases were also split as designed:
      one where the query runs but finds no match (open ticket is a
      `story`, written ticket isn't among its children), one where the
      query never runs at all (open ticket isn't a `story`).
