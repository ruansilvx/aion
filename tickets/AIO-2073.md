# T40. Unit tests for the `TicketsCubit` modifications from T25

(embedding trigger fires on title/description change and only
then; git projector invoked with the correct event label per
trigger; both no-op cleanly when omitted) in the existing
`aion/test/features/tickets/cubit/tickets_cubit_test.dart`
(corrected path, same as T39), mocking `EmbeddingProvider` and
`TicketGitProjector`. **Found and fixed a real regression while
writing these**: T25's new unconditional `getTicketById` calls in
`createTicket`/`updateTicketStatus`/`trashTicket`/`trashTickets`
broke 5 pre-existing tests that didn't stub it (mocktail throws
`MissingStubError` on an unstubbed call) — added the missing
stubs to those 5 tests rather than leaving them broken. Full
suite: 42 tests, all passing.
**Full-suite regression check** (not a listed task, done after T40 to be
sure nothing else broke): ran `flutter test` across the entire app.
Found and fixed two more pre-existing tests broken by this change:
- `bundled_baseline_repository_test.dart`'s "returns the single bundled
version" hardcoded `['0.1.0']` — updated to expect both versions now
that `_bundledVersions` has two entries.
- `drift_ticket_repository_test.dart`'s migration test builds a
hand-crafted "v1 shape" by dropping columns `onCreate` (which always
builds at the *current* schema) added — it already dropped
`deleted_at` but never accounted for the new `sync_status` column,
causing a duplicate-column error on the simulated upgrade. Fixing it
surfaced a real ordering constraint: `sync_status` can't be dropped
before the test's `createTicket` call, since (unlike `deleted_at`)
`DriftTicketRepository.createTicket` now sets it explicitly — dropped
it immediately after the insert instead.
Final count: 252 tests, all passing.
