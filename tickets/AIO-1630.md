# Post-`/verify` fixes (2 WARNING findings + 3 self-disclosed gaps + 1 SUGGESTION)

A `/verify` pass (all tasks above marked `[x]` at the time) found 3
WARNING-level deviations from the approved design, confirmed the 2
gaps this change's own tasks.md had already self-disclosed
(T25/T30), and flagged one test-efficacy SUGGESTION. Fixed below,
each re-verified with its own test(s); full suite re-run afterward
(1419/1419 passing, `flutter analyze` clean).

- [x] T34. Dropdown rows were missing the leading mono "ticket key"
      segment design.md Component Spec §6.4 specifies for the message
      line (approved design gate) — `Notification`/`NotificationsTable`
      never captured `Ticket.ticketId` (the human-readable "AIO-42"-style
      key), only `ticketTitle`. Fixed: added `ticketKey` to the
      `Notification` entity, `NotificationsTable` (amended in place —
      schema v17 hadn't shipped yet, so no v18 bump was needed),
      `NotificationDao.insert`/`getMostRecentForTicket`, and
      `DriftNotificationRepository`'s mapping; `TicketsCubit
      ._recordNotification` now resolves it from `ticket?.ticketId`;
      `_NotificationDropdownRow`'s message `Text.rich` now prepends the
      key + `" · "` (via `AionText.key`/`textSecondary`) ahead of the
      message span, guarded on non-empty. Regenerated Drift codegen.
      Updated every DAO/repository/cubit/widget test call site
      (`notification_dao_test.dart`, `drift_notification_repository
      _test.dart`, `notification_dropdown_test.dart`,
      `tickets_cubit_test.dart`) to pass/assert `ticketKey`. Also fixed
      `notification.dart`'s stale dartdoc reference to a
      `notification_bell_trigger.dart` file that was never created (the
      bell trigger lives inline in `workspace_nav_shell.dart` — T23's
      own note already explained why, the entity's dartdoc just hadn't
      been updated to match).
- [x] T35. The compact (bottom-tab-bar) `_NotificationBellTrigger` never
      rendered its keyboard-focus ring — Component Spec §3.2 requires
      one for Focused/Menu-open, same as the wide variant, but the
      compact tile's `BoxDecoration` in `workspace_nav_shell.dart` never
      included `boxShadow: boxShadow` (only the wide/sidebar tile's
      decoration did). Fixed: added the missing `boxShadow: boxShadow`
      to the compact tile's decoration.
- [x] T36. `ticketDetailCodingExecutionPrSubLine` (added per T20) was
      dead — `TicketDetailLoaded.executionPrSubLine` is populated
      directly from the stored notification's `message`
      (`notificationExecutionPrOpened`), never via this second key, per
      design.md §7's own unresolved-at-/apply-time open question about
      the two-key duplication. Fixed: removed the unused key from
      `app_en.arb` and regenerated `lib/l10n/generated/*`.
- [x] T37. Closed the coverage gap T30 self-disclosed: added 4 new
      `_recordNotification call sites` integration tests in
      `tickets_cubit_test.dart` — `executionVerificationFailed` (gated
      retry confidence, `taskNoStory`), `executionFailed` (a
      `gitClient.createWorktree` throw — the actual hard-catch trigger;
      confirmed via code reading that a `ChatCubit.runChatTurn` agent
      hard-failure instead just `break`s the retry loop with no
      notification at all, so an `agentClient.run` throw — the original
      plan — would never have reached this branch),
      `stageAdvanceCompleted` and `stageAdvanceFailed` (both via
      `advanceSddStage(epic)`, mirroring the existing "advanceSddStage —
      backgrounded stage-chat turn" group's happy-path/hard-failure
      setups). All 5 call sites now have dedicated coverage.
- [x] T38. Closed the keyboard-navigation gap T25 self-disclosed
      (design.md Component Spec §9: "arrow keys move row focus, Enter
      opens the ticket, Escape closes"). Fixed:
      `NotificationDropdownPanel` now owns one `FocusNode` per row,
      wraps its content in `CallbackShortcuts` mapping ArrowDown/ArrowUp
      to explicit row-focus movement (clamped, not wrapping) and Escape
      to `onDismiss`; each row's existing `FocusableActionDetector`
      accepts the panel-owned `FocusNode` so Enter's already-wired
      `ActivateIntent` handler (row tap) fires on the focused row. Added
      3 new widget tests exercising ArrowDown/ArrowUp/Enter/Escape via
      `tester.sendKeyEvent`.
- [x] T39. `github_cli_client_test.dart`'s two tests reimplemented
      `openPullRequest`'s URL/number-parsing formula inline rather than
      exercising the real method (`GitHubCliClient` had no injectable
      process runner, unlike `GitRepositoryClient`, whose local `git`
      subprocess calls are safe to run for real against a temp repo —
      `gh pr create` has a real side effect, creating a live PR, so it
      can't be tested that way). Fixed: added a `ProcessRunner` typedef
      + optional constructor param to `GitHubCliClient` (defaults to
      `Process.run`, backward-compatible with its one production call
      site in `app_router.dart`); rewrote the test file to inject a fake
      runner and invoke `openPullRequest` for real, asserting the exact
      `gh` args, the URL/number parse, the multi-line-stdout case, and
      the `ProcessException`-on-failure path.
