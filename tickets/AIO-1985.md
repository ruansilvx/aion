# Show Last Updated Timestamp On Each Ticket

# Proposal: Show a last-updated timestamp on each ticket's detail screen

## What

Add a "Updated {relative time}" line to `TicketDetailScreen` (via
`TicketMetadataSection`), directly below the existing "Created {date}"
line. The relative-time label is granular (minutes/hours, e.g. "Updated
2m ago", "Updated 3h ago") and **actively ticks** while the screen stays
open — it advances on its own once a minute, without requiring a write
to the ticket or a manual reload.

## Why

`Ticket.updatedAt` already exists, is already maintained precisely by
every genuine user edit (`TicketRepository.updateTicket`/
`.updateTicketStatus`/`.updateTicketParent`/`.updateTicketSddStage` each
stamp a fresh `updatedAt`; derived/background writes like
`updateEmbedding`/`updateSyncStatus`/`updateRollup`/
`applyEstimationSuggestion` deliberately do not — see
`aion-arch/specs/tickets.md`), and is already sortable via
`TicketSortField.updatedAt` — but it is never surfaced anywhere in the
UI. A user sorting the ticket list by "Last updated" has no way to see
*why* a given ticket ranks where it does once they open it.

See `aion-arch/ideas/show-last-updated-timestamp-on-each-ticket.md` for
the full exploration session this proposal is based on.

## Scope

- **In scope**: `TicketDetailScreen` only (via `TicketMetadataSection`,
  shared with `ChatTranscriptPane`'s collapsing header for `chat`-type
  tickets — this line renders unconditionally there too, same as the
  existing "Created" line it sits beside). A new Cubit-owned periodic
  ticker so the label advances live while the screen is open. Minor
  test-coverage addition for `formatRelativeTime` (already shipped for
  `InboxHistoryItem`, but never unit-tested — this change makes it a
  load-bearing, always-visible label instead of an inbox-only one, so
  it's brought up to the same coverage bar as its sibling
  `formatTrashedAge`).
- **Out of scope**: list/board card display (explicitly rejected during
  brainstorming — those surfaces are already visually crowded).
  Showing `createdAt` alongside it is not part of this change (it
  already renders on its own line just above). Any settings/config for
  the tick interval.

## Design decisions

1. **Reuse the existing `formatRelativeTime` helper**
   (`lib/core/utils/relative_time_format.dart`), not a new formatter.
   The original brainstorm session assumed a new granular formatter was
   needed, but `formatRelativeTime` — added for `InboxHistoryItem`
   (`new-project-onboarding-inbox`) — already produces exactly the
   target shape ("just now", "2m ago", "3h ago", "2d ago", "3w ago",
   "2mo ago"). Building a second one would duplicate it for no reason.
2. **The periodic refresh lives in `TicketsCubit`, not
   `TicketDetailScreen`'s widget state** — per this project's existing
   convention that debounce/timer logic belongs in the Cubit layer.
   `TicketsCubit` gains a `Timer`-backed broadcast stream
   (`detailTick`) mirroring the existing `codebaseAnalysisStatus`
   precedent (a transient, non-`TicketsState` stream a single widget
   subscribes to), started/stopped by `TicketDetailScreen`'s
   `initState`/`dispose` — see `design.md` for the full mechanism and
   why re-emitting `TicketDetailLoaded` itself was rejected.
3. **Always show the line**, even for an unedited ticket where
   `updatedAt == createdAt` (both are stamped identically at creation).
   No conditional-hide logic — simplest version, consistent with how
   "Created" already renders unconditionally beside it.

## Non-goals

- No settings/config surface for the tick interval or for
  hiding/showing this line.
- No change to `TicketBoardCard`/`TicketListTile` (explicitly deferred
  during brainstorming).
- No retroactive backfill or data migration — `updatedAt` already
  exists and is already correctly maintained.
