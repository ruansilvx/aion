# Spec Delta: configurable-ticket-workflow

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (51/57 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **`WorkflowStatusRole`** (`domain/enums/workflow_status_role.dart`) —
  `executionTrigger | reviewReady | done`. The generalized replacement
  for `TicketsCubit`'s literal `TicketStatus.inProgress`/`.inReview`/
  `.done` comparisons. Exactly one shared-base `WorkflowStatus` must hold
  each value at all times — enforced by `WorkflowConfigCubit`, never the
  repository.
- **`WorkflowStatus`** (`domain/entities/workflow_status.dart`) — a
  project-defined ticket status: `id`, `name` (written to `Ticket.status`),
  `displayName`, `ticketType` (`TicketType?` — `null` = shared base,
  applies to every ticket type; non-`null` = a per-type extension), a
  `sortOrder`, and an optional `role` (`WorkflowStatusRole?`, restricted
  to shared-base entries only — a per-type extension can never hold a
  role).
- **`defaultWorkflowStatuses`** (`domain/entities/default_workflow_statuses.dart`)
  — the seeded baseline preset reproducing today's exact prior hardcoded
  behavior: `backlog`/`todo`/`inProgress`[`executionTrigger`]/
  `inReview`[`reviewReady`]/`done`[`done`]/`cancelled`, all shared-base,
  sorted in that order.
- **`WorkflowStatusRepository`** (`domain/repositories/workflow_status_repository.dart`)
  — `getAll()`, `create`/`update`/`delete`, `reorder(List<String>
  idsInSortOrder)`, `seedDefaultsIfEmpty()`. Dumb persistence only — no
  validation.
- **`SddStageConfigRepository`** (`domain/repositories/sdd_stage_config_repository.dart`)
  — `getDesignStagesEnabled()`/`setDesignStagesEnabled(bool)` (default
  `true`) and `getDisplayNameOverride(SddStage)`/
  `setDisplayNameOverride(SddStage, String?)`. Mirrors
  `AutomationSettingsRepository`'s shared-preferences-backed, fixed-enum-
  keyed shape.
- **`WorkflowConfigCubit`** (`presentation/cubit/workflow_config_cubit.dart`)
  — owns `WorkflowStatus` CRUD/reorder and the two `SddStageConfigRepository`
  settings. Enforces: status-name uniqueness within scope; every
  `WorkflowStatusRole` always resolves to exactly one shared-base status
  (rejects a create/update/delete that would leave a role unfilled);
  rejects deleting a status any live ticket currently occupies (no
  migration story yet — see proposal.md's Non-goals).
- **`WorkflowConfigState`** (`presentation/cubit/workflow_config_state.dart`)
  — `WorkflowConfigInitial` / `WorkflowConfigLoaded` (`statuses`,
  `designStagesEnabled`, `stageDisplayNameOverrides`) /
  `WorkflowConfigError` (carries the prior `WorkflowConfigLoaded` so the
  screen never loses its list on a rejected edit).
- **`WorkflowStatusesTable`** (`data/models/workflow_status_table.dart`,
  drift) — `id`, `name`, `display_name`, `ticket_type` (nullable), `sort_order`,
  `role` (nullable). No FK constraints, matching every other table in
  this schema. Row type `WorkflowStatusData`.
- **`WorkflowStatusDao`** (`data/daos/workflow_status_dao.dart`) — CRUD +
  `seedDefaultsIfEmpty` (idempotent: a no-op once the table is non-empty).
- **`DriftWorkflowStatusRepository`** (`data/repositories/drift_workflow_status_repository.dart`)
  — implements `WorkflowStatusRepository` via `WorkflowStatusDao`.
- **`SharedPrefsSddStageConfigRepository`** (`data/repositories/shared_prefs_sdd_stage_config_repository.dart`)
  — implements `SddStageConfigRepository`, mirroring
  `SharedPrefsAutomationSettingsRepository`'s key-naming pattern.
- **`WorkflowStatusSettingsScreen`** (`presentation/screens/workflow_status_settings_screen.dart`)
  — new Settings surface, reached from `WorkspaceNavShell`'s
  secondary-actions popover alongside the existing provider
  `SettingsScreen`. Two sections: Ticket Statuses (add/rename/reorder/
  delete base statuses and per-type extensions; reassign the three
  required roles) and SDD Stages (`designStagesEnabled` toggle + five
  display-name override fields, one per `SddStage` value).
- **Drift schema version 15** — adds `WorkflowStatusesTable`; `onCreate`
  and the `from < 15` `onUpgrade` branch both call
  `WorkflowStatusDao.seedDefaultsIfEmpty()`, so every pre-existing
  project's database backfills `defaultWorkflowStatuses` exactly once.

## MODIFIED

- **`Ticket.status`** (`domain/entities/ticket.dart`) — type changes from
  `TicketStatus` to `String`, now holding a project-defined status name
  resolved against `WorkflowStatusRepository`/`WorkflowConfigCubit`
  rather than a fixed enum value. No `tickets` table schema change — the
  `status` column was already a raw `TextColumn`
  (`ticket_model.dart:30`).
- **`TicketRepository.updateTicketStatus`/`DriftTicketRepository
  .updateTicketStatus`** — signature's `TicketStatus status` parameter
  becomes `String status`, mirroring `updateTicketSddStage`'s existing
  `SddStage`-typed sibling. The enum-deserialization round-trip at
  `drift_ticket_repository.dart:533` (`TicketStatus.values.firstWhere(...)`)
  is removed — the stored string passes straight through.
- **`TicketsCubit._interceptBlockedDependencyTrigger`/
  `_interceptTaskExecutionTrigger`/`updateTicketStatus`/
  `updateStatusForTickets`** — every `status == TicketStatus.inProgress`
  comparison becomes a role lookup: `_roleOf(status) ==
  WorkflowStatusRole.executionTrigger`, resolved against a new
  constructor-injected `WorkflowStatusRepository`-backed in-memory cache
  (`_workflowStatuses`).
- **`TicketsCubit._isTicketBlocked`** (both call sites) — `byId[blockerId]
  ?.status != TicketStatus.done` becomes `_roleOf(byId[blockerId]?.status)
  != WorkflowStatusRole.done`.
- **`TicketsCubit._runCodingExecution`**'s PR-confirmed auto-transition —
  `updateTicketStatus(task.id, TicketStatus.inReview)` becomes: resolve
  the current `reviewReady`-role status's `name`, write that string.
- **`TicketsCubit._sddStageAdvanceCheck`**'s `proposed`/`designSync`
  branches — `c.status == TicketStatus.done`/`t.status ==
  TicketStatus.done` become `_roleOf(...) == WorkflowStatusRole.done`.
- **`TicketsCubit._storyNeedsDesignReview`** — gains a new leading
  short-circuit: when the project's `SddStageConfigRepository
  .getDesignStagesEnabled()` is `false`, returns `false` unconditionally
  (no Story ever needs design review) before its existing per-Story
  child-signal heuristic runs. That heuristic is otherwise completely
  unchanged when the toggle is `true` (the default).
- **`TicketsCubit`'s stage-display-name resolution** — now checks
  `SddStageConfigRepository.getDisplayNameOverride(stage)` first, falling
  back to today's hardcoded literal label when no override is set.
- **Every ticket-creation call site's default status literal**
  (`status: TicketStatus.backlog`, ~9 occurrences across
  `tickets_cubit.dart`) — becomes the shared base set's lowest-`sortOrder`
  status's `name`, resolved from `_workflowStatuses` rather than a
  compile-time enum value.
- **`TicketSortField.status`'s comparator** (`ticket_sort_comparator.dart`)
  — sorts by each ticket's resolved `WorkflowStatus.sortOrder` instead of
  `TicketStatus.values`' declaration order.
- **`tickets_board_view.dart`, `ticket_filter_popover.dart`,
  `ticket_columns_popover.dart`, `ticket_metadata_section.dart`** — every
  `TicketStatus.values` iteration is replaced by reading
  `WorkflowConfigCubit`'s current `statuses` (filtered/merged by the
  relevant `ticketType`, sorted by `sortOrder`).
- **`shared_prefs_ticket_list_filter_repository.dart`,
  `shared_prefs_ticket_board_column_visibility_repository.dart`** —
  the `TicketStatus.values.where((v) => v.name == name)` validation
  round-trip on read now validates against the live
  `WorkflowConfigCubit`-resolved status list instead of the (now-removed)
  enum's `.values`.
- **`ticket_markdown_serializer.dart`/`ticket_markdown_template.dart`** —
  the `for (final s in TicketStatus.values)` loop and any enum-typed
  status parameter become `String`/`WorkflowStatus`-typed; the actual
  markdown output (status name substitution) is unaffected.
- **Drift schema** — version 14 → 15. See ADDED above.

## REMOVED

- **`TicketStatus`** (`domain/enums/ticket_status.dart`) — the fixed
  6-value enum is deleted entirely, replaced by `WorkflowStatus`/
  `defaultWorkflowStatuses` (project-defined data) per ADDED above.

## Non-goals carried into this spec (see proposal.md)

- No skill attachment of any kind (Phase 2).
- No new computed-confidence signal.
- No pluggable gate *types* (Phase 3) — only which configured status/
  stage occupies an *existing* role/toggle is configurable.
- No `SddStage` reordering, removal, or brand-new stages — narrowed from
  the idea file's looser "reorder/relabel/skip" to toggle + relabel only,
  per this proposal's flagged reasoning.
- No per-type `WorkflowStatusRole` assignment — roles live on the shared
  base set only.
- No migration UI for renaming/removing a status live tickets currently
  occupy — `WorkflowConfigCubit` rejects that edit outright in Phase 1
  rather than attempting a migration.
