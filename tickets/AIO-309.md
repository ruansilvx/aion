# 3. `ActiveProjectState` / `ActiveProjectCubit` / `ActiveProjectProvider`

- [x] 3.1 Modify
      `aion/lib/features/projects/presentation/cubit/active_project_state.dart` —
      `ActiveProjectOpen` gains `bool offerBaselineUpgrade` (default
      `false`), independent of `offerCodebaseAnalysis`; update `props` and
      the class dartdoc (document both flags clearly as independent).
- [x] 3.2 Modify `aion/lib/core/contracts/active_project_provider.dart` —
      add `bool get offerBaselineUpgrade`, `void
      consumeBaselineUpgradeOffer()`, and `Future<void>
      acceptBaselineUpgrade()` to the interface, documented per
      design.md's contract section (mirror the existing
      `offerCodebaseAnalysis`/`consumeCodebaseAnalysisOffer` doc style).
- [x] 3.3 Modify
      `aion/lib/features/projects/presentation/cubit/active_project_cubit.dart` —
      constructor gains `BaselineRepository` and `BaselineTailoringService`
      parameters; `switchTo` computes `offerBaselineUpgrade` by comparing
      `project.baselineVersion` against
      `_baselineRepository.getAvailableBaselineVersions().last` and emits
      it; new `consumeBaselineUpgradeOffer()` (preserves
      `offerCodebaseAnalysis` untouched) and `acceptBaselineUpgrade()` per
      design.md's exact implementation (registry update, conditional
      manifest rewrite + tailoring on desktop only, re-emit with the
      bumped project and the flag cleared). `_withLastOpened` (or a new
      `_withBaselineVersion` helper) updated/added to construct the
      bumped `Project` copy. Full dartdocs on every new/changed public
      member.
- [x] 3.4 Extend
      `test/features/projects/cubit/active_project_cubit_test.dart`
      (`bloc_test` + mocktail, mocking `BaselineRepository`/
      `BaselineTailoringService`) — new cases: `switchTo` emits
      `offerBaselineUpgrade: true` when the project's pinned version
      isn't the latest bundled one, `false` when it already is;
      `consumeBaselineUpgradeOffer` clears only that flag, leaving
      `offerCodebaseAnalysis` as it was; `acceptBaselineUpgrade` updates
      the registry, writes the manifest and calls
      `tailorNewlyIntroducedAssets` when `rootPath` is set, skips both
      when `rootPath` is `null`, and no-ops entirely when already on the
      latest version.
