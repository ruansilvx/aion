# Spec Delta: workflow-skill-attachments

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (66/67 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **`SkillAttachmentKind`** (`domain/enums/skill_attachment_kind.dart`) —
  `aionNativeTemplate | delegatedSkill`. Which of the two Phase 2
  attachment mechanisms a `SkillAttachment` uses.
- **`SkillAttachment`** (`domain/entities/skill_attachment.dart`) — `id`,
  `workflowStatusId` (`String?`) / `sddStage` (`SddStage?`) — exactly one
  non-`null`, identifying what this attaches to — `kind`,
  `templateId`/`skillName` (`String?` each, exactly one non-`null`,
  matching `kind`), and `confidence` (`AutomationConfidence`). Both
  either/or invariants are enforced by `WorkflowConfigCubit`, never the
  repository or the entity.
- **`WorkflowPromptTemplate`** (`domain/entities/workflow_prompt_template.dart`)
  — `id`, `name` (unique project-wide), `body` (plain text with
  `{{variable}}` placeholders).
- **`renderWorkflowPromptTemplate`** (`domain/utils/render_workflow_prompt_template.dart`)
  — pure function substituting `{{ticket.title}}`/`.description`/`.type`/
  `.status`/`.priority` placeholders against a `Ticket`; an unrecognized
  placeholder passes through as literal text.
- **`WorkflowSkillAttachmentRepository`** (`domain/repositories/workflow_skill_attachment_repository.dart`)
  — `getAll()`, `create`/`update`/`delete`, `onChanged` (`Stream<void>`).
  Dumb persistence only — no validation.
- **`WorkflowPromptTemplateRepository`** (`domain/repositories/workflow_prompt_template_repository.dart`)
  — `getAll()`, `create`/`update`/`delete`. Dumb persistence only.
- **`WorkflowSkillAttachmentsTable`** (`data/models/workflow_skill_attachment_table.dart`,
  drift) — `id`, `workflow_status_id` (nullable), `sdd_stage` (nullable),
  `kind`, `template_id` (nullable), `skill_name` (nullable),
  `confidence`. No FK constraints. Row type `WorkflowSkillAttachmentData`.
- **`WorkflowPromptTemplatesTable`** (`data/models/workflow_prompt_template_table.dart`,
  drift) — `id`, `name`, `body`. Row type `WorkflowPromptTemplateData`.
- **`WorkflowSkillAttachmentDao`/`WorkflowPromptTemplateDao`**
  (`data/daos/*.dart`) — plain CRUD, no seeding logic.
- **`DriftWorkflowSkillAttachmentRepository`/`DriftWorkflowPromptTemplateRepository`**
  (`data/repositories/*.dart`) — implement the two domain repository
  interfaces via their DAO.
- **Drift schema version 16** — adds `WorkflowSkillAttachmentsTable` and
  `WorkflowPromptTemplatesTable`; both start empty (no seeded defaults —
  there is no pre-configuration attachment behavior to reproduce).
- **`WorkflowConfigCubit` attachment/template methods** —
  `createAttachment`/`updateAttachment`/`deleteAttachment` (rejects a
  create/update that would leave a target — a `WorkflowStatus` or
  `SddStage` — holding more than one attachment) and
  `createTemplate`/`updateTemplate` (rejects a project-wide name
  collision) /`deleteTemplate` (rejects while a live `SkillAttachment`
  still references it).
- **`WorkflowConfigState.WorkflowConfigLoaded`** gains `attachments`
  (`List<SkillAttachment>`) and `templates` (`List<WorkflowPromptTemplate>`)
  fields.
- **`TicketsCubit` attachment firing** — `_fireSkillAttachment`
  (generalizes `_createStageChat`/`_runStageChatTurn`'s spawn-chat-then-run
  shape to any `SkillAttachment`: `aionNativeTemplate` runs text-only via
  `renderWorkflowPromptTemplate`'s output; `delegatedSkill` runs
  tool-enabled with `workingDirectory` set to the project checkout,
  prompt `/<skillName>`), `_resolveAndFireAttachment` (confidence-gates
  the fire: `auto` fires unawaited immediately, `gated` populates a new
  pending-attachment map surfaced via `TicketDetailLoaded
  .pendingSkillAttachment`, `manual` no-ops), `confirmPendingSkillAttachment`/
  `rejectPendingSkillAttachment` (resolve/clear a `gated` pending
  attachment), `runAttachedSkillManually` (always-available trigger for
  a `manual`-confidence attachment).
- **`TicketDetailLoaded.pendingSkillAttachment`** (`SkillAttachment?`) —
  new field, `null` unless a `gated` attachment is currently awaiting
  confirmation for the loaded ticket.
- **`_AttachmentForm`/`_AttachmentBadge`** — new inline components on
  `WorkflowStatusSettingsScreen`'s existing `StatusRow` (any scope,
  including per-type extensions) and `SddStageRenameRow`, editing a
  target's attachment (kind, name, confidence).
- **`WorkflowPromptTemplatesScreen`** (`presentation/screens/workflow_prompt_templates_screen.dart`,
  route `/workspace/settings/workflow/templates`) — list + create/edit/
  delete for `WorkflowPromptTemplate`s.
- **`_PendingSkillAttachmentBanner`/`_RunAttachedSkillButton`** — new
  `TicketDetailScreen` widgets for the `gated` confirmation and `manual`
  trigger paths respectively.

## MODIFIED

- **`TicketsCubit.updateTicketStatus`/`updateStatusForTickets`** — after
  a successful status write, additionally resolve the new status's id
  and look up a configured `SkillAttachment` via `_attachmentForStatus`;
  if found, call `_resolveAndFireAttachment`. Symmetric to, and
  independent of, the existing `executionTrigger`-role check.
- **`TicketsCubit._createStageChat`/`_runStageChatTurn`** — gain a
  leading check: if the target `SddStage` has a configured
  `SkillAttachment` (`_attachmentForStage`), its rendered prompt (via
  `_fireSkillAttachment`'s prompt-construction logic) replaces
  `_assembleStageContext(parent, stage)`'s hardcoded prompt, and firing
  routes through `_resolveAndFireAttachment` (confidence-gated) instead
  of the unconditional `unawaited` call `advanceSddStage` makes today. A
  stage with **no** configured attachment is byte-for-byte unaffected —
  same hardcoded prompt, same unconditional fire.
- **Drift schema** — version 15 → 16. See ADDED above.
- **`app_router.dart` provider tree** — gains
  `WorkflowSkillAttachmentRepository`/`WorkflowPromptTemplateRepository`
  providers; `WorkflowConfigCubit` and `TicketsCubit` constructors each
  gain the two corresponding optional parameters.

## Non-goals carried into this spec (see proposal.md)

- No multiple attachments per status/stage — at most one.
- No template conditionals/logic — plain `{{variable}}` substitution
  only.
- No new computed-confidence signal, no new `AutomationContext` value,
  no `AutomationSettingsRepository` change — attachment confidence lives
  on the attachment record itself.
- No app-defined tool (`AgentRequest.tools`) exposure to attachment
  runs.
- No pluggable gate *types* (Phase 3) — this only adds a new *effect*
  (run a skill), gated by the existing closed `auto/gated/manual` enum.
- No verification of delegated-skill invocation for any `AgentProvider`
  other than the Claude Agent SDK.
- No migration/backfill concerns — purely additive data.
