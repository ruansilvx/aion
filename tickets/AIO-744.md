# Spec Delta: dependency-caching-and-ancestor-sibling-conflict

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md` "Coding execution" section's Dependency caching (Node.js) and Hybrid scheduling subsections — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification (e.g. bare `_foo` vs `TicketsCubit._foo`), line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. `_nextEligibleForHybrid`'s ancestor-conflict logic is confirmed present and matches this delta's own description closely.

## ADDED

- **`DependencyCacheService`** (`lib/core/build/dependency_cache_service.dart`)
  — `seed(String cacheDir, String targetDir)` (copies a cache into a
  fresh worktree's dependency directory, no-op if the cache doesn't
  exist yet), `writeBack(String sourceDir, String cacheDir)` (replaces
  the cache with the worktree's current, post-install state — delete
  then copy), `cacheDirFor(String projectStorageKey, String
  dependencyDirName)` (resolves a per-project cache path under
  `Directory.systemTemp`, co-located with coding-execution worktrees).
  Copy-based, not hardlink-based — `dart:io` has no native hardlink
  API.
- **`_runCodingExecution`'s Node.js dependency step** — before the
  implement turn, when `ProjectStackDetector().detect(rootPath)
  ?.language == 'Node.js'`: seeds the worktree's `node_modules` from
  the project's cache directory, then mechanically runs `npm install`
  via `Process.run` (a new, deliberate step — previously left entirely
  to the model's own first action, mirroring the verify gate's existing
  `flutter analyze` mechanical-invocation precedent). On a successful
  install, writes the worktree's `node_modules` back to the cache. A
  failed install is not treated as fatal to the run — the model's own
  implement turn can still attempt its own fix, starting from whatever
  partial state the failed install left.
- **`TicketsCubit._ancestorIds(String ticketId)`** — walks a ticket's
  `parentId` chain via `_repository.getTicketById` until reaching a
  ticket with no parent, returning every ancestor id encountered.
  Shared by `_nextEligibleForHybrid` and the new `topmostAncestorIds`
  batch method, so both use one identical chain-walking definition.
- **`TicketsCubit.topmostAncestorIds(List<String> ticketIds)`** —
  batch method returning each ticket's topmost ancestor id (an Epic,
  for a well-formed hierarchy; the ticket's own id if it has no
  parent). Feeds `TicketsLoaded.topmostAncestorId` below.
- **`TicketsLoaded.topmostAncestorId`** (`Map<String, String>`, default
  `{}`) — precomputed cluster keys for every currently-loaded ticket,
  recomputed alongside `_refreshInFlightBoardState()`'s existing
  pattern, but **only while `ExecutionSchedulingMode.hybrid` is
  active** — the only mode `clusterSiblingsAdjacently`/
  `_nextEligibleForHybrid` are ever reached under, so Strict
  FIFO/Parallel sessions pay zero extra ancestor-walk cost.

## MODIFIED

- **`TicketsCubit._nextEligibleForHybrid`'s conflict-membership test**
  — was: direct `ticket.parentId == inFlightTicket.parentId` equality.
  Now: shares any ancestor id (via `_ancestorIds`, each candidate's own
  id included in its comparison set so the pre-existing direct-sibling
  case remains covered as a subset of the broader test). A queued Task
  under a different Story of the same Epic as an in-flight Task is now
  correctly treated as conflicting; previously it was not.
- **`clusterSiblingsAdjacently`'s signature and grouping key**
  (`lib/features/tickets/domain/utils/sibling_cluster.dart`) — was:
  `List<Ticket> clusterSiblingsAdjacently(List<Ticket> tickets)`,
  grouping by direct `ticket.parentId` equality. Now: `List<Ticket>
  clusterSiblingsAdjacently(List<Ticket> tickets, Map<String, String>
  topmostAncestorId)`, grouping by shared topmost-ancestor id. Still a
  pure, synchronous function with no I/O of its own — the caller
  (`BoardColumn`) supplies the precomputed map. Visual output for
  already-direct siblings is unchanged; two Tasks under different
  Stories of the same Epic now cluster adjacently too, matching the
  scheduler's own generalized conflict signal.
- **`BoardColumn`'s call site**
  (`lib/features/tickets/presentation/screens/tickets_board_view.dart:326`)
  — now passes `ticketsLoaded.topmostAncestorId` as
  `clusterSiblingsAdjacently`'s second argument. Still called only
  under `ExecutionSchedulingMode.hybrid`, unchanged from today.

## Out of scope (explicitly not covered by this delta)

- Dependency caching for any language other than Node.js.
- Hardlink/junction-based cache seeding.
- Cache invalidation logic beyond `npm install`'s own reconciliation of
  a seeded `node_modules` against the worktree's actual `package.json`.
- Cache size limits/eviction.
- Ancestor generalization beyond the existing Epic→Story→Task/Bug
  hierarchy depth, or any change to the hard `blocks`/`blockedBy` gate.
