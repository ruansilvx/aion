# Design: sdd-ticket-execution

Read alongside [proposal.md](proposal.md) for the why and the re-scoping
rationale. This file covers the technical shape only.

## Domain layer

### `TicketComplexity` (new — `domain/enums/ticket_complexity.dart`)

```dart
/// A rough size estimate for a [Ticket](../entities/ticket.dart), set
/// manually by the user (no automated estimation yet). `null` means
/// unset — omitted from display, mirroring [TicketPriority.none]'s
/// "hidden rather than shown empty" convention, but via nullability
/// instead of a fourth enum value since unlike priority there is no
/// meaningful "no complexity" ticket state, only "not sized yet."
enum TicketComplexity {
  /// A small, quick unit of work.
  small,

  /// A moderate unit of work.
  medium,

  /// A large unit of work, a candidate for further breakdown.
  large,
}
```

### `SddStage` (new — `domain/enums/sdd_stage.dart`)

```dart
/// An [epic] or [story] Ticket's progress through the SDD cycle
/// (explore → propose → verify → archive), mirroring the
/// `aion-arch/.claude/skills/` stage names. `null` on [Ticket.sddStage]
/// means the cycle hasn't started. Meaningful only for
/// [TicketType.epic]/[TicketType.story] — [TicketsCubit.advanceSddStage]
/// rejects every other type. Task-level execution has no stage of its
/// own; a Story's `verifying` transition is gated on its child Tasks'
/// [TicketStatus.done], not a distinct Task-level stage value.
enum SddStage {
  /// The Exploration-stage chat is active or has completed.
  exploring,

  /// The Propose-stage chat produced children (Stories for an epic,
  /// Tasks for a story) and is awaiting their completion.
  proposed,

  /// The Verification-stage chat is active or has completed.
  verifying,

  /// The Archival-stage chat has completed; the cycle is closed.
  archived,
}
```

### `AutomationConfidence` (new — `lib/core/automation/automation_confidence.dart`)

Lives under `core/`, not a feature, since `project.md` §5 describes it as
cross-cutting infrastructure shared by every future automated-decision
point — same reasoning as `AgentModelClient` living in
`core/contracts/` rather than under `features/providers/`.

```dart
/// The shared three-state confidence level for an automated decision
/// point, per `project.md` §5's "Shared automation-confidence pattern."
/// This change ships its first real instance and consumer
/// (SDD-stage-triggering, see `TicketsCubit.advanceSddStage`) — later
/// automated points (a budget gate, a batch-flush gate) get their own
/// [AutomationConfidence] instance via [AutomationSettingsRepository]
/// once they're built, not a shared single value.
enum AutomationConfidence {
  /// Applies the automated decision silently, no user interaction.
  auto,

  /// Surfaces the decision and waits for explicit confirmation before
  /// applying it.
  gated,

  /// Never surfaces proactively; the user must initiate the action
  /// themselves via an always-available control.
  manual,
}
```

### `CommentAuthorType.system` (modified — `domain/enums/comment_author_type.dart`)

New third value, additive:

```dart
enum CommentAuthorType {
  human,
  ai,

  /// Authored by Aion itself, not a human or a model — the
  /// auto-assembled context message a spawned SDD-stage chat starts
  /// with (see `TicketsCubit.advanceSddStage`). Never user- or
  /// model-generated.
  system,
}
```

`CommentTile` (`presentation/screens/ticket_detail_screen.dart`) currently
branches only on `isAi = comment.authorType == CommentAuthorType.ai`,
treating everything else as human. It gains a second check,
`isSystem = comment.authorType == CommentAuthorType.system`, rendering a
muted/neutral style (no avatar initial, no "via `<model>`" line) instead
of falling into the human branch.

### `Ticket` entity (modified — `domain/entities/ticket.dart`)

Two new nullable fields, following the existing `estimate`/`timeSpent`
`TicketFieldSetter` pattern exactly (so `copyWith` can distinguish "leave
unchanged" from "explicitly clear"):

```dart
/// Rough size estimate, user-set. `null` until sized.
final TicketComplexity? complexity;

/// This ticket's SDD-cycle progress. `null` until the cycle starts.
/// Meaningful only for [TicketType.epic]/[TicketType.story] — see
/// [SddStage]. Written only via [TicketsCubit.advanceSddStage], never
/// through the generic [copyWith]-based [TicketRepository.updateTicket]
/// path other fields use, so its precondition can't be bypassed by a
/// plain edit.
final SddStage? sddStage;
```

`copyWith` gains a `TicketFieldSetter<TicketComplexity?>? complexity`
parameter (mirroring `estimate`/`timeSpent`) but deliberately **no**
`sddStage` parameter — every write to that field goes through
`TicketsCubit.advanceSddStage` → `TicketRepository.updateTicketSddStage`,
never through `copyWith`/`updateTicket`, so there is no way to set it
without the precondition check running.

## Data layer

### `TicketsTable` (modified — `data/models/ticket_model.dart`)

Two new nullable `TextColumn`s, storing each enum's `.name`:

```dart
/// `TicketComplexity.name`, nullable.
TextColumn get complexity => text().nullable()();

/// `SddStage.name`, nullable. Written only via
/// `TicketDao.updateSddStage` — see [TicketRepository.updateTicketSddStage].
TextColumn get sddStage => text().named('sdd_stage').nullable()();
```

### `AppDatabase` migration (modified — `core/database/app_database.dart`)

`schemaVersion` becomes `5`. `onUpgrade` gains:

```dart
if (from < 5) {
  await m.addColumn(ticketsTable, ticketsTable.complexity);
  await m.addColumn(ticketsTable, ticketsTable.sddStage);
}
```

Both columns land in one version bump (matching how `syncStatus` alone
justified version 4) since neither has a migration dependency on the
other. `onCreate`'s `m.createAll()` picks up both automatically for
fresh installs — no separate handling needed there.

### `TicketRepository` (modified — `domain/repositories/ticket_repository.dart`)

`updateTicket`'s dartdoc widens to name `complexity` among the fields it
persists (implementation: one more field in `DriftTicketRepository`'s
existing companion-object update call — no new method, `complexity` is a
plain content field like `priority`).

New dedicated method, mirroring `updateTicketStatus`'s "only touches this
field" shape:

```dart
/// Updates only the [stage] (and `updatedAt`) of the ticket with id
/// [id]. Does not touch any other field, and performs no precondition
/// validation — callers (`TicketsCubit.advanceSddStage`) are
/// responsible for checking the transition is legal before calling
/// this. Throws if [id] does not exist.
Future<void> updateTicketSddStage(String id, SddStage stage);
```

### `AutomationSettingsRepository` (new — `lib/core/automation/automation_settings_repository.dart`)

A new small repository, not folded into `AgentSettingsRepository` (whose
own dartdoc scopes it to "provider identity," a different concern):

```dart
/// Persists the single global [AutomationConfidence] value for
/// SDD-stage-triggering (see `TicketsCubit.advanceSddStage`). One value
/// today; per-context storage (a `Map`-shaped persistence key per
/// automation point) is deferred until a second consumer (budget gate,
/// batch-flush gate) actually exists — see `project.md` §5.
abstract interface class AutomationSettingsRepository {
  /// Returns the persisted confidence level, defaulting to
  /// [AutomationConfidence.gated] if none has been saved yet — surfaces
  /// a suggestion rather than acting silently or requiring the user to
  /// discover a manual control, the safest default for a brand-new
  /// automated decision point.
  Future<AutomationConfidence> getSddStageAutomation();

  /// Persists [confidence] as the SDD-stage-triggering confidence level.
  Future<void> setSddStageAutomation(AutomationConfidence confidence);
}
```

`SharedPrefsAutomationSettingsRepository` implements it via
`shared_preferences`, mirroring
`SharedPrefsAgentSettingsRepository`'s existing shape exactly (one string
key, `AutomationConfidence.values.byName`/`.name` round-trip).

## Presentation layer

### `TicketsCubit.advanceSddStage` (new — `presentation/cubit/tickets_cubit.dart`)

```dart
/// Advances [ticket]'s [Ticket.sddStage] to the next stage, after
/// checking that stage's precondition. Rejects (emits
/// `TicketsError(reason: sddStagePreconditionNotMet)` then re-emits
/// `TicketDetailLoaded`, mirroring `_emitInvalidParent`) if:
/// - `ticket.type` is not [TicketType.epic]/[TicketType.story], or
/// - the precondition for the current → next transition isn't met yet.
///
/// Preconditions:
/// - `null` → `exploring`: none, any epic/story may start.
/// - `exploring` → `proposed`: the ticket's most recent `chat` child
///   (by `createdAt`) has a terminal AI comment (i.e. isn't mid-run —
///   see [ChatCubit]).
/// - `proposed` → `verifying`: every direct child at the next rank down
///   (Tasks for a story, Stories for an epic) has reached a terminal
///   state (`TicketStatus.done` for a Task; `SddStage.archived` for a
///   Story).
/// - `verifying` → `archived`: the ticket's most recent `chat` child
///   tagged for the verifying stage has a terminal AI comment.
///
/// On success: persists the new stage via
/// `TicketRepository.updateTicketSddStage`, then spawns the next stage's
/// chat (see `_spawnStageChat` below) unless the new stage is
/// `archived` (nothing to spawn after Archival).
Future<void> advanceSddStage(Ticket ticket) async { ... }
```

Companion private helper `_spawnStageChat(Ticket parent, SddStage stage)`:
creates a `chat`-type child ticket (title `"<Stage> — <parent.title>"`),
posts a `CommentAuthorType.system` comment assembling context (parent
`title`/`description`, direct `relatesTo` links, and — for `verifying`/
`archived` — child Tasks' titles/statuses, plain text, no
embeddings/repo-map involvement per proposal.md's Out of scope), then
calls `AgentModelClient.run()` with a stage-specific prompt template and
delegates the streamed response to the same accumulate-then-persist
logic `ChatCubit.sendMessage` uses (extracted into a shared private
method both call, so the spawn path and the user-message path can't
drift). Returns the spawned chat ticket's id so callers can navigate to
it.

### Precondition check on ticket-detail load (modified — `TicketsCubit.getTicketById`)

When the loaded ticket's `type` is `epic`/`story`, `getTicketById` also
fetches its direct children (`TicketRepository.getTicketsByParent`,
already exists) and evaluates whether `advanceSddStage`'s precondition
for the *current* stage is met, attaching the result to a new field on
`TicketDetailLoaded` (`bool canAdvanceSddStage`) rather than computing it
again in the widget layer. `TicketDetailScreen` reads
`AutomationSettingsRepository.getSddStageAutomation()` (via a small
Cubit-level read, cached once per screen instance — no polling) to
decide which of the three renderings (silent auto-advance call, gated
banner, plain manual button) to show, per proposal.md's semantics
section. The `auto` case calls `advanceSddStage` itself, once, guarded
against re-firing on rebuild by a `_autoAdvancedTicketIds` set on the
Cubit (keyed by ticket id + target stage, cleared when the ticket
navigates away).

### `TicketsCubit.promoteSignalToEpic` (new)

```dart
/// Promotes [signal] (must be `TicketType.signal`, else no-ops with
/// `TicketsError`) into an epic: if [existingEpicId] is given, links
/// [signal] to that epic via `TicketLinkRepository.createLink(...,
/// linkType: TicketLinkType.relatesTo)`; otherwise creates a new
/// `TicketType.epic` ticket copying `signal.title`/`description`, then
/// links the two the same way. Does not delete or change `signal`'s own
/// type or status — promotion is a link, not a conversion, consistent
/// with `release`'s existing cross-cutting-link precedent.
Future<void> promoteSignalToEpic(Ticket signal, {String? existingEpicId}) async { ... }
```

### `ChatCubit` (new — `presentation/cubit/chat_cubit.dart` + `chat_state.dart`)

Stays inside the existing `features/tickets` module (operates on
`chat`-type tickets via the existing `CommentRepository`, not a new
top-level feature — see proposal.md's re-scoping). Provided alongside
`CommentsCubit` on the ticket-detail route, used instead of it only when
`ticket.type == TicketType.chat`.

```dart
class ChatCubit extends Cubit<ChatState> {
  ChatCubit(this._repository, this._client) : super(const ChatInitial());

  final CommentRepository _repository;
  final AgentModelClient _client;

  Future<void> loadMessages(String chatTicketId) async { ... }

  /// Posts a human comment, then calls [AgentModelClient.run], emitting
  /// `ChatLoaded(comments, streamingText: ...)` on every `AgentTextEvent`
  /// chunk for live rendering, and persisting the accumulated text as one
  /// `CommentAuthorType.ai` comment (`aiModel: model.id`) on
  /// `AgentDoneEvent`. On `AgentErrorEvent`, emits `ChatError` without
  /// persisting a partial comment — the human message the user sent
  /// stays, nothing broken is written for the reply.
  Future<void> sendMessage({
    required String chatTicketId,
    required String content,
    required AgentModel model,
  }) async { ... }
}
```

States: `ChatInitial`, `ChatLoaded(List<TicketComment> comments, {String? streamingText})`,
`ChatError(String message)`. Reuses `TicketComment`/`CommentTile` for
every settled message; a new lightweight `_StreamingBubble` widget in
`ticket_detail_screen.dart` renders `streamingText` while non-null,
directly below the settled list, styled distinctly from a `CommentTile`
per the Design gate.

# Aion — SDD Ticket Execution: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing`, `SelectionMenu<T>`, `TypeChip`, `CommentTile`, `TicketOverflowMenu`, `TicketLinkPicker`, `TicketDetailScreen`, `CreateTicketScreen`, `SettingsScreen` by name.

This change lets Aion drive its own further development through its own ticket UI. It **adds no new screens** — it extends three existing surfaces:

- **`TicketDetailScreen`** (epic/story tickets) — a new SDD-stage section (§2).
- **`TicketDetailScreen`** (chat tickets) — a streaming reply bubble in the existing comment thread (§3), and a new `system`-authored `CommentTile` variant (§4).
- **`TicketDetailScreen`** (signal tickets) — a "Promote to Epic" overflow action + chooser (§5).
- **`TicketDetailScreen` / `CreateTicketScreen`** (every type) — a Complexity picker beside the existing Priority picker (§1).
- **`SettingsScreen`** — an "SDD Stage Automation" section (§6).

**No Material widgets anywhere.** Every surface is `DecoratedBox` / `Padding` / `Row` / `Column` / `GestureDetector` / `AnimatedContainer` / `AnimatedOpacity` / `CustomPaint` / `Overlay` + `CompositedTransformFollower`. No `Card`, `ElevatedButton`, `Scaffold`, `ThemeData`, `ColorScheme`, `ListTile`, `InkWell`, `DropdownButton`, `SnackBar`, or `Chip`.

Themes: **Arctic** (light, celestial-cold) and **Obsidian** (dark, abyssal-cold). All layout, dimensions, spacing, radius, and typography are **identical** between themes; only color tokens differ, and every color below is a named `AionColors` token that already resolves per theme. Concrete hex is given as `Arctic / Obsidian` for reference only — implement against the token, never the literal. Translucent fills are always `token.withOpacity(x)` with the theme's `fillAlpha` (Arctic `0.11`, Obsidian `0.16`) unless another alpha is stated.

**No new color, typography, or radius tokens are required** — every value below resolves to an existing token. Two small structural additions only: the `TicketComplexity` and `AutomationConfidence` enums, and the `CommentAuthorType.system` value. See §7.

## 1. Complexity picker

A `SelectionMenu<TicketComplexity>` instance (`small` / `medium` / `large`), placed **immediately to the right of the existing Priority picker** — in `CreateTicketScreen`'s create form (as a two-up row: Priority | Complexity) and in `TicketDetailScreen`'s ticket-meta row. It reuses `SelectionMenu`'s trigger/menu geometry (base spec §2.5 / Signal spec §3.2–§3.3) verbatim; only the trigger content and item-row content are new and specified here.

Complexity is a **neutral, non-priority** dimension, so its visual language is deliberately monochrome (`textSecondary` / `primary`), never the priority hues — it must not read as a second priority scale. The distinguishing motif is a **3-bar ascending meter** (a size progression), not three arbitrary colors.

### 1.1 The complexity meter (shared glyph)

A `CustomPaint` (or a `Row` of three `DecoratedBox` bars) drawn at `14×12`:

- Three vertical bars, width `3` each, `gap: 2`, bottom-aligned, radius `1`.
- Bar heights: `5 / 8.5 / 12`.
- **Filled count** encodes size: `small` = 1 filled, `medium` = 2, `large` = 3.
- Filled bar color: `primary` (`#2E86D4 / #9366FF`). Empty bar color: `borderStrong` (`#BAC8D6 / #35415C`).
- When rendered inside the trigger's value chip and in menu rows, the meter uses this same fill logic.

### 1.2 Trigger — value set (default)

Shared geometry with every other create-form control (base spec §2.5): `GestureDetector` → `DecoratedBox` → `Padding` → `Row`.

| Property | Value |
|---|---|
| Width | `double.infinity` (fills its half-column) |
| Padding | `EdgeInsets.symmetric(horizontal: 13, vertical: 11)` |
| Fill | `surface` (`#FBFCFE / #131A29`) |
| Border | `1px solid border` (`#D6E0EA / #232C40`) |
| Radius | `BorderRadius.circular(11)` (`AionRadius.lg`, screen value) |
| Shadow | none |
| Layout | `Row`, `gap: 9`, `crossAxisAlignment: center` |
| Content | complexity meter (§1.1) + label + `Spacer` + trailing chevron |
| Label | selected name title-case (`"Small"` / `"Medium"` / `"Large"`), `AionText.bodySm` (render 14), color `textPrimary` (`#142230 / #E7EDF7`) |
| Trailing chevron | `caret-down`, `11–12px`, color `textMuted` (`#8496A6 / #6B7690`) |

### 1.3 Trigger — unset / placeholder

Identical geometry; content is placeholder text `"Select complexity"`, `AionText.bodySm` (render 14), color `textMuted` (`#8496A6 / #6B7690`), no leading meter. Matches the Priority field's own unset pattern (`"Select a priority"`). Complexity is **optional** — no required asterisk, no error state.

### 1.4 Menu item rows

Reuse the overlay panel geometry from Signal spec §3.3 (fill `surface`, 1px `borderStrong`, radius `12`, `EdgeInsets.symmetric(vertical: 4)`, overlay shadow via `Colors.black.withOpacity(isDark ? 0.55 : 0.20)`, blur 46, spread −14, offset `(0, 22)`). Three rows, in ascending order:

- Padding: `EdgeInsets.symmetric(horizontal: 13, vertical: 9)`.
- Layout: `Row`, `gap: 10`, `crossAxisAlignment: center`.
  - Leading: complexity meter (§1.1) with the row's filled count (1 / 2 / 3).
  - Label: `"Small"` / `"Medium"` / `"Large"`, `AionText.bodySm`, color `textPrimary`, `Expanded`.
  - Sub-hint (trailing, before the check): a one-word scale hint, `AionText.time` (mono 11 / w400), color `textMuted` — `"~1 file"` / `"a few files"` / `"multi-module"`.
  - Trailing (selected only): `check` glyph, `15px`, color `primary`.

### 1.5 Trigger states

| State | Border | Fill | Extra |
|---|---|---|---|
| Default | `1px border` | `surface` | — |
| Hover | `1px borderStrong` | `surface` | chevron `textMuted` → `textSecondary`; `MouseRegion` click cursor |
| Focused | `1.5px primary` | `surface` | focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), blurRadius: 0, spreadRadius: 3)` |
| Pressed / Open | `1.5px primary` | `surface` | ring as focused; chevron flips to `caret-up`; `AnimatedScale` to `0.99` over 80ms on `onTapDown` |
| Disabled | `1px border` | `surface` @ `0.5` opacity | `IgnorePointer`; meter/label/chevron → `textMuted`; only while a form is submitting |
| Error | — | — | **n/a** — Complexity is optional and has no error state |

1.5px borders inset 0.5px vs. the 1px default (`BorderSide` drawn inside) so the box does not resize between states.

### 1.6 Item states

Identical to Signal spec §3.3.2: Default `transparent`; Hover/Focused `surfaceHover` (`#E4EDF6 / #1C2436`); Pressed `border` fill → commits on release + closes; Selected `surfaceHover` + trailing `check` in `primary`; no option ever disabled.

## 2. SDD-stage section (epic / story detail only)

A new section on `TicketDetailScreen`, rendered **only for `epic` and `story` tickets**, placed directly below the ticket-meta row (type chip + status + priority + complexity) and above the Description block. Hidden entirely for every other type.

### 2.1 Section container + stage tracker

- Container: full-width, top `border` 1px (`#D6E0EA / #232C40`) — same section divider as Description/Comments. Padding `EdgeInsets.fromLTRB(22, 16, 22, 16)`. No fill, no radius (it is a flush section, not a card). Inner layout `Column`, `crossAxisAlignment: stretch`, `gap: 14`.

## 3. Streaming chat bubble

Appears in `TicketDetailScreen`'s existing comment thread (`chat`-type tickets only), directly below the last settled `CommentTile`, **only while an AI reply streams**. It mirrors an AI `CommentTile` (base spec §2.8) with an in-progress affordance.

### 3.1 Bubble

- Layout: identical to an AI comment — `Row`, `gap: 10`, `crossAxisAlignment: start`; leading `30×30` AI mark avatar (radius `9` square, fill `primary`, `diamond`/`sparkle` glyph `#FFFFFF`, glow `BoxShadow(color: primary.withOpacity(isDark ? 0.60 : 0.45), blurRadius: 14)`).
- **Header row** (`gap: 7`): author `"Aion"` `12.5px w700` color `primary`; `"AI"` tag (`8.5px w800` uppercase, `primary` on `primarySubtle`, padding `2×6`, radius `4`); **no timestamp** while streaming (a `"typing…"` mono `AionText.time` `textMuted` label sits where the time would, right-aligned).
- **Bubble:** fill `primarySubtle` (`#DBE9F7 / #241F3E`); border `1px solid primary.withOpacity(isDark ? 0.42 : 0.28)`; radius `12` with top-left corner `3`; padding `EdgeInsets.symmetric(horizontal: 12, vertical: 10)`; text `13px` color `textPrimary` height `1.5`.
- Content: the streamed text so far, followed inline by the affordance (§3.2).

### 3.2 In-progress affordance — blinking caret + trailing dots

Two coordinated cues (both, so the state reads whether or not any text has arrived yet):

- **Blinking caret:** a `2×15` `DecoratedBox`, fill `primary`, radius `1`, rendered immediately after the last streamed character (baseline-aligned). `AnimatedOpacity` `1 → 0 → 1` on a `1100ms` linear loop (step, not ease — a terminal-style blink).
- **Typing dots** (shown only before the first token arrives, then removed): three `5×5` `primary` dots, `gap: 4`, each pulsing scale `0.6 → 1.0` on a staggered `900ms` loop (`0 / 150 / 300ms` delays) via `AnimatedScale`. Driven from `renderVals`/an `AnimationController` in the logic class, never from template-inline CSS keyframes.

### 3.3 Resolution into a settled `CommentTile`

**Instant swap on stream completion** (no cross-fade — a crossfade would double-expose the same text and read as a flicker):

- On the final token, the caret and any dots are removed in the same frame the bubble is rebuilt as a normal AI `CommentTile`.
- The settled tile is byte-identical in geometry (same avatar, bubble, fill, border, radius, padding) — only the header's right slot swaps the `"typing…"` label for the real `AionText.time` timestamp (`"now"`, then relative). Because geometry is unchanged, there is no layout jump; the caret simply disappears and the timestamp appears.
- The composer (base spec §2.10) stays enabled throughout; the streaming bubble is purely additive at the thread tail.
