# Spec Delta: Ticket Search Pagination

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (30/34 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **`TicketSearchPage` domain entity**
  (`domain/entities/ticket_search_page.dart`) — `Equatable`, carries
  `tickets: List<Ticket>` and `hasMore: bool`. The return type of
  `TicketRepository.searchTickets`.

- **`TicketRepository.searchTickets`'s `limit`/`offset` parameters** —
  `required int limit`, `int offset = 0`. Returns a `TicketSearchPage`
  (at most `limit` tickets starting after the first `offset` matches, plus
  whether further matches exist) instead of the full unfiltered result
  set.

- **`TicketDao.searchTickets`'s `limit`/`offset` parameters** — same
  meaning, applied mechanically to both the typed-select branch
  (`.limit(limit, offset: offset)`) and the raw FTS `customSelect` branch
  (`LIMIT ? OFFSET ?` appended to the SQL, bound as `Variable`s — never
  string-interpolated, same rule the existing filter variables already
  follow). The DAO itself makes no `hasMore` decision — it returns
  exactly what it's asked for.

- **`TicketsCubit.loadMoreTickets()`** — fetches the next page for
  whichever query/filters the cubit's last `searchTickets()` call used,
  appending to the currently loaded list. No-ops unless the cubit is in a
  settled list-shaped state with `hasMore: true` (covers: nothing loaded
  yet, a load-more already in flight, or the end of results already
  reached) — this state-based check is also the sole concurrency guard
  against a fast/bouncy scroll firing the trigger multiple times, no
  timer involved.

- **`TicketsState.TicketsLoadingMore`** — carries the tickets loaded so
  far while a `loadMoreTickets()` call is in flight.

- **`TicketsState.TicketsLoadMoreFailed`** — carries the tickets loaded
  before a failed `loadMoreTickets()` attempt (unchanged — never
  discarded) plus the `hasMore` value from before the attempt, so the UI
  can offer a retry instead of losing the already-loaded rows or
  silently treating a transient failure as end-of-list.

- **Infinite-scroll loading in `TicketsListScreen`'s flat list** — a
  `ScrollController` triggers `TicketsCubit.loadMoreTickets()` when the
  user scrolls within 400 logical pixels of the bottom. A footer row
  (spinner while loading, retry control on failure, nothing once
  `hasMore` is `false`) renders below the last ticket row.

- **A "Load more" button in board mode** (`TicketBoardView`'s parent,
  `TicketsListScreen`) — visible when board mode is active, `hasMore` is
  `true`, and selection mode is inactive. Board mode has no single
  scrolling container to attach a scroll-proximity trigger to (six
  independent per-status columns), so it gets an explicit trigger instead
  of an automatic one; both call the identical
  `TicketsCubit.loadMoreTickets()`.

## MODIFIED

- **`TicketRepository.searchTickets`** (§Repository interfaces) — return
  type changes from `Future<List<Ticket>>` to `Future<TicketSearchPage>`;
  gains `required int limit, int offset = 0`. Filter semantics
  (`status`/`type`/`priority` exact-match ANDed, `query` full-text,
  ordering, trash exclusion) are unchanged — only the result is now one
  page instead of the complete match set.

- **`TicketDao.searchTickets`** (§DAOs) — same signature change, both
  query branches. Filter/ordering semantics unchanged.

- **`DriftTicketRepository.searchTickets`** (§Repository implementations)
  — no longer a bare pass-through. Requests `limit + 1` rows from the
  DAO, trims to `limit`, and sets `hasMore = (rows returned from DAO) >
  limit` — deriving "is there another page" without a separate `COUNT`
  query.

- **`TicketsCubit.searchTickets`** (§`TicketsCubit`/`TicketsState`) — now
  passes `limit: 50` (the app-wide ticket page size) to the repository
  and emits `TicketsLoaded(tickets, hasMore: ...)` instead of
  `TicketsLoaded(tickets)`. Internally remembers the query/filters it was
  called with (for `loadMoreTickets()` and the mutation-refresh methods
  below) and bumps an internal generation counter so a
  `loadMoreTickets()` call already in flight from before this call is
  discarded when it resolves, rather than appending onto an unrelated
  list.

- **`TicketsCubit.createTicket` / `.updateTicketStatus` / `.trashTicket`
  / `.trashTickets`** (§`TicketsCubit`/`TicketsState`) — their
  post-mutation list refresh switches from the unbounded
  `TicketRepository.getAllTickets()` to the paginated `searchTickets`,
  using the cubit's remembered filters and requesting
  `max(50, <tickets already loaded before this mutation>)` so a
  background mutation (e.g. a board drag's status update) never collapses
  an infinite-scrolled list back down to one page, and no longer silently
  discards whatever search/filter was active (its `getAllTickets()`-based
  behavior before this change). `TicketCreated`, `TicketStatusUpdated`,
  and `TicketsBatchTrashed` each gain the same `hasMore: bool` field
  `TicketsLoaded` gains.

- **`TicketsListScreen`** (§Screens) — the flat list's `ListView.separated`
  gains a `ScrollController` and a footer item; `_currentTickets`
  (the helper pulling the renderable list out of state) gains cases for
  the two new states so a scroll-triggered load or a failed retry doesn't
  blank the screen.

## REMOVED

- **The "Known gaps" bullet**: `TicketRepository.searchTickets`/
  `TicketDao.searchTickets` return every matching row with no
  `LIMIT`/pagination (currently at line 1222 of `aion-arch/specs/tickets.md`)
  — removed entirely on `/archive`, this change closes that gap.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **`TicketRepository.getAllTickets()`** — stays fully unbounded.
  `TicketsCubit.getValidParentCandidates`/`updateTicketParent`'s
  cycle-detection walk needs the complete ticket graph to be correct; a
  paginated view could silently miss a cycle involving a ticket outside
  the loaded window. Not touched by this change.
- **Pagination style.** Offset-based `LIMIT`/`OFFSET`, not a true keyset/
  cursor (e.g. `(created_at, id)` or a `bm25`-stable comparator). See
  proposal.md's "Why this shape" for the reasoning — this is a
  reversible, additive choice, not a structural commitment.
- **No page-count or "jump to page N" UI anywhere.** Infinite scroll only,
  consistent with every other list already in this app.
- **`TicketLinkRepository`/`CommentRepository`/`TicketDao`'s other
  methods** (`getAllTickets`, `getTicketById`, trash/restore/permanent-
  delete surface, comments, links) — untouched.
- **Schema.** No column, table, or migration change.
