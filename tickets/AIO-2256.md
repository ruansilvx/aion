# Spec Delta: Ticket Link Count Excludes Trashed

**Reconciled 2026-09-03:** a small, self-contained query change (`TicketLinkDao.getLinksForTicket` excluding links to a currently-trashed ticket). No indication anything in this area has changed since — the join-based implementation described is exactly the kind of internal detail unlikely to be touched by unrelated later work. No drift found.

## ADDED

None. No new public API surface — `TicketLinkDao`/`DriftTicketLinkRepository`/
`TicketLinkRepository` keep their existing method signatures.

## MODIFIED

- **`TicketLinkDao.getLinksForTicket`** — now excludes links whose *other*
  endpoint (not the queried `ticketId`) is currently trashed
  (`TicketsTable.deletedAt` non-null). Implemented as two joined queries
  (source-side, target-side) against `TicketsTable`, concatenated. A link
  to a trashed ticket reappears automatically once that ticket is
  restored (no extra logic needed — the join re-evaluates live), and
  disappears for good once it's permanently deleted (already
  cascade-deleted via `deleteLinksForTickets`, unaffected by this
  change).

- **`LinkCountLabel`** (`tickets_list_screen.dart`) — no code change, but
  its displayed count is now accurate: a ticket's list-row link count no
  longer includes links to tickets currently sitting in Trash.

- **`TicketLinkRepository`'s interface dartdoc** — corrected from "No
  link UI exists yet in this slice" to note that `LinkCountLabel` already
  consumes `getLinksForTicket`, while a full link-browsing/editing screen
  still doesn't exist.

- **`aion-arch/specs/tickets.md`'s "Known gaps" bullets**:
  - The bullet at line 1098-1101 ("A live ticket's link count... still
    counts links to a currently-trashed linked ticket") is **removed
    entirely** on `/archive` — this change closes that gap.
  - The bullet at line 1149-1150 ("No UI for `ticket_links` (schema and
    repository exist; no screen consumes them yet)") is reworded on
    `/archive` to: "No dedicated UI for browsing, creating, or editing
    individual `ticket_links` rows — `LinkCountLabel`
    (`tickets_list_screen.dart`) already consumes
    `TicketLinkRepository.getLinksForTicket` for a per-ticket count, but
    there is no screen to view or manage the links themselves."

## REMOVED

None.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **Schema.** No column, table, or migration change — `ticket_links` and
  `tickets` are structurally identical to before.
- **`ticketId` itself being trashed.** Only the *other* endpoint of each
  link is filtered. `LinkCountLabel` only ever renders for tickets in the
  live list, so this case doesn't arise in practice and isn't handled
  specially.
- **`DriftTicketLinkRepository`/`TicketLinkRepository` method
  signatures.** Both keep `getLinksForTicket(String ticketId)` and
  `createLink({...})` exactly as before — only `TicketLinkDao`'s internal
  query changes.
- **Restore (`restoreTicket`) and permanent-delete
  (`permanentlyDeleteTicket`/`emptyTrash`) behavior.** Already correct
  today (confirmed by `/explore live ticket link count`, 2026-07-16) —
  untouched.
- **No `TicketLinksRepository` UI, no `LinksCubit`, no link-browsing
  screen.** Still not built; still tracked by the reworded known-gaps
  bullet above, not implemented here.
