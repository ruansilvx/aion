# 5. Cubits — `features/projects/presentation/cubit/`

- [x] 5.1 `project_hub_state.dart` — `ProjectHubState` sealed hierarchy
      (`Initial | Loading | Loaded | Empty | Error`) per design.md §5.
      Dartdoc on each state describing the UI condition it represents.
- [x] 5.2 `project_hub_cubit.dart` — `ProjectHubCubit`, loads projects via
      `ProjectRepository`, emits `Empty` vs `Loaded` based on result
      length. Header + dartdoc.
- [x] 5.3 `create_project_state.dart` — `CreateProjectState` sealed
      hierarchy (`Initial | Validating | Ready | Submitting | Success |
      Failure`) per design.md §5. Dartdoc per state.
- [x] 5.4 `create_project_cubit.dart` — `CreateProjectCubit`. Owns the
      validation invariants per design.md §5: name non-empty and unique
      among `ProjectRepository.getAllProjects()`, and (desktop) chosen
      directory has no existing `.aion/manifest.json`. On submit: writes
      the `.aion/manifest.json` marker (desktop), `git init`s at
      `rootPath` (desktop only — no-op on mobile/web), and calls
      `ProjectRepository.createProject`. Header + dartdoc.
- [x] 5.5 `active_project_state.dart` — `ActiveProjectState` sealed
      hierarchy (`None | Switching | Open`) per design.md §5. Dartdoc per
      state.
- [x] 5.6 `active_project_cubit.dart` — `ActiveProjectCubit implements
      ActiveProjectProvider`. `switchTo(Project)` emits `Switching` then
      `Open`, calls `ProjectRepository.updateLastOpened`. Header +
      dartdoc, including a note on why it implements the `core` contract
      (Pattern 1, cross-feature access).
