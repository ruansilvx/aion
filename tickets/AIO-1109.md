# T5. In the same file, in `updateTicketStatus(String id, TicketStatus

status)`, add `unawaited(_refreshDetailIfOpenAndAffected(id))`
immediately after the existing `emit(TicketStatusUpdated(tickets,
hasMore))` on the success path — after the git-projection step, per
`design.md`. No change to the optimistic `TicketStatusUpdating`
emission or the failure path.
**Found and fixed while writing T6's tests, before any code ran:**
`updateTicketStatus`'s own `TicketStatusUpdating`/`TicketStatusUpdated`
emissions overwrite `state` *synchronously*, before this new call
even runs — so a live `state` read at that point would never see
the detail screen that was open when the call started, making
`_refreshDetailIfOpenAndAffected`'s Story/child-status case
permanently dead code as originally written in `design.md`. Fixed
by capturing `state` into `stateBeforeThisWrite` at the top of
`updateTicketStatus` (before its own emissions) and giving
`_refreshDetailIfOpenAndAffected` an optional `TicketsState?
fromState` parameter (defaulting to a live `state` read, which
stays correct for the `createTicket`/`updateTicket` call sites —
those chain onto `_estimationSuggester`'s completion well after
their own synchronous emission, so "is a detail screen open right
now" is the right question there). `updateTicketStatus` passes
`fromState: stateBeforeThisWrite` explicitly. One consequence
documented rather than engineered away: because
`updateTicketStatus`'s own emissions already interpose a
non-`TicketDetailLoaded` state, `getTicketById`'s Loading-skip
condition can't apply for this path — the Story's detail screen
still sees a brief `TicketsLoading` frame before the refreshed
`TicketDetailLoaded` lands, unlike the fully invisible
`createTicket`/`updateTicket` case. Still a strict improvement
over today (no refresh at all, permanently stale until a manual
reload) — not the fully flicker-free result originally described,
but the flicker was already unavoidable given this single-cubit
architecture's pre-existing behavior (any unrelated cubit
emission already blanks `TicketDetailScreen`'s body to
`SizedBox.shrink()` while it's outstanding).
