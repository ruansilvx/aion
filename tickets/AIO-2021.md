# Spec Delta: spec-ticket-type

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (35/38 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`. Read alongside
[proposal.md](../proposal.md) and [design.md](../design.md) — this file
only lists what changes, not full current-state context.

## ADDED

- **`TicketType.spec`** (`domain/enums/ticket_type.dart`) — Aion's
  record of a capability's current-state behavior, the ticket-native
  replacement for `aion-arch/specs/*.md`. Parentless; may parent a
  `chat`, nothing else. Created automatically once per Epic when its
  `SddStage` reaches `archived`, or manually via the generic New Ticket
  flow.
- **`TicketTypeHierarchy.isAlwaysRoot`**/**`canParent`** — both gain
  `spec` alongside the existing `idea`/`knownGap`/`openQuestion`/
  `release` case: parentless, may parent only `chat`.
- **`AutomationContext.specAutoLink`** (`core/automation/automation_context.dart`)
  — gates whether a fresh `knownGap`/`openQuestion`, or a `bug` reaching
  a `done`-role status, auto-links to the most similar `TicketType.spec`
  ticket. Distinct from the existing `ticketLinking` context, which
  gates a model's own `add_link` tool-call request — this context gates
  a deterministic, code-computed similarity match with no model
  involved.
- **`TicketsCubit._createEpicSpec(Ticket epic)`** — synthesizes and
  creates an Epic's spec ticket: assembles context (epic title/
  description + each direct Story child's title/status, the same shape
  `_assembleStageContext` already builds for `verifying`/`archived`),
  resolves the model via `ModelPhase.capable`, creates a
  `TicketType.spec` ticket titled `"Spec — <epic.title>"` with the
  reply as content, links it to the epic via `TicketLinkType.relatesTo`.
  No `chat` ticket is spawned. Called `unawaited` from
  `advanceSddStage`'s `archived` branch, guarded to `TicketType.epic`
  only — a Story reaching `archived` (routine, since it's the
  precondition for its parent Epic's own `verifying` transition) does
  not trigger this.
- **`TicketsCubit._maybeAutoLinkToSpec(Ticket ticket)`** — best-effort
  auto-link to the single best-matching live `spec` ticket via
  `domain/utils/embedding_similarity.dart`'s `cosineSimilarity`
  (`ticket.title`+`description` as query, 0.75 threshold — the same
  bar `TicketContextEnricher` already uses, but a single best match
  rather than a top-K list, since this creates a real `relatesTo` link
  rather than context prose). Gated by
  `AutomationSettingsRepository.getConfidence(AutomationContext
  .specAutoLink)`: `auto` links immediately, `gated` surfaces a confirm
  banner on the ticket's detail screen, `manual` surfaces nothing
  proactively (a manual "Link to spec" action remains available,
  reusing the same lookup to prefill a suggestion). Called `unawaited`
  from `createGapOrQuestion` (additive to its existing mandatory target
  link) and from `updateTicketStatus` (when a `TicketType.bug` reaches
  a `done`-role status).
- **`TicketsErrorReason.specWriteFailed`** — emitted if `_createEpicSpec`'s
  model call or ticket creation fails; the triggering Epic's own
  `archived` transition is unaffected (already persisted before this
  step runs).
- **`AionColors.typeSpec`** — new required color-token field, one
  accent per theme, feeding `TypeChip`'s tinted-fill rendering for the
  new type; `LinkedTicketsSection._typeColor` gains a matching arm.
- **`ticketTypeSpec`** l10n key (`lib/l10n/app_en.arb`) and matching
  `ticketTypeLabel` switch arm.

## MODIFIED

- **`CreateTicketScreen`**'s type dropdown — `spec` is added to the
  included types (previously excluded only `page`/`knownGap`/
  `openQuestion`), making manual spec creation possible — the fallback
  path if `_createEpicSpec` fails, and the mechanism used for the
  one-off "Architecture — Aion" spec that plays `project.md`'s role
  (content migration itself is out of scope — see proposal.md).
- **`PagesCubit`/`PageDetailScreen`** — every existing
  `ticket.type == TicketType.page` branch that decides whether a
  ticket is theirs to render becomes `ticket.type == TicketType.page ||
  ticket.type == TicketType.spec`. Content editing (the `MarkdownEditor`
  instance, the save path) is unchanged, since both types already store
  their body in `description`. `PageCreateScreen` is unmodified — a
  `spec` ticket is never created through it.

## Unchanged (explicitly, to avoid ambiguity)

- **`DocumentationScreen`**'s `ticket.type == TicketType.page` check
  (line ~325) is left as-is — `spec` tickets are not surfaced in the
  generic Documentation-section listing, the same treatment
  `knownGap`/`openQuestion` already get. Reachable via the owning
  Epic's `relatesTo` link instead.
- No drift schema migration — `TicketsTable.type` is a plain
  `TextColumn` (purely additive enum value); `AutomationContext` is
  `SharedPrefsAutomationSettingsRepository`-backed, keyed by enum name
  (purely additive value).
