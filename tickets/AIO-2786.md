# 8. `/verify` follow-up fixes

`/verify` found one CRITICAL and one SUGGESTION. Both fixed on the same
branch — see design.md's "`/verify` follow-up" section for the full
rationale behind each.

- [x] **CRITICAL — `_reconcileTrashState` compared against a stale
      `existingByTicketId` snapshot.**
      `lib/features/tickets/data/services/ticket_db_reconstruction_service.dart`:
      `_reconcileTrashState` now takes `existingByTicketId` as a third
      parameter and, after any `trashTicket`/`restoreTicket` call,
      re-fetches every id in that call's own returned affected-id list
      via `getTicketById`, writing each fresh `Ticket` back into the map
      — so a later loop iteration reconciling one of those same
      cascaded tickets compares against its true post-cascade state,
      not a stale pre-cascade one. Updated the method's dartdoc to
      document both the fix and the residual "genuinely conflicting
      hierarchy" limitation cascading methods can't fully resolve
      either way.
      Added `test/features/tickets/data/services/ticket_db_reconstruction_service_test.dart`'s
      `"/verify regression — a descendant cascade-trashed by its
      parent's own reconciliation does not also trigger a second,
      redundant trashTicket call..."` test: a `MockTicketRepository`
      delegating every call to a real in-memory `DriftTicketRepository`
      (mocktail call-count verification is the only way to observe the
      redundant call — a real repository has no introspection of its
      own). Manually confirmed the test fails against the pre-fix code
      (`trashTicket` called twice) before confirming the fix makes it
      pass (called once).
- [x] **SUGGESTION — add an end-to-end (real repository + real git)
      test for the cascade → one-commit chain.**
      `test/features/tickets/data/repositories/git_projecting_ticket_repository_test.dart`:
      added a new group wiring a real `DriftTicketRepository`
      (in-memory), a real `TicketGitProjector` (real
      `GitRepositoryClient`, a real `git init`'d temp directory), and
      the real `GitProjectingTicketRepository` decorator together — no
      mocks at any layer. Trashes an epic + child, restores only the
      child, and asserts exactly one `"2 tickets trashed"` commit and
      one `"2 tickets restored"` commit land, plus that the epic's own
      `.md` file is actually rewritten to `deletedAt: null` — literal,
      end-to-end proof of the AIO-2703/2704 fix, not just per-layer unit
      coverage.
- [x] Re-ran `flutter analyze` (still clean, same 2 pre-existing
      unrelated lints) and the full `test/features/tickets/` suite:
      1285/1285 (1283 plus the 2 new tests above).
