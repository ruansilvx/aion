# Core — markdown serialization

- [x] T13. Create `lib/core/markdown/ticket_markdown_template.dart` —
      frontmatter field-name constants and the field ordering used for
      deterministic serialization. **Corrected from design.md**: `title`
      is modelled as the body's leading `# ` heading, not a frontmatter
      field — design.md's frontmatter example omitted `title` entirely
      (a real gap, not an intentional exclusion).
- [x] T14. Create `lib/core/markdown/ticket_markdown_parse_result.dart`
      — sealed `TicketMarkdownParseResult` with `ParsedOk`,
      `ParsedPartial` (carries `validFields` + `invalidFieldNames`),
      and `Unparseable` (carries a `reason`) variants, each documented.
- [x] T15. Create `lib/core/markdown/ticket_markdown_serializer.dart` —
      `TicketMarkdownSerializer` with a pure, deterministic
      `serialize(Ticket) -> String` and a `parse(String) ->
      TicketMarkdownParseResult`. No Flutter import (must stay
      importable from the plain-Dart CLI in T31).
- [x] T16. Create `lib/core/markdown/ticket_markdown_linter.dart` — a
      DB-agnostic function that takes raw file content and returns
      either a reformatted string or `null`. Deliberately conservative:
      only trims trailing whitespace when the content already parses
      (`ParsedOk`/`ParsedPartial`); returns `null` for genuinely
      `Unparseable` content rather than guessing at a YAML repair.
      Shared by `TicketRepairService` (T23) and `bin/ticket_lint.dart`
      (T31).
