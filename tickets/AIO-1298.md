# Design: New-project onboarding — attach-to-existing-project flow

## Key architectural decisions

These resolve gaps between the source idea's aspirational description and
what's actually in the codebase today (confirmed by reading the code, not
assumed from the idea file):

1. **No separate "Attach" screen or Cubit.** `CreateProjectCubit.submit`
   already accepts any `rootPath`, empty or not — the only thing missing is
   the gitignore gate. Building a second screen/flow for "attach" would
   duplicate `NewProjectScreen`/`CreateProjectCubit` for no functional
   gain. One form handles both cases; the gitignore gate and the
   post-creation summarization offer both key off one fact ("is this
   directory already a git repo"), computed once.

2. **The gitignore-gate check moves earlier than stack detection currently
   runs.** The idea assumed the gate fires "the same moment
   `ProjectStackDetector`'s marker-file detection runs." In the actual
   code, `ProjectStackDetector.detect` only runs post-submit, inside
   `CreateProjectCubit.submit` → `BaselineTailoringService.tailorForDetectedStack`
   (`create_project_cubit.dart:134-138`) — never at directory-selection
   time. Since the gate must appear "inline, pre-submit" (per the idea's
   final brainstorm session), this proposal adds a new, separate,
   synchronous check at pick-time (`_browseDirectory` in
   `new_project_screen.dart`), not a move of existing stack-detection
   logic. It only needs to answer "does `<path>/.git` exist" — cheap, no
   need to invoke the heavier stack-detection/baseline-tailoring machinery
   early.

3. **"Shown once" is in-memory, not persisted.** The codebase-summarization
   offer must appear "immediately after creating a project" and never
   again unprompted. Rather than adding a persisted flag to `Project`
   (schema change, drift migration, `RegistryDatabase` bump), the offer
   flag lives only in `ActiveProjectCubit`'s in-memory state for the
   project-switch that just happened, consumed once by the ticket-list
   screen. Restart the app, or switch projects and back, and the offer is
   gone — matching "shown once, right after creation," not "shown once,
   ever, tracked forever."

4. **No new shell-level toast/notification infrastructure.** The idea
   assumed reuse of a "shell-level toast mechanism" from
   `board-execution-indicators-and-notifications`. That idea is
   unshipped (`status: explored`, no corresponding `changes/archive/`
   entry) — no such mechanism exists in code. Every existing toast in
   Aion is a direct, per-call-site `AppToast.show(context, message)`
   (8 existing call sites, e.g. `ticket_detail_screen.dart`,
   `tickets_list_screen.dart`). The gitignore-decline warning follows the
   same proven pattern: fired directly from `NewProjectScreen`'s
   `BlocListener`, which already has a `BuildContext` at the moment
   `CreateProjectSuccess` arrives. This keeps the proposal self-contained
   — it does not depend on unshipped infrastructure from another idea.

5. **Full-depth summarization reuses the existing worktree-isolation
   pattern**, not a new restricted tool tier. `agent_bridge/index.mjs` is
   binary: `toolsEnabled: false` → zero tools (used by every SDD-stage
   chat and the Settings connection test); `toolsEnabled: true` → full
   bypass-permissions tool access (used only by
   `TicketsCubit._runCodingExecution`, always inside an isolated `git
   worktree`, never against the developer's real checkout). There is no
   third, read-only tier anywhere in the codebase, and the source idea's
   own conclusion doesn't ask for one ("reuses the exact tool-enabled
   mechanism coding-execution already has"). Full-depth summarization
   therefore runs `toolsEnabled: true` inside a fresh worktree created via
   the already-existing `GitRepositoryClient.createWorktree`/
   `removeWorktree` — even though the run is conceptually read-only, it
   gets the same blast-radius containment coding-execution already
   depends on (a stray write lands in a disposable worktree, never in the
   user's real checkout, and is never pushed or merged back).

6. **No `Ticket` schema change for the shallow-scan flag.** The idea
   describes a "this knowledge is shallow" flag a later chat could act on.
   Since nothing consumes that flag yet (the Inbox's Q&A chat, the
   intended future consumer, doesn't exist), this proposal writes it as a
   plain leading line in the signal ticket's `description`
   (`"[Shallow scan — structural only, may be incomplete]"`) rather than
   adding a new nullable field to `Ticket`/a drift migration for a
   consumer that can't read it yet. Matches Aion's existing "plain
   description text" fallback used elsewhere before a field earns its own
   column.

## Data flow

```
NewProjectScreen                         CreateProjectCubit
  │  _browseDirectory()                       │
  │  → GitRepositoryClient.isGitRepository(path)   (new, sync .git dir check)
  │  → setState(_isExistingGitRepo)            │
  │  [gitignore banner shown inline if true]   │
  │                                             │
  │  submit(appendGitignore: checkbox state) ─→│  submit(..., appendGitignore)
  │                                             │  ├─ existing validation unchanged
  │                                             │  ├─ _initializeDesktopProject:
  │                                             │  │    if already a git repo:
  │                                             │  │      skip GitRepositoryClient.init()
  │                                             │  │      if appendGitignore:
  │                                             │  │        GitignoreEditor.ensureIgnored(rootPath, [".aion/", "tickets/"])
  │                                             │  │    else: init() as today
  │                                             │  └─ emits CreateProjectSuccess(project, wasExistingGitRepo)
  │  BlocListener<CreateProjectSuccess>         │
  │  if wasExistingGitRepo && !appendGitignore: │
  │    AppToast.show(context, declineWarning)   │
  │  onCreated(project, offerCodebaseAnalysis: wasExistingGitRepo)
  │                                             │
  ▼
app_router._openProject(context, project, offerCodebaseAnalysis)
  → ActiveProjectCubit.switchTo(project, offerCodebaseAnalysis: offerCodebaseAnalysis)
  → context.go('/workspace/tickets')
                                             │
                                             ▼
TicketsListScreen.initState
  → reads ActiveProjectCubit state's offerCodebaseAnalysis
  → if true: shows CodebaseAnalysisBanner (offer state)
  → calls ActiveProjectCubit.consumeCodebaseAnalysisOffer() (clears the flag — never reappears)

CodebaseAnalysisBanner (user picks depth, or dismisses)
  → TicketsCubit.runCodebaseSummarization(depth: shallow | full)
      shallow: single toolsEnabled:false model turn, prompt built from
               ProjectStackDetector.detect(rootPath) + a depth-limited
               Directory.list() (filenames only, no file content)
      full:    mirrors _runCodingExecution's shape —
               GitRepositoryClient.createWorktree (fresh temp worktree)
               → spawn root `signal` ticket "Codebase Analysis — <project name>"
               → spawn its `chat` child (signal.canParent(chat) only)
               → ChatCubit.runChatTurn(toolsEnabled: true, workingDirectory: worktreePath)
                 streaming onChunk/onToolUse into that chat's comments
               → GitRepositoryClient.removeWorktree (always, in `finally`)
  → parses the model's final structured reply (terminated by a
    `SUMMARY: DONE` marker, mirroring _runCodingExecution's
    `IMPLEMENTATION: DONE` convention) into N findings
  → for each finding: TicketRepository.createTicket(type: signal, title, description)
    then TicketLinkRepository.createLink(finding.id, runSignalTicket.id, relatesTo)
    (each finding is its own root signal ticket — signal can't structurally
    parent another signal, only a chat — linked back to the run for traceability)
  → CodebaseAnalysisBanner reflects a small status stream exposed by
    TicketsCubit (idle → running → done(count) → failed(message))
```

## New/modified classes

### `core/git/git_repository_client.dart` (modify)
```dart
/// Returns whether [rootPath] is already inside a git working tree —
/// checked via `<rootPath>/.git` existing, not a `git` subprocess call
/// (cheap, consistent with ProjectStackDetector's own marker-file-only
/// approach). Doesn't distinguish a worktree/submodule `.git` file from a
/// full repo's `.git` directory — both count as "already a repo" for this
/// gate's purposes.
Future<bool> isGitRepository(String rootPath);
```

### `core/git/gitignore_editor.dart` (new)
```dart
/// Appends any of [entries] not already present (line-exact match) to
/// `<rootPath>/.gitignore`, creating the file if absent. Idempotent —
/// safe to call on a `.gitignore` that already has some or all entries.
/// Pure file I/O, no git subprocess involved.
class GitignoreEditor {
  Future<void> ensureIgnored(String rootPath, List<String> entries);
}
```

### `presentation/cubit/create_project_cubit.dart` (modify)
- `submit({..., bool appendGitignore = true})` — new parameter, only
  consulted when the resolved `rootPath` is already a git repo.
- `_initializeDesktopProject` — branches on `GitRepositoryClient.isGitRepository`:
  already a repo → skip `init()`, optionally call `GitignoreEditor`;
  not a repo → unchanged (`init()` as today).

### `presentation/cubit/create_project_state.dart` (modify)
- `CreateProjectSuccess` gains `bool wasExistingGitRepo` — lets the widget
  layer decide the decline-toast and the downstream summarization-offer
  flag without re-deriving the git-repo check itself.

### `presentation/screens/new_project_screen.dart` (modify)
- `_browseDirectory` runs the new `isGitRepository` check after
  `getDirectoryPath()` resolves; stores `_isExistingGitRepo` and
  `_appendGitignore` (checkbox, default `true`) in local state.
- New inline banner (design-gated — see proposal.md), shown only when
  `_isExistingGitRepo` is true, between the directory picker and the
  baseline-version field.
- `onCreated` callback signature widens to
  `void Function(Project project, {required bool offerCodebaseAnalysis})`.
- `BlocListener` shows the decline toast (`AppToast.show`) when
  `wasExistingGitRepo && !_appendGitignore`, before calling `onCreated`.
- Copy tweak on the directory-picker hint text (existing
  `newProjectLocationHint` ARB string) clarifying an existing codebase is
  a valid choice, not just an empty folder.

### `core/routing/app_router.dart` (modify)
- `NewProjectScreen(onCreated: (project, {offerCodebaseAnalysis}) =>
  _openProject(context, project, offerCodebaseAnalysis: offerCodebaseAnalysis))`
- `_openProject` gains `{bool offerCodebaseAnalysis = false}`, forwarded to
  `ActiveProjectCubit.switchTo`.

### `presentation/cubit/active_project_cubit.dart` / `active_project_state.dart` (modify)
- `switchTo(project, {bool offerCodebaseAnalysis = false})`.
- `ActiveProjectOpen` gains `bool offerCodebaseAnalysis` (default `false`).
- New `consumeCodebaseAnalysisOffer()` — re-emits the current
  `ActiveProjectOpen` with the flag cleared to `false`. Called once by
  `TicketsListScreen.initState` after reading it, so a rebuild (e.g.
  navigating away and back within the same session) never shows the offer
  twice.

### `features/tickets/presentation/cubit/tickets_cubit.dart` (modify)
- New `SummarizationDepth` enum (`shallow`, `full`) — presentation-layer,
  UI-facing only, not persisted.
- New `Stream<CodebaseAnalysisStatus> get codebaseAnalysisStatus` +
  backing state (`CodebaseAnalysisIdle` / `Running` / `Done(count)` /
  `Failed(message)`) — deliberately kept separate from the main
  `TicketsState` used for the ticket list itself, since this is a
  transient, first-open-only concern, not part of the list's own
  filter/sort/pagination state.
- New `Future<void> runCodebaseSummarization({required SummarizationDepth depth})`
  — shallow path: one `ChatCubit`-less direct `AgentModelClient` call
  (`toolsEnabled: false`) since there's no chat ticket to anchor a
  no-tool text turn to; full path: mirrors `_runCodingExecution`'s
  worktree/chat/streaming shape exactly, reusing the same
  `_gitClient`/`_agentClient`/`_commentRepository`/`_projectRootPath`
  dependencies that method already has injected.
- New private parser (mirrors `_computeExecutionFailure`'s existing
  "detect a marker line in the final comment" approach) turning the
  model's `SUMMARY: DONE` reply into a list of `(title, description)`
  finding pairs.

### `features/tickets/presentation/widgets/codebase_analysis_banner.dart` (new)
State machine mirrors `TicketsCubit.codebaseAnalysisStatus` directly:
offer (two `AppButton`s — "Shallow scan" / "Full scan" — plus a dismiss
`×`) → running (spinner + streamed status text) → done (`"Found N items"`
+ dismiss) → failed (error text + dismiss). Non-Material, `AionColors`/
`AionText`/`AionSpacing` only, composed the same way `EmptyHubState` and
`TicketNeedsRepairBanner` already are — exact visual shape is
design-gated (see proposal.md's Design gate block).

### `features/tickets/presentation/screens/tickets_list_screen.dart` (modify)
- Mounts `CodebaseAnalysisBanner` above the ticket list/board when
  `ActiveProjectCubit`'s `offerCodebaseAnalysis` is true at first build;
  calls `consumeCodebaseAnalysisOffer()` in `initState`.

## Sequencing

1. `GitignoreEditor` + `GitRepositoryClient.isGitRepository` (no
   dependents yet, pure infrastructure — first, testable in isolation).
2. `CreateProjectCubit`/`CreateProjectState` changes (depends on 1).
3. `NewProjectScreen` UI changes (depends on 2) — **design-gated**.
4. `app_router.dart` + `ActiveProjectCubit`/`ActiveProjectState` changes
   (depends on 3's new `onCreated` signature).
5. `TicketsCubit.runCodebaseSummarization` + `CodebaseAnalysisStatus`
   (depends on nothing above — can build in parallel with 1-4).
6. `CodebaseAnalysisBanner` + `TicketsListScreen` wiring (depends on 4 and
   5) — **design-gated**.

- Exact copy for the gitignore-gate banner and the summarization-offer

- Whether `runCodebaseSummarization`'s shallow-path prompt needs a hard
  token/character cap on the directory listing for very large repos —
  worth a sanity check during `/apply`, not an architectural blocker.

# Aion — Attach Existing Repo: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name. **No Material widgets anywhere** — every surface below is `DecoratedBox` / `Container` (decoration only) / `GestureDetector` / `CustomPaint` / `Row` / `Column` / `Stack` / `AnimatedFoo`, never `Card`, `Chip`, `Banner`, `ElevatedButton`, `TextButton`, `ListTile`, `Checkbox`, `CircularProgressIndicator`, `LinearProgressIndicator`, `SnackBar`, `ColorScheme`, or `ThemeData`. All color is read from `AionColors` via `ThemeScope.of(context)` — no raw hex in a widget.

Two additions to the existing project-creation / first-open flow, letting a user point Aion at an already-git-tracked codebase and optionally get an AI-drafted starting backlog:

1. `GitignoreConfirmationBanner` — inline, pre-submit banner on `NewProjectScreen`, shown the moment the chosen directory is detected as an existing Git repo (§2).
2. `CodebaseAnalysisBanner` — inline, once-only banner on `TicketsListScreen`, shown on first open after attaching to an existing repo; four states (§3).

No new screens. Insertion points into the existing screens are described in §4. Mockups: [Aion Attach Existing Repo Mockups](./Aion%20Attach%20Existing%20Repo%20Mockups.dc.html).

## 1. Foundations added

### 1.1 State enums

```dart
// GitignoreConfirmationBanner has no enum — it is a single banner with a
// boolean `excludeAionPaths` (default true) driving its checkbox.

enum CodebaseAnalysisState { offer, running, done, failed }
enum CodebaseScanDepth { shallow, full }
```

`CodebaseAnalysisBanner` is built only once per project, and only when the project was created from an existing Git repo. Per this doc's own "Key architectural decisions" §3 above, this is **in-memory only, not persisted**: `ActiveProjectCubit`/`ActiveProjectState` carry an `offerCodebaseAnalysis` flag consumed once by `TicketsListScreen.initState`, and the widget-local `_showCodebaseAnalysisOffer` flag it sets from that offer is what dismissing (× or the `done`/`failed` state's dismiss) flips back to `false` — no `Project`/`RegistryDatabase` field. (An earlier draft of this section described a persisted `project.codebaseAnalysisDismissed` flag; that was never built — see decision §3's rationale.) After dismissal the banner is simply absent from the widget tree, no reserved space.

### 1.2 New derived tint tokens

Follow the established `AionColorsHubTokens` derived-tint pattern (compute from a base token + theme-dependent alpha; never a standalone hex). Reuse existing families where they already exist:

- **Gitignore banner** reuses the existing `noticeFill(isDark)` / `noticeBorder(isDark)` (`primary` at 0.06/0.10 fill, 0.20/0.30 border) already used by `NewProjectScreen`'s "no directory" notice — it is informational, not a warning.
- **Codebase `running`** reuses `pendingTint(isDark)` / `pendingSpinnerTrack(isDark)` (from the sync spec).
- **Codebase `done`** reuses `repairedTint` / `repairedBorderTint` / `repairedIconTint` (`success` family).
- **Codebase `failed`** reuses `dangerTint` / `dangerBorderTint` (`danger` family).

Add these new tints (icon-chip fills and the `signal`-accent family, which has no existing helper):

```dart
// primary family — icon-chip fill behind the gitignore branch glyph
Color noticeIconTint(bool isDark)   => primary.withOpacity(isDark ? 0.22 : 0.14);

// primary family — icon-chip fill behind the running spinner
Color pendingIconTint(bool isDark)  => primary.withOpacity(isDark ? 0.20 : 0.12);

// success family — icon-chip fill behind the done checkmark
// (repairedIconTint already covers this: success @ 0.24/0.16 — reuse it)

// danger family — icon-chip fill behind the failed warning glyph
Color dangerIconTint(bool isDark)   => danger.withOpacity(isDark ? 0.24 : 0.16);

// signal family — the codebase-analysis identity accent (typeSignal),
// output of a scan is `signal` tickets. No existing helper — new, justified.
Color signalFill(bool isDark)       => typeSignal.withOpacity(isDark ? 0.13 : 0.08); // banner fill
Color signalBorderTint(bool isDark) => typeSignal.withOpacity(isDark ? 0.34 : 0.26); // banner border
Color signalIconTint(bool isDark)   => typeSignal.withOpacity(isDark ? 0.22 : 0.15); // icon chip fill
Color signalChipTint(bool isDark)   => typeSignal.withOpacity(isDark ? 0.20 : 0.13); // "SIGNALS" badge fill
```

**No new hex values, no new color tokens.** Every family reuses an existing `AionColors` base (`primary` / `success` / `danger` / `typeSignal`). `isDark` throughout = `theme.brightness == Brightness.dark` (Obsidian).

## 2. `GitignoreConfirmationBanner`

Inline banner (not a modal), rendered inside `NewProjectScreen`'s form column between the Location picker and the Baseline-version field (§4.1). Built only on desktop builds, and only while `selectedDirectory != null && directoryIsGitRepo == true`. Informational **notice** tone (`primary`-tinted) — this is "inform, don't block," so it never uses `warning`/`danger` styling in its resting states.

### 2.0 Shared geometry (both states)

- Width: fills the form column (`double.infinity`; column is capped at `520` inside `ContentMaxWidth`).
- Outer container: `Container(decoration: BoxDecoration(...))`.
  - Padding: `EdgeInsets.fromLTRB(15, 14, 15, 14)`.
  - Radius: `AionRadius.lg` (12).
  - Fill: `noticeFill(isDark)` → `primary.withOpacity(isDark ? 0.10 : 0.06)`.
  - Border: `Border.all(width: 1, color: noticeBorder(isDark))` → `primary.withOpacity(isDark ? 0.30 : 0.20)`.
  - Shadow: **none**.
- Internal layout: `Column`, `crossAxisAlignment: start`, `gap: AionSpacing.sp12` (12) between the message row and the checkbox row.
- Vertical spacing to neighbours in the form: `AionSpacing.sp16`–`sp20` (matches the form's existing inter-field gap; use `18`).

### 2.1 Message row

`Row`, `crossAxisAlignment: start`, `gap: 11`.

**Icon chip** (leading):
- Box: `28 × 28`, `AionRadius.sm`→`8` (`iconBtnSm`), fill `noticeIconTint(isDark)` → `primary.withOpacity(isDark ? 0.22 : 0.14)`. `Container`, `margin: EdgeInsets.only(top: 1)`.
- Icon: **Phosphor `GitBranch` (Light)**, size `17`, color `AionColors.primary`, centered.

**Text block** (`Expanded`, `Column`, `crossAxisAlignment: start`):
- Title: `AionText.cardTitle.copyWith(color: textPrimary)` (Manrope 14 / w600), `height: 1.35` — "This folder is already a Git repository".
- Gap: `3`.
- Body: `AionText.bodySm.copyWith(color: textSecondary)` (Manrope 13.5 / w400), `height: 1.5` — "Aion keeps its own bookkeeping in `.aion/` and `tickets/` here. Keep them out of your repo's history?"
  - The two paths render as inline monospace: `AionText.key`-sized runs (JetBrains Mono 12 / w600) on a `surfaceHover` fill, `EdgeInsets.symmetric(horizontal: 5, vertical: 1)`, `AionRadius.sm - 2`→`4`, color `textSecondary`. Implement with a `WidgetSpan` or a `RichText` of inline `Container`s.

### 2.2 Checkbox row (`AppCheckbox`, reused)

`Row`, `crossAxisAlignment: center`, `gap: 10`, `padding: EdgeInsets.only(left: 39)` (aligns the checkbox under the text block, past the 28px chip + 11px gap).

- **Checkbox** — reuse `AppCheckbox` at its `18 × 18` size; do **not** redesign. Bound to `excludeAionPaths`, **checked by default**.
  - Checked: box fill `AionColors.primary`, `AionRadius.sm - 1`→`5`, check glyph `#FFFFFF` (Phosphor `Check` Bold or the existing `AppCheckbox` painter), stroke `~3`.
  - Unchecked: fill `AionColors.surface`, `Border.all(width: 1.5, color: borderStrong)`.
  - Hover: box border → `AionColors.primary` (unchecked) / fill → `primaryHover` (checked); `MouseRegion` + `GestureDetector`, no `InkWell`.
  - Focused: `2px` focus ring `primary.withOpacity(isDark ? 0.30 : 0.16)` outside the box (reuse `AppCheckbox` focus treatment).
  - Pressed: fill `primaryHover`.
  - Disabled: n/a (always enabled here).
- **Label**: `AionText.body.copyWith(color: textPrimary, fontWeight: FontWeight.w500)` (Manrope 13.5–15 / w500) — "Add `.aion/` and `tickets/` to `.gitignore`". The three code fragments are inline monospace `AionText.key`-sized (JetBrains Mono 12 / w600), color `textSecondary`, **no** fill (distinguishes them from the message-row paths). Tapping the label toggles the checkbox (same `GestureDetector`).

### 2.3 Unchecked hint (conditional)

When `excludeAionPaths == false`, append a third row inside the banner (`gap: 12` above it, but pull `margin-top: -2` to tighten). This is the **only** non-notice accent in the banner and it is deliberately low-key — a hint, not an alarm:

- `Row`, `crossAxisAlignment: center`, `gap: 7`, `padding: EdgeInsets.only(left: 39)`.
- Icon: **Phosphor `Warning` (Light)**, size `13`, color `AionColors.warning`.
- Text: `AionText.time`-weight caption in Manrope — use `AionText.bodySm.copyWith(fontSize: 12, color: textMuted)`, `height: 1.4` — "Aion's files will be committed to your repo unless you exclude them yourself."
- The banner's fill/border **do not change** — it stays notice-tinted. Only this hint line appears. (Rationale from brief: "inform, don't block"; the hard warning, if any, belongs at submit time, not here.)

### 2.4 States summary

| State | Trigger | Visual delta |
|---|---|---|
| Default (checked) | banner mounts | as §2.1–2.2, checkbox checked |
| Unchecked | user clears checkbox | checkbox empty + §2.3 hint row appears |
| Checkbox hover / focus / pressed | pointer / keyboard | per `AppCheckbox` states (§2.2) |
| Not shown | dir not a git repo, or mobile/web build | `SizedBox.shrink()` |

Both themes identical in structure; only token values differ (§1.3). Transition when the git-repo condition flips: `AnimatedSize` + `FadeTransition`, `180ms`, `Curves.easeOut`.

## 3. `CodebaseAnalysisBanner`

Inline banner mounted at the top of `TicketsListScreen`'s scroll body, above the list/board (§4.2). Full-width within the content area. One instance, four states via a single `AnimatedSwitcher` (crossfade, `200ms`, `Curves.easeInOut`).

### 3.0 Shared geometry (all states)

- Width: `double.infinity` (spans the content column; on wide viewports it sits inside the same padding as the ticket rows).
- Outer container: `Container(decoration: BoxDecoration(...))`.
  - Radius: `AionRadius.lg` (12).
  - Border: `Border.all(width: 1, color: <state border>)`.
  - Shadow: **none**.

## 5. Behavior notes

- **Once-only:** `CodebaseAnalysisBanner` never reappears after any dismiss or after `done`/`failed` is cleared — enforced by the persisted `project.codebaseAnalysisDismissed` flag, checked before build.
- **Transitions:** gitignore banner mount/unmount = `AnimatedSize` + `FadeTransition` `180ms easeOut`; codebase state changes = `AnimatedSwitcher` crossfade `200ms easeInOut`; running status line = inner `AnimatedSwitcher` `120ms` fade.
- **No Material:** spinners = `AppSpinner` (`CustomPaint`), progress bar = hand-built `Container` + `FractionallySizedBox`, checkbox = `AppCheckbox`, buttons = `AppButton`. No `SnackBar`/`ScaffoldMessenger` for the outcome — the `done`/`failed` states ARE the inline confirmation.
- **Accessibility:** icon chips are decorative (`ExcludeSemantics`); the banner titles are the semantic labels; the checkbox and every button expose `Semantics(button: true)` with checked/label state; dismiss × has `Semantics(label: 'Dismiss')`.
