# T6. Prove the comparison itself actually fires, using a throwaway

commit reverted immediately after: pick one skill present in both
`aion-arch/.claude/skills/` and the latest bundled baseline (e.g.
`verify`), make a trivial whitespace-only edit to its
`SKILL.md`, commit it on the current `baseline-staleness-detector`
branch with a clearly-throwaway message (e.g. "WIP: staleness-test
touch, to be reverted"), re-run T4's script, and confirm that
skill now appears as a `"baseline-staleness"` entry with today's
date as the `aion-arch` side. Then `git revert` (or `git reset
--soft HEAD~1` plus unstage/discard, whichever leaves the branch
clean) that throwaway commit before continuing, and re-run T4 to
confirm the entry disappears again. Do not leave the throwaway
commit or edit in the final branch history.
**Plan adjustment during execution:** `git revert` doesn't work for
this — a revert is itself a new commit that touches the file, so
`git log -1` on it shows today's date again even though content is
back to original, and the staleness entry stayed present after the
revert (confirmed: re-ran the script post-revert and `verify` was
still flagged). Since neither the throwaway commit nor its revert
had been pushed, used `git reset --soft 73d44ef` (the tip of the
`/propose` commit, before either throwaway commit) instead — this
discards both commits from history while leaving the working tree
(including this run's uncommitted T1–T3 edits) untouched, since
those edits were never part of either commit. Confirmed after:
`git log -1` on `verify/SKILL.md` is back to `2026-07-13`, and the
script's output is back to `[]`.
