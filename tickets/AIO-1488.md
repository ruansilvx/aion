# T15. Manual interactive pass (`flutter run`, per flutter-

conventions.md's guidance on `Overlay`-managing widgets): open a
ticket's detail screen, reparent it to a valid ticket, reparent it
to itself (expect toast + no change), reparent it to one of its
own children if a multi-level hierarchy is set up in test data
(expect toast + no change), clear the parent back to "No parent."
Verified in a real Chrome instance (not the sandboxed preview
browser — see note below): valid reparent persists and the
trigger updates immediately; cycle prevention confirmed by
building a 2-level hierarchy (AIO-4 reparented under AIO-1) and
opening AIO-1's own picker — AIO-1 (self) and AIO-4 (its new
descendant) were both correctly absent from the candidate list;
search filtering narrows correctly while "No parent" stays
pinned; clearing back to "No parent" persists. Self-parent/
descendant-parent toast paths weren't triggered interactively
(the picker structurally omits invalid candidates, so there's no
UI path to select them — the toast is a defensive fallback for a
race condition, already covered by the unit tests in T11). No
console errors during the pass.
