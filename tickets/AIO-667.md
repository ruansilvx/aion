# `DecisionNodeForm` (`lib/features/providers/presentation/widgets/decision_node_form.dart`)

- [x] `_ConditionPicker`'s `items` in `DecisionNodeForm.build` becomes
      `[...decisionConditionsFor(automationContext), if
      (ruleBuilderConditionSpec(automationContext) case final spec?)
      spec]`. Per design.md (Component Spec) §2 "Custom rule" entry in
      the condition picker.
- [x] When `_condition?.id == ruleBuilderConditionId`, render the
      field/operator/value trio described in design.md §3 in place of
      the existing `for (final spec in _condition!.parameterSpecs)`
      loop (which naturally renders nothing for this spec, since
      `parameterSpecs` is empty) — field `SelectionMenu<DecisionFieldSpec>`,
      operator `SelectionMenu<DecisionRuleOperator>` (options from
      `operatorsFor(field.type)`), value control (`AppTextField` +
      `digitsOnly` for `integer`, `SelectionMenu<bool>` for `boolean`).
      Changing the field resets operator/value to
      `defaultRuleConditionParams`-equivalent defaults for the new
      field's type. Per design.md (Component Spec) §3 `RuleFieldGroup` —
      the Field / Operator / Value trio (layout §3.1, field picker §3.2,
      operator picker §3.3, value slot §3.4, states §3.5, save gating
      §3.6).
- [x] `_save()`: when `_condition!.id == ruleBuilderConditionId`, build
      `conditionParams` from the trio's local state instead of
      `_paramControllers`.
- [x] Add an operator display-label helper (short symbol/word per
      `DecisionRuleOperator` value, per design.md §3) — reused by both
      the operator picker's `itemLabel` and `decisionNodeSummary`. Label
      text and chip symbols per design.md (Component Spec) §1.2
      Operator catalog.
