# Spec Delta: coding-execution-reliability-and-safety

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/README.md`, `aion-arch/specs/projects.md`, `aion-arch/specs/providers.md`, `aion-arch/specs/release.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (36/41 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **Worktree isolation for coding execution.** Every coding-execution run
  creates a dedicated `git worktree` (`GitRepositoryClient.createWorktree`)
  on a fresh branch (`aion/task-<taskId>`) in a temp directory, runs
  `flutter pub get` in it once, and points every model turn's
  `workingDirectory` at the worktree instead of `Project.rootPath`. The
  worktree (not the branch) is removed in a `finally` block regardless of
  outcome. The developer's real checkout (`Project.rootPath`) is never
  touched by a coding-execution run.
- **`GitRepositoryClient.createWorktree`/`removeWorktree`/`push`** — new
  methods on the existing `core/git/git_repository_client.dart` class.
- **New `GitHubCliClient`** (`core/git/github_cli_client.dart`) —
  `openPullRequest` wraps `gh pr create`, returning the created PR's URL.
- **New `FlutterVerifier`** (`core/build/flutter_verifier.dart`) —
  `analyze` wraps `flutter analyze`, returning a pass/fail result plus raw
  output.
- **Two-turn implement → verify → PR split.** The implementation turn ends
  with `IMPLEMENTATION: DONE` and no longer opens a PR itself. Aion then
  runs `FlutterVerifier.analyze` in the worktree (no model call). Only on
  a clean pass does Aion itself (`GitRepositoryClient.push` +
  `GitHubCliClient.openPullRequest`, no model call) push the branch and
  open the PR, posting a system comment ending `EXECUTION: PR_OPENED
  <url>`.
- **Retry-on-verify-failure, gated by a new `AutomationContext.
  codingExecutionRetry`.** `auto` retries automatically via a corrective
  turn (the analyze output fed back to the model), capped at 2 attempts;
  once exhausted, treated as `gated` regardless of configured value
  (mirrors the existing overage-forces-`gated` precedent). `gated`
  surfaces a one-shot `TicketsErrorReason.executionVerificationFailed`
  toast plus the failure banner (below); `manual` only ever surfaces via
  the banner's retry control, no toast.
- **New `TicketsErrorReason.executionVerificationFailed`** — one-shot
  toast, same shape as the existing `executionBudgetOverageDetected`.
- **New `AgentToolUseEvent`** on `AgentModelClient` (`core/contracts/
  agent_model_client.dart`) — a non-terminal `AgentEvent` carrying a tool
  name and short summary, parsed by `ClaudeAgentSdkClient` from a new
  `{"type":"tool_use","name","summary"}` NDJSON line `agent_bridge/
  index.mjs` now emits per tool-use content block (previously discarded).
- **`ChatCubit.runChatTurn` gains `onToolUse`** — invoked per
  `AgentToolUseEvent`, mirroring the existing `onOverageDetected` shape.
  **`ChatState.ChatLoaded` gains `currentToolUse`** (`String?`) — a live
  "Running `<tool>`..." status string, cleared on the next text chunk or
  on completion.
- **`TicketDetailLoaded` gains `executionFailureReason`
  (`String?`) and `executionCanRetry` (`bool`)**, Task-only — computed in
  `getTicketById` from the most recent coding-execution chat's most
  recent comment (verify-gate failure, hard error, or an orphaned/stalled
  run with no terminal reply at all). Unlike `isExecuting`/
  `executionQueuePosition`, these survive an app restart, since they're
  derived from the persisted comment thread rather than in-memory queue
  state.
- **`TicketsCubit.retryCodingExecution(Ticket task)`** — new public
  method; re-enters the coding-execution flow for `task` from scratch
  (fresh worktree/branch). The failure banner's manual-retry action, and
  what the `gated`/exhausted-`auto` toast links to.
- **Unified Task-detail failure banner.** `_CodingExecutionSection`'s
  existing mutually-exclusive if/else chain (running / queued / awaiting-
  review) gains a fourth branch for `executionFailureReason != null`,
  checked before the awaiting-review branch. A new `_ExecutionActionBanner`
  widget, parameterized by tone (`success`/`failure`)/message/action,
  replaces `_ExecutionReadyForReviewBanner` as the single component
  backing both the existing ready-for-review state and the new failure
  state — not two separate banners.
- **Live tool-use indicator.** `_ExecutionRunningHint` (shown while
  `isExecuting`) additionally renders `ChatState.currentToolUse`, when
  available, as a secondary line below its existing rotating-gear row.
- **Settings gains a third `_AutomationSection` instance**, "Coding-
  Execution Retry," keyed to the new `AutomationContext.
  codingExecutionRetry`.

## MODIFIED

- **`_assembleExecutionContext`** no longer instructs the model to open a
  pull request, and no longer ends with `EXECUTION: PR_OPENED`/`NO_PR` —
  it now ends with `IMPLEMENTATION: DONE`. PR-opening moves entirely to
  Aion's own post-verify-pass logic (see ADDED, above).
- **`_executionSucceededWithPr`** now matches the `EXECUTION: PR_OPENED`
  line regardless of whether the comment's `authorType` is `ai` or
  `system` — previously required `ai` specifically, but the line is now
  posted by Aion itself (`system`) rather than the model.
- **`_runCodingExecution`** is restructured around the worktree lifecycle
  and the two-turn split described above; its single-turn, PR-in-the-
  same-call-as-implementation shape is replaced entirely. The existing
  post-completion `AutomationContext.codingExecution`-gated status-flip
  logic (`inProgress` → `inReview`) is unchanged, still runs only once a
  PR is confirmed (now via the relaxed author-agnostic check above).

## Out of scope (see proposal.md)

- Scoped `flutter test` as part of the verify gate (analyze only, this
  round).
- Worktree disk-bloat optimization (symlinking `.dart_tool`/`build`) —
  each run pays a fresh `flutter pub get`.
- Structured per-tool-call detail beyond a name + short summary in
  `AgentToolUseEvent`.
- Cancelling an in-flight or queued execution run.
- True concurrent (multi-slot) execution.
- A GitHub-agnostic PR-hosting abstraction — `GitHubCliClient` wraps `gh`
  directly.
