# `lib/features/tickets/data/repositories/git_projecting_ticket_repository.dart`:

- `trashTicket`/`restoreTicket`: change return type to
`Future<List<String>>`; capture `_inner.trashTicket(id)`/
`_inner.restoreTicket(id)`'s returned list, pass it to a new
`_projectAllOrSwallow(affected, eventLabel)` (see below), then
`return affected;`.
- Add `_projectAllOrSwallow(List<String> ids, String eventLabel)`:
re-fetches each id via `_inner.getTicketById` (dropping any
`null`), calls `_projector.projectBatch(tickets, _rootPath,
eventLabel)`, wrapped in the same `on ProcessException`/
`on FileSystemException` swallow `_projectOrSwallow` used.
**Deviation from design.md**: `_projectOrSwallow` turns out to
have no remaining callers once `trashTicket`/`restoreTicket`
switch to `_projectAllOrSwallow` (it was never called from
anywhere else) — `flutter analyze` flags it `unused_element`.
Removed it entirely rather than leaving dead code, folding its
rationale dartdoc into `_projectAllOrSwallow`'s own.
- Update `trashTicket`/`restoreTicket`'s own dartdoc to describe
the batched-cascade behavior and reference `_projectAllOrSwallow`
instead of `_projectOrSwallow`.
- Class-level dartdoc: update the "Projects exactly the six
events..." paragraph to note `trashTicket`/`restoreTicket` now
project every cascaded ticket, not just the named one.
