# Spec Delta: Ticket Delete Entry Points

**Reconciled 2026-09-03:** this delta is about *where* delete is reachable from (`TicketOverflowMenu` on the list tile and board card), which is still accurate — `TicketOverflowMenu` remains the shared entry point for delete/trash flows per current `aion-arch/specs/tickets.md`. What changed underneath it is the action itself: at the time of this delta it triggered the hard-delete `TicketRepository.deleteTicket`; it now triggers `trashTicket` (see the Ticket Deletion spec ticket's reconciliation note for that supersession). The entry-point structure this delta actually claims is unaffected.

Delta against `aion-arch/specs/tickets.md`. On `/archive`, these
changes merge into that file's prose (not appended as a changelog).

## ADDED

### Presentation

- Delete entry point on `TicketListTile` (list view row) — the
  `TicketOverflowMenu` trigger, identical "Delete ticket" → confirm →
  delete flow as `TicketDetailScreen`.
- Delete entry point on `TicketBoardCard` (board view card) — same
  `TicketOverflowMenu` trigger, alongside the existing
  `MoveToStatusMenu`.
- `TicketOverflowMenu` (`presentation/widgets/ticket_overflow_menu.dart`)
  — extracted from `ticket_detail_screen.dart` into a shared widget,
  now used by three screens.

### Localization

- New `app_en.arb` key: `ticketOverflowMenuLabel(String ticketId)` —
  "More actions for {ticketId}".

## MODIFIED

- `TicketsCubit.deleteTicket(String id)` — now captures the state
  active before the call and branches recovery/success on it:
  `TicketDetailLoaded` callers get the original detail-screen behavior
  (`TicketDeleted()` on success, re-emitted `TicketDetailLoaded` on the
  hasChildren block); any other (list/board-shaped) caller instead gets
  a refreshed `TicketsLoaded(tickets)` on success and on the
  hasChildren block, so the list/board UI never falls into a
  blank/stale state.
- `TicketOverflowMenu` — moved from `ticket_detail_screen.dart`
  (feature-local) to `presentation/widgets/ticket_overflow_menu.dart`
  (shared). Its semantic label changes from the fixed
  `ticketDetailOverflowMenuLabel` ("More actions") to the parameterized
  `ticketOverflowMenuLabel` ("More actions for {ticketId}").
- `TicketsListScreen` — its `BlocBuilder` gains a `TicketDeleting` arm
  (spinner) and is wrapped in a `BlocListener` that shows the
  count-aware "blocked by children" toast. Covers the board view too,
  since `TicketBoardView` has no `BlocBuilder` of its own.

## REMOVED

- `ticketDetailOverflowMenuLabel` ARB key (superseded by
  `ticketOverflowMenuLabel`).

## Known gaps closed (remove from `tickets.md`'s Known Gaps list on `/archive`)

- "Deletion (`TicketDetailScreen` only, via its header `⋮` menu) is the
  only entry point — no delete affordance exists on `TicketsListScreen`
  or `TicketBoardView`."

## Unaffected (explicitly, to prevent scope creep during `/apply`)

- Blocking-on-children behavior — unchanged, still blocks rather than
  cascades.
- `ticket_links` cascade-delete behavior — unchanged.
- No undo / soft-delete / trash — still a hard, permanent delete from
  every entry point.
- No bulk / multi-select delete.
- No swipe-to-delete or other lower-friction gesture — the
  tap-through-menu-then-confirm flow is unchanged.
