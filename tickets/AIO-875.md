# **T1.** Create `lib/features/tickets/domain/utils/ticket_rollup_calculator.dart`

— `RollupNode`/`RollupResult` records and the pure `computeRollups`
function, per design.md §1.2. Bottom-up post-order computation over a
`parentId -> children` adjacency map (same shape as
`TicketsCubit._descendantIds`'s existing helper); a node with zero
live children is omitted from the returned map; a node whose own
value and every descendant's effective value are all `null` produces
`null` (not `0`) for that field; defensive `visiting`-set cycle guard
(never expected to trigger — cycles are already rejected at write
time — but must not hang on malformed data). No Flutter/drift import.
**Added post-design-sync (design.md §0.3, amended 2026-08-11):**
`RollupResult` also carries `estimateCount`/`timeSpentCount` (`int` —
count of live tickets, self + descendants, contributing a non-null
value for that metric), computed in the same walk. These two fields
are query-only — never written to drift (only `estimateRollup`/
`timeSpentRollup` are persisted, by T5/T6/T11); they exist purely for
T11's `getRollupCounts` to hand to `TicketDetailScreen`'s on-demand
count caption (design.md §1.1). File header + dartdoc on both
typedefs and the function.
