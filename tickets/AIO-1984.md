# Spec Delta: SddStage Transition Preconditions

**Reconciled 2026-09-03:** confirmed against the current `aion-arch/specs/tickets.md` "Transition preconditions" section — still a comprehensive, accurate match (domain types, `TransitionPreconditionRepository`, baseline graphs, `TicketsCubit` integration, editor UI). The identifiers the automated check flagged as missing are all present in substance but abbreviated in this section's prose (CRUD method names summarized as "per-stage graph/node CRUD" rather than spelled out one by one) or documented in a cross-referenced section (`providers.md`'s Transition-precondition editor) instead of repeated here. No drift.

Relative to `aion-arch/specs/tickets.md` (`TicketsCubit._sddStageAdvanceCheck`,
`WorkflowStatusSettingsScreen`'s SDD Stages section). See
`proposal.md`/`design.md` for full rationale.

## ADDED

- `TransitionOutcome` (`features/tickets/domain/enums/transition_outcome.dart`)
  — `allowed | blocked`.
- `TransitionBranch`/`TransitionNode`
  (`features/tickets/domain/entities/`) — a strict-tree field-check
  node: `id`, `fieldId`, `matchedBranch`/`unmatchedBranch` (each a
  pointer to another node or a terminal `TransitionOutcome`). No
  parameters, no operator — every field is a plain boolean.
- `TransitionFieldSpec`/`transitionFieldsFor`
  (`features/tickets/domain/entities/transition_field_spec.dart`) — a
  7-entry, `SddStage`-scoped field catalog:
  `mostRecentChatHasTerminalReply` (`exploring`/`verifying`),
  `hasChildren`/`storyNeedsDesignReview`/`allChildrenComplete`
  (`proposed`), `linkedDesignPageHasContent` (`designBrief`),
  `allTasksComplete`/`designSyncApproved` (`designSync`).
- `TransitionPreconditionRepository`
  (`features/tickets/domain/repositories/transition_precondition_repository.dart`)
  — `getGraph`/`getNode`/`getAllNodes`/`upsertNode`/`deleteNode`/
  `setRoot`/`seedDefaultsIfEmpty`/`onChanged`. Implemented by
  `DriftTransitionPreconditionRepository`
  (`features/tickets/data/repositories/`), backed by two new drift
  tables: `TransitionPreconditionGraphsTable`,
  `TransitionPreconditionNodesTable` (schema version 18 → 19, additive
  migration, no FK constraints).
- `evaluateTransitionGraph`/`TransitionEvalContext`
  (`features/tickets/domain/utils/evaluate_transition_graph.dart`) —
  pure evaluator returning both the outcome and (when blocked) the
  failing field's display name.
- `TransitionPreconditionConfigCubit`/`TransitionPreconditionConfigState`
  (`features/providers/presentation/cubit/`) — CRUD + strict-tree
  invariant enforcement for the editor, keyed by `SddStage`.
- `SddStagePreconditionEditorScreen`/`TransitionOutlineList`/
  `TransitionNodeForm` (`features/providers/presentation/screens/`,
  `.../widgets/`) — dual-pane (`GraphCanvas<TransitionNode>` +
  new outline list) editor per precondition-bearing `SddStage` value,
  reached from `WorkflowStatusSettingsScreen`'s SDD Stages section.
- Seeded baseline `TransitionPreconditionGraph` rows for `exploring`,
  `verifying`, `proposed`, `designBrief`, `designSync` on fresh install
  and the schema-19 upgrade path, each reproducing
  `_sddStageAdvanceCheck`'s pre-existing branch exactly (see
  `design.md` §3).

## MODIFIED

- **`TicketsCubit._sddStageAdvanceCheck`** — its `exploring`,
  `verifying`, `proposed`, `designBrief`, `designSync` branches now
  build a `TransitionEvalContext` and consult that stage's
  `TransitionPreconditionRepository` graph via `evaluateTransitionGraph`,
  instead of running hardcoded per-branch logic directly. The `null`
  and `archived` branches are unchanged. Return type changes from
  `Future<({bool canAdvance, SddStageBlockReason? blockReason})>` to
  `Future<({bool canAdvance, String? blockReason})>` — `blockReason` is
  now auto-derived text (`"Waiting on: <field display name>"`), not an
  enum value.
- **`TicketDetailLoaded.canAdvanceSddStage`/`.sddStageBlockReason`** —
  type changes from `SddStageBlockReason?` to `String?`, matching
  `_sddStageAdvanceCheck`'s new return shape (both are computed from
  the same shared check, per that check's own dartdoc — they can't
  disagree).
- **`_SddStageSection`'s "Not ready" hint row** — the `switch` over
  `SddStageBlockReason` picking one of 4 hardcoded strings is replaced
  by direct display of the auto-derived `blockReason` string.
- **`TicketsCubit` constructor** — gains an optional
  `TransitionPreconditionRepository?` parameter, following
  `WorkflowStatusRepository`'s own optional-dependency convention.
  Omitting it resolves every precondition-bearing stage to `allowed`
  (not today's hardcoded checks) — any test exercising real
  precondition behavior must supply a repository seeded with the
  baseline graphs, or assert against the new shape directly.
- **`AppDatabase`** — schema version 18 → 19, registering the two new
  tables.
- **`WorkflowStatusSettingsScreen`**'s SDD Stages section — each
  precondition-bearing stage's `_SddStageRenameRow` gains a "Configure
  precondition" affordance.

## REMOVED

- **`SddStageBlockReason`** enum and its consumption in
  `_SddStageSection`'s hint-row `switch` — replaced by auto-derived
  plain-text `String?`, per `design.md` §4.

## Explicitly NOT modified

- `AutomationConfidence`/`AutomationContext`/every shipped
  `AutomationContext` decision graph — unrelated axis.
- `TicketsCubit._codingExecutionGateCheck` (`TicketStatus`'s design
  gate) — deferred to a future fast-follow proposal (see proposal.md's
  Non-goals); structurally identical but out of scope here.
- `SddStage`'s own configurability (`SddStageConfigRepository`,
  reorder/relabel/skip) — this proposal only changes what gates
  leaving a stage, not which stages exist.
