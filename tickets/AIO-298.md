# 1. Manifest writer + `BaselineTailoringService` generalization

- [x] 1.1 Create `aion/lib/core/build/project_manifest_writer.dart` —
      `ProjectManifestWriter` with a static `write(String rootPath, String
      baselineVersion)` writing `<rootPath>/.aion/manifest.json` (creating
      the `.aion/` directory if absent), per design.md's Data model
      changes section. File header + class + method dartdocs.
- [x] 1.2 Modify
      `aion/lib/features/projects/presentation/cubit/create_project_cubit.dart` —
      `_initializeDesktopProject` calls `ProjectManifestWriter.write`
      instead of its own inline `File(...).writeAsStringSync(...)`. No
      behavior change. Update the method's dartdoc if it referenced the
      inline write directly.
- [x] 1.3 Modify
      `aion/lib/features/projects/data/services/baseline_tailoring_service.dart` —
      `tailorForDetectedStack` gains a required `BaselineManifest
      manifest` parameter, resolving the `architectureConvention`-kind
      asset from it (plain loop, no `package:collection` dependency —
      see design.md) instead of the hardcoded `0.3.0` constant; no-ops if
      none found. New `tailorNewlyIntroducedAssets({required projectId,
      required rootPath, required BaselineManifest oldManifest, required
      BaselineManifest newManifest})` per design.md's exact shape: finds
      an `architectureConvention`-kind asset in `newManifest` whose key
      didn't exist in `oldManifest` at all, skips if an override already
      shadows it, otherwise calls `tailorForDetectedStack(manifest:
      newManifest)`. Update class dartdoc to describe both methods; full
      method dartdocs on both.
- [x] 1.4 Modify
      `aion/lib/features/projects/presentation/cubit/create_project_cubit.dart` —
      `submit` fetches `_baselineRepository.getManifest(resolvedVersion)`
      before calling `tailorForDetectedStack`, passing it as the new
      `manifest` argument. Update the surrounding dartdoc if it describes
      the old hardcoded-asset behavior.
- [x] 1.5 Extend
      `test/features/projects/data/services/baseline_tailoring_service_test.dart` —
      new cases: `tailorForDetectedStack` resolves the convention asset
      from an arbitrary passed-in manifest (not hardcoded to `0.3.0`), and
      no-ops if the manifest has no `architectureConvention`-kind asset;
      `tailorNewlyIntroducedAssets` writes an override only when the
      convention asset's key is absent from the old manifest and no
      existing override shadows it, and no-ops in every other case
      (key already existed in old manifest; key already overridden; no
      `architectureConvention`-kind asset introduced at all).
