# Design: intl String Retrofit

## 1. Localization infrastructure

### `l10n.yaml` (new, repo root of `aion/`)

```yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-dir: lib/l10n/generated
output-localization-file: app_localizations.dart
output-class: AppLocalizations
synthetic-package: false
nullable-getter: false
```

`synthetic-package: false` + explicit `output-dir` is required to make the
generated output land inside `lib/` (rather than the deprecated synthetic
`flutter_gen` package) while still keeping it out of source control —
mirrors the existing `*.g.dart` convention ("generated files are NOT
committed"). `lib/l10n/generated/` is added to `.gitignore` alongside the
drift/json_serializable `*.g.dart` pattern already there.

### `pubspec.yaml` changes

- Add `intl: ^0.20.2` under `dependencies` (currently only transitive via
  `flutter_localizations`; must become direct now that app code imports
  it — same rule this project already applies to `meta`).
- Add `generate: true` under the `flutter:` section, so `flutter
  gen-l10n` output is regenerated automatically as part of the standard
  build (same spirit as `build_runner` for drift/json_serializable, but
  `gen-l10n` runs via the Flutter tool itself, not `build_runner`).

### `lib/l10n/app_en.arb` (new — base/template ARB file)

Single flat namespace, `@@locale: "en"`. Key naming: `feature` +
`screen`/`context` + `purpose`, camelCase, e.g. `ticketsListSearchHint`,
`ticketDetailEstimateLabel`. A `common*` prefix is used for strings
reused across ≥2 screens (`commonCancel`, `commonSave`, `commonRetry`,
`commonNewTicket`) — this is where the two duplicated "New ticket"/
"Create ticket" literals found in the investigation collapse into one
key each, removing the duplication rather than preserving it.

Placeholders use standard ICU/ARB metadata (`{ticketId}`, `{count}`,
`{date}`, `{input}`) with a `@key` metadata block declaring the
placeholder's `type` (e.g. `String`, `int`, `DateTime`) so `gen-l10n`
produces a typed method rather than a raw string getter.

Full key list is populated in `tasks.md`'s ARB-authoring task — not
duplicated here to avoid two sources of truth that can drift apart
during `/apply`.

## 2. Context extension

`lib/core/localization/context_localizations_x.dart` (new file):

```dart
extension AppLocalizationsX on BuildContext {
  AppLocalizations get l10n => AppLocalizations.of(this)!;
}
```

The `!` is safe here because `AppLocalizations.delegate` is always
registered on the root `WidgetsApp.router` (see below) — every
`BuildContext` in the tree can resolve it. This mirrors the terser
`context.l10n` convention common in Flutter apps, keeping call sites
short: `Text(context.l10n.ticketsListEmptyState)` instead of the verbose
`AppLocalizations.of(context)!.ticketsListEmptyState`.

## 3. Root widget wiring (`lib/main.dart`)

`_AionAppState.build()`'s existing `WidgetsApp.router(...)` call gains
the generated delegate and supported-locales list alongside the
Material delegates already there for `TextField`:

```dart
WidgetsApp.router(
  routerConfig: appRouter,
  color: aionThemeArctic.colors.primary,
  localizationsDelegates: const [
    AppLocalizations.delegate,
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
  ],
  supportedLocales: AppLocalizations.supportedLocales,
)
```

`AppLocalizations.supportedLocales` is generated from the ARB files
present in `lib/l10n/` — currently just `app_en.arb`, so it resolves to
`[Locale('en')]`. Adding a second locale later is additive: drop in
`app_<code>.arb`, re-run `gen-l10n`, done — no change to this wiring.

## 4. Enum → label mapping pattern (extended, not new)

`ticketStatusLabel()` already exists and maps `TicketStatus` to a
display string via a hardcoded switch. This change:

1. Changes its signature to accept `BuildContext` and return
   `context.l10n.*` per case instead of a literal string.
2. Adds two new sibling functions, `ticketPriorityLabel(BuildContext,
   TicketPriority)` and `ticketTypeLabel(BuildContext, TicketType)`,
   following the exact same shape — replacing today's raw
   `priority.name.toUpperCase()` / `type.name.toUpperCase()` call sites.

All three functions live together (co-located with wherever
`ticketStatusLabel` is currently defined) so the enum-label pattern
stays discoverable in one place rather than spreading across files.

## 5. Error-message localization pattern (new — the one real architectural decision in this change)

**Problem:** `Cubit`s (`TicketsCubit`, and potentially `CommentsCubit`)
currently emit states carrying a hardcoded error message string (e.g.
`TicketsError('Ticket not found')`). Cubits have no `BuildContext` —
`AppLocalizations.of(context)` cannot be called from inside a Cubit, and
passing `BuildContext` into a Cubit would break the project's
presentation/domain separation and Cubit testability (`bloc_test` has no
widget tree). The same problem applies to two exception sites:
`duration_format.dart`'s `FormatException('Not a valid duration:
"$input"')` (thrown from a plain utility function, no context) and
`ticket_detail_screen.dart`'s `FormatException("Title can't be empty")`
(thrown inside the widget, where `BuildContext` *is* available at the
throw/catch site).

**Resolution — two cases, handled differently:**

- **No `BuildContext` anywhere near the throw site** (`TicketsCubit`'s
  `'Ticket not found'`, `duration_format.dart`'s parse exception): carry
  a typed error code instead of a message string. `TicketsError` gains a
  `TicketsErrorReason` enum field (`notFound`, ...) instead of/alongside
  its raw message; `duration_format.dart`'s parse function throws a
  dedicated `InvalidDurationFormatException` carrying the raw `input`
  value as structured data, not a formatted message. Resolution to
  display text happens at the widget layer, which does have
  `BuildContext`, via new mapping functions
  (`ticketsErrorMessage(BuildContext, TicketsErrorReason)`, analogous in
  shape to the enum-label functions above) or directly via
  `context.l10n.invalidDurationError(input)` (ICU placeholder) at the
  `AppToast` call site.
- **`BuildContext` already available at the throw/catch site**
  (`ticket_detail_screen.dart`'s title-empty validation): no exception
  message localization needed at all — rework the validation to check
  the condition and read `context.l10n.titleEmptyError` directly at the
  point of use, rather than round-tripping through an exception message
  string.

`tasks.md` treats this pattern as its own task, separate from the
mechanical per-screen literal retrofits, since it changes a state shape
and a function signature rather than just swapping a `Text()` argument.

## 6. Date/duration formatting

`ticket_detail_screen.dart`'s ad hoc `_formatDate()` helper is replaced
with `intl`'s `DateFormat` (e.g. `DateFormat.yMMMd()`), which is
locale-aware by construction — this is the one place `intl` is used for
something beyond string lookup, consistent with why the package exists
at all.

## Implementation notes (deviations from the plan above, decided during `/apply`)

Reading the actual source during implementation surfaced a simpler
mechanism for §5 than originally planned, plus a few additions kept
within the same task scope:

- **No `InvalidDurationFormatException` was introduced.** Both duration
  parser call sites (`ticket_detail_screen.dart`'s estimate/time-spent
  `InlineEditableField`s) already run inside a `BlocBuilder` closure with
  `BuildContext` in scope. Instead of a new exception type, the `parser:`
  argument is a small closure that calls `parseDurationMinutes`, catches
  its plain `FormatException`, and re-throws a new `FormatException`
  built from `context.l10n.durationInvalidFormat(raw)`. Same outcome (no
  unlocalized text reaches `AppToast`), one fewer type. `duration_format.dart`
  itself still throws its original English `FormatException` — that
  message is now always caught and replaced before display, so it's
  effectively internal/dev-facing, not user-facing.
- **`durationNotSet` was never added to the ARB file.** Every real call
  site already passed `placeholder: ''` explicitly — the `'Not set'`
  default was dead code. `formatDurationMinutes`'s `placeholder`
  parameter was made `required` instead (no default value at all, since
  Dart default values must be compile-time constants and can't call
  `context.l10n`).
- **The title-empty validation still throws a `FormatException`** — it
  wasn't rewritten to avoid throwing. Its closure also already has
  `context` in scope (same `BlocBuilder`), so it just builds the
  exception from `context.l10n.ticketDetailTitleEmptyError` directly
  rather than a hardcoded string. Simpler than the original "avoid the
  throw entirely" plan, same result.
- **`l10n.yaml` omits `synthetic-package`.** The Flutter SDK in this repo
  (3.44.4) no longer honors that key (deprecated); `flutter gen-l10n`
  warned and it was removed.
- **`AppLocalizationsX.l10n` has no `!`.** §2 above shows
  `AppLocalizations.of(this)!`, but `l10n.yaml`'s `nullable-getter:
  false` makes the generated `AppLocalizations.of()` return
  non-nullable `AppLocalizations` directly — the `!` would be a
  no-op (`flutter analyze` flags it as
  `unnecessary_non_null_assertion`), so the implementation is
  `AppLocalizations.of(this)` with no assertion needed.
- **A few literals not in the original survey were found and retrofitted
  within the same tasks** (T3/T18), since they fall under those tasks'
  existing "all identified literals" scope rather than being new work:
  `app_text_field.dart`'s "  Optional" marker, and three semantic labels
  in `ticket_detail_screen.dart` ("Change type", "Edit time spent", "Edit
  description"). Also: "Create ticket" (not just "New ticket") turned out
  to be duplicated between `tickets_list_screen.dart`'s FAB semantic
  label and `create_ticket_screen.dart`'s submit button — both were
  consolidated behind a `commonCreateTicket` key alongside `commonNewTicket`.

## 7. What does *not* change

- No new widgets, no new screens, no layout changes — every retrofit
  task is a literal-for-lookup swap plus the two structural exceptions
  in §5.
- No locale-switcher UI, no `Locale` state in any Cubit — `supportedLocales`
  is fixed to `[Locale('en')]` for this slice.
- `flutter-conventions.md` gets one new paragraph (the enforcement
  convention) — no changes to existing documented patterns (BLoC
  structure, Drift shape, token usage) beyond what §4/§5 above describe.
