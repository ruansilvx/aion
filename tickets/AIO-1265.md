# Spec Delta: Native Windows Verification Pass

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/providers.md`, `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (8/8 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

None — this change adds no new app-facing behavior. It records the
result of exercising three already-shipped flows live on a native
Windows build; nothing about the app's behavior changes.

## MODIFIED

- **`aion-arch/specs/tickets.md`'s "Known gaps" section** — the native
  Windows verification bullet is reworded on `/archive` from:

  > A native Windows desktop build has been verified end-to-end for ticket
  > creation and git projection (see
  > [Embeddings, sync status & git projection](#embeddings-sync-status--git-projection-desktop-only));
  > broader native-target coverage (other flows, other platforms) still
  > has not been. Relatedly, the `flutter-web` preview target uses an
  > in-memory Drift/sqlite3-WASM DB (`WasmStorageImplementation.inMemory`,
  > since the browser worker feature it needs for persistent storage isn't
  > available there) — data does not survive a full page reload in that
  > environment specifically; this is a property of the preview target,
  > not the app.

  to:

  > A native Windows desktop build has been verified end-to-end for
  > ticket creation, git projection (see
  > [Embeddings, sync status & git projection](#embeddings-sync-status--git-projection-desktop-only)),
  > Board drag-and-drop (the desktop `Draggable` mouse path, both
  > directions), and the Trash delete → confirm → restore round trip.
  > Broader native-target coverage still has not been — in particular,
  > the accessibility keyboard walkthrough and the mobile
  > `LongPressDraggable` touch path (see this section's other bullets)
  > remain unverified on any real device. Relatedly, the `flutter-web`
  > preview target uses an in-memory Drift/sqlite3-WASM DB
  > (`WasmStorageImplementation.inMemory`, since the browser worker
  > feature it needs for persistent storage isn't available there) —
  > data does not survive a full page reload in that environment
  > specifically; this is a property of the preview target, not the app.

- **`aion-arch/specs/providers.md`'s "Known gaps" section** — the
  `ProviderRegistry` single-implementation bullet gains one clause on
  `/archive`, appended after its existing text ("...Mobile/web have no
  working provider at all today, since Agent SDK is desktop-only
  (`dart:io Process`)."):

  > The one connection this does support — Settings' live `Test
  > Connection` ping against `ClaudeAgentSdkProvider` — has now been
  > verified working end-to-end on a native Windows build (`CHECKING` →
  > `CONNECTED`, confirming the `agent_bridge/` Node subprocess spawns
  > and replies correctly), the first live verification of this path on
  > any target. It has still only been exercised on Windows; macOS and
  > Linux desktop remain unverified, and it is structurally unreachable
  > on mobile/web per the note above.

None.
