# Post-implementation fix (found during manual verification)

Not part of the original plan — surfaced by the mandatory manual
interactive pass for `TicketColumnsPopover` (an `Overlay`-managing
widget; see `aion-arch/CLAUDE.md`'s Testing section), run on a native
Windows desktop build per this project's desktop-only verification
convention.

- [x] **T22.** Tapping the Columns trigger crashed with a Flutter
      "setState()/markNeedsBuild() called during build" assertion,
      thrown from `TicketColumnsPopover`'s `didUpdateWidget` calling
      `_overlayEntry?.markNeedsBuild()` synchronously — the `OverlayEntry`
      lives outside this widget's own subtree (under the root
      `Overlay`), so marking it dirty while an ancestor
      (`_TicketFilterAndSortSection`) is mid-build is invalid regardless
      of timing. Reproduced identically on the **pre-existing**
      `TicketFilterPopover` (same `didUpdateWidget` pattern) — not a new
      defect, a latent one this change's manual pass happened to
      surface. `TicketSortPopover` had already independently discovered
      and fixed this exact bug (deferring via
      `WidgetsBinding.instance.addPostFrameCallback`), but the fix was
      never back-ported to `TicketFilterPopover`. Fixed in both
      `ticket_columns_popover.dart` (new file, T11) and
      `ticket_filter_popover.dart` (pre-existing file, out of this
      change's original scope but necessary for Filters/Columns to be
      usable at all on desktop) using the same established pattern.
      Verified via `flutter analyze`, full `flutter test`, and a live
      interactive pass on `build\windows\x64\runner\Debug\aion.exe`:
      Filters/Sort/Columns all open without crashing; toggling columns
      updates the board live; the hidden-column set and the view-mode
      choice both survive a full app restart.
