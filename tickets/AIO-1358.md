# Cross-feature contract (new — pages needs tickets' data)

- [x] T7. Modify `features/tickets/presentation/cubit/tickets_cubit.dart`:
      change `createTicket`'s and `updateTicket`'s return type from
      `Future<void>` to `Future<Ticket>`, returning the persisted/refreshed
      ticket, in addition to still emitting the same Bloc state as before.
      Update existing callers only if the changed signature requires it
      (existing `TicketDetailScreen`/`CreateTicketScreen` call sites may
      ignore the return value — verify with `flutter analyze` that no
      caller breaks). Update the methods' dartdoc `@returns` sections.

- [x] T8. Create `core/contracts/page_ticket_provider.dart`:
      `PageTicketProvider` abstract interface (`getPage`,
      `loadPageRelations`, `createPage`, `updatePage`, `trashPage`,
      `getValidParentCandidatesForPage`) and the `PageRelations` DTO
      (`childDocs`/`linkedTickets`/`backlinks`, all `List<Ticket>`,
      `Equatable`), per design.md. File header identifying it as a
      `core/contracts` cross-feature interface. Dartdoc on the interface,
      every method, and `PageRelations`, following `ActiveProjectProvider`
      (`core/contracts/active_project_provider.dart`)'s existing doc
      convention (name the implementing class + file, cite this change's
      design.md).

- [x] T9. Create `features/tickets/data/page_ticket_provider_impl.dart`:
      `PageTicketProviderImpl implements PageTicketProvider`, constructed
      with `TicketsCubit`, `TicketRepository`, `TicketLinkRepository`.
      `getPage`/`loadPageRelations`/`getValidParentCandidatesForPage` read
      directly via the repositories (mirroring what
      `TicketsCubit.loadDocumentRelations`/`getValidParentCandidatesForType`
      already do internally); `createPage`/`updatePage`/`trashPage`
      delegate to `TicketsCubit.createTicket`/`.updateTicket`/
      `.trashTicket` (using T7's new return values). File header + dartdoc
      per design.md.

- [x] T10. Create `features/tickets/data/page_ticket_provider_impl_test.dart`:
      mocktail-mocked `TicketsCubit`/`TicketRepository`/`TicketLinkRepository`,
      confirming reads call the repositories and writes delegate to
      `TicketsCubit`'s methods with the right arguments, per T9.
