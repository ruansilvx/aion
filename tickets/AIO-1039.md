# Spec Delta: intl String Retrofit

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/tickets.md` "Localization" section — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification (e.g. bare `_foo` vs `TicketsCubit._foo`), line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. l10n enforcement convention, `context.l10n`, and delegate wiring all confirmed unchanged.

## ADDED

- Localization infrastructure: `l10n.yaml`, `lib/l10n/app_en.arb` (base
  template), generated `AppLocalizations` (via `flutter gen-l10n`,
  gitignored output under `lib/l10n/generated/`), `intl` as a direct
  dependency.
- `AppLocalizationsX` `BuildContext` extension
  (`lib/core/localization/context_localizations_x.dart`) exposing
  `context.l10n` as the app-wide call-site convention for reading
  localized strings.
- `ticketPriorityLabel(BuildContext, TicketPriority)` and
  `ticketTypeLabel(BuildContext, TicketType)` label-mapping functions,
  extending the existing `ticketStatusLabel()` pattern to the two ticket
  fields that previously rendered raw enum identifiers.
- `TicketsErrorReason` enum (or equivalent typed error code) on
  `TicketsError`, and `InvalidDurationFormatException` (structured, no
  baked-in message) replacing the current plain `FormatException` thrown
  by `duration_format.dart`'s parser.
- `ticketsErrorMessage(BuildContext, TicketsErrorReason)` mapping
  function resolving error codes to localized text at the widget layer.
- A documented convention in `flutter-conventions.md`: all new
  user-facing text in presentation-layer code must be read via
  `context.l10n` — no new hardcoded string literals. Enforced by review,
  not lint/CI.

## MODIFIED

- `lib/main.dart` (`AionApp`/`_AionAppState.build()`): `WidgetsApp.router`
  now includes `AppLocalizations.delegate` in `localizationsDelegates`
  and uses `AppLocalizations.supportedLocales` (currently `[Locale('en')]`)
  instead of the previous hardcoded single-locale list.
- `ticketStatusLabel()`: signature changes from a pure enum→string
  switch to `(BuildContext, TicketStatus) → String`, sourcing each case
  from `context.l10n` instead of a hardcoded literal.
- Every screen/widget under `lib/features/tickets/presentation/`
  (`tickets_list_screen.dart`, `tickets_board_view.dart`,
  `ticket_detail_screen.dart`, `create_ticket_screen.dart`,
  `inline_editable_field.dart`) and the shared primitives in
  `lib/core/widgets/` (`app_header.dart`, `app_spinner.dart`,
  `app_dropdown.dart`, `app_text_field.dart`) that previously rendered
  hardcoded string literals now source that text from
  `AppLocalizations` via `context.l10n`. No visual, layout, or behavioral
  change — text content and rendering are identical, only the text's
  source changed.
- `TicketsCubit`'s `TicketsError('Ticket not found')` emission now
  carries a `TicketsErrorReason` value instead of (or in addition to,
  transitionally) a raw hardcoded message string; the message is
  resolved to display text only at the widget layer.
- `duration_format.dart`'s duration parser throws
  `InvalidDurationFormatException` (carrying the raw invalid input as
  data) instead of a `FormatException` with a baked-in English message;
  its formatter's `placeholder` default value is no longer a hardcoded
  `'Not set'` — callers now pass a localized string explicitly.
- `ticket_detail_screen.dart`'s date display uses `intl`'s `DateFormat`
  instead of the previous ad hoc `_formatDate()` helper.
- Two duplicated string instances ("New ticket" appearing separately in
  `tickets_list_screen.dart` and "Create ticket" in
  `create_ticket_screen.dart`) are consolidated behind shared
  `common*`-namespaced ARB keys.

## REMOVED

- None. No user-facing behavior is removed — this change is a source
  (literal → localized lookup) swap plus the structural error-code
  changes in §MODIFIED, not a feature change.
