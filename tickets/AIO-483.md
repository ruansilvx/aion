# Extraction (prep — no new files beyond the extraction target)

- [x] T1. Extract the existing ticket-metadata rendering (everything
      currently inside `ticket_detail_screen.dart`'s shared
      `SingleChildScrollView`'s `ContentMaxWidth` column, from the
      header-fields `BlocBuilder<TicketsCubit>` through
      `BacklinksSection` — **excluding** the trailing chat-or-comments
      `BlocBuilder` block) into a new file,
      `features/tickets/presentation/widgets/ticket_metadata_section.dart`,
      as a **public** `TicketMetadataSection extends StatelessWidget`
      — public and its own file (not a screen-private class) because
      T4's collapsing header renders it from a different file. Follows
      the same "existing folder, one-widget-per-file" convention
      already used for `ChatMessageBubble`/`ChatTranscriptPane`/
      `ChatComposeField` in this change. It reads whatever Cubits/
      state it already reads today via `BuildContext`
      (`TicketsCubit`, `TicketLinkRepository`, etc.) — no behavior
      change, content and internal layout untouched, purely relocated;
      constructor takes only `ticket` (design.md §8.4). File header +
      full class/method dartdocs. Used by both the chat branch (T4, via
      the collapsing header) and the non-chat branch (T6) of
      `ticket_detail_screen.dart`.
      **Deviation:** the original content also depended on four
      `_TicketDetailScreenState`-private members
      (`_isSyncable`/`_automationConfidence`/`_advanceSddStage`/
      `_maybeAutoAdvanceSddStage`) that a separate-file widget can't
      reach. `_isSyncable`'s logic is reimplemented locally (self-
      contained, no state dependency); the other three are threaded
      through as new required constructor parameters
      (`automationConfidence`, `onAdvanceSddStage`,
      `onMaybeAutoAdvance`) supplied by the caller — so the constructor
      ends up wider than "only `ticket`," not narrower behavior.
