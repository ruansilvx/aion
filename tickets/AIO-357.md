      the Set-not-queue divergence.
- [x] T5. Same file — `_spawnStageChat` removed; replaced by
      `_createStageChat(Ticket parent, SddStage stage)` (the
      `await`ed chat-creation + context-comment half) and
      `_runStageChatTurn(Ticket parent, SddStage stage, String chatId)`
      (the `unawaited` `ChatCubit.runChatTurn` half, with a `catch` that

      `_inFlightStageAdvanceIds` on both success and failure) (design.md

      dartdoc content (design-Page side effect, model-per-phase
      resolution) split across the two.

      early no-op if `ticket.id` is already in
      `_inFlightStageAdvanceIds`; on success, adds `ticket.id` to the
      set, re-emits `TicketDetailLoaded(isAdvancingStage: true)`, calls

      the resulting chat id to the set too, fires
      `unawaited(_runStageChatTurn(...))`, returns the chat id. Rewrite
      the method's dartdoc: contract (`Future<String?>`) is unchanged,
      but note it now resolves after chat creation, not after the first
      AI reply.

      `sddStageFailureReason`/`sddStageCanRetry` to `epic`/`story` only.
