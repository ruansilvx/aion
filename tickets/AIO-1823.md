# T5. Create `aion/.github/workflows/release.yml` — triggers on

`v*.*.*` tag push. `build-windows` job (windows-latest): checkout,
`subosito/flutter-action`, `flutter pub get`, `flutter build
windows --release`, `choco install innosetup -y`, run `ISCC.exe`
against T2's script passing `/DAppVersion=<tag-without-v>`, upload
the resulting installer as a build artifact. `build-linux` job
(ubuntu-latest): checkout, `subosito/flutter-action`, install
`ninja-build`/`libgtk-3-dev`, `flutter pub get`, `flutter build
linux --release`, run T4's script with the tag's version, upload
the resulting AppImage as a build artifact. `publish-release` job
(needs both): downloads both artifacts, extracts the pushed tag's
section from T1's `CHANGELOG.md` (split on `## [` headers), and
runs `gh release create <tag>` attaching both artifacts with the
extracted section as the release body. No model-API credentials
anywhere in this workflow.
