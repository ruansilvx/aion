# Delta spec: multi-project-hub

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/projects.md` text — every distinctive symbol/behavior this delta names is still present and accurate (7/7 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Target current-state file on archive: `aion-arch/specs/projects.md` (new
file — no `projects` spec exists yet). Also patches `aion-arch/specs/`'s
implicit single-project assumption wherever it appears (none of the
existing spec files state it explicitly today, so no other file needs a
MODIFIED entry).

## ADDED

### Project isolation

- A **`Project`** is the unit of isolation in Aion: a `name`, a
  `storageKey`, an optional `rootPath` (desktop only), a pinned
  `baselineVersion`, `createdAt`, `lastOpenedAt`.
- Each project has its own drift database, addressed by `storageKey`
  (desktop/mobile: real file path under the project or app-documents
  directory; web: an isolated WASM/OPFS database name). No ticket, board,
  chat, or post data is shared across projects.
- Desktop-only: each project additionally gets its own git repository at
  `rootPath`, initialized (empty) at project creation. Event-triggered
  commit content (per `project.md`'s Storage Model) is not implemented by
  this change — see Open questions.
- A separate, single, non-project-scoped **registry database** lists all
  known projects and their metadata. It is the only drift state that
  exists before any project is opened.

### Baseline package + override resolution

- A **baseline** is a versioned, app-bundled manifest of default skills,
  model/provider config, and architecture-convention references
  (`assets/baseline/<version>/manifest.json`).
- Every project pins one baseline version at creation time. The pin is
  immutable through this change's UI (no upgrade flow ships yet).
- A project may locally override individual baseline items by name via
  files under `<rootPath>/.aion/overrides/` (desktop only in this
  change). Resolving "effective config" for a project merges the pinned
  baseline with any present overrides, override-wins by matching key.
  This is a read-time merge — no override-authoring UI ships in this
  change.

### Hub screen (new entry point)

- `/hub` is the app's initial route. It lists all known projects
  (empty-state if none exist yet), and offers "New Project".
- Selecting a project's "Open" action makes it the active project and
  navigates into the existing ticket/board workspace (now nested under
  `/workspace`).
- The workspace exposes a "Switch Project" action that returns to `/hub`
  without closing the app.
- Removing a project from the Hub removes only its registry entry — its
  on-disk data (desktop) or storage namespace (mobile/web) is left
  intact and is not currently reachable again through the UI once
  removed (recreating a project with a matching path/storageKey is not
  supported by this change).

### Active-project switching (runtime behavior)

- Switching the active project is a live operation — no app restart.
  The previously active project's database connection is closed and its
  entire workspace UI subtree is torn down and rebuilt against the newly
  active project before the workspace becomes interactive again.
- `lastOpenedAt` is updated on the registry entry each time a project is
  opened.
- Navigating to any `/workspace/...` route while no project is active
  redirects to `/hub`.

## MODIFIED

### Storage Model (`project.md`, superseding the single-instance framing)

- The existing three-layer storage model (drift live state, embedding
  semantic memory, git event-triggered version history) is unchanged in
  mechanism but is now explicitly **scoped per project** rather than to
  one global Aion instance. This change implements the drift-scoping and
  git-repo-initialization halves of that; embedding bundling and the
  ticket↔Markdown git sync engine remain as described in `project.md`
  today and are not modified by this change (tracked separately — see
  Open questions).

## REMOVED

- The implicit single global `AppDatabase` location. `AppDatabase` no
  longer opens one fixed path/WASM-db-name; it always opens against
  whichever `Project` is currently active (or the registry database,
  which is a separate, distinct connection — see ADDED above).

## Open questions (not resolved by this change, tracked for follow-up)

- Mobile/web project-scoped git version history — deliberately out of
  scope; only drift-level isolation ships for those platforms in this
  change.
- Baseline version upgrade flow for an existing project.
- Override-authoring UI.
- Whether removing a project should ever offer to also delete its
  on-disk data / storage namespace.
- Bundled on-device embedding model and ticket↔Markdown git sync
  mechanics (frontmatter schema, `resource`/`page` bidirectional
  watcher, lint/repair tooling) — tracked in
  `aion-arch/ideas/storage-model-per-project-scoping.md`, explicitly
  deferred from this change per `proposal.md`.
