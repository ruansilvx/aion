# Spec Delta: Verify-stage quality gate

**Reconciled 2026-09-03:** checked against the current aion-arch/specs/tickets.md's Transition preconditions section (the verifying stage's baseline graph) — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. verifyGateApproved is confirmed current — explicitly named in the current spec as the field added to the verifying stage's baseline graph after this mechanism first shipped, exactly matching this delta's own description.

Relative to `aion-arch/specs/tickets.md` and `aion-arch/specs/providers.md`
as they stand before this change. See those files for the current-state
prose this delta will be merged into at `/archive`.

## ADDED

- **`verifyGateApprovedField`** (`TransitionFieldSpec`, id
  `verifyGateApproved`) — wraps `TicketsCubit._verifyGateApproved`:
  whether the Verifying-stage chat's most recent AI reply contains the
  literal line `VERIFY GATE: APPROVED`. Valid for `SddStage.verifying`
  only. Added to `transitionFieldCatalog`.
- **`TransitionEvalContext.verifyGateApproved`** (`bool?`) and its
  `_fieldAccessors` entry in `evaluateTransitionGraph`.
- **`AutomationContext.verifyGateRetry`** — whether, once every fix
  Task/Bug a `VERIFY GATE: PENDING` verdict spawned reaches `done`, a
  fresh verification turn fires automatically, asks first (a "ready to
  retry verification" banner), or waits for the existing manual "Retry
  validation" action. Persisted the same `auto | gated | manual` way
  every other `AutomationContext` value is.
- **`TicketsCubit._verifyGateApproved(String storyOrEpicId)`** — the
  `verifyGateApprovedField` accessor. Mirrors `_designSyncApproved`, but
  resolves the chat-title prefix through the override-aware
  `_stagePresentName(SddStage.verifying)` rather than a hardcoded
  literal.
- **`TicketsCubit.retryVerify(Ticket verifyingChat)`** — re-runs the
  Verifying-stage chat's validation in place, mirroring
  `retryDesignSync` exactly (re-assembled context, same chat, same
  model/provider resolution via `SddStage.verifying.modelPhase`).
- **`TicketsCubit._materializeVerifyFixes(Ticket parent, String reply)`**
  — parses an optional `## Fixes Needed` fenced block out of a `VERIFY
  GATE: PENDING` reply (one `"- Task: <title>"`/`"- Bug: <title>"` line
  per fix, optional `" (blockedBy: <title>)"` suffix), creating each as a
  new child under `parent` — mirrors `_materializeDecomposition`'s
  parsing exactly, reusing its line-parsing logic.
- **`TicketsCubit._maybeRetryPendingVerify(Ticket task)`** — checked
  whenever a Task/Bug reaches a `WorkflowStatusRole.done` status
  (`updateTicketStatus`/`changeTicketStatus`, alongside the existing
  `_maybeAutoLinkToSpec` side effect): if that Task's parent Story/Epic
  is at `SddStage.verifying` with an explicit `VERIFY GATE: PENDING`
  verdict and every one of its current Task/Bug children has now reached
  `done`, resolves `AutomationContext.verifyGateRetry`'s confidence —
  `auto` fires `retryVerify` immediately (guarded against concurrent
  re-entrancy the same way `advanceSddStage`'s own spawn is);
  `gated`/`manual` surface the new UI tier below instead of firing
  automatically.
- **`TicketDetailLoaded.verifyRetryReady`** (`bool`, default `false`) and
  **`TicketDetailLoaded.verifyRetryConfidence`** (`AutomationConfidence?`)
  — computed by `TicketsCubit.getTicketById` alongside
  `canAdvanceSddStage`, read by the new UI tier below.
- **A "ready to retry verification" footer tier** in `_SddStageSection`
  (Epic/Story detail screen), rendered when `verifyRetryReady` is `true`
  — a `gated`/`manual`/`auto`-styled banner/button/note per
  `verifyRetryConfidence`, the same three treatments
  `advanceSddStage`'s existing confidence tier already uses. Takes
  priority over the generic "Not ready" hint when it applies.
- **A manual "Retry validation" bar on the Verifying-stage chat**
  (`TicketDetailScreen`), shown whenever that chat's most recent AI
  reply contains `VERIFY GATE: PENDING` — reuses the existing
  `_RetryValidationButton` widget and `chatRetryValidation` l10n key
  verbatim; structurally identical to the Design Sync chat's existing
  retry bar, available regardless of `AutomationContext.verifyGateRetry`
  confidence.
- **A schema-20 migration** (`TransitionPreconditionDao
  .upgradeVerifyingGraphIfDefault`) that upgrades an existing project's
  `verifying` `TransitionGraph` to the new two-node shape only if it's
  still the exact original single-node default (untouched by any
  project-level customization).
- **`decisionGraphContextTitleVerifyGateRetry`** and three
  `settingsAutomationVerifyGateRetry*SubLabel` l10n keys, plus
  `ticketDetailSddStageSubReadyToRetryVerify`/
  `ticketDetailSddStageRetryVerifyAction`.

## MODIFIED

- **`TicketsCubit._sddStageAdvanceCheck`'s `SddStage.verifying` branch**
  — previously shared a switch case with `SddStage.exploring`, computing
  only `mostRecentChatHasTerminalReply`. Now a separate case that also
  computes `verifyGateApproved` and passes both into
  `TransitionEvalContext`, so a project's `verifying` graph can gate on
  either or both fields.
- **`verifying`'s default seeded `TransitionGraph`**
  (`TransitionPreconditionDao.seedDefaultsIfEmpty`) — was a single node
  checking `mostRecentChatHasTerminalReply`; now a two-node tree also
  requiring `verifyGateApproved`, mirroring `designSync`'s existing
  `allTasksComplete` → `designSyncApproved` shape. Applies to fresh
  installs automatically; existing installs get the schema-20 migration
  above instead.
- **`TicketsCubit._assembleStageContext`'s `verifying`-stage prompt** —
  now additionally requests the reply end with `VERIFY GATE:
  APPROVED`/`PENDING`, and, on `PENDING`, optionally a `## Fixes Needed`
  block. The `archived`-stage prompt (Epic spec synthesis) is
  unaffected.
- **`TicketsCubit._runStageChatTurn`'s `verifying`-stage completion
  path** — now calls `_materializeVerifyFixes` when the reply contains
  `VERIFY GATE: PENDING`, mirroring the existing `proposed`-stage call
  to `_materializeDecomposition`.
- **`_GatedBanner`/`_ManualAdvanceButton`/`_AutoAdvancedNote`**
  (`ticket_metadata_section.dart`) — generalized to accept explicit
  `title`/`subLine`/`actionLabel` overrides (defaulting to their
  existing stage-derived computation when omitted), so the new "ready to
  retry verification" tier can reuse them rather than duplicating three
  near-identical widgets.
- **`TicketsCubit._designSyncApproved`** — its chat-title lookup now
  resolves the `"<display name> — "` prefix through the override-aware
  `_stagePresentName(SddStage.designSync)` (already used by
  `_createStageChat` to title the chat in the first place) instead of
  the hardcoded literal `"Design Sync — "`. Fixes a latent bug: a
  project that overrides `designSync`'s display name via
  `SddStageConfigRepository` previously made this lookup permanently
  unable to find its own chat, silently blocking `designSync →
  verifying` forever. Folded into this change since `_verifyGateApproved`
  is built as its direct sibling and must not copy the same bug forward.
- **`settings_screen.dart`'s `_confidenceSubLabel`** and
  **`decision_graph_editor_screen.dart`'s `decisionGraphContextTitle`**
  — both exhaustive `switch` expressions over `AutomationContext`; each
  gains a `verifyGateRetry` case (no dedicated Settings row, mirroring
  the existing `specAutoLink` precedent).
