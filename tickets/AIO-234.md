# `test/features/providers/presentation/screens/decision_graph_editor_screen_test.dart`

— renders both panes bound to the same `DecisionGraphConfigCubit`
state; the empty-graph state renders when the context has no root.
### Additional bugs found and fixed while writing the tests above
None of these were in the original `/verify` report — the total absence
of widget tests for this feature (itself a `/verify` finding) had hidden
all three:
- **`_ConditionPicker` (`decision_node_form.dart`) could never select a
single-item catalog's only entry.** `SelectionMenu` excludes its
`currentValue` from the offered list (by design — re-offering the
already-selected value is a wasted tap), but the picker passed
`current ?? items.first` as `currentValue`; with nothing selected yet,
that silently hid `items.first` from the menu. For
`codingExecutionRetry`/`codingExecution` — whose catalog has exactly
one entry each — this made the condition picker completely unusable
from an unselected state. Fixed with a private, non-const
`_unselectedConditionSentinel` (never `==` a real catalog entry) used
in place of `items.first`.
- **`_DecisionNodeFormState` never listened to its parameter
`TextEditingController`s.** A `TextField`'s own internal redraw on
keystroke doesn't propagate to an ancestor's `State` unless something
explicitly listens — nothing did, so `_isValid`/Save's enabled state
and the parameter field's `isError` highlight went stale after typing,
only catching up whenever some unrelated state change (e.g. switching
the condition) happened to force a rebuild. Fixed by attaching
`_onParamChanged` (a plain `setState(() {})`) to every param
controller in `_seedParamControllers`.
- **`DecisionOutlineList` had no scroll view at all**, despite design.md
§2 explicitly calling for "`Column` inside a scroll view" — any graph
tall enough to exceed the pane's height overflowed with no way to see
the rest of the tree. Fixed by pinning the header and wrapping the
tree body in a `SingleChildScrollView` (a plain equivalent to the
spec's `CustomScrollView`/`SliverList`, since this pane has no lazy-
building need).
- (Also fixed in the same pass, found by inspection rather than a
failing test: `_BranchModeToggle`'s "End here"/"Continue to condition"
segments had no overflow protection — wrapped each in `Flexible` with
`overflow: TextOverflow.ellipsis` on the label.)
