# External, optional per-project tickets repository

## What's building

An optional, per-project tickets git repository, decoupled from the
project's source-code repository. Today `Project.rootPath` is the only
filesystem path a project has; `TicketGitProjector` and five other
ticket-data services (`TicketDbReconstructionService`,
`TicketMarkdownReconciler`, `TicketRepairService`,
`TicketMarkdownWatcherService`, plus every `GitRepositoryClient` call
`TicketGitProjector` makes) all hardcode `$rootPath/tickets/...`. This
adds a second, optional location for that same `tickets/` tree, defaulting
to unset (today's behavior -- tickets stay under `rootPath`) so no existing
project changes behavior unless it opts in.

## Why

Every ticket create/status-change/etc. commits a `ticket: <id> ...`
commit into the project's own source-code git history. For `aion` (this
project, self-hosted), that's now thousands of commits mixed into real
source history -- confirmed noise, not fixable by gitignoring `tickets/`
in place (the existing `GitignoreConfirmationBanner`/`appendGitignore`
path only prevents *tracking*, it doesn't stop the projector from trying,
and doesn't apply to a project that's already tracking `tickets/`). A
dedicated repo is the only real fix, and matches the original per-project
storage-model design intent (each project was meant to get "own git repo
for both ticket data and architecture/spec history", separate from
source).

## Out of scope

- Auto-provisioning a *remote* tickets repo for a fresh project.
  `GitHubCliClient` only opens PRs today; there's no `gh repo create`/
  clone capability anywhere in the app. A fresh project's dedicated
  tickets repo stays local-only (`git init`, no remote) for now -- same
  as how the source repo itself already works.
- Migrating any project other than `aion` -- this covers `aion` as the
  concrete first adopter only, not a bulk-migration tool.

## Technical shape

- New optional path/repo concept on `Project` (name TBD during
  implementation -- e.g. `ticketsRootPath`), persisted alongside
  `rootPath` in the registry DB.
- The six `$rootPath/tickets/...` call sites read the new path when set,
  falling back to `rootPath` when not (default, backward compatible).
- Project-creation flow (`NewProjectScreen`/`CreateProjectCubit`) gains
  the choice at the same first-run moment as the existing
  `GitignoreConfirmationBanner`/`appendGitignore` decision, rather than a
  second, separate toggle.
- `aion` itself adopts this, pointed at the already-provisioned private
  repo `ruansilvx/aion-tickets` (seeded via `git subtree split` with the
  full preserved history of `aion`'s existing `tickets/` folder -- 75
  commits). No ticket-data migration needed: `TicketGitProjector` writes
  one-way DB -> file and never reads git history back, so the DB stays
  authoritative throughout the cutover.
