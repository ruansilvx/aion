# Design: Trash screen multi-select

## 1. Overview

`TrashScreen` gains a selection mode identical in spirit to
`TicketsListScreen`'s, reusing `TicketSelectionCubit` unmodified. Two new
bulk actions — Restore and Delete forever — are added, each wired
through `TrashCubit`. The two actions take different implementation
paths (see proposal.md's "Implementation split" section): Restore loops
the existing single-ticket `TicketParentTrashService.restore`; Delete
forever calls one new batch repository method,
`TicketRepository.permanentlyDeleteTickets`.

No new `TrashState` subclasses are introduced — `TrashCubit`'s existing
"no per-row in-flight state, `load()` re-fetches and re-emits after every
write" pattern (see `trash_cubit.dart`'s existing `restore`/
`permanentlyDelete`/`emptyTrash`/`purgeOldTrash`) is kept for the two new
bulk methods too.

## 2. Domain layer — `TicketRepository` interface

Add one new method, placed immediately after `permanentlyDeleteTicket`:

```dart
/// Permanently deletes every ticket in [ids] — and each one's full
/// structural subtree — in one transaction. Mirrors [emptyTrash]'s
/// transaction shape (comments → ticket_links → page_wikilinks →
/// ticket rows), scoped to [ids]'s cascade instead of the entire
/// trashed set. Returns the total number of tickets actually deleted
/// (== [ids] plus every cascaded descendant, deduplicated), mirroring
/// [trashTickets]'s return-count convention. Ids that don't exist are
/// silently skipped. Irreversible.
Future<int> permanentlyDeleteTickets(List<String> ids);
```

No other domain-layer changes. `restoreTicket` (singular) is reused
as-is by the presentation layer — no `restoreTickets` (plural) method is
added here; see §4.

## 3. Data layer — `DriftTicketRepository`

### 3.1 Generalize the existing cascade helper

`_resolveTrashCascade` (existence-filter + descendant-union, currently
shared by `trashTickets`/`previewTrashCount`) has no trash-specific
behavior — it's a generic "id plus full descendant subtree, deduplicated"
resolver. Rename it to `_resolveDescendantCascade` and update its dartdoc
to describe the broader reuse; update `trashTickets`'s and
`previewTrashCount`'s call sites to the new name. No behavior change.

### 3.2 `permanentlyDeleteTickets` implementation

```dart
@override
Future<int> permanentlyDeleteTickets(List<String> ids) async {
  final affected = await _resolveDescendantCascade(ids);
  if (affected.isEmpty) return 0;
  final affectedIds = affected.toList();
  await _db.transaction(() async {
    await _db.commentDao.deleteCommentsForTickets(affectedIds);
    await _db.ticketLinkDao.deleteLinksForTickets(affectedIds);
    await _db.pageWikilinkDao.deleteLinksForTickets(affectedIds);
    await _db.ticketDao.deleteTicketRows(affectedIds);
  });
  return affected.length;
}
```

Identical transaction shape to `emptyTrash`/`purgeTrashOlderThan`, scoped
to `_resolveDescendantCascade(ids)` instead of the entire trashed set (or
an age-filtered subset).

No `TicketDao` changes — `getDescendantIds`, `deleteTicketRows`, and the
comment/link DAOs' list-based delete methods already exist and already
support this shape (they back `emptyTrash`/`purgeTrashOlderThan` today).

## 4. Presentation layer — `TrashCubit`

Two new public methods, placed after `permanentlyDelete` and before
`emptyTrash`. Both return `Future<bool>` (`true` on success, `false`
after emitting `TrashError` on failure) — a small, deliberate deviation
from every existing `TrashCubit` method's `Future<void>` signature,
needed so `TrashScreen` can gate a summary toast on genuine success
without risking a false-positive toast on a swallowed exception (see
§7.3).

```dart
/// Restores every ticket in [ids] via [TicketParentTrashService.restore]
/// (looped, not batched — see proposal.md's "Implementation split"
/// section for why this is correctness-equivalent to a real batch call
/// here), then reloads the trash list. Returns `true` on success,
/// `false` (after emitting [TrashError]) on failure.
Future<bool> restoreTickets(List<String> ids) async {
  try {
    for (final id in ids) {
      await _parentTrashService.restore(id);
    }
    await load();
    return true;
  } catch (e) {
    emit(TrashError(e.toString()));
    return false;
  }
}

/// Permanently deletes every ticket in [ids] — and each one's full
/// structural subtree — via [TicketRepository.permanentlyDeleteTickets],
/// then reloads the trash list. Returns `true` on success, `false`
/// (after emitting [TrashError]) on failure.
Future<bool> permanentlyDeleteTickets(List<String> ids) async {
  try {
    await _repository.permanentlyDeleteTickets(ids);
    await load();
    return true;
  } catch (e) {
    emit(TrashError(e.toString()));
    return false;
  }
}
```

No new constructor dependencies — both reuse fields `TrashCubit` already
holds (`_parentTrashService`, `_repository`).

## 5. `TicketSelectionCubit` reuse — no code changes

Provided a second time, screen-scoped, around
`/workspace/tickets/trash` (see §8). Its existing `enter()`/`clear()`/
`toggle(id)`/`selectAll(ids)` API is used unmodified — Trash's `ids`
argument to `selectAll` is `TrashLoaded.tickets.map((t) => t.id).toList()`
(root ids only, mirroring `TicketsListScreen`'s own
`visibleTickets.map((t) => t.id).toList()`).

## 6. `TrashSelectionBar` — new widget

New file: `presentation/widgets/trash_selection_bar.dart`. Visually
modeled on `TicketSelectionBar`'s outer chrome (bordered, rounded,
shadowed surface; leading Cancel control; count label; Select-all/
Deselect-all `AppButton`) but with exactly two trailing actions instead
of Status/Priority/Delete, and no overlay/menu machinery (`LayerLink`,
`OverlayEntry`) since neither action opens a sub-picker. No compact/
breakpoint behavior (see proposal.md's Non-goals) — two `AppButton`s are
expected to fit or wrap without a dedicated narrow-width mode.

```dart
class TrashSelectionBar extends StatelessWidget {
  const TrashSelectionBar({
    super.key,
    required this.selectedCount,
    required this.allSelected,
    required this.onCancel,
    required this.onSelectAll,
    required this.onRestore,
    required this.onDeleteForever,
  });

  final int selectedCount;
  final bool allSelected;
  final VoidCallback onCancel;
  final VoidCallback onSelectAll;
  final VoidCallback onRestore;
  final VoidCallback onDeleteForever;

  // build(): same DecoratedBox/BoxShadow chrome as TicketSelectionBar's
  // outer container (duplicated, not shared — TicketSelectionBar's
  // chrome is private to its own file); a Cancel control duplicating
  // TicketSelectionBar's private _CancelControl (same 34×34 icon-button
  // shape); the count label (reuses `ticketSelectionCountLabel`); a
  // Select-all/Deselect-all AppButton (ghost variant, reuses
  // `ticketSelectionSelectAllAction`/`DeselectAllAction`); then two
  // AppButtons: Restore (`AppButtonVariant.secondary`, reuses
  // `ticketTrashRestoreAction` for its label,
  // PhosphorIcons.arrowUUpLeftLight — matches the per-row Restore
  // action's own glyph) and Delete forever (`AppButtonVariant
  // .destructive`, reuses `ticketTrashPermanentDeleteAction`,
  // PhosphorIcons.trashLight), both disabled when selectedCount == 0.
}
```

## 7. `TrashScreen` wiring

### 7.1 Header — select-mode toggle

A new private `_TrashSelectModeToggle` widget, placed in the header row
next to the existing "Purge old"/"Empty trash" actions (or, on narrow
layouts, in the same reflowed action row) — same 34×34-or-labelled shape
and `context.watch<TicketSelectionCubit>().state.isActive`-driven active
look as `TicketsListScreen`'s private `_SelectModeToggle`, duplicated
rather than shared (same file-privacy constraint as §6). Disabled
(`Opacity` 0.45, non-tappable) when `TrashLoaded.tickets.isEmpty`,
matching "Purge old"/"Empty trash"'s existing
disabled-when-nothing-qualifies convention. Tapping calls
`context.read<TicketSelectionCubit>().enter()`. Reuses
`ticketSelectionToggleLabel` ("Select tickets") for its semantics label
— generic enough already, no new string needed.

### 7.2 Header — hide Purge old / Empty trash while selecting

Both `_PurgeOldAction` and `_EmptyTrashAction` render only when
`!selection.isActive` (mirroring how `TicketsListScreen` hides `AppFab`
under the identical condition) — avoids an ambiguous "act on my
selection vs. act on everything" affordance clash while selection mode
is active.

### 7.3 Body — `Stack`-wrapped, floating `TrashSelectionBar`

`TrashScreen`'s body (currently a plain `Column`: header → info banner →
`Expanded(ListView)`) gains a `Stack` wrapping the existing `Column`,
with a `Positioned(left: 12, right: 12, bottom: 16, child:
TrashSelectionBar(...))` shown only when `selection.isActive` — no
`AppFab` to swap out here (Trash has none), so the bar simply appears/
disappears rather than replacing anything.

- `onCancel` → `TicketSelectionCubit.clear()`.
- `onSelectAll` → `TicketSelectionCubit.selectAll(state.tickets.map((t)
  => t.id).toList())` (from the current `TrashLoaded` state).
- `onRestore` → calls a new private `_bulkRestore(context,
  selection.selectedIds)`: no confirmation, calls
  `TrashCubit.restoreTickets(ids)`; if it returns `true`, shows
  `AppToast.show(context, context.l10n.ticketTrashBulkRestoreSummaryToast
  (ids.length))` and calls `TicketSelectionCubit.clear()`. (A returned
  `false` means `TrashError` was already emitted and is already visible
  via the existing error-state rendering — no toast.)
- `onDeleteForever` → calls a new private `_bulkPermanentlyDelete`:
  computes the aggregate count (`ids.length +` the sum of
  `state.descendantCounts[id] ?? 0` for each selected id, from the
  already-loaded `TrashLoaded`), opens the existing
  `_confirmPermanentDelete` helper (reusing
  `ticketTrashPermanentDeleteConfirmTitle` — "Delete forever?" — and a
  new `ticketTrashBulkPermanentDeleteConfirmMessage(total)` message), and
  on confirm calls `TrashCubit.permanentlyDeleteTickets(ids)`; on `true`,
  toasts `ticketTrashBulkPermanentDeleteSummaryToast(total)` and clears
  selection.

### 7.4 `TrashedTicketTile` — checkbox + conditional actions

Mirrors `TicketListTile`'s self-contained selection wiring exactly (no
new constructor params): reads `TicketSelectionCubit` directly via
`context.select` for `isSelectionActive`/`isSelected`. When
`isSelectionActive`:

- A leading `AppCheckbox` (value `isSelected`, `onChanged` toggles via
  `TicketSelectionCubit.toggle(ticket.id)`) is inserted before the id
  badge.
- Tapping anywhere on the row toggles selection — new behavior; today a
  Trash row's body has no `onTap` at all (only its two trailing icon
  buttons are interactive), so this doesn't collide with any existing
  gesture.
- The trailing `_RestoreAction`/`_PermanentDeleteAction` pair is hidden
  (`if (!isSelectionActive) ...[...]`), matching §7.2's "avoid an
  ambiguous scope" rationale at the row level.

## 8. Router wiring

`app_router.dart`'s `/workspace/tickets/trash` `GoRoute` builder changes
from a single `BlocProvider<TrashCubit>` to a `MultiBlocProvider` adding
`BlocProvider<TicketSelectionCubit>(create: (_) =>
TicketSelectionCubit())` — same construction as `/workspace/tickets`'s
own provider, screen-scoped (fresh instance per visit, per
`TicketSelectionCubit`'s own dartdoc).

## 9. New localized strings (`lib/l10n/app_en.arb`)

- `ticketTrashBulkRestoreSummaryToast` — ICU plural on `count`, e.g.
  `"{count, plural, one{Restored 1 ticket.} other{Restored {count}
  tickets.}}"`.
- `ticketTrashBulkPermanentDeleteConfirmMessage` — ICU plural on
  `total`, e.g. `"{total, plural, one{1 ticket} other{{total} tickets}}
  will be permanently deleted. This cannot be undone."` (mirrors
  `ticketTrashEmptyConfirmMessage`'s shape, minus the "All ... in Trash"
  framing, since this is a selection, not the whole trash).
- `ticketTrashBulkPermanentDeleteSummaryToast` — ICU plural on `count`,
  e.g. `"{count, plural, one{Permanently deleted 1 ticket.}
  other{Permanently deleted {count} tickets.}}"`.

No new strings for the select-mode toggle (`ticketSelectionToggleLabel`
reused), the bar's action labels (`ticketTrashRestoreAction`/
`ticketTrashPermanentDeleteAction` reused), the bar's count/select-all
labels (`ticketSelectionCountLabel`/`ticketSelectionSelectAllAction`/
`ticketSelectionDeselectAllAction`/`ticketSelectionExitLabel` reused), or
the bulk delete confirm title (`ticketTrashPermanentDeleteConfirmTitle`
reused).

## 10. Testing

- `test/features/tickets/data/repositories/drift_ticket_repository_test.dart`
  — new `permanentlyDeleteTickets` cases (mirroring the existing
  `permanentlyDeleteTicket`/`emptyTrash` group): deletes a childless
  ticket cleanly; deletes a multi-level subtree for a selection spanning
  several roots; a descendant already covered by another selected root's
  cascade isn't double-counted in the returned total; non-existent ids
  are silently skipped; comments/links/wikilinks cascade-delete
  alongside the ticket rows; no-ops (returns 0) on an empty/
  all-nonexistent `ids` list.
- `test/features/tickets/cubit/trash_cubit_test.dart` — new
  `restoreTickets`/`permanentlyDeleteTickets` `bloc_test` cases: each
  reloads (`TrashLoaded`) on success and returns `true`; each emits
  `TrashError` and returns `false` on a repository throw;
  `restoreTickets` calls `TicketParentTrashService.restore` once per id
  (verified via the existing DI seam); `permanentlyDeleteTickets` calls
  `TicketRepository.permanentlyDeleteTickets` once with the full id list
  (not looped).
- No widget tests for `TrashSelectionBar` or the modified
  `TrashedTicketTile`/`TrashScreen` — same established rationale already
  documented in `tickets.md`'s Testing section for this `Overlay`/
  selection-bar family of widgets (see the archived
  `bulk-status-and-priority-edit-for-ticket-selection` change's identical
  call). Covered by manual verification instead (§11).

## 11. Manual verification

Per the project's Desktop-only verification convention: a native Windows
debug build (`flutter run -d windows`), driven via PowerShell/UIA system
calls. Confirm: the select-mode toggle is disabled on an empty Trash and
enabled otherwise; entering selection mode shows checkboxes on every row
and hides each row's Restore/Delete-forever buttons and the header's
Purge-old/Empty-trash actions; tapping a row toggles its checkbox;
Select-all/Deselect-all toggles correctly; bulk Restore with no
confirmation restores the selection (including each root's trashed
descendants) and shows the correct-count toast; bulk Delete forever's
confirm dialog states the correct aggregate count (roots + descendants)
and, on confirm, permanently removes the selection and shows the
correct-count toast; Cancel exits selection mode without acting; a
repository failure (simulated if feasible) surfaces `TrashError`'s
existing retry UI rather than a false-positive toast.

# Aion — Trash Screen Multi-Select

Implementation-ready spec for selection mode on the Trash screen
(`/workspace/tickets/trash`): a header **Select** toggle, a per-row leading
checkbox, and a floating **`TrashSelectionBar`** offering bulk **Restore** and
bulk **Delete forever**. Companion mockups: `Aion Trash Multi-Select Mockups.dc.html`.

**Scope.** Additive UI on the existing `TrashScreen`. New: the Select-mode
toggle button, the row selection checkbox + selected-row treatment, the
`TrashSelectionBar`, and body copy for the bulk Delete-forever confirm. No new
screens. The existing header (back, title, count), info banner, trashed-row
layout (id badge, title, type chip, `+N subtasks`, age label), per-row Restore /
Delete-forever icon buttons, and the Purge-old / Empty-trash actions are
unchanged except where §5 and §1 note they hide during selection mode.

**Hard constraint — non-Material.** Every visual is a plain Flutter primitive
(`DecoratedBox`, `Container`, `GestureDetector`, `CustomPaint`, `Row`, `Column`,
`Align`, `Padding`, `Focus`, `Positioned`, `AnimatedContainer`, `Opacity`). No
`Card`, `ElevatedButton`, `Scaffold`, `ThemeData`, `ColorScheme`, `Checkbox`,
`ListTile`, `AppBar`, `SnackBar`, `TextButton`, `InkWell`, or any other Material
widget/type anywhere.

## 1. Select-mode toggle — header button (NEW)

A header icon+label ghost button matching the existing Purge-old / Empty-trash
button sizing and shape. Tapping it turns selection mode **on**; it stays
visible while active, reflecting the on state. When Trash is empty it is
disabled.

`GestureDetector` → `Focus` → `AnimatedContainer(150 ms)` → `Row(mainAxisSize: min)`.

- Dimensions: intrinsic width, height driven by padding (≈ 34).
- Padding: `EdgeInsets.symmetric(horizontal: 12, vertical: 8)`.
- Radius: `BorderRadius.circular(AionRadius.md)` (10).
- Layout: icon, `SizedBox(width: 6)`, label.
- Icon: check-in-square, 15×15 `CustomPaint`, stroke 1.8, round caps/joins — a
  rounded rect (`rx 4`) with an interior checkmark. Tinted with the state's
  foreground.
- Label: `"Select"`, `AionText.button.copyWith(fontSize: 12.5)`.
- Shadow: none (ghost button, sits in the header row).

### 1.1 Default (selection mode off, Trash non-empty)
- Fill `Color(0x00000000)`; border `Border.all(color: border, width: 1)`;
  icon + label `textSecondary`.

### 1.2 Hover (pointer platforms)
- Fill `surfaceHover`; border `borderStrong`; icon + label `textPrimary`.

### 1.3 Focused (keyboard)
- Fill `Color(0x00000000)`; border `Border.all(color: primary, width: 1)`;
  icon + label `textPrimary`; focus ring
  `BoxShadow(color: primary.withOpacity(ringAlpha), spreadRadius: 3, blurRadius: 0)`
  where `ringAlpha` = 0.16 Arctic / 0.30 Obsidian (outer shadow, no layout shift).

### 1.4 Pressed
- As Default/Active fill with `Transform.scale(0.97)` for the press frame.

### 1.5 Active (selection mode ON)
- Fill `primarySubtle`; border `Border.all(color: primary, width: 1)`;
  icon + label `primary`. Persists for the whole duration of selection mode.

### 1.6 Disabled (Trash empty — nothing to select)
- Fill `Color(0x00000000)`; border `border`; icon + label `textMuted`;
  wrapped in `Opacity(0.45)`; `GestureDetector.onTap: null`; excluded from focus
  traversal.

### 1.7 Header composition while active
When selection mode is on, the header's existing **Purge old** and **Empty
trash** ghost buttons are removed from the tree (not merely hidden) to avoid a
"selection vs. everything" affordance clash. Only the Select toggle (in its
Active state, §1.5) remains, right-aligned via `Spacer()`. The back button,
"Trash" title, and item count are unchanged. Mockup: **1a** (active) vs **2a**
(default header with all three actions).

### 1.8 Theme differences
Structurally identical across Arctic and Obsidian; only token *values* differ.

## 2. Row selection checkbox + selected-row treatment (NEW)

While selection mode is active, each trashed-ticket row gains a leading
`AppCheckbox` inserted **before** the id badge, and the row as a whole adopts the
selected treatment when checked. Row tap toggles selection (the whole row is the
hit target; the checkbox mirrors state).

### 2.1 Row container changes

- The row's outer `Row` switches `crossAxisAlignment` to `start` and gains a
  leading `SizedBox(width: kCheckboxSize)` checkbox + `SizedBox(width: 12)`.
- Left padding drops from `20` to `16` to seat the checkbox; right / vertical
  padding unchanged: `EdgeInsets.fromLTRB(16, 14, 20, 14)`.
- Unselected row: fill `surface`; no accent.
- Selected row: fill `primarySubtle`; inset left accent
  `BoxShadow(color: primary, spreadRadius: 0, blurRadius: 0, offset: Offset(-…))`
  implemented as `inset 3px 0 0 primary` (a `DecoratedBox` foreground border on
  the left edge, width `kRowSelectAccent`). Row title color rises from
  `textSecondary` (muted, the trash default) to `textPrimary` when selected, so
  the selection reads clearly.
- Bottom hairline `Border(bottom: BorderSide(color: border, width: 1))` unchanged.

### 2.2 AppCheckbox

`GestureDetector` → `AnimatedContainer(120 ms)`; `20×20`,
`BorderRadius.circular(AionRadius.sm)` (6); centered checkmark
`CustomPaint` (14×14, stroke 3, `#FFFFFF`, round caps/joins) when checked.

#### 2.2.1 Unchecked (default)
- Fill `surface`; border `Border.all(color: borderStrong, width: 1.5)`; no mark.

#### 2.2.2 Hover (pointer)
- Fill `surface`; border `Border.all(color: primary, width: 1.5)`; no mark.

#### 2.2.3 Checked
- Fill `primary`; border `Border.all(color: primary, width: 1.5)`; white check.

#### 2.2.4 Focused (keyboard)
- Checked or unchecked visual per state, plus focus ring
  `BoxShadow(color: primary.withOpacity(ringAlpha), spreadRadius: 3, blurRadius: 0)`
  (`ringAlpha` 0.16 Arctic / 0.30 Obsidian).

#### 2.2.5 Pressed
- Momentary `Transform.scale(0.92)`; colors follow the target checked state.

#### 2.2.6 Disabled
- Not applicable in normal use (every trashed row is selectable). If needed,
  `Opacity(0.45)` + `onTap: null`, border `border`.

#### 2.2.7 Error
- Not applicable at the checkbox level.

### 2.3 Theme differences
Structurally identical; only token values differ. `fillAlpha` (0.11 vs 0.16) is
not used by the checkbox itself (solid fills), only by tinted areas elsewhere.

## 3. `TrashSelectionBar` (NEW)

A floating, rounded, shadowed contextual bar shown **only** while selection mode
is active, positioned over the list near the bottom. Two stacked rows:
1. **Cancel** (✕) icon button · **count** label · flexible spacer ·
   **Select-all / Deselect-all** ghost text button.
2. Two equal-width action buttons side by side: **Restore** (non-destructive) ·
   **Delete forever** (destructive).

The two-row layout keeps the two full-width, clearly-labelled bulk actions
legible on a phone; on wide viewports (§3.6) it collapses to a single row.

### 3.1 Bar container

- Widget: `DecoratedBox` → `Padding` → `Column(mainAxisSize: min)`.
- Fill: `AionColors.surface`.
- Border: `Border.all(color: AionColors.border, width: 1)`.
- Radius: `BorderRadius.circular(AionRadius.xl)` (16).
- Padding: `EdgeInsets.symmetric(horizontal: 12, vertical: 10)`.
- Inter-row gap: `SizedBox(height: 8)`.
- Shadow: single `BoxShadow(color: shadowColor, blurRadius: 40, spreadRadius: -14, offset: Offset(0, 18))`
  where `shadowColor` = Arctic `rgba(24,46,74,0.22)`, Obsidian `rgba(0,0,0,0.6)`.
  Express via `.withOpacity`.
- Placement (phone): `Positioned(left: 12, right: 12, bottom: 16)` over the list.

### 3.2 Row 1 — Cancel · count · Select-all

- **Cancel icon button**: 34×34, `BorderRadius.circular(AionRadius.md)`, fill
  `surfaceHover`, glyph ✕ (`CustomPaint`, 16×16, `textSecondary`, stroke 2,
  round caps). Tap exits selection mode (returns to §2a default screen). Hover:
  fill deepens to `surfaceHover` w/ `textPrimary`; focus ring as §1.3.
- **Count label**: `"$n selected"`, `AionText.button` (14/w700), color
  `textPrimary`. At 0 selected → color `textMuted`, text `"None selected"`.
- **Spacer**: `Spacer()`.
- **Select-all / Deselect-all** ghost text button: text only,
  `AionText.button.copyWith(fontSize: 12.5)`, color `primary`,
  `EdgeInsets.symmetric(horizontal: 6, vertical: 7)`. Label is `"Select all"`
  when not all rows are selected, `"Deselect all"` when every row is selected.

### 3.3 Row 2 — Restore action button

`GestureDetector` → `Focus` → `AnimatedContainer(150 ms)` → `Row(center)`.

- `Expanded` (equal width with Delete forever), min content height
  `kBarActionMinHeight` (40).
- Padding: `EdgeInsets.symmetric(horizontal: 14, vertical: 10)`.
- Radius: `BorderRadius.circular(AionRadius.md)` (10).
- Layout: icon 15×15 (rotate-back / restore arrow, `CustomPaint`, stroke 1.8),
  `SizedBox(width: 7)`, label `"Restore"`, `AionText.button.copyWith(fontSize: 13.5)`.

#### 3.3.1 Default (≥1 selected)
- Fill `surfaceHover`; border `Border.all(color: borderStrong, width: 1)`;
  icon + label `textPrimary`. Non-destructive neutral tone — deliberately not
  `primary`-filled so it doesn't compete with the destructive action for
  emphasis; both read as peers.

#### 3.3.2 Hover
- Fill `surfaceHover`; border `borderStrong`; icon + label `textPrimary`
  (unchanged fill, slight elevation via existing shadow).

#### 3.3.3 Focused
- Focus ring `BoxShadow(color: primary.withOpacity(ringAlpha), spreadRadius: 3, blurRadius: 0)`
  outside the border.

#### 3.3.4 Pressed
- `Transform.scale(0.98)`; fill `primary.withOpacity(fillAlpha)`
  (0.11 Arctic / 0.16 Obsidian); label `textPrimary`. Restore performs
  immediately — **no confirmation dialog**.

#### 3.3.5 Disabled (0 selected)
- Fill `surfaceHover`; border `border`; icon + label `textMuted`;
  `Opacity(0.6)`; `onTap: null`; excluded from focus.

### 3.4 Row 2 — Delete forever action button

Same structure, dimensions, padding, radius, and `Expanded` sizing as §3.3. Only
tone differs.

- Icon: trash can, 15×15 `CustomPaint`, stroke 1.8.
- Label: `"Delete forever"`, `AionText.button.copyWith(fontSize: 13.5)`.

#### 3.4.1 Default (≥1 selected)
- Fill `danger`; border none; icon + label `#FFFFFF`.

#### 3.4.2 Hover
- Fill `danger` deepened — use `Color.alphaBlend(const Color(0xFF000000).withValues(alpha: 0.08), danger)`
  (no stored `dangerHover` token — a one-off computed blend, matching how
  `AionColorsHubTokens.dangerText`/`warningText` already derive a blended shade
  inline rather than storing every derived color as its own field); icon + label
  `#FFFFFF`.

#### 3.4.3 Focused
- Focus ring `BoxShadow(color: danger.withOpacity(ringAlpha), spreadRadius: 3, blurRadius: 0)`.

#### 3.4.4 Pressed
- `Transform.scale(0.98)`; fill deepened as §3.4.2. Opens the confirm dialog
  (§4) — does **not** delete immediately.

#### 3.4.5 Disabled (0 selected)
- Fill `surfaceHover`; icon + label `textMuted`; `Opacity(0.6)`; `onTap: null`;
  excluded from focus.

#### 3.4.6 Error
- If `bulkDeleteForever` fails after confirm, surface a transient inline message
  built from `danger` (e.g. a thin banner above the bar), not inside a closed
  dialog. Not a persistent bar state.

### 3.5 Zero-selected bar state
The bar remains visible at 0 selected (selection mode is still on) with both
action buttons in their disabled state (§3.3.5 / §3.4.5), count reading
"None selected", and Select-all offered. Mockup: **4a**, second bar.

### 3.6 Wide-viewport variant
On tablet/desktop widths the bar centers with `maxWidth: 620` and collapses to a
**single row**: Cancel · count · Spacer · Select-all · Restore · Delete forever
(the two actions become intrinsic-width, not `Expanded`). Same tokens, same
states; implement via one `LayoutBuilder` switch — no separate component.

### 3.7 Theme differences
Structurally identical; only token values differ. `fillAlpha` differs (0.11 vs
0.16) for the Restore pressed fill and `ringAlpha` (0.16 vs 0.30) for focus rings.

## 4. Bulk Delete-forever confirm dialog (content only)

Reuses Aion's **existing** confirm-dialog component (danger-tone variant). This
section specifies only the content it is fed — no new dialog chrome, dimensions,
or shell.

- Icon: existing danger-circle treatment — 44×44 circle, fill
  `danger.withOpacity(fillAlpha)`, centered warning glyph (⚠), color `danger`.
- Title: `"Delete forever?"`, `AionText.dialogTitle` (18/w800), `textPrimary`,
  centered.
- Body: `AionText.bodySm` (13.5/w400), `textSecondary`, centered, line-height 1.6.
  Copy states the aggregate count:
  > **{n} tickets** will be permanently deleted. This cannot be undone.

  The count `{n}` is emphasized `textPrimary`/w700. Use correct pluralization —
  singular: `"1 ticket will be permanently deleted. This cannot be undone."`
- Actions (existing dialog button pair): **Cancel** (neutral — `surfaceHover`
  fill, `borderStrong` border, `textPrimary`) and **Delete forever**
  (destructive — `danger` fill, `#FFFFFF`), each `flex: 1`, radius
  `AionRadius.md`, existing dialog padding.
- Confirm applies `bulkDeleteForever(selectedIds)`, closes the dialog, exits
  selection mode, and returns to the (now shorter) default Trash screen. Cancel
  dismisses with no change and keeps selection mode active with the selection
  intact.
- The subtask count is intentionally **not** enumerated per-ticket here (unlike
  the reversible Move-to-Trash dialog); the aggregate ticket count is the
  decision-relevant number for permanent deletion. Mockup: **3a**.

## 5. Row state while selection is active (trailing space)

When selection mode is active, each row's existing trailing **Restore** and
**Delete-forever** 34×34 icon buttons are removed from the tree (not disabled,
not hidden with reserved space). Bulk actions live only on the
`TrashSelectionBar`, so per-row trailing actions would be redundant and would
invite ambiguity.

- With the trailing icon buttons gone, the row's content column (`Expanded`)
  extends to the row's right padding; the row **ends after the age label** with
  standard end padding `20` (the right value in `EdgeInsets.fromLTRB(16,14,20,14)`).
  No trailing chevron, spacer, or placeholder is substituted.
- The freed horizontal space is absorbed by the `Expanded` title/meta column;
  long titles get more room before ellipsis. No change to row height or vertical
  rhythm.
- On exiting selection mode, the checkbox and left-padding change revert and the
  two trailing icon buttons return (default screen, §2a). Transition may
  cross-fade (150 ms) but no layout jump is required.

## 6. Interaction summary

1. Trash non-empty → **Select** toggle enabled (§1.1). Trash empty → disabled (§1.6).
2. Tap **Select** → toggle enters Active (§1.5); Purge-old / Empty-trash hide
   (§1.7); every row gains a leading checkbox (§2.2), left padding shifts, per-row
   trailing actions hide (§5); `TrashSelectionBar` appears at 0 selected (§3.5).
3. Tap a row or its checkbox → toggles that row's selection; row adopts / drops
   the selected treatment (§2.1); count updates.
4. **Select all / Deselect all** → selects or clears every row; label toggles (§3.2).
5. **Restore** (≥1 selected) → `bulkRestore(selectedIds)` immediately, **no
   confirm**; restored subtrees leave Trash; selection mode exits.
6. **Delete forever** (≥1 selected) → opens the confirm dialog (§4); confirm runs
   `bulkDeleteForever` and exits selection mode; cancel keeps selection.
7. **Cancel** (✕ on the bar) or the Select toggle → exits selection mode,
   restoring the default screen (§2a).
