# Design: Ticket Parent Selection UX

## Current state (as of `/explore`)

- `TicketsCubit.getValidParentCandidates(Ticket ticket)`
  (`tickets_cubit.dart:315-321`) fetches `_repository.getAllTickets()`
  once and excludes `ticket` itself plus its full descendant set
  (`_descendantIds`, a forward DFS over `parentId`, lines 379-396).
- `TicketsCubit.updateTicketParent(Ticket ticket, String? newParentId)`
  (lines 336-363) re-derives the same descendant set to reject
  self-parent, epic-with-parent, and cycle cases, then persists via
  `TicketRepository.updateTicketParent`.
- `TicketParentPicker` (`ticket_detail_screen.dart:795-1104`) is a
  `StatefulWidget` requiring `required Ticket ticket`. It loads
  candidates once in `initState`, renders a trigger control plus an
  `OverlayEntry` with a search field, a `_NoParentRow`, and a
  `ListView.builder` of `_CandidateRow` (lines 1183-1260+) — each row is
  `ticketId` (56px monospace) + `title` (flat `Expanded` text), file-
  private to `ticket_detail_screen.dart`.
- `TicketsCubit.createTicket` (lines 181-227) already accepts an
  optional `parentId` and persists it — `CreateTicketScreen`
  (`create_ticket_screen.dart`) never passes one; its form has title,
  type, priority, description only.
- `/tickets/new` (`app_router.dart:31`) has exactly one entry point (the
  FAB on `TicketsListScreen`), no query params — so there is currently
  no "create subticket under X" shortcut either; this change doesn't add
  one, it only adds a manual parent field to the existing form.

## Changes

### 1. Extract `TicketParentPicker` into its own file

Move `TicketParentPicker`, `_NoParentRow`, `_CandidateRow`, and their
`State` classes out of `ticket_detail_screen.dart` into a new
`presentation/widgets/ticket_parent_picker.dart`. This is a same-feature
file move (not a cross-feature promotion, so none of `project.md`'s
Pattern 1/2 dependency-inversion rules apply) — done purely because a
file-private (`_`-prefixed) widget can't be reused from
`create_ticket_screen.dart` otherwise.

### 2. Generalize `TicketParentPicker`'s constructor

Replace `required Ticket ticket` with parameters that work whether or
not the ticket already exists:

```dart
class TicketParentPicker extends StatefulWidget {
  const TicketParentPicker({
    super.key,
    required this.ticketType,
    required this.currentParentId,
    required this.excludeTicketId, // null when creating
    required this.onParentSelected,
  });

  /// The type of the ticket being edited/created — gates whether a
  /// parent can be set at all (epics never have one).
  final TicketType ticketType;

  /// The ticket's current parent id, if any. Drives the trigger's
  /// resolved-title display and the overlay's "current selection"
  /// check mark.
  final String? currentParentId;

  /// The id to exclude from candidates (the ticket itself, plus its
  /// descendants, computed by the caller). `null` when there is no
  /// existing ticket yet (creation flow) — nothing to exclude.
  final String? excludeTicketId;

  /// Called with the chosen parent id (`null` clears it) when the user
  /// picks a row. The caller decides whether that means an immediate
  /// persistence call (`TicketDetailScreen`) or just local form state
  /// (`CreateTicketScreen`, deferred until submit).
  final ValueChanged<String?> onParentSelected;
}
```

Internally, `_loadCandidates()` now branches:
- If `excludeTicketId != null`: call
  `context.read<TicketsCubit>().getValidParentCandidates(...)` — but
  that method takes a `Ticket`, not an id. Simplest change: add a
  sibling `Future<List<Ticket>> getValidParentCandidateIds(String
  excludeId, TicketType excludeType)` overload — no, avoid duplicating
  the descendant-walk. Instead keep `getValidParentCandidates(Ticket
  ticket)` as-is (still called from `TicketDetailScreen`'s usage site,
  which has the full `Ticket`), and give the picker a single
  `Future<List<Ticket>> Function() candidatesLoader` callback instead of
  reimplementing branching inside the picker itself. Each call site
  supplies its own loader:
  - `TicketDetailScreen`: `() => cubit.getValidParentCandidates(ticket)`
  - `CreateTicketScreen`: `() => cubit.getAllTickets()` (new method,
    see below) — no exclusion needed since the ticket doesn't exist yet.

This keeps `TicketParentPicker` itself free of any branching on
"does this ticket exist" — it just awaits whatever loader it's given,
which also means the picker doesn't need `excludeTicketId` at all once
loading is delegated. Revised constructor:

```dart
class TicketParentPicker extends StatefulWidget {
  const TicketParentPicker({
    super.key,
    required this.ticketType,
    required this.currentParentId,
    required this.candidatesLoader,
    required this.onParentSelected,
  });

  final TicketType ticketType;
  final String? currentParentId;
  final Future<List<Ticket>> Function() candidatesLoader;
  final ValueChanged<String?> onParentSelected;
}
```

`ticketType` is used only to decide the trigger's disabled/hidden
treatment when it's `TicketType.epic` — the picker itself always renders
if built; the *caller* decides whether to build it at all (see
`CreateTicketScreen` below).

### 3. `TicketsCubit.getAllTickets()`

New thin passthrough, no state emission (same pattern as
`getValidParentCandidates` — a query-only helper feeding a picker
overlay):

```dart
/// Returns every ticket in the workspace, for pickers that need the
/// full candidate set with no self/descendant exclusion (e.g. the
/// create-ticket parent field, where the ticket being created doesn't
/// exist yet). Performs a query only — does not emit a state.
Future<List<Ticket>> getAllTickets() => _repository.getAllTickets();
```

### 4. Ancestor breadcrumb

New top-level pure function in `ticket_parent_picker.dart`, unit-
testable without Flutter/Cubit dependencies:

```dart
/// Builds a "Grandparent / Parent" breadcrumb string for [ticket] by
/// walking `parentId` upward through [byId] (an id-keyed index of the
/// same candidate list the picker already fetched). Returns null if
/// [ticket] has no parent. Stops after [maxDepth] hops (default 8) as a
/// defensive bound — cycles shouldn't exist given
/// TicketsCubit.updateTicketParent's validation, but this keeps the UI
/// from hanging if one ever slips through.
String? ancestorBreadcrumb(
  Ticket ticket,
  Map<String, Ticket> byId, {
  int maxDepth = 8,
}) {
  final segments = <String>[];
  var currentParentId = ticket.parentId;
  var hops = 0;
  while (currentParentId != null && hops < maxDepth) {
    final parent = byId[currentParentId];
    if (parent == null) break; // ancestor outside the fetched set
    segments.add(parent.title);
    currentParentId = parent.parentId;
    hops++;
  }
  if (segments.isEmpty) return null;
  return segments.reversed.join(' / ');
}
```

`byId` is built once per overlay build from the already-fetched
candidate list (`{for (final t in candidates) t.id: t}`) — no new
query. Because `getValidParentCandidates` excludes only self and
descendants, every ancestor of a candidate is still present in that
same list, so lookups resolve without gaps in the reparent-flow case.
In the create-flow case (`getAllTickets()`), the full set is present by
definition.

`_CandidateRow` gains an optional `breadcrumb` string, rendered as a
second `Text` line (`AionText.caption`, `c.textMuted`) below the title,
`maxLines: 1` + ellipsis, omitted entirely when null (root-level
candidates keep today's single-line layout).

### 5. `CreateTicketScreen`

- New `String? _selectedParentId` state field.
- New form row, positioned after the type dropdown (parent depends
  conceptually on type, so it reads top-to-bottom as type → parent):
  `_selectedType == TicketType.epic ? const SizedBox.shrink() :
  TicketParentPicker(ticketType: _selectedType, currentParentId:
  _selectedParentId, candidatesLoader: () =>
  context.read<TicketsCubit>().getAllTickets(), onParentSelected: (id)
  => setState(() => _selectedParentId = id))`.
- When `_selectedType` changes to `TicketType.epic` in the type
  dropdown's `onChanged`, also clear `_selectedParentId` — an epic
  can't carry a stale parent selection forward if the user switches
  type after picking one.
- `_submit()` passes `parentId: _selectedParentId` into
  `context.read<TicketsCubit>().createTicket(...)`.

### 6. `TicketDetailScreen` call site update

Line 256's `TicketParentPicker(ticket: ticket)` becomes:

```dart
TicketParentPicker(
  ticketType: ticket.type,
  currentParentId: ticket.parentId,
  candidatesLoader: () =>
      context.read<TicketsCubit>().getValidParentCandidates(ticket),
  onParentSelected: (parentId) =>
      context.read<TicketsCubit>().updateTicketParent(ticket, parentId),
)
```

Note this site still builds `TicketParentPicker` even for an epic
ticket being viewed — epics can't take a parent, but showing a
disabled/hidden trigger for an *existing* epic is a display-only
concern the widget already partially handles today (it's on the
detail screen regardless of type). Task list clarifies: gate this site
the same way as the create form (`ticket.type == TicketType.epic ?
SizedBox.shrink() : TicketParentPicker(...)`), matching current
`updateTicketParent`'s existing epic rejection so the UI doesn't offer
an action the Cubit will bounce.

# Aion — Create-form Parent Field & Candidate Breadcrumbs: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md) and the [Editable Ticket Parent Spec](./Aion%20Ticket%20Parent%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing`, `AppTextField`, `TicketParentPicker` by name.

**No Material widgets anywhere.** The Parent field trigger is a `GestureDetector` → `DecoratedBox` → `Padding` → `Row`; the overlay is the existing `TicketParentPicker` (`OverlayEntry` + `CompositedTransformTarget`/`Follower`), unchanged structurally. `MouseRegion` handles hover; `Focus`/`FocusNode` handles keyboard focus.

Two additions, both reusing the existing `TicketParentPicker` overlay:

1. A new **form-field variant of the picker trigger** on `CreateTicketScreen`, inserted between the Type and Priority fields (§1–§2).
2. A new optional **ancestor-breadcrumb line** on every candidate row in the picker overlay, used by both the create-flow field and the existing ticket-detail reparent flow (§3).

One new text style is introduced (`AionText.breadcrumb`, §3.1) — see the rationale for refining the brief's `caption` assumption. No new color, radius, or spacing tokens.

Themes: Arctic and Obsidian. All layout, dimensions, spacing, radius, and typography are **identical** between themes; only color tokens differ, and every color below is a named `AionColors` token that already resolves per theme. Concrete hex is given in parentheses as `Arctic / Obsidian` for reference only — implement against the token, never the literal.

## 1. CreateTicketScreen — form layout context

`CreateTicketScreen` (route `/tickets/new`) is a `Column` of stacked form fields inside a scrollable body, with a screen header on top and a pinned action row at the bottom. Field order, top to bottom:

1. **Title** — `AppTextField`, required.
2. **Type** — `AppDropdown` (Task / Story / Epic).
3. **Parent — new** (§2).
4. **Priority** — `AppDropdown`.
5. **Description** — multiline `AppTextField`.

- Body padding: `EdgeInsets.fromLTRB(22, 2, 22, 14)`.
- Vertical gap between fields: `AionSpacing.sp16` (16) — implement as `SizedBox(height: 16)` or a `Column` with `spacing: 16`. (Mockup uses 17; 16 is the token — snap to 16.)
- Each field is a `Column`, `crossAxisAlignment: start`, with a **label row** (§1.1) then the **control**, `gap: 7` between them.

### 1.1 Field label row

Applies to every field including Parent.

- Layout: `Row`, `MainAxisSize.min`, `gap: 6`, baseline-aligned.
- Label text: `AionText.label` (Manrope 12 / w700), color `textSecondary` (`#46586A / #A2AEC6`), sentence case (`"Parent"`, not uppercase — distinct from the mono `caption` eyebrows used for section headers).
- Required marker: trailing `"*"`, `AionText.label`, color `danger` (`#CE3D54 / #F1546C`). Present on Title and Type only.
- Optional marker: trailing `"Optional"`, `AionText.bodySm.copyWith(fontWeight: w500)` (13.5→render at 11), color `textMuted` (`#8496A6 / #6B7690`). **Present on the Parent field** (parent is always optional).

### 1.2 Type-dependent visibility

- The Parent field (label + control) is rendered **only when the selected `TicketType` is `task` or `story`**.
- When Type = `epic`, the entire field is removed from the tree (not merely hidden/opacity) — the Priority field moves up to sit directly below Type with the standard `16` gap. Animate the collapse with an `AnimatedSize` (150ms, `Curves.easeOut`) so the form doesn't jump when the user switches Type.

## 2. Parent field trigger (form-field variant)

A new visual treatment of the `TicketParentPicker` trigger for embedding as a form field. Distinct from the compact inline `"+ PARENT"` trigger on the ticket detail screen (Ticket Parent Spec §1) — here it must read as "another form field," matching the `AppDropdown` controls immediately above and below it.

Wrapped in `CompositedTransformTarget` (`LayerLink`) so the overlay (§2.4) anchors to it. `GestureDetector(onTap: openPicker)`, `MouseRegion(cursor: click)`, wrapped in a `Focus` node for keyboard entry.

Shared control-box geometry (both empty and filled states):

- Width: `double.infinity` (fills the form column).
- Fill: `surface` (`#FBFCFE / #131A29`).
- Border radius: `AionRadius.lg` — the create form uses **11** (per base spec §2.5 "11 used in screens"). Use `BorderRadius.circular(11)`.
- Border: `1px solid border` (`#D6E0EA / #232C40`) at rest — matches the sibling `AppDropdown`/`AppTextField`.
- Shadow: none at rest.

### 2.1 Empty state — default

No parent selected yet.

- Padding: `EdgeInsets.symmetric(horizontal: 13, vertical: 11)`.
- Layout: `Row`, `gap: 10`, `crossAxisAlignment: center`.
  - **Leading glyph:** `git-branch` (or `link`), **15px**, color `textMuted`.
  - **Placeholder text:** `"Select a parent ticket"`, `AionText.body` (Manrope 15 / w500 → render 14), color `textMuted`. Expands (`Expanded`).
  - **Trailing chevron:** `caret-down`, **11–12px**, color `textMuted`. (Matches the `AppDropdown` trailing chevron, base spec §2.5.)

### 2.2 Filled state — default

A parent is selected; show its key + title.

- Padding: `EdgeInsets.fromLTRB(12, 9, 11, 9)` (slightly tighter vertically to seat the key badge).
- Layout: `Row`, `gap: 9`, `crossAxisAlignment: center`.
  - **Key badge:** mono ticket key, `AionText.key` (JetBrains Mono 11 / w600 / ls 0.11), color `textSecondary`; fill `surfaceHover` (`#E4EDF6 / #1C2436`), border `1px solid border`, padding `EdgeInsets.symmetric(horizontal: 7, vertical: 3)`, radius `AionRadius.sm` (6). `MainAxisSize.min`, does not shrink (`flex: 0`).
  - **Title:** `AionText.bodySm` (Manrope 13.5 / w400 → render 14), color `textPrimary` (`#142230 / #E7EDF7`). `Expanded`, `maxLines: 1`, `TextOverflow.ellipsis`.
  - **Type square:** `8×8`, radius `2`, filled `typeX` (the parent's own type accent — `typeTask` / `typeStory` / `typeEpic`). `flex: 0`.
  - **Trailing chevron:** `caret-down`, **11px**, color `textMuted`, `margin-left: 2`.
- Clearing the selection is done inside the picker via its `"No parent"` row (Ticket Parent Spec §2.3) — the field itself carries **no** inline clear affordance, keeping it visually a single dropdown-like control.

### 2.3 Interactive states (empty and filled share these)

| State | Border | Fill | Extra |
|---|---|---|---|
| Default | `1px border` | `surface` | — |
| Hover (pointer) | `1px borderStrong` (`#BAC8D6 / #35415C`) | `surface` | leading/trailing glyphs step `textMuted` → `textSecondary` |
| Focused (keyboard) | `1.5px primary` (`#2E86D4 / #9366FF`) | `surface` | focus ring `BoxShadow(color: primary.withOpacity(isDark ? 0.30 : 0.16), blurRadius: 0, spreadRadius: 3)` |
| Pressed / open | `1.5px primary` | `surface` | ring as focused; while the overlay is open the trigger holds this state |
| Disabled | `1px border` | `surface` at `0.5` opacity | text/glyphs `textMuted`; `IgnorePointer`. (Only reachable transiently — the field is removed, not disabled, for Epic; disabled applies if the whole form is submitting.) |
| Error | `1.5px danger` (`#CE3D54 / #F1546C`) | `surface` | ring `danger.withOpacity(isDark ? 0.30 : 0.16)`; used only if a server-side reparent validation fails on submit (rare — see Ticket Parent Spec §3). Paired with a helper line below: `AionText.bodySm`, color `danger`. |

- 1.5px focus/error borders inset by 0.5px vs. the 1px default so the control box does not change size between states (`BoxDecoration` border is drawn inside the box; if using `Container`, no layout shift results — verify the border is `BorderSide` inside, not outside).
- Press feedback: `AnimatedScale` to `0.99` over 80ms on `onTapDown`, back on release/open — subtler than the inline trigger's `0.98` (a full-width field warrants less motion).

### 2.4 Opening the picker

- On tap/Enter/Space: opens the existing `TicketParentPicker` overlay (Ticket Parent Spec §2), anchored via `CompositedTransformFollower` to this field's `LayerLink`, offset `(0, 6)`, growing top-left.
- Overlay width: `320` (Ticket Parent Spec §2.1), left-aligned to the field's left edge — narrower than the full-width field, which is intentional and matches every other overlay in the app.
- Candidate rows inside now render with the breadcrumb line (§3).
- Selecting a candidate → field transitions empty → filled (§2.1 → §2.2); selecting `"No parent"` → filled → empty. No success toast.

## 3. Candidate row breadcrumb

An optional second line beneath the existing ticket-key/title line on every candidate row in the `TicketParentPicker` overlay (Ticket Parent Spec §2.4). Used by both the create-flow field (§2) and the existing ticket-detail reparent flow — one component change, both call sites benefit.

### 3.0 Row structure (revised from Ticket Parent Spec §2.4)

- Row: `GestureDetector` → `DecoratedBox` → `Padding` → `Row`, `gap: 10`, `crossAxisAlignment: start` (was `center` — now top-aligned so the key sits level with the title's first line when a breadcrumb wraps the row taller).
- Padding: `EdgeInsets.symmetric(horizontal: 13, vertical: 8)`.
- Min height: `44` (unchanged); a row with a breadcrumb grows to ~`56` naturally.
- **Leading key:** `AionText.key`, color `textSecondary`, `SizedBox(width: 52)`, `padding-top: 1` to optically align with the title cap-height. `flex: 0`.
- **Center column:** `Expanded` → `Column`, `crossAxisAlignment: start`, `gap: 2`:
  - **Title line:** `AionText.bodySm`, color `textPrimary`, `maxLines: 1`, `TextOverflow.ellipsis`.
  - **Breadcrumb line (§3.1):** rendered only when the candidate has ≥1 ancestor.
- **Trailing type square:** `8×8`, radius `2`, `typeX` base color, `margin-left: 8`, `padding-top: 4` (aligns with the title line, not the row center). `flex: 0`.
- Fill states unchanged: default `transparent`, hover `surfaceHover`, pressed `border`. No inter-row divider.

### 3.1 Breadcrumb text style

**Refinement of the brief's default assumption.** The brief proposed `AionText.caption` (mono, w600, letter-spacing 1.54, conventionally UPPERCASE). That style is the app's wide-tracked eyebrow — applied to a mixed-case ancestor path with `/` separators (`"Auth Epic / OAuth redesign"`) it forces ugly uppercasing, exaggerated tracking, and poor legibility of the very titles it's meant to preview. **Rejected.**

Instead, define one small proportional style:

```dart
// AionText — add:
static const breadcrumb = TextStyle(
  fontFamily: _ui,            // Manrope
  fontSize: 11,
  fontWeight: FontWeight.w500,
  letterSpacing: 0,
  height: 1.2,
);
```

- Applied color: `textMuted` (`#8496A6 / #6B7690`) via `.copyWith(color: c.textMuted)`.
- Single line: `maxLines: 1`, `TextOverflow.ellipsis`.
- Ancestor path joined root→parent with `"  /  "` (space-slash-space); the separators carry the same `textMuted` color (no separate token — the muted weight already reads as connective tissue).
- No leading glyph — the indentation under the title and the muted tone are enough; a glyph would compete with the leading key.

### 3.2 Root-level candidate (no breadcrumb)

- The center column contains the title line **only** — the breadcrumb `Text` is omitted entirely (not rendered empty), so the row collapses back to its `44` single-line height. Unchanged from today's behavior.

### 3.3 One-ancestor candidate

- Breadcrumb shows the single ancestor title, e.g. `"Auth Epic"`. Rarely needs truncation at 320px.

### 3.4 Multi-level chain (truncation)

- Full path shown root→parent, e.g. `"Product Platform / Auth Epic / OAuth redesign & token rotation"`.
- At the fixed `320` overlay width, after the `52`+`10`+`8`+`8`+`26` (key, gaps, square, padding) chrome, the center column has ~`≤216px`. The breadcrumb ellipsis-truncates from the **end** (`TextOverflow.ellipsis`), preserving the root of the path (which orients the user) and dropping the tail nearest the title — e.g. `"Product Platform / Auth Epic / OAuth re…"`.
- The **title line always truncates independently** of the breadcrumb; neither line ever pushes the other. Both are `maxLines: 1`.
- No tooltip on truncation (touch-first app); the user opens the candidate to see the full path if needed.

## 5. Token summary

- **New text style:** `AionText.breadcrumb` (§3.1) — Manrope 11 / w500 / ls 0. The only new token in this spec.
- **No new colors:** all colors are existing `AionColors` tokens (`surface`, `surfaceHover`, `border`, `borderStrong`, `primary`, `textPrimary`, `textSecondary`, `textMuted`, `danger`, `typeTask`/`typeStory`/`typeEpic`), resolving per theme.
- **No new radius:** `AionRadius.lg` (11 in screens), `AionRadius.sm` (6) for the key badge.
- **No new spacing:** field gap `AionSpacing.sp16` (16); internal paddings are 4-multiples given as explicit `EdgeInsets`.
- Translucent fills (focus/error rings) via `token.withOpacity(x)`, never hardcoded ARGB.
