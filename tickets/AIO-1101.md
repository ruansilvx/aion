# Design: List/board view persistence & board column visibility

## 1. Overview

Two independent-but-related additions to `lib/features/tickets/`,
built by copying two already-proven patterns in this exact codebase:

- **View-mode persistence** copies `TicketListSortRepository`'s shape
  almost exactly (a single-value, project-scoped preference with
  "never explicitly chosen yet" as a real, distinct state).
- **Board column visibility** copies `TicketListFilterRepository`'s
  shape (a project-scoped *set* of values, string-list-backed,
  "empty means default" semantics) plus `TicketFilterPopover`'s
  checkbox-group overlay mechanics.

Both pieces plug into the same three layers filters/sort already use:
a domain entity, a domain repository interface, a `SharedPreferences`
implementation, and two `TicketsCubit` methods
(`loadPersistedX`/`setX` or `toggleX`) wired from
`TicketsListScreen.initState`.

## 2. Domain layer (`lib/features/tickets/domain/`)

### 2.1 `TicketListViewMode` (new)

`domain/entities/ticket_list_view_mode.dart` — promotes today's
private, widget-local `_TicketViewMode` enum
(`presentation/screens/tickets_list_screen.dart`) to a shared domain
enum, since it's now read/written from three places (the cubit, the
repository, the screen) instead of one:

```dart
/// Which rendering `TicketsListScreen` uses for its loaded ticket list.
enum TicketListViewMode {
  /// The flat, chronologically-sortable `ListView` of every ticket.
  list,

  /// `TicketBoardView`, grouped by status and filtered to task/story
  /// tickets.
  board,
}
```

Not `Equatable` — a plain enum, same as `TicketSortField`/
`TicketSortDirection` (which back `TicketListSort`, itself the
`Equatable` wrapper). No wrapper value object is needed here the way
`TicketListSort` wraps `field`+`direction` — a view mode is already a
single scalar, so the repository interface (below) reads/writes the
enum directly rather than through a one-field holder class.

### 2.2 `TicketBoardColumnVisibility` (new)

`domain/entities/ticket_board_column_visibility.dart` — an immutable
`Equatable` value object, sibling in shape to `TicketListFilters`:

```dart
/// The board's per-project column visibility selection: which
/// `TicketStatus` columns the user has hidden. A plain value holder,
/// mirroring `TicketListFilters` — exists so
/// `TicketBoardColumnVisibilityRepository` has one type to read/write
/// instead of a bare `Set<TicketStatus>`, and so `TicketsCubit` has
/// one type to pass to/from it.
class TicketBoardColumnVisibility extends Equatable {
  const TicketBoardColumnVisibility({this.hiddenStatuses = const {}});

  /// Statuses whose board column is currently hidden. An empty set
  /// (the default) means "nothing hidden — all six columns visible,"
  /// the same "empty = no constraint" convention `TicketListFilters`
  /// already uses for its three fields.
  final Set<TicketStatus> hiddenStatuses;

  @override
  List<Object?> get props => [hiddenStatuses];
}
```

### 2.3 `TicketListViewModeRepository` (new)

`domain/repositories/ticket_list_view_mode_repository.dart` — a
sibling of `TicketListSortRepository`, same "unset means no explicit
choice yet" semantics:

```dart
/// Persists and restores the ticket list's per-project view-mode
/// choice. Implemented by `SharedPrefsTicketListViewModeRepository`;
/// UI and Cubit code depend only on this interface.
abstract interface class TicketListViewModeRepository {
  /// The persisted explicit view mode for [projectId], or `null` if
  /// the user has never explicitly switched away from the fixed
  /// `TicketListViewMode.board` starting default in this project.
  Future<TicketListViewMode?> getViewMode(String projectId);

  /// Persists [mode] as [projectId]'s explicit choice, overwriting
  /// whatever was saved before.
  Future<void> setViewMode(String projectId, TicketListViewMode mode);
}
```

### 2.4 `TicketBoardColumnVisibilityRepository` (new)

`domain/repositories/ticket_board_column_visibility_repository.dart`
— a sibling of `TicketListFilterRepository`:

```dart
/// Persists and restores the board's per-project hidden-column
/// selection. Implemented by
/// `SharedPrefsTicketBoardColumnVisibilityRepository`; UI and Cubit
/// code depend only on this interface.
abstract interface class TicketBoardColumnVisibilityRepository {
  /// The persisted `TicketBoardColumnVisibility` for [projectId], or a
  /// default-empty one (nothing hidden) if nothing has been saved yet.
  Future<TicketBoardColumnVisibility> getHiddenColumns(String projectId);

  /// Persists [visibility] as [projectId]'s hidden-column selection,
  /// overwriting whatever was saved before.
  Future<void> setHiddenColumns(
    String projectId,
    TicketBoardColumnVisibility visibility,
  );
}
```

Plain reads/writes, no validation — same shape as
`TicketListFilterRepository`/`ExecutionContextCapRepository`.

## 3. Data layer (`lib/features/tickets/data/`)

### 3.1 `SharedPrefsTicketListViewModeRepository` (new)

`data/repositories/shared_prefs_ticket_list_view_mode_repository.dart`
— mirrors `SharedPrefsTicketListSortRepository`'s file almost line for
line, but with one string key instead of two (a view mode has no
second dimension the way sort has field+direction):

```dart
class SharedPrefsTicketListViewModeRepository
    implements TicketListViewModeRepository {
  String _key(String projectId) => 'ticket_list_view_mode.$projectId';

  @override
  Future<TicketListViewMode?> getViewMode(String projectId) async {
    final prefs = await SharedPreferences.getInstance();
    final name = prefs.getString(_key(projectId));
    if (name == null) return null;
    return TicketListViewMode.values.where((v) => v.name == name).firstOrNull;
  }

  @override
  Future<void> setViewMode(String projectId, TicketListViewMode mode) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_key(projectId), mode.name);
  }
}
```

A project with no persisted key yet, or a stored name that no longer
matches a `TicketListViewMode` value, reads back as `null` — "no
explicit choice yet," exactly `SharedPrefsTicketListSortRepository`'s
existing contract.

### 3.2 `SharedPrefsTicketBoardColumnVisibilityRepository` (new)

`data/repositories/shared_prefs_ticket_board_column_visibility_repository.dart`
— mirrors `SharedPrefsTicketListFilterRepository`'s string-list
convention, one key:

```dart
class SharedPrefsTicketBoardColumnVisibilityRepository
    implements TicketBoardColumnVisibilityRepository {
  String _key(String projectId) =>
      'ticket_board_column_visibility.$projectId.hiddenStatuses';

  @override
  Future<TicketBoardColumnVisibility> getHiddenColumns(
    String projectId,
  ) async {
    final prefs = await SharedPreferences.getInstance();
    final names = prefs.getStringList(_key(projectId)) ?? const [];
    final hidden = names
        .map(
          (n) => TicketStatus.values.where((v) => v.name == n).firstOrNull,
        )
        .whereType<TicketStatus>()
        .toSet();
    return TicketBoardColumnVisibility(hiddenStatuses: hidden);
  }

  @override
  Future<void> setHiddenColumns(
    String projectId,
    TicketBoardColumnVisibility visibility,
  ) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setStringList(
      _key(projectId),
      visibility.hiddenStatuses.map((s) => s.name).toList(),
    );
  }
}
```

A stale stored name (e.g. an enum member later removed) is silently
dropped on read, not surfaced as an error — same convention
`SharedPrefsTicketListFilterRepository` already documents.

## 4. `TicketsCubit` changes (`presentation/cubit/tickets_cubit.dart`)

Two new optional constructor dependencies, following the cubit's
established optional-dependency convention exactly
(`filterRepository`/`sortRepository`'s own pattern):

```dart
TicketsCubit(
  this._repository, {
  // ...existing params...
  TicketListViewModeRepository? viewModeRepository,
  TicketBoardColumnVisibilityRepository? boardColumnVisibilityRepository,
}) : super(const TicketsInitial()) {
  // ...existing assignments...
  _viewModeRepository = viewModeRepository;
  _boardColumnVisibilityRepository = boardColumnVisibilityRepository;
}
```

`null` (every existing test/call site) makes both features behave
exactly as before this change — an unpersisted, in-session-only
`board` default and an always-empty hidden-columns set; real usage
(`app_router.dart`) always supplies both, alongside
`filterRepository`/`sortRepository`/`projectId`.

New private state:

```dart
late final TicketListViewModeRepository? _viewModeRepository;
late final TicketBoardColumnVisibilityRepository? _boardColumnVisibilityRepository;

TicketListViewMode _viewMode = TicketListViewMode.board;
Set<TicketStatus> _hiddenColumns = {};
```

New public members — deliberately **plain getters/methods that never
`emit`**, the same "metadata about a selection, not the list-loading
lifecycle" reasoning `selectedStatuses`/`currentSort` already use:
neither the view mode nor the hidden-column set changes which tickets
are loaded, so neither belongs in `TicketsState`.

- **`currentViewMode`** (getter) → `_viewMode`. Read by
  `TicketsListScreen` everywhere it currently reads its own `_viewMode`
  field.
- **`setViewMode(TicketListViewMode mode)`** — sets `_viewMode = mode`,
  then persists via `_viewModeRepository`/`_projectId` (no-op if either
  is `null`, same guard shape as `setSort`). Does **not** call
  `searchTickets` — a view-mode change never affects which tickets
  match the current query, only which widget renders the already-loaded
  list.
- **`loadPersistedViewMode()`** — reads the active project's persisted
  view mode (via `_viewModeRepository`/`_projectId`; no-ops if either is
  `null`, or if nothing was persisted yet — `_viewMode` keeps its
  `board` default in that case) into `_viewMode`, *without* running a
  search or emitting a state — same load-before-first-render precedent
  as `loadPersistedSort`. Called from `TicketsListScreen.initState`
  alongside `loadPersistedFilters`/`loadPersistedSort`.
- **`hiddenBoardColumns`** (getter) → `_hiddenColumns`. Read by
  `TicketBoardView` (which columns to skip) and `TicketColumnsPopover`
  (each row's checked state).
- **`toggleBoardColumnVisibility(TicketStatus status)`** — toggles
  `status`'s membership in `_hiddenColumns` (add if absent, remove if
  present — same `_toggleFilter<T>`-style shape `toggleStatusFilter`
  already uses), persists the resulting
  `TicketBoardColumnVisibility(hiddenStatuses: _hiddenColumns)` via
  `_boardColumnVisibilityRepository`/`_projectId` (no-op if either is
  `null`). Does **not** call `searchTickets`, same reasoning as
  `setViewMode`.
- **`loadPersistedBoardColumnVisibility()`** — reads the active
  project's persisted `TicketBoardColumnVisibility` (via
  `_boardColumnVisibilityRepository`/`_projectId`; no-ops if either is
  `null`) into `_hiddenColumns`, *without* running a search or emitting
  a state. Called from `TicketsListScreen.initState` alongside the
  other three persisted-restore calls.

## 5. `TicketsListScreen` changes (`presentation/screens/tickets_list_screen.dart`)

### 5.1 Removing the widget-local view mode

The private `_TicketViewMode` enum and the `_viewMode` field are
deleted. Every reference (`_ViewModeToggle`'s `mode` param, the
board/list branch in the body switch, the `_narrowToVisible`-style
helper around the existing `if (_viewMode == _TicketViewMode.board)`
check) is updated to read `TicketListViewMode` from
`context.read<TicketsCubit>().currentViewMode` instead of a local
field. This mirrors how `selectedStatuses`/`currentSort` already work
— the cubit is the sole source of truth, the screen never keeps its
own shadow copy.

### 5.2 Restoring persisted state before first paint

`_initializeAndSearch` (today: awaits `loadPersistedFilters()` then
`loadPersistedSort()`, then runs the first search) gains two more
awaited calls, before the existing ones resolve into the first
`_runSearch()`:

```dart
Future<void> _initializeAndSearch() async {
  final cubit = context.read<TicketsCubit>();
  await cubit.loadPersistedViewMode();
  await cubit.loadPersistedBoardColumnVisibility();
  await cubit.loadPersistedFilters();
  await cubit.loadPersistedSort();
  if (!mounted) return;
  setState(() {}); // picks up the four restored selections for first build
  _runSearch();
}
```

The trailing `setState(() {})` is required for the same reason
`_handleSortSelected` already documents: `currentViewMode`/
`hiddenBoardColumns` live outside `TicketsState` entirely, so nothing
about restoring them alone would otherwise trigger a rebuild before
`_runSearch()`'s own eventual `TicketsLoaded` emission arrives (and
that emission might not even change `tickets`/`hasMore` if this
project's default query result is unaffected — same Equatable-skip
footgun `_handleSearchTextChanged` already guards against).

### 5.3 View-mode toggle

The `_ViewModeToggle` trigger's `onChanged` handler changes from a
bare local `setState`:

```dart
// Before
onChanged: (mode) => setState(() => _viewMode = mode),
```

to a cubit round-trip followed by a forced rebuild, the same shape
`_handleSortSelected` already established for exactly this "the value
lives on the cubit, not in a local field" situation:

```dart
// After
onChanged: _handleViewModeChanged,
// ...
Future<void> _handleViewModeChanged(TicketListViewMode mode) async {
  await context.read<TicketsCubit>().setViewMode(mode);
  if (mounted) setState(() {});
}
```

### 5.4 Columns trigger and popover

`_TicketFilterAndSortSection` gains one new required param,
`viewMode: TicketListViewMode`, purely for gating — the Columns
control has no meaning in List mode. Its `build` adds a third trigger,
after the existing Filters/Sort pair, only when `viewMode ==
TicketListViewMode.board`:

```dart
Row(
  mainAxisSize: MainAxisSize.min,
  children: [
    TicketFilterPopover( /* ...unchanged... */ ),
    const SizedBox(width: AionSpacing.sp8),
    TicketSortPopover( /* ...unchanged... */ ),
    if (widget.viewMode == TicketListViewMode.board) ...[
      const SizedBox(width: AionSpacing.sp8),
      TicketColumnsPopover(
        trigger: _ColumnsTriggerButton(
          hiddenCount: cubit.hiddenBoardColumns.length,
          isOpen: _isColumnsPopoverOpen,
          isFocused: _isColumnsTriggerFocused,
        ),
        hiddenStatuses: cubit.hiddenBoardColumns,
        onToggleColumn: widget.onToggleColumnVisibility,
        onOpenChanged: (isOpen) =>
            setState(() => _isColumnsPopoverOpen = isOpen),
        onFocusChanged: (isFocused) =>
            setState(() => _isColumnsTriggerFocused = isFocused),
      ),
    ],
  ],
),
```

`_isColumnsPopoverOpen`/`_isColumnsTriggerFocused` are two new private
fields on `_TicketFilterAndSortSectionState`, mirroring
`_isSortPopoverOpen`/`_isSortTriggerFocused`.

**Why `onToggleColumnVisibility` is threaded in from the parent,
unlike `onToggleStatus`/`onToggleType`/`onTogglePriority`.** Those
three are wired directly inside `_TicketFilterAndSortSectionState` to
bare `context.read<TicketsCubit>().toggleXFilter` calls, with no
forced local rebuild, because each one re-runs `searchTickets()`
internally — the resulting `TicketsLoaded` emission is what eventually
updates `TicketBoardView`/the flat list elsewhere on screen, via their
own independent `context.watch` subscriptions. Toggling a hidden
column has no equivalent emission to piggyback on (§4 above:
`toggleBoardColumnVisibility` never calls `searchTickets`), and
`TicketBoardView` is a **sibling** of `_TicketFilterAndSortSection`,
outside its subtree — so the forced rebuild has to happen at the
common ancestor, `_TicketsListScreenState` itself:

```dart
// On _TicketsListScreenState
Future<void> _handleColumnVisibilityToggled(TicketStatus status) async {
  await context.read<TicketsCubit>().toggleBoardColumnVisibility(status);
  if (mounted) setState(() {});
}
```

passed down as `_TicketFilterAndSortSection(
onToggleColumnVisibility: _handleColumnVisibilityToggled, ...)`. The
resulting top-level `setState` rebuilds the whole screen subtree,
which is what lets the sibling `TicketBoardView` (below) re-read
`cubit.hiddenBoardColumns` and skip the newly-hidden column.

### 5.5 Wiring `TicketBoardView`

The existing `TicketBoardView(tickets: ...)` construction site gains
one new required param:

```dart
TicketBoardView(
  tickets: /* ...unchanged, already type-filtered... */,
  hiddenStatuses: context.read<TicketsCubit>().hiddenBoardColumns,
)
```

`context.read`, not `.watch` — the same reasoning as §5.3/§5.4: the
value only ever changes as a side effect of an already-forced
`setState`, so watching it here would add nothing.

## 6. `TicketBoardView`/`_BoardColumns` changes (`presentation/screens/tickets_board_view.dart`)

`TicketBoardView` gains one new required field:

```dart
class TicketBoardView extends StatelessWidget {
  const TicketBoardView({
    super.key,
    required this.tickets,
    required this.hiddenStatuses,
  });

  final List<Ticket> tickets;

  /// Statuses whose column is currently hidden — see
  /// `TicketsCubit.hiddenBoardColumns`. Column *order* is unaffected;
  /// this only controls which of `TicketStatus.values` get a
  /// `BoardColumn` at all.
  final Set<TicketStatus> hiddenStatuses;

  @override
  Widget build(BuildContext context) {
    final grouped = <TicketStatus, List<Ticket>>{
      for (final status in TicketStatus.values)
        status: tickets.where((t) => t.status == status).toList(),
    };
    // ...unchanged pendingResumePrompt read...
    return Column(
      children: [
        // ...unchanged ResumeRunsPrompt banner...
        Expanded(
          child: _BoardColumns(grouped: grouped, hiddenStatuses: hiddenStatuses),
        ),
      ],
    );
  }
}
```

`_BoardColumns` filters `TicketStatus.values` down to the visible
subset before building its `ListView.separated`, and — new — renders a
centered hint instead of an empty horizontal scroller when every
status is hidden:

```dart
class _BoardColumns extends StatelessWidget {
  const _BoardColumns({required this.grouped, required this.hiddenStatuses});

  final Map<TicketStatus, List<Ticket>> grouped;
  final Set<TicketStatus> hiddenStatuses;

  @override
  Widget build(BuildContext context) {
    final visibleStatuses = TicketStatus.values
        .where((s) => !hiddenStatuses.contains(s))
        .toList();
    if (visibleStatuses.isEmpty) {
      return const _NoColumnsVisibleHint();
    }
    return ListView.separated(
      scrollDirection: Axis.horizontal,
      padding: const EdgeInsets.symmetric(
        horizontal: AionSpacing.sp20,
        vertical: AionSpacing.sp16,
      ),
      itemCount: visibleStatuses.length,
      separatorBuilder: (context, index) =>
          const SizedBox(width: AionSpacing.sp12),
      itemBuilder: (context, index) {
        final status = visibleStatuses[index];
        return SizedBox(
          width: _kColumnWidth,
          child: BoardColumn(status: status, tickets: grouped[status]!),
        );
      },
    );
  }
}
```

`_NoColumnsVisibleHint` is a small new `StatelessWidget` — centered
icon + a primary line ("No columns are visible") + a secondary hint
line ("Reopen Columns above to show one."), styled after the existing
"No tickets match your search" empty state's shape (tinted rounded
motif + two-line copy) but distinct copy, since this is "you hid
everything," not "nothing matches."

`BoardColumn`, `TicketBoardCard`, `MoveToStatusMenu`, and the
hybrid-clustering behavior are **entirely unchanged** — a rendered
column doesn't know or care whether its sibling columns are hidden.
`MoveToStatusMenu` in particular keeps listing all 5 other statuses
regardless of hidden state (§ Out of scope reasoning in proposal.md) —
hiding is a display preference, not a workflow restriction.

## 7. New widgets (design-gated — see proposal.md)

### 7.1 `TicketColumnsPopover`

`presentation/widgets/ticket_columns_popover.dart` — structurally a
straight copy of `TicketFilterPopover`'s `Overlay`/`OverlayEntry`/
`CompositedTransformFollower`/`Escape`-to-dismiss mechanics
(`LayerLink`, `didUpdateWidget` → `_overlayEntry?.markNeedsBuild()` so
an already-open popover's checkboxes reflect a rebuild triggered from
outside its own subtree, `FocusableActionDetector` +
`ActivateIntent`), reduced to a **single** checkbox group instead of
`TicketFilterPopover`'s three:

```dart
class TicketColumnsPopover extends StatefulWidget {
  const TicketColumnsPopover({
    super.key,
    required this.trigger,
    required this.hiddenStatuses,
    required this.onToggleColumn,
    this.onOpenChanged,
    this.onFocusChanged,
  });

  final Widget trigger;
  final Set<TicketStatus> hiddenStatuses;
  final ValueChanged<TicketStatus> onToggleColumn;
  final ValueChanged<bool>? onOpenChanged;
  final ValueChanged<bool>? onFocusChanged;

  // ...State mirrors _TicketFilterPopoverState exactly...
}
```

The overlay body is one `OverlayMenuItem` row per `TicketStatus.values`
(fixed declared order, matching `BulkStatusMenu`'s existing fixed
status order), each wrapping the same `_CheckRow`-shaped content
`TicketFilterPopover` uses (an `AppCheckbox` + the field's accent dot +
label) — **checked means visible**, i.e. `checked: !widget.hiddenStatuses
.contains(status)`, the inverse of `TicketFilterPopover`'s "checked
means selected/included in the filter." No group header is needed (a
single group, unlike Filters' three), no `_GroupDivider`. Reuses
`ticketStatusLabel`/the existing `_StatusAccentDot`-equivalent color
mapping from `tickets_board_view.dart` for visual consistency with
every other status-colored element on screen.

### 7.2 `_ColumnsTriggerButton`

Private to `tickets_list_screen.dart`, mirrors `_FilterTriggerButton`
exactly: idle sub-state (no columns hidden) vs. active sub-state
(`hiddenCount` ≥ 1, shown with a trailing count badge — "how many are
hidden," the same badge grammar `_FilterTriggerButton` already uses
for "how many filters are active"), plus the shared
open/focused-emphasis treatment every trigger in this row uses. Icon:
a column-layout glyph (Phosphor Light), distinct from the funnel
(Filters) and sort-arrows (Sort) icons already in this row.

# Aion — List/Board View Persistence & Board Column Visibility: Component Spec

Implementation-ready spec for two quality-of-life additions to the existing `TicketsListScreen` / `TicketBoardView`: **view-mode persistence** (a behavior-only change to the existing List/Board toggle) and **board column visibility** — a new **"Columns" trigger button** (sibling of the existing "Filters" and "Sort" triggers; see [Aion Ticket Sort and Board Default Spec](./Aion%20Ticket%20Sort%20and%20Board%20Default%20Spec.md) §3) that opens a single-group checkbox popover to hide/show individual status columns, plus one **all-columns-hidden empty state** inside the board area. All within the existing `/workspace/tickets` screen — no new screens.

**No Material widgets or types anywhere.** Every component below is built from `flutter/widgets.dart` primitives only: `DecoratedBox`, `Container`, `GestureDetector`, `MouseRegion`, `FocusableActionDetector`, `CustomPaint`, `Row`, `Column`, `Align`, `Padding`, `Overlay` / `OverlayEntry` / `CompositedTransformFollower`. Never `Card`, `ElevatedButton`, `Scaffold`, `PopupMenu*`, `ListTile`, `InkWell`, `Checkbox`, `ThemeData`, `ColorScheme`, `AppBar`, or any `material.dart` import.

- `c` = active `AionColors` (`arctic` / `obsidian`); `isDark` = Obsidian. Both themes share **one** code path; only token values differ. Where a component is identical across themes it is stated explicitly.
- Existing primitives reused unchanged: the `TicketFilterButton` / `_SortTriggerButton` trigger geometry, the `SelectionMenu` elevated-panel treatment, the `OverlayMenuItem` row-fill formula (see [Aion Overlay Menu Item Spec](./Aion%20Overlay%20Menu%20Item%20Spec.md) §1.3), the checkbox glyph and `_StatusAccentDot` from `TicketFilterPopover`, and the empty-state motif treatment from the existing "No tickets match your search" state.
- Translucent fills are always `token.withOpacity(x)` — never hardcoded ARGB. (`withOpacity` per this spec's export convention; the codebase's `withValues(alpha:)` is the equivalent call.)
- Companion mockups: `Aion Board Column Visibility Mockups.dc.html` (Arctic + Obsidian; popover open over the board with Backlog + Cancelled hidden `1a`, all-columns-hidden empty state `1b`, trigger + popover-row control states `1c`).

## 1. Models & behavior

### 1.1 View-mode persistence (behavior only — no new visual)

The `TicketsListScreen` view mode is the existing enum, driven by the existing List/Board toggle icons already in the header.

```dart
enum ViewMode { list, board }
```

- **Today:** initializes to `ViewMode.board` (the current default) and resets each visit.
- **Change:** the last-chosen `ViewMode` is **persisted per project** and restored on entry, taking precedence over the `board` default. Toggling updates the persisted value immediately.
- Same persistence mechanism as the existing Filters / Sort persistence — keyed per project id.
- **No new component.** The toggle, its two icon buttons, their states, and all rendering are unchanged; only the initial-state source differs (persisted value → `board` fallback).

### 1.2 Column-visibility model

```dart
enum TicketStatus { backlog, todo, inProgress, inReview, done, cancelled }

/// Persisted per project. Absent → all columns visible.
class BoardColumnVisibility {
  final Set<TicketStatus> hidden; // empty == all visible
  const BoardColumnVisibility(this.hidden);

  bool isVisible(TicketStatus s) => !hidden.contains(s);
  int get hiddenCount => hidden.length;
  bool get allHidden => hidden.length == TicketStatus.values.length; // 6
}
```

### 1.3 Fixed column order

Columns always render in this fixed order; visibility never reorders them:

**Backlog · To Do · In Progress · In Review · Done · Cancelled**

The popover lists the six statuses in this same order.

### 1.4 Tap semantics (live, popover stays open)

- Tapping a popover row **toggles** that status in/out of `hidden`. The board re-renders **immediately** (no "Apply" step), skipping hidden columns entirely; visible columns keep their fixed relative order.
- The popover does **not** auto-close on toggle — the user can hide/show several columns in one open session. It dismisses only on outside-tap or `Escape` (§3.2).
- Board re-render reuses the existing `120ms` opacity cross-fade used elsewhere on the board.

### 1.5 Status → accent-dot color

Reused verbatim from `StatusIndicator` / `TicketFilterPopover`'s `_StatusAccentDot`:

| Status | Accent dot |
|---|---|
| `backlog` | `c.textMuted` |
| `todo` | `c.textMuted` |
| `inProgress` | `c.primary` |
| `inReview` | `c.textMuted` |
| `done` | `c.success` |
| `cancelled` | `c.textMuted` |

### 1.6 Scope

- Board mode only. The **Columns trigger is hidden entirely in List mode** (§2.4); List rendering is unaffected by `BoardColumnVisibility`.
- `hidden` persists across mode switches — hiding a column in Board, switching to List, and back preserves the hidden set.

## 3. `TicketColumnsPopover` — the checkbox-group overlay

An overlay panel anchored under the Columns trigger, hosting one flat list of 6 status rows. Same shell as `TicketFilterPopover`, but a **single group with no group header** (Status is the only group).

### 3.1 Container

Matches the `SelectionMenu` elevated-panel treatment (identical to `TicketFilterPopover` / `TicketSortPopover`).

- **Fill:** `c.surface`.
- **Border:** `1px c.borderStrong`.
- **Border radius:** `AionRadius.lg` (12), `clipBehavior: Clip.antiAlias` (first/last row washes clip to the corners).
- **Shadow:** `BoxShadow(color: Color.fromRGBO(0, 0, 0, isDark ? 0.55 : 0.30), offset: Offset(0, 20), blurRadius: 40, spreadRadius: -14)`.
- **Width:** `min(236, availableWidth - 40)` — sizes to the longest label ("In Progress") + checkbox + accent dot without stretching to the trigger's width. (Narrower than Filters' `260` because there is a single short-label group; either reads correctly — `236` chosen to match the Sort popover.)
- **Panel padding:** `EdgeInsets.symmetric(vertical: 6)` (row horizontal padding lives on the rows).
- **Position:** `top: triggerHeight + 6`, anchored to the Columns trigger via `CompositedTransformFollower` (`targetAnchor: bottomLeft` / `followerAnchor: topLeft`). Because Columns is the third trigger, if the left-aligned panel would overflow the right edge it **shifts left to stay ≥ 16px inside** the screen (as in the mockup); if it would overflow the bottom it flips upward (`targetAnchor: topLeft` / `followerAnchor: bottomLeft`).
- **Max height / scroll:** `maxHeight: min(availableHeight - anchorBottom - 16, 420)`; `SingleChildScrollView` when exceeded. Six rows fit without scrolling on a phone.

### 3.2 Dismissal

- **Tap outside:** a full-screen transparent `GestureDetector` barrier behind the panel (part of the `OverlayEntry`) closes on tap.
- **Escape:** a `Shortcuts` / `Actions` pair (`DismissIntent` → close) while the panel owns focus.
- **No close button, no "Apply".** Toggles apply live (§1.4).

### 3.3 Structure

```dart
Column(crossAxisAlignment: CrossAxisAlignment.stretch, children: [
  _ColumnRow(status: TicketStatus.backlog,    ...),
  _ColumnRow(status: TicketStatus.todo,       ...),
  _ColumnRow(status: TicketStatus.inProgress, ...),
  _ColumnRow(status: TicketStatus.inReview,   ...),
  _ColumnRow(status: TicketStatus.done,       ...),
  _ColumnRow(status: TicketStatus.cancelled,  ...),
])
```

No `_GroupHeader`, no `_GroupDivider` — a flat list (unlike Filters' three grouped sections).

### 3.4 `_ColumnRow` — one status row

Full-row tap target. Reuses the `OverlayMenuItem` neutral row-fill formula: resting transparent → hover/focus `surfaceHover` → pressed `border`, animated `100ms Curves.easeOut`. Tapping the row toggles that column's visibility (§1.4).

- **Row layout:** `Row(crossAxisAlignment: center)` → checkbox, `SizedBox(width: 10)`, accent dot, `SizedBox(width: 8)`, label, `Spacer`. The whole width is the tap target.
- **Row padding:** `EdgeInsets.symmetric(horizontal: 13, vertical: 8)` → row height ≈ 36.
- **Checkbox:** `20×20`, `borderRadius: AionRadius.sm` (6), `1.5px` border. **Checked = column currently visible.**
  - **Checked:** fill `c.primary`, border `c.primary`, a `12px` `#FFFFFF` check glyph (`✓`, w800), optically centered (`marginTop: -1`).
  - **Unchecked:** fill `c.surface`, border `c.borderStrong`, no glyph.
- **Accent dot:** `8×8`, `borderRadius: 50%`, color per §1.5.
- **Label:** `AionText.bodySm` (Manrope 13.5 / w400) in `c.textPrimary`. Text = the status display name (`Backlog`, `To Do`, `In Progress`, `In Review`, `Done`, `Cancelled`).

#### 3.4.1 `_ColumnRow` states

| State | Row fill | Checkbox | Notes |
|---|---|---|---|
| **Default** | transparent | per checked/unchecked (§3.4) | — |
| **Hover** | `c.surfaceHover` | unchanged | `100ms` fade |
| **Focused (keyboard)** | `c.surfaceHover` **plus** inset ring `c.primary.withOpacity(isDark ? 0.30 : 0.16)`, spread `2`, blur `0` (the `OverlayMenuItem` focus treatment) | unchanged | each enabled row is a focus stop; on open the popover autofocuses the first row |
| **Pressed** | `c.border` | unchanged | — |
| **Disabled** | n/a | — | rows are never disabled — a column may always be toggled, including the last one (→ empty state §4) |
| **Error** | n/a | — | toggling cannot fail |

- **Focus model:** `FocusableActionDetector` per row; `Enter` / `Space` toggles (§1.4).
- **Transition:** `100ms Curves.easeOut` fill fade (matches `OverlayMenuItem`); the check glyph swaps instantly on toggle.

**Theme note:** identical structure both themes; only token values differ.

## 6. Tokens

**No new `AionColors`, `AionRadius`, or `AionSpacing` members.** Every value resolves to existing tokens or to explicit multiples of 4 already used by the Filters / Sort triggers:

- **Colors** — all from `AionColors`: `surface`, `border`, `borderStrong`, `primary`, `primarySubtle`, `surfaceHover`, `textPrimary`, `textMuted`, `success` (Done dot), plus the status dots per §1.5. Badge fill `c.primary`; badge text `#FFFFFF`.

The only explicit non-scale numbers are the `236` panel width, the `6` panel top offset, the `18`/`20` checkbox size, the `8` accent-dot size, and the `60`/`6`/`24` motif dimensions — each intentional and local, matching the Filters / Sort specs' equivalents.
