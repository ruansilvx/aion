# Spec Delta: per-phase-tier-based-model-routing

**Reconciled 2026-09-03:** checked against the current `aion-arch/specs/providers.md's ModelRoutingCubit section` — the mechanism/behavior this delta describes is still present and architecturally coherent with current text. Identifiers the automated screen flagged as missing are private-method requalification, line-wrapped tokens, or names covered in a neighboring section rather than repeated here — not behavioral drift. per-phase model selection (ModelRoutingReady.modelByPhase, requiredToolAccessTier filtering) matches this delta's mechanism closely.

Delta against `aion-arch/specs/providers.md` and `aion-arch/specs/tickets.md`.
Read alongside [proposal.md](../proposal.md) and [design.md](../design.md) —
this file only lists what changes, not full current-state context.

## ADDED

- **`ModelPhase`** (new enum, `features/providers/domain/enums/model_phase.dart`)
  — `frontier | capable | execution`. The reasoning-weight tier a model
  call belongs to, independent of the existing tool-access axis
  (`no-tools | read-only | full`).
- **`SddStage.modelPhase`** (new extension getter,
  `features/tickets/domain/enums/sdd_stage.dart`) — maps `exploring |
  proposed | verifying` to `ModelPhase.frontier`, and `designBrief |
  designSync | archived` to `ModelPhase.capable`.
- **`ModelRoutingRepository`** (new interface,
  `features/providers/domain/repositories/model_routing_repository.dart`)
  — `getModelForPhase(ModelPhase) → Future<AgentModel>` /
  `setModelForPhase(ModelPhase, AgentModel) → Future<void>`.
  `SharedPrefsModelRoutingRepository` (`data/repositories/`) implements
  it via one `shared_preferences` string key per phase
  (`model_routing.frontier_model_id`, `.capable_model_id`,
  `.execution_model_id`), each defaulting — when unset — to whatever the
  pre-existing single-model key (`agent_settings.selected_model_id`)
  held, else `AgentModel.sonnet`.
- **`ModelRoutingCubit`/`ModelRoutingState`** (new,
  `features/providers/presentation/cubit/`) — loads/persists the
  selected `AgentModel` for every `ModelPhase`, structurally identical to
  `AutomationSettingsCubit`/`AutomationSettingsState`.
  `ModelRoutingReady.modelByPhase` (`Map<ModelPhase, AgentModel>`) is the
  ready state's payload.
- **Settings screen "MODELS" section** — a new eyebrow and three
  `_ModelPhaseSection` rows (Frontier/Capable/Execution), each a label,
  one-line description, and an `AppDropdown<AgentModel>` bound to
  `ModelRoutingCubit`. Occupies the visual slot the removed single
  "Model" dropdown (below) used to.
- **`TicketsCubit` resolves models per phase.** New optional constructor
  parameter `modelRoutingRepository` (`ModelRoutingRepository?`, `null`
  default, same optional-dependency pattern as `agentClient`/
  `commentRepository`/`automationSettingsRepository`). New private
  `_resolveModel(ModelPhase)` helper. `_spawnStageChat` resolves through
  `stage.modelPhase`; `retryDesignSync` resolves through
  `SddStage.designSync.modelPhase`; `_runCodingExecution` resolves
  through the literal `ModelPhase.execution`. A cubit constructed without
  a `ModelRoutingRepository` falls back to `AgentModel.sonnet` for every
  resolution — today's behavior, unchanged for that case.
- **`ChatCubit` infers a chat's phase from its parent ticket.** New
  required constructor dependencies `TicketRepository` and
  `ModelRoutingRepository`. New private `_phaseForChat(String
  chatTicketId)` helper: an `epic`/`story` parent resolves via
  `parent.sddStage?.modelPhase`; a `task` parent resolves to
  `ModelPhase.execution`; a missing/unresolvable parent defensively
  falls back to `ModelPhase.capable` (never hit in real usage — every
  chat ticket is spawned with a parent).

## MODIFIED

- **`AgentSettingsRepository` → `ModelRoutingRepository`.** The single
  global model concept is removed outright, not kept alongside the new
  per-phase one.
- **`ProviderSettingsCubit`** — constructor now takes a
  `ModelRoutingRepository` instead of an `AgentSettingsRepository`.
  `load()`/`testConnection()` resolve the model to ping via
  `getModelForPhase(ModelPhase.frontier)`, re-read fresh on every call
  rather than cached. `selectModel(AgentModel)` is removed — model
  selection now happens exclusively through `ModelRoutingCubit`'s three
  tier dropdowns.
- **`ChatCubit.sendMessage`** — drops its `required AgentModel model`
  parameter. The model is now resolved internally via `_phaseForChat`
  plus `ModelRoutingRepository.getModelForPhase`, instead of being
  supplied by the caller. `ChatCubit.runChatTurn` (the shared static
  helper) is unchanged — still takes an already-resolved `AgentModel`.
- **`ticket_detail_screen.dart`'s `_sendComment`** — drops the
  `model: AgentModel.sonnet` argument to `ChatCubit.sendMessage`, per the
  above signature change.
- **Settings screen** — the single `AppDropdown<AgentModel>` under a
  "Model" label is removed, replaced by the new "MODELS" section
  described above.
- **`main.dart`** — `RepositoryProvider<AgentSettingsRepository>` is
  replaced by `RepositoryProvider<ModelRoutingRepository>`
  (`SharedPrefsModelRoutingRepository`), same global (not per-project)
  scope.
- **`app_router.dart`** — `ProviderSettingsCubit`'s construction is
  updated for its new dependency; a new `BlocProvider<ModelRoutingCubit>`
  is added to `/workspace/settings`; `ChatCubit`'s construction at
  `/workspace/tickets/:id` gains `TicketRepository`/`ModelRoutingRepository`
  args; every `TicketsCubit` construction site across the router gains
  `modelRoutingRepository: context.read<ModelRoutingRepository>()`.

## REMOVED

- **`AgentSettingsRepository`** (`domain/repositories/agent_settings_repository.dart`)
  and **`SharedPrefsAgentSettingsRepository`**
  (`data/repositories/shared_prefs_agent_settings_repository.dart`) —
  fully superseded by `ModelRoutingRepository`.
- **`ProviderSettingsCubit.selectModel`** — no replacement method; model
  selection moved to `ModelRoutingCubit.selectModel(ModelPhase, AgentModel)`.
- **The single global "Model" dropdown** on the Settings screen.
- **`settingsModelDropdownLabel`** l10n key (`lib/l10n/app_en.arb`) — no
  longer referenced.
