# 5. End-to-end native Windows verification

- [x] T17. On a native Windows build (`flutter run -d windows
      --debug`), driven live (Win32 automation or the `Windows-MCP` tool
      surface — see `design.md` §5 and the `native-windows-verification-
      pass` precedent): create a Task ticket, trigger coding execution,
      and observe the run through to a real `EXECUTION: PR_OPENED <url>`
      (confirmed via an actual `gh pr create` call, not a self-reported
      model claim). Confirm the resulting entry appears correctly in the
      persistent notification center. Record the ticket id, the PR URL,
      and the notification content observed as this task's evidence. No
      source file created/edited.

      **Evidence (live, native Windows debug build, `v1-release-
      readiness` branch, driven via PowerShell/Win32 mouse+keyboard
      automation — Flutter's semantics tree isn't reliably exposed to
      UIA without a screen reader active, matching `native-windows-
      verification-pass`'s own precedent):**
      - Target repo: the disposable "Test" project
        (`C:\Users\ruans\Desktop\test`) freshly wired to a new private
        scratch GitHub repo
        (`https://github.com/ruansilvx/aion-verification-scratch`) —
        a real `gh pr create` needs a real remote, and the pre-existing
        "Test" project had none configured.
      - Created Task **AIO-42** "T17 verification task", description:
        create `T17_VERIFICATION.md` at the repo root with one fixed
        line of text, don't touch anything else. Dragged it from
        `Backlog` to `In Progress` on the Board (the status-picker
        `SelectionMenu` trigger on the detail page and the Board card's
        `MoveToStatusMenu` icon both proved unreliable to hit via
        screenshot-coordinate clicks in this pass — drag-and-drop, the
        method `native-windows-verification-pass` already established,
        worked immediately and is the reliable path for future live
        passes).
      - **First attempt failed** with a real, reproducible bug (filed
        as a separate follow-up, not fixed here — T17 is verification,
        not a fix task): `GitRepositoryClient.defaultBranch` falls back
        to the literal `'main'` whenever `git rev-parse --abbrev-ref
        origin/HEAD` fails, which it does on this repo because the
        remote was added via `git remote add` rather than `git clone`
        (`origin/HEAD` is never auto-populated that way) — so
        `changedFileCount`'s `git diff --name-only main...aion/task-
        <id>` failed with "unknown revision" right after both the
        implement and verify turns had already succeeded, aborting the
        run. Confirmed both from the live "Verification failed — PR not
        opened" banner and by reading `ticket_comments` directly from
        the project's `.aion/data/app.db` for the un-locatable-via-
        search-UI coding-execution chat ticket (AIO-43).
      - Worked around locally (`git remote set-head origin -a`, a
        one-time fix to *this scratch repo's* git config, not to Aion)
        to continue the pass. Clicking **Retry** then surfaced a
        **second, distinct real bug**, also filed separately: the retry
        path reuses the same deterministic `aion/task-<id>` branch name
        without deleting the branch the failed attempt already created,
        so it immediately failed again with "a branch named ... already
        exists." Worked around by deleting the stale local branch by
        hand, then Retry succeeded.
      - **Full live run, start to finish, confirmed via the app UI and
        independently via `gh`/git querying the real repo (not a
        self-reported model claim):** implement turn (`IMPLEMENTATION:
        DONE`) → verify turn (`VERIFICATION: PASSED`) → `git push` →
        `gh pr create` → ticket detail showed "Run complete / Coding
        run finished — PR opened / PR #1 opened · 1 file changed" with
        a "Mark ready for review" affordance (status correctly stayed
        `In Progress`, not auto-flipped — "Coding Execution Automation"
        was left at its existing `Gated` value throughout this pass).
        `gh pr list --repo ruansilvx/aion-verification-scratch`
        confirmed a real open PR: **PR #1,
        https://github.com/ruansilvx/aion-verification-scratch/pull/1**,
        head `aion/task-caacc07b-721e-4e55-a98c-57dc0fa0cde8` →
        base `master`. `gh pr diff 1` confirmed the diff contains
        exactly `T17_VERIFICATION.md` with the exact requested content
        (plus the ticket's own git-projected `tickets/AIO-42.md`, per
        this project's normal git-projection behavior) — no other
        files touched.
      - **Notification center**, confirmed via the in-app dropdown:
        top entry reads **"T17 verification task — AIO-42 · PR #1
