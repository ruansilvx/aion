# 6. Post-`/verify` fixes

Two WARNING findings from the first `/verify` pass — both real gaps in
this change's own stated goal ("a renamed/added/removed status actually
shows up everywhere a status can be seen"), not new scope.

- [x] T18. `aion/lib/features/tickets/presentation/screens/
      tickets_list_screen.dart`'s `StatusIndicator` (the ticket-detail
      status picker's trigger, `chat_meta_header.dart`, and the ticket
      list row) still hardcodes its dot color to `'backlog'`/
      `'inProgress'`/`'done'` name matching — the fourth duplicate
      `design.md`'s Design gate note missed when it counted "three."
      Migrate it to the shared rule: take the live `WorkflowConfigCubit`
      status scope via `context.watch` (shared-base scope — this widget
      spans all ticket types, same as Board/Filters/Columns), resolve
      the status via `statusDotColorForName` (`status_dot.dart`), and
      render with `StatusDot` in place of the inline `DecoratedBox`.
      Dartdoc update on the class describing the change. No layout
      change — same 7×7 dot, same position.

      **Done.** `StatusIndicator.build` now reads
      `context.watch<WorkflowConfigCubit>().state`, resolves
      `sharedBaseStatuses` (falling back to `const []` pre-load, same
      pattern as `BoardColumn`), and colors its dot via
      `statusDotColorForName`/`StatusDot`. Confirmed all three call
      sites (`tickets_list_screen.dart`'s row, `ticket_metadata_
      section.dart`'s picker trigger, `chat_meta_header.dart`) sit under
      `WorkspaceShell`'s `ShellRoute` in `app_router.dart` (`/workspace/
      tickets`, `/workspace/tickets/:id`), so `WorkflowConfigCubit` is
      in scope at every one — no new `ProviderNotFoundException` risk.
      `flutter analyze`: no issues. Full `flutter test`: 1451/1451
      passed (existing harnesses already carried a `WorkflowConfigCubit`
      fixture from T12).
- [x] T19. `aion/test/features/tickets/presentation/widgets/
      status_dot_test.dart` (new file): unit tests for `status_dot.dart`
      — `statusDotColor` (all four `WorkflowStatusRole` branches plus
      both `null`/terminal combinations, per design.md §2.1's table),
      `isStatusTerminal` (a status before/after the `done`-role status by
      `sortOrder`, and the no-`done`-in-scope case defaulting `false`),
      and `statusDotColorForName` (a known name resolves through
      `statusDotColor`; an unknown name falls back to `c.textMuted` per
      §2.3). File header comment included.

      **Done.** 13 cases across three `group`s, using the top-level
      `arctic` `AionColors` constant directly (no widget pump needed —
      pure functions). Covers every §2.1 table row, `isStatusTerminal`'s
      boundary (the `done`-role status itself is not terminal; no-`done`
      -in-scope defaults `false`), and `statusDotColorForName`'s unknown-
      name/empty-scope fallback to `c.textMuted`. 13/13 passed.
