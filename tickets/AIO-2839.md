# Coding-execution retry recovery AIO-2828 doesn't fix task-scoped tool_use id corruption

Root cause is still unknown. Since a brand-new chat with zero prior messages reproduces the exact same failure, the corruption cannot live in the chat's own persisted conversation state which is what aion#122/AIO-2828 assumed. It must be something scoped to the task instead -- candidates worth checking: the git worktree/branch state for this task, a tool-call id generator or cache keyed by task id, or how the agent session/thread is resolved for a given task.
