# **CRITICAL — concurrent git commits from loop-created tickets.**

`lib/features/tickets/data/services/ticket_git_projector.dart`:
added an internal FIFO queue (`_tail`/`_enqueue`) serializing every
`project`/`projectBatch` call through one `TicketGitProjector`
instance, so tickets created back-to-back in a loop (`TicketsCubit
._materializeParsedChildren`, backing SDD decomposition/
verify-fixes materialization) can no longer fire concurrent `git`
subprocesses against the same working tree and lose a projection to
an `index.lock` collision. A failing queued call still throws to
its own caller and does not block calls queued behind it. Added a
`serialization (git-projection-concurrency-race)` test group to
`test/features/tickets/data/services/ticket_git_projector_test.dart`
covering both the queuing behavior (a blocked first call delays a
second call's `git.add`) and the no-wedge-on-failure behavior.
