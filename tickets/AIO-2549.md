# Spec Delta: Trash screen multi-select

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (30/35 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

Delta against `aion-arch/specs/tickets.md`. On `/archive`, these changes
merge into that file's prose (not appended as a changelog).

## ADDED

### `TicketRepository`/`DriftTicketRepository` — bulk permanent delete

- `TicketRepository.permanentlyDeleteTickets(List<String> ids) →
  Future<int>` — permanently deletes every ticket in `ids`, and each
  one's full structural subtree, in one transaction (cascading to
  comments and `ticket_links`/page-wikilinks, same as `emptyTrash`).
  Returns the total number of tickets actually deleted (`ids` plus every
  cascaded descendant, deduplicated), mirroring `trashTickets`'s
  return-count convention. Ids that don't exist are silently skipped.
  Irreversible.
- `DriftTicketRepository`'s private cascade-resolution helper (formerly
  `_resolveTrashCascade`, shared by `trashTickets`/`previewTrashCount`)
  is renamed `_resolveDescendantCascade` and reused by
  `permanentlyDeleteTickets` too — no trash-specific behavior, so no
  duplication.

### `TrashCubit` — bulk restore/delete writes

- `restoreTickets(List<String> ids) → Future<bool>` — restores every
  ticket in `ids` by looping the existing
  `TicketParentTrashService.restore(id)` once per id (not a new batch
  repository method — see this change's proposal.md for why looping is
  correctness-equivalent here: `TrashLoaded`'s roots always have a fully
  live ancestor chain, and distinct roots' subtrees never overlap), then
  reloads the trash list via `load()`. Returns `true` on success, `false`
  (after emitting `TrashError`) on failure.
- `permanentlyDeleteTickets(List<String> ids) → Future<bool>` —
  permanently deletes every ticket in `ids` (and their subtrees) via the
  new `TicketRepository.permanentlyDeleteTickets`, then reloads the
  trash list via `load()`. Returns `true` on success, `false` (after
  emitting `TrashError`) on failure.

### `TicketSelectionCubit` — provided a second time, around Trash

- No code change to `TicketSelectionCubit`/`TicketSelectionState`
  themselves. A second, independent, screen-scoped instance is now
  provided around `/workspace/tickets/trash` (via `app_router.dart`'s
  `MultiBlocProvider`), alongside the existing instance already provided
  around `/workspace/tickets`.

### `TrashSelectionBar` — new widget

- New floating bar (`presentation/widgets/trash_selection_bar.dart`),
  shown at the bottom of `TrashScreen` only while
  `TicketSelectionCubit.state.isActive` is `true`. Exposes: a Cancel
  control (clears selection and exits selection mode), a selected-count
  label, a Select-all/Deselect-all toggle (operating over the currently
  loaded trashed root tickets), a **Restore** action (no confirmation,
  restores every selected root and its trashed descendants, then shows a
  count toast), and a **Delete forever** action (`destructive`-tone
  confirm dialog stating the aggregate selected-root-plus-descendant
  count, then permanently deletes the selection and shows a count
  toast).

### `TrashScreen` — select-mode toggle and conditional header actions

- A new header icon button toggles selection mode on (disabled when
  Trash is empty), reusing `TicketSelectionCubit.enter()`. Not itself an
  exit path — `TrashSelectionBar`'s Cancel control handles that, same
  split as `TicketsListScreen`'s own toggle/Cancel pair.
- The existing "Purge old" and "Empty trash" header actions now render
  only while selection mode is inactive, avoiding an ambiguous
  "act on my selection vs. act on everything" affordance clash.

### `TrashedTicketTile` — selection checkbox and conditional row actions

- While selection mode is active: a leading `AppCheckbox` reflects/
  toggles the row's selected state, and tapping anywhere on the row body
  toggles selection (new — a Trash row's body has no tap behavior
  today). The row's existing trailing Restore/Permanently-Delete icon
  buttons hide during selection mode, for the same "avoid ambiguous
  scope" reason as the header actions above.

### New localized strings

`ticketTrashBulkRestoreSummaryToast`,
`ticketTrashBulkPermanentDeleteConfirmMessage`,
`ticketTrashBulkPermanentDeleteSummaryToast`.

## MODIFIED

  this bullet.

## UNCHANGED (confirmed, not modified)

- `TicketSelectionCubit`/`TicketSelectionState` — reused verbatim, no
  code changes.
- `TicketSelectionBar`, `BulkStatusMenu`, `BulkPriorityMenu` (the
  ticket-list-specific selection bar and its overlays) — untouched.
  `TrashSelectionBar` is a separate, simpler widget.
- `TicketDao` — no changes. Every bulk primitive this change needs
  (`getDescendantIds`, `deleteTicketRows`, the comment/link DAOs' list
  deletes) already existed, already backing `emptyTrash`/
  `purgeTrashOlderThan`.
- Single-row Restore/Permanently-Delete behavior, and the screen-level
  "Purge old"/"Empty trash" actions' own logic — unchanged outside of
  the new visibility condition described above.
- `TicketRepository.restoreTicket` (singular) — unchanged; reused as-is
  by `TrashCubit.restoreTickets`'s loop. No plural `restoreTickets`
  repository method is added.
