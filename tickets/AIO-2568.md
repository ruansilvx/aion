Stage Automation" section), run a real Epic → Story → Task
lifecycle through live SDD-stage advances. Confirm each
transition fires correctly with no unwanted side effect (no
unintended chat spawn, no incorrect ticket-status write), and
that a `gated`-configured transition still waits for confirmation
rather than silently applying. Record the exact scenario and
outcome as this task's evidence (no source file created/edited).
**Evidence (live, native Windows debug build, `v1-release-
readiness` branch, the "Test" project):**
- Set Settings → SDD Stage Automation to `Auto` (Coding Execution
Automation and Ticket creation both left at their existing
`Gated`).
- Created Epic AIO-36 "T14 verification epic". It immediately and
automatically entered `Exploring` and began "Advancing to
Proposed — running the stage chat" with **no confirmation
prompt** — a real chat ticket (AIO-37) was spawned, ran live
against `claude-opus-4-8` via the Claude Agent SDK, and (after
one clarifying reply, since the placeholder epic had no real
task content) produced a placeholder exploration summary.
- The Epic then auto-advanced to `Proposed` (a second real chat,
AIO-38, produced a 4-Story decomposition as **text only** — it
did not call `create_ticket`, so no ticket was created; correct
isolation from the separately-`Gated` "Ticket creation" setting)
and correctly **stopped** at "Advance unlocks once every Story
is archived" — a structural SDD precondition that `auto`
confidence does not bypass. No incorrect ticket-status write
occurred at any point; AIO-36 stayed `Backlog` throughout, as
expected pre-execution.
- Manually created Story AIO-39 "Provision test fixtures" under
the Epic (ticket creation itself is `Gated`, so this step is
manual by design). It **also** immediately and automatically
began advancing (`Exploring` → running the stage chat) —
confirming `auto` fires identically for both `advanceSddStage`
consumers, Epic and Story.

waits":** AIO-39's Explore-stage chat attempted a real
`create_ticket` tool call (a Task, "T14 fixture — SDD stage
advance A"). Because "Ticket creation" is `Gated`, the app
correctly **paused** with a "Paused — waiting for your

it. Clicking **Confirm** created the task and the model
immediately proposed a second one ("...advance B"), re-pausing
identically — confirming the gate re-fires reliably, not just
once. Clicking **Reject** on the second correctly discarded it
without creating a ticket.
- The persistent notification center recorded every stage
transition live (`AIO-36 · Advanced to Exploring`, `AIO-36 ·
Advanced to Proposed`, `AIO-39 · Advanced to Exploring`),
confirmed via the notification dropdown.
