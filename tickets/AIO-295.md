# Design: Baseline Skill Staleness Detector

## Architecture

No Dart, no Flutter, no drift schema, no BLoC/Cubit — this is entirely
Bash tooling under `aion-arch/`, matching the existing
`detect-cycle.sh`/`detect-gaps.sh` pattern documented in
`workflow/shared/cycle-stages.md` and `detect-gaps.sh`'s own header
comment. One new script, one small integration point in an existing
script, one small doc update in an existing skill.

```
aion-arch/
  workflow/scripts/
    detect-baseline-staleness.sh   <-- new
    detect-gaps.sh                 <-- modified: folds new script's output in
  .claude/skills/what-next/
    SKILL.md                       <-- modified: one new sentence in the Note
```

## New script: `detect-baseline-staleness.sh`

Full content, following `detect-cycle.sh`/`detect-gaps.sh`'s existing
conventions exactly (`set -euo pipefail`, `SCRIPT_DIR`/`OPENSPEC_DIR`
resolution, a local `json_escape` helper duplicated rather than shared,
`git -C <repo> log` for repo-scoped history queries):

```bash
#!/usr/bin/env bash
# Reports skills whose aion-arch source (.claude/skills/<name>/SKILL.md)
# has been committed more recently than its bundled baseline counterpart
# (aion/assets/baseline/<latest-version>/skills/<name>.md) was last
# touched. Emits a JSON array in the same entry shape detect-gaps.sh's
# own priority-0 entries use, so detect-gaps.sh can fold this script's
# output directly into its results. See aion-arch/specs/projects.md's
# "Baseline package and override resolution" section for what a
# baseline version is and why aion-arch's own skills are developed and
# proven there first.
#
# This is a *staleness* signal, not a content sync: it only tells you a
# review is due, never what to change. aion-arch's skills are operative,
# project-specific instructions; the bundled baseline content (0.3.0+)
# is deliberately generic and stack-agnostic — porting an aion-arch
# skill update into its baseline counterpart always needs human
# judgment about what generalizes, not a mechanical copy.
#
# Depends on aion/ existing as a sibling checkout of aion-arch/ (see
# CLAUDE.md's "Workspace setup"). Degrades to an empty array, not an
# error, if it isn't found — not every aion-arch checkout sits inside
# the full aion-workspace/ monorepo layout.
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
OPENSPEC_DIR="$(cd "$SCRIPT_DIR/../.." && pwd)"
SKILLS_DIR="$OPENSPEC_DIR/.claude/skills"
AION_DIR_CANDIDATE="$OPENSPEC_DIR/../aion"

json_escape() {
  local s=$1
  s=${s//\\/\\\\}
  s=${s//\"/\\\"}
  printf '%s' "$s"
}

if [ ! -d "$AION_DIR_CANDIDATE" ] || [ ! -d "$SKILLS_DIR" ]; then
  echo "[]"
  exit 0
fi
AION_DIR="$(cd "$AION_DIR_CANDIDATE" && pwd)"

BASELINE_ROOT="$AION_DIR/assets/baseline"
if [ ! -d "$BASELINE_ROOT" ]; then
  echo "[]"
  exit 0
fi

latest_version="$(ls "$BASELINE_ROOT" 2>/dev/null | sort -V | tail -1)"
if [ -z "$latest_version" ]; then
  echo "[]"
  exit 0
fi
BASELINE_SKILLS_DIR="$BASELINE_ROOT/$latest_version/skills"

entries=()

for skill_path in "$SKILLS_DIR"/*/; do
  [ -d "$skill_path" ] || continue
  name="$(basename "$skill_path")"
  skill_file="${skill_path}SKILL.md"
  baseline_file="$BASELINE_SKILLS_DIR/$name.md"

  [ -f "$skill_file" ] || continue
  [ -f "$baseline_file" ] || continue

  aion_arch_date="$(git -C "$OPENSPEC_DIR" log -1 --format=%ad --date=short -- ".claude/skills/$name/SKILL.md" 2>/dev/null || true)"
  baseline_date="$(git -C "$AION_DIR" log -1 --format=%ad --date=short -- "assets/baseline/$latest_version/skills/$name.md" 2>/dev/null || true)"

  # Either file has no commit history yet (e.g. staged but not
  # committed) — nothing to compare, skip rather than guess.
  [ -z "$aion_arch_date" ] && continue
  [ -z "$baseline_date" ] && continue

  # ISO (YYYY-MM-DD) dates sort correctly as plain strings.
  if [[ "$aion_arch_date" > "$baseline_date" ]]; then
    title="\`$name\` skill changed in aion-arch ($aion_arch_date) since its bundled $latest_version baseline counterpart was last reviewed ($baseline_date)"
    next_action="/explore baseline staleness $name skill"
    rel_path="aion/assets/baseline/$latest_version/skills/$name.md"

    entries+=("$(printf '{"priority": 0, "source": "baseline-staleness", "file": "%s", "title": "%s", "next_action": "%s"}' \
      "$(json_escape "$rel_path")" "$(json_escape "$title")" "$(json_escape "$next_action")")")
  fi
done

if [ "${#entries[@]}" -eq 0 ]; then
  echo "[]"
else
  printf '[\n'
  for i in "${!entries[@]}"; do
    if [ "$i" -lt $((${#entries[@]} - 1)) ]; then
      printf '  %s,\n' "${entries[$i]}"
    else
      printf '  %s\n' "${entries[$i]}"
    fi
  done
  printf ']\n'
fi
```

Notes on specific choices:

- **`sort -V | tail -1` for "latest version."** Mirrors what
  `BundledBaselineRepository._bundledVersions` and
  `CreateProjectCubit`'s `versions.last` resolve to today (`0.1.0` <
  `0.2.0` < `0.3.0`, both semver order and filesystem sort order agree).
  This script doesn't parse Dart, so it can't consult
  `_bundledVersions` directly — if a future bundled-version directory
  name ever broke that alignment, this script would silently compare
  against the wrong version. Acceptable given the three existing
  directories agree today, and worth revisiting only if that ever
  changes.
- **Only the latest version is checked**, not `0.1.0`/`0.2.0` — both are
  frozen per `specs/projects.md`, so there's nothing actionable to
  surface about them.
- **Silently skip skills with no bundled counterpart** (`[ -f
  "$baseline_file" ] || continue`) — e.g. `prepare-release` exists only
  in `aion-arch/.claude/skills/`, with no `assets/baseline/*/skills/
  prepare-release.md` anywhere. Nothing to compare, so it's excluded
  rather than flagged.
- **Silently skip pairs with no git history on either side** — a file
  that's staged but not yet committed has no `git log` output; comparing
  against it would either error or produce a nonsensical always-newer
  result. Skipping is the safe default matching this script's overall
  "signal, not noise" goal.
- **Executable bit not required.** The integration point below invokes
  it via `bash "$SCRIPT_DIR/detect-baseline-staleness.sh"` rather than
  relying on `+x` surviving a Windows checkout.

## Integration: `detect-gaps.sh`

Two edits to the existing file.

**1. Header comment** (lines 6–8 today) gains a fourth clause on the
existing Priority 0 bullet:

```diff
 # Priority 0 — "Known gaps" and "Open questions" items documented in
 #              aion-arch/specs/*.md (follow-up work and unresolved
-#              decisions acknowledged in a shipped feature's spec).
+#              decisions acknowledged in a shipped feature's spec), plus
+#              live-detected staleness between an aion-arch skill and its
+#              bundled baseline counterpart (see
+#              detect-baseline-staleness.sh).
```

**2. New section**, inserted immediately after the existing "Priority 0:
`Open questions` sections in spec files" block (ends at the closing `fi`
around today's line 159) and before the "Priority 1 & 3: idea files"
comment block (today's line 161):

```bash
# --- Priority 0: baseline skill staleness (aion-arch vs. bundled) --------
# Folds detect-baseline-staleness.sh's own JSON array output into this
# script's priority-0 results — see that script for what it checks.
BASELINE_STALENESS_SCRIPT="$SCRIPT_DIR/detect-baseline-staleness.sh"
if [ -f "$BASELINE_STALENESS_SCRIPT" ]; then
  while IFS= read -r raw_line; do
    trimmed="$(printf '%s' "$raw_line" | sed -e 's/^[[:space:]]*//' -e 's/,[[:space:]]*$//')"
    [[ "$trimmed" == \{* ]] || continue
    p0_entries+=("$trimmed")
  done < <(bash "$BASELINE_STALENESS_SCRIPT" 2>/dev/null || echo "[]")
fi
```

This reuses `detect-gaps.sh`'s existing `p0_entries` array (declared
earlier in the file, alongside `p1_entries`/`p2_entries`/`p3_entries`)
and its existing final-assembly/dedup-blank-entries logic at the bottom
of the file — neither needs to change. The `sed` trim strips the
sub-script's pretty-printing (leading two-space indent, trailing comma)
back down to a bare `{...}` object per line, matching the shape every
other `p0_entries+=(...)` call already produces.

No changes needed to `detect-cycle.sh`.

## Integration: `what-next/SKILL.md`

The "Note on the gaps above" paragraph (after the "Context — prioritized
gaps" injection) gains one sentence, describing the new `source` value
the same way it already describes `"specs"` and `"specs-open-questions"`:

```diff
 Note on the gaps above: entries with `"priority": 0, "source": "specs"` come
 straight from a `## Known gaps` section in an `aion-arch/specs/*.md` file —
 a bullet list the spec's own author wrote to flag follow-up work left
 undone in a feature that's already shipped. Entries with `"priority": 0,
 "source": "specs-open-questions"` come from that same spec's `## Open
 questions` section instead — an unresolved decision hanging over an
 already-shipped feature, rather than unbuilt follow-up work. Both are
 treated as the strongest signal in the list (see [Priority
 order](#priority-order) below); the difference only affects the
 recommended command: a known gap suggests `/explore <topic>`, an open
 question suggests `/brainstorm <topic>` since it's a decision to make,
 not code to investigate.
+
+Entries with `"priority": 0, "source": "baseline-staleness"` mean an
+`aion-arch` skill has been committed more recently than its bundled
+`aion/assets/baseline/` counterpart was last reviewed — a live drift
+signal computed fresh on every run, not a written-down gap someone
+authored. Same priority-0 weight as the two sources above; its
+`next_action` recommends `/explore` since deciding whether and how to
+port the change needs investigation, not a pure yes/no decision.
```

No changes to the "Instructions" priority-order logic (steps 1–7) —
these entries arrive pre-merged into the same `detect-gaps` JSON output
that step 3 already reads, so "If detect-gaps output contains any
priority 0 items → pick the SINGLE most impactful one" already covers
them without modification.

## Verification approach

No `flutter analyze`/`flutter test`/manual Chrome pass applies — no Dart
file is touched. Verification is: run the new script standalone against
real repo state and confirm valid, sensible JSON; run `detect-gaps.sh`
and confirm the merge doesn't break its existing output shape; and
prove the staleness comparison itself actually fires, using a throwaway
commit that's reverted immediately after. See `tasks.md`'s Verification
section for the exact steps.
