# Design: AI-assisted complexity and estimate suggestions

## 1. Domain layer

### 1.1 `TicketEstimationSource` (new enum)

`lib/features/tickets/domain/enums/ticket_estimation_source.dart`:

```dart
enum TicketEstimationSource {
  /// The current value came from the automatic background estimator or
  /// an explicit "Regenerate" action, and — since it's unlocked — remains
  /// eligible to be silently replaced by a future automatic re-estimate.
  aiSuggested,

  /// Same as [aiSuggested], but produced with zero comparable historical
  /// tickets to calibrate against (a cold-start guess from title/
  /// description content alone). Rendered with an extra low-confidence
  /// caveat; otherwise behaves identically to [aiSuggested] (still
  /// unlocked, still eligible for silent re-estimation).
  aiSuggestedLowConfidence,

  /// The user set this value directly (typed a fresh value, or edited/
  /// confirmed an existing AI suggestion). Locked: the automatic
  /// background estimator skips this field permanently until an explicit
  /// "Regenerate" action overrides the lock.
  manual,
}
```

Mirrors `TicketComplexity`/`TicketSeverity`'s plain-enum shape.
`complexity == null`/`estimate == null` always implies its companion
source is also `null` — there is nothing to source when a field is
unset. This is enforced structurally by every write path below, not
re-validated defensively at read time.

### 1.2 `Ticket` entity changes

`lib/features/tickets/domain/entities/ticket.dart` gains two fields,
placed and documented the same way `estimateRollup`/`timeSpentRollup`
are — **excluded from `copyWith`**, since which value they take depends
on *which write path* produced the field value, not something a plain
field-setter can express:

```dart
/// Where the current [complexity] value came from, or `null` if
/// [complexity] itself is unset. Written only by `TicketRepository`'s
/// dedicated methods — see [Ticket.complexity]'s updated dartdoc and
/// `aion-arch/changes/ai-assisted-complexity-and-estimate-suggestions/design.md`
/// §1.2. Never part of [copyWith].
final TicketEstimationSource? complexitySource;

/// Same as [complexitySource], for [estimate].
final TicketEstimationSource? estimateSource;
```

Added to the constructor (both optional, default `null`), `props`, and
`_withRollup`-style full-reconstruction call sites (see §2.3).
`Ticket.complexity`'s and `Ticket.estimate`'s own dartdocs get a
one-line pointer to `complexitySource`/`estimateSource` respectively.

### 1.3 `embedding_similarity.dart` (new shared utility)

`lib/features/tickets/domain/utils/embedding_similarity.dart` — extracts
`TicketDocumentSearchService._cosineSimilarity`'s existing body verbatim
into a top-level function:

```dart
/// Cosine similarity between two embedding vectors serialized as raw
/// `Float32List` bytes (the format `EmbeddingProvider.embed` produces).
/// Returns `0.0` for a zero-length vector or a zero vector, rather than
/// dividing by zero.
double cosineSimilarity(Uint8List a, Uint8List b) { ... }
```

`TicketDocumentSearchService` is updated to call this instead of its own
private copy (its own `_cosineSimilarity` method is deleted). The new
`TicketEstimationSuggester` (§2.1) uses the same function — this is the
only piece the two features genuinely share; `TicketDocumentSearchService`
itself is not otherwise touched (still page/resource-scoped, still its
own query shape) per proposal.md's scope note.

## 2. Data / orchestration layer

### 2.1 `TicketEstimationSuggester` (new)

`lib/features/tickets/presentation/cubit/ticket_estimation_suggester.dart`
— placed alongside `TicketRollupRecomputer`, not in `data/services/`,
because it owns the actual judgment logic (is a field locked? how many
comparable tickets? what counts as low-confidence?) that
`aion-arch/ideas/feedback_cubit_domain_logic`-equivalent project
convention keeps out of the repository/service layer. `TicketsCubit`
constructs one instance in its own constructor body, next to
`_rollupRecomputer`:

```dart
class TicketEstimationSuggester {
  TicketEstimationSuggester(
    this._repository, {
    EmbeddingProvider? embeddingProvider,
    ProviderRegistry? providerRegistry,
    ModelRoutingRepository? modelRoutingRepository,
  }) {
    _embeddingProvider = embeddingProvider;
    _providerRegistry = providerRegistry;
    _modelRoutingRepository = modelRoutingRepository;
  }

  final TicketRepository _repository;
  late final EmbeddingProvider? _embeddingProvider;
  late final ProviderRegistry? _providerRegistry;
  late final ModelRoutingRepository? _modelRoutingRepository;

  static const _maxComparableTickets = 5;

  /// Background path — fires from `TicketsCubit.createTicket`/
  /// `updateTicket`, always `unawaited`. Silently no-ops (no exception
  /// ever escapes) if:
  /// - constructed without an `EmbeddingProvider`/`ProviderRegistry`
  ///   (mirrors `_triggerEmbeddingRegen`'s/`_runShallowSummarization`'s
  ///   own optional-dependency guards), or
  /// - both `complexity` and `estimate` are already `manual`-locked
  ///   (nothing eligible — skips the model call entirely rather than
  ///   spending one for zero writable output).
  /// Only requests a suggestion for whichever of `complexity`/`estimate`
  /// is *not* currently `manual` (i.e. `null` source or already
  /// `aiSuggested`/`aiSuggestedLowConfidence`).
  Future<void> suggest(Ticket ticket) =>
      _run(ticket, forceComplexity: false, forceEstimate: false);

  /// User-invoked path — fires from `TicketsCubit.regenerateComplexitySuggestion`/
  /// `regenerateEstimateSuggestion`, always awaited by the caller so it
  /// can re-emit `TicketDetailLoaded` once this resolves. Bypasses the
  /// lock for exactly the one field the caller names (`forceComplexity`/
  /// `forceEstimate`) — the other field is left completely untouched
  /// regardless of its own lock state, even if this call also happens to
  /// produce a value for it (per design §2.1's per-field independence).
  Future<void> regenerate(
    Ticket ticket, {
    bool forceComplexity = false,
    bool forceEstimate = false,
  }) => _run(
    ticket,
    forceComplexity: forceComplexity,
    forceEstimate: forceEstimate,
  );

  Future<void> _run(
    Ticket ticket, {
    required bool forceComplexity,
    required bool forceEstimate,
  }) async {
    final embeddingProvider = _embeddingProvider;
    final providerRegistry = _providerRegistry;
    if (embeddingProvider == null || providerRegistry == null) return;

    final wantComplexity =
        forceComplexity || ticket.complexitySource != TicketEstimationSource.manual;
    final wantEstimate =
        forceEstimate || ticket.estimateSource != TicketEstimationSource.manual;
    if (!wantComplexity && !wantEstimate) return;

    try {
      final queryVector = await embeddingProvider.embed(
        '${ticket.title}\n\n${ticket.description ?? ''}',
      );
      final all = await _repository.getAllTickets();
      final comparable = <(Ticket, double)>[
        for (final other in all)
          if (other.id != ticket.id &&
              other.embedding != null &&
              (other.complexity != null || other.estimate != null))
            (other, cosineSimilarity(queryVector, other.embedding!)),
      ]..sort((a, b) => b.$2.compareTo(a.$2));
      final topComparable = comparable
          .take(_maxComparableTickets)
          .map((e) => e.$1)
          .toList();
      final lowConfidence = topComparable.isEmpty;

      final model = await _resolveModel();
      if (model == null) return;
      final provider = providerRegistry.providerById(model.providerId);
      final prompt = _buildPrompt(
        ticket,
        topComparable,
        wantComplexity: wantComplexity,
        wantEstimate: wantEstimate,
      );

      final buffer = StringBuffer();
      final events = await provider.client.run(
        AgentRequest(prompt: prompt, model: model.modelId),
      );
      await for (final event in events) {
        switch (event) {
          case AgentTextEvent(:final text):
            buffer.write(text);
          case AgentDoneEvent():
          case AgentOverageDetectedEvent():
          case AgentToolUseEvent():
            break;
          case AgentErrorEvent():
            return; // background nicety — swallow, never surface TicketsError
        }
      }

      final parsed = _parseSuggestion(buffer.toString());
      if (parsed == null) return;

      await _repository.applyEstimationSuggestion(
        ticket.id,
        complexity: wantComplexity && parsed.complexity != null
            ? (value: parsed.complexity!, lowConfidence: lowConfidence)
            : null,
        estimate: wantEstimate && parsed.estimateMinutes != null
            ? (value: parsed.estimateMinutes!, lowConfidence: lowConfidence)
            : null,
      );
    } catch (_) {
      // Background nicety — never let a network/parse failure surface as
      // TicketsError or interrupt the caller's own save flow.
    }
  }

  /// Mirrors `TicketsCubit._resolveModel(ModelPhase.capable)`'s exact
  /// fallback chain (routing repository → first registered provider's
  /// first model → hardcoded default) — duplicated rather than shared
  /// because `TicketsCubit._resolveModel` is private; both copies must be
  /// kept in sync if that fallback chain ever changes. Returns `null`
  /// only when even the hardcoded default can't be constructed, which
  /// doesn't happen in practice — kept nullable defensively.
  Future<AgentModelDescriptor?> _resolveModel() async { ... }

  String _buildPrompt(
    Ticket ticket,
    List<Ticket> comparable, {
    required bool wantComplexity,
    required bool wantEstimate,
  }) { ... } // see §2.2 for the exact format

  ({TicketComplexity? complexity, int? estimateMinutes})? _parseSuggestion(
    String text,
  ) { ... } // see §2.2
}
```

### 2.2 Prompt format and parsing

Deliberately mirrors `_runShallowSummarization`/`_parseSummaryFindings`'s
existing "ask for a fixed delimited format, buffer text, parse markers"
shape rather than introducing structured tool-calling (the `capable`
phase is `noTools`).

Prompt shape (only the requested lines are asked for — `wantComplexity`/
`wantEstimate` each gate one line of the request):

```
You are estimating a work ticket's size. Respond with exactly these
line(s) and nothing else:
COMPLEXITY: small, medium, or large
ESTIMATE_MINUTES: a positive integer

Ticket to estimate:
Title: <ticket.title>
Description: <ticket.description ?? "(none)">

Comparable past tickets, for calibration:
- "<title>" — complexity: <small|medium|large|unset>, estimate: <N min|unset>
  (repeated per comparable ticket; section omitted entirely when
  `comparable` is empty)
```

Parsing: a line-anchored regex per requested field (`^COMPLEXITY:\s*(small|medium|large)`,
`^ESTIMATE_MINUTES:\s*(\d+)`, case-insensitive, multiline). A missing or
malformed line for a field means the model declined/failed to produce
that value — treated as "no suggestion this round" for that field (skip
writing it), never an error. `ESTIMATE_MINUTES` of `0` or a non-positive
parse is treated the same as missing (a zero/negative estimate is
meaningless).

### 2.3 `Ticket` reconstruction call sites

`TicketRollupRecomputer._withRollup` and any other full-reconstruction
call site (`grep` for `Ticket(\s*$` constructor calls specifying every
field) gain `complexitySource: ticket.complexitySource, estimateSource:
ticket.estimateSource,` — a mechanical pass-through, not a design
decision.

## 3. Repository layer

### 3.1 `TicketRepository` (interface changes)

```dart
/// Writes an AI-generated complexity/estimate suggestion for the ticket
/// with id [id]. Each parameter, when non-null, overwrites that field's
/// value and sets its companion source to
/// [TicketEstimationSource.aiSuggestedLowConfidence] (if `lowConfidence`)
/// or [TicketEstimationSource.aiSuggested] otherwise; a `null` parameter
/// leaves that field (and its source) completely untouched — this is how
/// a caller writes just one field when the other is locked or the model
/// produced no value for it. Never touches `updatedAt` — an AI
/// suggestion is a background side effect, not a user edit, mirroring
/// [updateEmbedding]/[updateRollup]. Throws if [id] does not exist.
Future<void> applyEstimationSuggestion(
  String id, {
  ({TicketComplexity value, bool lowConfidence})? complexity,
  ({int value, bool lowConfidence})? estimate,
});
```

`updateTicket`'s existing dartdoc/behavior is **modified** (not
replacing its signature, just its write semantics): whenever the
`Ticket` passed in has a non-null `complexity`, the write also stamps
`complexitySource = TicketEstimationSource.manual`; whenever `complexity`
is `null`, `complexitySource` is also cleared to `null`. Same rule for
`estimate`/`estimateSource`. This is unconditional and mechanical —
`updateTicket` is definitionally the plain-user-edit path (the detail
screen's `SelectionMenu`/`InlineEditableField` onCommit handlers are its
only callers), so every value that reaches it through that path is by
definition user-set, never something `TicketsCubit` needs to branch on
per-call.

### 3.2 `DriftTicketRepository`

- `applyEstimationSuggestion`: builds a `TicketsTableCompanion` with only
  the non-null side(s) populated (`complexity`/`complexitySource` and/or
  `estimate`/`estimateSource`), no `updatedAt`, via
  `TicketDao.updateFields` (the same generic method `updateTicket`/
  `updateTicketStatus` already use) — no new DAO method needed.
- `updateTicket`: companion gains `complexitySource: Value(ticket.complexity
  != null ? TicketEstimationSource.manual.name : null)` and the mirror
  line for `estimateSource`/`estimate`.
- `createTicket`'s insert companion gets the identical two lines — a
  ticket created with a `complexity`/`estimate` already filled in (the
  create form's own Complexity picker) is just as much a manual edit as
  a later one through `updateTicket`, so it's `manual`-locked from the
  moment it's created. A ticket created with either field left `null`
  (the common case) naturally gets `null` sources — freshly eligible for
  the automatic suggester's very next `suggest()` call.
- `_toEntity`: two more `_parseNullableEnum(TicketEstimationSource.values,
  row.complexitySource)`/`row.estimateSource` lines, same pattern as
  every other nullable enum column.

### 4.2 Trigger call sites

  `unawaited(_triggerEmbeddingRegen(persisted));` line, add

- `updateTicket`: inside the existing `if (previous == null ||

### 4.3 New public methods (user-invoked regenerate)

```dart
/// Explicitly re-suggests [ticket]'s complexity via
/// [TicketEstimationSuggester.regenerate], bypassing the lock even if
/// `ticket.complexitySource == TicketEstimationSource.manual`. Awaited —
/// unlike the passive background trigger in [createTicket]/[updateTicket],
/// this is a direct response to the detail screen's Regenerate button, so
/// it re-fetches and emits [TicketDetailLoaded] with the refreshed value
/// once the suggestion lands, rather than leaving the UI to catch up on
/// next reopen. No-ops (does nothing, emits nothing) if
/// `ticket.complexity == null` — nothing to regenerate against an unset
/// field; the picker's own "+ COMPLEXITY" flow is how a first value gets
/// set. Emits [TicketsError] only if the repository re-fetch itself
/// throws — a failed/empty model suggestion (see
/// [TicketEstimationSuggester]'s swallow-on-failure behavior) silently
/// leaves the ticket's current value in place and still re-emits
/// [TicketDetailLoaded] unchanged, rather than erroring the whole screen
/// over a background-nicety failure.
Future<void> regenerateComplexitySuggestion(Ticket ticket) async {
  if (ticket.complexity == null) return;
  await _estimationSuggester.regenerate(ticket, forceComplexity: true);
  final refreshed = await _repository.getTicketById(ticket.id);
  if (refreshed != null) emit(TicketDetailLoaded(refreshed));
}

/// Same as [regenerateComplexitySuggestion], for `estimate`.
Future<void> regenerateEstimateSuggestion(Ticket ticket) async {
  if (ticket.estimate == null) return;
  await _estimationSuggester.regenerate(ticket, forceEstimate: true);
  final refreshed = await _repository.getTicketById(ticket.id);
  if (refreshed != null) emit(TicketDetailLoaded(refreshed));
}
```

# Aion — AI Suggestion Badge & Regenerate Action Specification

Two new inline affordances added to the **existing** Complexity and Estimate rows in `TicketMetadataSection` on the ticket detail screen. **No new screens; no changes to list rows, board cards, or the ticket-creation form.**

1. **`AiSuggestionBadge`** — flags a field value that was produced by the background suggester and not yet confirmed or edited by the user. Two variants: **plain** ("AI suggested") and **low confidence** (a cold-start guess produced with zero comparable historical tickets). §1.
2. **`RegenerateButton`** — a small icon-only button shown next to a **locked** field (one the user has manually edited), letting the user explicitly request a fresh AI take on that one field, overriding the lock. §2.
3. **Composed row states** — how both affordances compose with the existing Complexity/Estimate layouts across the full lifecycle. §3.

Behavioral model (drives which affordance shows — the visual layer only):

- A field is either **AI-suggested** (value came from the suggester, untouched by the user → **badge**, no regenerate button) or **locked** (user typed or edited it → **no badge, regenerate button**). The two are mutually exclusive; a field is never both.
- Editing an AI-suggested field by hand locks it: the badge disappears, the regenerate button appears. The automatic suggester never overwrites a locked field.
- **Regenerate** is the only way to ask for a fresh suggestion on a locked field. While that request is in flight the button is in its loading state (§2.6).

This spec is implementation-ready. All values reference Aion's `AionColors` / `AionText` / `AionRadius` / `AionSpacing` tokens read via `ThemeScope.of(context)`. **No Material widgets** — Flutter primitives only (`DecoratedBox`, decoration-only `Container`, `Row`/`Column`/`Padding`, `Text`, `GestureDetector`, `Focus`, `AnimatedRotation`/`RotationTransition`, `PhosphorIcon`). Translucent fills are `token.withOpacity(x)`, never hardcoded ARGB. Both themes (**Arctic** light, **Obsidian** dark) are covered; where identical it is stated.

## 0. Foundations for this feature

### 0.1 Tokens — reuse, no new hue

The AI badge is **informational, neutral, secondary-priority** — not an accent, not a priority/severity/status signal. It must not compete with `PriorityBadge`'s colored scale or introduce a new hue.

It therefore reuses the existing quiet-chrome tints already defined for the estimate rollup (`AionColorsHubTokens`), **not** `primarySubtle`:

```dart
// neutral, informational tint — quiet numeric/data chrome (already defined)
Color get neutralTint =>
    textSecondary.withOpacity(isDark ? 0.14 : 0.09);

// hairline for the same family (already defined)
Color get neutralBorderTint =>
    textSecondary.withOpacity(isDark ? 0.26 : 0.18);
```

**Design decision — `neutralTint` over `primarySubtle`.** `primarySubtle` is documented as "AI comment bubble / AI badge background," which makes it a tempting fit. It is rejected here: `primarySubtle` *is* the primary hue tint, and the brief requires the badge to read as monochrome and to *not* introduce or compete with an accent. `primarySubtle` stays where it belongs — on the AI **comment** surface, which is meant to read as a first-class primary-accented author. The inline field badge is quieter chrome and sits in the same neutral family as the rollup subline it lives beside. **No new color tokens are introduced.**

One translucent value is needed for the regenerate loading fill; it reuses `primary` and follows the existing `xxxWash` opacity convention. If a `primaryWash` helper already exists, reuse it; otherwise add:

```dart
// faint primary fill under an actively-working control
Color get primaryWash =>
    primary.withOpacity(isDark ? 0.16 : 0.10);
```

`focusRing` (`primary.withOpacity(isDark ? 0.30 : 0.16)`, per Design System §Shadows) is reused verbatim for the regenerate button's focus state.

### 0.2 Typography

The badge label is short prose ("AI suggested"), not an uppercase tag, so it uses a calm sentence-case Manrope style rather than `AionText.chip`. No existing style is exactly 11 / w600, so one small style is added to `AionText`:

```dart
// small inline informational badge label
static const badgeLabel = TextStyle(
  fontFamily: 'Manrope',
  fontSize: 11,
  fontWeight: FontWeight.w600,
  height: 1.0,
);
```

The low-confidence caveat reuses a lighter inline treatment: `AionText.badgeLabel.copyWith(fontSize: 10.5, fontWeight: FontWeight.w400)`. All styles are colorless; color is applied at the use site.

| AI-generated | `PhosphorIcons.sparkle` | Fill | Leading glyph in `AiSuggestionBadge` |

## 1. `AiSuggestionBadge`

A small, non-interactive pill rendered inline immediately **after** a field's value — after the Complexity meter+label, or after the Estimate's numeric value. Shown only while the field is AI-suggested and untouched by the user. It has no hover / focus / press / disabled states of its own.

### 1.1 Default (plain) variant

- Container: `DecoratedBox` (or decoration-only `Container`), `mainAxisSize: min` so it hugs content.
  - `padding: EdgeInsets.fromLTRB(7, 3, 8, 3)`
  - `borderRadius: BorderRadius.circular(6)` — `AionRadius.sm`
  - fill: `colors.neutralTint`
  - border: **none**
  - shadow: **none**
- Inner `Row`, `mainAxisSize: min`, `crossAxisAlignment: center`, `spacing`/gap **5**:
  - **Leading icon** — `PhosphorIcon(PhosphorIconsFill.sparkle, size: 12, color: colors.textSecondary)`.
  - **Label** — `Text('AI suggested', style: AionText.badgeLabel.copyWith(color: colors.textSecondary))`.

### 1.2 Low-confidence (cold-start) variant

Shown when the suggestion was produced with **zero comparable historical tickets**. It stays in the same neutral family — no new hue — but is distinguishable **at a glance** by a dashed hairline and the appended caveat.

Identical to §1.1 except:

- **Border:** `Border.all(color: colors.neutralBorderTint, width: 1)` rendered **dashed**. Since Flutter's `Border` has no dash style, draw the dashed rounded rect in a `CustomPaint` border (`PathMetric`-based dash, `strokeWidth: 1`, radius 6) behind the same `neutralTint` fill — do **not** use a Material `OutlinedBorder`. Dash geometry: `dashWidth: 3, dashGap: 2.5`.
- **Leading icon opacity:** the `sparkle` glyph is drawn at `color: colors.textSecondary.withOpacity(0.72)` (slightly dimmed to reinforce tentativeness).
- **Trailing caveat** — after the label, one more child in the same `Row`:
  - `Text('· low confidence', style: AionText.badgeLabel.copyWith(fontSize: 10.5, fontWeight: FontWeight.w400, color: colors.textMuted))`.

The dashed edge is the primary glanceable differentiator; the caveat text is the explicit confirmation. Both read calm and monochrome — never as a warning or error.

### 1.3 Dimensions summary

| Property | Plain | Low confidence |
|---|---|---|
| Padding | `EdgeInsets.fromLTRB(7, 3, 8, 3)` | same |
| Radius | `AionRadius.sm` (6) | same |
| Fill | `AionColors.neutralTint` | same |
| Border | none | 1px **dashed** `AionColors.neutralBorderTint` |
| Shadow | none | none |
| Icon | `PhosphorIconsFill.sparkle`, 12, `textSecondary` | same glyph, `textSecondary.withOpacity(0.72)` |
| Label | `AionText.badgeLabel`, `textSecondary` | same + caveat `10.5 w400`, `textMuted` |
| Inner gap | 5 | 5 |
| Approx height | ~20px (matches meta-row chips) | same |

### 1.4 Theme differences

Identical structure, radius, padding, and token references in both themes. Only the resolved colors differ via the active `AionColors`: `neutralTint` = `textSecondary @ 0.09` (Arctic) / `@ 0.14` (Obsidian); `neutralBorderTint` = `@ 0.18` / `@ 0.26`; text/icon colors resolve to the theme's `textSecondary` / `textMuted`. No per-theme layout or radius change.

## 2. `RegenerateButton`

A small, icon-only, keyboard-focusable button shown inline next to a **locked** field's value. It is deliberately secondary: ghost by default (no fill, muted glyph), gaining fill and glyph weight only on interaction. Built from `Focus` + `GestureDetector` (or a raw `FocusableActionDetector`) wrapping a `DecoratedBox` — **no `InkWell`, `IconButton`, or other Material widget**.

### 2.0 Geometry (shared by all states)

- Visual box: `24×24` → wrap in a `SizedBox(width: 26, height: 26)` with the icon centered; extend the hit target to a minimum `44×44` via a transparent `Padding`/`GestureDetector` behind it (this app's minimum touch target) without enlarging the visible box.
- `borderRadius: BorderRadius.circular(8)` — `AionRadius.iconBtnSm`.
- Glyph: `PhosphorIcon(PhosphorIconsBold.arrowsClockwise, size: 15)`; color is state-dependent below.
- Shadow: none, except the focus ring (§2.4).

### 2.1 Default state

- Fill: **transparent** (ghost).
- Border: none.
- Glyph color: `colors.textMuted`.
- Cursor: `SystemMouseCursors.click`.

Recedes next to the field value — the value stays the loudest thing in the row.

### 2.2 Hover state

- Fill: `colors.surfaceHover`.
- Glyph color: `colors.textSecondary`.

### 2.3 Pressed state

- Fill: `colors.surfaceHover`.
- Glyph color: `colors.textPrimary`.
- Transform: `scale(0.96)` (matches the Design System's button press treatment).

### 2.4 Focused state (keyboard)

- Fill: `colors.surfaceHover`.
- Glyph color: `colors.textSecondary`.
- Focus ring: `BoxShadow(color: colors.focusRing, blurRadius: 0, spreadRadius: 3)` — the app-standard solid 3px ring, not a blur. Same treatment whether reached by keyboard or as a combined hover+focus.

### 2.5 Disabled state

Used when regenerate is unavailable for the field (e.g. suggester offline). Distinct from in-flight (§2.6).

- Fill: transparent.
- Glyph color: `colors.textMuted`.
- Opacity: **0.45** applied to the whole control (Design System disabled convention).
- Ignores pointer + not focusable (`Focus(canRequestFocus: false)`, `IgnorePointer`).

### 2.6 In-flight (loading) state

Shown from the moment a regenerate request is sent until the fresh suggestion arrives. The control is **active work**, not greyed-out — so it does **not** use the 0.45 disabled dimming.

- Fill: `colors.primaryWash` (§0.1).
- Glyph color: `colors.primary`.
- **Animation:** the glyph spins continuously — `RotationTransition` driven by an `AnimationController(duration: Duration(milliseconds: 900))..repeat()`, linear curve, clockwise. Dispose the controller when the state leaves in-flight.
- Not tappable and not focus-activatable while spinning (taps ignored); pointer cursor `SystemMouseCursors.basic`.
- On completion: controller stops, state returns to §2.1 (the field is now AI-suggested again → the row swaps the button back for `AiSuggestionBadge`, per §3).

### 2.7 State table

| State | Fill | Glyph color | Extra |
|---|---|---|---|
| Default | transparent | `textMuted` | — |
| Hover | `surfaceHover` | `textSecondary` | — |
| Pressed | `surfaceHover` | `textPrimary` | `scale(0.96)` |
| Focused | `surfaceHover` | `textSecondary` | 3px solid `focusRing` ring |
| Disabled | transparent | `textMuted` | whole control `opacity 0.45`, no pointer/focus |
| In-flight | `primaryWash` | `primary` | glyph spins 900ms linear loop; taps ignored |

### 2.8 Dimensions summary

| Property | Value |
|---|---|
| Visible box | `26×26` (glyph `15`) |
| Hit target | ≥ `44×44` (transparent extension) |
| Radius | `AionRadius.iconBtnSm` (8) |
| Glyph | `PhosphorIconsBold.arrowsClockwise`, 15 |
| Focus ring | `focusRing`, blur 0, spread 3 |
| Press scale | 0.96 |
| Spin period | 900ms, linear, clockwise |

### 2.9 Theme differences

Identical geometry and token references in both themes. Only resolved colors differ via the active `AionColors`: `surfaceHover`, `textMuted` / `textSecondary` / `textPrimary`, `primary`, `primaryWash`, `focusRing`. No per-theme geometry.

## 3. Composed row states — `TicketMetadataSection`

Both affordances slot into the **existing** Complexity and Estimate rows without changing their base layout. Each field column is a `Column`, `crossAxisAlignment: start`, gap `AionSpacing.sp8` (8): the existing caption label, then the value row. The badge / regenerate button is appended **inside the value row**, after the value, in a `Row` with `crossAxisAlignment: center` and gap **9** (badge) / **8** (regenerate button). Reserve a `minHeight: 26` on the value row so it does not jump when the trailing element swaps between badge and button.

The two field columns sit in a `Row` with horizontal gap `34`; wrap to a second line rather than truncate.

### 3.1 State set (per field)

| # | State | Trailing element | Notes |
|---|---|---|---|
| 1 | **Unset** | none | Today's row, unchanged — reference only, not redesigned. |
| 2 | **AI-suggested** | `AiSuggestionBadge` plain (§1.1) | Value present, untouched by user. No regenerate button. |
| 3 | **AI-suggested, low confidence** | `AiSuggestionBadge` low-confidence (§1.2) | Cold-start guess. No regenerate button. |
| 4 | **Locked / manual** | `RegenerateButton` default (§2.1) | User typed fresh, or edited an AI value. No badge. |
| 5 | **Regenerate in flight** | `RegenerateButton` in-flight (§2.6) | Spinning; taps ignored until value returns. |

Exactly one trailing element is ever present (badge **or** button, never both), matching the mutually-exclusive behavioral model in the header.

### 3.2 Complexity row

Base (unchanged): the `SelectionMenu` trigger — `ComplexityMeter` (14×12, 3 ascending bars, filled `primary` / empty `borderStrong`) + level label (`Text('Small'|'Medium'|'Large')`, `AionText.bodySm` w600, `textPrimary`), or the muted `+ COMPLEXITY` placeholder when unset. The value keeps its normal `textPrimary` weight in every state — the badge, not a dimmed value, carries the "not typed by hand" signal.

- Value → badge gap: **9**.
- Value → regenerate gap: **8**.
- Meter → label gap: **8** (unchanged).

### 3.3 Estimate row

Base (unchanged): caption label above (`AionText.caption`, `textMuted`), inline value = `PhosphorIcons.timer` (15, `textSecondary`) + `Text(formatMinutes(value))` (`AionText.bodySm` w600, `textPrimary`) — e.g. "45 min", "3h 30m", "2h" — or the `Add an estimate…` placeholder (`textMuted`) when unset. Same trailing-element rules and gaps as §3.2.

### 3.4 Layout notes

- The badge and button share the value row's vertical center; the badge's ~20px height and the button's 26px box both sit comfortably against the 14px value with the reserved `minHeight: 26`.
- When a field transitions AI-suggested → locked (user edits) the trailing element swaps badge → button in place; locked → in-flight swaps default → spinning button; in-flight → AI-suggested swaps button → badge. Cross-fade with a short `AnimatedSwitcher` (150ms) if desired, but not required.

## 4. Implementation notes

- **Mutually exclusive trailing element.** A field is AI-suggested (badge) **or** locked (button) — never both, never neither-when-set. Drive it off the ticket's per-field `isAiSuggested` / `isLocked` flags; the widget layer is pure display.
- **No new hue.** Badge fill/border use `neutralTint` / `neutralBorderTint`; only the regenerate in-flight and focus states touch `primary` (`primaryWash`, `focusRing`). Never hardcode a tint — read from `colors`.
- **No Material.** Badge = `DecoratedBox`/`Container` + `Row` + `Text` + `PhosphorIcon`; dashed border = `CustomPaint`. Button = `Focus` + `GestureDetector` + `DecoratedBox` + `RotationTransition`; **no** `Card`, `Chip`, `IconButton`, `InkWell`, `Tooltip`, `OutlinedBorder`.
- **Keyboard.** The regenerate button is in the tab order and activates on Enter/Space (`Shortcuts`/`Actions` or `FocusableActionDetector`); its focus ring is the app-standard solid 3px `focusRing`.
- **Dispose the spinner.** The in-flight `AnimationController` is created on entering in-flight and disposed on leaving it; never leave it repeating in the background.
- **Touch target.** Keep the visible button at 26px but guarantee a ≥44px hit target via a transparent extension — do not enlarge the visible chrome.
