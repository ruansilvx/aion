# Tickets cubit

- [x] **T5** — `aion/lib/features/tickets/presentation/cubit/tickets_cubit.dart`:
  add `prepareReleaseDraft(String releaseTicketId)` per `design.md` §4.1
  — fetch the release ticket and its `relatesTo`-linked work via
  `TicketLinkRepository.getLinksForTicket`, assemble the prompt (mirror
  `_createEpicSpec`'s context-assembly shape), resolve
  `ModelPhase.capable` via `_resolveModelAndProvider`, run the one-shot
  `AgentModelClient.run` call, call
  `ProjectStackDetector().detectVersionFile(_projectRootPath)`, return
  the assembled `ReleaseDraft`. Guard on `_providerRegistry`/
  `_linkRepository`/`_projectRootPath` being non-null (return `null`,
  no error emitted — mirrors `_createEpicSpec`'s own guard). On a model
  failure, emit
  `TicketsError(reason: TicketsErrorReason.releasePreparationFailed)`
  and return `null`. Full dartdoc per `design.md` §4.1's own wording.

- [x] **T6** — Same file: add `autoCreateReleaseTicket()` per
  `design.md` §4.2 — look up the cached `_workflowStatuses` entry with
  `role == WorkflowStatusRole.done`, query
  `getAllTicketsByType([epic, story, task, bug])` filtered client-side
  to that status, subtract every id already `relatesTo`-linked to any
  existing `release` ticket (`getLinksByTypes([relatesTo])` cross-
  referenced against `getAllTicketsByType([release])`'s ids), create a
  new `release` ticket titled `"Release — <today, yyyy-MM-dd>"`, link
  every surviving candidate via the existing `createTicketLink`, return
  the new ticket (or `null` if nothing qualifies). Full dartdoc.

- [x] **T7** — Same file: add `confirmRelease(ReleaseDraft draft)` per
  `design.md` §4.3 — write/create `CHANGELOG.md`'s new version section
  under `## [Unreleased]`, conditionally call
  `ProjectStackDetector().writeVersion` when
  `draft.detectedVersionFile != null`, `GitRepositoryClient.add` +
  `.commit` (`"chore(release): v<version>"`), `.tag`, `.push`, `.pushTag`
  — in that order (commit+push before tag+push, per `design.md` §4.3's
  no-stranded-untagged-commit rationale). Propagates failures rather
  than catching them (caller keeps the draft alive for retry — see
  T10). Full dartdoc, explicitly noting the ordering rationale and the
  lack of automatic rollback on a partial failure.
