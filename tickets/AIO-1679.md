# 6. `TicketsCubit` — agentic verify turn

- [x] Update `lib/features/tickets/presentation/cubit/tickets_cubit.dart`
      per design.md §5:
      - Constructor: remove `FlutterVerifier? flutterVerifier`; add
        `BaselineRepository? baselineRepository`, `String? projectId`,
        `String? baselineVersion` (and matching `late final` fields),
        following the existing optional-dependency pattern.
      - Rename `_maxAnalyzeRetries` → `_maxVerifyRetries`.
      - Add `_effectiveAssetContent(String assetKey)` (§5.2).
      - Change `_assembleExecutionContext` to `Future<String>`, adding
        the `## Project conventions` section and the environment-setup
        sentence (§5.3).
      - Add `_assembleVerificationContext(Ticket task)` (§5.4).
      - Restructure `_runCodingExecution`'s loop: drop the
        `flutterVerifier.pubGet` setup call; replace the
        `flutterVerifier.analyze` check with a second `ChatCubit.
        runChatTurn` call using `_assembleVerificationContext`'s prompt,
        followed by `_lastCommentContent` +
        `_verificationFailureReason` to decide pass/fail (§5.5). Update
        the null-guard to require `baselineRepository`/`projectId`/
        `baselineVersion` instead of `flutterVerifier`.
      - Add `_lastCommentContent(String chatTicketId)` and
        `_verificationFailureReason(String? reply)` (§5.6).
      - Change `_assembleCorrectiveContext` to take a `String reason`
        parameter instead of `FlutterVerifyResult` (§5.7).
      - Rewrite every dartdoc comment referencing `FlutterVerifier`/
        `flutter analyze` by name (the class-level dartdoc, the
        constructor's dartdoc, `_runCodingExecution`'s dartdoc,
        `_assembleExecutionContext`'s dartdoc,
        `_assembleCorrectiveContext`'s dartdoc) to describe the
        implement-then-verify two-model-turn loop instead (§5.8).
- [x] Update `test/features/tickets/cubit/tickets_cubit_test.dart` —
      replace any `FlutterVerifier` mock/fake and
      `flutterVerifier:`/`.pubGet`/`.analyze` references with fakes for
      `BaselineRepository`/`projectId`/`baselineVersion`, and assertions
      against the new two-turn (implement + verify) `ChatCubit.
      runChatTurn` call sequence, the `VERIFICATION: PASSED`/`FAILED`
      terminal-line parsing, and the retry loop behavior. Also added a
      `stubStatefulComments` helper — replaces every hand-crafted
      "final state" `getCommentsForTicket` stub in the affected groups
      with a real append-only store fed by `addComment`, since the new
      code reads that repository twice per run (mid-run for the verify
      turn, end-of-run for `_executionSucceededWithPr`) and a static
      snapshot can't correctly answer both.
- [x] Update `lib/core/routing/app_router.dart`'s `TicketsCubit`
      construction site per design.md §7: remove `flutterVerifier:
      FlutterVerifier()`, add `baselineRepository:
      context.read<BaselineRepository>()`, `projectId:
      widget.project.id`, `baselineVersion:
      widget.project.baselineVersion`.
- [x] Update `lib/l10n/app_en.arb`'s
      `settingsAutomationCodingExecutionRetryDescription` to describe
      verification generically instead of naming `flutter analyze`
      literally (e.g. "When verification fails after a coding-execution
      run, retry automatically, ask first, or always wait for a manual
      retry.").
- [x] Update every other doc-comment/string in `lib/` that names
      `flutter analyze`/`FlutterVerifier` literally and is no longer
      accurate: `lib/core/automation/automation_context.dart`'s
      `codingExecutionRetry` dartdoc, `lib/features/tickets/
      presentation/cubit/tickets_state.dart` (two dartdoc references),
      `lib/features/tickets/presentation/screens/
      ticket_detail_screen.dart` (dartdoc/comment references to the
      live tool-use hint text and the error-well content — reword
      generically; the *behavior* those widgets render is unchanged,
      only the wording that names a specific command).
