# T32. Implement `MarkdownEditor`'s saving/error states (design.md

§1.3–§1.4), finding #5: changed `onCommit`'s type from
`ValueChanged<String>` to `Future<void> Function(String)` so the
widget can await the result — the design's own fire-and-forget
signature couldn't support this. Save now shows an `AppSpinner` and
disables both buttons while in flight; a thrown error shows an inline
danger row (new `pageDetailMarkdownSaveError` l10n string) that clears
on the next keystroke. Note: `AppButton` has no built-in
loading-label slot (no screen in this codebase swaps a button's
label for a spinner — confirmed via `CreateTicketScreen`'s
`_isSubmitting`), so this places the spinner beside the buttons
rather than widening that shared atom's API for one caller.
