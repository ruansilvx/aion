# Upgrade the pinned @anthropic-ai/claude-agent-sdk dependency off the stale ^0.1.0 range

`agent_bridge/package.json` pins `"@anthropic-ai/claude-agent-sdk": "^0.1.0"`, which resolves to `0.1.77` — installed via `npm install`/`npm ci` today. npm's `latest` is `0.3.268` (published the same day this was filed): the pin means `npm install`/`npm ci` can never move past `0.1.x` regardless of how many fixes ship upstream, so Aion has been running many months behind on a dependency under near-daily active development.

Filed as a follow-up out of the AIO-2839 investigation (task-scoped `tool_use` id-collision bug, fixed there via an in-place turn retry — [aion#124](https://github.com/ruansilvx/aion/pull/124)): the specific bug is a known, actively-reported upstream issue (`anthropics/claude-code` #21089, #20693, #20631, #20885, #20573, #21317; `anthropics/claude-agent-sdk-typescript` #151) that is still being reported against CLI builds close to today, so an upgrade is **not** expected to conclusively fix that bug on its own — AIO-2839's in-place-retry recovery is the actual mitigation for it. This ticket is about the dependency hygiene problem on its own merits: staying multiple minor versions behind means missing over a year of unrelated fixes (e.g. the 0.3.196 tool-use-id dedup fix for long-running sessions) and improvements.

**Live-tested against AIO-2817/AIO-2819 on 2026-09-11** (after aion#124 merged): both retried and both hit the identical `tool_use` id-collision error again, with a fresh `request_id` each time — confirming these two tasks trigger the bug *deterministically* on every attempt (not just intermittently), so aion#124's bounded retry-and-handoff couldn't recover them. An SDK/CLI upgrade is the only remaining lever for tasks in this bucket, though as noted above it isn't guaranteed to fix it.

**Scope**:
- Bump `agent_bridge/package.json`'s version constraint to track current stable (or at least a much narrower/newer range than `^0.1.0`), and run `npm install` to update `agent_bridge/package-lock.json` (or equivalent).
- Re-verify `agent_bridge/index.mjs`'s usage against the new version's API surface — `query()`'s options shape, the `resume`/`forkSession` handling, and the `message.error`/`result` event shapes it parses — since real API changes are likely across two major version jumps (0.1 → 0.3). Confirmed via the SDK's own CHANGELOG.md that the `Options` interface and event shapes have evolved; a blind bump without re-checking `index.mjs` risks silently breaking coding-execution turns.
- Re-run the full test suite plus a live coding-execution smoke test (implement + verify turn against a real ticket) after the bump.
- Once bumped, re-retry AIO-2817/AIO-2819 to see if the upgrade actually resolved their deterministic trigger.

**Not in scope**: chasing the AIO-2839 parallel-tool-call bug itself further — no SDK-level flag to disable parallel tool use was found in either the pinned version or latest's `.d.ts`, so there is nothing to configure around it beyond the in-place retry already shipped.
