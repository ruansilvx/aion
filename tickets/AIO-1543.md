# Spec Delta: Persistent Navigation Shell

**Reconciled 2026-09-03, with real drift folded in:** this delta describes the *original* shell — two destinations (Tickets, Documentation), a two-action popover (Switch Project, Trash), and three now-removed per-screen buttons (`_SwitchProjectButton`, `_DocumentationEntryButton`, `_TrashEntryButton`). Two later changes extended it further, per the current `aion-arch/specs/tickets.md` "Persistent navigation shell" section: a third destination, **Inbox**, was added (see the `new-project-onboarding-inbox` change's own spec ticket), and the secondary-actions popover grew two more entries, **Settings** and **Workflow** (added alongside the configurable-workflow/provider-settings work — see `providers.md`'s Settings screen). The structural mechanism this delta introduced (the responsive `WorkspaceNavShell`, the shared popover pattern, active-destination detection) is otherwise unchanged and still accurate.

Delta against `aion-arch/specs/tickets.md` and `aion-arch/specs/projects.md`.
Read alongside `proposal.md` and `design.md` in this change folder.

## ADDED

- `WorkspaceNavShell` (`core/routing/workspace_nav_shell.dart`) — a
  persistent navigation shell wrapping every `/workspace/*` route's
  content (rendered inside `WorkspaceShell`, which already wraps that
  content today for provider wiring). Two responsive layouts, switched
  via `LayoutBuilder` at an 900px breakpoint:
  - **Wide (`> 900px`)**: a left sidebar listing Tickets and
    Documentation as persistent, always-tappable destinations, plus a
    secondary-actions trigger at the bottom.
  - **Compact (`<= 900px`)**: a bottom tab bar with the same two
    destinations plus the same secondary-actions trigger.
- A shared secondary-actions popover (reusing the existing
  `SelectionMenu<T>` overlay primitive), triggered by a single
  avatar-circle affordance present in both layouts, offering "Switch
  Project" (navigates to `/hub`) and "Trash" (navigates to
  `/workspace/tickets/trash`).
- Active-destination detection: `/workspace/documentation` and
  `/workspace/pages/*` both resolve to the Documentation destination;
  everything else under `/workspace/tickets*` resolves to Tickets.
  Tapping a nav item always navigates to that destination's root route,
  regardless of which sub-route is currently active.
- `WorkspaceShell` (`core/routing/app_router.dart`) gains a
  `currentLocation` field, threaded from the `ShellRoute` builder's
  `GoRouterState.uri.path` (previously discarded), so
  `WorkspaceNavShell` can compute the active destination.
- New localized string `navShellSecondaryMenuLabel` (semantics label for
  the secondary-actions trigger).

## MODIFIED

- `DocumentationScreen` now has a way back to Tickets on every platform
  (not just web, where a browser back button happened to exist) — it's
  wrapped by the same persistent nav shell as every other
  `/workspace/*` screen. This directly resolves the previously-open gap:
  Documentation had no shared chrome with the rest of the workspace.
- `TicketsListScreen`'s header no longer renders
  `_SwitchProjectButton`, `_DocumentationEntryButton`,
  `_TrashEntryButton`, or the decorative avatar circle — those three
  navigation actions and the account affordance now live in the shared
  `WorkspaceNavShell` instead of being screen-local. The header's
  `_ViewModeToggle` (List/Board) and `_SelectModeToggle` are unaffected.
- `DocumentationScreen`'s header no longer renders its own decorative
  avatar circle — same account affordance now lives in the shared
  `WorkspaceNavShell`.
- `ProjectSwitcherMenu` (`features/projects/presentation/widgets/project_switcher_menu.dart`)
  goes from unused (only referenced in its own file's dartdoc elsewhere)
  to... actually not directly reused as a component in this change — see
  design.md §2.3, `_NavItem` matches its visual language but is a
  separate widget. `ProjectSwitcherMenu` itself remains unused after this
  change; its "Switch Project" destination is instead served by the new
  `_SecondaryActionsTrigger` popover's "Switch Project" entry, which
  calls the same `context.go('/hub')` navigation `ProjectSwitcherMenu`
  was built for.

## REMOVED

- Nothing removed outright at the route/behavior level — every existing
  `/workspace/*` route keeps its path and builder unchanged. What's
  removed is the three ad hoc per-screen header buttons and two
  decorative avatar circles listed above, superseded by the shared shell.

## Known gaps carried forward (not resolved by this change)

- No `StatefulShellRoute`-style per-section navigation-state
  preservation — switching between Tickets and Documentation still
  drops the previous section's scroll position/sub-route, same as
  today. See proposal.md's Non-goals.
- The companion "consistent max-width content layout" idea remains
  unresolved by this change — screen content still stretches
  edge-to-edge on wide screens inside the new nav shell's content area.
- The three bugs flagged alongside this idea during brainstorming
  (childless-page chevron, markdown checkbox rendering, clipped
  "synced" info bubbles) are unaddressed — out of scope, unrelated to
  navigation.
