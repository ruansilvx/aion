# Design: Consistent max-width, centered content layout

## Architecture summary

This is a pure presentation-layer change — no new entities, no new
Cubit, no repository or drift changes. It adds one new
`design_system/` token file, one new `design_system/` widget, and
retrofits seven existing screen files to use that widget in place of
their current unconstrained (or, for `NewProjectScreen`, ad hoc)
content wrapping.

No BLoC states are added or modified by this change.

## New token: `AionContentWidth`

New file: `design_system/tokens/aion_content_width.dart`.

```dart
// design_system/tokens/aion_content_width.dart — Content max-width
// token pair (design-system layer).

/// Aion's content max-width scale. Every screen that constrains its
/// content column to a readable/scannable width uses one of these two
/// values via [ContentMaxWidth] — never a raw number in widget code.
abstract final class AionContentWidth {
  /// Forms and short interactive flows (create/edit screens). Matches
  /// the value `NewProjectScreen` established before this widget
  /// existed.
  static const double form = 520;

  /// Reading-oriented content: ticket detail, page detail/documentation
  /// content, documentation tree/search list, ticket list.
  static const double reading = 840;
}
```

Two values only, matching the two `ContentWidthVariant` cases below.
No breakpoint system — see proposal.md's Non-goals.

## New widget: `ContentMaxWidth`

New file: `design_system/atoms/content_max_width.dart`. An atom, not
a molecule: single-purpose structural wrapper, no sub-widgets, no
state, no awareness of any feature.

```dart
// design_system/atoms/content_max_width.dart — Max-width, centered
// content wrapper (design-system layer).

import 'package:flutter/widgets.dart';

import 'package:aion/design_system/tokens/aion_content_width.dart';

/// Which [AionContentWidth] value a [ContentMaxWidth] wrapper applies.
enum ContentWidthVariant {
  /// Forms and short interactive flows — [AionContentWidth.form].
  form,

  /// Reading-oriented content — [AionContentWidth.reading].
  reading,
}

/// Constrains [child] to a maximum width and centers it horizontally,
/// so content on wide viewports stays readable instead of stretching
/// edge-to-edge. Does not add its own horizontal padding — callers keep
/// their existing outer padding (e.g. [AionSpacing.sp20]) so narrow/
/// mobile viewports still get edge breathing room; this widget only
/// caps and centers once space exceeds the variant's max width.
class ContentMaxWidth extends StatelessWidget {
  /// Creates a [ContentMaxWidth] wrapping [child] at the given
  /// [variant]'s max width. Defaults to [ContentWidthVariant.reading],
  /// the more common case across in-scope screens.
  const ContentMaxWidth({
    super.key,
    required this.child,
    this.variant = ContentWidthVariant.reading,
  });

  /// The content to constrain and center.
  final Widget child;

  /// Which max-width value to apply.
  final ContentWidthVariant variant;

  @override
  Widget build(BuildContext context) {
    final maxWidth = switch (variant) {
      ContentWidthVariant.form => AionContentWidth.form,
      ContentWidthVariant.reading => AionContentWidth.reading,
    };
    return Align(
      alignment: Alignment.topCenter,
      child: ConstrainedBox(
        constraints: BoxConstraints(maxWidth: maxWidth),
        child: child,
      ),
    );
  }
}
```

`Align(topCenter)` rather than `Center` — the wrapped content is
typically a `Column` inside a `SingleChildScrollView`, which sizes to
its content height; `Center` would also try to vertically center it
within the scroll view's viewport, which is not the desired effect for
top-anchored scrollable content. `Align(topCenter)` centers
horizontally only.

Barrel export: add both new files to `design_system/design_system.dart`
alongside the existing token/atom exports.

## Placement pattern (applies to every retrofitted screen)

Every in-scope screen already follows the same shape: an outer
`Padding`/`SingleChildScrollView` with hardcoded horizontal padding
(mostly `20`, `NewProjectScreen` uses `32`), wrapping a `Column` of
actual content. `ContentMaxWidth` slots in **around that inner
`Column`, inside the existing outer padding** — the same nesting
`NewProjectScreen` already used with its raw `ConstrainedBox`:

```
SingleChildScrollView(padding: <existing horizontal padding>)
  └─ ContentMaxWidth(variant: <form|reading>)
       └─ Column(<existing content, unchanged>)
```

The outer padding is left as-is in every screen (still using
`AionSpacing` constants where it already does — this change does not
introduce new padding-token usage, only the width constraint). This
keeps narrow/mobile viewports pixel-identical to today; only viewports
wider than `AionSpacing`-padding-plus-`maxWidth` see any visual change.

Pinned/footer elements that sit **outside** the scrollable region
(ticket detail's comment composer, every form's submit button) get
their own matching `ContentMaxWidth` wrapper at the same variant, so
they stay visually aligned under the scrollable body above them.

#### Overlay anchoring (design decision)

The FAB, the multi-select `TicketSelectionBar`, and the board
"load more" button are all `Positioned` directly against the
screen's root `Stack`, not against the list body. **They stay
viewport-anchored and are not wrapped in `ContentMaxWidth`.** This
matches standard FAB/toolbar placement conventions (bottom-right/
bottom-center of the visible viewport, not of a content column) and
avoids a jarring effect where a floating action button would jump
inward on wide screens while everything else stays at the viewport
edge. If a future design pass wants overlays to track the constrained
column instead, that's a separate, explicit change — not a side
effect of this one.

## Testing

No Cubit or repository logic is introduced or changed, so per
project.md's Testing section ("Unit tests required for every Cubit and
repository with real logic") no new Cubit/repository tests are needed.

`ContentMaxWidth` is a new public, reusable `design_system/` widget —
it gets a small widget test verifying: (a) it constrains its child to
the expected width for each `ContentWidthVariant`, and (b) it centers
that child within a wider available width. See tasks.md.

Existing widget tests (if any target the retrofitted screens'
layout/padding structure) must still pass unmodified — this change
does not touch outer padding values, only what wraps the content
inside them. `tasks.md` includes a regression-check task
(`flutter test`) rather than assuming this in advance.

## Non-Material / token compliance

`ContentMaxWidth` uses only `Align`, `ConstrainedBox`, and
`BoxConstraints` — all `flutter/widgets.dart`, none of them on the
Non-Material banned list in project.md. No raw hex, font size, or
spacing values are introduced; the two width numbers live in the new
`AionContentWidth` token class, matching how `AionSpacing`/`AionRadius`
already centralize their respective scales.

# Aion — Consistent Max-Width, Centered Content Layout: Component Spec

Extends the base [Aion Design System Spec](./Aion%20Design%20System%20Spec.md). References `AionColors`, `AionText`, `AionRadius`, `AionSpacing` by name. **No Material widgets anywhere.** Build from Flutter primitives only — `Align`, `ConstrainedBox`, `LayoutBuilder`, `Padding`, `Row`/`Column`, `SizedBox`, `SingleChildScrollView`, `Stack`/`Positioned`. `TextField` (via the existing `AppTextField` atom) remains the sole sanctioned exception and is not touched by this change.

This feature adds one small shared layout primitive — `ContentMaxWidth` — that caps a screen's content to a maximum width and centers it on wide viewports, and retrofits it consistently across the app's detail screens, list views, and forms. `NewProjectScreen` already proves the pattern with an ad hoc `ConstrainedBox(maxWidth: 520)`; this generalizes it into a reusable widget with two named width variants.

**No new screens are created.** Each retrofitted screen's visual design is unchanged — only its width/centering behavior on wide viewports.

Both themes are specified where relevant: **Arctic** (light, celestial-cold) and **Obsidian** (dark, abyssal-cold). `ContentMaxWidth` itself is **theme-agnostic** — it draws nothing (§1.4).

## 0. New tokens

### 0.1 Content width variants

Add a small enum and a max-width resolver. No color, radius, or type tokens are added.

```dart
enum ContentWidthVariant { form, reading }

// Max content width in logical px per variant.
double contentMaxWidthFor(ContentWidthVariant v) {
  switch (v) {
    case ContentWidthVariant.form:    return 520; // short interactive flows
    case ContentWidthVariant.reading: return 840; // reading-oriented content
  }
}
```

- `ContentWidthVariant.form` → **520px** — create/edit forms (Create Project, Create Ticket, Create Page).
- `ContentWidthVariant.reading` → **840px** — ticket detail, page detail, documentation content, documentation tree/search, ticket list (list mode).

These are the only two values. Do not introduce ad hoc widths; migrate the existing `ConstrainedBox(maxWidth: 520)` in `NewProjectScreen` to `ContentMaxWidth(variant: ContentWidthVariant.form)`.

### 0.2 No new spacing

Outer screen padding is unchanged and owned by each parent screen, not by `ContentMaxWidth`:
- Most screens: `AionSpacing.sp20` (20) horizontal.
- `NewProjectScreen`: `AionSpacing.sp32` (32) horizontal.

`ContentMaxWidth` applies **zero** padding of its own (§1.4).

## 1. `ContentMaxWidth`

A **structural, non-interactive, invisible** wrapper. It caps its child to the variant max-width and centers it horizontally when the available width exceeds that cap; otherwise it is a pass-through.

### 1.1 API

```dart
class ContentMaxWidth extends StatelessWidget {
  const ContentMaxWidth({
    super.key,
    required this.child,
    this.variant = ContentWidthVariant.reading,
  });

  final Widget child;
  final ContentWidthVariant variant;
}
```

### 1.2 Behavior spec

Given available width `W` (from the incoming constraints) and variant max-width `M` (520 or 840, per §0.1):

- **`W <= M`** — the child renders at its **natural width**, left-aligned within whatever outer padding the parent screen already applies (typically `AionSpacing.sp20` horizontal; `sp32` on `NewProjectScreen`). No visible change from today.
- **`W > M`** — the child is constrained to `M` px wide and **centered horizontally** in the available space. The horizontal gutters on either side reveal the parent's `background` fill (Arctic `#EDF2F8` / Obsidian `#0A0E18`).
- **Vertical position is never affected** — always top-anchored, since this always wraps scrollable or top-of-screen content. The wrapper imposes no height constraint and does not stretch the child vertically.

### 1.3 Implementation

Pure `Align` + `ConstrainedBox` composition — no `LayoutBuilder` needed, because `Align` with `widthFactor` unset lets the child fill up to the constraint and `ConstrainedBox` caps it:

```dart
@override
Widget build(BuildContext context) {
  return Align(
    alignment: Alignment.topCenter,
    child: ConstrainedBox(
      constraints: BoxConstraints(maxWidth: contentMaxWidthFor(variant)),
      child: child,
    ),
  );
}
```

`Align(alignment: Alignment.topCenter)` centers horizontally and top-anchors vertically. `ConstrainedBox(maxWidth: M)` caps the width; when `W <= M` the child simply takes its natural/available width (no centering effect is visible because it already fills the space inside the parent's padding).

### 1.4 Visual spec — none

- **Dimensions:** width = `min(W, M)`; height = child's intrinsic height. No `SizedBox`/fixed height.
- **Padding:** `EdgeInsets.zero`. Outer padding stays with the parent screen.
- **Border radius:** none.
- **Fill:** none (transparent). Gutters show the parent screen's `background`.
- **Border:** none.
- **Shadow:** none.
- **Text style / icon size / icon color:** N/A — draws no text or icons.

State this explicitly rather than inventing decoration: `ContentMaxWidth` paints nothing.

### 1.5 States — none

`ContentMaxWidth` is **non-interactive**. It has no default / hover / focused / pressed / disabled / error states, no gesture handling, no focus node, no semantics beyond passing the child through.

### 1.6 Usage rules

- Wrap the **scrollable content column** (or the top-of-screen content), inside the `SingleChildScrollView` viewport, so the scrollbar and background gutters stay full-width while the content column is capped.
- For screens with a **pinned bottom bar** (comment composer, submit button), wrap the pinned bar in its **own** `ContentMaxWidth` of the same variant so it aligns under the content column (see §2.1, §6.1).
- **Full-width / viewport-anchored elements are exempt** and must NOT be wrapped: kanban board mode, the FAB, and the multi-select action bar stay anchored to the full viewport (§5.2).

Wrap the ticket detail's scrollable body in `ContentMaxWidth(variant: reading)`. The pinned bottom comment composer is wrapped in a **second** `ContentMaxWidth(variant: reading)` so it sits directly under the 840px content column.

Structure (unchanged internally):

```dart
Column(children: [

    child: SingleChildScrollView(
      padding: EdgeInsets.symmetric(horizontal: AionSpacing.sp20, vertical: AionSpacing.sp20),

      child: ContentMaxWidth(child: /* composer row */),   // reading, 840 — aligns under body

])
```

- Content: `AIO-12 "Redesign OAuth callback flow"` — Story, Medium priority, In Progress; description, 2 linked tickets, 3 comments.
- On ≥1600px viewports the 840px column is centered with `background` gutters on both sides; composer aligns under it.
- **Reference §1** for all `ContentMaxWidth` visual/state details — nothing new is drawn here.

## 5. Ticket list — list mode (retrofit) — `reading`, 840px

### 5.1 List body

Wrap only the **list-mode row column** in `ContentMaxWidth(variant: reading)`. Header/filter row above stays full width. 6–8 rows with mixed priority badges (`AIO-7` Critical, `AIO-15` High, `AIO-22` Medium, `AIO-30` Low).

### 5.2 Exemptions (explicit)

These are **viewport-anchored** and MUST NOT be wrapped in `ContentMaxWidth`:

- **Kanban board mode** — horizontally scrolling columns stay full-width.
- **FAB** — anchored to the bottom-right of the **full viewport** via `Stack` + `Positioned(right: sp20, bottom: sp20)`, outside the `ContentMaxWidth` subtree.
- **Multi-select action bar** — floating overlay anchored to the full viewport, not the centered column.

```dart
Stack(children: [
  Column(children: [
    ListFilterHeader(),                       // full width
    Expanded(child: SingleChildScrollView(
      child: ContentMaxWidth(child: TicketRowsColumn()),   // reading, 840
    )),
  ]),
  Positioned(right: AionSpacing.sp20, bottom: AionSpacing.sp20, child: Fab()), // full-viewport
])
```
