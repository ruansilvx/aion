# Spec Delta: Live-Refresh an Open Ticket Detail Screen

**Reconciled 2026-09-03:** cross-checked against the current `aion-arch/specs/tickets.md` text — every distinctive symbol/behavior this delta names is still present and accurate (30/30 identifiers confirmed verbatim; the rest are prose/filename references, not drift). No content changes needed.

## ADDED

- **`TicketsCubit._refreshDetailIfOpenAndAffected(String writtenTicketId)`**
  (private) — after a background write completes, re-fetches and
  silently re-emits `TicketDetailLoaded` for the currently-open ticket
  detail screen if either (a) `writtenTicketId` is the ticket currently
  shown, or (b) the currently shown ticket is a `story` and
  `writtenTicketId` is one of its direct `task`/`bug` children. No-ops
  otherwise. Never emits `TicketsLoading` (see `getTicketById`'s
  Loading-skip below).

## MODIFIED

- **`TicketsCubit.createTicket`/`updateTicket`** — the existing
  `unawaited(_estimationSuggester.suggest(ticket))` fire-and-forget call
  now chains `_refreshDetailIfOpenAndAffected(ticket.id)` onto that
  future's completion, closing the AI-suggestion live-push gap
  (tickets.md's "AI-suggested complexity/estimate" Known gaps bullet) for
  the *passive* background path specifically. No change to
  `TicketEstimationSuggester.suggest`'s own signature or behavior, and no
  change to the explicit `regenerate`/`regenerateComplexitySuggestion`/
  `regenerateEstimateSuggestion` path, which already re-emits immediately.

- **`TicketsCubit.updateTicketStatus(String id, TicketStatus status)`** —
  after its existing `TicketStatusUpdated(tickets, hasMore)` emission on
  success, now also fires
  `unawaited(_refreshDetailIfOpenAndAffected(id))`, closing the
  `canAdvanceSddStage` staleness gap (tickets.md's Known gaps bullet on
  this) for the case where the currently-open detail screen is the
  affected ticket's parent Story. `changeTicketStatus` (the detail
  screen's own status-write path) is unaffected — it already re-emits
  `TicketDetailLoaded` for itself synchronously and has no staleness gap.

- **`TicketsCubit.getTicketById(String id)`** — now skips its
  `TicketsLoading` emission when the current state is already
  `TicketDetailLoaded` for this exact `id`, still emitting it in every
  other case (fresh navigation, a different ticket's stale detail on
  screen, an error state, etc.). Mirrors `searchTickets`'s existing
  "`TicketsLoading` only when nothing is on screen yet" precedent, scoped
  per-ticket-id instead of per-list. Required so
  `_refreshDetailIfOpenAndAffected`'s re-fetch lands invisibly; also
  quietly smooths the three pre-existing re-fetch-via-`getTicketById`
  call sites (`updateTicket`, `changeTicketStatus`,
  `regenerateComplexitySuggestion`), none of which depended on a
  Loading flash occurring.

- **`aion-arch/specs/tickets.md`'s "Known gaps" bullet on AI-suggested
  complexity/estimate** — the "no live push/refresh of an already-open
  `TicketDetailScreen` when the passive background suggestion lands"
  clause is removed from that bullet; the remaining clauses (no list/
  board badge, no trigger from a hand-edited Markdown file, no
  model-self-reported confidence score, no Settings-level config) are
  unaffected and stay documented as-is.

- **`aion-arch/specs/tickets.md`'s "No polling/live-refresh of
  `TicketDetailLoaded.canAdvanceSddStage`" bullet** — narrowed on
  `/archive` to note that the single-ticket status-write path
  (`updateTicketStatus` — board drag, `MoveToStatusMenu`) now
  live-refreshes an open Story's detail screen when a direct Task/Bug
  child's status changes; the bulk status-edit path and any
  Epic-level/`sddStage`-driven staleness remain open, per this
  proposal's Non-goals.

## REMOVED

None.

## Explicitly unchanged (called out to prevent scope creep during `/apply`)

- **No new `TicketsState` subclass.** Every refresh still emits the
  existing `TicketDetailLoaded`.
- **No new `TicketRepository` method.** `getTicketsByParent` already
  exists and already supports the `types` filter this uses.
- **No DB migration, no new `Ticket` field.**
- **`TicketEstimationSuggester`/`TicketRollupRecomputer`/
  `TicketContextEnricher`** — none of these classes change. The refresh
  check lives entirely in `TicketsCubit`, one layer up.
- **Bulk status/priority edit** (`TicketsBatchStatusUpdating`/
  `TicketsBatchStatusUpdated`) — does not call
  `_refreshDetailIfOpenAndAffected`. A bulk status change to a Story's
  child Task/Bug while that Story's detail screen is open still requires
  a manual reload.
- **`estimateRollup`/`timeSpentRollup`** — `TicketRollupRecomputer`'s own
  background recompute still doesn't refresh an open ancestor's detail
  screen. Not touched by this change.
- **List rows and board cards** — unaffected either way; they already
  read whatever `Ticket` is in their already-loaded list/board state and
  this change doesn't touch list/board refresh timing.
