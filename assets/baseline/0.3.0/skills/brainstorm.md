# brainstorm

Structured idea exploration, grounded in the project's actual current
state rather than abstract discussion. Sits before the SDD cycle
(`explore → propose → apply → verify → archive`) — for working out
*what* to build or *how* to think about a problem, not yet planning the
implementation.

Works by asking one targeted question at a time rather than dumping a
wall of open questions — each answer should narrow or redirect the next
question, the way a real design conversation would. Ends when the
direction is either clearly resolved or explicitly deferred with a
stated reason.

Persists the session as a written record (an "idea" file) so the
thinking isn't lost between sessions — future work can reference it
without re-deriving the same reasoning. A quick/abbreviated mode exists
for smaller questions that don't need a full multi-question session.

Once a brainstorm reaches a clear direction, its natural next step is
`propose`.
